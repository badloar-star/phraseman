## Ревью №1 (SECURITY APPROVE, SPEC HOLD) → Ремонт №2 отдан
- P1: метка гидрации переживает выход (не в инвентаре аккаунтных ключей) → выход/вход того же uid при включённом выключателе = пустые карточки на телефоне (сервер цел).
- P2a: unsetFields из засеянного сервером зеркала может стереть правку другого устройства.
- P2b: старый сервер отвечает payload_invalid на unsetFields и теряет fields той же операции → снятие отдельной операцией; функции выкладывать до клиента.
- P3: es/de карточки идут в оба канала (дубль); бэкап Android + server_disabled.

## Порядок выкладки (ремонт №2, P2b) — ОБЯЗАТЕЛЬНО

Функции (`accountsV2SyncApply` с поддержкой `unsetFields`) выкладываются ДО клиента.
Старый сервер отвечает `rejected payload_invalid` на операцию с `unsetFields`; поэтому
клиент шлёт снятие полей ОТДЕЛЬНОЙ операцией (`fields: {}` + `unsetFields`) — отказ
старого сервера не уносит правки полей, но само снятие на старом сервере теряется.

## Ограничения (ремонт №2, P3)

- Ключи выключателя — только en/fr (старая синхронизация других языков карточек не
  ведёт); es/de карточки V2 только дублируются, не теряются.
- Метка гидрации снимается при `server_disabled` (restore со следующего старта —
  старым путём); первый старт после переноса бэкапа Android с выключенным сервером V2
  может один раз пропустить restore — данные на сервере не теряются.
