# Диалоги: строгий UI и отдельное правило доступа

Сценарии и ассет главной полностью переоформляются после согласования дизайна. Цветная карта не должна быть единственным способом понять тему/сложность. Ключевая строка списка: сценарий, язык, доступность. Сам диалог также новый UI, не только новый список.

S66–S67: доступ открывает уровень, НЕ Plus и НЕ прямая покупка за руны. Последний абзац убрал обычный уровень; рабочее решение — `minCoinRank`. Оно явно фиксируется в D05, затем утверждается таблица. Не делать скрытую проверку XP для сохранения старого кода. Приобретённый до обновления диалог сохраняется по grandfathered праву или отдельному согласованному решению, а не закрывается новым ранговым порогом.

Пример access decision: `ownedBeforeMigration OR coinRank >= minCoinRank`. Это проектная формула для согласования, не готовая схема базы. Снижение остатка монет на другой расход не убирает coinRank. Plus не подменяет ранг, но энергополитика Plus остаётся общей.

Если диалоги генерируются внешним AI, доступ к каталогу и бюджет API — разные вопросы. Требуется отдельная transparent quota/cost policy, которая не превращает «не Plus» в молчаливую подписочную блокировку. Бесплатный ранговый доступ не доказательство нулевой цены выполнения.

Локализация касается prompt, ролей, ответа, проверки, TTS, safety, контекста и persistence. Нельзя заменить language code и объявить локаль качественной. Добавлять только готовые сценарии, изолировать learning direction. При сбое сохранять доступность выхода/повтора и корректно завершать session accounting.
