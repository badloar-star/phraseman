## Outcome

Приложение запускается всегда, даже когда нативного модуля `ExpoTaskManager`
нет в текущей сборке. Фоновая догрузка аудио при этом отключается и пишет в
лог причину, а не роняет весь бандл. Мера успеха: на текущей сборке без
пересборки экран открывается, в логах видна строка `[BG-PREFETCH]` с причиной
отказа; после пересборки та же строка сообщает об успешной регистрации задачи.

Повод — багрепорт владельца 2026-09-20 со скриншотом
`Uncaught Error: Cannot find native module 'ExpoTaskManager'`.

## Почему первый круг не помог (важно для следующей сессии)

Круг 1 заменил статический `import` на `require` внутри `try/catch`. Стек в
повторном багрепорте изменился — падение переехало внутрь
`loadNativeBackgroundModules`, то есть catch НЕ сработал. Причина:

- `expo-task-manager/build/ExpoTaskManager.js` состоит из одной строки
  `export default requireNativeModule('ExpoTaskManager')` — бросок происходит
  при ВЫЧИСЛЕНИИ модуля, а не при вызове функции;
- в `metro.config.js` нет `inlineRequires`, поэтому Metro поднимает `require`
  на верх модуля и выполняет его при загрузке бандла — до входа в функцию,
  где стоит `try/catch`.

Вывод: обернуть загрузку в try/catch недостаточно. Нельзя ДОПУСКАТЬ загрузку
пакета, пока не известно, что нативная часть есть.

## Scope

В scope:
- `app/learning_v2_audio_prefetch_background_v1.ts` — единственный импортёр
  `expo-task-manager` / `expo-background-task`.

Вне scope: сам алгоритм догрузки (`learning_v2_audio_prefetch_coordinator_v1.ts`),
`app/_layout.tsx`, версии пакетов в package.json, `metro.config.js`,
конфигурация EAS и пересборка нативного клиента. Пакеты в `node_modules`
не патчатся.

## Architecture

Границы не меняются. Меняется способ проверки доступности: вместо «попробовать
загрузить и поймать ошибку» — «сначала спросить у реестра нативных модулей,
потом грузить». Реестр доступен как `globalThis.expo.modules` — это тот же
источник, который внутри себя опрашивает `requireOptionalNativeModule`
(см. `expo-modules-core/src/requireNativeModule.ts`).

Инвариант: пакеты `expo-task-manager` и `expo-background-task` загружаются
только после того, как `ExpoTaskManager` найден в реестре. Если его нет, файл
импортируется успешно, экспортируемая функция возвращает управление,
приложение работает без фоновой догрузки.

Загрузка по-прежнему остаётся в try/catch как второй рубеж: реестр может
измениться в будущих версиях Expo, и отказ обязан быть мягким.
