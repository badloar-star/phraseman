## Outcome

Образец `settings-gaps-states.html` №12 «Уведомления — телефон не разрешает» показывает при системном запрете:
- главный переключатель **выключен**;
- все строки (Ежедневное напоминание, Время, категории) **выключены и приглушены**.

В приложении (кадр Сверки 13.10 09:48) при том же запрете мастер включён и строки активны, потому что показываются сохранённые выборы. Нужно показывать **фактическое** состояние: пока телефон запрещает, ни одно уведомление не придёт.

## Scope

In scope: `app/settings_notifications.tsx` — значения, которые экран показывает (не сохранённые), и журнал `[NOTIF-PERM]`; source-контракт `tests/settings_notifications_blocked_display_contract.test.ts`.

Out of scope:
- сохранённые настройки (`saveNotifPrefs` / `saveNotifSettings`) — не меняются; после разрешения выборы человека возвращаются как были;
- логика запроса разрешения.

## Architecture

`masterShown = prefs.master && !needsPermission`; дальше везде, где экран рисовал `master`, используется `masterShown`:
- значения переключателей строк = `masterShown && значение`;
- `disabled` = `!masterShown`;
- приглушение блока и строки «Время» — по `masterShown`.

Тап по выключенному мастеру при запрете → `toggleMaster(true)` → прежний путь `persistPrefs` → `ensurePermissionIfEnabling` спрашивает разрешение (или ведёт в настройки). Это и есть естественное действие «включить». Строки при запрете недоступны, как в образце.

## Technical debt
