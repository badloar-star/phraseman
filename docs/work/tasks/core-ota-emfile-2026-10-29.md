## Outcome
Сборка кандидата от 8ee3cc045 остановилась на шаге «экспорт ios» с ошибкой `EMFILE: too many open files`
на 92% (16196 модулей). Прошлые удачные экспорты 25–26.10 собирали 13290–13378 модулей.
`--max-workers 1` уже стоит, значит файлы открывает основной процесс сборщика.
Цель — PASS экспорта без правки кода приложения.

## Scope
Только сборочная обвязка: датчик открытых файлов в scratchpad (подключается через NODE_OPTIONS=--require)
и диагностический повтор экспорта в снимке /c/Temp/claude/ota_head. Код приложения и конфиг сборщика
не трогаю, пока лог не покажет причину.

## Architecture
[EMFILE-PROBE] считает одновременные открытия (fs.open / readFile / promises), их пик, расширения файлов
и печатает стек на EMFILE. По логу выбираю решение: очередь открытий (graceful-fs через --require только
в ota_from_head.sh) или устранение источника, который открывает файлы веером.

## Security and privacy
Данных пользователей нет. Диагностический экспорт идёт без production-ключей (.env.ota.pulled уже стёрт),
бандл не публикуется.

## Technical debt
Если причина — рост числа файлов курса, нужен постоянный предохранитель в ota_from_head.sh, а не разовый обход.

## Verification
Повтор экспорта ios/android до строки «Bundled … modules»; затем полная сборка ota_from_head.sh → PASS;
ota_final_check у Ревизора.

## Rollback
Датчик живёт только в scratchpad и в переменной окружения диагностического прогона — удалить файл.
Ограничитель: убрать `--require scripts/ota_fs_limit.cjs` из NODE_OPTIONS в ota_from_head.sh (одна строка) и сам файл.

## Диагноз по датчику [EMFILE-PROBE] (29.10 14:30, снимок 8ee3cc045, экспорт ios)
- Процесс expo export (pid 51148): одновременно открыто до 8960 файлов, всего открытий 16935, EMFILE 772 раза.
  Расширения: «(none)» 16785 — это записи кэша Metro (C:\Temp\claude\ota_tmp\metro-cache\…), .webp 150.
- Дочерние процессы и npx — пик 1, проблемы нет.
- Источник: metro-cache FileStore.get → `fs.promises.readFile` на КАЖДЫЙ модуль сразу (FileStore.js:21), запись —
  `fs.promises.writeFile` (:55). При тёплом кэше обход графа запрашивает все 16,8 тыс. модулей веером, и на Windows
  упираемся в предел открытых файлов процесса (около 8 тыс.). Раньше было 13,4 тыс. модулей — помещались. Рост дала
  пересборка курса.
- graceful-fs 4.2.11 fs.promises не патчит → не поможет.

## Решение
scripts/ota_fs_limit.cjs — подключается через NODE_OPTIONS=--require ТОЛЬКО в ota_from_head.sh:
- семафор на fs.promises.readFile / writeFile (до 1024 одновременно);
- при EMFILE — повтор с паузой (до 8 попыток);
- журнал [OTA-FS-LIMIT]: пик ожидающих, число повторов, итог на выходе процесса.
В бандл приложения не попадает. Кэш оставляем тёплым (быстрее).
