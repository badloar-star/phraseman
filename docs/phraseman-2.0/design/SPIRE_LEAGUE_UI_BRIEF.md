# Бриф для сессии «Новый стиль приложения»: экраны Шпиля и нового рейтинга

От: сессия «Башня» (логика/данные Шпиля, PM-270…287, эпик E25).
Кому: сессия «Новый стиль приложения» (D31/D40 — она делает вид/вёрстку).
Референсы владельца — 4 скриншота, присланы вместе с этим запросом в чат
(тренировка «Блиц» старый/новый стиль, шторка «Фраза дня», карточка в
сообществе). Ключевые черты стиля по ним:
- тёмный почти чёрный фон с мягкой радиальной подсветкой пятнами по краям
  (не сплошной градиент, а несколько размытых светлых пятен);
- **кольцевой таймер** вместо линейного прогресс-бара на заданиях;
- капсулы/карточки с **тонкой полупрозрачной обводкой** (разрешено D43/D46
  для нового стиля — обычный запрет CLAUDE.md на обводки здесь снят);
- крупная типографика, разрядка в лейблах (ВЫБЕРИ ПЕРЕВОД — капс + трекинг);
- мягкие тени/подсветка внутри карточек, не резкие рамки;
- пустые кружки-радио вместо явных обводок для вариантов ответа;
- шторки (bottom sheet) с ручкой сверху для доп. контента (фраза дня, выбор режима).

## 1. Что заменяется

**Раздел «Лига» внутри вкладки «Сообщество» полностью заменяется «Шпилем».**
Рабочее название игры — «Шпиль». 12 ступеней лиги (Медная…Высшая) переименованы
в 12 камней: Гранит, Базальт, Мрамор, Нефрит, Кварц, Агат, Оникс, Аметист,
Опал, Топаз, Обсидиан, Алмаз (см. `modules/spire/tier_names.ts` — готовые
названия на 9 языках интерфейса, используйте их, не придумывайте свои).

Полная продуктовая логика — `docs/phraseman-2.0/docs/TOWER.md` (читайте
целиком, особенно §2 решения T1–T42 и §4 «Устройство» — там механика ступени,
этажа, таймера, ботов, монет). Контракт данных — `docs/TOWER_CONTRACT.md`.

## 2. Полный список экранов и состояний

### 2.1 Тур первого входа (3 экрана)
1. «Поднимайся выше всех за неделю» — образ шпиля/камня.
2. «10 заданий, общее время, 3 сердца» — те же кольцевой таймер и сердца,
   что в тренировках карточек (см. референс «Блиц»).
3. «Верхние пятеро переходят в следующий шпиль» — намёк на повышение.
Кнопка «Пропустить» на каждом. Кнопка «Далее»/«Начать» в стиле референса
(закруглённая капсула справа внизу, как «Далее» на скриншоте «Блиц»).

### 2.2 Главный экран Шпиля (замена сегодняшнего экрана Лиги)
- Вертикальный шпиль-силуэт (12 вариантов камня — картинки будут от Codex по
  брифу `docs/TOWER_ASSET_PROMPTS.md`, пока используйте плейсхолдер/заглушку).
- Мой маркер на текущей ступени/этаже.
- Аватарки ближайших соперников выше/ниже («Аня — на 2 ступени выше»).
- Пьедестал топ-3 + кнопка «Все участники» (полный список, как раньше в лиге).
- Таймер до конца недели.
- Энергия в шапке (как на главном экране приложения — переиспользуйте
  существующий компонент энергии, не рисуйте заново).
- Главная кнопка «Подняться» — крупная, capsule-style как на референсах.
- Этажи-Стражи (каждый 5-й) и вершина (15-й) визуально выделены на шпиле.
- Строка «Друзья на этой неделе» с их этажом (данные готовы — PM-282,
  `functions/src/friends_profiles.ts`, поле `spireFloor`/`spireLang`).
- Первый кадр — БЕЗ спиннера, из локального кэша (`app/spire_config_client.ts`
  уже даёт мгновенный дефолт).

### 2.3 Экран ступени (сама игра)
- Переиспользует компоненты заданий Арены: `components/arena/ArenaQuestion.tsx`
  и его типы (`choice`, `translate`, `match`/пары, `listen`, `dictate`, `voice`).
- **Кольцевой таймер** на весь бюджет ступени (не на отдельное задание — это
  ключевое отличие от Арены!) — используйте паттерн `ArenaTimerRing.tsx`, но
  привяжите к общему таймеру ступени (логика уже в `modules/spire/step_machine.ts`,
  поле `elapsedBudgetMs`/`budgetMs`).
- 3 сердца (как на референсе «Блиц» — три сердечка в шапке).
- При ошибке — короткий показ правильного ответа (таймер стоит), см.
  `phase: 'revealing'` в движке.
- Голосовое задание — обычный UI записи речи, НЕ снимает сердце при неудаче
  (до 2 доп. попыток — просто визуально предложить «Ещё раз»).
- Пауза при сворачивании приложения — просто скрыть контент, ничего не рисовать
  специально (это уже логика, не экран).
- Экран «назад» с подтверждением — стандартный алерт/шторка «Выйти? Ступень
  будет провалена» — используйте паттерн существующих модалок подтверждения
  приложения (тёмный стиль, capsule-кнопки).

### 2.4 Итог ступени (внутри той же сцены, не отдельный переход)
- Пройдена: маркер едет вверх по шпилю (анимация), + монеты, кнопка «Выше».
- Провалена: «Ещё раз» (если есть энергия) / «Позже».

### 2.5 Этаж пройден / Страж побеждён / Вершина
- Празднование НА ЭКРАНЕ ШПИЛЯ (не отдельный оверлей поверх другого экрана —
  правило «празднование не ставится в durable-очередь», см. память проекта).
- Вершина (15 этаж) — самый заметный момент, светящаяся точка на шпиле.

### 2.6 Итог недели
- Показывается на экране Шпиля при ПЕРВОМ заходе новой недели: «Ты поднялся
  в Нефрит» / «Остаёшься в Кварце» — фактом, без отдельного модального потока.
- Данные уже готовы (PM-276, `functions/src/spire_finalize_core.ts`,
  `users/{uid}/spire_week_results/{weekId}_{lang}`).

### 2.7 Нет энергии
- Free: таймер до следующей единицы энергии + мягкий призыв Plus
  «Поднимайся без ожидания». БЕЗ блокирующей модалки на весь экран.

### 2.8 Пустые/крайние состояния
- Комната ещё не набрана / язык без готового пула — честное «скоро» (не
  подсовывать задания другого языка).
- Нет сети — свой прогресс работает (маркер локальный), чужие цифры
  «обновим при связи».
- Переход из старой Лиги (см. §3 ниже) — состояние ожидания на первом входе.

## 3. Важно: состояния миграции из Лиги (НОВОЕ, добавлено сегодня, PM-278)

Первый вход игрока в Шпиль вызывает сервер и может вернуть отказы — экран
обязан их аккуратно показать, не как голую ошибку:
- `league_finalization_pending` — «Идёт подведение итогов лиги, подожди
  немного» (переносим место только после того, как подведён итог прошлой
  недели лиги) — с тихим повтором, не с красным текстом ошибки.
- `spire_migration_paused` — «Шпиль откроется чуть позже» (админ поставил
  перенос на паузу).
- Обычный успешный перенос — тихо, без отдельного экрана («О, ты сразу в
  Нефрите!» можно показать один раз как приятный факт, не обязательно).

Контракт: `functions/src/spire_league_migration_contract.ts`,
`functions/src/admin_spire_league_migration.ts`. Экран должен слать
`currentStudyTarget` (текущий изучаемый язык) при первом входе в Шпиль.

## 4. Что НЕ входит в эту работу

- Названия шпилей и вся продуктовая механика — уже решены, не придумывайте
  заново (используйте `modules/spire/tier_names.ts`, `docs/TOWER.md`).
- Финальное имя игры «Шпиль» уже выбрано владельцем — не предлагайте другие.
- Картинки самих 12 шпилей делает Codex по `docs/TOWER_ASSET_PROMPTS.md` —
  до готовности используйте простую заглушку (силуэт/градиент), не тратьте
  время на рисование камня самим.
- Сама миграция данных из Лиги в Шпиль НЕ запущена на проде — ждёт решений
  владельца (см. `docs/phraseman-2.0/evidence/PM-278_league_migration.md`).
  Экран должен работать и без реально перенесённых данных (частая ситуация
  в разработке — человек ещё не мигрирован).

## 5. Технические точки входа (для хуков/данных, не для вёрстки)

- `modules/spire/step_machine.ts` — состояние ступени (chисто, без UI).
- `app/spire_report_client.ts`, `modules/spire/report_queue.ts` — отправка
  прогресса, есть готовая `spireHasUnsyncedSteps()` для индикатора «сохраняем».
- `app/spire_config_client.ts` — конфиг (таймер/монеты/высота) с кэшем.
- `functions/src/friends_profiles.ts` (`spireFloor`/`spireLang` в
  `FriendPublicProfile`) — для строки друзей.
