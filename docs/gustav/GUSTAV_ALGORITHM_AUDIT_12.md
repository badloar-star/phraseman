## 3. Confirmed blockers

### GVA-052A: achievements_state needs achievement taxonomy

`achievements_state` maps local `achievements_v1` into one cloud blob.

Problem:

- lesson/quiz/trainer/active-recall/flashcard achievements are target-specific;
- arena/league/social/shards/commerce achievements may be global;
- `unlockedAt`, `notified` and `shardClaimed` follow the achievement id scope.

Required fix:

- classify every achievement definition id as global or study-target;
- split cloud state into global achievements and `targets/{studyTarget}/achievements`;
- migrate legacy flat achievements to English target where appropriate.

### GVA-052B: user_stats_v1 mixes exercise and commerce analytics

Target fields:

- `lessonsStarted`;
- `lessonsAbandoned`;
- `answersTotal`;
- `answersCorrect`;
- `quizLevels.easy|medium|hard`.

Global fields:

- `energyHits`;
- shard shop fields.

Mixed fields:

- `featuresOpened`;
- card pack click/purchase fields.

Required fix:

- split target exercise analytics from account/product analytics;
- add feature id and card pack target metadata.

### GVA-052C: stats_daily_breakdown_v1 needs metric-level split

Target metrics:

- `words_learned`;
- `flashcards_saved`;
- `phrases_learned`;
- `quizzes_completed`.

Global or mostly global metrics:

- `arena_wins`;
- `arena_losses`;
- `shards_earned`;
- `shards_spent`.

Mixed metric:

- `daily_tasks_claimed`.

Required fix:

- split daily breakdown into global and target buckets;
- preserve max-per-day merge policy per bucket.

### GVA-052D: daily_stats requires XP/streak product policy

`daily_stats.{date}.points` is generated by learning activity but represents account XP today.

Required product decision:

- if XP is one account-wide track, keep `daily_stats` global but record target attribution elsewhere;
- if XP is per target, move `points` under `targets/{studyTarget}`.
