# Task packet: сторожа исходника ложно краснеют на CRLF — общий помощник readSource

Governance-ID: TG-E851634527BE
Status: In progress
Owner: сессия 1 · ЯДРО (координатор 05.10)

## Outcome

На этом ПК core.autocrlf=true: 16 535 файлов в рабочей копии CRLF (индекс LF), 631 со смешанными окончаниями.
Сторожа в tests/, которые читают исходник и сверяют с многострочным литералом/регуляркой («\n»), ложно падают
(пример — 9d7efccaf). Цель: один помощник tests/helpers/read_source.ts (readSource с CRLF → LF), перевести
на него найденные сторожа пачками по 20–30 файлов; если дёшево — сторож, запрещающий новые сырые
readFileSync исходника в tests/ мимо помощника.

## Scope

Только tests/ (помощник, правка чтения в найденных тестах, необязательный сторож). Настройки git, окончания
строк рабочей копии и код приложения НЕ трогаем (затронуло бы все сессии и Codex). Зоны Codex (gustav_* —
входы hash-lock) не трогаем.

## Architecture

readSource(relativePath | absolutePath) → string: readFileSync(utf8).replace(/\r\n?/g, '\n'). В тестах меняется
только способ чтения исходника; ожидания не меняются. Проверка поиска — скриптом-сканером (scratchpad),
запуск только изменённых тестов через семафор.

## Security and privacy

Не затрагивается.

## Technical debt

Сторожа по тексту исходника хрупкие по природе; помощник снимает только класс «окончания строк».

## Verification

Каждая пачка: прогон только изменённых тестов (run_one), сравнение «до/после» по числу красных.

## Rollback

git revert пачки.
