# Task packet: название набора из видео — пусто → имя видео, выкладка

## Outcome
Слово владельца (через координатора, 05.11): в админке каждый набор из видео можно назвать любым именем (переименовывается НАБОР, не видео); если имя не писать — набор называется именем видео. Само поле «Название набора» уже сделано в R110 (d7bde78f6), но в бою не выложено: `adminSuggestVideoPackTitle` отсутствует, `adminSaveVideoPhraseDraft` старее R110. Здесь: запасное имя = имя видео (раньше — имя документа), лог `[VIDEO-PACK-TITLE] source=pack|video|document`, плейсхолдер в поле админки с именем видео, затем адресная выкладка трёх функций и админки.

## Scope
- `functions/src/video_phrases.ts`: версия черновика хранит `videoTitle`; публикация и пересборка передают его в сборщик набора как запасное имя; `titleSource: video_title`.
- `admin/v2/legacy.html` (только свои хунки): при сохранении черновика шлётся `videoTitle` выбранного видео; плейсхолдер поля — имя видео.
- Тест `functions/src/video_pack_title_fallback.test.ts`.
- Не трогаются: остальные функции (levelSpinStarGrant и др.), правила базы, клиент приложения (читает titleRu… из документа набора как раньше).

## Architecture
Название набора живёт в том же документе набора (`community_packs`), новых чтений нет. Приоритет: название набора админа → имя видео → имя документа → «Фразы из видео». Правила Firestore не меняются: набор пишет только сервер (admin-callable).

## Security and privacy
Личных данных нет: имя видео — публичное название ролика. Запись только через admin-callable с правом `content.draft.write`. Клиентам запись не открывается.

## Technical debt
Уже опубликованные наборы получат имя видео только при повторной публикации/пересборке (backfill использует сохранённое `videoTitle`; у старых версий его нет — останется имя документа).

## Verification
Юнит-тест на `buildVideoPackDoc` (3 случая приоритета); проверка типов functions; сухой прогон выкладки; после выкладки — проверка на одном наборе.
