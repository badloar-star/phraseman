## Outcome

Правило владельца: «Диалоги открываются все по мере ранга. С самого начала доступен только 1 диалог уровня A1 в «Общении» и всё. Все остальные открываются по рангу. Ранги все используются, а не с 7».
Было: ранг открытия = номер сценария в разделе (index+1), на ранге 6 в «Общении» открыто 6, замок «ранг 7».
Стало: одна таблица-источник `unlockRank` в каталоге (shared/dialogue_v2_catalogue_index): ранг 0 — только `social_01` («Поздороваться после знакомства», A1), остальные 75 диалогов равномерно по рангам 1…19 в порядке уровня A1→C2 (по 4, на 19-м ранге 3). Подпись «Откроется на ранге N» с монетой N — как была, N теперь из таблицы. Пройденные диалоги остаются «пройдено» и не запираются. Журнал `[DIALOG-RANK-GATE]`.

## Scope

In scope: `shared/dialogue_v2_catalogue_index.ts` (+ зеркало `.js`), `shared/dialogue_v2_access_contract.ts` (ранг 0 допустим), `app/dialogue_v2_local_rank_access.ts`, `app/dialogue_v2_authorized_catalogue_projection.ts`, `app/dialogue_v2_released_catalogue_projection.ts`, сторож `tests/dialogue_v2_unlock_rank_table.test.ts`, правка устаревших ожиданий в тестах доступа.

Out of scope: поле `rankRequired` внутри пакетов диалогов (структурный ранг в хэшируемых пакетах не меняется, хэши пакетов и манифест те же); сервер (запрета по рангу на сервере нет, только показ у клиента); старый список диалогов (не рендерится).

## Architecture

В записи каталога два поля: `rankRequired` (структурный номер сценария в разделе, остаётся для проверки пакетов) и новое `unlockRank` (ранг, на котором диалог открывается у человека). Замки, подписи и брифинг берут `unlockRank` через проекции каталога (`item.rankRequired` в проекции = `unlockRank`). Контракт доступа принимает ранг 0 (раньше ранги < 1 отбрасывались). Таблица одна: массив по рангам, сторож проверяет её целостность.
