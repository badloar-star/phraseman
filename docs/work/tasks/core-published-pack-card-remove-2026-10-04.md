# Task packet: удаление одной карточки из своего опубликованного набора

Governance-ID: TG-70136847BAD7
Status: In progress
Owner: сессия 1 · ЯДРО (задача от сессии 3 «Карточки» через координатора 04.10)

## Outcome

Автор убирает карточку из своего опубликованного набора (cloudPackId, документ в community_packs).
Клиент прячет карточку сразу и 5 с держит удаление у себя («Вернуть» — без сети). Затем — ОДИН вызов
communityAuthorRemoveCard({ packId, cardId }); вызов лежит в очереди на устройстве и доживает до
следующего запуска. Сервер одной транзакцией: автор = вызывающий (идентификатор от клиента не берётся),
карточка есть, после удаления ≥ 10 карточек (иначе reason card_count), cards и cardCount меняются
вместе (каталог читает этот же документ), повтор → ok + not_found_already_removed, лог [PACK-CARD-REMOVE]
на каждом выходе. Клиент после успеха обновляет локальный набор по cloudPackId и сбрасывает кэш каталога;
при отказе — откат с причиной (подключает сессия 3 в deletePackCard).

## Scope

functions/src/community_pack_card_remove.ts (новый), экспорт в functions/src/index.ts, тест ядра;
app/community_packs/functionsClient.ts (вызов), app/community_packs/publishedPackCardRemoval.ts (новый:
5 с окно, очередь на устройстве, применение результата). Вне: localPackCardOps.ts и экран (сессия 3),
выкладка функции (координатор по имени, с согласия владельца).

## Architecture

Правила Firestore не меняются: клиенту и сейчас разрешены в community_packs только счётчики лайков.
Функции «вернуть» нет — отмена живёт только на клиенте до отправки.

## Security and privacy

Новых данных нет: удаляется карточка, которую автор сам добавил. Автор определяется по входу,
не по присланному идентификатору. Политика конфиденциальности не затронута.

## Technical debt

заявки вернёт карточку обратно.
