# Смена темы и ползунок: замер перерисовок, лог [THEMES-PERF]

Governance-ID: TG-FBBD4C8B5F41
Status: в работе
Owner: сессия «4 · ТЕМЫ 2.0» (задача координатора: оптимизация смены темы и ползунка)

## Outcome
Есть измеримый ответ «сколько компонентов перерисовывается при смене темы / шаге ползунка и сколько стоит пересчёт токенов»: dev-лог [THEMES-PERF] печатает причину смены значения контекста, время сборки темы и число перерисованных подписчиков useTheme. Дешёвые правки — только по цифрам из лога.

## Scope
components/ThemeContext.tsx — dev-счётчик в useTheme и dev-лог в провайдере (IS_DEV, в боевой сборке нулевая цена). Вид, токены и логика выбора темы не меняются.

## Architecture
Модульный счётчик вызовов useTheme; эффект провайдера сравнивает прежний и новый выбор (тема / насыщенность / оформление / шрифт) и через 250 мс печатает дельту счётчика. Время makeLiquidGlassTheme замеряется внутри useMemo.

## Security and privacy
Данные пользователя не собираются и не уходят: лог идёт только в консоль dev-сборки.

## Technical debt
Счётчик считает вызовы useTheme (≈ рендеры подписчиков), а не точные коммиты React; для точных цифр нужен Profiler. Если лог покажет тяжёлое место, правка пойдёт отдельным коммитом.

## Verification
Тесты themes (theme_persist и соседние), срез типов по ThemeContext, чтение журнала на эмуляторе при жесте ползунка.

## Rollback
git revert коммита; в боевой сборке IS_DEV=false, поведение не меняется.
