## Outcome
Dev-превью Шпиля принимает `tier=` (индекс лиги 0…11: 0 = Гранит, 3 = Нефрит — прежнее значение) и `floor=` (мой этаж 1…15; прежнее значение 7). Без параметров поведение прежнее. Только dev: маршрут в релизе не существует (гейт release_guard), моки вырезаны из боевой сборки.

## Scope
components/spire/spire_preview_fixtures.ts (разбор параметров + применение в week/game/ctx), app/dev_spire_preview.tsx (чтение параметров, передача), tests/spire_preview_tier_floor.test.ts. Боевой код Шпиля, Ядро и [SPIRE-GATE] не затрагиваются.

## Architecture
Чистая функция parseSpirePreviewOverrides(tier, floor): только целые в допустимом диапазоне, остальное игнорируется с предупреждением в журнале [DEV-STATE]. Применение — модульная переменная на время синхронной сборки модели (dev-фикстуры), этаж смещается относительно базового 7 (состояние `win` — этаж+1, `summit` на вершине остаётся, этажи ниже 1 прижимаются к 1).

## Security and privacy
Только dev-фикстуры, без данных пользователей и сети.

## Technical debt
Смещение «относительно базового 7» для состояний с другим базовым этажом (lobby, tour — 1) может дать этаж 1 при малых значениях — это документировано; если нужен абсолют, добавится `floorAbs=`.
