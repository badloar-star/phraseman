# Spec: Опросы за осколки (Shard Survey)

> Сбор обратной связи от пользователей через короткие опросы, встроенные в
> экран ежедневных заданий. За прохождение — фиксированная награда в осколках.
> Ответы стекаются на сервер; админка даёт сводную аналитику, ленту сырых
> ответов, редактор опросов и выгрузку CSV.
>
> **Идея владельца (кандидат «Кира», 2026-07-05):** «первое, что я бы сделала —
> собрала обратную связь; можно в виде теста за осколки». Эта спека реализует
> именно это, но безопасно (серверный антифрод) и в существующей архитектуре.

---

после успешного ответа сервера — как в `purchaseCommunityPackWithShards`).

## 1. Триггер показа — «Ежедневная задача»

**Единственный триггер в v1:** опрос появляется как одна из ежедневных задач на
экране заданий (`app/daily_tasks_screen.tsx`), тип задачи `survey`.

### 1.1. Правила появления
- Опрос — **не каждый день**. Появляется, только когда выполнены ВСЕ условия:
  1. на сервере есть хотя бы один **активный** опрос (`enabled: true`), который
     данный пользователь ещё не проходил;
  2. пользователь подходит под **аудиторию** опроса (см. §4 targeting);
  3. с момента прошлого показанного опроса прошло ≥ `minDaysBetweenSurveys`
     (конфиг, дефолт 7) — чтобы не спамить.
- В один день показывается **максимум один** опрос-задание.
- Опрос-задание **не занимает** слот обычной задачи для «Забрать всё за 3 задания»
  — это отдельная бонусная карточка сверху (не ломать существующую экономику
  `daily_tasks_all`). *(решение: не смешивать с наградой за 3 задачи)*

### 1.2. Жизненный цикл карточки
- Показана → пользователь тапает «Пройти опрос» → открывается экран опроса
  (`app/survey_screen.tsx`, новый) → отвечает на все вопросы → «Отправить».
- После успешного ответа сервера: карточка помечается `claimed`, осколки
  зачислены, показывается тост «+N 💎 за опрос».
- Если пользователь закрыл опрос не завершив — прогресс не сохраняется, задача
  остаётся доступной в тот же день (можно вернуться).

> **На будущее (НЕ в v1, вынести в бэклог):** триггеры «спящим/ушедшим»,
> «после отмены подписки», «разово новичкам». Архитектура данных (§5) должна их
> допускать без переделки, но UI/логику показа для них в v1 НЕ делаем.

## 2. Как всё засчитывается (антифрод)

Полностью повторяет модель `vip_survey.ts` + `dailyTasksAllShardsClaim`.

### 2.1. Отправка ответа
Новая callable-функция `submitShardSurvey` (`functions/src/shard_survey.ts`):

1. `request.auth?.uid` обязателен → иначе `unauthenticated`.
2. `surveyId` должен совпадать с **активным** опросом из конфига → иначе
   `invalid-argument: unknown_survey`.
3. `answers` валидируются по каталогу вопросов ЭТОГО опроса (как `normalizeAnswers`):
   - для вопроса с вариантами `optionId` обязан быть из списка `options`;
   - для `textOnly`-вопроса обязателен непустой `comment` (trim, ≤500 симв.);
   - каждый ответ обрезается по длине; лишние поля игнорируются.
4. Разрешение стабильного uid: `resolveStableUidForAuth` (как в vip_survey).
5. Транзакция:
   - читаем `shard_survey_responses/{surveyId}__{stableUid}`;
   - если ответ уже есть и `rewardGranted === true` → **не начисляем повторно**,
     возвращаем `{ ok: true, alreadyGranted: true, reward: 0 }` (ответы можно
     пересохранить с `resubmittedAt`, но осколки — нет);
   - иначе: пишем ответ + начисляем осколки через тот же путь, что
     `dailyTasksAllShardsClaim` (идемпотентный delta с `reason: 'survey_completed'`,
     `opId` = `survey_${surveyId}_${stableUid}`), возвращаем новый баланс.
6. Возврат клиенту: `{ ok, alreadyGranted, reward, balanceAfter, shardsUpdatedAtMs }`.

### 2.2. Идемпотентность и rate-limit
- **Идемпотентность:** id документа ответа = `${surveyId}__${stableUid}` →
  один пользователь = один зачёт за конкретный опрос. Повторная отправка не
  плодит осколки.
- **Rate-limit:** переиспользовать паттерн `client_reports.ts` (окно/лимит на uid),
  напр. max 20 сабмитов опросов в сутки на uid — защита от спама/скриптов.
- **Клиентская защита от даблтапа:** кнопка «Отправить» блокируется на время
  запроса (как в существующих экранах покупок).

### 2.3. Награда
- Источник в каталоге: `ShardSource = 'survey_completed'`, значение в
  `SHARD_REWARDS` — **фикс, дефолт `3`** *(решение владельца: фикс осколки)*.
- Сервер начисляет ровно `SHARD_REWARDS.survey_completed`. Клиент это число НЕ
  задаёт (не доверяем клиенту сумму).
- `bumpLifetimeShardsEarned` вызывается при начислении (учёт lifetime, как у
  прочих источников).

## 3. Экран опроса (клиент)

Новый файл `app/survey_screen.tsx` + данные опроса приходят с сервера (см. §4.2).

- Заголовок опроса + подзаголовок «Ответь на N вопросов, получи 💎N».
- Вопросы по одному или списком (реюз стиля существующих экранов; **без обводок
  контейнеров** — правило проекта `design_no_borders_tone_only`).
- Типы вопросов: `single_choice` (варианты), `text` (свободный текст, ≤500).
- Прогресс-индикатор (1/9 и т.д.).
- Кнопка «Отправить» активна, только когда все обязательные вопросы отвечены.
- После успеха: `hapticSuccess`, тост «+3 💎», возврат на экран заданий, карточка
  → `claimed`.
- Ошибки сервера маппятся в человекочитаемый тост (мультиязычно, как
  `formatCommunityPurchaseError`): unknown_survey → «Опрос уже недоступен»,
  unauthenticated → «Нужен вход в облако», уже пройден → «Опрос уже пройден».
- Локализация всех строк UI (ru/uk/es/pt-BR/vi/id/tr/pl — как в проекте).

## 4. Редактор опросов + доставка контента (без релиза)

*(решение владельца: редактор опросов нужен)*

Вопросы НЕ зашиваются в клиент. Они лежат в конфиг-документе Firestore и
редактируются из админки — по образцу `arena_season_config.ts`.

### 4.1. Модель опроса (конфиг)
Коллекция `shard_surveys/{surveyId}`:
```
{
  surveyId: string,           // напр. 'onboarding_impression_v1'
  enabled: boolean,           // вкл/выкл без релиза
  title: LocalizedString,     // {ru, uk, es, ...}
  subtitle: LocalizedString,
  rewardShards: number,       // дефолт 3; сервер берёт из конфига, НЕ из клиента
  minDaysBetweenSurveys: number,  // глоб. антиспам, дефолт 7
  audience: {                 // targeting (§4.3)
    tier?: 'free' | 'premium' | 'any',
    minLessons?: number,
    maxLessons?: number,
    platforms?: ('ios'|'android')[],
  },
  questions: [
    { id: string, type: 'single_choice'|'text',
      text: LocalizedString,
      options?: [{ id: string, label: LocalizedString }] }
  ],
  createdAtMs, updatedAtMs, updatedBy
}
```

### 4.2. Доставка на клиент
- Callable `getActiveShardSurvey({ platform, stableId })`:
  - возвращает первый подходящий активный опрос, который пользователь ещё не
    проходил и который проходит targeting + `minDaysBetweenSurveys`;
  - если нет — `{ survey: null }` (тогда карточка-задание не показывается).
- Клиент кэширует ответ на день (как прочий контент через реестр-аксессоры —
  правило Performance Bible: ленивый контент через registry).

### 4.3. Targeting (аудитория)
Сервер фильтрует по `audience` на основе `users/{uid}.progress`:
- `tier`: free / premium (реюз `hasPremiumOrVipAccess` из vip_survey);
- `minLessons/maxLessons`: по числу пройденных уроков;
- `platforms`: ios/android.
v1 может ограничиться `tier: 'any'` + без ограничений — но поля закладываем.

### 4.4. Валидация редактора
- surveyId — `^[a-z0-9_]+$`, уникален.
- ≥1 вопрос; каждый `single_choice` — ≥2 варианта; каждый `text` — без вариантов.
- Все локализованные поля минимум с `ru` (fallback-язык проекта).
- rewardShards в диапазоне 1..20 (защита от опечатки «300»).
- Запись только для admin (проверка прав — как у прочих admin-callable).

## 5. Схема данных (Firestore)

```
shard_surveys/{surveyId}                     ← конфиг опроса (редактируется в админке)
shard_survey_responses/{surveyId}__{uid}     ← один ответ на опрос от юзера
  {
    surveyId, uid, authUid,
    answers: { [questionId]: { optionId?, comment? } },
    answerQuestionIds: string[],
    platform, appVersion,
    rewardShards, rewardGranted: boolean,
    submittedAt, submittedAtMs,
    resubmittedAt?, resubmittedAtMs?
  }
shard_survey_stats/{surveyId}                ← агрегаты для быстрой сводки (см. §6.1)
  {
    totalResponses: number,
    perQuestion: { [questionId]: { [optionId]: count } },
    lastResponseAtMs
  }
```
- Ответы удаляются при удалении аккаунта — добавить `shard_survey_responses`
  в список коллекций `account_delete.ts` (как `subscription_cancel_surveys`).

## 6. Админка (`admin/index.html`, раздел «Опросы»)

*(решения владельца: сводка + лента сырых + редактор + CSV)*

### 6.1. Сводка ответов (аналитика) — главный экран раздела
- Список опросов с бейджем «активен/выключен» и `totalResponses`.
- По выбранному опросу — по каждому вопросу с вариантами: распределение ответов
  **в % и абсолютных числах**, столбики/бары. Для `text`-вопросов — счётчик
  ответов + переход в ленту.
- Источник: `shard_survey_stats/{surveyId}` (агрегат обновляется сервером в той
  же транзакции сабмита — инкремент `perQuestion[qid][optionId]`), чтобы админка
  не считала по всем документам вживую.
- Верхние метрики: сколько всего прошли, за 24ч / 7д (как в
  `admin_daily_digest.ts`).

### 6.2. Лента сырых ответов
- Хронологическая лента `shard_survey_responses` по выбранному опросу.
- Каждая строка: дата, платформа, ответы по вопросам, **раскрытые текстовые
  комментарии** (главная ценность — живые формулировки).
- Пагинация/лимит (как прочие ленты в админке); поиск по тексту комментария.

### 6.3. Редактор опросов
- Список опросов + «Создать опрос».
- Форма: surveyId, локализованные title/subtitle, rewardShards,
  minDaysBetweenSurveys, audience, конструктор вопросов
  (добавить/удалить вопрос, тип, локализ. текст, варианты).
- Тумблер `enabled` — включить/выключить опрос **без релиза приложения**.
- Кнопка «Сохранить» → пишет `shard_surveys/{surveyId}` через admin-callable
  с валидацией §4.4.

### 6.4. Выгрузка CSV
- Кнопка «Скачать CSV» по опросу: колонки = `uid, дата, платформа, <q1>, <q2>, …`,
  где ячейка — выбранный optionId или текст комментария.
- Генерация на клиенте админки из уже загруженной ленты (или отдельный
  admin-callable, если объёмы большие).

## 7. Edge-cases и правила

- **Опрос выключили, пока юзер его открыл:** сабмит вернёт `unknown_survey` →
  тост «Опрос уже недоступен», осколки не начисляются, карточка исчезает.
- **Повторная отправка того же опроса:** ответы могут перезаписаться
  (`resubmittedAt`), осколки — НЕ повторяются (`rewardGranted` гейт).
- **Смена аккаунта:** ответы и «пройдено» привязаны к stableUid — при смене
  аккаунта прогресс опросов корректно разъезжается (реюз `resolveStableUidForAuth`).
- **Оффлайн:** карточка показывается из кэша; сабмит без сети → тост «нет
  соединения», задача остаётся доступной.
- **Экономика:** новый источник осколков `survey_completed` не должен ломать
  существующие тесты экономики — добавить целевые тесты, не трогая чужие.
- **Дизайн:** без обводок контейнеров, тон/градиенты (правило проекта).
- **Звук:** клик-звук только на управляющих кнопках, не на вариантах ответа
  (правило `ui_sounds_only_on_controls`).
- **Perf:** контент опроса — ленивый, через registry-аксессор; экран не грузит
  фон в неактивном состоянии (Performance Bible).

## 8. Тесты (обязательны)

- `submitShardSurvey`: валидация каждого типа вопроса, отказ на unknown_survey,
  идемпотентность награды (второй сабмит → reward 0), rate-limit.
- Начисление осколков ровно `SHARD_REWARDS.survey_completed`, вызов lifetime-bump.
- Targeting: free/premium/lessons/platform фильтры.
- `getActiveShardSurvey`: не отдаёт уже пройденный / выключенный / не по аудитории.
- Агрегат `shard_survey_stats` инкрементится верно.
- account_delete чистит `shard_survey_responses`.
- daily_tasks: карточка `survey` появляется/не появляется по правилам §1.1.

## 9. Что НЕ входит в v1 (бэклог)

- Триггеры «спящим», «после отмены подписки», «новичкам» (архитектура готова,
  логику показа не делаем).
- A/B опросов, ветвление вопросов (skip logic), рейтинговые шкалы (NPS 0–10).
- Пуш-уведомление «пройди опрос».
- Награда, зависящая от типа опроса (в v1 — фикс из конфига опроса).

## 10. План реализации (порядок)

1. **Сервер-ядро:** `shard_survey.ts` (`submitShardSurvey`, `getActiveShardSurvey`),
   конфиг-модель, коллекции, источник осколков `survey_completed`. + тесты.

3. **Админка:** раздел «Опросы» — сводка, лента, редактор, CSV.
4. **Интеграции:** account_delete чистка, опц. дайджест-хук, локализации.
5. **Проверка:** тесты зелёные, экономические тесты не сломаны, ручной прогон
   опроса на девайсе.
