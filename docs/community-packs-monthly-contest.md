# Наборы месяца — правила и проверка

## Правила для участников

Создавай и публикуй наборы: другие участники смогут добавлять их себе и заниматься по ним. Участники выбирают лучшие наборы сердечками.

Первый конкурс начинается 1 ноября 2026 года в 00:00 UTC. До этого экран показывает «До начала конкурса» и число оставшихся дней, без выдуманных мест и результатов. Далее каждый конкурс длится календарный месяц: следующий начинается первого числа. Во время конкурса отображается «До конца конкурса».

Набор участвует каждый календарный месяц по UTC, пока ни разу не занял 1, 2 или 3 место. После любого призового места он навсегда исключается из следующих конкурсов — даже если награда ещё не получена. В рейтинг входят только новые сердечки этого месяца, а не общий счёт. Старые сердечки не переносятся. Поддержать чужой набор сердечком можно сразу, без добавления себе. Один участник может поставить набору одно сердечко и затем убрать его. За собственный набор голосовать нельзя.

После окончания месяца три набора с наибольшим числом сердечек получают награды:

- 1 место — Plus на три календарных месяца.
- 2 место — 2000 монет.
- 3 место — 1000 монет.

При равном числе сердечек выше набор, опубликованный раньше; при совпадении времени порядок определяется постоянным идентификатором набора. Наборы без сердечек и снятые с публикации не награждаются. Если подходящих наборов меньше трёх, награждаются только они.

Набор может занять призовое место только один раз за всё время; его награда выдаётся однократно. Повторное нажатие и повтор запроса после потери связи возвращают ту же квитанцию. Plus продлевает действующий срок; число месяца ограничивается последним днём соответствующего месяца. Бессрочный доступ не отменяется. Монеты поступают в существующий баланс монет; руны и жемчуг не являются валютами приложения.

## Поведение интерфейса

Сердце и число меняются сразу в общем состоянии всех экранов. Повторное открытие использует этот же снимок, а локальная загрузка не ожидает сеть. Подтверждённый отказ записи откатывает сердце и число во всех местах с сообщением. Записи разных наборов на диск выполняются последовательно. Смена аккаунта очищает снимки и запрещает применение старых ответов.

Кнопка «Назад» присутствует в экране набора и в демонстрационном экране; используется общая позиция кнопки приложения. Пьедестал передаёт идентификатор выбранного набора.

## Серверный контракт

`pack_likes` и числовой счётчик меняются атомарно: отдельно нарастить счётчик нельзя. Правила проверяют владельца голоса, запрет собственного голоса и серверное время. Добавлять набор себе перед сердечком не требуется.

`contest_votes/{monthId}_{userId}` фиксирует отдельное состояние голоса за каждый месяц; поля `monthId`, `userId`, `liked`, `updatedAt`. Запись разрешена только вместе с реальным изменением членства лайка. Существующее сердечко нельзя просто перенести в следующий месяц. После окончания месяца клиент не меняет этот снимок. Сервер считает только записи внутри границ месяца. `community_contest_winners/{packId}` атомарно фиксирует первое призовое место вместе с итогами и квитанцией; следующая финализация исключает этот набор. Пьедестал получает месячный счёт через `communityMonthGetRanking`, общий счёт каталога не используется. Итоги используют снимки голосов, а не доверяют отображаемому счётчику. Связанные после объединения аккаунты считаются одним участником. Приватная квитанция прежнего аккаунта остаётся доступна его каноническому владельцу.

Выдача монет, запись журнала и квитанция коммитятся одной транзакцией. Для Plus одной транзакцией записываются срок, проекция доступа и квитанция. Обновление публичного значка Plus выполняется после коммита и не может отменить приз.

## Выпуск — ещё не выполнен

Изменения проверяются локально; серверные функции и Firestore Rules не опубликованы. Конкурс по умолчанию выключен на сервере, обычные лайки продолжают работать без нового протокола.

`community_contest_config/current` — закрытая для клиентских изменений настройка `enabled` и `firstFullMonth`. Активировать её допустимо только после совместного выпуска клиента, правил и функций. Старые клиенты без записи `contest_votes` требуют обязательного обновления перед включением. Нельзя выдавать награды за неполный месяц, за который нет защищённой истории голосов. `firstFullMonth` задаёт первый целиком защищённый месяц; это условие выпуска, а не утверждение о состоявшемся запуске.

Перед выпуском: проверить опубликованный контракт, порядок обязательного обновления, выбранный первый полный месяц, индексы запросов и видимость призового окна только в открытом разделе. Реальные призы и реальные данные пользователей во время проверки не изменялись.
