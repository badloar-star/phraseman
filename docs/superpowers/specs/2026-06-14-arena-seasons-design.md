# Дизайн: Сезоны Арены + Топ-100 + удержание на потолке (Легенда III)

Дата: 2026-06-14
Статус: утверждён к реализации (ожидает вычитки спека пользователем)

## Проблема

Из content-репорта (юзер Janitor, Lv36, Premium): на Легенде III (потолок ранга) играть
дальше незачем — выше ничего нет, прогресс упирается в стену, интерес пропадает. Карточка
рейтинга показывает бессмысленное `X/3 до повышения`. (Связанный баг отката Легенда III→Легенда I
уже починен отдельно — см. [[phraseman_arena_rank_duplicate_math]].)

## Цель

Дать игроку на вершине причину продолжать играть и **удерживать** позицию: сезонный сброс
(квартал) + соревнование за места (глобальный топ-100) + награды за сезон + торжественные
модалки. Тон текстов — строго по `docs/personal-plans-copy-style.md` (спокойный тренер,
без жаргона, без обещаний по календарным датам — срок только относительный «через N дней»).

## Ключевое решение по архитектуре (Вариант A)

SR (Season Rating, «очки сезона») начисляются **только когда игрок достиг Легенды III**.
До потолка — обычная звёздная лестница без изменений (новичков не трогаем). На потолке вместо
звёзд работает SR. Это прицельно лечит «потолок-тупик», бережёт низы и переиспользует
существующую инфраструктуру. НЕ создаём «второй ранг» (ранг один; SR — надстройка, видимая
только наверху).

Отвергнуто: B (сквозной SR с Бронзы — крупный рискованный рефактор ядра звёзд),
C (отдельный параллельный сезонный ранг — путаница «какой ранг настоящий»).

## Секция 1 — Модель данных

Понятия:
- **SR** — числовой рейтинг, копится только на Легенде III. Победа +SR, поражение −SR (пол 0).
- **Сезон** — квартал (3 месяца). `seasonId` (напр. `2026-Q3`), `startsAt`, `endsAt`, `status`.
- **peakSR / seasonPeakRankIndex** — лучшее достижение за сезон. Награда считается по ПИКУ,
  а не по финалу (один неудачный вечер в конце не отнимает заслуженное — уважительный тон).

Хранилище (всё по существующим паттернам, минимум нового):
- `arena_profiles/{uid}` — новые поля: `sr`, `peakSR`, `seasonId`, `seasonPeakRankIndex`,
  `lastSeasonReward`. (Клиент в `arena_profiles` обычно не пишет; SR пишет сервер в матч-
  транзакции, а для бот-матчей — клиентская `runBotArenaProfileTransaction`, как ранг сейчас.)
- `arena_seasons/{seasonId}` — мета сезона (один активный).
- `arena_season_leaderboard/{seasonId}/entries/{uid}` — топ-100: uid, name, sr, peakSR, аватар/
  рамка/аура (как hill-топ).
- `arena_season_claims/{seasonId}_{uid}` — идемпотентность выдачи награды (как `league_chest_claims`).
- `arena_season_hall/{seasonId}` — зал славы топов сезона (навсегда).

Числа (через Remote Config, крутятся без релиза): SR за победу +25, поражение −20, пол 0,
ничья 0. Бот-матч — половина за победу (+12), поражение −20.

## Секция 2 — Сезонный сброс (мягкий откат на −N рангов)

Крон `arenaSeasonRolloverCron` в момент `endsAt`: закрывает старый сезон, открывает новый.

Ранг = индекс 0–23 (Бронза I=0 … Легенда III=23). Откат:
```
newIndex = max(FLOOR_INDEX, oldIndex − ROLLBACK_STEPS)
```
- `ROLLBACK_STEPS = 3` (Легенда III→Грандмастер III; Серебро II→Бронза II).
- `FLOOR_INDEX = Бронза III (2)` — ниже не опускаем (новичков не наказываем).
- Звёзды → 0 на новом ранге.

SR: `peakSR` уже зафиксирован → по нему награда; `sr/peakSR/seasonPeakRankIndex` обнуляются,
`seasonId` переписывается.

Надёжность:
- Крон идёт БАТЧАМИ по `arena_profiles`, каждый профиль помечается новым `seasonId` →
  идемпотентно (перезапуск после падения безопасен; известная боль с OOM-кронами учтена).
- Награда выдаётся НЕ в кроне, а лениво при заходе игрока (claim, как `leagueChestClaim`).
  Крон только фиксирует «сезон закрыт» и считает финальный топ-100.

Чистая функция: `applySeasonRollback(tier, level, steps, floorIndex) → {tier, level, stars:0}`
в `functions/src/arena_season.ts`, покрыта юнит-тестами. Никакой инлайн-математики.

## Секция 3 — Соревнование за места: SR на потолке + топ-100

Начисление SR — в существующей матч-транзакции, без новых триггеров:
- Был ДО матча на Легенде III → SR вместо звёзд: победа +25, поражение/последнее −20 (пол 0),
  ничья/не последний 0. `peakSR = max(peakSR, sr)`.
- Не на потолке → всё как сейчас (звёзды).
- `seasonId` устарел → перед начислением `sr/peakSR` обнуляются, `seasonId` переписывается
  (ленивая инициализация, если крон ещё не дошёл).

КРИТИЧНО (урок из бага отката): SR-математика — ОДНА чистая функция
`applySeasonRatingDelta(sr, peakSR, outcome, isBot)`, зовётся из сервера (`onArenaSessionFinished`)
И из клиентского бот-пути (`runBotArenaProfileTransaction`). Один источник правды, один тест.

Топ-100 — онколл `arenaSeasonGetTop` (копия `arenaHillGetDailyTop`): читает
`arena_season_leaderboard/{seasonId}/entries`, сортировка по `sr` desc, лимит 100, обогащение
косметикой тем же кодом. Возвращает `{ seasonId, endsAtMs, myPlace, mySR, entries[] }`
(`myPlace` даже если ниже 100-го).

Бот-матчи дают SR в половинном размере (+12/−20): ноль убил бы потолок без живых соперников,
полный размер дал бы фарм топа об ботов. Половина — компромисс, число в Remote Config.

Анти-чит: SR пишется только на потолке и только в матч-транзакции (клиент не накрутит, как и
звёзды сейчас). Rules на `arena_season_leaderboard` — писать только свою строку и только поля
рейтинга (по образцу `arena_profiles`/`arena_hill_thrones`).

Карточка рейтинга на потолке: `SR 340 · #58 в сезоне` + `Сезон 1 · через 12 дней` +
кнопка `Таблица сезона`. Ниже потолка — без изменений.

## Секция 4 — Награды за сезон («Шкатулка сезона»)

Онколл `arenaSeasonClaimReward` (1-в-1 `leagueChestClaim`): claim начисляет награды в
транзакции, пишет `arena_season_claims/{seasonId}_{uid}` (дважды не выдаст), дропы в `progress`
через существующий `buildRewardProgressPatch`, осколки через `userPatch.shards`.

Размер — по ПИКУ за сезон (`seasonPeakRankIndex` + место по финальному SR):

| Пик за сезон | Осколки | Косметика | Титул | Практичное |
|---|---|---|---|---|
| Ниже Легенды III | по рангу (Алмаз/Мастер/ГМ), растущая | — | — | мелкий xp_boost |
| Легенда III | крупнее | сезонная аура | «Легенда сезона N» | energy/бусты |
| Топ-100 SR | ещё крупнее | аура (+рамка позже) | «Топ-100 · Сезон N» | pack_trial/arena_plays |
| Топ-10 SR | макс | эксклюзив-аура | «Топ-10 · Сезон N» | макс бусты |
| #1 SR | макс+бонус | уникальная аура/значок | «Чемпион сезона N» (зал славы) | макс |

Типы дропов — существующий каталог (`shards`, `xp_boost`, `energy_fast_recovery`,
`streak_shield`, `arena_plays`, `pack_trial_48h`, `avatar_aura`, `custom_avatar`, `gold_theme`),
количества из диапазонов лиг (не перекашивать экономику).

Сезонный титул (топ-100/топ-10/чемпион) = **бейдж рядом с ником** (в лидерборде/профиле),
активен до конца СЛЕДУЮЩЕГО сезона, затем гаснет. Хранится в `arena_profiles.seasonBadge`
(`{ seasonId, tier: 'top100'|'top10'|'champion' }`), показывается там же, где ник, через
`titles.ts`-стиль. Топы дополнительно навсегда пишутся в `arena_season_hall/{seasonId}`.

Косметика на старте: из готового каталога (ноль блокеров) + 1-2 НОВЫЕ сезонные ауры кодом
(см. Секцию 4а). Рисованные портретные аватары для #1/топ-10 — ОТЛОЖЕНЫ (нужен художник/
DALL·E); на старте верхушке идёт эксклюзив-аура + зал славы.

## Секция 5 — Модалки и экраны (тексты по библии)

   когда сезон закончится.`; кнопка `Вперёд`.
2. **«Итоги сезона»** (1 раз после смены сезона): загол. `Сезон N завершён`; подзаг. по
   результату (топ-100 / дошёл до Легенды III / лучший ранг); тело `Забери награды за сезон.
   Новый сезон уже начался — ранг немного снижён, чтобы было куда расти.`;

4. **Экран «Таблица сезона»** (`arena_season_leaderboard.tsx`, по образцу hill-топа): 100 строк

5. **Карточка рейтинга** (`arena_rating.tsx`): на потолке заменить `X/3 до повышения` на

- SR за ботов: половина (+12/−20).
- Косметика: на старте из готового каталога + 1-2 новые сезонные ауры кодом; SVG-значок/
  новую рамку пока НЕ делаем.
