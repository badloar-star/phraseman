# Admin 2 integration design

## Решение

Admin 2 становится единственной площадкой для новой административной разработки. Корень Firebase Hosting `admin` открывает Admin 2. Старая админка сохраняется временно как `/legacy.html`, не получает новых функций и удаляется только после подтверждённого покрытия.

## Источники интеграции

- Текущий продуктовый baseline: `7b509cc69`.
- Консолидированный модульный shell и существующие Admin 2 workflows: `codex/admin-language-factory` (`d9dd98dea`).
- Детальная аналитика и её серверные callable-контракты: текущие scoped-файлы из основного рабочего дерева.

Интеграция переносит только Admin 2, связанные admin-only callable-файлы, тесты и аудит-скрипты. Нельзя целиком вливать ветку Language Factory, потому что она содержит независимые runtime/content изменения.

## Информационная архитектура

Первый уровень содержит ровно семь разделов:

1. Обзор.
2. Приложение.
3. Пользователи.
4. Деньги.
5. Контент.
6. Комьюнити.
7. Диагностика.

Подробная аналитика открывается внутри Admin 2, а не в legacy. Раздел `Приложение` первым доказывает полный вертикальный сценарий: чтение реального состояния, понятные loading/empty/error/permission states, preview, причина изменения, подтверждение, серверная запись, audit и откат.

## Безопасность и сохранение функций

- Никакие старые функции не удаляются во время переноса.
- Legacy остаётся доступной по отдельному адресу, но не является основным входом.
- Прямые чувствительные Firestore-записи не копируются в Admin 2.
- RevenueCat, права доступа, модерация, массовые операции и выдача Plus остаются read-only или guarded, пока нет серверного контракта.
- Все динамические данные экранируются; технические ошибки не показываются оператору как сырой текст.

## UX-контракт

Admin 2 следует `docs/design/ADMIN_UI_BIBLE.md`: спокойный светлый интерфейс, SVG-иконки с текстом, один главный CTA на странице, понятные русские подписи, tooltip на hover/focus, видимый focus, WCAG AA и адаптивность на 375/768/1024/1440 px. Горизонтальный promotional journey и декоративные dashboard-паттерны не применяются.

## Критерии готовности фазы

- `/` админ-хостинга открывает Admin 2, `/legacy.html` сохраняет старую админку.
- В legacy отсутствуют новые аналитические панели и script includes.
- Admin 2 имеет семь разделов и рабочие маршруты.
- Детальная аналитика работает внутри Admin 2 и сохраняет честные оговорки о consent, Firebase installations и RevenueCat truth.
- `Приложение` содержит технические работы, обновление и баннеры; хотя бы технические работы проходят полный guarded workflow.
- Migration matrix показывает текущую правду; fallback не маскируется как готовая функция.
- Полные Admin 2 smoke, runtime-state, visible-text, language и route/action проверки проходят на фактических модульных путях.
