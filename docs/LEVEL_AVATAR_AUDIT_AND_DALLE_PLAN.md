# Level Avatars 1-60: Audit And DALL-E Production Plan

Date: 2026-05-18

## Scope

Current level avatars live in `assets/images/levels/`.

Primary runtime maps:

- `constants/avatars.ts`: `AVATARS`, level unlocks, `getBestAvatarForLevel`.
- `components/LevelBadge.tsx`: static level image map.
- `components/AvatarView.tsx`: renders avatars through `expo-image`, usually at 22-82 px.

Reference contact sheets:

- `qa-artifacts/current-level-avatars-1-50.webp`
- `qa-artifacts/level-avatars-41-60.webp`
- `qa-artifacts/level-avatars-audit-1-60-44px.png`

## Technical Audit

- All levels 1-60 exist.
- Current files are WebP with alpha (`yuva420p`).
- Dimensions are inconsistent:
  - Levels 1-34, 36-40: mostly `372x407`.
  - Level 35: `374x411`.
  - Levels 41-50: `445x419`.
  - Levels 51-60: `512x512`.
  - `54-readable.webp` and `55-readable.webp`: `512x512`.
- File sizes range from about 9 KB to 109 KB, average about 24 KB.
- Levels 54 and 55 are already replaced in code with `54-readable.webp` and `55-readable.webp`, which confirms a real readability issue in the original generated numbers.
- The app renders these assets very small in many places, including 22, 28, 32, 36, 44, 52, 54, 56, 62, 68, and 82 px.

## Visual Audit

### What Works

- The set clearly communicates level progression through color and complexity.
- The base hexagonal/gem language is appropriate for a gamified learning app.
- Transparent badges work well in circular avatar frames and profile UI.
- Levels 51-60 have a stronger premium feeling than levels 1-40.

### Main Problems

- The full 1-60 set feels like three different generations rather than one designed system:
  - 1-40: flat colored hex medals.
  - 41-50: ivory/gold prestige badges.
  - 51-60: dense crystal/prism badges.
- Early levels are too simple and look closer to placeholder UI than premium rewards.
- Later levels contain too much internal detail for 44 px rendering.
- Number styling is inconsistent across tiers.
- DALL-E style numbers are not reliable enough for final production, shown by the readable replacements for 54 and 55.
- Canvas sizes and silhouette bounds vary, so perceived scale jumps between tiers.
- Some level jumps feel weaker than they should: 45 is underwhelming, 47-50 are noisy, 58 is a strong color outlier.

## Recommended Art Direction

Keep the core idea: numbered hexagonal/gem medallions with transparent background.

Upgrade it into a single premium system:

- One consistent 512x512 transparent canvas.
- One centered emblem silhouette, occupying about 82-88% of the canvas.
- Numbers added deterministically after generation, not generated by DALL-E.
- Shared typography for all numbers:
  - dark warm fill,
  - bright ivory inner highlight,
  - gold or dark outer stroke,
  - strong contrast at 44 px.
- One lighting model:
  - upper-left soft key light,
  - lower-right depth shadow inside the object,
  - no cast shadow outside the transparent asset.
- Complexity increases every 5 levels, with major prestige jumps every 10 levels.

## Tier System

| Levels | Current Read | New Direction |
| --- | --- | --- |
| 1-10 | pale grey to blue starter hexes | frosted glass novice sigils, clean silhouette, gentle cyan progression |
| 11-20 | blue/purple crystalline hexes | arcane blue-violet gems with deeper bevels and controlled inner facets |
| 21-30 | pink/red/orange facets | rose-to-ember forge badges, stronger core glow and sharper gemstone depth |
| 31-40 | amber/gold geometry | scholar-gold mechanical medallions, rings and sacred geometry but still readable |
| 41-50 | ivory/gold prestige artifacts | master ivory/gold relics, premium metalwork, consistent shape family |
| 51-60 | legendary crystal prisms | legendary celestial crystals, prismatic accents, restrained detail, maximum contrast |

## DALL-E Strategy

Do not ask DALL-E to render the final number. Generate numberless emblems, then overlay the numbers locally. This gives a cleaner, more professional result and avoids broken digits.

Recommended flow:

1. Generate six anchor badges first: levels 10, 20, 30, 40, 50, 60.
2. Pick one winning style direction and refine it.
3. Generate intermediate levels in batches of 10 using the chosen anchor as style reference.
4. Remove chroma-key background or use transparent output workflow if available.
5. Normalize every emblem to `512x512`, same center, same visual bounds.
6. Overlay deterministic numbers.
7. Export as WebP with alpha.
8. QA at 22, 44, 62, and 82 px before replacing app assets.

## Number Overlay Specification

Generate badges without numbers, then render numbers in post-processing.

Number style:

- Font: bold geometric sans, close to Montserrat ExtraBold / Inter Black.
- Fill: `#2A170D` or very dark warm brown.
- Inner highlight: subtle vertical gold/ivory gradient.
- Stroke 1: ivory `#FFF1C0`, 6-8% of canvas width.
- Stroke 2: dark umber `#24130B`, 3-4% of canvas width.
- Optional thin gold outer glint only for levels 41-60.
- Center aligned optically, not mathematically, because two-digit numbers need slight kerning correction.

Critical rule: every number must pass at 44 px before export.

## Per-Level Progression Rules

- Every level must be recognizable as part of one family.
- Adjacent levels should differ, but not look like unrelated badges.
- Every 5th level gets a visible reward jump.
- Every 10th level gets a major prestige jump.
- Levels 50 and 60 must feel like milestone trophies, but 60 must clearly beat 50.
- Do not let decorative facets cross the central number area.
- Do not use tiny radial lines that disappear at 44 px.
- Keep all silhouettes inside a shared bounding box.

## Production Checklist

Before generation:

- [ ] Confirm final art direction with six anchor badges.
- [ ] Decide if numbers are overlaid in a script or design tool.
- [ ] Choose final number font and stroke colors.
- [ ] Choose output size: `512x512`.
- [ ] Choose target format: WebP with alpha.
- [ ] Save current assets before replacement.

For each generated badge:

- [ ] No number, no text, no watermark in the generated emblem.
- [ ] Flat removable background or true alpha.
- [ ] Central area clean enough for the number.
- [ ] Emblem centered.
- [ ] Same perceived scale as neighboring levels.
- [ ] Clear tier color and material.
- [ ] Not too noisy at 44 px.
- [ ] No dark halo/fringe after background removal.

After number overlay:

- [ ] Number is exact and readable at 22 px, 44 px, 62 px, and 82 px.
- [ ] Number does not touch the rim.
- [ ] Stroke contrast works on light and dark badge centers.
- [ ] Level 10/20/30/40/50/60 milestones look stronger than surrounding levels.
- [ ] Levels 54 and 55 no longer require special readable replacement files.
- [ ] File names match `1.webp` through `60.webp`.
- [ ] `constants/avatars.ts` and `components/LevelBadge.tsx` point to the final filenames.
- [ ] App screens render without layout jumps.

Final QA:

- [ ] Contact sheet at original size.
- [ ] Contact sheet at 44 px.
- [ ] In-app check on profile, friends, leaderboard, chat, level gift modal, avatar select.
- [ ] Bundle size check.

## Acceptance Bar

The new set is successful only if:

- It feels like one designed collection.
- It is obviously more premium than the current 1-40 assets.
- It preserves the current hex/gem/numbered reward identity.
- Every number is readable in the smallest real UI sizes.
- The final tier 51-60 looks legendary without becoming noisy.
