# Пик: ступени ужатия верха (компактный подиум → строка этажа → прокрутка страницы), touch lock при уходе с экрана (координатор 15.10)

Governance-ID: TG-564311DBEDE5
Governance-ID: TG-B51099BCDF82

## Outcome
Координатор разрешил компактный подиум по условию и поставил цель: на Pixel 8 и iPhone 390×844 при шрифте 1.3 первый экран показывает окно башни ≥120 dp, карточку «Этаж N» и «Играть», ничего не уходит под док. Порядок ужатия: компактный подиум (−40) → карточка этажа одной строкой (−32) → режим прокрутки страницы. Решение — по rawFit с гистерезисом, без качелей. Заодно 🟡 Ревизора: блокировка страницы при касании окна башни снимается при уходе с экрана (blur), а `wasCompactRef` не пишется в рендере.

## Scope
`components/spire/spire_tower_window.ts` (уровни 0–3), `use_spire_tower_budget.ts` (уровень, нормализация верха окна к полному подиуму, ref в layout-эффекте), `SpirePodium.tsx` (проп `compact`: монеты 44/36, плиты 60/46/34), `SpireHomeScreen.tsx`, `use_spire_tower_touch_lock.ts` (сброс на blur), тесты `spire_tower_window_height`, `spire_dock_always_above_pill`.

## Architecture
rawFit — окно при полном подиуме и полной карточке; уровень: 0 (rawFit ≥ 180), 1 (140…179, компактный подиум), 2 (48…139, подиум и строка этажа), 3 (< 48, всё полное, окно 220, прокрутка страницы). Гистерезис 16 dp на каждой границе. Верх окна башни при компактном подиуме приводится к «полному» прибавкой 40, режим подиума на момент замера запоминается вместе с замером — иначе решение зависело бы от самого себя. Минимум окна 120 на уровнях 0–2 (раньше 220 при rawFit 180…219 давал налезание), 220 на уровне 3.

## Technical debt
По модели (замер Pixel 8 + заголовок 66/86/130·шрифт + подиум) на iPhone 390×844 при шрифте 1.3 шапка страницы одна занимает больше половины экрана: цель «башня+карточка+док на первом экране» физически не достижима, остаётся режим прокрутки. Это вынесено в отчёт координатору.
