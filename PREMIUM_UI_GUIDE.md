# КАК СОЗДАВАТЬ PREMIUM UI ДЛЯ PHRASEMAN

> Этот документ — обязательное чтение перед созданием любого экрана.
> Нарушение правил = технический долг, который придётся возвращать вручную.

---

## 1. ПОЧЕМУ ПРЕДЫДУЩИЙ UI БЫЛ ПЛОХИМ

### 1.1 Архитектурные провалы

**Мёртвый код внутри живого рендера.**
Fallback-ветка (`else` в конце большого тернарника) содержала старый рендер с другими стилями, другой иерархией, другим поведением. Новые режимы добавлялись сверху, старое оставалось снизу. Пользователь мог попасть на сломанный экран без понимания причины.

**Заглушки через `{false && ...}` вместо удаления.**
Закомментированный код остаётся в JSX-дереве. Это не архитектурное решение — это трусость. Мусор надо удалять, а не прятать.

**Дублирование носителей одного смысла.**
`modeSubLabel` ("Вставь пропущенное слово") + `hintPanel` с иконкой и ещё одной инструкцией на том же экране. Мозг пользователя не знает куда смотреть. Один носитель — одно сообщение.

**4 элемента в заголовке конкурируют за внимание.**
Back-кнопка + kicker + H1 + иконка режима + счётчик прогресса. Иконка режима дублирует ModeStrip внутри карточки. Один из них лишний — всегда.

**Написанные инструкции нигде не показываются.**
`chrome.instruction` тщательно заполнялась в `chromeForExerciseType`, но компонент `PlanExerciseModeStrip` принимал только `title` и `iconName`. Ценный UX-текст выбрасывался на входе компонента — месяц работы в корзину.

### 1.2 Типографические провалы

**fontWeight '900' везде — иерархии нет.**
H1, прогресс, заголовок панели, главная фраза, текст кнопок, чипы ответов, счёт — всё 900. Когда всё кричит — ничто не говорит. Иерархия существует только тогда, когда есть контраст.

**`phraseTranslation` fontWeight '800' — мутный текст набран жирнее главного.**
Перевод вторичен по смыслу. Но его weight 800 против weight 900 у главной фразы — разница в один шаг. Это шум, не иерархия.

**`kicker` без letterSpacing — слипшийся uppercase.**
`fontSize: 11, fontWeight: '900', textTransform: 'uppercase', letterSpacing: 0`. Caps + вес 900 + нулевой трекинг = нечитаемое пятно. Базовая типографическая ошибка.

### 1.3 Визуальные провалы

**Несогласованные border-radius — сигнал низкого качества.**
`bigCard` — 28, `feedbackSurface` — 30, `phraseCard` — 30, `panel` — 28, `recorderStack` — 18. Рекордер торчит и выглядит дешевле остального экрана. Несоответствующие радиусы = "mismatched socks".

**`pronunciationOrb` — прямоугольник с именем "orb".**
`borderRadius: 24` на `minWidth: 200` — всегда вытянутый прямоугольник. Orb должен быть `width === height`. Именование лжёт о форме.

**Декоративная линия `liquidRail` без смысла.**
2px accent-полоска между элементами. Не разделяет секции, не визуализирует прогресс, не несёт информации. Pure visual noise.

**Два индикатора прогресса на одном экране.**
Счётчик "2/5" в header + `PlanExerciseProgressRail` внизу. Пользователь видит прогресс дважды — ни один из них не работает как главный.

**Placeholder `●●● ●●● ●●●` вместо loading state.**
Статичные точки без анимации. Пользователь не понимает: это контент или состояние ожидания?

### 1.4 Поведенческие провалы

**30+ кнопок без feedback — только `activeOpacity`.**
`TouchableOpacity` с `activeOpacity 0.78–0.84` — единственный отклик на нажатие. Нет scale, нет border-flash, нет цветового перехода. `TapScale` использовался только для кнопки назад.

**Разблокировка кнопки "Проверить" без анимации.**
Мгновенная смена `backgroundColor` при заполнении. Нет spring, нет Animated.Value. Пользователь не чувствует момент разблокировки — один из самых важных UX-моментов в упражнении.

**Ошибка показывается как обычный статус, только красным.**
`recorderStatusText` без иконки ошибки, без shake-анимации, без выделенного блока. Пользователь может не заметить критическое состояние.

### 1.5 Мышление создателя

Предыдущий UI строился методом "добавь сверху, не трогай снизу". Результат: 15+ мёртвых стилей в StyleSheet (`phraseBuildCard`, `missingWordCard`, `naturalChoiceCard`, `rosettaPromptCard` и другие), которые нигде не применяются в JSX. Слепок истории разработки, встроенный в продакшн-код.

**Корневая причина:** нет архитектурного момента "старое удалено перед добавлением нового". Каждый новый режим = наслоение поверх предыдущего.

## 2. ПРИНЦИПЫ PREMIUM UI — 10 ГЛАВНЫХ ПРАВИЛ

### Правило 1: Один экран — одна иерархия внимания

Каждый экран имеет ровно одну точку входа для глаза. H1 — самый яркий элемент. Всё остальное убывает. Если два элемента одинаково яркие — один лишний.

**Проверка:** прищурить глаза на скриншоте. H1 должен читаться первым, всегда.

### Правило 2: Depth через физику, не через декорацию

Глубина создаётся через градиенты освещения, направленные тени и разницу фонов — не через decorative линии и borders ради borders. Карточка выглядит дорого, когда её верхняя граница светлее остальных (имитация освещения сверху).

**Проверка:** убрать все декоративные элементы. Если карточка стала плоской — depth была декоративной, не структурной.

### Правило 3: Accent в четырёх местах с убывающей opacity

Accent-цвет экрана присутствует минимум в 4 слоях:
- активная иконка / CTA label: opacity 1.0
- selected border: opacity 0.55
- background tint карточки: opacity 0.10
- shadow CTA кнопки: shadowColor = accent, opacity 0.40

Если accent виден только в одном месте — экран незавершён.

### Правило 4: Каждое нажатие имеет физический отклик

Нет нажатия без `scale + opacity + изменение тени`. Это минимум. Correct-ответ добавляет bounce + зелёный border. Wrong — shake + красный border. Disabled убирает тень и gradient полностью.

**Никакого** `TouchableOpacity` без `Pressable` с `scale` или аналогичного механизма.

### Правило 5: Типографическая иерархия через контраст opacity И weight

| Уровень | weight | opacity |
|---------|--------|---------|
| H1 | 700–800 | 1.0 |
| H2 / section label | 600 | 0.90 |
| Body | 400 | 0.65 |
| Caption / hint | 400 | 0.40 |

Правило: любые два соседних уровня различаются на **≥ 0.20 opacity ИЛИ ≥ 200 weight**. Если разница меньше — это шум, не иерархия.

fontWeight '900' используется только для: числовых индикаторов (счёт, прогресс) и одного H1 максимум. Не для всего подряд.

### Правило 6: Меньше = дороже

Каждый элемент на экране — это налог на внимание пользователя. Если можно убрать — убрать. Luxury is space. Два индикатора прогресса = ни один не работает. Две инструкции = ни одна не читается.

**Правило удаления:** если элемент можно убрать и смысл не потеряется — убирать.

### Правило 7: Loading states — точная копия контента

Skeleton повторяет точную форму финального контента: высота, ширина, borderRadius. Shimmer-анимация через LinearGradient. Никаких статичных точек, никаких серых спиннеров в пустом пространстве.

### Правило 8: Анимации входа — stagger, не одновременно

Каждый элемент в списке/сетке входит со смещением: `delay: index * 50ms`. Первые 5 элементов с индивидуальным stagger, остальные вместе с 5-м. Числа анимируются count-up. Bottom sheets — translateY снизу с отдельным backdrop fade.

### Правило 9: Единая система размеров — не нарушать

```
borderRadius:
  bottom sheet: 24dp
  карточки:     16–20dp
  кнопки:       14dp
  чипы:         8–10dp

отступы (кратны 4):
  горизонтальный экран: 16dp или 20dp — ОДИН на весь экран
  padding карточки:     16dp
  gap между карточками: 8dp или 12dp
  gap между секциями:   24dp или 32dp

touch target: минимум 44×44dp
```

### Правило 10: Мёртвый код удаляется — не комментируется, не заглушается

`{false && ...}` — не решение. Закомментированный блок — не решение. Если код не используется — его нет. Каждый добавленный режим требует удаления предыдущей версии.

## 3. ВИЗУАЛЬНЫЙ ЯЗЫК PHRASEMAN

### Цветовая система (константы — не изменять)

```js
// Фоны
BACKGROUND:   '#0A0A0F'   // основной фон экрана
CARD:         '#111118'   // фон карточки (+7 от фона)
ELEVATED:     '#18181F'   // поднятая поверхность (+7 от карточки)

// Границы
BORDER_BASE:  'rgba(255,255,255,0.08)'   // стандартная граница
BORDER_TOP:   'rgba(255,255,255,0.10)'   // верхняя граница (имитация освещения)
DIVIDER:      'rgba(255,255,255,0.06)'   // разделитель

// Никогда — чистый #000000 или #FFFFFF в качестве основного цвета
```

### Accent-цвета по режимам (один на экран, не смешивать)

| Режим | Accent |
|-------|--------|
| Listen & Choose | #6C8EFF (синий) |
| Missing Word | #A78BFA (фиолетовый) |
| Phrase Build | #34D399 (зелёный) |
| Pronunciation | #F472B6 (розовый) |
| Natural Choice | #FBBF24 (янтарный) |

### Типографическая шкала

```
// Не использовать fontWeight '900' для текстового контента
// '900' только для: числа прогресса, счёт, streak

H1 (главная фраза):     fontSize 22–24, fontWeight '700', opacity 1.0
H2 (заголовок режима):  fontSize 16–18, fontWeight '600', opacity 0.90
Body (инструкция):      fontSize 14–15, fontWeight '400', opacity 0.65
Caption (подсказка):    fontSize 12–13, fontWeight '400', opacity 0.40
Kicker (uppercase):     fontSize 11, fontWeight '700', letterSpacing 1.5, uppercase
```

### Карточка (шаблон)

```js
{
  backgroundColor: '#111118',
  borderRadius: 16,
  borderWidth: 1,
  borderColor: 'rgba(255,255,255,0.08)',
  borderTopColor: 'rgba(255,255,255,0.10)',
  shadowColor: '#000000',
  shadowOffset: { width: 0, height: 4 },
  shadowOpacity: 0.30,
  shadowRadius: 12,
  elevation: 6,
  padding: 16,
}
// Для selected/CTA карточки: shadowColor = ACCENT, shadowOpacity: 0.40
```

### CTA кнопка (шаблон)

```js
{
  borderRadius: 14,
  paddingVertical: 16,
  paddingHorizontal: 24,
  borderWidth: 1,
  borderColor: 'rgba(255,255,255,0.18)',
  shadowColor: ACCENT,
  shadowOffset: { width: 0, height: 6 },
  shadowOpacity: 0.40,
  shadowRadius: 16,
  elevation: 10,
}
// label: fontWeight '700', fontSize 17, color '#fff', opacity 1.0
```

### Inner glow (glass highlight — обязателен для карточек)

```js
// LinearGradient поверх карточки, position: 'absolute', pointerEvents: 'none'
// from: rgba(255,255,255,0.07) at 0%
// to: rgba(0,0,0,0) at 40%
// direction: top to bottom
```

## 4. АЛГОРИТМ СОЗДАНИЯ КАЖДОГО РЕЖИМА

### Шаг 1: Подготовка (до первой строки кода)

- [ ] Определить accent-цвет режима (из таблицы выше)
- [ ] Выписать все текстовые элементы экрана и назначить им уровень (H1/H2/Body/Caption)
- [ ] Перечислить все интерактивные элементы и их состояния: default / pressed / correct / wrong / disabled / loading
- [ ] Определить единый горизонтальный padding (16dp или 20dp — один на весь экран)
- [ ] Убедиться что нет дублирования смысла: одна инструкция, один индикатор прогресса, одна иконка режима

### Шаг 2: Структура рендера

```
Screen
├── Header (back + title + progress — максимум 3 элемента)
├── ProgressRail (один, не два)
└── ScrollView / FlatList
    └── ExerciseCard
        ├── ModeStrip (иконка + eyebrow + instruction — показывать chrome.instruction)
        ├── ContentArea (главная фраза, перевод, контекст)
        ├── InteractionZone (чипы, инпут, запись)
        └── SubmitButton
```

Одна ветка рендера на режим. Никакого fallback с устаревшим UI. Если добавляется новый тип — старый код удаляется.

### Шаг 3: Интерактивные состояния (реализовать все)

```js
// PRESSED (Reanimated/Animated):
scale: 0.96, opacity: 0.82, shadowOpacity: shadowOpacity * 0.50

// CORRECT (после проверки):
border → ACCENT_GREEN (#34D399) за 150ms
scale bounce: [1.0, 1.04, 0.98, 1.0] за 300ms
checkmark scale-in за 200ms с delay 100ms

// WRONG:
border → ERROR_RED (#F87171) мгновенно
shake: translateX [-8, 8, -6, 6, -4, 4, 0] за 350ms

// DISABLED:
backgroundColor: CARD без gradient
borderColor: 'rgba(255,255,255,0.05)'
shadowOpacity: 0, elevation: 0
contents opacity: 0.30
```

### Шаг 4: Проверка accent в 4 местах

Пройтись по экрану и найти все 4 слоя. Если какой-то отсутствует — добавить.

### Шаг 5: Удалить всё лишнее

Запустить mental-test: что произойдёт если убрать каждый элемент? Если ничего — убрать.
