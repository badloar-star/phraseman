# AVATAR STUDIO — конвейер ассетов кастомизатора (2.5D, зелёный канон v2)

Самодостаточный пайплайн: любой ИИ (ChatGPT, Gemini, Claude…) по этим файлам
генерирует детали аватара, которые ТОЧНО встают в кастомизатор приложения.
Любая сессия любого ИИ продолжает работу отсюда. Для внешнего генератора
главный файл — `000_START_HERE.md` (владелец даёт зип + одну строку команды).

## Три закона конвейера

1. **Паспорт кадра — закон.** `frame_passport.v1.json` (v2): холст 1316×1195
   (альбомный, голова крупно), фон — сплошной зелёный хромакей, лицо по центру,
   поля: 3% сверху, 4% по бокам для головы; плечи могут уходить за нижние края.
   В приложении зелёный снимается — фон рисует само приложение.
2. **Только edit эталона, в два шага.** Деталь генерится (1) НА персонаже
   (`base/base_m.png` — мальчик, `base/base_f.png` — девочка) — это фиксирует
   посадку, свет и позицию; (2) тут же изолированно на чистом #00FF00 в той же
   позиции (`prompts/isolate.md`). Генерить деталь на зелёном БЕЗ шага 1
   запрещено — без персонажа она не сядет по форме/свету/перспективе.
   Цвета волос/одежды — перекрасом скриптом, не генерацией.
3. **FAIL не существует.** Ассет попадает в каталог только через
   `scripts/check_render.mjs` → PASS (зелёный слой — через
   `scripts/key_green.mjs`). Проверки не ослаблять, кривое не принимать «на глаз».

## Карта папки

| Путь | Что это |
|---|---|
| `000_START_HERE.md` | полная инструкция для внешнего ИИ-генератора |
| `frame_passport.v1.json` | числа канона v2: холст, хромакей, поля, lock-зоны |
| `prompts/*.md` | шаблоны промптов по типам деталей + `isolate.md` (шаг 2) |
| `base/` | эталоны `base_m.png`, `base_f.png` (зелёный фон, SHA в манифесте) |
| `inbox/` | сюда скачиваются кандидаты из генератора |
| `catalog/<слот>/` | принятые картинки «на персонаже» (только через PASS) |
| `layers-src/<слот>/` | чистые слои из зелёных изоляций (через key_green) |
| `manifest.json` | реестр каталога: id, слот, SHA-256, подпись, дата |
| `scripts/check_render.mjs` | сторож-приёмщик деталей на персонаже |
| `scripts/key_green.mjs` | хромакей зелёной изоляции + сверка позиции |
| `scripts/publish_catalog.mjs` | публикация в приложение: кеинг баз, запекание портретов |
| `scripts/recolor.mjs` | перекрас принятой детали по маске |

## Рабочий цикл (каждый ассет — пара картинок)

1. Владелец получает от генератора ДВЕ картинки: деталь на персонаже + та же
   деталь на зелёном (см. `000_START_HERE.md`), кладёт в `inbox/`.
2. Приёмка версии «на персонаже»:
   ```
   node content/avatar-studio/scripts/check_render.mjs inbox/файл.png --slot hair --base base/base_m.png --accept --id hair_<имя>_m --label "Подпись"
   ```
3. Приёмка зелёной изоляции:
   ```
   node content/avatar-studio/scripts/key_green.mjs inbox/слой.png --onmodel catalog/hair/<id>.png --base base/base_m.png --accept --id <id>
   ```
4. Публикация: `node content/avatar-studio/scripts/publish_catalog.mjs` —
   базы кеятся в прозрачность, на каждую деталь запекается готовый портрет
   (пиксели эталона + деталь + стирание убранного → кеинг). В приложение уходит
   лёгкий webp с альфой; фон портрета рисует приложение.

## Правила для ИИ-ассистента, который это читает

- Прочти этот файл и `frame_passport.v1.json` ПЕРЕД любой работой с ассетами.
- Не выдумывай свои промпты — бери шаблоны из `prompts/`.
- Не перегенерируй `base/*.png`: замена эталонов = отдельное решение владельца
  (весь каталог сверяется с ними попиксельно и обнуляется при смене).
- Не клади файлы в `catalog/`/`layers-src/` руками и не правь `manifest.json`
  руками — только скрипты приёмки.
- Проверка упала — чини картинку (перегенерацией), а не сторожа.
