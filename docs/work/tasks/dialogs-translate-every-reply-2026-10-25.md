## Outcome

Кнопка «Перевод» у каждой реплики собеседника, для которой перевод есть; перевод — под репликой по тапу, повторный тап скрывает.
Перевода нет (старый сервер / нет в пакете) — кнопки нет, журнал [DIALOG-BUBBLE] reason=no_translation (с источником).
Источники (решение координатора, без отдельного вызова на реплику):
- сценарий: первая реплика — перевод из пакета content.opening.translations[язык интерфейса]; ответы — replyTranslations
  разбора хода (как было);
- свободный разговор: необязательное поле assistantTranslation в ответе хода (та же генерация, делает Ядро).
Отдельную функцию «перевести» — НЕ делаем.

## Scope

- app/dialogue_v2_briefing_model.ts — opening.translation из content.opening.translations по языку интерфейса.
- app/dialogue_v2_session.tsx — перевод первой реплики в ленте.
- components/dialogs/DialogueV2SessionScreen.tsx — перевод ПОД репликой (раньше подменял текст); журнал no_translation.
- app/dialogue_v2_freeform_client.ts — ответ хода принимает необязательное assistantTranslation (старый сервер без поля — как раньше).
- app/dialogue_v2_freeform.tsx, components/dialogs/DialogueV2FreeformScreen.tsx — кнопка и перевод под репликой.
- tests: dialog_translate_every_reply.

## Architecture

Приложение ничего нового серверу не шлёт (запрос хода проверяется сервером по точному набору полей — новое поле сломало бы ход
на старом сервере). Как серверу узнать язык интерфейса — решает Ядро (предложение: прочитать язык из профиля один раз на старте
сессии; или необязательное поле в запросе старта, принимаемое сервером ДО того, как клиент начнёт его слать).
