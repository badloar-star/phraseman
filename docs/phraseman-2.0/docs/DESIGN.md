# Новый интерфейс — бриф после отклонения «Графита»

## Что отклонено
Текущий отзыв владельца: «оно выглядит ... как приложение из интернет 2000х». Это достаточная причина не продолжать направление. В этом пакете нет новых готовых макетов; есть конкретное задание на их создание и проверку. Нельзя переименовать старый mockup и снова выдать его за новый.

## Требуемый результат
Современное мобильное приложение для взрослого пользователя: спокойное, ясное, быстрое. Ровный тёмный фон, минимум цвета, аккуратная иерархия, естественные списки и controls. Не тёмная веб-админка с рамками вокруг каждого числа. Не чёрно-золотой «люкс» по умолчанию. Не стеклянные карточки в несколько слоёв ради эффекта. Полупрозрачность из заметок допустима как простая поверхность; дорогой blur не является требованием.

## Три задания на направления — предложения, не утверждённые UI
A. Контентное: библиотека наборов и продолжение практики в центре, минимум виджетов.
B. Нативное: строгие строки, контекстные действия, bottom sheets только по смыслу, спокойная монохромная навигация.
C. Редакционное: выраженная типографическая иерархия, воздух вокруг главного учебного действия, компактные списки вторичных разделов.

Каждое направление показать на одних и тех же пяти экранах: главная, список наборов, открытый набор/карточка, видео, активность. Предлагаются три направления; владелец просил несколько, поэтому количество можно согласовать, но не заменить одним вариантом. Для демонстрации брать реальные размеры экрана и содержание, не выдуманные цифры успеха/наград. Показать хотя бы одно длинное русское название, смешанную RU–EN пару и состояние без данных.

## Компонентный контракт
Согласовать spacing scale, текстовые роли, button heights, border treatment, icons, navigation, sheet/modal, lists, focus/pressed/disabled/error/loading. Владелец не хочет множество шрифтов и размеров. Рекомендация — одна системно-подобная семья normal/semibold и ограниченное число ролей; обсуждается как интерпретация, а не скрытый отказ от его «двух размеров».

Ни один экран не сохраняется только потому, что «он работает»: работоспособность сохраняет engine, новый UI проверяется отдельно. Карточки/диалоги/тренировки/профиль/статистика/настройки/онбординг/paywall/модалки входят в coverage. После выбора макета сначала создать согласованные компоненты и один вертикальный сценарий, затем переносить остальные экраны.

## Движение
Разрешаемый кандидат: переворот карточки, функциональная навигация, короткая цифра расхода энергии, разовое превращение монеты и спокойное подтверждение Premium. Разовая анимация топ-3 — по решению. Удаляем вечные loops, aura, shakes, полёт валюты, подарочные праздники. Статичный огонь серии не требует непрерывного свечения. Уменьшение движения имеет альтернативу для каждого эффекта.

## Приёмка владельцем и судьёй
Владелец утверждает внешний вид. UX-судья проверяет задачу человека, видимость действий, отсутствие лишнего текста, доступность, длину строк, слабое устройство, loading/empty/error/offline, отсутствие старых декораций. Красивый статичный screenshot не доказывает usability или performance. Дизайн-board этого пакета — рабочий реестр документов, НЕ макет приложения.
