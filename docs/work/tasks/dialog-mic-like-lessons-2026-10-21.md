## Outcome

Решение владельца 21.10 (реестр «Диалоги», B3; репорт №12: «устно ответить в диалоге — пишет недоступно на этом
устройстве, а в уроках записывает»). Микрофон в Диалогах работает на тех же телефонах, что и в уроках: без запрета по
версии Android (≤12). При реальном сбое микрофона — понятное сообщение и ввод текстом (поле текста есть всегда).

## Scope

- app/dialogue_voice_capability.ts (resolveDialogueAsrCapability — общий для старого экрана ai_dialog_session и нового
  use_dialogue_v2_voice_message):
  - убран отказ android_api_unsupported (API ≤ 32);
  - на Android пустой/непроверенный список языков распознавателя (обычно на Android ≤ 12) больше не отказ — пробуем,
    как уроки (use_learning_v2_local_hold_to_talk_v1: живое распознавание проверяет только наличие модуля);
  - явный отказ остаётся, когда список получен и в нём нет нужного языка (exact_locale_missing) и при service_mismatch;
  - журнал [DIALOG-MIC] на каждое решение (платформа, версия, размер списка, итог, причина).
- tests/dialogue_voice_capability.test.ts — новые ожидания.

## Architecture

Реальный сбой после старта (ошибка распознавателя, нет речи, нет разрешения) обрабатывают уже существующие ветки:
not_heard / permission_denied / unavailable → тексты на экране, поле ввода текста доступно всегда.

## Security and privacy

Новых данных и разрешений нет: тот же системный распознаватель и то же разрешение микрофона, что в уроках.

## Technical debt

На старых Android распознаватель может не знать английский — тогда сообщение «не расслышали/недоступно» после попытки,
а не до неё (как в уроках).
