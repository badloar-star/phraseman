## Outcome

Механизм (подтверждён по коду): `timeout 110 bash scripts/safe_commit.sh` → TERM bash'у → `trap cleanup EXIT` удаляет временный
индекс и общий замок, а дочерний `git commit` (GIT_INDEX_FILE=$TMP_INDEX) жив; git перечитывает индекс ПОСЛЕ pre-commit → индекса
нет → пустое дерево → коммит «удалить всё». Пост-сверка только писала «ТРЕВОГА» и не откатывала.

Защита (scripts/safe_commit.sh, раздел 5 переписан):
1. Дерево пишется из временного индекса ДО хуков (`git write-tree`) — дальше работаем с неизменяемым объектом. numstat BASE..TREE
   сверяется с --expect повторно (по объекту, а не по индексу).
2. Жёсткий стоп: число путей в дереве < 90 % HEAD → отказ (SAFE_COMMIT_ALLOW_MASS_DELETE=1 — только осознанно).
3. Критическая секция `trap '' TERM INT HUP` от хуков до сдвига ветки; дочерние процессы наследуют игнор.
4. pre-commit зовётся явно (с GIT_INDEX_FILE временного индекса); после хука дерево из индекса пересчитывается — если не совпало
   с TREE (хук изменил/удалил индекс) → отказ, ветка не двигается.
5. Коммит — `git commit-tree TREE -p BASE` + атомарный `git update-ref <ветка> NEW BASE` (сдвиг только если ветка всё ещё на BASE);
   post-commit зовётся явно после сдвига. Замок ветки «Unable to create …lock» — прежние правила ожидания/снятия.
6. После сдвига — сверка numstat коммита; не совпало → откат `git update-ref <ветка> BASE NEW` + отказ (вместо «ТРЕВОГА»).
Журнал [SAFE-COMMIT] на каждой ветке.
