# Полный аудит Phraseman + исправления — 2026-06-14

Аудит по 4 направлениям (онбординг, код/безопасность, монетизация, UX) дал ~60 находок
от параллельных агентов. После **адверсариальной проверки кода** (каждая находка
перепроверена по полной цепочке, а не по excerpt) подтвердилась лишь часть — остальное
оказалось ложными срабатываниями: агенты видели фрагмент, а не всю систему.

Ключевой урок: **вердикты read-only агентов нужно перепроверять в обе стороны** —
и «РЕАЛЬНА» тоже. Из ~15 «реальных» P1/P2 после проверки осталось 6 настоящих.

## ✅ Исправлено и в master

### Безопасность
- **arena_profiles: клиентская запись запрещена** (`firestore.rules:971` → `allow write: if false`).
  Проверено: ни одного `setDoc('arena_profiles')` в `app/` — пишет только CF (Admin SDK).
  Открытая запись позволяла накрутку `rank.tier/stars/xp`.
- **Контракт-тесты rules сделаны устойчивыми** (`tests/firestore_rules_security.test.ts`):
  соседняя сессия усилила правило (`&& hasNoShardWrites()`), 2 теста пинили точную строку
  и упали. Заменены на regex по префиксу owner+premium-guard. 49/49 зелёные.

### Монетизация (Apple-комплаенс + конверсия)
- **Главный пейвол: «3 дня» больше не захардкожено** (`premium_modal.tsx`). 10+ мест
  (ценники, CTA, hero-заголовки, юр-текст автопродления на 8 языках) теперь берут
  длину триала из стора (`getTrialInfo`/`trialDaysOrDefault`) со склонением по языкам
  (`trialDaysPhrase`/`trialDaysFreePhrase` + `slavicDayWord` для ru/uk/pl). При смене
  триала на 7 дней пейвол не соврёт.
- **Пейвол v2: добавлено раскрытие цены** (`premium_modal_v2.tsx`, Apple 3.2.1(vii)):
  под CTA «Бесплатно N дней, затем €X/период. Автопродление — отмени…». (v2 — QA-превью,
  но правка безвредна и делает превью честнее.)
- **Празднование + энергия после покупки в боевом хуке A/B/C** (`paywall_purchase.ts`):
  хук слал `premium_activated`, но не звал `markCelebrationPending()`/`reloadEnergy()`
  как `premium_modal.tsx`. После оплаты через A/B/C-пейволы был «пустой» экран и
  устаревшая энергия до рестарта. Добавлены оба (celebration — только на покупку,
  energy — и на restore).

### UX (темы)
- **Баннер заморозки серии чинит все Premium-темы** (`app/(tabs)/home.tsx`): холодный
  синий fallback (`#1A3A5C/#4FC3F7/#90CAF9`) заменён на токены темы (`t.accent`,
  `t.bgCard`, `t.textMuted`). На Coral/Ember/Volt/Mint/светлой больше не выбивается.
  Gold/Compass-ветки не тронуты.

### Онбординг (конверсия + аналитика)
- **Трекинг выбора в воронке плана** (`onboarding.tsx` + `analytics.ts`): шаги
  goal/level/minutes слали только `onboarding_step_view` (факт показа), но не выбор.
  Добавлены `onboarding_plan_{goal,level,minutes}_select` + `onboarding_plan_phrase_done`
  (флаг `correct` = сигнал активации). Воронка теперь видит распределения.
- **Контекст плана на экране имени** (`onboarding.tsx`): `nameBranchSubtitle`
  («Личный план подключён…») вычислялся, но не рендерился — покупатель и бесплатный
  юзер видели идентичный экран. Теперь рендерится под заголовком (пустая строка для
  бесплатного потока = ничего). Убран мёртвый закомментированный блок.
- **Симметричная аналитика отказа от плана**: «Продолжить без плана» на planResult не
  трекался, на planPaywall — да. Добавлен `onboarding_continue_free` с
  `from:'plan_result'/'plan_paywall'`.

### Документация
- **Docstring `deleteAccountAndWipe` исправлен** (`auth_provider.ts`): описывал
  несуществующий блокирующий flow («sign out только после подтверждения сервера»),
  хотя код фоновый (осознанно, чтобы Google-вход не висел в loading). Docstring
  приведён к факту; поведение не менялось.

## ❌ Снято после проверки (ложные срабатывания)

| Находка | Почему ложная |
|---|---|
| friendLikeActivity принимает senderStableId из body | Сверяется с `request.auth.uid` (`firebaseAuthUid`), строки 73–77. Подделать нельзя. |
| RevenueCat webhook без HMAC | Есть shared-secret auth (`revenuecat_shards.ts:545–549`), fail-closed + идемпотентность. Официальная схема RC. |
| premium_expiry='0' = подписка не истекает | `'0'` = sentinel «не ограничивать legacy-полем»; реальное истечение через `premium_rc_expiry_ms` (`premium_guard.ts:103`). |
| isPremium в merge-вайтлисте | Это `leaderboard` (admin-only запись по rules), не users. Значок премиума корректно переезжает на основной аккаунт. |
| v2 не в A/B routing | v2 — устаревший дизайн, намеренно убран. Боевой тест: v1 vs A/B/C. v2 только в QA-панели. |
| leaderboard_stats allow read: if true | Только агрегаты-пороги перцентилей (`compute_leaderboard_stats.ts:75–82`), без PII. |
| DEV_MODE/FORCE_PREMIUM хардкод эксплуатируем в проде | Все потребители гашены `!IS_STORE_RELEASE`; в стор-сборке схлопываются в false. Закреплено тестом. |
| Grace-баннер «зафиксировали цену» вводит в заблуждение | ×2 = заявленная будущая цена («скоро будет»), не фантомная старая. Легально, в стор не уходит. |
| Черновые отзывы могут попасть в прод | `includeUnverified=false` по дефолту + явный false в боевых вызовах. |
| Tooltip энергии за край экрана | `Math.min/max` clamp реализован корректно. |
| lessons back→goHome ломает deeplink | Осознанный таб-паттерн (у таба нет стека истории). |
| Home: нули без скелетона | Hydration (`peekHomeScreenHydration`) покрывает горячий старт. |
| Смена плана → неверные минуты | `minutesPerDay` = личный ритм юзера (влияет на объём дня), ортогонален теме плана. Подтягивать минуты плана было бы неверно. |

## ⏸ Отложено осознанно (low-impact / файл занят другой сессией)

- **Home: error-state при сбое сети** — реально (catch только логирует), но кэш/hydration
  показывается (не пустой экран). Файл `home.tsx` активно правит другая сессия — риск
  конфликта выше пользы. Low-impact (оффлайн работает).
- **Home без плана: голая CTA** — реально, но subjective; это большой UX-редизайн
  (progressive disclosure), не точечный фикс.
- **accessibilityLabel на ~8–15 элементах** (home/lessons) — реально, low; те же файлы заняты.
