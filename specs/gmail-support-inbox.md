# Gmail Support Inbox — входящая почта поддержки в админке + ИИ-ответы

## Objective

Ловить входящие письма поддержки с ящика **support.phraseman@gmail.com** (отдельный
личный Gmail), складывать их в Firestore, показывать в админке Phraseman отдельной
вкладкой, и давать возможность отвечать: ИИ пишет черновик ответа (по кнопке — на одно
письмо или на все новые сразу), владелец проверяет/правит и отправляет. К каждому ответу
автоматически цепляется редактируемая подпись.

Существующая вкладка **Support (site)** (`website_contact_inbox`) ловит только форму с
сайта — это ДРУГОЕ и не трогается. Здесь — настоящая входящая почта.

Главный ориентир проекта — **максимальная экономия** (дешёвая модель ИИ, минимум вызовов,
бесплатные квоты Gmail/Firebase, забор почты раз в сутки).

## Requirements

### Доступ к почте
1. Доступ к ящику — по **App Password + IMAP** (не OAuth). Пароль лежит в секрете Cloud
   Functions `GMAIL_SUPPORT_APP_PASSWORD`; логин-адрес — в конфиге/константе
   `support.phraseman@gmail.com`. Пароль НИКОГДА не хранится в коде/гите.
2. Чтение почты — по IMAP с `imap.gmail.com:993` (TLS). Если на окружении Cloud Functions
   исходящий IMAP заблокирован — это фиксируется в логах явной ошибкой (не молчаливый
   провал), и в спеке отмечено как fallback-риск (тогда переход на OAuth Gmail API).

### Забор писем
3. Забор новых писем — **раз в сутки**, крон `gmailSupportPullCron` (по образцу
   `premiumExpiryReminderCron`), регион `us-central1`.
4. Тянуть **только непрочитанные письма из папки INBOX** (`UNSEEN`). Gmail сам отсекает
   спам/промо в другие папки — они не забираются.
5. **Первый запуск**: если в Firestore ещё нет писем, подтянуть последние ~50 писем из
   INBOX (не только непрочитанные), чтобы вкладка не была пустой. Дальше — только новые
   непрочитанные.
6. Идемпотентность: письмо идентифицируется по Gmail `Message-ID` (заголовок) → docId в
   Firestore. Повторный забор того же письма НЕ создаёт дубль (merge/skip по существующему).
7. После успешного забора письмо помечается в Gmail как прочитанное (снять флаг `\Unseen`),
   чтобы следующий крон его не тянул снова. (Если пометка не удалась — дубль всё равно не
   создастся из-за п.6.)
8. Из каждого письма сохраняются: `messageId`, `from` (email + имя), `subject`,
   `bodyText` (текст письма; HTML → текст, обрезка до разумного лимита, напр. 20000 симв.),
   `receivedAt`/`receivedAtMs`, `status`, `lang` (определяется позже при генерации ответа).

### Хранение и вкладка админки
9. Письма хранятся в новой коллекции Firestore `support_inbox`.
10. Новая вкладка админки **«Почта поддержки»** (`tab-gmail-support`, id-контейнеры
    `gsi-*`), по образцу существующих вкладок (`class="reports-tab"`, ленивая загрузка в
    `switchTab`). Не трогает вкладку Support (site).
11. Каждое письмо в списке показывает: отправитель, тема, дата, короткий превью текста,
    статус, и (если есть) сгенерированный черновик ответа.
12. Фильтр статусов вверху: **Новые / Отвеченные / Все**. Статусы:
    `new` (пришло, не отвечено) → `answered` (ответ отправлен). Плюс ручной `archived`
    (спам/не требует ответа). Кнопка архивировать/вернуть на каждом письме.
13. Кнопка **«🔄 Проверить почту»** — вручную запускает тот же забор, что и крон (callable),
    чтобы не ждать сутки.

### ИИ-ответы
14. Кнопка **«✨ Сгенерировать ответ»** на каждом письме → ИИ пишет черновик, он
    сохраняется в документ письма (`draftReply`, `draftLang`) и показывается в поле,
    доступном для **ручного редактирования**. Ничего не отправляется автоматически.
15. Кнопка **«✨ Сгенерировать всем»** (вверху) → генерит черновики для всех писем со
    статусом `new` без черновика, **пачкой не больше 25 за одно нажатие** (больше —
    повторным нажатием; сколько осталось — показать). Существующие черновики не перетирает.
16. Кнопка **«📤 Отправить»** на письме → отправляет текущий (возможно, отредактированный)
    текст ответа + подпись; письмо переходит в `answered`, фиксируется `repliedAt`,
    `sentReply`. Кнопка **«📤 Отправить все черновики»** — отправляет все готовые непустые
    черновики по письмам `new`, идемпотентно (уже `answered` пропускает).
17. Ответ отправляется **через тот же Gmail по SMTP** (`smtp.gmail.com:465`, тот же App
    Password), чтобы письмо ушло реально «из support.phraseman@gmail.com», встало в ту же
    цепочку (заголовки `In-Reply-To`/`References` = messageId исходного) и человек увидел
    его в своём треде. From = `support.phraseman@gmail.com` (+ отображаемое имя из подписи
    или константа).
18. Язык ответа — **на языке письма** (ИИ определяет по тексту `bodyText`). Тон — как в
    ответах на репорты: тёплый, от лица команды, без канцелярита, по делу, без обещаний
    сроков.
19. В ИИ уходит только **тема + тело письма** (обрезанные), не вся переписка — экономия
    токенов.

### Подпись
20. Редактируемое поле **подписи** в этой вкладке. Значение хранится в Firestore
    (`admin_config/support_inbox` → `signature`), меняется в любой момент кнопкой
    «Сохранить подпись». Одна подпись на все языки.
21. Подпись **автоматически добавляется в конец каждого отправляемого ответа** (ИИ её НЕ
    генерирует и НЕ видит — цепляется на этапе отправки). В превью черновика видно, что
    подпись будет добавлена.

### Экономия ИИ
22. Модель ИИ — дешёвая, через существующий `openai_jobs_config.ts`: новый job-тип
    `support` (дефолт `gpt-4o-mini` или `gpt-4.1-nano`), с kill-switch (`assertJobEnabled`)
    и дневным капом. Один вызов OpenAI на один сгенерированный ответ. Ключ — существующий
    секрет `OPENAI_API_KEY`.

### Безопасность/доступ
23. Все callable-функции — **admin-only** (проверка `request.auth?.token?.admin === true`,
    как в `report_replies.ts`). Обычный пользователь не может дёргать.
24. App Password и содержимое писем не логируются в открытом виде.

## Constraints

- Стек: Firebase Cloud Functions v2 (TypeScript, `functions/src`), Firestore, админка =
  `admin/index.html` (single-file, Firebase SDK v10 modular, глобальные хелперы `db`,
  `getDocs/collection/query/where/orderBy/limit/doc/getDoc/setDoc/updateDoc`, `escapeHtml`,
  `showToast`, `httpsCallable(functionsUs, ...)`).
- Новые npm-зависимости в `functions/`: библиотека IMAP (напр. `imapflow`) + парсер писем
  (напр. `mailparser`) + SMTP-отправка (напр. `nodemailer`). Установить в `functions/`.
  ⚠️ EAS/lockfile-ловушка: после установки синхронизировать `package-lock.json`.
- НЕ трогать: вкладку/логику Support (site) (`website_contact.ts`, `website_contact_inbox`),
  отправку через Resend (`admin_email.ts`) — она остаётся для рассылок; здесь отправка
  своя (Gmail SMTP), т.к. нужно попасть в тред.
- Отправка писем — outward-facing действие: «отправить» всегда по явной кнопке владельца,
  никакой авто-отправки ИИ-ответов.
- Регистрация функций — реэкспортом в `functions/src/index.ts`; крон — там же по образцу
  `premiumExpiryReminderCron`.
- Максимальная экономия — сквозной приоритет (см. Requirements 3,4,15,19,22).

## Edge cases to handle

- **IMAP недоступен на окружении** → крон/кнопка не падают молча: ошибка в логах +
  осмысленный тост «не удалось подключиться к почте» в админке. Не создаёт битых записей.
- **Письмо без текста / только HTML / только вложения** → сохранить `bodyText` из HTML
  (или пометку «пустое тело»); ИИ-кнопка на пустом теле не зовёт OpenAI зря (тост «нечего
  анализировать»).
- **Очень длинное письмо** → `bodyText` обрезается до лимита перед сохранением и перед
  отправкой в ИИ.
- **Дубликат при повторном заборе** (тот же Message-ID) → пропуск, без второй записи.
- **Отправка ответа не удалась** (SMTP ошибка) → письмо НЕ помечается `answered`, тост с
  ошибкой, черновик сохраняется (можно повторить). Никаких «серебряных» ложных успехов.
- **«Отправить все» / «Сгенерировать всем»** по 0 подходящих писем → тост «нет подходящих
  писем», без вызовов.
- **Кап ИИ исчерпан / job выключен** → `assertJobEnabled` бросает, админка показывает
  понятный тост, другие письма не ломаются.
- **Пустая подпись** → допустимо (просто ничего не добавляется в конец).
- **Первый запуск на пустой коллекции** → тянет ~50 последних; повторный — только новые.
- **Пользователь-не-админ дергает callable** → `permission-denied`.
- **Нет секрета `GMAIL_SUPPORT_APP_PASSWORD`** → `failed-precondition` с понятным
  сообщением (как `OPENAI_API_KEY not configured`).

## Definition of done

- [ ] Новые Cloud Functions компилируются: `cd functions && npx tsc --noEmit` → 0 ошибок.
- [ ] Чистые/тестируемые части (парсинг письма → запись, определение дубля по Message-ID,
      обрезка тела, сборка ответа с подписью, отбор `new`-без-черновика для «всем» с лимитом
      25) покрыты unit-тестами (jest), все зелёные. I/O (IMAP/SMTP/OpenAI) отделено от
      чистой логики, как в `re_engage_push.ts`/`admin_daily_digest.ts`.
- [ ] Весь `admin/index.html` проходит `node --check` (module-скрипт) без синтаксических
      ошибок; новая вкладка + панель + loader присутствуют в DOM (проверка в preview);
      логин-гейт не сломан; консоль без ошибок при загрузке.
- [ ] Функции зарегистрированы в `index.ts` (реэкспорт + крон). `support` job-тип добавлен в
      `openai_jobs_config.ts` (3 места: union, массив, дефолты).
- [ ] Кнопки в админке присутствуют и вызывают правильные callable: «Проверить почту»,
      «Сгенерировать ответ» (одно), «Сгенерировать всем», «Отправить», «Отправить все
      черновики», «Сохранить подпись», фильтр Новые/Отвеченные/Все, архивировать.
- [ ] Живой прогон (за владельцем, после деплоя + установки секрета): письма из
      support.phraseman@gmail.com появляются во вкладке; ИИ-черновик генерится на языке
      письма; отправленный ответ приходит адресату из support.phraseman@gmail.com и встаёт в
      тред; подпись видна в конце; отвеченное письмо ушло из «Новых».
- [ ] Ничего не закоммичено с реальным паролем/ключом; `git status` чистый по секретам.

## Out of scope

- OAuth/Gmail API (используем IMAP+App Password; OAuth — только запасной план, не в этой
  сборке).
- Realtime/частый polling (только раз в сутки + ручная кнопка).
- Авто-отправка ИИ-ответов без проверки владельцем.
- Отдельные подписи под каждый язык (одна на все).
- CSV-экспорт писем.
- Вложения: сохраняем факт письма и текст; работа с файлами-вложениями (скачивание/показ) —
  не в этой сборке.
- Изменение существующей вкладки Support (site) и отправки через Resend.
- Треды/переписка внутри админки (показываем письмо + один ответ; полноценный тред-вид — нет).
