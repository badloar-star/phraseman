# GUSTAV Algorithm Audit 13

Status: `HOLD`

Scope: achievement taxonomy for `achievements_state` split.

## 1. What improved

Gustav now has an executable achievement taxonomy generator:

```text
scripts/gustav_achievement_taxonomy.ts
```

It reads `app/achievements.ts`, extracts `ALL_ACHIEVEMENTS` and classifies every achievement id as:

- `global`;
- `study_target`;
- `mixed`;
- `unknown`.

It writes:

```text
docs/gustav/runs/2026-05-19_fr_inventory_v0a1/audits/achievement_taxonomy.json
docs/gustav/runs/2026-05-19_fr_inventory_v0a1/audits/achievement_taxonomy.md
```

The run validator now checks this artifact structurally:

- schema version;
- run id;
- non-empty entries;
- duplicate ids;
- scope and migration action;
- target entries include `legacyTarget=en` and `targetPath`;
- no `PASS` while blocker achievement entries remain.

## 3. Confirmed blockers

### GVA-052A.1: 101 achievements are target-specific

These must move under:

```text
progress/targets/{studyTarget}/achievements/<id>
```

Examples:

- lesson achievements;
- quiz achievements;
- CEFR medal achievements;
- combo answer streak achievements;
- exam achievements;
- flashcard learning achievements;
- trainer and active recall achievements;
- daily phrase achievements.

Legacy flat `achievements_v1` values for these ids may map only to English.

### GVA-052A.2: 57 achievements are mixed-policy

These cannot be safely placed until product policy is explicit.

Main groups:

- account XP achievements, because XP is currently generated by target-learning actions;
- streak achievements, because streak may be account-wide but is fed by target-learning activity;
- daily task achievements, because tasks may include global and target-content goals;
- pack achievements, because entitlement may be global but pack content may be target-specific;
- share achievements, because the shared achievement may be target-specific or global.

### GVA-052A.3: 69 achievements look global

These can likely stay under account/global achievement state after review:

- login streaks;
- arena;
- league;
- social;
- shards;
- energy;
- avatar/profile customization;
- wager achievements.

They still require an explicit product decision in the migration plan.

## 4. Required migration shape

Current:

```text
progress.achievements_state -> local achievements_v1 flat array
```

Required future:

```text
progress/global/achievements
progress/targets/en/achievements
progress/targets/fr/achievements
```

Legacy migration:

- target-specific legacy unlocks map to `targets/en`;
- global legacy unlocks map to `global`;
- mixed legacy unlocks require a product policy before migration;
- `unlockedAt`, `notified` and `shardClaimed` follow the achievement id scope.
