## Outcome

1. Гость привязывает свободный аккаунт → без вопросов, прогресс остаётся (как было).
2. Гость с прогрессом входит в ДРУГОЙ существующий аккаунт → одна шторка GuestSwitchWarningSheet (Дизайн, e4869015b) →
   «Войти» = смена гостя на чистого (аварийная копия, без слияния) + вход тем же выбором без второго окна;
   «Отмена» = остаётся гостем. Без прогресса — сразу вход (как было).
3. Вошёл в A → нажал Google/Apple → окно выбора → выбрал B → штатная смена A (облако догоняет, копия) → вход в B, без
   отказа account_switch_required и без промежуточных окон. Выбрал тот же A → ничего не меняется.

## Architecture

Смена A→B выполняется ВНЕ резерваций текущего входа (иначе вложенные замки): внутренний вход только выбирает аккаунт и
возвращает сигнал; публичная функция делает signOutAndWipeForAccountSwitch({syncDeadlineMs 3000,
allowWipeWithoutSync}) и resumeSignInAfterAccountSwitch(provider). Журнал [AUTH-SWITCH] с ISO-временем на каждой развилке:
правило, значение, решившее ветку, итог.
