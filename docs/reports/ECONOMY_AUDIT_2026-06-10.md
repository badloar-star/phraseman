# Аудит экономики Phraseman — 2026-06-10

Полная проверка игровой экономики и монетизации: осколки, энергия, XP/уровни/лиги, стрики, подарки, ставки, дневные лимиты, premium. Аудит проводился 6 параллельными агентами + ручная верификация критичных находок.

**Главный вывод:** экономика продумана по механикам, но почти целиком живёт на клиенте (AsyncStorage + прямая запись в Firestore без валидации). Серверная защита есть только у «Объясни просто», подарков друзьям и квот ИИ-диалогов — и даже там premium-статус берётся со слов клиента.

## P0 — чинить в первую очередь (прямые деньги / целостность)

### 1. Cloud Functions верят клиенту, что у него Premium ⬅ ДЕНЬГИ (OpenAI)
- `functions/src/premium_dialog.ts:262` — `const isPremium = data.isPremium === true; // TODO Phase 1`
- `functions/src/weekly_review.ts:357` — то же
- `functions/src/stats_insights.ts:393` — то же
- `functions/src/index.ts:230` — `isPremium: !!data.isPremium`

Любой бесплатный пользователь шлёт `isPremium: true` в body → получает premium-квоты платных OpenAI-функций (100 диалогов/день вместо 1, обзор раз в 7 дней вместо 14, инсайты раз в 3 дня вместо 7). Оплачивает это владелец проекта.

**Фикс:** в CF читать premium/VIP из `users/{stableUid}` через Admin SDK (поля `premium_*`/`vip_*` уже защищены rules — им можно верить) и игнорировать `data.isPremium`. TODO в коде уже стоит — реализовать.

### 2. firestore.rules не защищают ни одно экономическое поле
- `firestore.rules:40,105` — `progressHasNoPremiumWrites()` блокирует только `premium_*`/`vip_*`. Поля `shards`, `user_total_xp`, `weekly_xp`, `week_points_v2`, `streak_count`, `energy_state`, `chain_shield`, `gift_xp_bank_v1` клиент пишет напрямую без проверки значений.
- `app/shards_system.ts:264–287` — клиент сам делает транзакцию и пишет любой баланс.
- `firestore.rules:135–138` — `arena_profiles/{userId}`: `allow write: if isOwner(userId)` без ограничений на поля → можно выставить себе `isPremium`/`isVip`/любые множители напоказ.

**Грозит:** накрутка валюты (обнуляет смысл IAP-пакетов осколков), накрутка лидерборда/лиг, фейковый premium-бейдж.

**Фикс (поэтапно):** (а) rules-валидация диапазонов / blocklist по аналогии с `progressHasNoPremiumWrites`; (б) среднесрочно — начисление осколков и XP через CF, клиент только читает. Минимум — закрыть `arena_profiles` поля `isPremium`/`isVip`.

### 3. Экзамен ≥90% = 10 000 XP, без капа и идемпотентности
- `app/exam.tsx:622` и `app/exam.tsx:722` — `p >= 90 ? 10000 : 50 + p/2`.
- XP идёт через `registerXP` как earned → умножается на ВСЕ бусты (аддитивная сумма до ~×10.6: лига +110%, comeback ×2, стрик ×1.8, бусты лиги/подарков/сундука). До ~106 000 XP за одну пересдачу, пересдавать можно.

**Грозит:** один экзамен в понедельник = гарантированный топ лиги; ломает недельное соревнование для всех в группе.

**Фикс:** идемпотентный флаг «золото уже получено за этот lessonId» + не применять множители к экзаменному бонусу (или кап, напр. 2000/день по source `exam_complete`).

### 4. A/B пейвола назначается `Math.random()` ⬅ ДЕНЬГИ (аналитика конверсии)
- `app/premium_modal.tsx:1679` — `Math.random() < 0.5 ? 'v2' : 'v1'`, кэш в AsyncStorage. При переустановке/чистке юзер меняет вариант → A/B-данные конверсии загрязнены, решение по пейволам принять нельзя.
- Готовая детерминированная `getPaywallVariant(userId)` уже есть в `app/remote_flags.ts:199` — не используется.

**Фикс:** одна строка — заменить на `getPaywallVariant(userId)`.

### 5. `tester_no_limits` и `tester_energy_disabled` работают вне dev-рантайма
- `app/premium_guard.ts:236–237` — гейт только `!IS_STORE_RELEASE` (нет `IS_DEV_RUNTIME`), слабее эталонного предохранителя FORCE_PREMIUM (`config.ts:71–72`, тот в норме).
- `app/EnergyContext.tsx` (контекст энергии, `readUnlimited`) — `tester_energy_disabled` из AsyncStorage без проверки `__DEV__` → на Android с adb-доступом можно включить себе безлимит навсегда.

**Фикс:** добавить `&& IS_DEV_RUNTIME` в оба места — по образцу FORCE_PREMIUM (см. tests/force_premium_prod_guard.test.ts, можно расширить тест-страж).

### 6. `referral_enabled` всё ещё `false` по умолчанию
- `app/remote_flags.ts:60`. Пока в админке/RC не включено — рефералка (7 дней VIP) мертва в проде, виральный канал не работает. Это операционный пункт, не код.

## Баланс цифр (как сейчас сходится)

**Приход осколков** активного бесплатного игрока: ~10–15💎/день, ~75–100💎/неделю (уроки +6–10, задания +1, арена +3–5, стрик ~+0.4/день амортизированно).

**Стоки:** рефилл энергии 5, заморозка 10, ревайв 15–100, реролл задания 3, бусты лиги 20–50, аватар 50, аура 35, карточка профиля до Elite суммарно **1130**, IAP-пакеты 35/92/210/500💎.

Выводы по балансу:
- Утилиты (энергия/заморозка) доступны — нормально.
- Топ-косметика = 2–3 месяца накоплений — жёстко, но это и есть пуш к IAP; приемлемо, ЕСЛИ закрыть фарм-дыры (иначе IAP бессмыслен).
- **Streak repair бесплатен и почти безлимитен** (`app/streak_repair.ts:61–90`: пропущен ровно 1 день → сыграй урок — починено; можно через день вечно). Это обесценивает и заморозку (10💎), и ревайв (15–100💎), и premium-страховку стрика. Рекомендация: лимит N бесплатных repair в месяц или маленькая цена.
- Энергия списывается за ошибки (Duolingo-модель) — безошибочная игра бесплатна. Осознанный дизайн, но фикс. списания только у арены (1), диагностики (1) и экзамена (8).
- Wager-и (стрик ×4, арена ×2) — клиентские, см. P1.
