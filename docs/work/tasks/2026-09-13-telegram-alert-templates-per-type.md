## Outcome

Владелец с одного взгляда на письмо в Telegram понимает **что произошло и что с этим
делать**, не читая текст целиком. Сегодня все 47 типов рендерятся одним каркасом
(`renderAdminAlertMessages`): заголовок → «Профиль события» → «Контекст» →
«Содержимое события». Поэтому покупка Premium выглядит так же, как падение крона,
а у «Нового пользователя» письмо вырождается в три строки-заглушки
(«ник не найден», «не передана клиентом») — это видно на скриншоте владельца.

Успех: для каждого типа своя шапка-герой, свой порядок блоков и свой тон
(праздник / нейтраль / предупреждение / тревога / сводка); пустые поля не печатаются;
денежные и ростовые события читаются как праздник.

Владелец 2026-09-13 сказал «ДЕЛАЙ» — макет и код сделаны в одном заходе,
функции выложены в прод.

## Architecture

Текущая граница: один рендер на все типы. `renderAdminAlertMessages` собирает
фиксированный каркас, `TELEGRAM_FORMAT_VERSION = 3` замораживает текст первой
доставки (снапшот в `telegramMessages`), поэтому ретрай не смешивает форматы.

Намеченная граница: тот же единственный вход `renderAdminAlertMessages` + таблица
шаблонов «тип → (герой, тон, порядок блоков)». Рендер остаётся одной функцией,
меняется только раскладка. Приватность не переезжает: `sanitizeAdminAlertPayload`,
`SAFE_FIELD_POLICY`, `DETAIL_POLICY` и `redactAdminAlertText` остаются
единственными воротами — шаблон **не может** напечатать поле, которое не прошло
санитайзер.

Инварианты, которые нельзя нарушить будущей правкой кода:
- ник только из серверного поиска профиля, никогда из клиентского payload;
- время только `Europe/Dublin`, без слова «Ирландия»;
- 4096 знаков на часть, разрез только по границам экранированного HTML;
- при смене раскладки обязателен bump `TELEGRAM_FORMAT_VERSION` → 4.

На этом шаге архитектура рантайма не меняется: правятся только файлы в `docs/`.

## Security and privacy

Личные данные: макет использует **вымышленные** имена (Axiom 31657, Мария,
Данил 90210) и вымышленные суммы. Ни одной строки из боевой базы в макет не
попадает. Скриншот владельца не переносится в репозиторий.

Правило проекта (`CLAUDE.md`, раздел админки) гласит: «в Telegram не уходят ни
имена, ни uid, только количества». Формат v3, выложенный в прод 2026-09-13 по
прямому заданию владельца, ник **отправляет** (публичный display name, отфильтрованный
`sanitizePublicNickname`). Это расхождение — не побочный эффект данной задачи,
но текст правила надо привести в соответствие решению, иначе следующая сессия
воспримет ник как утечку и «починит». Вынесено в 🟡-итог владельцу.

Privacy Policy: новых данных не собирается, новых получателей нет, канал тот же
(приватный чат владельца). Правка политики не требуется.

Секреты: не затрагиваются. `ADMIN_ALERT_BOT_TOKEN` живёт в Secret Manager,
макет его не касается.

## Rollback

Макет — статические файлы в `docs/`, на рантайм не влияют: удаление папки
`docs/design/telegram-alerts/` полностью откатывает задачу, данные пользователей
не затрагиваются.

Для будущей правки рендера: откат = вернуть предыдущую раскладку и оставить
`TELEGRAM_FORMAT_VERSION` увеличенным. События, уже отправленные в новом формате,
имеют замороженный снапшот текста и не перерисовываются, поэтому отката «задним
числом» не требуется и не бывает смешанных писем.
