## Outcome

Аудит показал разрыв со спецификацией: в исходном задании владельца было
«возможность удалить чужой комментарий, **ответить**, пожаловаться», но
действия «Ответить» нет в коде вообще — ни в `PackCommentsSheet.tsx`
(меню «···» содержит только закрепить/скрыть/удалить/пожаловаться), ни в
модели `packComments.ts` (нет поля `replyTo`, список плоский).

Владелец выбрал вариант **плоских ответов**: тап «Ответить» подставляет
`@ник` в поле ввода и ставит фокус, комментарий остаётся в общем списке.
Дёшево, без миграции данных, без правки правил Firestore, без переработки
списка во вложенную структуру.

## Scope

In scope:
- `app/community_packs/PackCommentsSheet.tsx`: кнопка «Ответить» в строке
  действий опубликованного отклика (рядом с реакциями, до «···»); по тапу —
  подстановка `@ник ` в начало черновика (не дублируя уже стоящий префикс),
  фокус в поле ввода, лёгкий хаптик. Композер получает `ref` для фокуса.
  Кнопка видна только тем, кто может писать (`canWrite`), и не показывается
  на своём собственном отклике (отвечать самому себе бессмысленно).

Out of scope:
- Вложенная ветка ответов (`replyTo`, уровни) — владелец выбрал плоский
  вариант; вложенность потребовала бы поля в документе, правок правил и
  переработки рендера списка.
- Уведомление автору отклика о том, что ему ответили — сейчас уведомление
  идёт только автору НАБОРА (`notifyOnPackCommentCreated`). Расширение
  триггера на «ответили на твой отклик» требует разбора `@ник` на сервере,
  это отдельное решение.

## Architecture

Не меняется. Ответ — обычный отклик с упоминанием в тексте; ни модель, ни
Firestore-слой, ни правила не трогаются. Лимит длины (200 знаков) уже
действует и теперь включает префикс `@ник` — это осознанно, чтобы не
обходить лимит через упоминания.

## Security and privacy

Не затрагивается: `@ник` — тот же публичный никнейм, который уже виден в
шапке отклика. Новых данных не собирается и не раскрывается.

## Technical debt

Нет нового долга. Если позже понадобится настоящая ветка ответов, плоский
вариант не мешает — поле `replyTo` можно добавить, не ломая существующие
отклики.
