## 🔴 CRITICAL (фича может быть сломана прямо сейчас)

### C1. `json_object` не поддерживается дефолтной моделью диалога → HTTP 400
`functions/src/premium_dialog.ts:555`. В игровом режиме безусловно ставится `response_format: { type: 'json_object' }`. Но дефолтная модель диалога = **`gpt-4.1-nano`** (`openai_dialog_model_config.ts:8` MODEL_DEFAULT). **Перепроверено лично:** все ОСТАЛЬНЫЕ функции проекта с json_object (`stats_insights.ts`, `weekly_review.ts`, `explain_choice.ts`) намеренно стоят на **`gpt-4o-mini`** — единственной модели из ALLOWED_DIALOG_MODELS, надёжно поддерживающей JSON mode. Диалог же дефолтит на 4.1-nano. Риск: каждый игровой сценарий падает с 400 «model does not support response_format», квота/лимит откатывается, юзер не получает ответ. **Фикс:** либо включать game mode только когда `/gpt-4o/.test(dialogModel)` (иначе текстовый фолбэк), либо перевести дефолт диалога на gpt-4o-mini, либо добавить метаданные `supportsJsonObject` к ALLOWED_DIALOG_MODELS и гейтить по ним.

## 🟠 HIGH (ломает UX или требование пользователя)

### H1. Утечка сырого JSON юзеру при обрезке по токенам
`premium_dialog.ts:584`. Если ответ модели обрезался по `max_tokens` (420 в игре), JSON битый → `parseGameEnvelope` вернёт null → фолбэк присваивает `assistantMessage = rawContent` = **обрезанный сырой JSON**, который показывается юзеру как реплика (`{"reply":"Привет там...`). **Фикс:** при null в игровом режиме regex-извлечь `"reply":"..."` или показать дружелюбную ошибку, не сырой JSON.

### H2. Провал помечается как «Пройдено»
`ai_dialog_session.tsx:317`. `applyTurnState` зовёт `markDialogCompleted` при ЛЮБОМ терминальном исходе, включая `lost_patience`/`stalled`. Сценарий, где собеседник тебя выгнал, в списке диалогов показывается «Пройдено» (DialogsTabContent). Подрывает механику повтора и противоречит модалу «потерял терпение». **Фикс:** различать успех/провал — отмечать «Пройдено» только при `success`, провалы как «Попытка».

### H3. XP по исходу НЕ начисляется (мёртвый код)
`dialog_outcome.ts:98` `outcomeXpMultiplier` определён, протестирован, но **нигде не вызывается** (перепроверено grep лично). Диалог вообще не начисляет XP напрямую (только `trackEvent('ai_dialog_completed')`). Требование пользователя «больше XP за успех» НЕ реализовано. **Фикс:** подключить начисление XP по исходу при терминальном outcome (или честно убрать обещание XP, если диалог по дизайну XP не даёт).

### H4. success без всех галочек
`premium_dialog.ts:385` + клиент. «success = все под-цели» решает ТОЛЬКО модель; ни сервер (`parseGameEnvelope`), ни клиент не валидируют, что `objectivesMet` содержит все id. Модель может объявить success при неполных галочках → модал «Получилось 🎉» с незакрытыми кружками. **Фикс:** валидация в parseGameEnvelope — если outcome=success и objectivesMet неполный, понизить до stalled (или явная инструкция + лог).

### H5. Чек-лист целей — только по-русски
`ai_dialog_session.tsx:1206`. В модале рендерится `o.labelRu` для ВСЕХ языков. Испаноязычный юзер видит русские названия целей. `DialogObjective` вообще имеет только `labelRu`/`labelEs?`. **Фикс:** хранить метки на 8 языках (или переводить), выбирать через `triLang(lang, …)`.

### H6. Хардкод-цвета в нейтральном финале
`ai_dialog_session.tsx:1373,1376`. Кнопка «Продолжить без лимита» — `'#4A9EFF'`/`'#fff'` вместо токенов. В тёмных/нестандартных темах (Ocean/Sakura/Gold/Coral) не гармонирует/невидима. **Фикс:** `t.accent`/`t.correctText`. (Примечание: эта кнопка была и ДО фичи — но всплыла в аудите.)

### H7. Расхождение стартового mood клиент↔сервер
Клиент `temperamentStartMood` (учитывает warmth ±5), сервер `startMoodForPatience` (только patience). warm+high: клиент 90, сервер 85. **Фикс:** добавить warmth-модификатор в серверный `startMoodForPatience`.

### H8. Regex темперамента без границ слов
`ai_dialog_scenarios.ts:1736`. `/…|line|…/` без `\b` ловит подстроки: `airline` (сценарий airport_checkin role «airline check-in agent») → ложно patience=low. Дружелюбный персонаж становится нетерпеливым. **Фикс:** `\b(…)\b`.

### H9. Пустой/односложный goalEn молча выключает игру
`ai_dialog_scenarios.ts:1698`. `splitGoalParts` фильтрует части `length>1`; при `goalEn` пустом/односложном → `objectives=[]` → `gameEnabled=false`, игра тихо выключена без ошибки. Сейчас скрыто (все goalEn многословны), всплывёт при импорте/новом контенте. **Фикс:** дефолтная под-цель при пустом результате.

### H10. Инъекция промпта через `en`
`premium_dialog.ts:336-345,373`. `en` вставляется в gameBlock без экранирования. Сейчас `en` из каталога (не юзер-ввод) — но это клиентский ввод по сети, скомпрометированный клиент может прислать payload с переносами строк/инструкциями. **Фикс:** чистить `en` от `\n\r\t` и подозрительных символов в `sanitizeObjectives`.

### H11. Стоимость игрового режима не наблюдаема
`premium_dialog.ts:366-393,622`. gameBlock (+~100-150 токенов промпта) + json_object на КАЖДЫЙ игровой ход. В billing-запись флаг `gameMode` НЕ пишется → нельзя измерить долю и рост стоимости. **Фикс:** логировать `gameMode` в billing + документировать ~15-20% рост.

### H12. Нет метаданных совместимости моделей
`openai_dialog_model_config.ts:13`. ALLOWED_DIALOG_MODELS — просто список имён без признака `supportsJsonObject`. Админ может выставить несовместимую модель → молчаливый 400 (см. C1). **Фикс:** метаданные совместимости + хелпер-гард.
