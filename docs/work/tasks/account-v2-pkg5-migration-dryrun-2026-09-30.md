## Outcome

Чистая функция dry-run миграции: из снимка старых данных пользователя (документ users/{uid} и известные подколлекции — в тестах фикстуры) строит план переноса в Account V2 (операции конверта по доменам lesson/flashcard/library, права Plus как ссылка на существующую систему, без копирования экономики) и отчёт: что перенесено, что отброшено по решению владельца (жемчуг, XP, уровни, лиги, сезоны, бусты, руны/осколки как экономика — счётчики без копирования), что неизвестно (HOLD с путём поля). Скрипт-обёртка читает ЛОКАЛЬНЫЙ JSON-экспорт (не Firestore), пишет отчёт по схеме. Ничего не записывает в облако.

## Scope

In scope: новые functions/src/accounts_v2_migration/*.ts (чистое ядро dry-run + тесты на фикстурах), scripts/accounts-v2-migration-dry-run.mjs (только локальный файл вход/выход), docs/reports/accounts-v2-migration-dry-run.schema.json. Out of scope: чтение production Firestore, запись куда-либо кроме локального отчёта, деплой, commit.

## Architecture

Инвентарь полей — явная таблица: carry (переносится), drop (отбрасывается по решению владельца, со ссылкой на решение), derive (права Plus — только ссылка/проверка через существующую систему покупок, не копия), unknown → HOLD. Результат детерминирован; операции миграции используют тот же конверт/лимиты, что клиент (ACCOUNT_SYNC_LIMITS), чтобы сервер их принял; operationId детерминированы от uid+пути (идемпотентность повторного прогона).

## Security and privacy

Отчёт содержит только счётчики и пути полей, без значений и без uid (uid → хэш). Персональные данные не выводятся. Реальные данные не читаются в этом шаге.
