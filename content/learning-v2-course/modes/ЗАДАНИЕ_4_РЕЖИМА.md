## Режим 1 · `dialogue_reply` — «Ответь в диалоге»

**Зачем.** Весь курс построен на сценах с людьми; это единственный режим,
где ученик отвечает человеку, а не заданию.

**Что видит ученик.** Реплика собеседника (пузырь слева, с аватаром роли:
«начальник», «коллега», «сосед»; аудио-кнопка) → ученик отвечает: либо
выбором из 3–4 реплик, либо сборкой из плиток (два подрежима, задаются
контентом). После верного ответа — короткая ответная реплика собеседника
(«закрывающая»), чтобы диалог ощущался живым.

**Данные от контента.**
```
{ family: "dialogue_reply",
  speaker: { role: "boss" | "colleague" | ... , nameByLocale },
  cue:  { text: "Tired?", audioId },
  input: "single_choice" | "ordered_tokens",
  options: [{ responseId, text }], correctResponseId | orderedCorrect,
  wrongFeedbackByResponseId (8 локалей),
  closing: { text: "Great, let's go.", audioId } }
```

**Ощущение.** Появление реплики — как в мессенджере (пузырь с лёгкой
пружиной снизу, `MODE_SPRING_UI_V1`), «печатает…» 400 мс перед закрывающей
репликой; верный ответ — пузырь ученика «долетает» в ленту справа.

## Режим 2 · `type_phrase` — «Напечатай сам»

**Зачем.** Плитки проверяют узнавание; память проверяется только без
подсказок. У Duolingo после первых уроков это половина упражнений.

**Что видит ученик.** Смысл на своём языке (и/или аудио) → поле ввода с
клавиатурой → «Проверить». Снисходительная проверка: регистр, знаки
препинания, пробелы, апострофы (`I'm` = `I am` только если контент разрешил),
одна опечатка на слово длиной ≥ 5. Первая ошибка — точечная подсветка
неверного слова прямо в поле (без тряски), вторая — показ правильной
фразы и просьба перепечатать.

**Данные.** `{ family: "type_phrase", promptByLocale, acceptedAnswers: string[],
  tolerance: { typoPerWord: 1, contractions: boolean }, hintTokens?: string[] }`.

**Ощущение.** Клавиатура не прыгает: поле ввода живёт над футером с учётом
`useStableSafeAreaInsets`; после верного — символы «застывают» в чип и чип
улетает в счётчик, как звезда в существующих режимах.

## Режим 3 · `spot_the_error` — «Найди ошибку»

**Зачем.** Сессия 5 каждой главы — «контраст и ремонт». Ученик должен не
выбирать правильное, а **видеть неправильное** — это другой навык.

**Что видит ученик.** Фраза с ровно одной ошибкой, слова — тапабельные
чипы. Шаг 1: тап на слово-ошибку (неверный тап — тонировка, без тряски).
Шаг 2: выбрать замену из 3 вариантов (или ничего не заменять — «лишнее
слово», тогда чип улетает). Разбор — только для тапнутого неверного
варианта.

**Данные.** `{ family: "spot_the_error", tokens: string[], errorIndex,
  fix: { kind: "replace" | "delete" | "insert_after", options, correctResponseId },
  wrongFeedbackByResponseId }`.

**Ощущение.** Найденная ошибка «трескается» (масштаб 1 → 0.92 → 1 с
`MODE_SPRING_MICRO_V1`), исправление въезжает на её место как чип в
phrase_builder (FLIP, `chipFlightMs`).

## Режим 4 · `read_choose_meaning` — «Прочитай и пойми»

**Зачем.** Понимание без звука и без сборки. Обратное направление к
phrase_builder.

**Что видит ученик.** Английская фраза крупно (без аудио-кнопки по
умолчанию — это чтение) → 3–4 варианта смысла на своём языке, атомарные
(один вариант — одна формулировка). Дистракторы — близкие по смыслу,
из пройденного.

**Данные.** `{ family: "read_choose_meaning", text, options (по локали),
  correctResponseId, wrongFeedbackByResponseId }`.

**Ощущение.** Как `listen_choose`, но акцент на типографике: фраза
появляется словами по 40 мс, варианты — стаггером `bankStaggerMs`.

## Общее для всех четырёх

- Машина состояний, `reducedMotion`, `referenceAudioState`, `onSubmit`/`canSubmit`
  — строго по `mode_contract_v1.ts`; режим не хранит источник истины,
  player — хранит.
- Ошибка — тонировка и подсказка, никогда тряска экрана.
- Каждый неверный вариант — своё объяснение, 8 локалей (правило фабрики).
- Все тексты интерфейса режима — через `mode_copy_v1.ts`, 8 локалей.
- Хаптик: только на «Проверить» и на успех.
- Проверка на устройстве: словами «сделано» без скриншота с телефона не
  отчитываться.
