# Сверка темы кадра в порядке съёмки R1 с таблицей «Тема кадра по страницам»

Governance-ID: TG-0324BC16DB54
Status: в работе
Owner: сессия «4 · ТЕМЫ 2.0» (поручение координатора: пока робот на паузе — сверить, что тема кадра каждой строки SHOOT_ORDER_R1 соответствует таблице классов страниц)

## Outcome
Список расхождений (если есть) между темой кадра, которую по таблице класса страницы должен получить каждый id из `SHOOT_ORDER_R1_2026-10-13.md`, и тем, как его снимут: строки без макета, страницы вне таблицы, страницы в двух классах. Расхождения — одной строкой Сверке и координатору.

## Scope
Только чтение: `SHOOT_ORDER_R1_2026-10-13.md`, `visual_parity.json`, таблица класса в `DEV_SWITCHES_R1_CORE.md`; временный скрипт сверки вне репозитория. Файлы репозитория не меняются (кроме этого пакета).

## Architecture
Для каждого id по реестру берётся файл макета, страница сопоставляется классу таблицы (A — `theme=grad_aurora&level=1`; A-светлый — `level=0.6&appearance=light` для светлого телефона; B — по странице; C — `theme=graphite&level=0`; D онбординг — без темы; E — не экран).

## Security and privacy
Только чтение внутренних таблиц, данных пользователей нет.

## Technical debt
Таблица классов описывает страницы целиком; какой именно телефон страницы (тёмный/светлый) снимается, решает строка реестра и подпись образца — это сверка не проверяет, только класс страницы.

## Verification
Скрипт печатает число id по классам и списки аномалий; результат сопоставляется с шапкой порядка съёмки.

## Rollback
Нечего откатывать: правок кода и данных нет.
