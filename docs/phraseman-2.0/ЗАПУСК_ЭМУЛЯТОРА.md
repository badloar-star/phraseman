# Запуск эмулятора Pixel_8

Governance-ID: TG-38AB37520F1C

Проверено 10.10.2026. Эмулятор — AVD `Pixel_8`, образ Android 35 (Google APIs, x86_64).

## Команда запуска

Из Git Bash или PowerShell:

```bash
"$LOCALAPPDATA/Android/Sdk/emulator/emulator.exe" -avd Pixel_8 -gpu angle_indirect -no-metrics -memory 2048 -cores 4 -no-boot-anim -netdelay none -netspeed full -no-snapshot-save -no-snapshot-load -no-audio
```

Окно эмулятора открывается на экране (без `-no-window`).

## Ключи и почему они нужны

- `-gpu angle_indirect` — режим видеокарты. На этой сборке эмулятор пишет «not valid, switching to auto»: фактически рисует через системный OpenGL на видеокарте NVIDIA (проверено: `dumpsys SurfaceFlinger` показывает NVIDIA GeForce RTX 5070 Ti). Режим `guest` на API 35 молча работал как SwiftShader (программная отрисовка на процессоре), и именно он давал падения.
- `-no-metrics` — отключает блокирующее окно согласия на отправку статистики. Без него запуск зависает на окне, которое не видно в списке окон.
- `-no-snapshot-save -no-snapshot-load` — холодный старт без снимка, как того требуют замеры.
- `-memory 2048 -cores 4` — память и процессоры для гостя.

## Если эмулятор не загружается

1. Проверить `adb devices`. Если пусто — `adb kill-server`, затем `adb start-server`.
2. Направить вывод запуска в файл (`> emu_boot.log 2>&1`) и искать `ERROR`, `Critical`, `crashdialog`.
3. Если появилось окно «отчёт о сбое» — переименовать `C:\Temp\AndroidEmulator\emu-crash-36.4.10.db` в `.bak` (не удалять) и запустить снова.
4. Остались висящие процессы — `taskkill /F /IM qemu-system-x86_64.exe` и `emulator.exe`, удалить папку `~/.android/avd/Pixel_8.avd/hardware-qemu.ini.lock` и файл `multiinstance.lock`.

## После загрузки

```bash
adb -s emulator-5554 reverse tcp:8081 tcp:8081
adb -s emulator-5554 shell monkey -p app.phraseman -c android.intent.category.LAUNCHER 1
```

Порядок важен: сначала `reverse`, потом запуск приложения. Иначе приложение пишет «Unable to load script».

## Что пока не выяснено

- Что именно сняло ночные падения. Совпадение по времени есть: после перехода с `guest` на видеокарту с 11:17 до 12:00 падений не было. Но падение 18:46 случилось в том же режиме, значит, это не полное решение. Нужен повтор сценария «Мои ошибки → Отработать» и журнал сбоя из папки `reports`.
- Почему `angle_indirect` не принимается. Выбор режима — с владельцем, без его решения не менять.
