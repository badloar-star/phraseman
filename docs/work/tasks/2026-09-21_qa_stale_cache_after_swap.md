# После переворота полей панель проверяет ПРОТУХШИЕ карточки

Governance-ID: TG-CCA96FE6FE46
Дата: 2026-09-21

Запрос владельца: «проверь по логам что было сделано и какого зуя после
исправления снова появилось это».

## Диагноз (по логам и данным, не по догадкам)

Переворот полей СРАБОТАЛ и записался в базу:

```
[PACK-QA-APPLY] результат { applied: 32, skipped: 0, reasons: [] }
qaFixesAppliedAt: 2026-09-21T17:41:31.408Z
qaFixesAppliedCount: 32
```

Состояние заявки в Firestore ПОСЛЕ переворота:

```
en="The match was called off" [латиница]   ru="Матч был отменен" [кириллица]
en содержит латиницу:   16 из 16
ru содержит кириллицу:  16 из 16
ВЫВОД: ПОЛЯ НА МЕСТЕ
```

Но на экране ИИ снова заявил «весь набор загружен наоборот» — и сам себя
опроверг в блоке правки:

```
БЫЛО:  Матч был отменен          ← этого в поле en УЖЕ НЕТ
СТАЛО: The match was called off  ← это там уже лежит
```

Последний `[PACK-QA] вход` в логах — **16:07**, переворот — **17:41**.
Проверки после переворота на сервере не было вовсе: панель отправила данные,
которые считала текущими.

**Причина:** `pmPhase4GetCommunitySubmission` (`legacy.html:26225`) читает
`_communitySubmissionsCache` — снимок очереди, загруженный при открытии
раздела. `adminCommunityPackApplyQaFixes` пишет в Firestore, но кэш браузера
после этого никто не обновляет. Панель продолжает жить на старом снимке.

Класс бага: «механизм есть, а данных ему дали протухшие».

## Outcome

После успешного применения правок (и переворота, и обычных) панель работает
с актуальными карточками:
1. кэш очереди перечитывается из Firestore;
2. черновик и его отпечаток (`fingerprint`) пересобираются под новые данные;
3. повторная проверка уходит на сервер с уже исправленным текстом.

## Scope

### Правится
- `admin/v2/legacy.html` — `applyFixesAndPublish`: после успеха обновить
  `_communitySubmissionsCache` и пересобрать черновик.

### НЕ трогается
- `functions/src/*` — сервер отработал корректно, правок не требует.
- Логика `applyQaFixesToPayload` — сверка `before` работает как задумано.

## Architecture

Перезагружаем очередь существующей `loadCommunitySubmissions(true)` — она уже
умеет читать Firestore и обновлять `_communitySubmissionsCache`. Своего запроса
не заводим: второй путь чтения разошёлся бы с первым.

Вызов делается ТОЛЬКО после успешного применения (applied > 0), то есть не
чаще одного раза на действие владельца — лишних чтений Firestore нет.

После перезагрузки пересобираем черновик: `fingerprint` считается от нового
payload, поэтому устаревшие находки не переживут обновление.

## Security and privacy

Изменений в доступе и сборе данных нет: перечитывается та же коллекция тем же
админом. В OpenAI по-прежнему уходит только содержимое карточек.
Privacy policy правок не требует.

## Technical debt

Кэш очереди остаётся единственным источником для панели. Если появится другой
путь записи в заявку, его тоже придётся сопровождать обновлением кэша.
Радикальное решение — подписка на документ — здесь избыточна и дороже по
чтениям Firestore.
