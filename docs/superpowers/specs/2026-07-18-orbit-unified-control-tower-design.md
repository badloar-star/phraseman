# Orbit: единый диспетчер разработки

## Статус и цель

Статус: утверждено владельцем 2026-07-18.  
Цель: заменить два отдельных навыка `orbit` и `orbit-v2` одним навыком `orbit`. Он принимает обычную задачу, безопасно разбивает ее на независимые пакеты, создаёт отдельные видимые задачи на доступных моделях, собирает проверяемые результаты и сохраняет понятный след работы между сессиями.

Orbit — не самостоятельный продуктовый план и не обещание, что любая задача будет распараллелена. Это экономный диспетчер: отдельная сессия создаётся только тогда, когда она уменьшает время, риск или стоимость.

## Пользовательский контракт

Пользователь может написать `делай <задачу> по Orbit` либо использовать один из режимов:

- `ORBIT PLAN` — изучить задачу, показать разбиение и план маршрутизации без записи и запуска исполнителей.
- `ORBIT BUILD` — выполнить утверждённую реализацию через отдельные рабочие задачи и обязательные проверки.
- `ORBIT FIX` — воспроизвести и локализовать ошибку, затем исправить её через узкий пакет.
- `ORBIT REVIEW` — выполнить независимое чтение спецификации, кода и рисков без изменения исходников.
- `ORBIT STATUS` — показать состояние основной задачи, работников, результаты и следующий шлюз.
- `ORBIT HANDOVER` — записать воспроизводимое состояние для следующей сессии без продвижения работы.

Каждая созданная Orbit видимая задача называется строго так:

`ORBIT · <РОЛЬ> · <краткая цель>`

Примеры: `ORBIT · EXECUTE · Экран статистики`, `ORBIT · VERIFY · Контракт авторизации`, `ORBIT · REVIEW · Платёжный сценарий`.

Основная управляющая задача по умолчанию работает на `gpt-5.6-terra` с уровнем рассуждений `medium`: это оптимальный баланс для декомпозиции, координации и сборки результатов. Это рекомендация, а не фиктивное переключение текущей сессии.

## Базовый цикл Control Tower

1. **Приём и защита контекста.** Проверить цель, область, рабочее дерево, незавершённые пользовательские изменения, связанные контракты и необходимые тесты. Не трогать чужие изменения.
2. **Классификация.** Оценить размер, независимость частей, цену ошибки, доступность проверок, риск данных/доступа/продакшена и необходимость решения владельца.
3. **План волн.** Сначала запускать независимый сбор фактов и проверку рисков; затем ровно одного писателя для конкретной зоны; затем независимые проверки. Не запускать исполнителя, пока пакет не имеет критериев готовности.
4. **Маршрутизация.** Создавать отдельную пользовательскую задачу только через интерфейс, который позволяет передать точные `model` и `thinking` и возвращает идентификатор задачи. Если такого интерфейса нет, остаться в текущей задаче и честно сообщить, что переключения модели не было.
5. **Сбор доказательств.** Принимать не декларацию «готово», а изменённые файлы, команды, итоговые коды, важные строки вывода, остаточные риски и следующий шаг.
6. **Шлюз качества.** После GREEN запускать независимую проверку, соразмерную риску. Новая проблема высокого приоритета возвращает работу в RED.
7. **Завершение.** Сообщить пользователю краткий результат на понятном языке, сохранив handover и очередь находок.

## Экономная модельная маршрутизация

Orbit выбирает только реально доступные модели. Нельзя объявлять сменой модели название роли, текст промпта или внутреннее делегирование.

| Роль | Модель / усилие | Разрешённая работа |
| --- | --- | --- |
| `SCOUT` | `gpt-5.6-luna` / `low` | Точный поиск, инвентаризация, сравнение файлов, сокращение логов. Только чтение. |
| `VERIFY` | `gpt-5.6-luna` / `medium` | Запуск узких детерминированных проверок и воспроизведение. Не исправляет исходники. |
| `EXECUTE` | `gpt-5.6-terra` / `medium` | Обычная ограниченная реализация с TDD. Единственный писатель своей зоны. |
| `REVIEW` | `gpt-5.6-sol` / `high` | Независимое ревью спецификации, контракта, интеграции и кода. Только чтение. |
| `CRITICAL` | `gpt-5.6-sol` / `high` | Единственный писатель для авторизации, доступа, денег, приватности, миграций, релизов и других критических контрактов. |
| `REDTEAM` | `gpt-5.6-sol` / `xhigh` | Только при P0/P1, конфликте нормативных источников или двух неудачных обоснованных гипотезах при критическом риске. |

Haiku, Sonnet и другие модели не включаются в таблицу, пока среда не предоставляет честный API выбора именно этих моделей. При появлении нового провайдера Orbit сначала добавляет явное соответствие «роль → модель → уровень рассуждений», а не угадывает его возможности.

## Правила параллелизма и слияния

- Один исходный файл или связанный контракт одновременно имеет только одного писателя.
- В одной волне допускаются максимум: координатор, один писатель и два независимых работника только для чтения/проверки.
- Параллельны лишь задачи с непересекающимися зонами и ясными входами. При сомнении Orbit делает их последовательно.
- Перед передачей писателю фиксируются базовый commit/рабочая копия, разрешённые пути и запрещённые пути.
- Ни одна рабочая задача не получает полномочий на push, deploy, Firestore, production-конфигурацию, секреты, удаление или необратимую операцию.
- Orbit не объединяет изменения молча: `Safe Merge` сначала проверяет пересечения путей, публичные контракты, зависимые тесты и грязные пользовательские файлы; затем показывает безопасный порядок объединения.

## Обязательный пакет задачи

Каждый worker получает только необходимый контекст по шаблону:

```text
ORBIT role: <SCOUT | VERIFY | EXECUTE | REVIEW | CRITICAL | REDTEAM>
Objective: <один проверяемый результат>
Workspace: <путь, ветка, базовый commit или безопасный снимок>
Authoritative inputs: <документы, файлы, тесты, решения владельца>
Allowed changes: <точные пути; для read-only: none>
Non-goals: <что не менять>
Invariants: <совместимость, безопасность, legacy, офлайн и т.п.>
Acceptance criteria: <наблюдаемые условия>
Verification: <точные команды или инспекция>
Handoff: changed files; evidence; failed approaches; risks; exact next action.
Do not expand scope, use secrets, deploy, push, or claim completion without evidence.
```

После создания координатор публикует квитанцию маршрутизации: ID/ссылку задачи, роль, точную модель/уровень, снимок workspace, границу ответственности и ожидаемый handoff.

## Качество, находки и улучшения

### Quality gates

Для изменяемого поведения Orbit применяет цикл RED → GREEN → независимый review → финальные детерминированные проверки. Набор проверок узкий и зависит от изменения; нельзя автоматически запускать тяжёлые глобальные наборы. Тест не должен изменять исходники, снапшоты или production-данные.

### Банк находок

Работник не расширяет свою задачу, если заметил чужую проблему. Он возвращает запись:

```text
Finding: <название>
Severity: <P0–P3>
Evidence: <файл, тест, воспроизведение>
User impact: <что реально может случиться>
Suggested owner/lane: <роль Orbit>
Suggested next step: <одна ограниченная проверка или задача>
```

Координатор автоматически запускает дальнейшее исследование только для доказанного P0/P1 или когда текущий контракт прямо требует его. Остальные находки попадают в компактный список предложений для владельца; это предотвращает самовольный scope creep.

### Дополнительные конвейеры

- **Health Radar** — read-only периодический или запрошенный скан узких сигналов: падения тестов, нарушения контрактов, тяжёлые экраны, дубли и риски доступа. Результат — приоритизированные доказанные находки, не правки.
- **Change Preview** — перед значимой правкой карта воздействия: пользовательский сценарий → состояние/хранилище → backend/callable → UI/потребители → тесты; включает пустое, offline, error, retry и account-switch состояние, где это применимо.
- **Product Lens** — после законченной функции формирует максимум три необязательных улучшения с пользовательской пользой, ценой и риском. Ничего не реализует без новой команды.
- **Regression Shield** — сохраняет минимальный набор связанных проверок на изменённую поверхность, чтобы будущие задачи повторяли релевантные проверки, а не случайный полный тестовый прогон.
- **Decision Log** — коротко хранит решения владельца, их причину, источник и затронутые контракты. Уже закрытые решения не открываются повторно без нового указания владельца.
- **Safe Merge** — перед интеграцией проверяет пересечения, зависимые контракты и незавершённые пользовательские изменения; возвращает порядок объединения или блокер, но не делает скрытое слияние.

## Специальный режим Phraseman Learning V2

Отдельного навыка `orbit-v2` больше нет. Когда задача касается Learning V2, 32-эпизодной программы, stars/access, voice activities, Speaking Club, Personal Review, dialogs, legacy migration или Admin Content Studio, единственный Orbit до планирования читает обязательные V2-документы и включает следующие усиления:

1. сверяет `docs/v2/HANDOVER.md`, V2 README и два утверждённых V2-плана с фактическим Git-состоянием;
2. соблюдает порядок источников: текущая команда владельца → правила среды/проекта → handover → планы → нормативные спецификации → реальный код и тесты;
3. задаёт ровно один вопрос владельцу только для действительно незакрытого решения, которое блокирует следующую задачу;
4. выполняет одну пронумерованную задачу за раз, с RED/GREEN, независимым review, проверками и немедленным обновлением V2 handover;
5. сохраняет legacy-функции до явно принятого решения Phase 14.

## Ошибки и стоп-условия

Orbit останавливается и запрашивает направление, если: требуется выбор владельца, конфликтуют равноправные нормативные источники, нужна новая внешняя власть, изменению мешают чужие незавершённые правки, или отсутствует безопасный способ создать видимую задачу на требуемой модели.

Orbit не останавливается только потому, что задача сложная: он выполняет безопасные read-only проверки, предлагает конкретный следующий шаг и фиксирует блокер.

## Проверка самой миграции

Миграция считается завершённой, когда:

1. существует только один discoverable `orbit` skill с актуальным `SKILL.md` и UI metadata;
2. `orbit-v2` удалён или исключён из discovery без сломанной ссылки;
3. единый skill содержит маршрутизацию, prompts, Control Tower, дополнительные конвейеры, V2-усиления и правила честной смены моделей;
4. документы не содержат команды, требующей отдельного `orbit-v2`;
5. валидатор навыка проходит, а поиск по skill roots подтверждает отсутствие устаревшей отдельной зависимости.
