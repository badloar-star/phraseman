# PM-143 — Аудит реальности локализации AI-диалогов (es/fr/de vs en)

Дата: 2026-09-24 · Ветка: `feature/referral-roulette` · Read-only разведка, код НЕ менялся.

Вопрос задания: локализация диалогового движка для es/fr/de — это настоящая
адаптация под язык, или просто параметр `language code`, вставленный в общий
шаблон? Проверено по 6 пунктам: prompt, validation, TTS, persistence, safety,
cost. Использована база из `docs/phraseman-2.0/docs/CONTENT_LOCALE_REGISTRY.md`
(раздел 1) — находка про `DIALOGUE_OWNER_RELEASED_TARGETS` не переоткрывается,
только достраивается новыми фактами.

---

## 1. Prompt (системный промпт AI)

**Вывод: настоящая локализация, не ярлык.** Одинаково для es/fr/de.

- `functions/src/premium_dialog.ts:350-365` — константа `DIALOGUE_PROMPT_EXAMPLES`
  содержит РАЗНЫЙ конкретный текст для каждого языка: пример грамматической
  ошибки ученика и её мягкое исправление (`correctionInput`/`correctionReply`),
  пример вежливого отказа/границы (`boundaries`), пример оскорблений на этом
  языке (`insults`), пример key-phrase разметки (`keyPhrase`). Например для fr:
  `'Je aller magasin hier' → 'Ah, vous avez été au magasin hier ?'`, для de:
  `'Ich gehen gestern Laden' → 'Ach, Sie sind gestern in den Laden gegangen?'`.
  Это не перевод одного шаблона переменной подстановкой — это отдельно
  подобранные грамматические ошибки, типичные для КАЖДОГO языка (fr/de имеют
  разный порядок слов и разные типичные ошибки конструкции инфинитива).
- `functions/src/premium_dialog.ts:385-408` (`GLOBAL_RULES`) — общий шаблон
  действительно один на все 4 языка (CEFR-уровни, "KEEP THEM TALKING",
  структура key-phrases), с плейсхолдерами `{TARGET_LANG}`,
  `{LEARNER_LANG_NAME}` и т.д. Это ожидаемо и не является нарушением: сама
  механика диалога (терпение, mood, coach) — намеренно единая игровая система,
  локализуется только языковой контент внутри неё.
- `functions/src/premium_dialog.ts:1571-1650` (`regulatedAdviceFallback`) —
  РЕАЛЬНО разные строки на es/fr/de для отказа в медицинском совете (не
  автоперевод одного шаблона, отдельные фразы с разной структурой).
- `app/dialogue_language_packs.ts:448-479` — у каждого языка свой `companion.opener`
  (первая реплика AI-компаньона) — разный текст, не шаблон.
- Каталог сценариев: `app/dialogue_language_packs.ts` содержит `ES_SCENARIOS`
  (53 сценария), `FR_SCENARIOS` (53 сценария по факту ключей, см. ниже),
  `DE_SCENARIOS` (51 сценарий) — с уникальными `title`/`goal`/`role`/`setting`/
  `persona`/`hint`/`greeting`/`objectives` на каждом языке, НЕ переводом
  английского текста один-в-один (тесты `dialogue_language_packs.test.ts`
  прямо проверяют это: `not.toMatch(/\b(the|with|your|you|please)\b/i)` —
  сторож от забытых английских слов, и негативные тесты вида "does not contain
  a generic French placeholder" `expect(objectives).not.toContain('Réalisez
  cette étape avec une phrase naturelle.')`).
- **Важная деталь**: три поля `englishBenchmarkSha256`, `sharedManifestSha256`,
  `promptContractSha256` в каждом языковом паке (`app/dialogue_language_packs.ts:451-483`)
  буквально равны строке `'pending-independent-review'` — то есть контент
  реально написан по-другому для каждого языка, но независимая проверка
  качества (заявленная как обязательная в `ai_dialog_target_gate.ts`
  `requiredEvidence`) формально НЕ пройдена и не может быть пройдена, пока эти
  хэши остаются плейсхолдером. Ссылается на уже известную находку реестра.

## 2. Validation (проверка ответов ученика)

**Вывод: специфики диакритики/грамматики НЕТ как отдельного правила — но есть
языковой guard, который был бы невозможен без учёта языка.**

- В коде НЕТ отдельного модуля, который бы разбирал грамматику ответа ученика
  правило-за-правилом (диалог — свободный текстовый чат с AI, не тест с
  фиксированными правильными ответами). "Проверка правильности" переложена на
  саму LLM внутри системного промпта (`GLOBAL_RULES`: "GENTLE CORRECTION" —
  модель сама решает, что исправить, без grammar-terms).
  Не нашёл диакритик-специфичной валидации (например, приема ответа без
  ударений в испанском/умлаутов в немецком) — если она есть, то реализована
  внутри LLM-промпта implicitly, не в детерминированном коде.
- `app/dialog_outcome.ts` — НЕ валидация ответа ученика; это чисто парсер
  JSON-конверта от сервера (mood/objectivesMet/outcome) с safe-fallback.
  Единственная "проверка" тут — это устойчивый парсинг чужого вывода, языка
  не касается вообще.
- **Единственная реально языко-специфичная проверка** —
  `functions/src/dialogue_ai_language_contract.ts:
  assertDialogueStudyLanguage` / `dialogueShortLanguageMismatch` (строки
  164-197): детектор "модель ответила не на том языке" на основе списков
  характерных коротких слов-маркеров для КАЖДОГО языка (`DIALOGUE_SHORT_LANGUAGE_MARKERS`
  — свои наборы для en/es/fr/de) и regex приветствий-паттернов
  (`DIALOGUE_DISTINCTIVE_SHORT_PATTERNS` — `bonjour|bonsoir|enchant[ée]` для fr,
  `hallo|guten\s+morgen|freut\s+mich` для de). Это настоящая языковая логика,
  не заглушка: она умеет отличать испанский ответ от французского по словам.
  Она включена и работает одинаково для es/fr/de (`functions/src/premium_dialog.ts:620-628`,
  `assertDialogGeneratedTargetFields`).
- Риск/наблюдение: это валидация ЯЗЫКА ответа AI (что модель не съехала на
  английский или русский), а НЕ валидация ГРАММАТИЧЕСКОЙ правильности ответа
  УЧЕНИКА. Грамматика ученика проверяется исключительно доверием к LLM внутри
  промпта — для всех 4 языков одинаково (архитектурное решение, не пробел
  именно в локализации es/fr/de).

## 3. TTS (голосовая озвучка)

**Вывод: настоящий, но не гарантированный контур — одинаковый уровень строгости
для всех 4 языков, никакой деградации в "молчание без объяснения".**

- `app/dialogue_voice_capability.ts` — `resolveDialogueVoiceCapability()`
  реально проверяет физическое наличие голоса нужной точной локали в
  устройстве (`es-ES`/`fr-FR`/`de-DE`, никаких `es-MX`-заменителей — код прямо
  комментирует "не proof for es-ES"). Логика одна и та же функция для всех
  языков — не переключается по `if (target === 'es') {...} else {...}` веткой
  для каждого языка отдельно, значит НЕТ шанса, что fr/de получили урезанную
  версию проверки относительно es.
  - на iOS для НЕ-английского таргета (es/fr/de) требуется отдельное
    `iosTargetSpecificProof` — то есть iOS-путь для НЕ-en языков строже, чем
    для en (осознанно, из-за истории с ложно доступным голосом, см. комментарии
    в файле).
  - Если голос точной локали не найден — `reason: 'exact_voice_missing'`,
    `available: false`. Комментарий в коде прямо запрещает подставлять
    дефолтный голос Expo вместо точного ("A voice list is evidence, not a
    hint... never let Expo select its default voice").
- ASR (распознавание речи) — `resolveDialogueAsrCapability()` в том же файле,
  тоже единая функция на все языки, с явной нормализацией локали
  (`en-US`/`es-ES`/`fr-FR`/`de-DE`).
- Это означает: TTS/ASR для fr/de **не деградирует молча** — либо есть точный
  голос устройства и он используется, либо кнопка озвучки недоступна с явной
  причиной (`reason`), а не тихо переключается на английский голос или молчит
  без объяснения. Не нашёл прямых доказательств РЕАЛЬНОГО прогона на живом
  fr-FR/de-DE устройстве в этом заходе (это вопрос физического наличия голоса
  на конкретном телефоне пользователя, не решается кодом) — код одинаково
  строг для всех 3 языков.
- `app/dialogue_language_registry.ts:16-21` — `speechLocale` для всех 4 целей
  задан явно (`en-US`/`es-ES`/`fr-FR`/`de-DE`), не общий/пустой дефолт.

## 4. Persistence (изоляция прогресса/истории между языками)

**Вывод: настоящая изоляция по ключам, проверена тестами, никакого смешения.**

- `app/dialogue_language_registry.ts: dialogueStateStorageKey()` — строит ключ
  `dialogue_v1::{target}::{legacyKey}` для НЕ-en языков, `en` использует
  необёрнутый legacy-ключ для обратной совместимости. Неизвестный target
  (`'it'`) возвращает `null` — явный fail-closed, а не тихий фолбэк на общий
  ключ.
- Используется в трёх реальных потребителях: `app/ai_dialog_hint_economy.ts`
  (дневной лимит подсказок), `app/ai_dialog_ownership.ts` (купленные диалоги +
  outbox отложенной синхронизации), `app/dialogs_progress.ts` (пройденные
  диалоги). Все три реально импортируют и используют функцию, не только
  испанский путь — grep подтвердил использование без ветвления по языку.
- `tests/dialogue_target_state_isolation.test.ts` — прямой тест: подсказки,
  использованные в 'es', НЕ уменьшают счётчик 'fr'/'de'/'en'
  (`markDialogHintUsed('es')` → `getDialogHintsLeftToday('fr')` остаётся 3);
  купленный диалог в 'es' не появляется как купленный в 'fr'; неизвестный
  таргет не может прочитать английские данные.
- Собственно ИСТОРИЯ переписки диалога хранится только в памяти компонента
  (`useState`, не в AsyncStorage) — при смене `studyTarget` компонент
  перемонтируется целиком через `key={studyTarget}` (`app/ai_companion_session.tsx:630-633`),
  что гарантированно сбрасывает историю чата при смене языка вместо утечки
  сообщений одного языка в контекст другого. Не нашёл отдельного постоянного
  (durable) хранилища для самого текста переписки — только метаданные
  (владение, лимиты, факт прохождения).

## 5. Safety (модерация контента)

**Вывод: два слоя защиты, но НЕИДЕНТИЧНЫ по составу — слой 1 (keyword) не
покрывает fr/de явно, слой 2 (OpenAI Moderation API) покрывает все языки
одинаково, потому что языко-независим по своей природе.**

- `functions/src/ai_safety.ts: TRIGGERS` (строки 72-155) — список ключевых
  фраз-триггеров (суицид/самоповреждение/абьюз/секс с детьми/угрозы насилия)
  явно размечен по языкам в комментариях: **EN, RU, UK, ES**. Для **fr и de
  фраз НЕТ вообще** ни в одной из 5 категорий (`suicide`, `self_harm`, `abuse`,
  `sexual_minors`, `violence`) — проверено прямым чтением файла, не найдено ни
  одной французской или немецкой фразы в `TRIGGERS`.
- Слой 2 — `moderateUserText()` (`functions/src/ai_safety.ts:220-260`) шлёт
  текст пользователя в OpenAI Moderation API без параметра языка и без
  фильтрации по языку — эта модель (`omni-moderation`, судя по паттерну
  вызова) мультиязычна по своей природе и не требует locale-специфичного
  словаря. Она вызывается ВСЕГДА для НЕ-флагнутого keyword-слоем текста
  (`functions/src/premium_dialog.ts:1027-1034`, тот же код в
  `premium_dialog_stream.ts:364-377`) — значит fr/de пользователи получают
  реальную защиту через слой 2, просто без "быстрого" слоя 1 (keyword-детектор
  работает без сетевого вызова, мгновенно; Moderation API имеет сетевую
  задержку и таймаут, хоть и не блокирует ответ, т.к. идёт параллельно).
- Отдельно — регулируемый медицинский совет (`containsUnsafeRegulatedAdvice`,
  `functions/src/premium_dialog.ts:645-648`) — здесь ЕСТЬ полноценные regex
  для медицинских терминов на всех 4 языках (`MEDICAL_DOSAGE_RE`,
  `MEDICAL_PRODUCT_RE`, `MEDICAL_RECOMMEND_RE`, `MEDICAL_DIAGNOSIS_RE` —
  строки 645-648 содержат явные fr/de паттерны: `paracétamol|ibuprofène`,
  `paracetamol|ibuprofen...Tabletten`). Эта конкретная проверка полностью
  локализована для всех языков.
- Системная safety-инструкция `SAFETY_SYSTEM_INSTRUCTION`
  (`functions/src/ai_safety.ts:60-65`) написана на английском и передаётся
  модели как системный промпт (не зависит от языка ответа модели — сама
  инструкция одна для всех targets, что нормально, т.к. модель мультиязычна и
  понимает английские инструкции одинаково хорошо независимо от языка диалога).
- **Итог по риску**: НЕ полная заглушка (слой 2 реально работает на fr/de), но
  ассиметрия реальна — быстрый keyword-слой (мгновенный, без сети, без
  зависимости от аптайма OpenAI Moderation) защищает только en/ru/uk/es.
  Если Moderation API недоступен/таймаутит для конкретного fr/de сообщения
  (`moderateUserText` явно проглатывает ЛЮБОЙ сбой и возвращает "не флагнуто",
  строки 244-260 в ai_safety.ts, это НАМЕРЕННОЕ поведение "не блокировать
  ответ"), то фраза на французском/немецком о суициде/самоповреждении НЕ будет
  поймана НИ ОДНИМ слоем в этот момент — то же сообщение на русском/испанском
  было бы поймано мгновенно слоем 1 даже при сбое сети.

## 6. Стоимость (модель/квоты по языкам)

**Вывод: полностью единая стоимость и квоты — языковых различий нет вообще.**

- `functions/src/openai_dialog_model_config.ts` — модель диалога
  (`MODEL_DEFAULT = 'gpt-4o-mini'`, настраиваемая админом через
  `admin_runtime_config/openai_dialog_model`) читается и применяется без
  какого-либо параметра `studyTarget`/`target` — один и тот же конфиг для всех
  языков. `ALLOWED_DIALOG_MODELS` — общий список из 4 моделей, тоже без
  языковой привязки.
- Квоты (`DIALOG_FREE_DAILY_REPLIES_DEFAULT = 10`,
  `DIALOG_PREMIUM_DAILY_REPLIES_DEFAULT = 200`,
  `resolveConfiguredDialogQuota()`) — единый конфиг
  `admin_runtime_config/openai_dialog_quota`, без разбивки по языку. Не нашёл
  ни одного места в `openai_dialog_model_config.ts`,
  `premium_dialog.ts`, `premium_dialog_stream.ts`, где цена/токен-лимит/модель
  зависели бы от `studyTarget`.
- Цена сценариев в рунах (`DIALOG_PRICE_RUNES = 5000`,
  `DIALOG_PRICE_RUNES_HARD = 10000`, `app/ai_dialog_scenarios.ts:70-88`) —
  свойство КОНКРЕТНОГО сценария (обычный/сложный), а не языка: один и тот же
  сценарий "coffee" стоит одинаково независимо от того, изучает ли пользователь
  через него en, es, fr или de.
- Собственно СТОИМОСТЬ выполнения (токены OpenAI) КОСВЕННО может отличаться
  между языками из-за разной токенизации (например, немецкий текст с составными
  словами часто токенизируется иначе английского), но это свойство модели
  OpenAI, а не решение проекта — код не делает НИЧЕГО специального для
  компенсации или учёта этого по языкам (нет per-language token budget или
  cost multiplier). Не нашёл evidence разницы в лимитах или мониторинге
  стоимости по языку.

## Найденные риски (для решения владельцем)

1. **🔴 Keyword safety-слой не покрывает fr/de.** `TRIGGERS` в
   `functions/src/ai_safety.ts` содержит фразы только на en/ru/uk/es. При сбое
   OpenAI Moderation API (сеть/таймаут/квота — код намеренно "тихо" пропускает
   такой сбой как "не флагнуто") сообщение о суициде/самоповреждении на
   французском или немецком **не будет поймано вообще**, тогда как то же
   сообщение на испанском поймает мгновенный keyword-слой независимо от
   доступности сети. Это разный уровень защиты по языкам в конкретном
   аварийном сценарии — стоит решить, добавлять ли fr/de фразы в `TRIGGERS`
   (риск невелик по вероятности, но последствие — самая тяжёлая категория
   (суицид/дети), поэтому подсвечиваю явно).

2. **🟡 Формальная evidence "pending-independent-review" никогда не станет
   PASS без ручного действия.** Уже задокументированная находка реестра
   (раздел 1 CONTENT_LOCALE_REGISTRY.md), подтверждена на уровне кода: поля
   `englishBenchmarkSha256`/`sharedManifestSha256`/`promptContractSha256` в
   `app/dialogue_language_packs.ts` буквально равны строке-заглушке
   `'pending-independent-review'`, а `DIALOGUE_LANGUAGE_ACTIVATION_RECEIPTS`
   в `app/dialogue_language_activation.ts` — пустой объект. Формально ни один
   из требуемых `requiredEvidence` списков (`SPANISH/FRENCH/GERMAN_AI_DIALOG_REQUIRED_EVIDENCE`
   в `app/ai_dialog_target_gate.ts`) никогда не будет отмечен закрытым, пока
   кто-то вручную не посчитает и не впишет настоящие SHA-256 хэши. Это не
   баг — так и задумано владельцем (ручной release override), но стоит знать,
   что "review evidence" не появится сама по себе.

3. **🟡 Grammar-validation ответа ученика полностью на совести LLM, без
   детерминированной проверки ни для одного языка.** Это не пробел именно
   es/fr/de (для en то же самое), но раз задание спрашивало про "диакритику,
   альтернативные формы" — детерминированного слоя для этого нет вообще ни для
   одного языка; вся коррекция происходит внутри промпта модели.

4. **Не найдено (явно, не гадаю):**
   - Не нашёл прямого автотеста, который реально запускал бы живой
     TTS/ASR на fr-FR/de-DE устройстве (только модульные тесты чистой функции
     `resolveDialogueVoiceCapability` с моками инвентаря голосов) — то есть
     "голос физически звучит на реальном iPhone для fr" не подтверждено кодом,
     только логика решения подтверждена.
   - Не нашёл per-language cost dashboard/лимита токенов — если у владельца
     есть скрытая проблема с более дорогой токенизацией немецкого/французского
     текста, код её никак не отслеживает и не компенсирует.
