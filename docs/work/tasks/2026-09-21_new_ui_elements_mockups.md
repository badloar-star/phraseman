# Task packet: макеты новых элементов интерфейса по итогам аудита 21.09

Governance-ID: TG-3FB5BE68FB41
Status: Planned
Owner: сессия Claude Opus 5 (аудит UX всех экранов)
Related epic/enabler: docs/work/tasks/2026-09-21_app_wide_ux_gap_audit.md

## Outcome

Владелец получает **точные по коду** макеты (не «примерно так выглядит») всех элементов
интерфейса, которых приложению не хватает по итогам аудита 144 экранов, вместе с
прописанными правилами поведения: когда элемент появляется, как анимируется, что
делает при ошибке, где Optimistic UI, где откат.

Наблюдаемый результат:
- два HTML-макета, открываемых в браузере, в которых каждый элемент показан во всех
  состояниях (покой → действие → успех → ошибка), с живыми анимациями и регулятором
  скорости для разглядывания деталей;
- скелеты React Native компонентов, собранные на реальных токенах проекта, готовые к
  подключению отдельными задачами.

Мера успеха: владелец может посмотреть макет и сказать «да/нет/поправь вот это» по
каждому элементу, не запуская приложение и не читая код; принятые элементы переходят
в реализацию без повторного проектирования.

## Scope

**In scope (новые файлы, ничего существующего не трогаем):**
- `docs/v2/mockups/33-new-ui-system-catalog.html` — каталог 10 переиспользуемых элементов:
  тост успеха, тост ошибки с «Повторить», undo-снэкбар с таймером, подтверждение траты
  с чеком «было → станет», плашка «данные устарели», пустое состояние с действием,
  кликабельная строка статистики, шторка паузы тренировки, поиск в списке,
  pull-to-refresh и счётчики-бейджи на плитках.
- `docs/v2/mockups/34-new-ui-scenes.html` — ТОП-12 сцен из аудита: элементы каталога
  в реальном контексте экранов приложения.
- `components/ui/new/*.tsx` — скелеты компонентов на токенах проекта,
  **НЕ импортируемые ни одним экраном**.

**Out of scope (сознательно не трогаем):**
- любая правка существующих экранов в `app/**` и `components/**` вне `components/ui/new/`;
- подключение новых компонентов к экранам — отдельные задачи после одобрения макетов;
- раздел MAX (запломбирован решением владельца 04.09);
- файлы Арены (запрет на откат/перезапись), пейволы, онбординг — не покрыты аудитом.

## Architecture

**Текущая граница.** Токены живут в `constants/theme.ts` (5 тем), движение в
`constants/motion.ts` и `constants/motionHybrid.ts`, хром тостов в
`constants/themedToastChrome.ts`. Тост уже существует — `components/ActionToast.tsx`,
слушает событие `action_toast` через `app/events.ts`, имеет 5 тонов
(success/error/info/warning/reward), геометрию minHeight 66 / radius 18 / padding 12,14.

**Намеренная граница.** Новые элементы — **расширение существующих систем, а не
параллельная вселенная**:
- тосты расширяют `ActionToast` (полоса жизни, кнопка действия, undo-кольцо), а не
  вводят второй механизм тостов — иначе на экране смогут оказаться две очереди тостов;
- подтверждение траты строится на `ThemedConfirmModal` (уже есть spring damping 16 /
  stiffness 180, дрожь через `TOAST.errorShakePx`);
- шторка паузы — та же геометрия bottom-sheet, что в эталоне 23-modals-states.

**Поток данных.** Макеты — статический HTML, данных не трогают. Скелеты компонентов
принимают всё пропсами и не ходят в сеть и в Firestore сами: решение «что показать»
принимает вызывающий экран. Это сознательно: компонент, который сам лезет за данными,
нельзя переиспользовать и невозможно протестировать.

**Инварианты, которые соблюдают макеты и скелеты:**
- нет обводок вокруг блоков (только односторонние разделители тоном);
- нет подписей-расшифровок мелким шрифтом под названием;
- нет `adjustsFontSizeToFit`;
- анимируются только `transform` и `opacity` (UI-тред, не JS);
- скелетон = точная геометрия финального кадра (layout stability);
- `prefers-reduced-motion` выключает движение во всех макетах.

**Решение:** макеты в `docs/v2/mockups/` рядом с уже утверждёнными (23, 24, 27, 30),
с наследованием их системы токенов 1:1 — чтобы владелец сравнивал новое со старым
в одном визуальном языке, а не через переводчик.

## Security and privacy

**Не применимо, и вот почему конкретно:**
- макеты — статический HTML без сети, без аналитики, без внешних ресурсов
  (иконки — инлайн SVG, шрифты — системные), не загружаются в приложение и не
  попадают в бандл;
- скелеты компонентов не содержат запросов, ключей, токенов и не читают хранилище;
- персональных данных в макетах нет: имена, балансы и фразы — выдуманные
  («to look forward to», 340 жемчужин), реальные uid и email не используются.

**Privacy Policy не затрагивается:** новых полей, сервисов, разрешений и путей
передачи данных задача не вводит. При реализации отдельных элементов это надо
перепроверить — экспорт данных и вложение скриншота в поддержку (оба есть в аудите)
политику затронут, но они **вне scope этой задачи**.

## Technical debt

- **Существующий тост не умеет действий и не показывает срок жизни** — *Contain*.
  Макет фиксирует целевое поведение; расширять `ActionToast.tsx` будет отдельная
  задача. Граница: новые скелеты лежат в `components/ui/new/` и ни на что не влияют.
  Условие выхода: элемент одобрен владельцем → расширяем существующий компонент,
  скелет удаляем. Не создаём второй тост-механизм ни при каких условиях.
- **Скелеты компонентов без тестов** — *Accept temporarily*. Владелец: эта задача.
  Дата пересмотра: момент подключения к экранам. Потолок влияния: нулевой, пока ни
  один экран их не импортирует. При подключении тесты обязательны.
- **Макеты дублируют CSS-систему из 24-missing-states.html** — *Accept temporarily*.
  Так устроены все макеты проекта (каждый самодостаточен и открывается один). Вынос
  общей системы в отдельный CSS сделает макеты неперсылаемыми по одному файлу.
  Условие пересмотра: если макетов станет больше 40.

## Rollback

Задача добавляет **только новые файлы** и не меняет ни одного существующего.
Откат — удаление добавленных файлов:

```
docs/v2/mockups/33-new-ui-system-catalog.html
docs/v2/mockups/34-new-ui-scenes.html
docs/work/tasks/2026-09-21_new_ui_elements_mockups.md
components/ui/new/*.tsx
```

Потери пользовательских данных невозможны: код не исполняется в приложении, в бандл
не попадает (макеты — документация, скелеты никем не импортируются, Metro их не
тянет без статического `require`). Ни одно выданное право/покупка не затрагивается.
Необратимых миграций нет.
