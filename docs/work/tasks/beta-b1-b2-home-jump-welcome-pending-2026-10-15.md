# Бета-тест Б1/Б2: прыжок Главной у нового гостя, окно «Встречайте 2.0» при медленном ответе, теория под заголовком, /lessons_list (15.10)

Governance-ID: TG-D6A182AC5410

## Outcome
(1) 🔴 Главная нового гостя: карточка «Продолжить» сначала скелетон, затем исчезает, и весь контент прыгает вверх на ~235 px (тап по «Уроки» попал в видео) — у человека без последнего урока скелетон держится доли секунды, а не до конца тяжёлой загрузки Главной; раскладка не прыгает. (2) P2/P11: окно «Встречайте PhraseMan 2.0» не теряется, если сервер ответил дольше 8 с — показываем при следующем запуске/входе на Главную ровно один раз; лог `[WHATSNEW-GATE]`. (3) Б2: теория урока — прокручиваемый текст не виден под заголовком «Урок 1» (заголовок перекрывает контент); (4) /lessons_list: первая отрисовка 1231 мс — найти тяжёлое на первом кадре и отложить.

## Scope
`app/(tabs)/home.tsx` (ранний узкий эффект чтения ключа «последний урок», только он; тело `loadData` не трогаем — сторож `home_lesson_progress_single_pass`); `app/legacy_bonus_client.ts` (метка `welcomePending`, на время правки — моя, по решению координатора; Ядро предупреждено); экраны теории урока и списка уроков — после первых двух пунктов.

## Architecture
(1) Дешёвое чтение одного ключа AsyncStorage сразу после монтирования (то же, что делает loadData, но без остальной загрузки): нет записи → «урока нет», заготовка снимается через `animateNextLayoutTransition`, с логом `[HOME-CONTINUE]` (значение ключа и решение). Есть запись — оставляем заготовку loadData (нужен прогресс). (2) При `timedOut` метка done получает `welcomePending: true` и полный результат для окна; на следующем запуске/входе читаем метку, показываем окно один раз и снимаем флаг.

## Security and privacy
Данные не покидают устройство; в метке — те же числа бонуса, что уже получены от сервера (итог монет, откуда).

## Technical debt
Ответ сервера по-прежнему не ждём дольше потолка — окно вернётся при следующем запуске; сам запрос не отменяем.

## Verification
Тест по исходникам и юнит: нет ключа → заготовка снята и залогирована; тест окна: таймаут → окно на следующем старте ровно один раз.

## Дополнение: метка welcomePending снимается только когда окно показано

Решение координатора/владельца: обновившиеся должны увидеть окно «Встречайте 2.0» обязательно. Метка `welcomePending` (+ результат) пишется при ЛЮБОМ ответе, где окно положено (не только при таймауте), и снимается только когда шторка реально на экране (слот получен) либо нажато «Понятно» — а не при получении ответа/запуске. Закрыли приложение до показа — при следующем запуске окно возвращается. Лог `[WHATSNEW-GATE] shown/cleared`. Начисление не тронуто (идемпотентно, replayed).

## Дополнение: P25 — окно «Встречайте 2.0» и метка привязаны к владельцу
Governance-ID: TG-F23546306CA2
Ревизор P25: `welcome` и `pendingClear` в `app/legacy_bonus_client.ts` не сбрасываются при смене владельца — гость после выхода мог увидеть окно с монетами прошлого аккаунта, а прошлый аккаунт терял своё окно. Фикс: состояние окна помнит владельца; подписка на смену аккаунта сбрасывает ПАМЯТЬ (не метку в хранилище — метка прошлого владельца остаётся); окно показывается только если владелец окна = текущий; следующий запуск для нового владельца разрешён (флаг «уже запускали» сбрасывается). Лог `[WHATSNEW-GATE] owner_changed`. Тест: «окно A ожидает → выход → гость окна не видит → вход A → окно A показано один раз».
