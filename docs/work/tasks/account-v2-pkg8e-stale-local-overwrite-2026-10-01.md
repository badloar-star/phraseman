# Task packet: Account V2 — Пакет 8E: старая локальная копия не перезаписывает правку с другого устройства

Governance-ID: TG-473FE4DBA2C3
Status: Done (SPEC+SECURITY APPROVE)
Owner: Claude session (Account V2, /loop)

## Outcome

P2 из ревью 8B (существует с 6G/7A): гидрация засевает зеркало серверными значениями карточки, а применение — только добавление (существующую локальную карточку не трогает). Сценарий: на устройстве B человек правит текст своей карточки → на устройстве A та же карточка уже есть со старым текстом → после гидрации A зеркало = новый текст, локально = старый → первый снимок A шлёт старый текст как правку с свежей base → сервер принимает, правка B потеряна.

Починка (выбрать безопасный вариант и обосновать в `// зачем:`):
- для карточек, уже существующих локально к моменту гидрации, решать по времени: если серверная версия свежее локальной (`updatedAt` 7E / `updatedAtMs` сущности против локальных `updatedAt`/`addedAt`/`lastSeenAt`, с запасом по часам как в 7E) — ПРИМЕНИТЬ серверные поля локально (а не только засеять зеркало); если локальная свежее — засеять зеркало из локальной копии (чтобы правка ушла);
- неизвестное время с любой стороны → не перезаписывать ничего у человека и не слать: зеркало из локальной копии + лог причины (без потери: позже правка уйдёт обычным путём или сервер выиграет при следующей гидрации — описать).
Касается своих карточек (тексты) и полей сохранённых карточек, которые человек может менять; SRS — уже по updatedAtMs (не трогать). Логи `[ACCOUNT-V2] hydrate card_conflict decision=… reason=…` без id/текста.

## Итог исполнителя (2026-10-01)

**RED.** `tests/account_v2_stale_local_8e.test.ts` идёт настоящим путём `hydrateAccountsV2Scope` (зеркало в памяти) → `applyAccountsV2HydrationLocally` (настоящие хранилища) → первый снимок → план производителя. До починки сценарий B→A: на A остался старый текст, первый снимок слал его как правку (4 из 5 красных; «одинаковые версии» — зелёный уже после 8B).

**Решение — в одном месте** `app/accounts_v2_hydration_conflicts.ts` (`decideCardConflict` + `applyHydratedCardConflicts`), первым шагом применения — ДО любых записей приложения (каждая запись карточек запускает снимок производителя). Только для карточек, которые уже лежат на телефоне и чьё зеркало засеяла ЭТА гидрация (производитель их раньше не вёл). Сравнение версий — без SRS, в нормализации 8B (производные поля приложения не конфликт). Время правки = max(updatedAt 7E, addedAt) по каждой стороне; SRS (свайпы) не входит — у него своё правило по updatedAtMs. Запас по часам — 1 ч, как в 7E.
- сервер свежее → серверные поля применяются локально (`replaceSavedFlashcardsFromAccountsV2` в hooks/use-flashcards.ts / `updateCustomCards`, под очередью записи; если человек изменил карточку после решения — не трогаем, лог `apply_skip reason=local_changed_since_decision`);
- локальная свежее → у человека не меняем, зеркало остаётся серверным — первый снимок отправляет локальную правку (она последняя);
- неизвестное время или в пределах запаса → у человека не меняем и ничего не шлём: зеркало засевается локальной копией (`HydrationSnapshot.mirror.seedFromLocal`, только если запись зеркала с момента засева не менял производитель; SRS-поля зеркала остаются серверными). Ничего не теряется: локальная версия у человека, серверная — на сервере; следующая правка любой стороны уйдёт обычным путём (поле, которое правят, уйдёт со свежей базой). Это же закрывает остаток 8B (точечные правки текста сохранённых карточек приложением без времени — больше не шлются после гидрации).
