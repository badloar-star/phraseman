Поиск соперника не может зависнуть из-за чужой висящей очереди. Владелец:

## Диагноз (лог устройства 14:38:19 → 14:39:20)

```

14:38:35 reconcile(heartbeat) failed: arena_queue_request_active
14:38:50 ... то же
14:39:05 ... то же
14:39:20 ... то же
```

Сервер (`arena_v2.ts:2006`) отбивает постановку, если за профилем уже висит
очередь со СТАРЫМ `requestId`. Клиент бесконечно повторяет heartbeat с новым
id и никогда не получает очередь — поиск идёт «вечно», ни бот, ни живой
соперник прийти не могут.

Осталась она от предыдущего поиска: тот закончился `accept_timeout`, матч
закрылся, а билет очереди на сервере остался в `waiting`.

## Scope

In scope: `modules/arena/background_search.ts`, `app/arena_background_search.ts`
— обработка `arena_queue_request_active`.

Out of scope: серверная логика, потолок 10 секунд (сделан отдельно).

## Architecture

**Причина.** Ядро обрабатывает только `arena_active_match_exists`. Второй
отказ того же класса — «за профилем висит ЧУЖАЯ очередь» — не обрабатывается
вовсе, и heartbeat крутится до бесконечности.

**Решение.** При `arena_queue_request_active` клиент снимает висящую очередь
(`arenaV2QueueCancel` без requestId — сервер закрывает текущую) и повторяет
постановку. Предел — две попытки, как у замка матча: бесконечный цикл
«отбой → отмена → отбой» недопустим.

`arenaV2QueueCancel(studyTarget)` без `requestId` закрывает очередь профиля
целиком — ровно то, что нужно, когда id старой очереди неизвестен.

**Инвариант.** Ни один отказ постановки в очередь не приводит к вечному
поиску: каждый либо разрешается за ≤2 попытки, либо честно заканчивает поиск.
