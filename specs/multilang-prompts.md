# Multilingual AI Prompts — по оси изучаемого языка (StudyTarget)

## Objective

Сделать **все OpenAI-промпты** приложения независимыми от изучаемого языка (target language), чтобы каждый изучаемый язык был **изолированным контекстом**, и любая AI-функция работала для **французского** ровно так же, как сегодня работает для английского — по тем же принципам (тёплый тон, «ты», простые слова, разборы, объяснения, диалоги/ситуации).

Сегодня все промпты в `functions/src` **жёстко зашиты под английский**: буквальные строки «English teacher», «explain THIS English phrase», «reply is ALWAYS in English», параметры `phraseEn`/`correctEn`/`goalEn`. Есть вторая ось — язык интерфейса/объяснения (`AiOutputLang`: ru/uk/es/pt-BR/vi/id/tr/pl/en) — она уже мультиязычна. **Не хватает первой оси — изучаемого языка (`StudyTarget`)**, которая в типах уже объявлена (`'en' | 'fr'`), плюмбится как данные (community_packs, client_reports, help_board), но **игнорируется в самих промптах**.

Целевой пользователь: тот, кто сейчас учит французский (target = `fr`) — он должен получать объяснения, разборы, диалоги, компас, недельный разбор и статистику **про французский и на своём родном языке интерфейса**, а не про английский.

### Две ортогональные оси (канон — не путать)

| Ось | Тип | Значения | Что задаёт | Резолвер |
|-----|-----|----------|-----------|----------|
| **OUTPUT / интерфейс** | `AiOutputLang` | ru, uk, es, pt-BR, vi, id, tr, pl, en | На каком языке НАПИСАНО объяснение/коучинг (родной язык юзера) | `resolveAiOutputLang` / `PROMPT_LANGUAGES` |
| **STUDY / изучаемый** | `StudyTarget` | en, fr | Какой язык УЧАТ; на каком языке фразы, реплики диалога, «wrap every … word» | `resolveStudyTarget` |

Обе оси уже существуют в `functions/src/ai_language_contract.ts`. Задача — **пронести `StudyTarget` во все промпты** как первоклассный параметр, симметрично `AiOutputLang`.

### Что «изолированный контекст» значит здесь (уточнено пользователем)

- **Общее на профиль (НЕ трогаем):** опыт (XP), лиги и очки лиги, осколки, персонаж, аватар. Остаются глобальными на пользователя.
- **Язык-специфичное (по активному изучаемому языку):** ошибки/слабые слова, «Моя практика», компас-бриффинг, вечерний ритуал, недельный разбор, статистика по языку. Пользователь учит французский → видит французские ошибки и практику, а НЕ английские.
- Инфраструктура этой изоляции **уже построена и работает**: `app/target_storage_keys.ts` (`targetKey(domain, target, id)` → `..._v2::fr::...`), `app/cloud_sync.ts` (`FRENCH_TARGET_SYNC_KEYS`, `SYNC_STUDY_TARGETS`), `assertTargetKey`-гард. Английский = legacy-ключи без сегмента, французский = `::fr::`. **В этой задаче хранилище/ключи НЕ меняем.** Задача — чтобы промпты и AI-поверхности читали/писали в контексте активного target, который клиент уже знает (`useStudyTarget()`).

## Requirements

### A. Ядро контракта языков

1. В `functions/src/ai_language_contract.ts` добавить единый справочник имён изучаемых языков: функция `studyTargetName(target: StudyTarget): string` → `'en' → 'English'`, `'fr' → 'French'`. Справочник расширяемый (добавление языка = одна запись). Не дублировать по файлам — существующие локальные мапы (`help_board.ts` `languageName`, `premium_dialog.ts`) должны опираться на этот единый источник.
2. Добавить (или переиспользовать) в контракте резолвер `resolveStudyTarget(value)` для всех точек входа промптов, которые сейчас его не вызывают. Дефолт при неизвестном/пустом значении — `'en'` (обратная совместимость).
3. Ни один промпт-билдер не должен содержать литерал `English`/`английск-` как **зашитый** изучаемый язык. Разрешён только через подстановку `${studyTargetName(target)}`. (Литерал `English` в справочнике имён — ОК.)

### B. Промпты объяснений/разборов (bucket «content-agnostic»)

Для каждого из билдеров ниже: добавить параметр `studyTarget: StudyTarget` (или прочитать его из уже приходящего payload), и заменить зашитый «English» на `${studyTargetName(target)}`. Логика, тон и структура остаются прежними.

4. `functions/src/explain/explain_prompts.ts` → `buildExplainPrompt`: «warm, patient English teacher» → «…{targetName} teacher»; «explain THIS English phrase» → «…this {targetName} phrase»; «wrap every English word» → «…every {targetName} word»; «English phrase to explain:» → «{targetName} phrase to explain:». Параметр `phraseEn` можно оставить по имени (внутренняя переменная), но семантика — «фраза на изучаемом языке».
5. `functions/src/explain/explain_prompts.ts` → `JUDGE_SYSTEM_PROMPT` + `buildJudgeUserPrompt`: судья-валидатор должен проверять, что объяснение про фразу на **изучаемом** языке (а не «English phrase»). «understand ONE English phrase» → «…one {targetName} phrase». `buildJudgeUserPrompt` уже получает `Target language: {outputLang}` — добавить отдельно `Study language: {targetName}`, не смешивая с языком объяснения.
6. `functions/src/explain/choice_explain_prompts.ts` → `buildChoicePrompt`: те же замены; параметр target пронести.
7. `functions/src/explain/quiz_explain_prompts.ts` → `buildQuizPrompt`: те же замены.
8. `functions/src/weekly_review.ts` → `buildSystemPrompt`: разбор недели должен говорить об изучаемом языке юзера; заменить зашитые «English» упоминания на `{targetName}`.
9. `functions/src/stats_insights.ts` → `buildSystemPrompt`: аналогично; статистика по активному изучаемому языку.
10. `functions/src/compass/compass_prompts.ts` → `buildCompassPrompt`: заменить зашитый «English» на `{targetName}`. Список запрещённых слов (сейчас English-only) сделать зависимым от изучаемого языка — см. требование 15.

### C. Промпты с зашитыми английскими данными (bucket «English data baked in»)

11. `functions/src/mistake_explain.ts` → `buildFullMessages` + `buildEli5Messages`: заменить «English phrase»/«every English word» на `{targetName}`. **Английские примеры-данные** («don't»=«do not», «I'm»=«I am», «cake», «dishes») вынести в **пер-таргетный набор** (map по `StudyTarget`): для `en` — текущие английские короткие формы/примеры; для `fr` — французские эквиваленты (напр. элизии «je + ai → j'ai», «le + ami → l'ami», нейтральные примеры-слова вместо «cake»/«dishes»). Билдер выбирает набор по `studyTarget`. Если для target набора нет — промпт не должен приводить конкретный английский пример (fallback на общую формулировку без примера).
12. Контраст-подсказки it/that / this/that и подобные англо-специфичные грамматические оси (если они зашиты как инструкции): пометить как англо-специфичные и подавать только при `target === 'en'`. Для `fr` эти конкретные англо-оси не подаются (модель разбирает по общей инструкции). Не выдумывать французские «эквиваленты» англо-грамматики.

### D. Диалоги / Ситуации (bucket «worst — fully English»)

Решение пользователя: **те же сценарии**, ИИ отвечает **по-французски**; отдельный французский набор сценариев НЕ создаём.

13. `functions/src/premium_dialog.ts`:
    - `premiumDialogSend` начинает принимать `studyTarget` из request (тип `'en' | 'fr'`, дефолт `'en'` через `resolveStudyTarget`). Существующий `interfaceLang` (ось OUTPUT) сохраняется.
    - `GLOBAL_RULES`: «English-speaking conversation partner» → «{targetName}-speaking…»; «OUTPUT LANGUAGE (ABSOLUTE RULE): your spoken reply is ALWAYS in English … This is English practice» → «…ALWAYS in {targetName} … This is {targetName} practice». Правило «если юзер пишет на своём языке — продолжай на {targetName} и предложи фразу на {targetName}».
    - `buildScenarioSystemPrompt`, `buildCompanionSystemPrompt`: все зашитые «English» → `{targetName}`. «wrap 1-3 useful English phrases in [[...]]» → «…{targetName} phrases…». `role`/`setting`/`persona`/`goalEn` остаются мета-инструкциями (модель их не произносит дословно), но реплики выдаёт на изучаемом языке.
    - `assertDialogReplyIsEnglish` → переименовать/обобщить в `assertDialogReplyMatchesTarget(reply, studyTarget)`; вместо `targetLang: 'en'` — `targetLang: studyTarget`. Гард должен пропускать французский ответ, когда target = `fr`, и заворачивать не-целевой язык.
    - Game-block/objectives: `objectives[].en` остаётся мета-описанием цели (данные для модели), coachTips — на языке интерфейса (`interfaceLang`), рекомендуемые фразы цитируются на изучаемом языке.
14. `functions/src/premium_dialog_review.ts` → `buildReviewSystemPrompt`: «quote any recommended English phrase in English» → «…{targetName} phrase in {targetName}». CEFR остаётся общей шкалой (см. требование 17). Praise/note — на языке интерфейса.
15. `functions/src/help_board.ts` → `buildHelpBoardCompassPrompt`: уже принимает `targetLang: StudyTarget` + `uiLang` и использует `languageName(targetLang)` — это **эталонный паттерн**. Привести его `languageName` к единому `studyTargetName` из контракта (требование 1). Проверить, что режимы тона (genuine/offtopic/rude/dangerous) не содержат зашитого «English» вне подстановки.

### E. Список запрещённых/предпочитаемых слов (словарь Библии в промптах)

16. Списки «не говори lesson/mistake/statistics», предпочтения «фраза не слово», фильтры слов-паразитов — сейчас часть завязана на конкретные английские/русские слова. Эти списки относятся к **языку вывода** (`AiOutputLang`), НЕ к изучаемому языку, и менять их логику не требуется; но там, где в них зашито слово «English» как изучаемый язык, заменить на `{targetName}`.

### F. Клиентская проводка (минимально необходимая + разрешено глубже)

17. CEFR (A1–C2) остаётся **общей шкалой для всех изучаемых языков** — отдельную систему уровней для французского НЕ вводим. Промпты говорят «level {CEFR} in {targetName}».
18. `app/ai_dialog_session.tsx`: уже вызывает `useStudyTarget()`, но НЕ передаёт `studyTarget` в `callPremiumDialogSend`. Добавить `studyTarget` в объект запроса `premiumDialogSend` (scenario и companion). Это замыкает диалоги для французского.
19. Пройти по остальным клиентским вызовам AI-функций (explain phrase/choice/quiz, mistake explain, compass, weekly review, stats insights, help board) и убедиться, что `studyTarget` из `useStudyTarget()` передаётся на сервер там, где сервер теперь его ожидает. Где клиент его уже шлёт (help board) — ничего не делать. Где не шлёт — добавить поле в вызов.
20. Разрешено при необходимости добавлять пер-таргетные данные на клиенте (напр. `goalFr` в сценарии, French UI-копию подсказок) — но только если без этого требование не выполняется. Не делать лишнего рефактора.

### G. Кэш и версии

21. Промпты объяснений/разборов кэшируются по ключу, включающему язык (`phraseHashFor(phrase, langKey)` / `resolvePromptLangKey`). Ключ кэша ДОЛЖЕН включать **изучаемый язык** (`studyTarget`), иначе француз получит закэшированное английское объяснение той же строки. Добавить `studyTarget` в состав кэш-ключа для всех кэшируемых AI-объяснений (explain, choice, quiz, mistake). Это также автоматически инвалидирует старое.
22. Бампнуть версии кэша / `LANGUAGE_CONTRACT_VERSION` там, где старые записи иначе не перегенерятся, чтобы изменённые промпты вступили в силу.

## Constraints

- **Стек:** TypeScript, Firebase Cloud Functions v2 (`functions/src`), React Native/Expo клиент. OpenAI через существующие вызовы (`chat.completions` и т.п.). Ничего нового в стек не вводим.
- **Не трогать (уже работает):** `app/target_storage_keys.ts`, `app/cloud_sync.ts` (namespacing прогресса `::fr::`), `app/study_target.ts`, `app/study_languages.ts` (гейт «1 язык фри»), `StudyTargetContext`. Прогресс/ошибки/практика уже изолированы по языку — эту инфраструктуру НЕ переписываем.
- **Профиль общий:** XP, лиги, очки лиги, осколки, персонаж, аватар — остаются глобальными. Никакой per-target изоляции для них не вводить.
- **Продовая видимость французского** гейтится флагом (`ENABLE_DEV_STUDY_TARGET_LANG`, `STUDY_TARGETS=['en']`). Эта задача НЕ включает французский в проде — она делает промпты готовыми, чтобы при включении флага всё работало. Не менять сам гейт.
- **Обратная совместимость:** для существующих англоязычных юзеров поведение и тексты промптов должны остаться идентичными (target по умолчанию `'en'`). Английский путь не должен измениться ни на слово, кроме как через ту же подстановку `{targetName}='English'`.
- **Параллельные сессии:** пользователь работает в одной ветке/дереве, коммиты атомарные. Если файл занят другой сессией (чужие незакоммиченные правки) — не лезть, искать обход, сообщить. НЕ создавать worktree/ветки, НЕ использовать `git stash`.
- **Тон/Библия:** сохранить все существующие правила тона (тёплый «ты», простые слова, ≤10 слов, gain-framing, no-mind-reading, запрет слов-паразитов), внесённые в `PROMPT_AUDIT_2026-06-21.md`. Мультиязычность НЕ должна их откатывать.
- **Performance Bible / AGENTS.md:** соблюдать при любых клиентских правках экранов.
- **Секьюрити:** промпт-инъекции — входные данные (фраза, текст диалога) остаются DATA, не инструкциями; существующие анти-инъекционные обёртки сохранить.

## Edge cases to handle

- **`studyTarget` не передан / пустой / неизвестный** → `resolveStudyTarget` возвращает `'en'`; промпт валиден и идентичен сегодняшнему английскому. Никаких падений.
- **Клиент старой версии** (не шлёт `studyTarget`) обращается к обновлённому серверу → сервер дефолтит на `'en'`; англоюзеры не ломаются. Французский на старом клиенте просто не активируется — это ожидаемо.
- **Гард языка ответа диалога:** если модель для target=`fr` случайно ответила по-английски (или наоборот) → `assertDialogReplyMatchesTarget` заворачивает, показывается дружелюбная ошибка «попробуй ещё», как сегодня для английского.
- **Кэш-коллизия по строке:** одна и та же строка-фраза существует и в английском, и во французском контенте → кэш-ключ с `studyTarget` разводит их; француз не получает английское объяснение и наоборот.
- **Смешанный вывод:** объяснение про французскую фразу написано на русском (язык интерфейса) и цитирует французские слова в кавычках — это КОРРЕКТНО. Судья/гард языка вывода не должен реджектить за французские вставки, аналогично тому, как сегодня не реджектит за английские (`non_target_language` — только если ПРОЗА объяснения не на языке интерфейса).
- **mistake_explain без пер-таргетных примеров для target:** если для изучаемого языка нет набора коротких форм/примеров → промпт не подставляет чужие (английские) примеры, а даёт общую формулировку. Никогда не показывать английский «don't=do not» французу.
- **Диалог-персона на английском колорите (имена Mia/Zoe и т.п.):** персона — мета-инструкция; ИИ говорит на изучаемом языке, но имя персонажа как есть — допустимо (не требуется локализовать имена в этой задаче).
- **CEFR у французского:** уровни A1–C2 подаются одинаково; никаких DELF/DALF-специфичных порогов не вводить.

## Definition of done

Проверяемый чеклист. Для каждого — как убедиться.

1. **Инвентарь закрыт:** `grep -rn "English"` по `functions/src` не находит ни одного места, где «English» — это **зашитый изучаемый язык** в теле промпта (допустимы: справочник имён, комментарии, вывод-язык). Ручная проверка каждого совпадения.
2. **Все билдеры принимают target:** `buildExplainPrompt`, `buildChoicePrompt`, `buildQuizPrompt`, `buildFullMessages`, `buildEli5Messages`, `buildCompassPrompt`, `weekly_review`/`stats_insights` `buildSystemPrompt`, `buildScenarioSystemPrompt`, `buildCompanionSystemPrompt`, `buildReviewSystemPrompt`, `buildHelpBoardCompassPrompt` — каждый использует `studyTargetName(target)` вместо литерала. Проверка: чтение сигнатур + тела.
3. **Диалоги на французском:** при `studyTarget='fr'` система-промпт `premiumDialogSend` инструктирует отвечать по-французски, ключевые фразы `[[...]]` на французском, гард пропускает французский ответ и заворачивает английский. Проверка: юнит-тест на `buildScenarioSystemPrompt('fr', …)` содержит «French», не «English»; тест на `assertDialogReplyMatchesTarget` (fr пропущен, en завёрнут).
4. **Английский путь не изменился:** для `studyTarget='en'` итоговый текст всех промптов побайтово эквивалентен «до» (кроме мест, где `{targetName}` подставляет ровно «English»). Проверка: снапшот-тесты промптов для `en` — до/после совпадают.
5. **Кэш разведён по языку:** кэш-ключ объяснений включает `studyTarget`; тест: одинаковая строка-фраза с `en` и `fr` даёт разные ключи, не переиспользует запись.
6. **Клиент диалогов замкнут:** `app/ai_dialog_session.tsx` передаёт `studyTarget` в `callPremiumDialogSend` (scenario и companion). Проверка: чтение вызова.
7. **Единый источник имён языков:** `help_board.ts`/`premium_dialog.ts` не держат собственных дубль-мап имён изучаемых языков — используют `studyTargetName` из контракта. Проверка: grep дублей.
8. **Тон сохранён:** правила из `PROMPT_AUDIT_2026-06-21.md` (тёплый «ты», ≤10 слов, gain-framing, no-mind-reading, анти-паразиты) присутствуют в изменённых промптах. Проверка: наличие соответствующих строк.
9. **Типы и сборка:** `cd functions && npx tsc --noEmit` → 0 ошибок; сборка `lib` — 0 ошибок. Клиент: `npx tsc --noEmit` → 0 ошибок.
10. **Тесты зелёные:** существующие тесты затронутых модулей (`ai_language_contract.test.ts`, `mistake_explain.test.ts`, `premium_dialog_prompt.test.ts`, `explain_*`, `compass`, `weekly_review`, `stats_insights`, `dialog_scenario_objectives.test.ts`, `help_board`) проходят; добавлены новые тесты на французский путь (п.3, п.5) и на неизменность английского (п.4).

## Out of scope

- **Изменение схемы хранилища/ключей прогресса** (`target_storage_keys.ts`, `cloud_sync.ts`) — уже работает, не трогаем. В частности НЕ переводим английский с legacy-ключей на `::en::` и НЕ обобщаем `(en|fr)`-юнион на N языков (это отдельная будущая задача).
- **Изоляция XP/лиг/осколков/аватара по языку** — они остаются общими на профиль по решению пользователя.
- **Создание французского учебного контента** (уроки, фразы, квизы, отдельные fr-сценарии диалогов) — это пайплайн «gustav», отдельные спеки (`gustav-french-*`). Здесь только промпты + подстановка target.
- **Включение французского в проде** / изменение гейта `ENABLE_DEV_STUDY_TARGET_LANG` / `STUDY_TARGETS` / гейта «1 язык фри».
- **Отдельная уровневая шкала для французского** (DELF/DALF) — CEFR общая.
- **Локализация имён персонажей диалогов** и прочая косметика, не влияющая на язык вывода.
- **Новые языки кроме en/fr** — каркас делаем расширяемым (добавление = запись в справочник), но данные наполняем только для en и fr.
- **Развёртывание** (`firebase deploy`) и пересборка приложения — выполняет пользователь; спек только требует, чтобы всё собиралось и тесты были зелёными.
