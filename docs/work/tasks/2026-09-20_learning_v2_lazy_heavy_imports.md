# Task packet: Learning V2 — снять 2,2 МБ с открытия раздела

Governance-ID: TG-AE4EBA241260
Status: Planned
Owner: Claude (сессия 20.09.2026), требование владельца провести полный аудит

## Outcome

Раздел открывается быстро: при входе телефон больше не разбирает мегабайты
данных, нужных только для запуска занятия.

Владелец: «раздел тормозит ужасно, проведи аудит и найди все до единой
причины». Аудит слоя данных нашёл главное: при открытии вкладки уроков
синхронно парсится ~2,2 МБ сгенерированных модулей.

Мера успеха: замер — `lessons.tsx` больше не тянет статически три
генерированных файла; вход в раздел не ждёт их разбора.

## Scope

In scope:
- `app/(tabs)/lessons.tsx` — два статических импорта переводятся на ленивые;
- при необходимости тонкая обёртка-аксессор рядом с ними.

Out of scope:
- переделка самих генераторов (дубль хэшей, тексты в манифесте) — это
  отдельная работа над форматом данных, здесь только способ загрузки;
- `app/plan_content_impuls.ts` (5 МБ мёртвого кода) — в бандл не попадает,
  удаление отдельной задачей.

## Architecture

Замер (аудит + проверка вручную):

| Файл | Размер | Тянется из |
|---|---|---|
| `factory_native_manifest_v1.generated.ts` | 1171 КБ | `lessons.tsx:194` → client_v3 → course_v1 |
| `factory_production_audio_entries_v1.generated.ts` | 554 КБ | `lessons.tsx:202` → audio_pack |
| `factory_lesson_audio_index_v1.generated.ts` | 503 КБ | `lessons.tsx:202` → audio_pack |

Все пять импортируемых функций (`prepareCurrentLearningV2CourseSessionV3`,
`stageLearningV2CourseSessionReadyHandoffV3`,
`getLearningV2CourseSessionReadyTimingV3`,
`isLearningV2SessionAudioPublishedV1`, `prepareLearningV2SessionAudioPackV1`)
вызываются РОВНО ПО ОДНОМУ разу и только в пути подготовки занятия — ни одна
не нужна для первого кадра карты.

Решение: заменить статические `import` на динамический `await import()`
внутри тех функций, где они используются. Метро оставит модули в бандле
(они нужны офлайн), но разбор произойдёт при первом запуске занятия, а не
при открытии раздела.

Инвариант: при открытии раздела ни один из трёх генерированных модулей не
находится в статическом графе `lessons.tsx`.

Риск и как снят: подготовка занятия уже асинхронная (`Promise`), поэтому
`await import()` не меняет её контракт. Первый запуск занятия станет чуть
дороже — но там уже идёт ожидание с индикацией, в отличие от входа в раздел.

## Security and privacy

Не применимо: меняется только момент загрузки локальных модулей. Данные не
собираются, в сеть ничего не уходит, разрешений нет.

## Technical debt

- **Pay now:** ленивая загрузка трёх тяжёлых модулей.
- **Contain:** сторож, запрещающий статический импорт этих модулей из
  `lessons.tsx` — иначе следующая правка молча вернёт 2,2 МБ.
- **Accept temporarily:** дубль хэшей озвучки в двух файлах и локализованные
  тексты в манифесте (≈0,9 МБ) — переделка формата данных, владелец о ней
  уведомлён в итоге, отдельная задача.

## Verification

1. `tsc --noEmit` — ноль ошибок в затронутых файлах.
2. Сторожа карты + контракт founder pass (jest).
3. Замер: модули отсутствуют в статическом графе `lessons.tsx`.
4. Живой прогон владельцем: открытие раздела и запуск занятия.

## Rollback

Правка локальна в одном файле и обратима `git revert`. При откате
возвращаются статические импорты — поведение прежнее, данных не теряется.
