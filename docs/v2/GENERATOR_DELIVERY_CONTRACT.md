# Learning V2 — обязательный контракт полной готовности генератора

**Статус:** обязательный входной документ для каждой следующей сессии Learning V2

**Владелец требований:** владелец продукта
**Правило объявления результата:** до выполнения всех гейтов ниже запрещено сообщать, что генератор, курс или Learning V2 «готовы на 100%».

**Обязательный content-quality source:**
[`QUALITY_REFERENCE_GENERATED_CURRICULUM_V3.md`](./QUALITY_REFERENCE_GENERATED_CURRICULUM_V3.md).
Он не меняет продуктовую topology `32 урока × 56 сессий`, а определяет
проверяемое качество любого owner-generated материала: objective → content →
practice → retrieval/application → evidence, CEFR plausibility, естественность,
перевод, theory, tasks, audio, memory, assessment и cross-artifact consistency.
Любой generated/repair пакет обязан выдать локализованные findings, dimension
scorecard и evidence coverage по этому reference. Высокий средний score не
может скрыть BLOCKER/ERROR.

Раздел reference о Personal Plan применяется только к возможной будущей
отдельной специализации. Он не возвращает Personal Plan в основной путь и не
блокирует готовность текущего основного генератора.

## 1. Главный порядок работы

1. Работа идёт строго последовательно по `EXECUTION_PLAN_2026-08-09.md`, `README.md`, `HANDOVER.md` и этому контракту.
2. Следующая стадия начинается только после полного закрытия предыдущей: реализация, негативные тесты, smoke-тест, проверка интеграции, независимый аудит и точная запись результата в `HANDOVER.md`.
3. Частично готовый пакет называется только частично готовым. Зелёный узкий тест не означает готовность всего генератора или продукта.
4. Тестовый контент никогда не считается одобренным и не может попасть в релиз. Для проверки генератора Codex создаёт методически цельный эталонный тестовый урок с невозможными production-ID и явным `neutral_test_fixture`; только реальный контент уроков 1–32 создаёт владелец и вручную подтверждает его на каждом установленном этапе.
5. Эталон разрешено взять как основу только копированием в новый `production_candidate`: новые lesson/session/interaction/capsule/intro ID, новый fingerprint, полный повторный server-side разбор всех 56 сессий и отдельное подтверждение владельца. Простая смена `contentClass` у тестового пакета запрещена.
6. Никакой автоматической публикации, активации, production deploy или перехода к следующей стадии без отдельного разрешения владельца.

## 2. Обязательная экспертная дискуссия

Перед каждым существенным архитектурным, педагогическим, языковым, визуальным, серверным или релизным решением проводится независимая оценка **5–10 агентов**. Набор ролей выбирается по задаче, но совокупно должен закрывать:

- продукт и пользовательский опыт;
- UI, motion, accessibility и премиальность;
- мобильную производительность и отсутствие лишней нагрузки;
- backend, масштабирование, стоимость и отказоустойчивость;
- безопасность, данные, права и release integrity;
- учебную методологию и curriculum science;
- грамматику, естественность, перевод и культурную уместность каждого затронутого языка;
- assessment/QA и защиту от псевдообучения.

Агенты сначала независимо исследуют задачу, затем сверяют противоречия и формируют одно точное решение. Реализация начинается только после зафиксированного консенсуса. После реализации агенты повторно проверяют код, тесты, smoke-результат и, для UI, скриншоты/видео.

## 3. Единственная правильная админка

- Единственная рабочая поверхность: корневая `admin/legacy.html`, production URL: `https://phraseman-ea0b3.web.app/legacy.html#control-panel`.
- Генератор Learning V2 размещается там отдельной понятной вкладкой, не смешивается с генератором турниров.
- `admin/v2` запрещён: его нельзя читать, изменять, связывать, тестировать, показывать или деплоить.
- UI следует `docs/design/ADMIN_UI_BIBLE.md`: понятные человеческие тексты, минимум шума, нормальные размеры, доступность, ясные статусы и действия.
- Нельзя показывать ложную готовность: manifest не равен готовому аудио, заполненные поля не равны языковому одобрению, generic `approved` не равен release approval.

## 4. Что обязан создавать генератор

Генератор создаёт **весь курс**, а не только интро:

- **весь реальный учебный контент уроков 1–32 создаёт только владелец,
  самостоятельно и без участия Codex**: он является автором фраз, заданий,
  объяснений, интро, сценариев, локализаций и остальных содержательных решений;
- Codex создаёт только генератор и техническую систему вокруг него и не пишет,
  не генерирует, не редактирует, не утверждает и не запускает от имени владельца
  реальный контент уроков;
- владелец вручную выбирает урок, вводит или импортирует свой авторский
  контент, запускает генерацию, проверяет preview и отдельно утверждает
  результат;
- по одному такому запуску генератор обязан технически собрать **весь выбранный
  урок** из авторских входных данных владельца: все 56 обязательных сессий,
  адаптивные учебные взаимодействия, интро и встроенные вопросы, объяснения,
  восемь интерфейсных локалей, четыре
  голосовых варианта каждого утверждённого аудиотаргета, preview, QA-результаты
  и версионированный пакет;
- один урок можно воспроизводимо перегенерировать отдельно, не затрагивая
  утверждённые версии остальных уроков; тестовые fixtures не считаются
  созданным владельцем уроком и никогда не заменяют ручное утверждение;
- локальная админка может показывать методически цельный нейтральный тестовый
  урок из 56 сессий для проверки всего маршрута. Сокращённый исторический
  12-сессионный fixture остаётся только совместимостью отдельных старых
  контрактов и не является полным уроком. Полный fixture маркируется
  `neutral_test_fixture`, имеет `releaseAuthority:false`, блокируется до
  сетевого импорта и дополнительно не совпадает с production `lessonId`. Он
  нужен только для визуальной, педагогической и технической проверки работы
  генератора. Кнопка «Взять эталон как основу» создаёт отдельную production-
  копию с новыми ID/fingerprint и никогда не повышает authority теста;

- структуру от полного нуля A0/Pre-A1 к более сложным сценариям с честной CEFR-informed разметкой;
- уроки, главы, сессии, экзамены/checkpoints и связи между ними;
- полноценные новые интро в общем стиле Learning V2;
- ровно три страницы в каждом session intro: каждая страница объясняет одну
  часть темы и содержит внизу один вопрос только по этой странице; эти вопросы
  являются canonical slots 1–3, а не отдельным блоком после интро; после
  правильного ответа на третьей странице практика начинается со slot 4;
- все 56 учебных сессий урока, взаимодействия, варианты, подсказки,
  объяснения, диалоги и проверки;
- интерфейсные тексты и весь пользовательский контент сразу для `ru`, `uk`, `es`, `pt-BR`, `vi`, `id`, `tr`, `pl`;
- аудио-пакеты и их доказательства качества;
- экзаменационные задания на новом материале без утечки тренировочных ответов;
- версии, provenance, fingerprints, QA receipts, preview и rollback-ready release artifacts.

Генератор не имеет права обещать пользователю сертификат или фактическое достижение C2 только потому, что curriculum помечен диапазоном до C2. Каждый учебный результат должен быть связан с реальной задачей, языковым источником и проверяемым evidence.

## 5. Языковое и педагогическое качество

- Для каждого языка обязательны отдельные специалисты по грамматике, естественности, переводу, локали, культурной уместности и педагогике.
- Все правила, фразы, ответы, distractors, объяснения и переводы проверяются по официальным или авторитетным языковым источникам.
- Машинная проверка может дать только `eligible_for_human_review`, но не человеческое одобрение.
- Автор/генератор не может одобрить собственный материал. Нужны независимые specialist reviews и отдельное финальное решение владельца.
- Задания должны реально учить: introduce-before-use, понятие → тренировка → перенос → независимая проверка → отложенное повторение.
- Интро-вопросы проверяют только понимание интро и не могут автоматически доказывать mastery.
- Звёзды, завершение, количество повторов и покупка доступа не являются доказательством знания.
- Для каждого lesson/session bundle обязательна coverage matrix
  `lesson objective component × session`: introduction, practice, retrieval,
  assessment и transfer должны быть видимы, а пробелы и fake diversity —
  отдельными findings.
- Quality dashboard обязан показывать минимум 15 dimensions из reference,
  confidence, BLOCKER/ERROR/WARNING counts, evidence coverage и exact objects,
  требующие повторной проверки после regeneration.
- После любого repair повторно проверяются изменённый объект, parent objective,
  answers/distractors, translations, audio, consuming activities, assessment и
  progression/coverage; локальный PASS без regression closure недостаточен.

## 6. Аудио

- Каждая утверждённая реплика генерируется четырьмя фиксированными голосами OpenAI: **Ash, Onyx, Nova, Coral**.
- Воспроизведение выбирает варианты разнообразно и предсказуемо: без постоянного повтора одного голоса; история выбора локальная и не требует серверного вызова на нажатие.
- Изменение текста, перевода, произношения, voice/model settings или правил генерации создаёт новую immutable-версию и требует перегенерации всех затронутых вариантов. Старые файлы не выдаются как актуальные.
- Manifest сам по себе не доказывает наличие или качество аудио. Нужны точные hashes/bytes, voice/model provenance, decoder/levels checks, человеческое прослушивание и device receipt.
- После первой установки кэшируется ближайшее окно: аудио уроков 1 и 2; после завершения урока N в фоне подготавливается N+2. Повторное воспроизведение использует локальный файл. Очередь учитывает Wi-Fi/сотовую сеть, storage budget, отмену, retry и очистку старых версий.
- В активной сессии нет remote TTS fallback и нет сетевого запроса на каждое прослушивание.

## 7. Продуктовый интерфейс Learning V2

- Основной экран — один непрерывный учебный маршрут. В интерфейсе ученика нельзя рекламировать внутреннее устройство генератора надписями вроде «32 эпизода», «4 сектора», «уроки и экзамены» или нумерацией секторов. Каноническая модель — 32 урока, каждый раскрывает 56 прямых сессий; скрытого деления по 12 нет ни в карте, ни в новом generator/release identity.
- На карте показываются текущая понятная тема, доступные шаги, прогресс и ближайшая проверка. Названия должны объяснять учебную цель человеку, а не повторять технические идентификаторы или черновые английские заглушки.
- Отдельные глобальные кнопки «Теория» и «Словарь» на карте не используются: теория появляется в нужной точке интро/задания, а слово или авторский chip изучается, озвучивается и при необходимости сохраняется непосредственно в контексте фразы.
- Путь идёт плотным зигзагом, как понятная игровая карта, но не копирует чужие иллюстрации или композицию.
- Визуальную соединяющую линию между узлами не рисовать.
- Использовать собственные иконки/персонажей и единый уникальный стиль Phraseman.
- Интро получает новый полноценный дизайн Learning V2; старый дизайн не переносится как финальный.
- Переход после ответа бодрый, мягкий и короткий. Пользователь сохраняет контроль; авто-переход применяется только там, где он не мешает прочитать feedback или accessibility announcement.
- Любая нижняя плашка/модальное окно на карте обязана закрываться четырьмя способами: явной кнопкой закрытия не меньше 44×44, нажатием на затемнённый фон, свайпом вниз и системной кнопкой «Назад». Закрытие отменяет подготовленное действие и не оставляет заблокированный экран.
- В заданиях сборки каждое выбираемое слово или цельный авторский chip имеет собственный аудиотаргет и озвучивается сразу при выборе. Один голос выбирается один раз на попытку задания и этим же голосом воспроизводятся полная фраза и все слова внутри задания.
- Первая ошибка не рисует красную рамку и не фиксирует неправильный вариант как выбранный: элемент получает короткую прозрачную тряску/анимацию по образцу текущего onboarding. После второй ошибки в том же задании показывается доступное текстовое объяснение причины ошибки. Владелец создаёт и утверждает эти тексты; генератор хранит все версии и даёт корневой админке фильтры по интерфейсному языку, типу задания, уроку и сессии.
- В каждом уроке, сессии и игровом задании доступны компактные действия: отправить репорт, сохранить фразу в карточки и дать устный ответ. Для речи удержание кнопки поддерживается как быстрый режим, но доступный tap-to-start/tap-to-stop остаётся обязательной альтернативой для VoiceOver, TalkBack и моторной доступности.
- За каждый валидный правильный ответ начисляются performance stars с приятной, но лёгкой для телефона анимацией. Звёзды — центральная игровая цель и будущая база лиг, но не учебное evidence.
- Никаких мелких служебных текстов, объяснений «для ИИ», ложных статусов, лишних полотен и перегруженных панелей.
- Первый кадр стабилен, интерактивен и не ждёт сервер. Анимации останавливаются вне фокуса, уважают reduced motion и не создают нагрев/лаг.

## 8. Сервер, телефон и offline

- Ответы, hints, skip, звёздная анимация и переходы выполняются локально; сервер не вызывается на каждое действие.
- Для мгновенной offline-проверки пакет задания физически разделяется на learner-safe render projection и внутреннюю локальную evaluator capsule; server-only sidecar остаётся только authoring/QA-артефактом и никогда не участвует в пользовательском решении «правильно/неправильно». Renderer не получает capsule bytes, а приложение не получает server sidecar.
- Локальная capsule честно считается доступной владельцу устройства для исследования и является единственным источником мгновенного verdict для текущего задания. Сервер не перепроверяет ответ, не возвращает правильный ответ и не может изменить уже показанный локальный verdict. Capsule не является секретом и сама по себе не доказывает mastery/evidence или право релиза.
- После полного завершения сессии в account-scoped фоновой очереди сохраняется только итоговая сводка сессии: координаты релиза, завершённые/пропущенные задания, число попыток, hints и локально рассчитанные звёзды. Тексты ответов, выбранные варианты и правильные ответы в этот транспорт не входят.
- Незавершённая сессия не имеет checkpoint/resume внутри задания: выход, закрытие приложения или обрыв сбрасывает текущий run. Следующий вход создаёт новый `sessionRunId` и начинает сессию с первого intro-экрана. Долговечно сохраняются только полностью завершённые сессии и их фоновая синхронизация.
- Interleaved review — это функция учебного плана, а не доказательство
  отложенного повторения. Настоящее delayed evidence возникает только из
  внешнего scheduler assignment/launch/timing receipt.
- Сессия длится 5–8 минут и не заканчивается по жёсткому счётчику. Стандартный
  бюджет — 14–18 основных учебных взаимодействий, цель 16; быстрые
  word/choice/build-сессии — 18–22, цель 20; voice/listening/dialogue-heavy —
  10–14, цель 12. Абсолютный максимум основных взаимодействий — 22. Повторы
  после ошибок и объяснение после второй ошибки не входят в базовый счётчик.
  Завершение требует покрытия objective: encounter/intro, guided practice,
  retrieval/application и независимой проверки без подсказки. Генератор не
  добавляет filler ради числа и не принимает старое `taskCount:12` как
  каноническую модель новой сессии.
- Прогресс сначала сохраняется надёжно локально, затем синхронизируется идемпотентно и переживает offline/restart/account switch.
- Генерация выполняется на сервере/в админском workflow, а не на телефоне пользователя.
- Все очереди имеют bounds, cursor/backoff, retry, idempotency, cost/spend guard и crash recovery.
- Никакой тестовый/demo provenance не может стать production release authority.
- Production release только immutable, hash-bound, versioned, с exact readback, staged rollout и rollback.

## 9. Definition of Done — только после этого можно сказать «готово»

Фраза «генератор готов на 100%» разрешена только если одновременно:

1. закрыты все обязательные этапы плана, а не один узкий пакет;
2. генератор создаёт полный canonical курс для всех восьми локалей и четырёх голосов;
3. maker-checker, specialist QA, owner approvals и release gates работают fail-closed;
4. тестовый контент физически исключён из production selection;
5. пройдены сотни целевых unit/contract/integration/emulator/security tests без известных блокеров;
6. пройдены smoke-тесты каждого этапа, сквозной author-to-device сценарий и rollback drill;
7. UI прошёл скриншотный аудит, animation/motion аудит, accessibility и performance gate;
8. реальный контент прошёл языковое, педагогическое, assessment, audio и human listening одобрение;
9. пройдены физические iOS/Android проверки, offline/clean-install/network capture и low-end performance;
10. все 32 урока проходят полный путь, а Lesson 1 → Lessons 1–8 → Lessons 1–32 rollout waves закрыты;
11. в `HANDOVER.md` нет незакрытых P0/P1/P2 release blockers для заявленного релиза;
12. владелец отдельно одобрил финальный пакет и production activation.

До этого момента отчёты обязаны использовать формулировки «закрыт пакет X», «готова часть Y», «остаётся Z». Переход к следующей стадии без полного гейта текущей запрещён.

## 10. Проверка в начале каждой следующей сессии

Перед любыми изменениями исполнитель обязан:

1. прочитать этот документ полностью;
