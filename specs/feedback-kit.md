# Спек: FeedbackKit — единая система ощущений (звук+вибрация+анимации+комбо) для ВСЕХ разделов v1.0

Дата: 2026-07-05. Статус: направление подтверждено владельцем (сессия «мягкость как у Duolingo»). Живые макеты: артефакт «phraseman-soft-mockups» (демо 01, 02, 04, 07) — https://claude.ai/code/artifact/176ee6d7-ac15-4ecd-871d-7b399e9b6630. Осуществимость проверена 6-агентным аудитом кода (заметка памяти `phraseman-smart-lesson-feasibility-soft-ux-mockups-2026-07-04`).

## 1. Суть

Один модуль ощущений — **FeedbackKit** — который делает КАЖДОЕ взаимодействие «мягким, как у Duolingo»: кнопки с физикой вдавливания, тёплый звук верного ответа, мягкий (не унизительный) звук ошибки, вибрация, пружинная плашка разбора, комбо-«молния» со звуковой лесенкой вверх, мостики-переходы между заданиями и секвенция наград в финале.

Подключается во **ВСЕ разделы** (требование владельца): уроки, словарь урока, неправильные глаголы, тренажёр предлогов, **теорию**, квизы, флешкарты, «Мою практику» (trainer/review), Личный план, диагностику, экзамены.

**Жёсткое правило: FeedbackKit — только ощущения.** Он НЕ трогает XP, энергию, SRS, дейлики, лимиты. Вся экономика остаётся ровно там, где сейчас (вердикт аудита: у каждого типа шага один владелец экономики; двойные списания — главный риск).

## 2. Архитектура

Новая папка `app/feedback/`:

- **`feedback_kit.ts`** — фасад-синглтон, событийный API (без React-state, чтобы не дёргать ре-рендеры — Perf Bible):
  - `fk.tap()` — при каждом pointer-down на интерактиве (тихий клик + haptic light);
  - `fk.correct()` / `fk.wrong()` — исход ответа (звук + haptic; wrong = мягкий низкий «туп», НЕ «бззз»);
  - `fk.combo(n)` — вызывается хостом с его счётчиком серии (лесенка нот + пороговые стингеры);
  - `fk.comboBreak()` — «шипение остывания»;
  - `fk.transition()` — «вжух» смены задания;
  - `fk.milestone(kind)` — star | medal | chest | chord (финальные);
  - `fk.tick()` — тик счётчика XP.
- **`combo_engine.ts`** — чистый модуль серии: `create() → {onCorrect(), onWrong(), value, level}`; пороги: 3 «Искра», 5 «Молния», 10 «Гроза»; события порогов наружу. Живёт на время сессии экрана. ВАЖНО: в `lesson1` уже есть внутренний combo-счётчик, участвующий в формуле XP (`app/lesson1.tsx:2935-2940`) — **формулу XP не трогаем**; ComboEngine в уроке синхронизируется с существующим счётчиком (single source of truth — счётчик lesson1), движок даёт только визуал/звук.
- **`sound_bank.ts`** — плеер поверх `expo-av`: предзагрузка пула при первом входе в любую сессию, полифония (повторный вызов не обрывает предыдущий), громкости по типам. UI-звуки **уважают беззвучный режим iOS** (`playsInSilentModeIOS: false`) — политика озвучки фраз/TTS не меняется (у неё своя).
- **`haptics.ts`** — обёртка `expo-haptics`: `light | medium | success | error | peak`; уровень комбо повышает силу (искра=light, молния=medium, гроза=peak).
- Визуальные компоненты (`components/feedback/`):
  - **`PressableScale.tsx`** — обёртка кнопки: вдавливание (translateY + сжатие нижней «толщины»-тени), spring-возврат; Reanimated, UI-thread. Вариант `variant="3d"` (кнопки ответов/CTA) и `variant="flat"` (мелкие).
  - **`FeedbackPlashka.tsx`** — плашка снизу с пружиной (`cubic-bezier(.34,1.56,.64,1)`-аналог), зелёная/красная, заголовок+разбор; API `show({kind, title, subtitle})`.
  - **`ComboRing.tsx`** — кольцо заряда вокруг мини-компаса в шапке сессии (SVG, stroke-dashoffset), число серии, состояние Искра/Молния/Гроза.
  - **`LightningOverlay.tsx`** — процедурная ветвящаяся молния (react-native-svg polyline, генерация пути как в макете: 20 сегментов + 3-5 ветвей), двойная вспышка (вспышка→затухание→повторный удар по новому пути), белый flash-слой с двойным миганием, лёгкая тряска контейнера (translate ±3px, 280мс), edge-glow уровней. В «Грозе» — фоновые зарницы раз в 2-4 с (ТОЛЬКО при активном экране — guard по focus/AppState, Perf Bible).
  - **`TransitionBridge.tsx`** — мостик «Теперь — на слух» (иконка типа + подпись, 750-850 мс, уходит сам): доработать/обобщить существующий переход плана (`app/personal_plan_exercise_transition*`), вынести из плана в общий компонент.
  - **`ResultsSequence.tsx`** — секвенция наград: медаль (spring, overshoot) → звёзды по одной (каждая — своя нота вверх) → XP тикает (count-up ~900 мс, тики звука/вибры) → конфетти 800 мс на пике → CTA выплывают. Обёртка над данными существующих экранов результатов, НЕ замена их логики наград.
  - **`VictoryBurst.tsx`** — «мини-победа» для коротких заданий: не полноэкранный, а карточка/баннер с пружиной по центру (заголовок + итог задания), звук `chord`/`medal`, короткий конфетти-бурст, haptic success; уходит сам или по тапу. Для финалов, где полноэкранная секвенция избыточна.

### 2.1 Экран победы — ПОД КАЖДОЕ задание (требование владельца)

Каждое завершённое задание/сессия в КАЖДОМ разделе заканчивается анимированным поздравлением со звуком — никаких «молчаливых» финалов и голых алертов:

| Раздел / задание | Финал сейчас | Что ставим |
|---|---|---|
| Урок (круг фраз) | `lesson_complete` (статичный) | ResultsSequence (полная) |
| Словарь урока — сессия Training | сухое завершение | VictoryBurst («Слова закреплены: N», штрих прогресса словаря) |
| Неправильные глаголы — проход LearnTab | сухое завершение | VictoryBurst («Глагол освоен: base–past–part») |
| Тренажёр предлогов — прогон/перфект | текстовый итог | VictoryBurst; при перфекте — конфетти + существующий бонус (экономику не трогаем) |
| Теория — раздел дочитан | ничего | VictoryBurst («Глава закрыта») + отметка прочтения |
| Квиз — результаты | экран с медалью (статичный) | ResultsSequence поверх существующих данных (медаль/%/ранг-фраза) |
| Флешкарты — раунд/«Идеальный раунд» | статичный экран | ResultsSequence (идеальный раунд = усиленный: аккорд+конфетти дольше) |
| Моя практика / Review — сессия | TrainerSessionReport (статичный) | ResultsSequence-мини (без медали: счёт, серия, XP-тикер) |
| Личный план / Маршрут — день закрыт | day reward | ResultsSequence → существующая награда дня |
| Диагностика — итог | статичный | ResultsSequence тихая (без молний/грозы) |
| Экзамен / сертификат | статичный сертификат | ResultsSequence торжественная тихая + сертификат въезжает с пружиной |
| Problem coach — тема «освоено» | текст | VictoryBurst («Тема закрыта») |

**Бюджет производительности (обязателен, «без нагрузки на систему»):**
- Компоненты победы монтируются ТОЛЬКО на финальном экране и полностью демонтируются после — ноль фоновых таймеров/циклов (perf-контракт).
- Конфетти: кап ≤120 частиц, длительность ≤1200 мс, автостоп, Reanimated/UI-thread (или Skia, если уже в проекте) — БЕЗ setInterval на JS-треде; на слабых устройствах (эвристика по `PixelRatio`/платформе) кап 60 частиц.
- Звук — только из предзагруженного пула (никаких загрузок в момент финала).
- Reduce-motion → статичная карточка + звук, без частиц и пружин.
- Секвенция не блокирует CTA дольше 3 с: кнопки доступны с момента их появления, тап пропускает остаток анимации.

## 3. Звуковой пакет

**Финальное качество = студийные сэмплы, НЕ синтез** (решение владельца: «нужны дорогие качественные звуки, реальная гроза»). Файлы в `assets/sounds/ui/` с фиксированными именами — покупной пак вставляется дроп-ином без правок кода:

| Файл | Что | Референс тайминга |
|---|---|---|
| `tap.m4a` | тихий клик касания | ≤30 мс |
| `pop.m4a` | плитка легла в слот | ~60 мс |
| `correct.m4a` | «дин-дон» колокольный с хвостом | ~600 мс |
| `wrong.m4a` | мягкий низкий «туп» | ~300 мс |
| `ladder_00..10.m4a` | 11 нот пентатоники (C5…C7), колокольные | ~500 мс |
| `spark.m4a` | стингер Искры (стеклянное арпеджио) | ~400 мс |
| `crack.m4a` | резкий ближний разряд | ~350 мс |
| `rumble.m4a` | средний раскат | ~1.2 с |
| `thunder.m4a` | полный раскат: крак→шипение→3 волны+суб | ~2.5 с |
| `thunder_far.m4a` | дальняя зарница | ~1.4 с |
| `fizzle.m4a` | «остывание» серии | ~400 мс |
| `whoosh.m4a` | переход между заданиями (стерео-проезд) | ~300 мс |
| `star_1/2/3.m4a` | три ноты звёзд по возрастанию | ~700 мс |
| `medal.m4a` | падение медали | ~800 мс |
| `chord.m4a` | финальный аккорд | ~1.2 с |
| `tick.m4a` | тик счётчика XP | ≤20 мс |

Гром приходит **со сдвигом 120-200 мс после вспышки** (реализм, как в макете). До покупки пака: временные сэмплы генерируются оффлайн-скриптом `scripts/gen_ui_sounds.cjs` (offline-рендер тех же слоёв, что в макете: FM-колокола+реверб+компрессор) — чтобы /build не блокировался; замена пака = замена файлов.

## 4. Настройки и доступность

- Два новых тумблера в настройках: **«Звуки эффектов»** (`ui_sfx_enabled`, деф. on) и **«Вибрация»** (`ui_haptics_enabled`, деф. on). Проверяются внутри FeedbackKit (хосты ничего не знают).
- Уважать системный reduce-motion (`AccessibilityInfo.isReduceMotionEnabled`): молния → только вспышка без тряски, пружины → короткие фейды.
- Звук фраз/TTS и его настройки НЕ трогаем.

## 5. Подключение по разделам (волны)

Правило подключения одинаково везде: `fk.tap` на все интерактивы (через PressableScale), `fk.correct/wrong` в СУЩЕСТВУЮЩИХ точках проверки ответа (рядом с текущей логикой, ничего не перенося), плашка — там, где сейчас текстовый фидбек, комбо — в сессиях с потоком ответов.

**Волна 1 — ядро + Урок:**

## 6. Performance Bible (обязательно)

- Пул звуков грузится один раз лениво, выгружается по memory-warning; никакой загрузки в цикле ответа.
- Все анимации — Reanimated UI-thread; молния/зарницы/шимеры ЖЁСТКО останавливаются при blur/фоне (freezeOnBlur-контракты, `tests/perf_freeze_contract.test.ts` не ослаблять).
- FeedbackKit — событийный (ref/emitter), ноль подписок через context-state в корне экранов.
- Первый кадр экранов не меняется (sync hydration как есть).

## 7. Acceptance criteria

На каждом подключённом экране: (1) любое нажатие вдавливается и кликает; (2) верный ответ = дин-дон + пружина-подпрыгивание + haptic success; (3) ошибка = мягкий туп + shake + haptic error, плашка объясняет; (4) серия: 3 = кольцо горит + стингер, 5 = молния через экран + вспышка + тряска, 10 = гроза (тёмный фон, раскат, зарницы), обрыв = fizzle; (5) переходы между заданиями — слайд с «вжух» (где типы чередуются — мостик с подписью типа); (6) **КАЖДОЕ задание из таблицы 2.1 заканчивается анимированной победой со звуком** (полная секвенция или VictoryBurst — по таблице), молчаливых финалов не осталось; (7) тумблеры настроек реально глушат звук/вибру; (8) в беззвучном iOS UI-звуков нет; (9) экзамены без молний; (10) бюджет производительности 2.1 соблюдён (кап частиц, автостоп, UI-thread, демонтаж); (11) tsc 0, тесты зелёные, perf-контракт не тронут.

## 8. Не делаем (осознанно)

- Никаких изменений XP/энергии/SRS/дейликов/лимитов/пейволов (только ощущения).
- Не заменяем механики режимов и не переносим логику проверки ответов.
- Живой Компас (Rive) — Этап 3, отдельно. Блиц — отдельная спека. Маршрут 2.0 — `specs/smart-route.md`.
- Не рефакторим lesson_help/монолиты — точечные обёртки.
- Лесенку НЕ реализуем рантайм-питч-шифтом (expo-av rate меняет темп) — только файлы нот.

## 9. Ловушки для /build (из аудитов и памяти)

- Параллельные сессии Клода правят соседние файлы — перед правкой каждого файла проверять `git status` этого файла; чужие незакоммиченные правки НЕ трогать, конфликтные файлы откладывать и сообщать.
- В `lesson1.tsx` комбо участвует в XP — менять только визуальный слой.
- `lesson_words.tsx` держит module-level кэш прогресса — не менять его запись/чтение.
- Все тексты — через локализацию (9 языков интерфейса), включая подписи «Искра/Молния/Гроза» и мостики; сырые кириллические строки в коде запрещены (детектор Heisenberg их ловит).
