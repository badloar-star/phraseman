# Instant UI and Battery Performance — Design

## Цель

Сделать подтверждённые пользовательские потоки PhraseMan визуально мгновенными и одновременно снизить фоновую нагрузку от таймеров, подписок и бесконечных анимаций, не меняя серверные контракты, начисления, покупки, арену или идентификацию пользователя.

## Границы первого пакета

Первый пакет включает пять интерфейсных поверхностей:

- аналитику фраз;
- сезонный рейтинг арены;
- каталог видео Lingman;
- ежедневные задания;
- реферальный экран.

Параллельно проводится трассировка recurring-источников работы. Исправляются не более четырёх источников, для которых доказано, что они продолжают работать на невидимом экране, в фоне приложения или создаются несколькими одновременно смонтированными потребителями.

Первый пакет не включает массовую переработку `ScreenGradient`, realtime-механику арены, общий offline-outbox, платежи, подписки, auth и account deletion.

## Архитектура мгновенной загрузки

Каждая затронутая поверхность использует один и тот же принцип:

1. Последний успешный результат хранится в ограниченном keyed-cache.
2. Ключ включает весь контекст, влияющий на содержимое: язык изучения, день, сезон или источник каталога.
3. Начальное состояние React читается синхронно через peek-функцию в `useState(() => ...)`.
4. Свежий кеш не запускает повторную работу при каждом фокусе.
5. Устаревший кеш остаётся на экране во время тихой фоновой сверки.
6. Ошибка сверки не стирает последние реальные данные и не создаёт ложное empty state.
7. Поздний ответ для старого ключа не может перезаписать новый контекст.

Кеш обязан иметь TTL и ограничение размера. Account-scoped данные дополнительно привязываются к canonical UID или account generation; данные предыдущего аккаунта игнорируются после переключения пользователя.

### Аналитика фраз

Текущий warm-cache сохраняется. Добавляется TTL, чтобы тяжёлый расчёт не запускался при каждом фокусе. При устаревшем кеше данные остаются видимыми, а обновление выполняется в фоне. Полноэкранный loading допустим только при настоящем cold start без данных.

### Сезонный рейтинг

Добавляется ограниченный снимок, ключ которого включает сезон. При возврате на экран старые строки остаются видимыми до ответа сервера. Persistent AsyncStorage-кеш добавляется только если при реализации подтверждается стабильный сезонный ключ и безопасная invalidation; иначе первый пакет ограничивается module cache.

### Lingman

Добавляется keyed peek-cache последнего успешного каталога. Skeleton показывается только без кеша. Существующее оптимистичное `mark seen` сохраняется без изменений.

### Ежедневные задания

Снимок задач и прогресса привязывается к `studyTarget + day`. Снимок другого дня или языка не используется. Независимые локальные чтения выполняются параллельно только после подтверждения отсутствия порядка и побочных эффектов. Существующий optimistic claim и rollback сохраняются. Замена задания с расходом осколков остаётся server-authoritative.

### Рефералы

Последний успешный список получает синхронный peek-cache поверх существующего AsyncStorage-кеша. `claimReferralVipDays()` остаётся агрегированным серверным действием. Во время claim показывается один понятный статус получения накопленных наград; строки не изображают несколько независимых операций, и успех не показывается до ответа сервера.

## Архитектура контроля фоновой работы

Каждый найденный `setInterval`, повторный `setTimeout`, `Animated.loop`, `withRepeat(..., -1)` или `onSnapshot` сначала классифицируется и трассируется. Одноразовые UI-таймеры с cleanup и анимации модалок, размонтируемых при закрытии, сами по себе не являются дефектами.

Recurring-источник исправляется только при наличии доказанного лишнего выполнения. Для него действует контракт:

- работа запускается только при видимом экране, активном `AppState` и наличии состояния, которому нужен tick/listener;
- cleanup останавливает interval, timeout, animation или subscription;
- несколько потребителей не создают дублирующую работу;
- countdown хранит абсолютный deadline и пересчитывается при focus/resume;
- секундный tick остаётся только там, где пользователь видит меняющиеся секунды;
- blur/background не меняет серверную семантику арены, начислений или синхронизации.

Первыми полностью трассируются `EnergyContext`, `LeagueChatPanel`, `HomeTheoAdvisorCard` и `LingmanVideosButton`. Последние два могут оказаться положительными эталонами и не требуют изменения без доказанной проблемы. `ScreenGradient` исследуется, но не переписывается в первом пакете.

## Ошибки и согласование состояния

- Фоновая ошибка сохраняет last-known data и даёт ненавязчивый retry.
- Optimistic rollback не должен перетирать более новую пользовательскую операцию.
- Firestore snapshot не должен преждевременно удалять pending overlay.
- Очереди и кеши не переносятся между аккаунтами.
- Покупки, Premium/VIP, XP, энергия, осколки, подарки, реферальные награды, результаты арены, рейтинг и auth никогда не показываются как подтверждённые до авторитетного ответа.

## Проверка

Разработка выполняется test-first. Для каждого изменения сначала добавляется узкий failing test, затем минимальная реализация.

Обязательные сценарии:

- cold start показывает skeleton только при отсутствии данных;
- warm return показывает реальные данные на первом render;
- свежий кеш не запускает повторный расчёт;
- stale cache остаётся видимым во время revalidation;
- ошибка revalidation не стирает данные;
- кеш другого ключа, дня, сезона или аккаунта не используется;
- исправленный timer/loop/listener не работает при blur/background и не дублируется;
- resume восстанавливает countdown по абсолютному времени;
- optimistic daily claim и server-authoritative referral claim сохраняют текущую семантику.

Узкая регрессия включает `perf_freeze_contract`, `navigation_back_underlay_contract`, `owner_direction_runtime_contract`, daily-task claim/cloud-merge тесты и новые тесты конкретных кешей и timer guards. Полный Jest автоматически не запускается.

## Критерии приёмки

- Warm screen показывает последние реальные данные на первом кадре.
- Возврат на экран не вызывает skeleton или ложное пустое состояние.
- Безопасное локальное действие визуально реагирует менее чем за 100 мс.
- Исправленные recurring-источники останавливаются при невидимом или background UI.
- После нескольких focus/blur циклов нет новых параллельных timer/listener instances.
- Серверно-авторитетные ценности не показывают ложный успех.
- Все узкие тесты проходят, а runtime-проверка охватывает cold/warm, background/resume, offline/error и account switch там, где данные account-scoped.

## Последующие этапы

Отдельные партии после измерений могут охватить общий visibility contract для `ScreenGradient`, realtime arena hooks, расширенное runtime-профилирование FPS/TTI и переиспользуемый outbox для строго идемпотентных обратимых действий.
