# Admin V2: персональные сообщения, Центр репортов и снимки данных

## Цель

Администратор может отправить конкретному пользователю персональное сообщение в колокольчик или как одноразовое окно при следующем входе. Admin V2 всегда сначала показывает последний безопасно сохранённый снимок каждого раздела, а затем обновляет его в фоне. Центр репортов становится рабочей очередью с полным экспортом открытых репортов, архивом и безопасной выдачей одной монеты только за подтверждённую и исправленную проблему.

## Границы и инварианты

- Все записи от имени администратора проходят через Cloud Functions; браузер не пишет в пользовательские коллекции напрямую.
- Персональная доставка адресуется только к проверенному стабильному UID. Повтор команды с тем же ключом идемпотентности не создаёт второй записи.
- Режим `inbox` создаёт видимое уведомление в колокольчике. Режим `next_login_modal` создаёт ту же запись и отдельный одноразовый флаг показа; после закрытия окно не повторяется, а сообщение остаётся в колокольчике.
- Снимки Admin V2 принадлежат текущему администратору и текущему браузеру, имеют TTL, удаляются при выходе/смене аккаунта и помечаются временем сохранения. Снимок никогда не маскирует ошибку обновления и не запускает сетевой запрос до первой отрисовки.
- «Открытые» для экспорта — все репорты без финального статуса `answered` или `archived`, а не только текущая страница. Экспорт читает документы сервером пакетами и сохраняет точные исходные поля.
- Черновик ответа генерируется существующим серверным механизмом и всегда остаётся редактируемым. Отправка требует ручного действия администратора.
- Награда — строго `0` или `1` монета. `1` допустима только при явном результате `confirmed_fixed`; сервер повторно проверяет его, выдаёт монету один раз и записывает аудит. Дубли, «в работе», отклонённые и неподтверждённые репорты получают `0`.
- Старый Admin не меняется и служит только источником текста инструкции для экспорта.

## Центр репортов

Очередь состоит из горизонтальных карточек. В шапке карточки: имя и UID автора, дата/время, источник и статус. Тело: текст репорта, адрес/экран, ОС, версия приложения, модель устройства и прочий контекст, если источник их предоставил. Для карточки доступны открытие профиля, переход статуса, генерация черновика, отправка ответа и передача в Офис агентов.

В шапке очереди доступны: копирование всех нерешённых с LLM-инструкцией, передача всех нерешённых в Офис агентов и переход в архив. Архив показывает итоговый статус, текст отправленного ответа, время, администратора и число выданных монет.

Экспорт сохраняет смысл прежней инструкции: проверить каждый репорт, сгруппировать дубли, исправлять только подтверждённые безопасные ошибки, писать живым уважительным языком пользователя, не раскрывать внутренние данные, подготовить отдельный ответ на каждый `reportId`, проверить черновики и не выполнять массовую живую отправку через CLI. Устаревшие правила осколков заменяются правилами одной монеты.

## Проверка

Новые контрактные тесты покрывают серверные входы, идемпотентность, одноразовое модальное сообщение, изоляцию и очистку снимков, полный экспорт открытой очереди, архив и правило монеты. Существующие узкие тесты Admin V2, реплаев и уведомлений остаются зелёными.
