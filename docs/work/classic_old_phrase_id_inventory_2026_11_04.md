## Summary of risks
1. Biggest dependency is POSITION not id: progress array, cellIndex, phraseOrder (indices into LESSON_DATA), error queue are by cell/index. Keeping per-lesson phrase COUNT identical keeps all of it valid; if a lesson count changes, progress array is silently reset to empty (lesson1.tsx:3091) while score/pass_count remain.
2. Mistake journal (#13) and saved flashcards (#9) are self-contained text snapshots, so they will not crash or disappear, but they keep OLD text; same phrase id with new text gets a new mistakeId (no dedupe) and the flashcard "saved" heart is keyed by ENGLISH text so replaced phrases look unsaved.
3. English-text keyed: lesson words counters (#7), saved-card heart/remove (#9), EN->UK repair (#10), analytics phrase index (#14), audio cache/map (#22). Preposition progress ids (#8) are positional in generated list and shift silently.
4. Resumed in-progress level exam (#16) rebuilds the blueprint from seed against new data without comparing stored task ids -> possible mismatch for unfinished attempts only.
5. Cheap safety net exists: bump APP_CONTENT_SCHEMA_VERSION in app/content_delivery_migration.ts to clear cellIndex/phraseOrder/errorReplay*/intro_shown (progress/scores kept); consider also clearing preposition progress and active level-exam attempts, and re-pointing hardcoded ai_dialog requiredPhraseIds (#18).
