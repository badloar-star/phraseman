## Outcome

Владелец видит один HTML-макет с **тремя стилями** новой вкладки раздела «Карточки» —
«Наборы из видео» — и выбирает стиль до написания кода.

Наблюдаемый результат: макет открыт, три варианта отличаются друг от друга по структуре
(не по цвету), в каждом сверху стоит выбор языкового контура, маленькое кликабельное
превью видео и основной акцент — сами наборы карточек.

Успех = владелец называет вариант (А / Б / В) либо комбинацию, которую надо собрать.

**На этом шаге код приложения НЕ пишется.** Реализация — отдельная задача после выбора.

Текущая граница (прочитано перед составлением макета, не по памяти):

- Языковой контур наборов уже существует: `app/flashcards/pack_languages.ts`
  (`PackLanguage = 'en' | 'fr' | 'de' | 'es'`), хранение выбора —
  `app/flashcards/pack_language_preferences.ts`, готовый UI —
  `app/flashcards/PackLanguagePicker.tsx`. Новый раздел обязан переиспользовать
  ИХ, а не заводить второй список языков (иначе повторится класс бага
  `project_deck_options_warm_cache_leaked_2026-09-22` — узкий литерал отстаёт
  от реального набора языков).
- Фразы из видео уже есть: `shared/video_phrases_contract.ts` → реэкспорт в
  `app/video_phrases_contract.ts`, клиент `app/video_phrases_client.ts`,
  сервер `functions/src/video_phrases.ts`, экран
  `components/youtube/YoutubeVideoPhrases.tsx`, лента `app/lingman_videos.tsx`.

Намеченная граница (предмет будущей реализации, здесь только зафиксирована):
новая вкладка раздела «Карточки» читает те же данные видео-фраз и тот же
языковой контур; **новых сущностей в админке не заводится** — набор лишь
связывается с языком и каналом.

Архитектурное изменение в ЭТОМ ходу: нет — создаётся только статический HTML-макет
вне дерева приложения (scratchpad), он ничего не импортирует и никем не импортируется.

## Security and privacy

Не применяется, и вот почему конкретно:

- макет — статический HTML в scratchpad, без сети, без скриптов, без форм ввода;
- персональные данные не отображаются: имена каналов и названия наборов в макете
  вымышленные, uid нигде не фигурирует;
- обложки видео НЕ подгружаются с YouTube — вместо них CSS-градиенты, поэтому
  запроса к стороннему домену из макета не происходит;
- новых разрешений, полей профиля, сторонних сервисов не добавляется →
  **privacy policy трогать не нужно** на этом шаге.

Отметка на будущее: при реализации превью будет тянуть обложку с
`i.ytimg.com`. Это обращение к стороннему домену с IP пользователя — тогда
надо будет свериться с политикой (правило владельца «тронул данные → owner-rules»).

## Technical debt

- **Accept temporarily**: макет живёт в scratchpad и не попадает в репозиторий.
  Владелец: эта сессия. Дата пересмотра: момент выбора варианта.
  Потолок влияния: нулевой — файл вне сборки, на бандл и типы не влияет.
  Exit condition: владелец называет вариант → макет заменяется реальным экраном,
  и тогда заводится отдельный паспорт задачи на реализацию.
- **Pay now**: в макете НЕ используются запрещённые владельцем приёмы —
  нет обводок контейнеров (`border` вокруг блоков), нет подписей-расшифровок
  мелким шрифтом под названиями, нет ужатия шрифта. Разделение — тоном и фоном.
  Это проверено при написании разметки, а не отложено.

## Verification

Детерминированные проверки для ЭТОГО шага:

1. Файл макета открывается в браузере, видны три колонки-телефона рядом.
2. Три варианта структурно различны: А — широкая обложка над набором;
   Б — список, превью 96×96 слева; В — сетка плиток 2 в ряд.
3. В каждом варианте присутствуют: строка выбора языка (4 языка), полоса канала,
   отдельная маленькая кнопка «плей», таббар раздела с активной вкладкой «Из видео».
4. Поиск по тексту макета не находит `border:` вокруг карточек-контейнеров
   (разрешены только служебные: рамка телефона, разделители).
5. Цвета совпадают с `constants/theme.ts` → `DARK` (сверено при написании:
   `bgPrimary #030604`, `bgCard #101710`, `accent #47C870`, `correctText #042010`).

Тесты (`jest`), `tsc`, сборка **не запускаются намеренно**: код приложения не
менялся, гонять их — сжечь слот светофора без повода. Слот для этой задачи не
брался: работа лёгкая (чтение файлов + один HTML).

Артефакт-свидетельство: сам HTML-файл, отправленный владельцу.

## Rollback

Откат тривиален и без потерь: файл макета лежит в scratchpad-директории сессии,
вне репозитория и вне сборки приложения. Удаление файла возвращает систему в
исходное состояние. Данные пользователей, выданные права и покупки не затрагиваются —
ни одной записи не создаётся и не изменяется.

Этот паспорт остаётся в `docs/work/tasks/` как след решения, даже если макет отвергнут.
