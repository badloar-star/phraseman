# Проверка темы на свежих кадрах A/C пачки B1 и новых ошибок шагов

Governance-ID: TG-0483714F6E36
Status: в работе
Owner: сессия «4 · ТЕМЫ 2.0» (поручение координатора: выборочно проверить тему кадров классов A и C и разобрать новые ROBOT_STEP_ERRORS)

## Outcome
По журналам прогонов (запрос `theme/level/appearance` и строка `applied`) и глазами установлено, что тема каждого проверенного кадра соответствует классу страницы (A — grad_aurora ＠1, C — graphite ＠0, онбординг — свои) и что нет протекания темы с прошлого кадра. Новые ошибки шагов, если есть, исправлены в модуле errfix.

## Scope
Только чтение журналов и кадров `evidence/parity`; временные скрипты вне репозитория; правки возможны только в `scripts/dev_links_r1_steps_errfix.py` (мой модуль). Код приложения не меняется.

## Architecture
Сопоставление id → страница макета → класс по таблице «Тема кадра по страницам» (DEV_SWITCHES_R1_CORE); для каждого журнала сравниваются тема из запроса и применённая тема из строки `[DEV-STATE] applied`.

## Security and privacy
Только чтение внутренних журналов тестового прогона.

## Technical debt
Выборка по журналам не доказывает вид самого кадра: для этого часть кадров просматривается глазами.

## Verification
Счётчик «применено верно из проверенных» и список расхождений; просмотр шести кадров; чтение ROBOT_STEP_ERRORS после времени последней проверки.

## Rollback
Нечего откатывать: изменения в репозитории только при новых исправлениях errfix.

## Дополнение: новые ошибки шагов (ROBOT_M_B1)
`onboarding-003/004` (`#auth-google-button`) и `onboarding-005` (`#onboarding-existing-account`): на кадрах ошибок нужные кнопки видны («Войти через Google», «У меня уже есть аккаунт»), но в снимке дерева их нет — экраны онбординга на входе анимируются (логотип и заголовок полупрозрачны). Исправление в errfix: пауза подлиннее и нажатие по координатам (как у cards-v2-037): Google (540,1902), «У меня уже есть аккаунт» (540,2242) на экране 1080×2400.
