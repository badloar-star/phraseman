## Шаг 0 — выкладка ТОЛЬКО из чистой выгрузки HEAD (сухой прогон 15.10)

`firebase deploy` собирает `functions/` из рабочего дерева как есть. 15.10 там лежали незакоммиченные правки Codex. Файл `content_factory/v2_activity_session_projection.ts` (+46/−3) входит в набор `default`, поэтому выкладка из дерева увезла бы их в прод. **Из рабочего дерева не выкладывать.**

Выкладка — скриптом, который выгружает ровно HEAD во временную папку вне репо, собирает там функции и проверяет паритет рантайма:

```bash
bash scripts/deploy_from_clean_head.sh --only "functions:default:legacyBonusConvertMine,functions:default:onboardingLevelRecord,firestore:rules"
```

- Без `--execute` это сухой прогон: ничего не выкладывает, печатает команду.
- Выкладка — тот же вызов с `--execute`, только по слову владельца.
- Цели только точечные: `functions:default[:имя]`, `firestore:rules|indexes`, `hosting:admin|knowlywww`. Голое `functions` отклоняется.
- `--force` запрещён скриптом.
- Перед этим — коммит всего, что должно уехать: скрипт берёт HEAD, незакоммиченное в выкладку не попадёт.

Проверки сухого прогона 15.10:
- правила новых серверных коллекций — в эмуляторе (`functions/src/deploy_2026_10_17_rules.emulator.test.ts`, 3/3). Найдено и исправлено (2028a9ee3): админский catch-all перекрывал «только сервер» у `auth_recovery_hint_rate_limits` / `onboarding_level_*`;
- индексы с прошлой выкладки (06d520e25) не менялись;
- правила: +15 строк (две коллекции онбординга и счётчики подсказки) и +6 (исключения catch-all).

Порядок 17.10: правила → функции (точечно, по пунктам ниже) → флаги `remote_config/app.bools` (`moments_v3`, `stories_v1`, затем `legacy_bonus_enabled`, когда клиент 16.10 в сторе). Откат по каждому шагу описан в его пункте и в разделе «Откат».

Пункт 9 — сторис у аватарки на Главной (D192; решение владельца 15.10 ~11:00: «включаем 17.10 вместе с moments_v3»).

Это тоже не деплой, а значение в Firestore: документ `remote_config/app`, поле `bools.stories_v1` = `true` (булево). Включать тем же заходом, что пункт 6.

- Что появится: кольцо вокруг монеты-аватара, когда есть непросмотренная история. Виды историй: итог недели в Пике, рубеж серии, новый ранг монеты, ачивка. Тап по аватару открывает просмотр; без историй тап ведёт в профиль, как раньше.
- Как включить: консоль Firebase → Firestore → `remote_config` → `app` → в карте `bools` добавить `stories_v1`, тип boolean, `true`. Писать только это поле, документ целиком не перезаписывать.
- Стоимость: ноль. Истории пишутся и читаются только в памяти телефона и его локальном хранилище (`story_events_v1:<stableId>`). Флаг берётся из уже загруженного кэша конфига. Новых чтений и записей Firestore и вызовов функций нет ни на старте, ни при показе. Это проверяют тесты `tests/story_events_store.test.ts` (старт при включённом флаге = одно локальное чтение, сетевых импортов в цепочке нет) и `tests/stories_ring_viewer_contract.test.tsx`.
- Флаг выключен (сейчас и в старых сборках): кольца нет, истории не пишутся, аватар — прежняя кнопка профиля.
- Когда увидят люди: как пункт 6 — кэш конфига обновляется не чаще раза в 6 ч. Истории копятся с момента включения: серия, ранг и ачивки, полученные раньше, кольцо не зажгут. Исключение — итог недели Пика: он перечитывается из кэша при входе. Поэтому прошлая закрытая неделя может появиться историей при первом входе после включения.
- Связь с пунктом 6: итог недели, уже показанный окном момента (m01–m03), ложится в историю сразу просмотренным. Кольцо на него не загорается, в «недавних» он есть 7 дней.
- Проверка: в журнале телефона `[STORY-EVENTS] flag: remote=true` после перезапуска. После первого факта — `[STORY-EVENTS] record: ok`, на Главной `[STORY-RING]`.
- Откат: `stories_v1` → `false` (или удалить поле). Кольцо гаснет после обновления кэша. Записанные локально истории не трогаются и сами истекают через 7 дней.
