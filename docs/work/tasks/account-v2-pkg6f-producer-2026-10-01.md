## Outcome

При включённом `accounts_v2_client_enabled` приложение пишет изменения уроков, карточек (+SRS) и библиотеки наборов в outbox V2 (параллельно со старой синхронизацией — dual-write; старый путь не трогаем, чтение пока из старого). При выключенном — ноль работы.

1. Найти точки записи в приложении: результат урока (best score / passed), добавление/изменение/удаление карточки и её SRS-памяти (свайпы), добавление/удаление наборов в библиотеке. Для каждой — один вызов тонкого `enqueueAccountsV2…` (ленивый, через ворота флага), который строит операцию конверта по контракту (`functions/src/accounts_v2_contract.ts`: типы сущностей lesson/flashcard/library, baseRevision из локальной области, SRS updatedAtMs = время правки на телефоне — решение владельца), кладёт её в outbox и будит раннер.
2. Без влияния на UI-поток: постановка в очередь асинхронная, вне кадра, не блокирует экран (Optimistic UI сохраняется — экран уже обновлён старым путём). Батчинг через существующий runner.
3. Идемпотентность и порядок: операции одной сущности — в порядке; повторная запись того же значения не плодит операций (сравнение с локальным состоянием области).
4. Логи `[ACCOUNT-V2]` на ранних выходах (флаг выкл, нет области, неподдерживаемая сущность).
5. E2E на эмуляторе (через очередь, dev-вход по почте): пройти урок / добавить карточку / свайпнуть / добавить набор → видно в эмуляторе Firestore `accounts_v2/{uid}`; смена аккаунта не смешивает; удаление стирает.
