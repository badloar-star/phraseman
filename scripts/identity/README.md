# Инструменты идентичности (этап 0 перестройки)

Разовые скрипты для разбора и починки расхождений между девятью именами
пользователя. Созданы 01.09.2026 по заданию владельца перед перестройкой
системы входа.

**Запускать ТОЛЬКО из `functions/`** — там установлен `firebase-admin`:

```bash
cd functions && node ../scripts/identity/identity_forensics.js
```

## Что делает каждый

| Скрипт | Назначение | Пишет в базу |
|---|---|---|
| `identity_forensics.js` | Полный разбор расхождений по трём группам: имена разошлись, привязка ведёт в никуда, след слияния потерял цель | нет |
| `identity_groupa.js` | Из группы A отделяет норму от настоящей проблемы: сможет ли человек реально войти | нет |
| `identity_repair.js` | Чинит: дожимает указатели до конечного живого аккаунта, создаёт недостающие привязки | **только с `--apply`** |

`identity_repair.js` без флага — сухой прогон, показывает план и ничего не
трогает. Все его записи идут через `{ merge: true }` и помечаются полями
`identityRepairAt` / `identityRepairReason` — по ним правку можно найти и
откатить. Прогресс не перезаписывается никогда.

## Результат прогона 01.09.2026

Было 33 расхождения на 4701 живой аккаунт → стало 5 настоящих.

- **группа B (21 → 0)**: привязки вели на промежуточное звено слияния вместо
  конечного живого аккаунта. Дожаты.
- **группа C (5 → 1)**: то же самое для следов слияния. Остался один пустой
  след, чья цель исчезла бесследно (XP=0, надгробия удаления нет) — терять
  нечего, безопасен.
- **группа A (7 → 5)**: три оказались нормой (человек вошёл анонимно, потом
  привязал Google — имена законно разные, вход работает). Из оставшихся
  четыре — тестовые аккаунты `admin-vip-e2e-*` без людей и прогресса.

**Один случай ждёт решения владельца.** `mytheoryborn@gmail.com` («Theo Ry»)
имеет ДВА аккаунта: старый `b27bc4fa` (90 XP, ник NOKIA, апрель) держит ключ
Google, а весь прогресс — на `6eccc17a` (**33 347 XP**, ник Professor LINGMAN,
май), который входит анонимным uid без записи привязки. Сейчас вход через
Google приведёт его на аккаунт с 90 XP. Починка = перевести ключ на аккаунт с
прогрессом и пометить старый слитым; это перезапись существующей привязки,
поэтому делается только с явного согласия.

## Класс бага, который это показало

Указатели слияния не «дожимались» до конечной цели: код писал ссылку на
непосредственного соседа, а цепочка потом удлинялась. Пока звеньев было два —
работало; на третьем звене вход ломался. В новой схеме (одно имя `account_id`)
такой цепочки не существует в принципе.
