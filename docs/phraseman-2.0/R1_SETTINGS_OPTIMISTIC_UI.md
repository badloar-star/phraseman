## Подробно

### 1–2. Уведомления (`app/settings_notifications.tsx`)
`persistPrefs` / `persistSchedule`: состояние меняется до записи (а), запись `saveNotifPrefs` / `saveNotifSettings` идёт после, затем проверка разрешения ОС и планирование.
**Чего не было 🔧.** (б) `persistSchedule` ловил ошибку пустым `catch {` — тумблер и время откатывались молча, причины в журнале не было; `persistPrefs` откатывал без сообщения человеку. (в) Откат применялся всегда, даже если за время записи человек уже сделал более новый выбор.
Теперь: у каждой записи свой номер (`prefsSeqRef`, `scheduleSeqRef`) — устаревший сбой откат пропускает с логом `rollback=skipped`; при реальном откате — тост «Не удалось сохранить настройку» (9 языков) и строка `[NOTIF-PREFS] / [NOTIF-SCHEDULE] persist_failed rollback=1 reason=…`.
Облако: `saveNotifPrefs` → `updateServerPushPrefs` пишет `users/{id}.pushPrefs` **только при реальном изменении** (локальный ключ `PUSH_PREFS_LOCAL_KEY`: streak/offers/league) — один merge-write на смену, лишних чтений нет. Мастер и категории `phrase_of_day`, `energy`, `weekly_recap`, `friends` в облако отдельно не пишутся (кроме `friends_push_v1` через синхронизацию ключей).

### 3. Приватность (файл Авторизации — не правил)
`applyConsentToggle` в `app/privacy_settings.tsx`: тумблер щёлкает сразу (а), откат при сбое локальной записи + счётчик тапов на каждый тумблер защищает от гонки (в) — это образец. Замечания для Авторизации: (б) откат без сообщения человеку; (д) `recordToCloud()` зовётся на КАЖДЫЙ тап без задержки — быстрые переключения дают N записей в облако, а неудача записи в облако только пишется в журнал, повтора нет (если человек выключил согласие, а облако не узнало — расхождение с «записью для учёта»). Предложение: склеивать до последнего значения (trailing-запись через ~1,5 с) и повторять при следующем входе. Цена S–M, это их файл.

### 4. «Очистить кэш» (`app/(tabs)/settings.tsx`, `app/cache_reset.ts`)
Нажатие → подтверждение (деструктивное, окно уместно) → статус живёт прямо в строке: `running` → `done` / `failed`, без спиннера на весь экран; повторное нажатие во время `running` игнорируется (в). Сбой хранилища не выдаётся за «Готово» (`ok:false`). **Чего не было 🔧:** `.catch(() => …)` в экране не писал причину — теперь `[CACHE-RESET] clear_failed_in_ui reason=…`.

### 5. Звук карточек (`app/settings_edu.tsx`, `app/flashcards/SoundService.ts`)
Тумблер меняется сразу, значение уходит в память (`cachedSfxOn` / `cachedAutoSpeakOn`), запись в AsyncStorage — фоном.
**Чего не было 🔧.** `setFcSfxEnabled` / `setFcAutoSpeakEnabled` сами ловили ошибку записи и возвращались успешно — `.catch(logToggleSaveFailure(..., откат))` в экране **не срабатывал никогда**: тумблер оставался «включён» при неудавшейся записи, после перезапуска значение возвращалось. Теперь сеттеры возвращают кэш (если он не менялся новым тапом) и пробрасывают ошибку; экран откатывает тумблер только если он всё ещё в положении этого тапа (`current === value`) и показывает тост.

### 6. Тактильный отклик (`app/(tabs)/settings.tsx`)
`toggleTapHaptics`: состояние, кэш хаптики и снимок приложения — сразу (а). **Чего не было 🔧:** комментарий в коде сознательно оставлял тумблер без отката при сбое записи (источник правды — снимок) — но снимок и экран показывали «включено», а `haptics_tap` на диске оставался прежним. Теперь откат (состояние, кэш хаптики, снимок) + тост + номер тапа против гонки; журнал `[OPT-UI] settings tap_haptics rollback …`. Ключ `haptics_tap` остаётся локальным (не уходит в облако, переживает смену аккаунта — `KEEP` в `cloud_sync.ts`).

### 7–8. Остальное
`settings_edu` `update()` (автопроверка, скорость речи): `applyUserSettingsNow` возвращает признак записи, откат с тостом, версия правки против позднего `loadSettings` — закрыто в аудите R1 (E4/E6). Раздел «Звук» (`updateSoundSetting`) скрыт флагом `SHOW_SOUND_SETTINGS = false`; когда его вернут, там нужен тот же шаблон (сейчас результат записи игнорируется). Тема — зона Темы, их контракт.
