## Outcome

Free получает 3 голосовые попытки в день на всё вместе: голос нового курса (Learning V2) и Диалогов. У Plus лимита нет. Попытка — начатая запись (как в D165).

На микрофоне каждого голосового задания курса видна цифра «сколько сегодня осталось». Лимит кончился посреди сессии:
- сессия идёт дальше;
- тап по микрофону открывает тот же пейвол Plus, что стена Диалогов;
- остальные задания проходятся.

Действует только для нового курса после его открытия; уроки R1 не меняются. Результат этого пакета — схема для Макетов и координатора, а не код.

## Scope

In scope (схема):
- ключ общего счётчика;
- перенос текущего значения из `dialogue_v2_voice_attempts_v1`;
- смена суток по локальной дате;
- поведение Plus;
- стоимость.

Out of scope:
- код в `app/` (до команды координатора);
- вид бейджа и микрофона (Дизайн / Макеты);
- обычные уроки R1.

## Architecture

1. Сейчас: `app/dialogue_v2_voice_daily_limit.ts` — память процесса + AsyncStorage `dialogue_v2_voice_attempts_v1` = `{day, count}`.
   - Локальная дата устройства, last-write-guard при чтении.
   - Решение `dialogVoiceLimitDecision`: Plus и «доступ ещё неизвестен» — без ограничения.
2. Предлагаемая граница — модуль `app/voice_daily_limit.ts`, общий для всех источников:
   - тот же формат `{day, count}` + `bySource: { dialogs, course }` (только для журнала и аналитики, лимит считает сумму);
   - новый ключ `voice_attempts_v1`.
3. Перенос при первом чтении нового ключа:
   - если его нет, а старый ключ за сегодня есть — берём старый count как `bySource.dialogs`;
   - старый ключ не удаляем до выхода сборки, которая его больше не читает (откат возможен);
   - читаем оба ключа одним `multiGet`.
4. Старые сборки пишут только старый ключ. После обновления новая сборка один раз сливает по max за сегодня. Двойного счёта нет: сумма = max(старый, новый общий) в день переноса.
5. `dialogue_v2_voice_daily_limit.ts` превращается в тонкий переходник к общему модулю. Имена экспорта сохраняются: их зовёт `dialogue_v2_session.tsx`, и есть тесты.
6. Plus — без лимита и без записи счётчика:
   - запись идёт только у Free, чтобы после окончания Plus не было «долга»;
   - «доступ неизвестен» → не блокируем, как сейчас.
7. Смена суток — `getLocalDayKey` (полночь человека): запись за другой день читается как 0, без отдельной очистки.

## Security and privacy

Только локальный счётчик на устройстве: ни новых полей в Firestore, ни передачи данных. Privacy policy не затрагивается — данных о человеке не добавляется, только число попыток за сегодня локально.

## Technical debt

- Contain: локальный счётчик сбрасывается переустановкой приложения. Это принятый компромисс D165, без сервера. Сверка раз в день не нужна: ей не с чем сверять, серверного счётчика нет; добавлять его — лишние записи.

## Verification

Для будущей реализации — тесты:
- перенос старого ключа;
- общий лимит (2 в Диалогах + 1 в курсе = стена в обоих);
- полночь по локальной дате;
- Plus не пишет счётчик;
- гонка двух вызовов не теряет попытку;
- переходник Диалогов отдаёт прежние имена.

## Rollback

Переходник возвращается к старому ключу. Новый ключ безвреден, старый не удалялся.
