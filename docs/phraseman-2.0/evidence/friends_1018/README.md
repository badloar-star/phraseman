# Друзья №2 ↔ №3 — сценарии прогона для Сверки (18.10)

Автор: 5 · АВТОРИЗАЦИЯ. Владелец: «функция добавления друзей должна быть проверена!!! И друзья должны находиться
мгновенно, а не через полчаса».

## Условия

- Аккаунты **№2** (Delta 94030) и **№3**. **№1 не трогать.** Вход — только выбором аккаунта в окне Google, без паролей.
- Сборка ≥ `834cced52` (проба колокольчика) и ≥ коммита аудита [AUTH-OPTIMISTIC]. После обновления — перезагрузка JS.
- Вкладки открывать **таб-баром**. Диплинк `phraseman://friends` чтения не запускает (вкладка там не активна).
- На холодном старте закрыть dev-экран «Движение · гибриды», если он открылся сам.
- Логи: `adb -s <serial> logcat -d | grep -a "FRIEND-ADD\|ACTIVITY-FEED\|FRIENDS\]\|FRIEND-REQUEST\|NICK-GEN"`.
  Сохранять в эту папку: `<шаг>_logcat.txt` и кадры `<шаг>.png`.

## Сценарий A — найти друга по нику и отправить заявку (№3 → №2)

1. Войти №3 → таб «Друзья» → «Добавить друга» → поиск `Delta 94030`.
   - Видим: карточка найденного за ≤ 3 с.
   - Логи: `[FRIEND-ADD] {"step":"lookup_nick",...,"found":true,"source":"name_index","ms":N}`.
2. Тап «Добавить».
   - Видим: карточка скрывается сразу, «Отправляем заявку…», затем «Заявка отправлена!».
   - Логи: `[FRIEND-ADD] {"step":"send","result":"sent","timedOut":false,"ms":N}`.
   - Двойной тап: второй не уходит — `[FRIEND-REQUEST] add: уже в пути — повторный тап пропущен`.
   - **Засечь T0** (время строки `send`).

## Сценарий B — заявка видна у №2 при следующем открытии (замер «отправил → увидел»)

1. Выход → вход №2 → Главная.
   - Видим: у колокольчика непрочитанное «заявка в друзья».
   - Логи: `[FRIEND-ADD] {"step":"bell_probe","reason":"home_focus","decision":"network_newer","headType":"friend_request",...}`,
     затем `[ACTIVITY-FEED] refresh ok`.
   - **T1** = время `bell_probe network_newer`. Цифра для владельца: **T1 − T0** (минус время выхода/входа по
     `[ACC-SIGNOUT]` / `[SIGNIN] ui:returned`).
2. Повторный заход на Главную раньше чем через минуту → `bell_probe decision=ttl_skip` (сеть не трогается).
3. Таб «Друзья».
   - Видим: входящая заявка от №3 сразу.
   - Логи: `{"step":"tab_active"...}`, `{"step":"requests_read","source":"server","count":1,...}`.

## Сценарий C — принять заявку (№2)

1. Тап «Принять».
   - Видим: строка заявки исчезает сразу, №3 появляется в друзьях сразу (до ответа сервера).
   - Логи: `[FRIEND-ADD] {"step":"accept","ok":true,...}`. Двойной тап по «Принять» игнорируется.
2. Уйти с вкладки и вернуться через ≥ 30 с → `friends_read source=server count≥1`; раньше 30 с — `source=memory_cache`.
3. Свой профиль на вкладке: первый раз `{"step":"my_profile","source":"server"}`, дальше 10 мин — `memory_cache`.

## Сценарий D — №3 видит, что его приняли

1. Выход → вход №3 → Главная → `bell_probe network_newer` (уведомление «принял заявку»).
2. Таб «Друзья» → №2 в списке; `friends_read source=server count≥1`.

## Сценарий E — удалить друга (№3), откат при ошибке

1. Профиль друга → «Удалить из друзей» → подтвердить.
   - Видим: друг исчезает сразу, «Друг убран».
   - При ошибке сети: друг возвращается, «Не получилось убрать друга. Попробуй ещё раз»; лог
     `[FRIENDS] remove friend failed — откат`.

## Сценарий F — смена ника видна в поиске сразу

1. №2: Аккаунт → «Изменить имя» → новое имя → «Сохранить» → `{"step":"nick_publish","source":"settings","status":"ok"}`.
2. №3: поиск нового имени → `lookup_nick found=true`.

## Что прислать координатору

- T1 − T0 (сценарий B) и `ms` поиска (A1), отправки (A2), принятия (C1).
- Любые строки `[FRIENDS] ... failed` и `skipped reason=auth_link_not_ready`.
- Кадры A2, B1, B3, C1, D2.
