# Засев ошибок гостя: пометка об облаке и поле cloud в журнале [DEV-STATE]

Governance-ID: TG-9AB0F373167E
Status: в работе
Owner: сессия «4 · ТЕМЫ 2.0» (вопрос координатора: уходят ли засеянные записи в облако)

## Outcome
Установлен факт и закреплён в коде: запись события журнала ошибок (`appendMistakeEvent`) кладёт его в очередь фактов практики состояния телефона (`commitPhoneStatePracticeFact` → `triggerSync`), поэтому засеянные шесть записей одноразового гостя МОГУТ уйти в облако (в его собственный раздел), если мост синхронизации активен. Это допустимо только потому, что гость одноразовый, как у фикстур карточек. В модуле засева это сказано одной строкой в «зачем», а в журнале `[DEV-STATE] mistakes seeded …` появился признак `cloud: pushed|local_only`.

## Scope
`app/dev_mistakes_seed.ts` (комментарий, необязательная зависимость `cloudState`, поле в логе) и `tests/dev_mistakes_seed_ready.test.ts` (одна проверка). Остальной код практики и синхронизации не меняется.

## Architecture
`cloudState()` читает проекцию фактов практики `mistake` (`readPhoneStatePracticeFactProjection`): статус `available` — мост активен, записи поставлены в очередь синхронизации (`pushed`, доставка не проверяется); иначе `local_only`. Только dev, только одноразовый гость.

## Security and privacy
Данные одноразового гостя (шесть учебных фраз-образцов, без личных данных) могут попасть в его собственный раздел облака; удаляются вместе с аккаунтом гостя. Для реального аккаунта засев отказывает (проверка одноразового гостя до вызова).

## Technical debt
`pushed` означает «поставлено в очередь», а не «подтверждено сервером»: подтверждение доставки здесь не проверяется.
