## Outcome

По сверке AA-0 и ревью S0: в 16 модулях AA (клиент `modules/account-authority-v2/*`, `modules/account-session-v2/account_authority_production_adapter.ts`, проводка в `accounts_v2_client_runtime.ts`; сервер `functions/src/account_authority/*`) почти нет логов. Правило владельца «сперва логи»: вход/каждое ветвление со значением/ранние выходы/каждый catch/сеть (что ушло, код, длительность)/итог.

1. Клиент: порт-логгер `AccountAuthorityLogger` (инъекция в runtime/reducer-драйвер/transport/adapter/bootstrap), реализация по умолчанию — `console.log/warn` с префиксом `[ACCOUNT-AUTHORITY]`; тесты подменяют. В reducer (чистый) — не логировать внутри, а логировать в драйвере результат перехода (from→to, событие, причина отказа).
2. Сервер: логгер со скрытием PII (`firebase-functions/logger`, только виды/коды/длительности, хеш-префиксы ≤8 символов, без uid/токенов/email); каждый вызов callable — вход (вид операции), ветка, итог (код), длительность; `mapCallableError`/`resolveIdentity`/`mapContractError` — неизвестная ошибка логируется с видом и уходит как `unavailable` (временные) или `internal` (с логом); `AccountLeaseError('invalid_input')` → `invalid-argument`; `delete_contract.ts:550,818` — catch с видом ошибки.
3. Переупаковывающие catch без лога (transport :127, :168, :234, :258; bootstrap_contract :85, :156) — лог с безопасным кодом.
4. `accounts_v2_client_runtime.ts:376` `hasError=${bool}` → безопасный код ошибки.
5. Сторож: тест-перепись «каждый catch в файлах AA содержит вызов логгера» + «логи AA не содержат uid/token/email» (по моку логгера в поведенческих тестах).
