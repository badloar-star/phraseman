## Outcome

На экране «Темы» вместо трёх кнопок «Спокойно / Акцент / Максимум» — один ползунок интенсивности 0…1. Тянешь — тема на глазах меняет насыщенность (весь экран перекрашивается по шагам во время перетаскивания), отпускаешь — выбор сохраняется. У людей после обновления ничего не прыгает: старые «Спокойно / Акцент / Максимум» становятся точками 0 / 0.5 / 1, на которых палитра байт-в-байт прежняя.

## Architecture

Было: `level ∈ {calm, accent, max}` → три отдельные формулы палитры (`buildLiquidGlassVariant`), ~270 экранов читают `liquidGlassTokens(id)` через активный вариант + кэш.

Стало: `intensity ∈ [0,1]`, опорные точки calm=0, accent=0.5, max=1. Токены промежуточной интенсивности = поканальное смешивание (sRGB + альфа) двух соседних опорных палитр; массивы градиентов выравниваются по длине; точки градиента интерполируются. На опорной точке возвращается опорная палитра без пересчёта (байт-в-байт). Интенсивность квантуется шагом 0.05 (21 шаг) — ключ кэша и шаг перекраски. Поле `level` в токенах сохраняется как корзина (0 → calm, (0, 0.75) → accent, ≥ 0.75 → max), чтобы ~10 экранов, ветвящихся по `level`, работали без правок.

Поток: жест на UI-потоке (shared value двигает бегунок и заливку каждый кадр) → при смене шага `runOnJS(onPreview)` → `ThemeProvider.previewIntensity` (НЕ пишется на диск) → дерево перекрашивается ≤ 21 раз за полный проход, не на каждый кадр → при отпускании `onCommit` → state + `AsyncStorage` (`liquid_glass_intensity` + совместимый `liquid_glass_color_level`) → превью сбрасывается.

Миграция: при старте один `multiGet` читает новый и старый ключи; есть `liquid_glass_intensity` → он; нет → старый уровень → опорная точка, и новый ключ дописывается. Лог `[THEME-INTENSITY]`.
