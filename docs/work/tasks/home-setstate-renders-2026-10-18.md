# Task packet: [HOME-SETSTATE] меньше перерисовок Главной на возврате

Governance-ID: TG-959F87139993
Status: In progress
Owner: сессия «2 · ДИЗАЙН» (поручение координатора 18.10)
Related epic/enabler: скорость Главной (Performance Bible), [HOME-RENDERS]

## Outcome

Главная перерисовывалась ~23–30 раз за окно возврата (замер Моментов; `evidence/cpu_1017/1_full.txt`: 23 рендера, из них `appSnapshot` менялся 9 раз). Цель: убрать перерисовки, где ничего видимого не изменилось, вид не меняется. Успех: `appSnapshot` меняется только при реальной смене профиля/серии/монет; число рендеров в окне падает (замер «было → стало» по [HOME-RENDERS] на эмуляторе, пока он занят — по тесту равенства).

## Scope

In scope: новый чистый помощник `app/home_snapshot_equal.ts` (равенство секций снимка без штампа `updatedAt`), подключение в `app/(tabs)/home.tsx` одним хунком (функция равенства у `useAppSnapshotSelector`), тест помощника.

Out of scope: само хранилище снимка (`app_snapshot_store.ts`, охранные правила порядка записей), хуки опроса/недели/«С возвращением» (причина их внутренних перерисовок — отдельный замер), перенос ~47 useState в один объект (>60 строк, после релиза).

## Architecture

Писатели снимка собирают секции заново с `updatedAt: Date.now()`, сравнение по ссылке всегда видит «новое». Селектор Главной получает сравнение по содержимому без `updatedAt`; при равенстве хук возвращает прежнюю ссылку, `useSyncExternalStore` не перерисовывает. Хранилище не меняется: оно по-прежнему принимает патчи и публикует их другим подписчикам. Инвариант: Главная не читает `updatedAt` снимка (проверено поиском по `home.tsx` и `resolveHomeProfileVisuals`).

## Security and privacy

Данные не собираются и не передаются, новых полей и сервисов нет.
