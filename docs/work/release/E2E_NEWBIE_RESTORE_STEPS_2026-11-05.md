# E2E: переустановка / восстановление / dev-гейты — пошагово для Сверки (05.11)

Составлено Входом по коду. Общий сценарий новичка — `E2E_NEWBIE_STEPS_2026-11-05.md` (там же таблица негативных сценариев, пункты ж и з — подробности здесь).

## 0. Подготовка (один раз)

1. Метку среза `RANK_GATES_NEW_USERS_SINCE_MS` подставит Вход ~01:15 по часам ПК; результат — сообщение координатору/Сверке с ISO-меткой. **Все тестовые аккаунты для «новичка» создавать ПОСЛЕ этой метки.** Аккаунты, созданные раньше, считаются «старыми» (`old_account`): ни приветствия, ни бонуса.
2. Нужна dev-сборка с Metro (в релизе `console.log` вырезается, журнала не будет). Метки журнала: `[RANK-GATE]`, `[WELCOME-B3]`.
3. Как смотреть баланс монет: счётчик монет в шапке Главной (рядом с аватаром). Записывать число ДО и ПОСЛЕ каждого шага.
4. Как смотреть журнал: `.expo/metro-console.log` (строки фильтровать по `[RANK-GATE]`, `[WELCOME-B3]`, `[SYNC]`).

## 1. Dev-принудительное включение гейтов (замки по рангу и «Открытия разделов»)

Гейты в первой версии ВЫКЛ по умолчанию (`rank_gates_enabled=false`, `section_openings_enabled=false`); включает Пульт после выхода сборки в сторе. Для проверки на эмуляторе, не трогая боевой Пульт:

- **Параметр:** переменная окружения сервера разработки `EXPO_PUBLIC_DEV_FORCE_FLAGS="rank_gates_enabled,section_openings_enabled"` (через запятую; можно один флаг).
- **Запуск:** остановить сервер разработки (Metro) и запустить заново с очисткой кэша (`--clear`) и этой переменной (значение встраивается при сборке бандла). PowerShell: `$env:EXPO_PUBLIC_DEV_FORCE_FLAGS="rank_gates_enabled,section_openings_enabled"` и затем обычная команда запуска Metro вашего проекта с `--clear`. Git Bash: та же переменная перед командой запуска. Приложение на эмуляторе перезагрузить (reload).
- **Действует только** в dev-сборке и НЕ в стор-релизе (`EXPO_PUBLIC_STORE_RELEASE=1` её обнуляет) — в релизной сборке переменная игнорируется.
- **Что должно появиться у НОВИЧКА (аккаунт создан после метки среза):** замки по рангу: Видео и Диалоги закрыты до ранга 1, Пик — до ранга 2, хаб Карточек — до ранга 3; окна «Открытие разделов» при открытии разделов. У «старого» аккаунта замков нет ни с флагом, ни без.
- **Без параметра** (дефолт 2.1.0): замков и окон нет — это ожидаемо. Приветствие B-3 и бонус +500 от флагов не зависят.
- **Проверка, что принуждение сработало:** замок виден на экране; в журнале нет `flag_off`.

## 2. Сценарий ж: переустановка → вход в ТОТ ЖЕ новый аккаунт (+500 не удваивается)

Предусловие: новый аккаунт A (создан после метки среза) прошёл онбординг и первое занятие классики, получил +500 один раз. Записать баланс `B0` (после бонуса).

1. Выйти из аккаунта или удалить приложение (переустановка). Поставить заново.
2. Пройти онбординг и войти В ТОТ ЖЕ аккаунт A (тот же способ входа).
3. Дождаться восстановления данных (баланс на Главной стабилизировался, ~10–30 с, строки `[SYNC]`).
4. Пройти первое занятие классики заново (или любое завершённое) и дойти до экрана результата.
- **Ожидание:** баланс = `B0` + обычная награда за урок, но **без дополнительных +500**. Допустимо один раз увидеть строку «+500 монет за первое занятие» (если вердикт «новый» вернулся раньше прогресса из облака) — но итоговый баланс не должен вырасти на 500 сверх обычной награды.
- **Журнал:** либо `[RANK-GATE] first_lesson_bonus skip reason=already_granted/not_new`, либо `granted` с тем же ключом операции — и сервер не добавляет монет второй раз (операция `level_spin:<requestId>.<lane>` одна на владельца, сервер схлопывает по квитанции).
- **Красный флаг:** баланс вырос на 500 относительно `B0` + обычной награды.

Как это обеспечено в коде (для справки): ключ операции `dailyjourney_<32>_1` — хеш от uid владельца, одинаков на любом устройстве; `functions/src/level_spin_star_grant.ts` принимает операцию один раз по квитанции.

## 3. Сценарий з: вход в старый аккаунт на новом устройстве — прогресс es/fr/de/it

**Только ПОСЛЕ серверной выкладки (деплой 02:00):** до неё клиентские ключи прогресса es/de/it считаются серверными, и прогресс этих курсов в облако не уходит.

Предусловие: аккаунт B с прогрессом в классике на устройстве 1 (несколько пройденных уроков в es / fr / de / it — минимум по одному уроку в каждом), прогресс отправлен в облако (подождать синхронизацию ~1 мин на устройстве 1).

1. На устройстве 2 (или после переустановки) — онбординг → вход в аккаунт B.
2. Дождаться восстановления (см. 2.3).
3. По очереди переключить язык изучения на es, fr, de, it (Настройки → язык изучения / выбор курса) и открыть «Уроки».
- **Ожидание:** для каждого языка отмечены те же пройденные уроки, что на устройстве 1 (ключи `lesson_progress_v2::<es|fr|de|it>::…` восстановлены). Замков по рангу нет (дефолт) и приветствия нет — это «старый» аккаунт.
- **Журнал:** `[RANK-GATE] verdict {"isNew":false,"reason":"old_account"|"prior_progress"}`; бонуса нет.
- **Красный флаг:** прогресс одного из языков пуст при непустом на устройстве 1 (после деплоя 02:00) — записать язык и время.

## 4. Что присылать координатору по итогам

Для каждого сценария: баланс до/после, строки журнала, скрин Главной. Если баланс вырос на 500 при ж — немедленно, с номером коммита среза.
