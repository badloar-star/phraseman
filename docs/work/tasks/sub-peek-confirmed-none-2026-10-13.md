## Outcome

Сейчас `rememberPremiumPlan` пустой план не пишет. После окончания подписки в том же процессе память держит прежний план, и первый кадр «Подписка Plus» может показать «Plus» без подписки.

Второй путь к той же ошибке: `manage_local` читает `premium_plan` из хранилища. Этот ключ после деактивации остаётся (меняется только `premium_active=false`). Значит, следующее открытие экрана снова запомнит старый план.

Нужно:
- Подтверждённое «нет подписки» записывается в память с тем же ключом поколения аккаунта.
- Первый кадр без плана — прежний скелет, а не прежний план.
- Слабый источник (чтение хранилища `manage_local`) не перезаписывает подтверждённое «нет» в том же поколении.
- Сильные источники (`rc_persist`, `guard_refresh` — подтверждение активной подписки) перезаписывают.
- Лог `[SUB-PEEK] cleared reason=… prev=… generation=…` и `[SUB-PEEK] skip source=… reason=confirmed_none`.

## Architecture

- Тип памяти: `plan: string | null`; `null` — подтверждённое «нет».
- `forgetPremiumPlan(reason)` пишет запись `{ plan: null, source: reason, generation }`.
- `peekPremiumPlan()` для записи «нет» возвращает `null`. Вызывающие не меняются: `null` = скелет, как до PM-214.
- Источник «нет» — событие `premium_deactivated`. Его шлют все места подтверждённой деактивации: фоновый refresh в `premium_guard`, снятие удержания `plus_transfer`, тяжёлая инициализация `_layout`.
  - Подписка ленивая: при первом `rememberPremiumPlan`, без побочного эффекта при импорте. Пока в памяти ничего нет — стирать нечего.
  - Ложная деактивация безопасна: даёт только скелет, никогда не неверный план.
- Слабые источники — `WEAK_SOURCES = {'manage_local'}`. Не перезаписывают «нет» текущего поколения.
