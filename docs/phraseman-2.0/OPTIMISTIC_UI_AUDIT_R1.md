## Подробно: что есть → чего нет

### 1. Сохранить / убрать карточку (закладка)
**Что есть.** `components/AddToFlashcard.tsx:172 handlePress`: закладка и анимация меняются на том же тапе (а); `inFlightRef` держит повторный тап, `blockStaleStorageHydrationRef` не даёт старому чтению затереть свежее (в); после записи `applyStorageTruthFor` сверяет с хранилищем (д); данные — `hooks/use-flashcards.ts:509 addFlashcard` / `removeFlashcardByEnglish` под общим замком записи аккаунта, дубль и лимит проверяются внутри; `restoreFlashcard` идемпотентен.
**Чего не было 🔧.** Откат («закладка сама снялась») был немым: `catch { setSaved(…) }`, результаты `stale` / «не убрано» — без причины и без сообщения. Теперь: `[OPT-UI] card_save|card_remove rollback reason=…` в журнал + тост «Не удалось сохранить / убрать карточку. Попробуй ещё раз.» Лимит по-прежнему ведёт в пейвол.
**1a.** `app/flashcards_collection.tsx:1202 onToggleOpenedSave`: галочка сразу, `openedSaveInFlightRef`, откат + тост при `stale/failed`, пейвол при лимите (закрыто Ядром 12.10).
**1b.** `components/youtube/YoutubeVideoPhrases.tsx` `save`: закладка сразу, `savingIdsRef`, откат с причиной `[VIDEO-PHRASE-SAVE]` и тостом.
**1c.** `app/flashcards_card_editor.tsx:192 handleSave`: форма ждёт локальную запись (десятки мс) и уходит — не сеть, поэтому (а) ⚠️. Ошибка → тост «Не удалось сохранить» + «Повторить», черновик остаётся. 🔧 Замок двойного тапа был на состоянии `saving` (ставится после рендера) — второй тап в том же кадре мог создать дубль карточки; теперь `saveLockRef` (синхронный) + `[OPT-UI]` лог. 🔧 Отказ по лимиту Plus (`plus_custom_card_limit_reached`) выглядел как «Не удалось сохранить» с бессмысленным «Повторить» — теперь тост называет причину.

### 2. Удалить карточку и «Вернуть»
**Что есть.** `app/flashcards/useCollectionData.ts:904 deleteCardById`: карточка исчезает из списка до записи (а); `deletingCardIdsRef` — один проход на карточку (в); при сбое возвращается ТОЛЬКО она на своё место + тост «Не удалось удалить карточку» (б); снекбар «Вернуть» 5 с, снапшот с индексом (д). `deleteCardsByIds:967` — то же для пачки, откат реконструирует список из хранилища.
**Чего не было 🔧.** (а) «Вернуть» возвращал карточку в список ПОСЛЕ записи в хранилище — теперь список обновляется в тот же кадр, запись догоняет (для «Сохранённых» и пачки); при сбое `catch` перечитывает факт и показывает тост. 🔧 Два немых `catch {}` (пакетное удаление, «Вернуть») получили причину в журнал.
**E4 закрыто (12.10).** «Вернуть» для СВОИХ карточек (`kind === 'custom'`) теперь тоже возвращает карточку в список в тот же кадр, запись догоняет; при сбое catch перечитывает `listCustomCards` и говорит тостом `Не удалось вернуть карточку` (лог `[OPT-UI] undo_delete rollback` / `custom reload_failed`).
