# Окно покупки набора следует цвету темы (токены Liquid Glass)

Governance-ID: TG-573D0530927E
Status: в работе
Owner: сессия «4 · ТЕМЫ 2.0» (решение координатора 12.10: «ДА» — вечная зелёная оболочка это дефект; окно обязано работать на любой цветовой теме, тёмной и светлой)

## Outcome
Построитель оболочки окна покупки набора из токенов (`app/flashcards/cardPackPaywallTokenTheme.ts`) покрыт тестом на тёмной и светлой темах и разных оттенках ползунка. Тест-отпечаток `tests/card_pack_paywall_theme_fingerprint.test.ts` остаётся записью «было» (зелёная оболочка по прежнему режиму `dark`) с пометкой, что новое поведение задаёт токен-оболочка. Подключение двух строк в экранах (`CardPackShardPaywallModal.tsx:457`, `useCollectionData.ts:1253`) передано Дизайну координатором. Список других мест, задетых тем, что ThemeContext всегда отдаёт themeMode='dark', — координатору.

## Scope
Новый файл построителя, два теста, список мест с жёстким themeMode. Экраны Карточек не правятся.

## Architecture
`cardPackPaywallShellFromTokens(GlassTokens)` — чистая функция без состояния: цвета берутся из токенов (accent, accentBright, accentInk, accentGlow, opaqueControl/opaqueCard, bg, text, isLight) через glassTone. Категорийные и UGC-патчи остаются поверх, как раньше. Старая таблица остаётся до подключения экранов, затем удаляется отдельным коммитом.

## Security and privacy
Только цвета. Данные, покупка и права не затрагиваются; политика конфиденциальности не меняется.

## Technical debt
Старая таблица по прежним id тем (≈65 литералов) живёт, пока Дизайн не подключит экраны; затем удалить вместе с тестом-отпечатком или оставить его как архив. Градиент цены и подложка подобраны по токенам без макета окна — сверка с макетом Дизайном.

## Verification
Точечный jest при свободных ≥3 ГБ и слоте светофора (`--maxWorkers=1`): отпечаток и тест токен-оболочки; срез типов по двум новым файлам; ratchet цветов.

## Rollback
git revert коммита; экраны не затронуты, поведение приложения не меняется до подключения.
