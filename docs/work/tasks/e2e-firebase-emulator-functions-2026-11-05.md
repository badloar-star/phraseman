# Task packet: локальный Firebase-эмулятор с функциями для живой проверки удаления аккаунта

Governance-ID: TG-44E4EE2E5610
Status: Planned
Owner: сессия «5 · Вход» по просьбе координатора (эмулятор 2, MAESTRO2_RESULTS 97b9f96fa)
Related epic/enabler: docs/work/release/E2E_RUNBOOK_DELETE_AND_PLAN_CHANGE_2026-11-06.md, задача 19 трекера 150

## Outcome

Набор эмуляторов auth 9099 + firestore 8085 + functions 5001 с функциями, собранными из чистого снимка HEAD, готов; исполнитель на эмуляторе 2 может пройти вход → удаление → повторный вход на тест-аккаунте. Успех: функции загружены эмулятором, вызов удаления отвечает без ошибки.

## Scope

In scope: снимок HEAD во временной папке вне репозитория, сборка functions, временный конфиг эмулятора, перезапуск своих эмуляторов, короткая запись в runbook.
Out of scope: любые правки кода приложения и функций; деплой; прод (только локальные порты); чужие незакоммиченные правки functions/src (в снимок не попадают).

## Architecture

No architecture change: локальная инфраструктура разработки. Данные текущего эмулятора переносятся через экспорт хаба (не теряем сид аккаунтов).

## Security and privacy

Только локальные 127.0.0.1-порты и демо-проект `demo-phraseman`; прод-ключи не используются; в снимок копируется только `functions/.env` (имена ключей в журнал, значения нет). Тест-аккаунты — из сид-файла, не реальные люди.

## Technical debt

Contain: рецепт сборки из снимка и конфиг фиксируются в runbook, чтобы не повторять поиск; выход — вынести в скрипт `scripts/e2e/` после релиза 150.

## Verification

Эмулятор печатает список загруженных функций; вызов `accountDeleteEnqueue`-цепочки из сид-аккаунта отвечает; порты 9099/8085/5001 слушают.

## Rollback

Остановить эмуляторы, удалить временную папку (junction — только через `.Delete()`), вернуть прежний запуск `auth+firestore`; экспорт данных остаётся.
