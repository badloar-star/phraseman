## PM-153 Позиционирование V1 как тренировочного курса

## PM-154 План новых языковых курсов V1
Объём (предложение владельца, COURSES.md): 32 урока × 50 фраз = **1600 фраз на язык**. Это ориентир, а не гарантия
качества: «случайные 1600 фраз» курсом не считаются.
Ступени: берём действующую сетку V1 — A1 (уроки 1–8), A2 (9–18), B1 (19–28), B2 (29–32) — границы разделов по стартовым урокам 9/19/29 в `app/lesson_lock_system.ts`, срезы знаний остаются; у каждого урока цель,
prerequisite и контрольная лексика.
Артефакты до публикации любого языка:
- **Реестр лексики** (слово/лемма, перевод ru и uk, урок первого появления, число повторов);
- **Реестр форм** (времена, артикли/род, порядок слов — какая форма вводится в каком уроке и не раньше);
- **План повторов**: повтор — педагогическое решение с пометкой «повтор», а не незаметный дубль;
- **Редакторская проверка** носителем до публикации (процесс — PM-155); без подписи редактора урок не публикуется;
- проверка существующего движка «Устно» для локали на устройстве; облачное распознавание не подключаем (PM-158).
Порядок: один пилотный язык и 3–4 урока с рубрикатором, затем остальное; «тысячу сессий генерации» заранее не создаём.
Какой язык первым — решение владельца (Q-C).

## PM-155 QA-процесс для 1600 фраз
Проход на каждую фразу и урок (чек-лист, результат — pass/fix/block + комментарий редактора):
1. **Естественность** — так говорят носители, а не калька; регистр уместен уровню.
2. **Уровень** — лексика и формы не выше ступени урока (сверка с реестром лексики/форм).
3. **Перевод** — ru и uk точны, без добавленного и пропущенного смысла.
4. **Повторение** — доля новых слов, интервалы повторов, нет скрытых дублей.
5. **Произношение** — озвучка/TTS выбранной локали читает фразу корректно (слушает человек; офлайн-движок проверяется на устройстве).
6. **Фактическая обучающая последовательность** — урок N использует только то, что введено в 1…N−1; проверка по реестрам.
Выборка: 100% фраз проходят автоматическую сверку с реестрами; редактор читает 100% текста урока; 10% аудио слушает человек
(при находке — урок целиком). Урок с блокирующей находкой не публикуется. Протокол хранится рядом с уроком.
Статус: процесс описан, ни на одном языке ещё не запускался.

## PM-158 Облачное распознавание голоса — исследование (платный API не подключаем)
Сейчас: распознавание на устройстве (`expo-speech-recognition`), оценка «Устно» —
`device-transcript-match-v1` (сравнение распознанного текста с целью, `app/pronunciation_scoring_*`). Облачный STT для
учеников не подключён (транскрипция в `functions/src/max_voice_config.ts` относится к запломбированному разделу MAX).
Порядок исследования, ничего не покупая:
1. **Качество** — набор сценариев: реальные акценты ru/uk-говорящих, 4 языка, шум, короткие фразы; метрика — доля верно
   распознанных слов и устойчивость к акценту; сравнение с текущим движком на тех же записях.
2. **Стоимость** — цена минуты/запроса, concurrency, влияние на энергию/Plus (оценка по числу попыток «Устно»).
3. **Согласия** — отдельное согласие на отправку голоса, возраст, обновление политики конфиденциальности до релиза (правило владельца о данных).
4. **Retention** — хранение/удаление записей, срок, право удаления; по умолчанию не хранить.
5. **Fallback** — офлайн/нет согласия → текущий движок устройства.
Граница: транскрипция измеряет «что распознано», а не артикуляцию; процент «правильного произношения» из неё не выдаётся.
(Замечание: нынешний балл «Устно» — совпадение текста; как он подписан пользователю — вопрос к дизайну/владельцу, Q-F.)

## PM-159 Голосовая ветка V2 (проект)
Цель — те же учебные цели, другой способ ответа. Модель совместимости:
- карта и прогресс **не дублируются**: прогресс ведётся по учебной цели (objective/skill), а способ ответа —
  атрибут попытки (`response_mode: tap | voice`); завершение цели любым способом даёт один и тот же кредит;
- у сессии один session ID; голосовой вариант — «режим» внутри неё (в V2 уже есть семейства режимов и
  `scripted_repeat_compare`, `modules/learning-v2/contracts/mode_native_authoring_contract_v1.ts`) — отдельный backend/контент не нужен;
- нет разрешения микрофона / нет движка / офлайн → автоматический возврат на обычный способ, без потери прогресса;
- микрофон и озвучка работают через единый арбитр звука (`modules/audio/audio_runtime_arbiter.ts`);
- голос не оценивается облаком, пока не решён PM-158.
Открыто: что считается «пройдено голосом» (порог) и награда — Q-G.
