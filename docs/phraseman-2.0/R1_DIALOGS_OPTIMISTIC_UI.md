## Подробно

### 1. Отправить реплику
`app/dialogue_v2_session.tsx` `send` → `runPendingTurn`: пузырь ученика и очистка поля — в том же кадре (а); синхронный замок `turnStartingRef` + `sending` (в); `turnId` идемпотентен — повтор того же хода сервер не считает дважды (в, д); сбой → панель ошибки с «Повторить», `quota_exhausted` — пузырь остаётся помеченным «не отправлено» + экран лимита, `paused` — отдельный экран, `rate_limited` — «Повторить» после остывания (б); «печатает» — внутри ленты, не на весь экран (г); пилюля «N/30» — E3, не трогал.
**Чего не было 🔧 — реплика, отправленная ДО готовности серверной сессии, не уходила никогда.** Ход ставился в очередь выставлением `sending=true`, а эффект «отправить, как только сессия готова» требовал `!sending` — условие никогда не выполнялось, пузырь висел «печатает…» без ответа (с 01.10, `a616db1af`; сценарий — быстрый тап «Отправить» сразу после входа или медленная сеть при старте сессии). Теперь очередь — отдельный `queuedTurnRef` (как у свободного разговора), эффект зависит от него, а не от `sending`; в журнале `[DIALOGUE-V2] turn:flush → session ready` / `→ nothing queued`.
**Чего не было 🔧 — немая очередь при недоступном старте.** После 5 неудачных стартов сессии (тихие повторы по 4 с) ход так и оставался в очереди без сообщения. Теперь: если старт уже провален — панель «Не получилось…» с «Повторить» сразу (пузырь остаётся), если провалился уже после постановки в очередь — то же самым эффектом; логи `turn:send → session start unavailable` и `turn:queued → session start unavailable`.

### 2–3. Подсказка и перевод фразы
`hooks/use_dialogue_v2_session_coaching.ts`: подсказка (`hint`), перевод (`replyTranslations`), «Лучше так» (`betterPhrasing`), объяснения приходят В ОТВЕТЕ хода и кладутся в состояние одним проходом; тап «Перевести» / «Подсказка» / «Лучше так» — только переключение локального набора (`translatedIds`, `fixOpenIds`), сети на тапе нет (а ✅, г ✅). Сбоев нет, откатывать нечего.

### 4. «Почему так»
`openWhy`: для Plus — сразу открыто; для Free — `revealWhy` на `allowanceRef` (дневные 3 раскрытия): состояние и счётчик меняются на тапе, запись на диск — `persistDialogueV2WhyAllowance` фоном, «уже раскрытое» не отнимается (в ✅). При исчерпании — тот же экран со шторкой-лимитом (`whyGate`), лог `[DIALOGUE-V2] why:gate`. Теоретическая гонка: тап до чтения сохранённого счётчика (первые миллисекунды экрана, когда ответа ещё нет и «Почему так» недоступен) — не воспроизводима на практике.

### 5. Завершить диалог / «Итоги»
`openSummary`: отметка «пройден» (`markDialogueV2Done`) и разбор ходов — в тот же кадр (память + хаб), диск догоняет; переход — сразу.
**Чего не было 🔧.** (в) переход шёл прямым `router.push/replace` — двойной тап по «Итоги»/«Завершить» открывал экран итога дважды (для `push` — два экрана в стеке, «назад» жалась дважды). Теперь `useGuardedNav` (окно 600 мс), так же защищён «Plus» на стене лимита.
**Что остаётся (⚠️ г).** Экран итога (`dialogue_v2_completion.tsx`) всегда ждёт сервер (ИИ-ревью): внутри экрана — карточка «Собеседник готовит итог…» с индикатором, заголовок и кнопка закрытия на месте (полноэкранного спиннера нет), при сбое — «Повторить». Локальные цифры (реплик, ошибок, список «Что исправить» из `readDialogueV2SessionOutcome`) уже есть на телефоне, но показываются только вместе с ответом сервера — E9 ниже.

### 6. Повторить после ошибки
`retry`: `setTurnFailure(null)` — панель исчезает в том же кадре, ход идёт тем же `turnId` (повтор не списывает второй раз); замки `turnStartingRef` / `sending`; потолки: `rate_limited` — кнопка после остывания, `plus_daily_cap` — кнопки нет (б, в ✅).
**Чего не было 🔧.** Если серверной сессии нет (старт не удался), «Повторить» молча игнорировался (`turn:retry → ignored`). Теперь: ход снова в очередь, `setStartAttempt(0)` перезапускает старт (если он был «недоступен»), панель скрыта, лог `turn:retry → no session, queue again and restart start`.

### 7–8. Микрофон: старт, стоп, повтор записи
`hooks/use_dialogue_v2_voice_message.ts` `start`: статус `starting` ставится синхронно ДО первого `await` (инвентарь языков, разрешение, готовность аудио) — кнопка реагирует в тот же кадр (а); поколения `voiceInputSessionRef` / `voiceStartGenerationRef` / `voiceCaptureTokenRef` отбрасывают поздние события старого захвата (в); устройство без распознавателя — понятный отказ с логом `[SPEECH-AVAIL]`, отказ в доступе — кнопка «Настройки», «не расслышал» — «Повторить» (б). `stop`: `releaseVoiceRecording` → `idle` сразу, распознаватель довозвращает итоговый транскрипт событием `result` (применяется, пока сессия захвата та же).
**Чего не было 🔧.** (б) повтор СВОЕЙ записи (`play`): два `catch {` без причины — не создался плеер / не начал играть, запись молча не звучала. Теперь `[DIALOGUE-V2] voice:replay → createAudioPlayer failed | play failed` с текстом ошибки.

### 9. Вход в сессию со списанием энергии
`dialogue_v2_briefing.tsx` `onStart`: замок `startInFlightRef` синхронно (двойной тап) (в ✅); порядок «согласие на ИИ → списание → переход» (шторка согласия до списания, 360 мс пауза, отмена при уходе с экрана — `consentStartTimerRef`) ✅; Free с нулевым месячным остатком — без списания сразу на экран лимита (зеркало на телефоне, 0 чтений сети) ✅; Plus не тратит (`unlimited`); `confirmSpendOne` — локальный журнал энергии (операция идемпотентна: номер = случайная метка открытия + счётчик попыток) — спиннера нет, цифра в шапке падает локально и догоняется сервером позже (д ✅); `insufficient` → окно «Нет энергии», `cancelled`/исключение → тост «Не получилось начать диалог» + новый номер попытки (б ✅). Возврат: отказ сервиса на первом ходе → `settleEnergy('refund')` + тост «Энергия возвращена»; согласие отклонено уже в сессии → возврат один раз (`consentRefundDoneRef`).
Холодный вход без снимка каталога: полноэкранный «Загружаем диалоги…» (`DialogueGlassGate`) — это E2 прежнего аудита (нужен тёплый снимок), не менялся.
