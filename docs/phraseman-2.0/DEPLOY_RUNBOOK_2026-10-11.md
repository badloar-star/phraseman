# Выкладка серверной части 2.0 — пакет на одну страницу (Ядро, 11.10)

Запускает владелец или сессия, которой владелец прямо сказал «выкладывай». Ядро сверило: все 53 имени функций из
[DEPLOY_NOW.md](DEPLOY_NOW.md) и [OWNER_RELEASE_STEPS.md](OWNER_RELEASE_STEPS.md) существуют в экспортах
`functions/src/index.ts`; папка `functions/` закоммичена (нет чужих незакоммиченных правок, которые уехали бы в облако).

## 0. Перед каждой группой — 30 секунд

```bash
git status --short functions/ firestore.rules firestore.indexes.json
```

Пусто — можно. Не пусто — стоп: `firebase deploy` берёт рабочую папку, а не коммит.

Ключи Шпиля (`config/spire_v1.enabled`, `remote_config/app.bools.spire_tab_enabled`) **не трогать** до сигнала
координатора — их включают после выхода сборки в сторе.

## 1. Порядок групп (команды — в DEPLOY_NOW.md, раздел «Шаг 1 → Команды»)

| № | Группа | Безопасно для боевой 1.6.x | Почему |
|---|---|---|---|
| 1 | Индексы и правила Firestore — только после сверки (раздел 2) | да, если сверка без неожиданностей | правила 2.0 открывают чтения новых коллекций; старых не закрывают |
| 2 | Приватность (5 функций: submitClientReport, adminAlert*) | да | меняется только то, что пишется в журнал и Telegram |
| 3 | Пакеты A+B+D и K (каталог YouTube, ошибки, друзья) | да | старый клиент читает те же документы; K только перестаёт публиковать одинаковый каталог |
| 4 | Диалоги V2 | да — новые имена | 1.6.x их не вызывает |
| 5 | Шпиль — 14 функций (команда в OWNER_RELEASE_STEPS §4, шаг 1) | да | комнат у 1.6.x нет, кроны работают только по существующим комнатам |
| 6 | Озвучка карточек, видео-наборы, прочее 2.0 | да | новые имена / только админ |
| 7 | `firebase deploy --only hosting:admin` | да | админка; кнопки Шпиля без нажатия ничего не меняют |
| 8 | Политика: `npm run legal:sync`, затем `firebase deploy --only hosting:knowlywww` | да | текст; абзац «Память диалогов» — от Авторизации (d4da63312) |
| 9 | В день выхода 2.0 — `levelSpinStarGrant` первым, затем остальные изменённые (DEPLOY_NOW, «день релиза») | только в день релиза | меняют поведение для 1.6.x |

После каждой группы: `firebase functions:log --only <одно имя> --limit 20` — нет ли ошибок на старте функции.

## 2. Правила и индексы — сначала сверка

```bash
firebase deploy --only firestore:rules --dry-run
```

Сверка с боевыми — Firebase Console → Firestore → «Правила» → история версий (сравнить с `firestore.rules` в коммите).
Любое правило, которое ЗАКРЫВАЕТ чтение/запись, нужное 1.6.x, — стоп и отчёт.

## 3. Переменные сборки EAS (production) — только имена

Должны быть заданы (значения — в EAS, не в чате): `EXPO_PUBLIC_RC_IOS`, `EXPO_PUBLIC_RC_ANDROID`,
`EXPO_PUBLIC_GOOGLE_WEB_CLIENT_ID`, `EXPO_PUBLIC_APPLE_ANDROID_SERVICE_ID`, `EXPO_PUBLIC_APPLE_ANDROID_REDIRECT_URI`,
`EXPO_PUBLIC_APPLE_ANDROID_APP_CALLBACK_URI`. Не должно быть `EXPO_PUBLIC_ENABLE_DEV_TOOLS=1`.
Проверка — `eas env:list --environment production` (выводит значения — смотреть самому, в чат не копировать).

## 4. Стоп-условия

- Ошибка сборки функций — стоп.
- `firebase deploy` спрашивает про удаление функций, которых нет в коде, — отвечать «нет», имена — в отчёт.
- Любой шаг, где боевые данные могут быть потеряны или перезаписаны, — стоп и отчёт.
- `--force` не использовать.
