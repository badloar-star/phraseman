# Task packet: полноценный визуальный редизайн шторки комментариев

Governance-ID: TG-2C5844EDC663

Related epic/enabler: docs/work/tasks/2026-09-17_real_avatars_in_pack_comments.md

## Outcome

Владелец явно попросил довести раздел комментариев под набором до уровня
остального приложения — «полноценный красивый и годный», не полагаться на
временный вид, собранный при первой реализации. Задача продолжает уже начатую
замену emoji-заглушек на настоящие аватарки (`resolveCommunityAuthorProfile`
уже готов) и добавляет слой визуальной полировки всей шторки: карточки
комментариев, композер, меню действий, пустое состояние — единый язык с
остальным приложением (тема `constants/theme.ts`, палитра «Индиго»).

## Scope

In scope:
- `app/community_packs/PackCommentsSheet.tsx`: подключить `AvatarView` вместо
  `avatarFor()`; вынести строку комментария в отдельный `memo`-компонент
  (без пере-рендера на подсветку/скролл); подтянуть профиль автора батчем при
  открытии шторки (уникальные authorId), с локальным своим аватаром для
  оптимистичной записи; общая полировка визуала (отступы, тени/тон вместо
  обводок, типографика) по правилам owner-rules.
- `functions/src/user_notifications.ts`: дописать `fromAvatar` в
  `notifyOnPackCommentCreated`.

Out of scope:
- Другие экраны (правка набора, колокольчик как список) — не трогаются.
- Изменение логики прав доступа — уже стабильно.

## Architecture

Не меняется структурно. Источник аватара — уже готовый
`resolveCommunityAuthorProfile` (packAuthorNames.ts, расширен в предыдущей
задаче). Дизайн-скиллы owner-rules применяются напрямую к существующему
компоненту без внешней инфраструктуры (нет отдельного PRODUCT.md/DESIGN.md
для RN-проекта — дизайн-язык уже задан `constants/theme.ts` и соседними
компонентами, impeccable-инфраструктура не запускается отдельно).
