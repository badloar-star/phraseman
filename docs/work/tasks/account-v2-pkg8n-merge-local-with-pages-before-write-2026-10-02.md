## Outcome

Клиентская выгрузка карточек (`app/flashcards_cloud_upload.ts` → `writeFlashcardPages`, общий путь sync/force с 8K) заменяет страницы целиком локальным списком. После серверного слияния 8M (5b4c1c781) в страницах победителя лежат карточки проигравшего; любое устройство победителя, у которого их нет локально (другие устройства; устройство входа, если restore пошёл sticky-веткой без чтения страниц), при первом изменении списка уберёт их из страниц. То же для любого второго устройства одного аккаунта: страницы = «последний записавший побеждает».

Сделать (минимально, дёшево по Firebase):
1. Сперва логи `[FLASHCARD-PAGES] pre_write_merge key=… local=… remote=… added_from_remote=… dropped_by_journal=…` без uid/содержимого.
2. Перед заменой страниц ключа — объединить локальный список с текущими страницами (по id; без id — по полному JSON), исключая карточки из журнала удалений 7D (переиспользовать `mergeLockedFlashcardsWithPages`/логику 8J из `app/flashcard_pages_read_result.ts` и `readCardDeletionJournal`). Добавленные из облака карточки записать и ЛОКАЛЬНО (иначе следующий синк снова их «удалит» и снимок разойдётся), с соблюдением Optimistic UI (без спиннеров; хук/кэш карточек обновить так же, как это делает restore).
3. Стоимость: не читать страницы на каждый синк. Читать только когда есть основания: (а) нет локальной отметки «страницы подтверждены после последнего restore/слияния» ИЛИ (б) серверный признак слияния (`identityMergedAt` в документе пользователя новее локальной отметки — документ уже читается при restore; если синк его не видит — предложить дешёвый вариант и обосновать). `writeFlashcardPages` уже делает `col.get()` — переиспользовать это чтение, если возможно, вместо второго запроса.
4. Ошибка чтения страниц → не писать (как замок 8J), лог.
5. Не ломать 8H-2 (null в документе), 8J (замок), 8K (force + потолок/отказ).

## Итог исполнителя (2026-10-02)

**Что сделано (п. 1–5):**
1. Логи `[FLASHCARD-PAGES] pre_write_merge key=… local=… remote=… added_from_remote=… dropped_by_journal=… decision=… reason=…` и `pre_write_merge_finish …` — только числа и коды, без uid и содержимого карточек (проверено тестом).
2. Перед заменой страниц ключа `writeFlashcardPages` отдаёт крючку `preWrite` снимок, который он и так читает (`col.get()` ради хвоста). Решение (`decideFlashcardPagesPreWrite`): страницы языка (фильтр как у сервера 8M: поле `target`, без поля — префикс id) → `classifyFlashcardPagesSnapshot` (8J) → при необходимости `mergeLockedFlashcardsWithPages` (8J) с журналом удалений 7D (`readCardDeletionJournal`, префикс `<target>:saved:`). Пришедшие из облака карточки после удачной записи страниц добавляются в локальный список через `mergeSavedFlashcardsFromAccountsV2` хука (`hooks/use-flashcards.ts`: очередь записи + кэш в памяти, без спиннеров; хук не менялся). Ничего не пришло — пишется локальное как есть (порядок не меняется).
3. Стоимость: **ноль дополнительных чтений Firestore** — переиспользуется существующий `col.get()`. Условие объединения — не `identityMergedAt` (синк документ не читает, отдельное чтение = +1 на такт), а локальный отпечаток (длина + FNV-1a) списка, который ЭТО устройство последним записало для аккаунта (`flashcard_pages_write_fingerprint_v1`, привязан к stableId, не в SYNC_KEYS). Совпал с облаком → объединения нет, журнал не читается, локальные удаления уходят как раньше. Не совпал (сервер 8M, второе устройство, sticky-restore, первый запуск после обновления) → объединение. Отпечаток сохраняется только после удачной записи страниц И удачного добавления в локальное.
4. Страницы прочитаны не с сервера (`from_cache`, `no_metadata`, все страницы битые) или решение упало → страницы не пишутся; ключ ведёт себя как запертый 8J (`lockedNow`: ни страниц, ни поля документа, снимок не запоминает значение; force → отказ `pages_locked`). Сбой самого `get` — путь прежний (doc_fallback 8K).
5. 8H-2/8J/8K не тронуты: подменные `writePages` в тестах крючок игнорируют → поведение прежнее; строка вызова `deps.writePages(uid, target, String(value))`, обе проверки поколения и их структура (сторож `account_authority_legacy_callsite_guard`) сохранены — крючок подставляет обёртка `withPagesPreWrite`. Force: облачные карточки остаются в страницах, локальное не трогается, отпечаток не сохраняется (очередь хука при смене аккаунта ждёт перехода — иначе потолок 8K).
