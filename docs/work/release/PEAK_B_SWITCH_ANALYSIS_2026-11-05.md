# Пик B при серверном rankBy=steps / promotionBonus=100 — разбор по коду HEAD (Моменты, 05.11)

Вердикт: **включать B безопасно.** Правок кода для согласованности со ступенями не нужно: B уже зависит от `rankBy` игры. Единственное, что врёт, — подписи для диктора (см. п. 2).

1. **Топ-5 и «Все участники» (steps).** Строки идут в порядке комнаты (`game.rankBy`), значение в строке — ступени, не монеты (`peak_model.ts:66`, зоны `spireZonesFor(rankBy)` → в steps верхние 15 %, как у сервера). Счётчик «моё» в steps — `spireStepsCount` (`PeakMyCounter.tsx:21`). «Все участники» открывает прежний `SpireAllMembers` с `rankBy={game.rankBy}` и подписью «по ступеням/по монетам» (`SpireHomeScreen.tsx:278,384`).
2. **Что врёт в steps.** Только невидимое: `PeakMyCounter.tsx:19` — подпись диктора всегда «Мои монеты: N» (N = ступени); `PeakTopRow.tsx:28` — подпись строки всегда «N монет» (`weekCoins`), хотя ранжирование по ступеням. Видимые тексты не врут: «5 лучших по монетам» и «+1000 монет» (`peakTour2`) показываются только при `rankBy==='coins'`.
3. **Тур.** Старый `SpireTour` при константе `PEAK_SCREEN_V2_ENABLED=true` скрыт (`SpireHomeScreen`), показывается `PeakTour`. В steps ключи прежние `tour1..3Title/Text` (15 этажей, «место по ступеням», «верхние 15 %»), окна — прежняя раскладка (`peakTourKeys/peakTourHoles/peakTourArrowPage`, `peak_tour_core.ts`), в coins — утверждённые `peakTour1..3` без заголовков. Флаг «тур показан» новый (`story_events_v1:peak_tour:<uid>`): кто видел старый тур, увидит тур B один раз.
4. **Награда/энергия.** «+N монет за повышение» — число сервера (`promotionCoins`), не зашито: при 100 покажет 100. «+1 к запасу энергии» от rankBy не зависит.
5. **Старая сборка 2.0.3 (148) при переключении на coins.** Рубильник `rankBy` и тексты coins (D162/D190, 13–14.10) в ней уже есть (предок бампа 0a6fa48db): ранжирование, зоны и тур покажут монеты согласованно. Нет в ней: «+1 к запасу энергии» и «дошедший до вершины повышается независимо от места» (a45dbea1d, 04.11) — в coins-режиме старый клиент нарисует такого игрока в «остаются», хотя сервер его повысит. Мелочь, без потери данных.
6. **Условие переключения (ложь только при рассинхроне).** `peakTour2` содержит «+1000 монет» зашитым текстом: переключать `rankBy=coins` и `promotionBonus=1000` одновременно. Если сначала coins при бонусе 100 — тур в B скажет 1000, карточка покажет 100.
7. **Включение B.** Это константа `PEAK_SCREEN_V2_ENABLED=true` (`peak_screen_flag.ts:4`), код не меняется; дев-подмена `?state=peak_tour&mode=steps` есть для кадров. Отдельная проверка кадров steps-режима B нужна глазами (тур на 375×667 может перекрыть нижние строки топ-5 — известно, логируется как `overlap`).
8. **Не проверено:** на устройстве B не запускался в этой сессии; выводы — чтение кода и тесты `peak_tour_*`, `spire_peak_screen_v2_*`.
9. **Если захотят чистоту для диктора** (необязательно, после выпуска): подпись счётчика и строки брать по `rankBy` (steps → `spireStepsCount`), две строки правок.
10. **Откат:** вернуть константу в `false` — старый экран и `SpireTour` возвращаются как были.
