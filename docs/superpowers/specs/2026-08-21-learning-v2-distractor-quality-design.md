# Learning V2: строгие task-specific дистракторы

**Дата решения владельца:** 2026-08-21  
**Статус:** design approved in conversation; written-spec review pending  
**Область:** первые 10 сессий урока 1, текущая сессия 11, все будущие сессии всех уроков и активных локалей

## 1. Цель

Каждый неправильный вариант обязан проверять конкретную языковую ловушку текущего
задания. Дистрактор не может быть случайной фразой из той же сессии, механическим
словом из общей категории или грамматически допустимым вторым ответом там, где
проверяется единственная форма.

Одобренные интро и наборы целевых фраз первых 10 сессий не переписываются. Для
них меняются только проекции заданий, дистракторы и связанные объяснения.

## 2. Основной принцип

Дистрактор строится от **проверяемого измерения** и отличается от правильного
ответа одной минимальной контролируемой ошибкой. Чем меньше визуальное и
смысловое расстояние до правильного ответа, тем полезнее ловушка — при условии,
что она остаётся однозначно неправильной для данного prompt и контекста.

Запрещены:

- произвольные первые два элемента из общего `rejectedAnswers`;
- соседние готовые фразы только потому, что они находятся в той же сессии;
- второй грамматически допустимый ответ без контекста, различающего смысл;
- дистракторы из ещё не введённой грамматики;
- одинаковый универсальный набор ловушек для разных механик;
- объяснения вида «тема близкая, но слово другое» без названной ошибки.

## 3. Контракт по типам заданий

### 3.1 Phrase builder и dictation builder

Все лишние плитки относятся к точной конструкции фразы. Подстановка плитки в
наиболее естественную позицию должна давать грамматически или коллокационно
неверную фразу, которая выглядит правдоподобно для невнимательного ученика.

Пример для `Are you tired?`:

- правильно: `Are you tired?`;
- ловушка согласования: `Is you tired?`;
- ловушка лишнего помощника: `Do you tired?`.

`isn’t` и `aren’t` здесь запрещены: они меняют полярность и проверяют другую
конструкцию, а не близкую ошибку сборки нейтрального вопроса.

### 3.2 Context gap grammar

Prompt всегда содержит достаточно смысла, чтобы правильным был ровно один
вариант. Для положительного `Ты счастлив? — ____ you happy?` допустимы `Are`
(правильно), `Is` и `Do` (ложные, но близкие формы). `Aren’t` запрещён, потому
что образует грамматически правильный отрицательный вопрос с другим смыслом.

Автоматический гейт обязан подставить каждый вариант в gap и блокировать:

- более одного грамматически допустимого ответа;
- изменение полярности вместо ошибки формы;
- вариант из грамматики, которая ещё не введена.

### 3.3 Preposition/collocation choice и speed match

Варианты сохраняют всю исходную фразу и меняют только проверяемый предлог или
коллокацию:

- `Are you at home?` — правильно;
- `Are you in home?` — близкая ловушка;
- `Are you on home?` — близкая ловушка.

Фразы `Are you tired?` и `Are you busy?` здесь запрещены: они проверяют значение
всей фразы, а правильный ответ становится очевидным из русского prompt.

### 3.4 Listening и sound contrast

Здесь неправильный вариант может быть грамматически правильным. Он обязан быть
акустическим minimal pair: близкое начало, один изменённый звук/слово/окончание
или одинаковый ритмический каркас. Случайная грамматическая ошибка не заменяет
проверку слуха.

### 3.5 Meaning/vocabulary choice

Здесь неправильный вариант также может быть грамматически правильным. Он обязан
быть близким семантическим соседом той же части речи и той же ситуации. Prompt
должен различать ответы конкретным контекстом, а не позволять угадать по теме.

## 4. Данные и проекция

Каждая карточка получает явное описание проверяемой ловушки:

- `testedDimension`: agreement, auxiliary, order, polarity, preposition,
  collocation, sound, orthography или semantic-neighbor;
- правильный элемент и его точная позиция;
- 2–5 вручную допустимых близких альтернатив;
- локализованную причину для каждой альтернативы во всех восьми локалях;
- границу ранее введённой грамматики.

Проектор выбирает варианты только из этого task-specific набора. Общий каталог
может хранить проверенные пары, но не имеет права самостоятельно подставлять
первые попавшиеся элементы одной широкой группы.

Если для задания нет двух однозначных близких ловушек, сборка возвращает `HOLD`,
а не дополняет варианты мусором.

## 5. Feedback и success

После ошибки текст обязан назвать:

1. выбранный вариант;
2. конкретную уловку;
3. почему она не работает именно в этой фразе;
4. правильный элемент и краткое правило.

Success-текст показывает целевую фразу ровно один раз. Проекция не добавляет
фразу повторно, если редакторское объяснение уже начинается с неё, и не создаёт
сочетание `?.` или `!.`.

## 6. Автоматические гейты

Новый обязательный gate проверяет первые 10, текущую и каждую будущую сессию:

- нет соседнего повтора целевой фразы в success;
- нет двойной пунктуации после готовой фразы;
- phrase builder не получает чужую полярность или произвольную форму;
- grammar gap имеет ровно один допустимый ответ в заданном смысле;
- preposition/collocation task меняет только проверяемый слот;
- speed match не берёт произвольные другие фразы сессии;
- listening использует акустически близкие варианты;
- meaning choice использует одну семантическую категорию;
- каждый неверный response id имеет уникальный локализованный разбор ловушки;
- все варианты находятся внутри curriculum boundary текущей сессии.

Любое нарушение даёт `HOLD`; гейт нельзя ослаблять ради зелёной сборки.

## 7. TDD и проверка макета

RED-фикстуры сначала воспроизводят утверждённые владельцем дефекты:

- `Are you tired?` + лишние `isn’t/aren’t`;
- `____ you happy` с одновременно допустимыми `Are/aren’t`;
- `Are you at home?` рядом с `Are you tired?/Are you busy?`;
- повтор `Are you tired?. Are you tired?` в success.

GREEN-фикстуры требуют:

- `Are / Is / Do` для формы вопроса;
- `at / in / on` внутри одной фразы для предлога;
- ровно одно появление целевой фразы в success;
- точные разные feedback-причины по каждому неверному варианту.

После focused gates пересобирается реальный макет сессии 11. Затем выборочно
проверяются задания первых 10 сессий и все activity families. Сессия 11 остаётся
`AUTO_PASS`, пока владелец не проверит обновлённый интерактивный макет.

## 8. Критерии приёмки

- Все четыре screenshot-дефекта воспроизводятся RED-тестами и исчезают после
  реализации.
- В каждой форме/сборке правильным остаётся ровно один ответ.
- Дистракторы близкие, правдоподобные и проверяют текущую цель, а не соседнюю тему.
- Правило действует на сессии 1–10 без изменения их одобренных интро.
- Тот же gate подключён к обязательному authoring pipeline будущих уроков.
- Реальный макет показывает фактические задания и фактические feedback-тексты.
