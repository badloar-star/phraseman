**Дата:** 2026-06-08
**Объём:** вся воронка конверсии — онбординг → intro-доступ → гейты → пейвол → триал → покупка → аналитика.
**Метод:** чтение исходного кода (4 параллельных аудита), каждое утверждение привязано к `файл:строка`.

## 0. Главный вывод

Технически воронка **зрелая и compliance-чистая** (цены из стора, нет фейковых таймеров/зачёркнутых цен, есть restore/Terms/Privacy, серверный webhook RevenueCat). Но конверсия теряется на **трёх системных уровнях**:

1. **Главный рычаг — free-trial — спрятан почти везде.** Триальный фрейминг показывается ТОЛЬКО при `source==='settings_premium'`. Все 14 контекстных входов показывают полную цену вместо «3 дня бесплатно».
2. **Команда почти слепа к воронке.** Онбординг, intro-модалки и ключевой момент `intro_ended` не трекаются; нет A/B и Remote Config. Невозможно понять, какой гейт конвертит.
3. **Тайминг гейтов бьёт по фрустрации, а не по победе.** 72 часа полного доступа → резкий «обрыв ценности» (14 лимитов включаются разом), а гейты срабатывают в моменты боли (нет энергии, исчерпан лимит), а не гордости.

## 1. КРИТИЧНЫЕ проблемы (исправить в первую очередь)

### 1.1. Триальный UI подавлен на всех контекстных входах — крупнейшая потеря конверсии
- `paywall_trial_offer.ts:4-10` — `shouldShowPrimaryTrialUi` = true только при `forceTrialUI` или `source==='settings_premium'`.
- `premium_modal.tsx:1825-1831` — от этого зависят золотая лента «3 дня бесплатно» (`:3519`), слово «Бесплатно» в карточках (`:3906`, `:4052`), триальная CTA (`:4118`, `:4151-4163`).
- Контекстные входы (`quizzes.tsx:858`, streak, trainer_limit, flashcard_limit …) НЕ передают `source` → стор реально отдаёт триал, а UI показывает полную цену и «🚀 Получить Premium».
- **Фикс:** разблокировать триал-UI по `hasStoreTrial` (реальная intro-фаза в сторе), а не по `source`.

### 1.2. Захардкоженные цены $4.99 / $39.99 в онбординге
- `components/onboarding.tsx:1664` (`$4.99 / месяц`), `:1675` (`$39.99 / год`) — НЕ из RevenueCat.
- Аудитория СНГ увидит `$`, потом другую сумму в RUB в платёжном листе → падение конверсии, рефанды, **риск отклонения ревью Apple (3.1.2)**.
- **Фикс:** брать цены из стора (как в `premium_modal.tsx`).

### 1.3. Онбординг обещает «3 дня бесплатно» безусловно
- `components/onboarding.tsx:1685` — CTA «Попробовать 3 дня бесплатно» захардкожена, без `storeProductHasTrialIntro`.
- Если триал недоступен (уже использован в Apple ID / Google) — обещание без триала, мгновенное списание → жалобы, 1★, **риск ревью 3.1.2**. Главный пейвол это делает правильно, онбординг отстал.

### 1.4. `intro_ended` не входит в `PremiumContext` → фоллбэк на `generic`
- `_layout.tsx:1661` открывает пейвол с `context:'intro_ended'` — это **самый ценный момент** (конец 72ч полного доступа).
- `intro_ended` отсутствует в `PremiumContext` (`premium_modal.tsx:117-144`) → `normalizePremiumContext` (`:268-276`) возвращает `'generic'`.
- Последствия: безликий заголовок вместо «твои 3 дня закончились — вот что теряешь»; триал-UI подавлен (нет source); аналитика пишет `context='generic'` — нельзя выделить сегмент.
- **Фикс:** добавить `intro_ended` как полноценный контекст с собственной копией + персонализацией потерь (твоя серия N, твои 20 карт, твой уровень).

### 1.5. Аналитика воронки дырявая — команда слепа
- `app/analytics.ts` — **мёртвый модуль** с `TODO: заменить на реальный SDK` (`:98`); `trackEvent()` не вызывается нигде.
- **Онбординг (`components/onboarding.tsx`, 4548 строк) — 0 событий**: не виден drop-off по шагам, сколько доходят до planPaywall, сколько жмут «3 дня бесплатно».
- **`IntroFullAccessModal` — 0 событий**: не видно конверсию в момент `intro_ended` (важнейший триггер).
- **Нет `purchase_started`**: drop-off на платёжном диалоге стора не измерим.
- **Webhook RevenueCat** (`functions/src/revenuecat_shards.ts`) не шлёт события в Firebase Analytics → воронка обрывается на `paywall_cta_click`, не смыкается с `INITIAL_PURCHASE`.
- **Нет A/B и Remote Config**: `grep remoteConfig` = 0; RevenueCat Experiments не настроены (`presented_offering_id` не читается). Цены/копи захардкожены в коде.
- **Severity: КРИТИЧНО** — без этого любые улучшения нельзя измерить.

### 1.6. `premium_modal_v2.tsx` — мёртвый «высококонверсионный» пейвол
- Все техники из шапки v2 (social proof first, savings −62%, identity framing, annual default с timer на карточке) **НЕ в проде**. v2 достижим только из `_admin_settings_testers.tsx:2584`.
- Прод-воронка целиком идёт в старый `premium_modal.tsx` (4487 строк).
- **Фикс:** либо смержить лучшие приёмы v2 в live-пейвол, либо завести A/B и катить v2 на трафик.

### 1.7. Выбор плана в онбординге теряется
- `onboarding.tsx:596,1658,1669` — юзер выбирает monthly/annual (`selectedPlanBilling`), но `onPersonalPlanPaywallStart()` вызывается без аргументов (`onboarding.tsx:68,1076`) → выбор отбрасывается, на пейволе план по умолчанию. Разрыв воронки.

## 2. Баланс free/premium и тайминг гейтов

### 2.1. 72ч intro full-access → «обрыв ценности»
- `intro_full_access.ts:10` + `premium_guard.ts:229` — первые 72ч `getVerifiedPremiumAccessStatus()===true`: энергия не тратится, квиз-лимит off, тренажёр без лимита, уроки 9+/smart/diagnosis открыты.
- **Первые 72 часа пользователь не видит НИ ОДНОГО гейта.** Потом 14 лимитов включаются разом — стена.
- **Фикс:** за 12-24ч до конца показывать персональное предупреждение (серия, карты, уроки); после интро вводить лимиты поэтапно. `scheduleUpsellNotifications` (`intro_full_access.ts:56`) уже есть — усилить конкретикой потерь.

### 2.3. Упущенные high-intent (победные) моменты
1. Нет праздничного пейвола после урока 8 на высоком score (момент «я молодец»). Сейчас стена реактивна — на входе в урок 9.
2. Завершение всего free-курса не отмечается достижением + апселл.
3. Streak-milestone (7/14/30) не триггерит апселл на пике гордости — `streak`-пейвол только при `willLose` (`home.tsx:1338`).
4. Smart/diagnosis — 0 бесплатного демо: юзер не знает, за что платит.

### 2.4. Перекосы лимитов
- **Тренажёр 1 сессия/день** (`trainer_session.ts:56-66`) — слишком стингово для SRS (работает на объёме). → 2-3/день + 1 проба smart/diagnosis в неделю.
- **Энергия:** MAX 5, восстановление 10 мин/ед (`energy_system.ts:12-14`) — агрессивнее Duolingo, но восстановление быстрое.
- **NoEnergyModal предлагает только pay/wait** (`NoEnergyModal.tsx:452-500`); осколочный refill (`energy_shard_refill.ts`) реализован, но в модалке не показан; rewarded-ad нет. → лестница «реклама → осколки → Premium» конвертит лучше бинарного «плати или жди».
- **Косметика как primary-гейт** (`theme`/`avatar_aura`) приучает «Premium = декор». → оставить как up-sell внутри Premium-экрана, не как стену.

## 3. Пейвол: упущенные техники (live `premium_modal.tsx`)

- **Нет социального доказательства**: ни рейтинга, ни отзывов, ни счётчика учеников, ни звёзд. Самый дешёвый недостающий рычаг. (Блок «Почему Premium» `:3579-3615` — это личная статистика юзера, не соц-пруф.)
- **Нет savings-бейджа** «Экономия N%» на годовом. Есть только «≈ X/мес» (`:3937-3965`) и слова «самый выгодный план» (`:3980`) без цифры — слабый якорь.

- **Мёртвый код**: disabled-`Modal` под `{false && (...)}` (`:3379-3490`) — дубль exit-trial, риск рассинхрона копий, удалить.
- **`incrementHardPaywallBlock` не вызывается в проде** (`paywall_personalization.ts:47`) → тег `hard_blocks` у реальных юзеров никогда не появится.
- Локализационные опечатки: vi «Dong» вместо «Đóng» (`:3195`), es без диакритики (`:3292`) — не риск ревью.

## 4. RevenueCat / IAP — корректность и утечки

**Сильное:** платформенная проверка ключа (`appl_`/`goog_`); `logIn(canonicalUserId)` + атрибут `phraseman_uid`; Android выбирает `subscriptionOption` с free-фазой (`premium_modal.tsx:2126-2136`); restore робастный; webhook с auth + идемпотентностью (`revenuecat_shards.ts:201-203,404-408`); серверная истина в Firestore; шарды НЕ каннибализируют подписку (тратятся только на расходники/косметику, `shards_system.ts:14-28`).

**Риски:**
- **Тихий сбой `syncRevenueCatIdentity`** (все `.catch(()=>…)`, `revenuecat_init.ts:150-169`): покупка пройдёт под анонимным RC-id, атрибуция в Firestore отсутствует до следующего успешного логина. Если юзер переустановит/сменит устройство в этом окне — cloud-restore премиума не сработает. → добавить фоновый отложенный ретрай логина/атрибутов.
- **`handleChangePlan`/restore требуют успешного identity-синка** (`:2217,2302`): при нестабильной сети СНГ юзер видит «Платежи готовятся» и не может купить/восстановить — точка отказа.
- **`RC_STALE_GRACE_MS` 24ч** (`premium_guard.ts:10,132-140`): допустимый компромисс — макс. утечка 24ч премиума после рефанда; привязан к реальному прошлому подтверждению. ОК.
- **Piracy:** премиум хранится AsyncStorage-first; rooted Android может подделать. При доступном RC перепроверяется. → для масштаба сделать премиум-гейт серверным (Firestore source of truth).
