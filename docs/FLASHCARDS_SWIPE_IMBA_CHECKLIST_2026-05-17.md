# Flashcards Swipe: аудит и чеклист "имба"-версии

Дата: 2026-05-17

## Область аудита

- Вход в раздел: `app/flashcards/FlashcardsCategoryHub.tsx`
- Основной экран: `app/flashcards_swipe.tsx`
- Старый practice-flow внутри коллекции: `app/flashcards_collection.tsx`
- Проверки: TypeScript, ESLint по связанным файлам, Jest по локализации карточек

## Короткий вывод

Раздел уже стал понятнее после упрощения, но до "имбы" ему не хватает продуктовой цельности. Сейчас это скорее отдельный экран с хорошей идеей, чем сильный режим обучения. Главные проблемы:

1. В приложении есть две разные "тренировки карточек": новый swipe-экран и старый typed practice внутри коллекции.
2. Вход в новый режим все еще называется `Swipe-тренировка`, то есть использует технический термин вместо пользовательской пользы.
3. Текущий игровой цикл проверяет recognition: "верный ли перевод?", но почти не развивает active recall: "вспомни сам".
4. Прогресс, возврат ошибок и результат сессии недостаточно объясняют пользователю, что происходит и почему карточка возвращается.
5. Интерфейс пока функционален, но не имеет сильной эмоциональной оболочки: нет режима "я вошел в тренировку", нет ощущения темпа, победы, прокачки, персональности.

## Ресерч: что важно для сильной карточной тренировки

- Anki строит ценность на active recall и spaced repetition: пользователь сначала пытается вспомнить, а система возвращает карточки в нужный момент. Источник: https://docs.ankiweb.net/background.html
- Roediger и Karpicke показывают testing effect: сам факт попытки вспомнить материал улучшает долгосрочное запоминание лучше, чем простое повторное чтение. Источник: https://learninglab.psych.purdue.edu/downloads/2006/2006_Roediger_Karpicke_Review.pdf
- Nielsen Norman Group: интерфейс должен снижать нагрузку на память, показывать видимые действия и говорить языком пользователя. Источник: https://www.nngroup.com/articles/ten-usability-heuristics/
- NN/g про touch/gesture-интерфейсы: пользователи не понимают, что элемент можно трогать, если он не выглядит интерактивным; инструкции должны быть короткими и появляться в нужный момент. Источник: https://media.nngroup.com/media/reports/free/iPad_App_and_Website_Usability_2nd_Edition.pdf
- Material Design: touch targets должны быть минимум 48x48 dp, состояние и контраст важны не только для accessibility, но и для обычной уверенности пользователя. Источник: https://m1.material.io/usability/accessibility.html
- Duolingo: удержание растет, когда барьер ежедневного действия низкий; ошибки не должны чувствоваться как наказание, особенно для новичков. Источники: https://blog.duolingo.com/improving-the-streak/ и https://blog.duolingo.com/duolingo-energy/

## Аудит текущего состояния

### Что уже хорошо

- На `app/flashcards_swipe.tsx` есть понятный основной вопрос: "Это правильный перевод?"
- Есть видимые кнопки "Нет" и "Да", поэтому swipe не является скрытым обязательным жестом.
- Наборы теперь выбираются по умолчанию, стартовая трение ниже.
- Есть озвучка английского слова.
- Есть повтор карточки после ошибки или открытого ответа.
- Экран поддерживает saved, custom, official и community источники.

### Что ломает ощущение продукта

- В хабе CTA все еще называется `Swipe-тренировка` (`app/flashcards/FlashcardsCategoryHub.tsx`). Для обычного пользователя это термин про жест, а не про пользу.
- Старый режим `mode === 'practice'` в `app/flashcards_collection.tsx` называется просто "Тренировка", но работает как typed recall. Это создает две разные ментальные модели.
- В `flashcards_swipe` выбор источников выглядит как настройка перед тестом. Для массового пользователя лучше "Начать быструю тренировку" и настройка вторым слоем.
- Сессия показывает прогресс через mastered, а не через "сколько действий сделал". Если карточка возвращается, пользователь может почувствовать, что прогресс застрял.
- После ошибки не объясняется петля: "Эта карточка вернется позже, чтобы закрепить".
- Итоговый экран слишком сухой: карточек, ошибок, повторить. Нет "что стало лучше", нет next best action.
- Нет first-run обучения на 1 экран: "смотри перевод -> Да/Нет -> если ошибся, карточка вернется".
- Нет режима выбора цели: "Быстро проверить", "Выучить слабые", "Вспомнить самому".

### Риски в текущей логике

- Recognition-only режим может быть легким и приятным, но недостаточно обучающим как единственный режим.
- Случайные decoys из общего pool могут быть слишком очевидными или слишком странными. И то, и другое портит доверие.
- Forced match после feedback полезен педагогически, но без объяснения выглядит как повтор той же карточки без причины.
- При большом количестве паков auto-select all может создать слишком широкий и шумный набор. Нужен "умный дефолт": due + recent + слабые.
- В старом typed practice нет общей связки со swipe-прогрессом, smart trainer и карточной статистикой.

### P0. Первый экран и старт

- [ ] Убрать ощущение "настройки перед экзаменом": главный CTA должен быть выше списка наборов.
- [ ] Показать короткую формулу:
  - `Слово`
  - `Перевод`
  - `Да / Нет`
- [ ] Добавить first-run micro-demo на первой карточке, не отдельный tutorial:
  - подсветить "Да";
  - подсветить "Нет";

- [ ] Сохранить "свайп" как shortcut, но не продавать режим через слово swipe.
- [ ] Если карточек мало, не показывать выбор размера сессии. Просто `Начать 7 карточек`.

### P0. Игровой экран

- [ ] Главный вопрос всегда рядом с карточкой: `Это правильный перевод?`
- [ ] Карточка должна иметь сильную иерархию:
  - английское слово крупно;
  - транскрипция/звук рядом;
  - перевод в отдельной спокойной зоне;
  - никаких pack labels на карточке по умолчанию.
- [ ] Кнопки `Нет` и `Да` сделать нижней "thumb zone" панелью, 64-72 dp высотой.
- [ ] Цвета: `Нет` и `Да` должны отличаться не только цветом, но и иконкой, текстом и формой состояния.
- [ ] Добавить swipe affordance:
  - маленькие стрелки под карточкой;
  - ghost labels `свайп влево` / `вправо` только первые 2-3 карточки;
  - потом скрыть.
- [ ] Прогресс разделить:
  - `4/20 просмотрено` для ощущения движения;
  - `12 закреплено` можно показывать на итогах, не в активной зоне.
- [ ] При ошибке показывать не "не засчитано", а обучающий разбор:
  - `Нет, это был неверный перевод`;
  - `Правильно: ...`;
  - `Вернем позже`.
- [ ] После "Показать ответ" не наказывать визуально, а показывать `Ок, посмотрели. Сейчас закрепим`.

### P0. Learning loop

- [ ] Ввести состояния карточки: `new`, `seen`, `wrong`, `hinted`, `recovered`, `mastered`.
- [ ] После ошибки возвращать карточку через 3-5 карточек и явно объяснять это один раз.
- [ ] После подсказки требовать 1-2 правильных ответа для mastered.
- [ ] Для easy correct убирать карточку из текущей сессии.
- [ ] Для repeated wrong переводить карточку в мини-урок:
  - пример;
  - literal meaning;
  - usage note;
  - еще одна проверка.
- [ ] Добавить "Не знаю" как отдельное действие в режимах active recall, чтобы пользователь не угадывал.
- [ ] Decoys выбирать умнее:
  - похожая часть речи;
  - похожая длина;
  - тот же pack или тема;
  - не использовать пустые/слишком длинные переводы;
  - не брать почти идентичные переводы.

### P1. Вау-функции

- [ ] Daily quick review: 10 карточек, 90 секунд, всегда одна кнопка в хабе.
- [ ] "Слабые карточки": отдельный режим по ошибкам, hints и long interval.
- [ ] "Перед сном": 5 самых важных повторов, низкая яркость, мягкая анимация.
- [ ] "Speed run": таймер, комбо, но без наказания за ошибку.
- [ ] "Listen first": сначала звук, потом слово и перевод.

- [ ] "Сохранить слабую в избранное" или `закрепить`.
- [ ] "Почему я ошибся?": быстрый выбор причины: похожее слово, забыл, не знал, перевод странный.
