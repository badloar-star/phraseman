# AVATAR STUDIO — конвейер ассетов кастомизатора (2.5D whole-render)

Самодостаточный пайплайн: любой ИИ (ChatGPT, Gemini, Claude, Midjourney…) по этим
файлам генерирует детали аватара, которые ТОЧНО встают в кастомизатор приложения —
без «уехавших» поз, вылезших аксессуаров и чужих фонов. Любая сессия любого ИИ
продолжает работу отсюда.

## Зачем так (история)

Раньше ассеты генерились свободными запросами — получалась «дичь»: пучок волос
уезжал вверх-влево, за спиной проступал чужой фон, маттинг выбивал дырки в
волосах. Причина: не было канона кадра и машинной приёмки. Теперь есть оба.

## Три закона конвейера

1. **Паспорт кадра — закон.** `frame_passport.v1.json`: холст 1024×1280, фон
   `#F7EFE4`, линия зрачков на 38% высоты, центр лица на 50% ширины, высота
   головы 42% холста, безопасные поля. Каждая картинка каталога стоит в этих
   долях.
2. **Только edit эталона.** Новая деталь = правка базового рендера
   (`base/base_m.png` — мальчик, `base/base_f.png` — девочка), НИКОГДА не
   свободная генерация с нуля. Меняется ровно одна вещь, остальное — пиксель в
   пиксель. Цвета волос/одежды — перекрасом скриптом, не генерацией.
3. **FAIL не существует.** Ассет попадает в каталог только через
   `scripts/check_render.mjs` → PASS. Проверку не ослаблять, кривое не принимать
   «на глаз».

## Карта папки

| Путь | Что это |
|---|---|
| `frame_passport.v1.json` | числа канона: холст, якоря, поля, lock-зоны, матрица P0 |
| `prompts/*.md` | готовые промпты на каждый тип детали — копируй в чат ИИ |
| `base/` | эталонные рендеры `base_m.png`, `base_f.png` (создаются 1 раз, SHA в манифесте) |
| `guides/guide_1024x1280.png` | сетка-подсказка (линия зрачков, поля) — можно прикладывать в чат |
| `inbox/` | сюда скачиваешь кандидатов из генератора |
| `catalog/<слот>/` | принятые ассеты (только через PASS) |
| `manifest.json` | реестр каталога: id, слот, SHA-256, дата |
| `scripts/check_render.mjs` | сторож-приёмщик: PASS/FAIL с причинами, `--accept` кладёт в каталог |
| `scripts/make_guide_overlay.mjs` | перегенерация сетки из паспорта |

## Рабочий цикл (каждый новый ассет)

1. Открой нужный промпт из `prompts/` (одежда → `outfit.md`, причёска →
   `hair.md`, глаза → `eyes.md`, аксессуар → `accessory.md`, головной убор →
   `headwear.md`, тон кожи → `skin_tone.md`, эмоция → `emotion.md`).
2. В чат ИИ приложи **базовый рендер** нужной базы (`base_m.png`/`base_f.png`) и
   вставь промпт, подставив название вещи в `{{ITEM}}`.
3. Скачай результат (PNG 1024×1280) в `inbox/`.
4. Проверь:
   ```
   node content/avatar-studio/scripts/check_render.mjs content/avatar-studio/inbox/файл.png --slot outfit --base content/avatar-studio/base/base_m.png
   ```
   PASS → прими в каталог тем же вызовом с `--accept --id outfit_leather_m`.
   FAIL → в отчёте написано, что не так; в конце каждого промпт-файла есть
   готовые фразы-исправления для повторной генерации.
5. Готово: ассет в `catalog/`, запись в `manifest.json`. Приложение берёт только
   из каталога.

Первый запуск: базовых рендеров ещё нет → начни с `prompts/base_render.md`
(создание `base_m.png` из утверждённого референса-парня и `base_f.png` из
феминного референса).

## Правила для ИИ-ассистента, который это читает

- Прочти этот файл и `frame_passport.v1.json` ПЕРЕД любой работой с ассетами.
- Не выдумывай свои промпты с нуля — бери шаблон из `prompts/` и подставляй вещь.
- Не перегенерируй `base/*.png`: замена эталона = отдельное решение владельца
  (все ассеты каталога сверяются с ним попиксельно).
- Не клади файлы в `catalog/` руками и не правь `manifest.json` руками — только
  `check_render.mjs --accept`.
- Слоёную композицию (вырезанные волосы поверх портрета) НЕ предлагать — путь
  отвергнут владельцем; только цельные рендеры.
- Проверка упала — чини картинку (перегенерацией), а не сторожа.

## Матрица P0 (утверждена владельцем 2026-08-22)

Две базы (мальчик `base_m`, девочка `base_f`) × 6 причёсок × 4 цвета волос
(перекрасом) × 6 одежд × капюшон × 3 тона кожи × 6 эмоций (`smile`, `joy`,
`surprise`, `sad`, `determined`, `wink`). Генераций ~44–50, остальное — скрипты.
