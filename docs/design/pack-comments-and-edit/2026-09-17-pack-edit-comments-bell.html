Правки набора без очереди · комментарии · колокольчик

Три вещи в одном макете: автор правит опубликованный набор сразу, без модерации; любой добавивший набор может оставить отклик и пожаловаться на конкретный комментарий; автор узнаёт о новом отклике колокольчиком и попадает прямо к нему одним тапом.

1Редактирование опубликованного набора — без очереди на проверку

Решение владельца 17.09: правки публикуются сразу — название, описание и все карточки. Сейчас на сервере такая правка уходит в community_pack_submissions со статусом update_pending и ждёт модератора; набор при этом остаётся опубликованным со старым содержимым. По новому решению сервер применяет правку к community_packs/{'{packId}'} сразу, без промежуточного статуса.

3Колокольчик: новый комментарий → сразу к нему, без промежуточных экранов

Новый тип уведомления pack_comment в существующей модели UserNotification (app/user_notifications.ts) и в NotificationCenterButton.tsx. Уходит только автору набора (решение владельца). Тап — не роутер на отдельный экран, а прямое открытие набора со сразу поднятой шторкой комментариев и подсветкой нужной строки, по аналогии с тем, как friend_event сегодня открывает /(tabs)/friends с параметром focusFriend.

ЧастьСтатусЧто делать
Модель отклика + Firestore-слой готово packComments.ts, packCommentsFirestore.ts — используются как есть
Счётчик «💬 N» с тапом готово CommunityPackSocialBar уже принимает onOpenComments — нужно подключить обработчик

Удаление комментария автором новое Существующая deletePackComment в packCommentsFirestore.ts — добавить серверную проверку прав (автор комментария ИЛИ автор набора)
Уведомление в колокольчик новое Новый тип pack_comment в UserNotification; Cloud Function на запись комментария пишет в users/{'{authorStableUid}'}/notifications
Deep-link к комментарию новое nav: { kind: 'pack_comment', packId, commentId } → router.push на экран набора с параметрами, экран открывает шторку и подсвечивает строку — по образцу focusFriend/socialEventId у friend_event

Что стоит обсудить отдельно

Правки без модерации — это снятие существующей защиты. Сейчас communitySubmitPackForReview с updatePackId специально уходит на повторную проверку (комментарий в коде датирован 2026-09-04): владелец набора мог бы заменить безобидные карточки на неприемлемый контент уже после того, как набор прошёл модерацию и получил лайки/добавления. При мгновенной публикации это становится возможным без единой проверки человеком. Раз решение — публиковать сразу, стоит держать хотя бы: (а) серверную проверку на стоп-слова в тексте карточек при сохранении, (б) видимость «изменено» в списке для админки задним числом, чтобы жалобу можно было быстро сверить с историей правок.
  • Приватность. Тексты комментариев и жалобы на них — то же обязательство, что уже отмечено в исходном прототипе комментариев: абзац в политике о новом виде пользовательских данных и их удалении вместе с аккаунтом.
  • История правок набора. Без модерации у владельца пропадает список «на проверке» — стоит решить, нужен ли автору набора простой лог «когда в последний раз менял», отдельно от админки.
