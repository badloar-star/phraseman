## Outcome

Владелец выигрывает приз в спине или получает награду в Ежедневном пути — и
**видит результат немедленно, без захода в раздел «Подарки» и без перезахода в
раздел**:

- руны, жемчужины, опыт, звёзды — падают на счёт в момент выигрыша, индикатор
  растёт мгновенно, с анимацией прилёта;
- спины — сразу увеличивают счётчик, золотая кнопка появляется без перезахода;
- энергия и предметы с длительностью (щит серии, ×2 опыта, подсказки, Второй
  шанс, Plus-дни) и косметика — **остаются** в «Подарках» и применяются по
  желанию; при применении энергии играет анимация наполнения шкалы.

Мера успеха: после спина на руны счётчик в шапке изменился до того, как владелец
куда-либо перешёл; в разделе «Подарки» плитки на валюту/спин больше не
появляются.

## Architecture

Текущая граница: спин **никогда** не применяет приз. `level_reward_spin.tsx:186-189`
пишет запись в журнал `LEVEL_SPIN_GIFT_JOURNAL_KEY`, приз становится плиткой в
`level_gifts_inventory.tsx` и применяется только тапом через `applyGift`
(`level_gift_system.ts:3395`). Это закреплено сторожем
`tests/level_reward_spin_finish_line_contract.test.ts:182` («keeps the spin result
pending for the Gifts inventory instead of auto-applying it»).

Готовая функция автовыдачи `applyLocalLevelSpinRewardExactlyOnce`
(`app/local_level_spin_auto_delivery.ts:27`) существует, покрыта тестами, но
**намеренно не подключена** — тот же сторож запрещает её импорт.

Целевая граница: каталог приза получает признак канала доставки —
`instant` (валюта, спины: применяется в момент выигрыша) против `inventory`
(энергия, предметы с длительностью, косметика: ждёт тапа). Спин вызывает
автовыдачу только для `instant`.

Инвариант, который нельзя нарушить: **приз начисляется ровно один раз.**
Защита уже есть — `readLevelSpinGiftOccurrenceClaimState` +
`markLevelSpinGiftOccurrenceClaimed` + `confirmDeferredLocalLevelGiftEffectReceipt`.
Автовыдача обязана проходить через тот же протокол, а не в обход.

Решение: прежнее правило «всё через инвентарь» **отменяется владельцем
2026-09-17**. Сторож переписывается под новое поведение, а не удаляется.

## Security and privacy

Личные данные не затрагиваются: меняется канал доставки уже начисляемых наград.
Начисление остаётся идемпотентным по `occurrenceId`, привязка к аккаунту через
`isCurrentAccountGeneration` сохраняется во всех новых путях — иначе поздний
ответ может начислить приз чужому аккаунту после переключения (известный класс
бага в проекте). Privacy policy правки не требует: новых полей, сервисов и
разрешений нет.

## Technical debt

- **Pay now**: немой `catch {}` в `local_level_spin_auto_delivery.ts:74` —
  глушит провал выдачи приза целиком. Плюс немые `catch` на путях, которые
  участвуют в новой мгновенной доставке.
- **Contain**: остальные из 38 немых `catch` в файлах подарков — закрыть
  трассировкой с единым префиксом `[GIFT-DELIVERY]`, оставить логи навсегда
  (правило владельца), выход — ноль немых `catch` в этих файлах.
- **Accept temporarily**: три параллельных механизма оповещения UI
  (`events.ts` / `app_snapshot_store` / сырой `DeviceEventEmitter` в
  `EnergyContext`). Владелец: сессия аудита. Ревью: при следующей работе с
  энергией. Потолок: не добавлять четвёртый механизм.

## Rollback

Все правки — один коммит на ветке `feature/referral-roulette`. Откат: `git revert`
этого коммита; журнал `LEVEL_SPIN_GIFT_JOURNAL_KEY` и протокол occurrence не
меняются по формату, поэтому уже выданные призы остаются корректными в обе
стороны. Файлы Арены не затрагиваются.
