# «Следующий урок»: платящий не видит пейвол при холодном кэше (Ревизор по 31029c044, 15.10, 🔴)

Governance-ID: TG-022C6790661C

## Outcome
Быстрая проверка доступа без облака (`allowCloudRefresh:false`) клала в кэш памяти `false` при холодном кэше; запасная проверка брала этот `false` (TTL 5 мин) и не шла в облако — платящий видел пейвол на уроке 4+ после «Следующий урок». Тот же `false` клала проверка при открытии экрана итога. Правило: пейвол — ТОЛЬКО при подтверждённом «нет».

## Scope
Новый `app/lesson_next_access.ts` (решение), `app/lesson_complete.tsx` (подключение патчем от HEAD: контекст Plus, сброс кэша, потолок 4 с; сброс холодного false при открытии экрана), тесты `lesson_next_access` и `lesson_complete_r58_taps_contract`.

## Architecture
`resolveNextLessonAccess({needsPremium, contextPremium, prepare, verify, timeoutMs})`: бесплатный урок или Plus в контексте → открыть сразу; иначе `prepare` (сброс кэша доступа в памяти) → полная проверка с облаком, но не дольше 4 с (кнопка «занята» — `primaryBusy`); ответ «Plus» → открыть; подтверждённое «нет» при контексте не-Plus → пейвол; нет ответа или сбой → открыть без пейвола (замок урока решает на входе).

## Security and privacy
Данные не затрагиваются; доступ к платным урокам по-прежнему защищает замок на входе в урок.

## Technical debt
Выдача доступа не меняется; только когда показывать пейвол.

## Verification
Юнит-тесты: холодный кэш + платящий → урок открывается, пейвола нет; подтверждённое «нет» → пейвол; таймаут и сбой → без пейвола; контекст Plus → без проверки.
