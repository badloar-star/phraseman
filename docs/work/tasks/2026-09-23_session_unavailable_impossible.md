# Task packet: «Сессия недоступна» становится структурно невозможной

Governance-ID: TG-EA8236B1F82A
Status: In progress
Owner: сессия Claude Opus 5, 2026-09-23
Related epic/enabler: none

## Outcome

Владелец на телефоне видел экран «Сессия недоступна» с причиной
`learning_v2_session_ready_handoff_missing` и двумя кнопками, одна из которых
(«Повторить») не может сработать НИКОГДА. Требование дословно: «сделай такое
состояние невозможным».

Наблюдаемый результат: в боевом режиме этот экран не появляется ни при каком
сценарии. Успех измеряется отсутствием `[V2-SESSION] unavailable:shown` в
журнале при репро «открыть занятие → закрыть → назад с карты».

Побочный, но более опасный результат: то же переигрывание адреса **повторно
списывало энергию** — после правки второго списания нет.

## Scope

В объёме:
- `app/navigation_back.ts` — маршрут занятия исключается из целей «назад»;
- `app/learning_v2_direct_session_player_v1.tsx` — выход помечается как replace;
  боевой тупик заменяется уходом на карту; «Повторить» только в dev-превью;
- `app/learning_v2_course_released_session_client_v3.ts` — мост перестаёт быть
  одноразовым, оба немых `return null` называют причину.

Вне объёма (правятся ДРУГОЙ сессией — не трогать):
- `app/(tabs)/lessons.tsx`;
- `app/learning-v2/session/[id].tsx`.

Вне объёма сознательно: экран занятия НЕ начинает готовить материал сам
(вариант отклонён, см. Architecture).

## Architecture

Текущая граница: материал занятия передаётся с карты на экран через
одноразовый мост в памяти модуля (`Map`, лимит 8, запись **удаляется при
чтении**, ключ — `sessionRunId`). Боевой экран намеренно не умеет готовить
материал сам. Следствие: маршрут можно открыть «по адресу» повторно, а его
содержимое к этому моменту уже съедено → тупик.

Целевая граница: три слоя, ни один не сетевой.

- **A. Адрес занятия не переигрывается.** Маршрут `/learning-v2/session`
  объявлен одноразовым и пропускается в `popBackCandidate`/`safeTarget`.
  «Назад» с карты садится на запись ПОД занятием при любом стиле выхода —
  нынешнем и будущем, без правки экранов.
- **B. Мост терпим к повторному чтению.** `consume` сравнивает
  `courseSessionId` ДО мутации и не удаляет запись. Ключ остаётся
  `sessionRunId`: сводка аудио, леджеры энергии и наград привязаны к нему,
  ключевание по `courseSessionId` развело бы идентификаторы.
- **C. Тупика нет.** Если моста всё же нет, экран не показывает ошибку, а
  уходит на карту — единственный законный подготовитель. Флаг выхода уже
  заставляет рендер рисовать пустой кадр в цвет темы.

Отклонённый вариант: экран сам зовёт `prepareCurrentLearningV2CourseSessionV3`.
Запрещено сторожем `learning_v2_session_route_zero_loading_frame_contract`
(подготовка не мгновенна — парсинг плюс хэш-проверка каждого MP3; карта прячет
её за анимацией модалки, экран спрятать не может → видимый кадр ожидания,
запрещённый Performance Bible). Для `es/de` добавил бы сетевой вызов на каждое
переигрывание.

Инвариант, который нельзя нарушить: `rememberNavigationPath` по-прежнему
создаёт запись занятия — иначе сломается `safeRouterBack` ИЗ самого занятия.

## Security and privacy

Не применимо. Правка не трогает аутентификацию, авторизацию, секреты,
персональные данные и детскую безопасность. Ни одного нового сетевого вызова,
ни одного нового поля данных. Privacy Policy не затрагивается: состав
собираемых данных не меняется.

## Technical debt

- **Pay now.** Два немых `return null` в `consume` — обе ветки получают
  причину в логе.
- **Pay now.** Кнопка «Повторить» в боевом режиме не имела успешного исхода —
  скрыта вне dev-превью.
- **Contain.** Doc-комментарий моста обновлён с «one-shot» на фактическое
  поведение: иначе следующая сессия «починит» обратно.
- **Accept temporarily.** Сторож `learning_v2_direct_intro_gate_contract`
  красный ДО этой правки (лимит длины против факта). Владелец: следующая
  сессия по Learning V2. Потолок влияния: контракт моста не охраняется
  автоматически. Чинить надо регулярку, а не растягивать лимит. В этот объём
  не входит.

## Verification

На этом ПК запрещены jest, tsc и эмулятор (прямое указание владельца), поэтому
проверка — детерминированным чтением кода:

1. `rememberNavigationPath` не изменён — запись занятия создаётся.
2. `popBackCandidate` снимает `leaving` ДО цикла — выход из самого занятия
   работает как раньше.
3. `isNonBackTargetPath` НЕ изменён — он влияет на `paywallDismissShouldReplace`.
4. В плеере не появилось ни `prepareCurrentLearningV2CourseSessionV3`, ни слова
   «Подготавливаем» — сторож `zero_loading_frame` остаётся зелёным.
5. `stage` остаётся единственным местом удаления записей моста.
6. `exitLearningV2Session` объявлена ВЫШЕ эффекта, который её использует
   (класс бага «имя в deps выше объявления» не воспроизводится).

Живая проверка владельцем на следующей сборке: открыть занятие, закрыть
крестиком, нажать «назад» с карты. Ожидается выход из раздела, без экрана
ошибки и без второго списания энергии. Артефакт: `grep [V2-HANDOFF]` и
`grep [V2-SESSION]` по `.expo/metro-console.log`.

## Rollback

Откат — обратные правки трёх файлов, данные не мигрируют и не теряются.
Каждый слой снимается независимо:
- слой A — убрать `ONE_SHOT_SESSION_PATHS` и два условия;
- слой B — вернуть `readyHandoffs.delete` в `consume`;
- слой C — вернуть `setLoadFailed(true)` вместо ухода на карту.

Прав и покупок правка не касается, поэтому откат не может отобрать уже
выданное право. Энергия при откате снова начнёт списываться дважды — это и
есть исходный дефект.
