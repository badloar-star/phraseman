## Как устроен перенос

- **Соответствие:** прямой индекс. Медная 0 → Гранит 0, Бронзовая 1 → Базальт 1 …
  Эфирная 10 → Обсидиан 10, Высшая 11 → Алмаз 11. Значение вне 0–11 прижимается к краю
  и помечается в копии (`clamped`).
- **Когда:** лениво, при первом `spireJoinRoom` человека. Крона по всей базе нет:
  «текущий язык» живёт только на устройстве (`study_target_v1` в AsyncStorage, в облако
  не синкается), массовый крон его не знает. Плюс экономия: одна транзакция на человека
  один раз, только у тех, кто открыл Шпиль.
- **Язык:** место лиги — в шпиль `currentStudyTarget` из запроса; если клиент его не
  прислал — в язык комнаты, которую человек открыл (`currentLangSource: 'room_lang'` в
  копии). Остальные три языка — Гранит (0).
- **Источник места лиги** (порядок доверия):
  1. `leaderboard.leagueId` (пишет только сервер), если человек уже в комнате лиги этой
     недели;
  2. то же + итог прошлой недели `league_week_results`, если он подведён и согласован
     (повышение/понижение прошлой недели не теряется) — проверка как у
     `resolveAuthoritativeLeagueId` лиги;
  3. `leaderboard.leagueId` как есть;
  4. `progress.league_state_v3` — только если в leaderboard нет leagueId вовсе;
  5. ничего — Гранит.
  Расхождения источников пишутся в копию (`conflicts`), решение не меняют.
- **Понедельник до итога лиги** (15 мин после полуночи UTC, итога нет) — отказ
  `league_finalization_pending`, клиент повторит. Устаревшее место не переносится.
- **Уже записанный шпиль** (итог недели PM-276) миграция не перезаписывает.
- **Повторный вход** — отметка уже стоит, ноль дополнительных чтений.

## Чего миграция НЕ трогает

`leaderboard.leagueId`, `groupId`, `groupWeekId`, коллекцию `league_groups`,
`users/{uid}/league_week_results`, `progress.league_state_v3`. Лига продолжает работать
как работала. Это главный элемент плана отката: возвращать в старую лигу нечего —
место лиги никуда не девалось.

## План отката

1. **Остановить перенос:** `adminSpireLeagueMigrationSetMode({mode:'paused', reason})`.
   Новые входы в Шпиль у ещё не перенесённых честно отказывают
   `spire_migration_paused` (не садят в Гранит без места). Уже перенесённые играют дальше.
2. **Посмотреть:** `adminSpireLeagueMigrationRollback({all:true, reason})` — по умолчанию
   dryRun, возвращает план по каждому человеку (страница ≤200).
3. **Откатить:** тот же вызов с `dryRun:false`, повторять пока `hasMore=true`. По одному
   человеку — `{uid, dryRun:false, reason}` (работает и без паузы: при следующем входе
   перенос пройдёт заново — так чинится «не тот язык»).
4. **Что делает откат:** по копии `spire_league_migration/{uid}` возвращает
   `leaderboard.spireTiers` к состоянию «до» и снимает отметку. Язык откатывается,
   только если его шпиль не менялся после переноса; если итог недели Шпиля уже поднял
   или опустил человека — это значение остаётся и попадает в `changedSinceMigration`
   (решает владелец). Копия не удаляется, а помечается `rolledBackAtMs`; каждое
   действие — запись в `admin_log`.
5. **Что откат НЕ делает:** не перекладывает человека из комнаты текущей недели
   (`spire_groups`). Комната недели закреплена первым входом; новый шпиль начнёт
   действовать со следующей недели.
6. **Код:** откатывается обычным git revert — данные пользователей не теряются
   (лига не тронута, копии остаются).

**Условие для удаления Лиги (не в этой задаче):** не удалять `leaderboard.leagueId`,
`league_groups` и `league_week_results`, пока владелец не подтвердил, что перенос прошёл
правильно (предложение — хранить минимум 4 недели после запуска Шпиля). Иначе откату
не на что будет опереться.

## Открытые вопросы владельцу

- **О1 (из TOWER.md §8, ещё не подтверждён).** Место лиги — только в шпиль текущего
  языка, остальные с Гранита. Реализовано по рекомендации; нужно «да».
- **О-278-1. Какой язык «текущий».** Сервер его не знает — только устройство. Сделано:
  клиент шлёт `currentStudyTarget` в `spireJoinRoom` (подключить в PM-279), без него
  берётся язык первой открытой комнаты. Если у человека два устройства с разными
  языками — выиграет то, с которого он первым вошёл в Шпиль. Устраивает?
- **О-278-2. Момент запуска.** Переносится место лиги на момент первого входа в Шпиль.
  Очки незавершённой недели лиги не учитываются, а если лига продолжит работать
  параллельно, её более поздние повышения в Шпиль не попадут. Рекомендация: запустить
  Шпиль в понедельник после итога лиги и в тот же момент остановить кроны лиги.
- **О-278-3. Запасной источник.** Если в `leaderboard` нет leagueId, берётся
  `progress.league_state_v3` — его синкает клиент (теоретически можно подделать один раз
  и получить высокий шпиль). Альтернатива — таким людям Гранит. Сейчас: доверяем, чтобы
  не потерять место; каждое такое решение помечено `progress_fallback` в копии.
- **О-278-4. Пауза блокирует вход.** На паузе не перенесённые люди не могут войти в
  Шпиль (честный отказ), чтобы никого не посадить в Гранит без места. Альтернатива —
  пускать в Гранит без переноса. Какой вариант?
- **О-278-5. Переводы имён камней** в 8 локалях — предложение без проверки носителем.
