# ThemeContext: бюджет перерисовок при смене темы и на пустом рендере

Governance-ID: TG-CD7D3A79DC54

## Outcome
Координатор 22.10: замерить, сколько компонентов перерисовывается при смене темы и на первом кадре из-за ThemeContext; лог [THEME-PERF]; если контекст отдаёт новый объект на каждый рендер или одна смена дёргает всё дерево лишний раз — оптимизировать, не меняя вид; цифры до/после и хэш.

## Scope
In scope: замер на живых логах эмулятора ([THEMES-PERF], уже стоит в ThemeContext с 15.10), сторож бюджета `tests/theme_context_render_budget.test.tsx` (пустой рендер родителя не будит подписчиков; одна смена темы = не больше двух рендеров подписчика; повтор той же темы = 0).
Out of scope: подписчики-экраны (число подписчиков задаёт приложение), внешний вид.

## Architecture
Значение контекста уже собирается через `useMemo` с устойчивыми зависимостями: все колбэки (`setLiquidGlassThemeId`, `setLiquidGlassAppearance`, `setLiquidGlassIntensity`, `releaseDevOverrides`, …) на `useCallback`, тема строится `useMemo` по `[liquidGlassThemeId, variant]`, `variant` — `useMemo`. Менять нечего; сторож закрепляет это, чтобы будущая правка не пустила объект в зависимости на каждый рендер.

## Security and privacy

## Technical debt
Цена смены темы в основном определяется числом смонтированных подписчиков (135 при массовой смене в холодном дереве, 5 в прогретом); сократить его можно только на экранах (заморозка невидимых вкладок), это отдельная работа Ядра.
