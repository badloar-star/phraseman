# 🚦 СВЕТОФОР ПАРАЛЛЕЛЬНЫХ СЕССИЙ

Владелец запускает 10+ сессий Claude/Codex на одном ПК одновременно.
23.08.2026 машина вылетала: одновременно жило **39 процессов node/claude**.

Светофор нужен, чтобы сессии работали ВМЕСТЕ, а не против друг друга.

## Правило в одну строку

**Перед тяжёлой работой возьми слот. Слотов всего 3. Нет слота — жди или делай лёгкое.**

## Что считается ТЯЖЁЛЫМ (нужен слот)

- запуск субагентов (Agent tool) — любое количество
- `npx jest` / любой прогон тестов
- `npx tsc` / полная типизация
- сборка, `expo`, Metro, EAS
- массовый grep/find по всему репозиторию
- Workflow (мультиагентные воркфлоу)

## Что ЛЁГКОЕ (слот НЕ нужен)

- чтение файлов, точечный grep по 1-2 файлам
- правка файла
- git status / add / commit
- разговор с пользователем

## Как взять слот

```bash
bash .claude/semaphore/slot.sh acquire "что делаю"
```

Ответ `GO` — работай. Ответ `WAIT` — слот не дали:
делай лёгкую часть задачи, попробуй позже, ИЛИ сообщи владельцу,
что ждёшь очереди.

## Как отдать слот (ОБЯЗАТЕЛЬНО)

```bash
bash .claude/semaphore/slot.sh release
```

Отдавай СРАЗУ как закончил тяжёлое — не держи слот во время разговора.

## Посмотреть светофор

```bash
bash .claude/semaphore/slot.sh status
```

## Не пошёл дальше при WAIT (15.10.2026)

`acquire` при отказе печатает строку, начинающуюся с `WAIT`, и выходит с кодом **1**: цепочка
`slot.sh acquire "зачем" && npm run test:one -- …` сама остановится. Но `;`, `|` и `grep -q '^GO'`
код выхода теряют — для тяжёлого используй обёртку:

```bash
bash .claude/semaphore/slot.sh run "зачем" -- npm run test:one -- tests/<файл>.test.ts
```

`run` ждёт слот (по умолчанию до 600 с, `--wait=СЕК` — своё), НЕ запускает команду, если слот не дали (код 1),
продлевает слот раз в 60 с, пока команда жива (прогон дольше 15 минут больше не теряет слот), отдаёт слот
и возвращает код самой команды. Остальное: `acquire --wait[=СЕК] "зачем"` (ждать до GO), `renew` (продлить вручную).

**ID сессии.** Слот называется по `PM_SESSION_ID`, а если его нет — по `CLAUDE_SESSION_ID` / `CLAUDE_CODE_SESSION_ID` (у Claude Code он стабилен).
У сессий без такой переменной (Codex и др.) запасной ID — `ppid-<PPID>`, и он может меняться между вызовами инструмента: тогда «мой слот» не узнаётся,
слот держится до TTL, а свой же `acquire` даёт ложный WAIT. Такая сессия один раз задаёт `export PM_SESSION_ID=codex-<имя>` (в том же shell, откуда зовёт скрипт).

## Защита от зависших слотов

Слот протухает через 15 минут. Если сессия умерла и не отдала слот —
он освободится сам. Насильно чистить: `slot.sh reap`.

## Состояние эмулятора (заметка для следующих сессий)

- **2026-10-03 (Дизайн): в dev-приложении на эмуляторе ВЫКЛЮЧЕН Fast Refresh.** Причина:
  другие сессии правят файлы в общем дереве, и каждая правка перезапускала приложение
  посреди сценария (за один заход 20 перезапусков). Включить обратно: меню разработчика
  (`adb shell input keyevent 82`) → «Enable Fast Refresh». После своих правок без Fast
  Refresh жми в том же меню «Reload».
- Слот под бандлер протухает через 15 минут — продлевай (`slot.sh acquire` повторно),
  иначе бандлер останется работать без слота.
- Магазинную сборку собирай так: `./gradlew :app:createReleaseUpdatesResources --rerun assembleRelease`.
  Без `--rerun` манифест expo-updates может быть старым, и тогда в сборке не будет новых картинок и звуков.
