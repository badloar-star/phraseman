# Заголовок формы плашки не следует за выбранным положением

Governance-ID: TG-505980B61222
Дата: 2026-09-21

Запрос владельца: «А ЧЕ ТУТ ТОЛЬКО НИЖНЯЯ ПЛАШКА? КАК ДОБАВИТЬ ВЕРХНЮЮ».

## Диагноз

Форма плашки ОДНА на оба слота. Положение выбирается в поле «Положение в
настройках» (`#am-settings-slot`, `legacy.html:14195`):

```
top    → «Сверху — под Phraseman Plus»
bottom → «Снизу — в конце настроек»
```

Заголовок `#am-form-title` ставится ОДИН раз при открытии формы
(`legacy.html:34166`) и больше не обновляется. Если владелец пришёл по кнопке
«Редактировать нижнюю» и затем переключил положение на «Сверху», заголовок
продолжает врать: «Нижняя плашка».

Отсюда и вопрос владельца: экран выглядит так, будто доступна только нижняя.

## Outcome

1. Заголовок следует за выбранным положением: переключил «Сверху» — заголовок
   стал «Верхняя плашка».
2. Из формы видно, что положение здесь же и меняется, то есть «добавить
   верхнюю» не требует возврата на вкладку «Плашки».

## Scope

### Правится
- `admin/v2/legacy.html` — обновление `#am-form-title` при смене
  `#am-settings-slot` и при смене поверхности показа.

### НЕ трогается
- Сохранение и валидация формы: они уже работают по значению селекта,
  а не по заголовку.
- `editSettingsMessageSlot` — она ставит верный заголовок при открытии.

## Architecture

Заголовок вычисляется одной функцией из текущих значений формы
(`#am-delivery-surface` + `#am-settings-slot`), а не присваивается в трёх
местах. Вызов вешается на `oninput` селекта — там уже есть
`updateAppMessagePreview()`, добавляем рядом.

Для режима редактирования существующего сообщения заголовок остаётся
«Редактирование сообщения»: подменять его на «Верхняя плашка» значило бы
потерять контекст, что правится уже созданная запись.

## Security and privacy

Только текст заголовка в интерфейсе. Данных, прав и сетевых вызовов не
касается. Privacy policy правок не требует.

## Technical debt

`#am-form-title` присваивается в четырёх местах (`legacy.html:14179`, `34077`,
`34166`, `39661`). Полная централизация — отдельная задача; здесь закрываем
только расхождение заголовка с выбранным слотом.

## Verification

- Живой прогон: открыть форму как «нижняя», переключить положение на
  «Сверху» → заголовок «Верхняя плашка», и наоборот.
- Проверить, что при поверхности «Inbox» заголовок не превращается в плашку.
- Убедиться, что режим редактирования существующего сообщения сохраняет свой
  заголовок.
