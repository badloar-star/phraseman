# План: +500 монет за полный просмотр видео (05.11.2026, «8 · Моменты»; КОД НЕ НАЧАТ — ждём ОК владельца на макет)

Слово владельца: «ЗА КАЖДОЕ ВИДЕО ЗА ФУЛЛ ПРОСМОТР ОТ НАЧАЛА И ДО КОНЦА ДАВАТЬ 500 МОНЕТОК; при завершении иконка и начисление +500 СРАЗУ». Решения владельца (через координатора): без дневного предела; воскресное ×2 НЕ применяется — всегда ровно +500; один раз навсегда на (uid, videoId).

## Одно событие
`onVideoFullyWatched(videoId)` → (1) пометка «просмотрено» (`markVideoWatched`, лента Дизайна), (2) +500 монет (журнал рун, локально сразу), (3) история «Видео просмотрено: +500». Пометка не зависит от успеха монет.

## Новые файлы
- `app/video_full_watch.ts` — детектор «досмотрел»: копит непрерывно сыгранные секунды по videoId (тики плеера, без перемотки), решение «досмотрел» = ended + накоплено ≥ 90 % длительности (порог — константа, лог на каждую ветку `[VIDEO-FULL]`).
- `app/video_watched_store.ts` — `markVideoWatched(videoId)`, `watchedVideoIds(uid, lang)`; хранилище по uid+язык, без сети (имена согласовать с Дизайном).
- `hooks/use_video_full_reward.ts` — обвязка для экранов: подписка на событие, оптимистичное начисление, откат/ретрай.
- `modules/story_events/video_reward_story.ts` (+ шаблон `components/stories/templates/frames_video_reward.tsx`, регистрация в `story_template_registry`, строки на 9 языков через Переводчика) — слот истории по макету.
- Тесты-стражи: `tests/video_full_reward_2026_11_05.test.ts` (500 ровно, без множителей, один раз на videoId, порог, повтор/двойной тап, пометка независима), замок в OWNER_LOCKS после слова владельца.

## Протоколы
- Награда один раз навсегда: ключ `video_full:{videoId}` в журнале; повтор/двойной тап/переоткрытие → no-op с логом.
- Оптимистично: локальный коммит журнала → шапка монет обновляется сразу; сервер догоняет; при отказе сервера — состояние «не начислено» и ретрай, не молчаливая потеря.
- Антифарм: клиентскому `ended` не верим одному (накопленные секунды без перемотки); серверная проверка — решение Ядра.

## Риски / вопросы
- 500 монет ≈ полцены ранга (1000): без дневного предела (решение владельца) — следить по метрикам; серверная проверка желательна.
- Политика конфиденциальности: если сервер хранит videoId просмотров — нужен абзац (раздел о данных активности).
- Язык ленты/смена языка: ключ просмотра по uid+язык, награда — по videoId навсегда (не повторять при смене языка).
- Лайвы/ролики короче порога/без длительности — не засчитывать, лог причины.

## УТОЧНЕНИЕ ВЛАДЕЛЬЦА (05.11, дословно: «Что считать полным просмотром — 70% видео. Повторный просмотр не даёт») — ЗАМЕНЯЕТ правило «до конца»
- Условие награды: накопленное непрерывно сыгранное время ≥ **70 %** длительности видео (перемотка вперёд и пауза не копятся). `ended` НЕ обязателен. Порог — константа `VIDEO_FULL_WATCH_RATIO = 0.7` в `app/video_full_watch.ts` (было 0,9 в правке Ядра п. 4 — Ядру сообщить, серверу порог не нужен, но тест-страж меняется).
- Момент награды: в секунду достижения 70 % — **+500 сразу** (оптимистично: шапка монет и иконка/анимация мгновенно); «история» — после конца или закрытия видео (не посреди просмотра).
- Повтор: если `videofull_<sha1(uid|videoId)>` уже есть (локально или на сервере) — никакой награды и никакой истории (no-op с логом `[VIDEO-FULL] repeat_skip`).
- Остальное без изменений: ровно +500, без множителей, без дневного предела; без длительности и лайвы — не начислять (лог причины); пометка «просмотрено» (`markVideoWatched`) ставится в том же событии, но НЕ от порога награды отдельно: ленте нужна пометка уже на 70 %.
- Тест-страж: порог 0,7 (69 % — нет, 70 % — да), перемотка не копится, повтор не награждает, история только после конца/закрытия, requestId `videofull_<40 hex>`.
- Сервер (Ядро, мягкая проверка): интервал между наградами ≥ 0,6 × длительность видео — только логирование `[VIDEO-REWARD]`, без блокировки; дневного лимита и ×2 нет. Порог детектора 0,7 подтверждён Ядром.
