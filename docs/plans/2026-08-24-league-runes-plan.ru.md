# Лига на рунах — план перевода с XP (2026-08-24)

Решения владельца (сессия 2026-08-24):

| Вопрос | Решение |
|---|---|
| Что считается очками лиги | **Весь приток рун в кошелёк за неделю** (earn + гранты: арена, турниры дня, Learning V2, «Вместе», спины, обмен монет, подарки) |
| Классические активности (уроки/экзамены/флешкарты/диалоги) | **Начисляют руны** (новые earn-поводы, шкалу предлагает Клод — см. §3) |
| Сундук лиги | **Общая цель комнаты** в рунах (механика прежняя, шкала новая — §5) |
| Бонусы лиг «+10%…+110%» | **Остаются XP-бонусами**, тексты клубов не трогаем |
| Боты-жители | Зарабатывают руны **как средний активный игрок** (§4) |
| Бусты ×2/×3 и «горячие 2 часа» ×2 | **Оба работают** — множат только очки лиги, кошелёк не трогают |
| Включение | **С новой ISO-недели** (константа-гейт по weekId, §6) |
| Модал-объяснялка | Авто при первом входе + круглая кнопка «?» справа сверху; **все 8 языков**; покрывает базу+сундук+горячие часы/бусты+XP-бонусы (§7) |

## 1. Архитектура: что меняется, что нет

**НЕ меняется:** ранжирование (competition ranking), зоны 15%, правило «нули понижаются»
(`computeGroupResults` / `calculateResult` — вход `points` агностичен к валюте),
структура `league_groups`, финализация кроном, модалка итогов как механизм,
кэш 6 часов (⛔-правило), бонусы лиг +XP%.

**Меняется — что кладётся в `points`:** вместо недельного XP — **недельные рунные очки**:

```
рунные очки недели = Σ (положительная дельта кошелька × активный множитель в момент начисления)
множители: личный буст клуба ×2/×3, горячие 2 часа ×2 (зона вылета) — только на очки лиги
```

## 2. Сервер

### 2.1 stars_ledger.ts — недельный приток
`weekEarned` считает только класс `earn`. Владелец выбрал «весь приток», значит:
- добавить в `StarsState`: `weekInflow`, `prevWeekInflow` (сумма ПОЛОЖИТЕЛЬНЫХ дельт
  классов `earn` + `grant` по той же ISO-неделе `weekKey`; `spend` не уменьшает);
- та же логика ролловера, что у `weekEarned` (`weekKey`/`prevWeekKey`);
- ноль новых чтений: поле живёт в том же `users/{uid}` документе.

### 2.2 Руны за классику — один callable
По образцу `mistake_practice_wallet_reward.ts`: **один** callable
`practiceSessionWalletReward` с параметром вида активности, серверные ставки и капы
(клиент сумму не задаёт). Новые earn-поводы в `StarOpReason`.

**Предлагаемая шкала (масштаб арены: матч ≈ 19–40 рун):**

| Активность | Руны | Кап |
|---|---|---|
| Классический урок — сессия завершена | 8 | 5/день |
| Повтор уже пройденного урока | 4 | в общем капе |
| Экзамен уровня сдан | 30 | 1 раз на экзамен |
| Диагностический тест | 15 | 1 раз |
| Флешкарты — сессия от 15 карт | 5 | 4/день |
| Диалог с ИИ завершён | 12 | 3/день |
| Словарь — сессия | 5 | 3/день |
| Неправильные глаголы — сессия | 6 | 2/день |
| Предлоги — сессия | 6 | 2/день |
| **Общий дневной кап классики** | **60/день** | ≈ 420/нед — сопоставимо с ареной, арена остаётся выгоднее |

Ставки утверждены владельцем 2026-08-24 (урок/повтор/экзамен/диагностика/флешкарты/
диалоги/словарь/глаголы/предлоги — все «да»).

Дедуп: `<sourceKind>:<sessionId>` как в журнале. Анти-фарм: капы серверные.

### 2.3 Боты-жители — рунная кривая
`residentWeeklyPoints` получает рунный режим (гейт по weekId): та же
детерминированная «человеческая» кривая роста по часам, но в новой шкале:
- слабые ~30–60 рун/неделю, медиана ~140, упорные до ~380;
- комната 28 жителей ≈ **4 100 рун/неделю** суммарно (≈40% цели сундука — как сейчас);
- `totalXp`/уровень/аватар жителя остаются XP-величинами (профиль не выдаёт бота).

### 2.4 Сундук — новая цель
`LEAGUE_CHEST_BASE_GOAL_RUNES = 10_000`, шаг `+500 × leagueId`
(пропорция достижимости как у 400 000 + 20 000: вклад ботов ~40%).
Зеркала клиент/сервер обязаны совпадать (контракт-тест).

### 2.5 Финализация и анти-чит
- `league_finalize_cron` — без изменений (вход тот же).
- Опция (фаза 2): крон сверяет `points` живых участников с
  `users/{uid}.stars.prevWeekInflow × 6` (макс ×3 буст × ×2 горячие часы) и клампит
  завышенные. Цена: ≤5 доп. чтений на комнату раз в неделю.
- Remote-флаг «повышение по порогу XP» (по умолчанию выключен): порог переосмысляется
  как руны; дефолт 1000 → предложение 150 рун. Не включаем.

## 3. Клиент

### 3.1 Новый модуль `app/league_week_runes.ts`
Локальный недельный счётчик рунных очков (оптимистичный):
- источник — оп-события рунного кошелька (дедуп по `opId`, НЕ по дельте баланса —
  иначе двойной счёт «оптимистично + серверный ack»);
- каждая положительная опа × активный множитель (буст/горячие часы) → счётчик недели;
- персист в AsyncStorage по `weekKey`, смена недели обнуляет;
- сверка с сервером: при заходе на экран клуба берём max(локальный, серверный
  `weekInflow`-производный) — «поздний ответ не затирает свежее» (last-write-guard).

### 3.2 Переключение писателя очков
- С недели старта `hall_of_fame_utils.addOrUpdateScore` больше НЕ дёргает
  `updateMyGroupPoints` (XP-путь остаётся для канонического XP/уровней/зала славы);
- новый писатель: `league_week_runes` → `updateMyGroupPoints(руныНедели)` (тот же
  дебаунс 8 сек, той же функцией).

### 3.3 UI (глиф ᚠ вместо XP)
- `club_screen.tsx`: числа участников с `RUNE_GLYPH_PRIMARY`, прогресс сундука в рунах;
- `LeagueResultModal.tsx`: итоговые очки = руны с глифом;
- `withMyLivePoints` — мои живые очки из `league_week_runes` (0 чтений);
- везде один дежурный глиф (правило владельца 23.08 — не «прыгает»).

### 3.4 Optimistic UI классических начислений
Завершение урока/сессии: мгновенно «+8 ᚠ» (анимация полёта глифов уже есть —
`runes_balance_updated`), локальный счётчик лиги растёт сразу, callable — фоном,
откат при отказе сервера (кап исчерпан → тихо убрать из счётчика лиги, кошелёк
не трогался).

## 5. Гейт перехода

`RUNES_LEAGUE_START_WEEK_ID = '2026-W36'` (понедельник 31.08) — общая константа,
зеркала в клиенте и functions:
- `weekId < start` → всё по-старому (XP-очки, XP-кривая ботов, XP-цель сундука);
- `weekId >= start` → рунные очки, рунная кривая, рунная цель.
Деплой клиента и functions обязан случиться ДО 31.08 (functions сейчас блокированы
чужими ошибками сборки — проверить перед деплоем).

## 6. Сторожа и тесты (точечные прогоны)

- контракт: цель сундука клиент == сервер (руны и XP-ветки);
- контракт: `RUNES_LEAGUE_START_WEEK_ID` клиент == сервер;
- ledger: `weekInflow` растёт от earn и grant, не падает от spend, ролловер недели;
- residents: рунная кривая детерминирована, сумма комнаты в ожидаемом диапазоне;
- league_week_runes: дедуп по opId, множители, обнуление недели, last-write-guard;
- существующие сторожа лиг (понижение, TTL 6ч) НЕ трогаем — они валютно-агностичны.

## 7. Риски / открытые хвосты

- **Достижения по очкам лиги**: проверить `achievements.ts` — пороги, завязанные на
  недельные очки, падают в ~50× шкале; пересчитать до релиза.
- **Зал славы / недельный лидерборд** остаётся XP — это отдельная витрина; убедиться,
  что нигде не подписан «очки лиги».
- **Смешанная неделя при сбое деплоя**: если functions не уедут до W36, клиент уже
  будет слать руны, а боты расти в XP — гейт по weekId обязан быть в ОДНОЙ константе
  с обеих сторон, деплой проверить глазами.
- **Цены магазина рун**: приток вырастет (классика до ~420/нед) — лестница
  45/50/55/60/65 и цены арены станут «дешевле» относительно дохода; владельцу решить,
  поднимать ли цены (отдельная задача).
