# Пейвол: красный экран «unknown_paywall_source:settings_plus» и ссылки «Условия / Конфиденциальность» под плашками (26.10)

Governance-ID: TG-F24BB734D928

## Outcome
1. Понять, откуда приходит source `settings_plus`: настоящая кнопка Plus в Настройках передаёт `settings_premium` (app/(tabs)/settings.tsx, plusRowPress), литерала `settings_plus` в коде приложения нет (есть только в тесте). Ядро в c161d894a записало: значение пришло из ссылки съёмки, не из кода. Добавляем журнал [PAYWALL-ENTRY] со ВСЕМИ параметрами входа ДО отказа, чтобы в следующий раз источник был виден сразу, без догадок.
2. Низ окна Plus (PaywallPlusDock): ссылки «Условия» и «Конфиденциальность» не должны перекрываться плашками «Восстановить» и «Ввести промокод» ни на узком экране, ни с крупным шрифтом.

## Scope
- app/paywall_entry_contract.ts — только журнал перед отказом (список допустимых source не меняется).
- components/paywall/PaywallPlus.tsx — раскладка низа окна (PaywallPlusDock), при необходимости PaywallServerRefusedDock.tsx.
- Тесты пейвола, сторож paywall_entry_callsite_registry_contract.

## Architecture
Контракт входа остаётся белым списком: `settings_plus` в него НЕ добавляется — это выдуманное значение, оно размыло бы аналитику воронки. Раскладка дока — обычная колонка React Native: плашки действий, затем отдельная строка ссылок с собственной высотой.

## Security and privacy
Новых данных нет. Журнал пишет только значения параметров входа (source, context, метки атрибуции), без личных данных.

## Technical debt
