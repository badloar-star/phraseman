# Видео: плейлист из «хвоста» каталога на медленной сети — не вечный скелет, dev-задержка, логи (R57 #23, координатор 15.10)

Governance-ID: TG-417BE64996B0

## Outcome
Снимок экрана видео держит ≤ 20 роликов и ≤ 8 плейлистов; плейлист из «хвоста» берётся из полного списка канала (кэш: память → диск, сеть не чаще раза в 6 ч). На очень медленной сети ответа не было дольше любого разумного срока, а экран показывал скелет бесконечно. Теперь: ждём `PLAYLIST_SLOW_MS` = 15 с, затем «Плейлист грузится дольше обычного» с кнопкой «Повторить»; пришёл ответ — экран сам становится обычным (контент или честная пустота). Добавлена dev-имитация медленной сети и журнал `[VIDEO-PLAYLIST]`.

## Scope
`app/lingman_playlist.tsx` (вид по чистой функции, таймер ожидания, «Повторить» сбрасывает ожидание, текст на 9 языках), новый `app/lingman_playlist_view_state.ts` (чистое решение «что показать»), новый `app/dev_video_network_delay.ts` (dev-флаг), `app/all_channel_videos_source.ts` (пауза перед сетью при dev-флаге), тест `tests/video_playlist_tail_slow_network.test.ts`.

## Architecture
`playlistViewKind({hasPlaylist, videosCount, status, waitedTooLong})` → skeleton / slow / empty / content / content_loading / content_slow / content_empty. Ветки: плейлиста нет и список грузится — скелет; ждём > 15 с — slow; полный список пришёл или сети и кэша нет — empty; плейлист есть, роликов нет — скелет списка, затем slow, затем content_empty. Dev-флаг: в dev-сборке `globalThis.__DEV_VIDEO_NETWORK_DELAY_MS__ = 20000` в консоли JS (0 — снять) — перед чтением полного списка пауза на это число мс; в стор-сборке (`EXPO_PUBLIC_STORE_RELEASE=1`) всегда 0. Служебные модули в app/ с заглушкой маршрута.

## Security and privacy
Данные не затрагиваются; сеть не добавляется — «Повторить» вызывает прежний `refresh` (принудительное чтение полного списка, одно).

## Technical debt
`revalidateYoutubeChannelCatalog` на экране плейлиста повторяется до 5 раз по 20 с, пока плейлист не найден, — оставлено как есть (гейт «хвоста» теперь через полный список; повтор останавливается, как только плейлист найден).

## Verification
Тест: все ветки решения, dev-задержка реально держит чтение на таймерах (до срока ответа нет, после — плейлист из «хвоста» на месте), исходники экрана и источника. Живая проверка на эмуляторе: dev-флаг 20000 → открыть плейлист из хвоста → 15 с скелет → «грузится дольше обычного» → ответ → контент; логи `[VIDEO-PLAYLIST] ждём полный список / медленно / вид`, `[ALL-VIDEOS] DEV: искусственная задержка сети`.
