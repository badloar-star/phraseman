# Task packet: комментарии под набором — настоящие аватарки + полноценный визуал

## Outcome

Владелец увидел живьём окно комментариев и назвал текущий вид неприемлемым:
вместо настоящей аватарки пользователя показывается случайный emoji
(авторское решение при первой реализации — `avatarFor(seed)` хэширует id в
один из 8 emoji). Плюс общее указание довести раздел до уровня остального
приложения («полноценный красивый и годный»). Задача — заменить
псевдо-аватарки на настоящую систему аватарок проекта (AvatarView, уже
используется в колокольчике/друзьях) и пройти по всей шторке комментариев
слоем полировки (impeccable → taste-skill → emil-design-eng, по owner-rules),
не трогая логику (уже почищенную в предыдущих задачах).

## Scope

In scope:
- `app/community_packs/PackCommentsSheet.tsx`: заменить `avatarFor()`
  emoji-заглушку на настоящий `AvatarView` (или эквивалент, используемый в
  `NotificationCenterButton.tsx`/друзьях) — нужен реальный аватар автора
  комментария, не заглушка по хэшу id.
- Источник данных для аватара: комментарий сейчас хранит только
  `authorId`/`authorName` — если для рендера аватара нужен объект аватара
  (frame/aura/etc, не просто картинка), может понадобиться подтягивать его
  так же, как это делают другие соц-компоненты (проверить, откуда его берёт
  AvatarView/друзья — единый источник или на лету).
- Полировка визуала шторки целиком: карточки комментариев, композер, меню
  действий, пустое состояние — под стандарт остального приложения (impeccable
  → taste-skill → emil-design-eng по owner-rules, т.к. это заметный редизайн
  экрана, не мелкая косметика).

Out of scope:
- Логика (кто может писать/закреплять/скрывать/жаловаться) — уже починена
  ранее в этой же сессии, не трогается.
- Другие экраны за пределами шторки комментариев.

## Architecture

Не меняется структурно — компонент остаётся тем же, меняется откуда он берёт
данные для рендера аватара (реальный источник аватарок вместо локального хэша)
и визуальное оформление.

## Security and privacy

Не затрагивается — рендер уже существующих данных пользователя (аватар),
никаких новых полей/сбора данных.
