## 3. Решения владельца — УЖЕ ПРИНЯТЫ, не переспрашивать

1. **Цикл состояний — «как у Duolingo»**: живой цикл (ответ → Проверить →
   inline-обработка → вердикт → авто-дальше), НИКАКИХ служебных панелей
   переключения состояний.
2. **Микрофон НАСТОЯЩИЙ, распознавание ТОЛЬКО на устройстве**, аудио не
   сохраняется. Privacy: `privacy.html` §13 уже покрывает (проверено
   2026-07-26), разрешения настроены в `app.config.js` (expo-speech-recognition).
   Готовый стек: `app/speaking_recognition_options.ts` (+ отладка OEM-капризов),
   `app/speaking_word_match.ts`, образец UI — `components/SpeakingPanel.tsx`.
   Экраны с обещанием СЕТЕВОЙ обработки голоса — НЕ показывать (враньё).
3. **Дистракторы**: каждый неверный вариант грамматически НЕВОЗМОЖЕН в данном
   контексте. Допустимый вариант = второй правильный ответ = запрещено.
   (память feedback_distractors_rule — распространяется на ВСЁ.)
4. **Тема**: режимы ПЕРЕНИМАЮТ цвета и акценты темы ПРИЛОЖЕНИЯ (useTheme,
   светлая/тёмная/золотая) — НЕ хардкод cinema-палитры Kimi. Это одна из
   причин браковки прототипа.
5. **Запреты дизайна**: без обводок контейнеров (тон/тень/фон; односторонние
   разделители можно), без подписей-расшифровок мелким шрифтом, без
   adjustsFontSizeToFit. Клик-звук — только управляющие кнопки; плитки — хаптика.
6. **Показ работы**: макеты в БРАУЗЕРЕ (HTML-витрина) → одобрение → перенос в RN.
   По одному режиму, волнами, с одобрением каждого.
7. **Sonnet-исполнитель / Opus-советник** — схема из глобального CLAUDE.md.
   Fable — ручная эскалация на дизайн макетов (владелец включает сам).
