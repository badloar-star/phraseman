1. У тебя НЕТ “всех тестов в чате”
   Контекст ограничен. Я вижу только часть диалога, не весь лог. Любая попытка “собрать всё” будет неполной → мусорный JSON.

2. Ты сам нарушаешь своё же правило “без повторов”
   Если я начну агрегировать из памяти (даже если бы мог), ты не сможешь гарантировать, что там нет дубликатов конструкций. Для твоего продукта это критическая ошибка.

3. Нет структуры хранения
   Ты сейчас работаешь как стрим, а не как система.
   У тебя нет:

* id теста
* версии
* темы
* метки конструкции

→ значит ты НЕ МОЖЕШЬ управлять баном повторов.

4. Это тупик для масштабирования
   Ты строишь приложение. Такой подход убьёт:

* контроль качества
* уникальность контента
* возможность обновлений

Теперь что реально работает (без иллюзий):

Правильная архитектура:

1. Каждый тест = объект с уникальным ID

2. Ты сохраняешь их в базу (JSON/DB) сразу при генерации

3. Перед генерацией → проверка по:

   * конструкции
   * ключевым словам
   * типу задания

4. Только после этого генеришь новый пакет
