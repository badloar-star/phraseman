# Шаблон записи прогресса (PM-253)

Каждая запись о закрытии или сдаче задачи в `PROGRESS.md` и в журнале
`evidence/review_to_done_audit_*.md` содержит ВСЕ поля ниже. Пустое поле пишется
явно: «нет (почему)», а не пропускается.

```markdown
### PM-NNN — <короткое название>
- **Task ID:** PM-NNN (критерии: PM-NNN-A1 ✓, PM-NNN-A2 ✓ / NOT_MET: <кто/что нужно>)
- **Base SHA:** <коммит, от которого начата работа>
- **Result SHA:** <коммит с результатом; для docs-only — коммит документа>
- **Changed files:** <пути через запятую или `git show --stat <sha>`>
- **Tests:** <файл — N/N; проба — PASS/FAIL; typecheck — 0>. Читать ТЕКСТ вывода (OOM даёт ложный ноль).
- **Screenshots:** <путь в evidence/design_gate/… | нет (изменение без видимой части) | ждём «Дизайн»>
- **Risks:** <что может сломаться, деньги/данные/прод; «нет» — с причиной>
- **Next action:** <кто и что делает дальше: ревьюер / владелец (деплой) / «Дизайн» (скриншот) / нет>
- **Reviewer / verdict:** <независимый ревьюер ≠ автор> / PASS | CHANGES_REQUIRED | BLOCKED
```

Правила:
- `result_sha` в `registries/tasks.json` для задач `kind: code` обязателен при `done` —
  это проверяет `tools/validate.py` («code done without result SHA»).
- Процент прогресса считается только по принятым критериям реестра (PM-253-A2), не на глаз.
- Отметка критериев — `tools/mark.py` (пишет только блок задачи и строку в `worklog.jsonl`).
