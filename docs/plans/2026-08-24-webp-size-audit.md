# Фаза 4 «Бандл-диеты»: размерный аудит webp и пережатие — 2026-08-24

Инструменты: `scripts/audit_webp_display_sizes.mjs` (аудит: пиксели файла vs
максимальный размер отображения в коде ×3 для @3x) и
`scripts/resize_webp_to_display.mjs` (пережатие по явному вайтлисту).
Иконки приложения пережаты отдельно (см. ниже).

## Что НЕ тронуто и почему

- **level-spin-rewards/** (0.67 МБ, 512px): контракт
  `tests/level_spin_reward_assets.test.ts` требует ровно 512×512. Реальное
  отображение ≤108dp (324px) — экономия ~0.35 МБ доступна, но только вместе с
  осознанным обновлением сторожа (решение владельца).
- **season/…/320×320** (0.33 МБ): контракт `season_aura_asset_safe_area` требует
  320×320. Отображение ≤74dp — потенциал ~0.15 МБ, тоже за сторожем.
- **home_menu/** (1.6 МБ): рисуется до 164dp (вотермарк лиги) → 492px @3x;
  текущие 384–512px НЕ избыточны. Пережатие только качеством — это уже делает
  `compress-bundled-assets.mjs` (другая сессия).
- **bronza.webp, izumrud.webp**: файлы редактируются в другой сессии (M) —
  пропущены фильтром.
- **personal_plan_tasks_fit/, friends-shared-flame/**: каталоги целиком
  untracked (создаются параллельной сессией) — пережимать нечего откатывать.

## Починен сторож, который вообще не работал

`tests/android_bundle_hygiene_contract.test.ts` падал с heap OOM (даже при
удвоенном лимите памяти): он собирал ~2266 путей в массив и в `.filter()` читал
содержимое каждого файла. То есть сторож **молча не охранял ничего**. Обход
переписан на генератор, копятся только нарушители. Проверки НЕ ослаблены — те же
8 утверждений, теперь **8/8 зелёные за 20 с**.

## Откат

Все изменённые файлы — tracked, откат одной командой `git checkout -- <пути>`
или revert коммита. Пути и имена файлов не менялись, код приложения не тронут —
риск только визуальный (резкость), а не поломка. Два коммита: `98e0e31f7`
(82 файла) и `6f5c13ed1` (44 иконки серий + монохром + сторож).
