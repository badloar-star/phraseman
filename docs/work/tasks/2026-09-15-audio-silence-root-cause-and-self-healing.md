## Outcome

Жалоба пользователей: «пропадает озвучка в приложении» — голос перестаёт звучать, часто
вместе со звуковыми эффектами, и помогает только перезапуск приложения.

Наблюдаемый результат после работы:
1. Ни один сбой воспроизведения не может оставить приложение навсегда немым: аудиослой
   самовосстанавливается без перезапуска.
2. Каждый отказ звука пишет причину в лог с единым префиксом `[AUDIO-LEASE]` —
   поддержка и владелец видят, что именно замолчало и почему.
3. Класс бага закрыт сторожем, а не разовой правкой: новый экран с озвучкой не может
   снова внести утечку аренды незаметно.

Мера успеха: сценарий «войти в урок → озвучка → свернуть приложение / входящий звонок /
отключить наушники → вернуться» оставляет звук рабочим; счётчик активных аренд
возвращается в ноль после завершения любого воспроизведения.

## Architecture

Текущая граница. Один процессный аудиотракт. Каждое воспроизведение берёт «аренду»
(`acquireAudioActivity('spoken')`) или запись — `'recording'`. Счётчики аренд решают три вещи:
нативный режим сессии (`setManagedAudioMode`), глушение эффектов (`soundDirector.setVoiceActive` /
`setRecordingActive`) и выдачу новых претензий (`claimSpokenAudio` возвращает null, пока идёт запись).

Дефект границы: аренда освобождается ИСКЛЮЧИТЕЛЬНО вручную вызывающей стороной. Нет ни одного
пути, который вернул бы счётчик в ноль самостоятельно. Любой пропущенный `release()` —
необратимая поломка звука до перезапуска процесса:
- `spokenLeases > 0` навсегда → `voiceQuietUntil = Infinity` в `sound_arbiter` → все эффекты
  без `mixWithVoice` отбрасываются с причиной `voice`;
- `recordingLeases > 0` навсегда → `claimSpokenAudio` возвращает null → вся озвучка молчит,
  а эффекты глушатся с причиной `recording`.

Интенция. Аренда становится самоограниченной по времени: владение аудио — ресурс с предельным
сроком, а не бессрочная запись. Дополнительно аудиослой обязан реагировать на жизненный цикл
приложения (уход в фон / возврат), чего сейчас нет вовсе.

Второй класс причин — исчерпание нативных плееров эффектов (`expo_sfx_backend.ts`).
Плеер занимает слот кэша, пока не придёт статус завершения от среды выполнения. Если статус
не придёт вовсе, слот занят навсегда: восстановление `releaseIdleNativePlayers` пропускает
занятые записи, а `evictIdleEntries` при полностью занятом кэше просто выходит. Кэш растёт
мёртвыми плеерами, ОС перестаёт выдавать новые, и отказ проглатывается немым
`catch { return false; }` — звук исчезает без единой строки в журнале.

Инварианты после правки:
1. Счётчик аренд не может расти монотонно: у каждой аренды есть потолок жизни.
2. Возврат приложения из фона приводит аудиослой к согласованному состоянию.
3. Любое обнуление аренды по предохранителю громко логируется — это всегда дефект вызывающей стороны.
4. Активный плейбек эффекта имеет предельный срок жизни: слот освобождается, даже если
   среда выполнения не прислала ни одного статуса.
5. Ни один отказ воспроизведения не проглатывается без причины в журнале.

## Technical debt

- **Pay now.** Утечки аренды на найденных путях (`learning-v2/session/[id].tsx`,
  `use_managed_spoken_audio_player.ts`, `SoundService.ts`, `use-audio.ts`): закрыть
  освобождением на каждом выходе.
- **Pay now.** Отсутствие предохранителя в `audio_activity`: аренда обязана иметь предельный
  срок жизни, иначе один новый экран снова похоронит звук.
- **Pay now.** Немой `voiceQuietUntil = Infinity`: бессрочная тишина эффектов.
- **Pay now.** Навсегда занятый слот плеера эффектов и немой `catch { return false; }`
  в `expo_sfx_backend.ts`: предельный срок жизни активного плейбека плюс причина отказа в журнале.
- **Pay now.** Немые отказы озвучки без диагностики: отказ выдачи аренды логируется в
  `use-audio.ts`, но молчит в уроке, карточках, онбординге и празднованиях. Привести к одному
  префиксу, иначе следующая жалоба снова будет неразбираема.
- **Contain.** Сторож на гарантию освобождения вместо проверки наличия строк. Условие выхода:
  тест падает, если в файле с `claimSpokenAudio` появляется путь без парного release.
- **Accept temporarily.** Реакция на смену аудиомаршрута (наушники выдернули) и на входящий
  звонок обрабатывается нативным expo-audio; собственного слоя не добавляем.
  Владелец: сессия. Дата пересмотра: при следующей жалобе на звук. Потолок влияния: звук
  восстанавливается предохранителем не мгновенно, а в пределах его срока.

## Rollback

Правки локальны и не мигрируют данные. Откат — обратный коммит: предохранители и логи
исчезают, поведение возвращается к текущему (звук снова может замолчать до перезапуска).
Пользовательские данные, покупки и выданные права не затрагиваются ни при применении,
ни при откате. Настройки звука пользователя не переписываются.
