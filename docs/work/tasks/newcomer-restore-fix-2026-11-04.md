## Outcome

Дыры из `newcomer-restore-conflicts-2026-11-04.md`: (1) ветеран на втором устройстве мог стать «новым» из-за гонки с облачным восстановлением; (2) липкая когорта и отметка
«приветствие показано» жили на устройстве и переносились между людьми. Результат: «новый» только если аккаунт Firebase Auth создан не раньше момента релиза гейтов
(`metadata.creationTime`, локально, 0 чтений); неизвестно/ошибка = не новый (всё открыто); когорта и «показано» привязаны к аккаунту и лежат в стираемом семействе `story_events_v1:`.

## Scope

- `app/rank_gates_new_user.ts` — правило «новый» + ключ когорты по аккаунту (поверх незакоммиченной липкой когорты Сайта, заменяю устройство-уровневый ключ).
- `components/onboarding/WelcomeGate.tsx` — ключ «показано» по аккаунту, пересчёт при смене аккаунта.
- `hooks/use_rank_access.ts`, `modules/section_openings/use_section_opening_host.ts` — вердикт не живёт между аккаунтами (сброс при смене владельца).
- новый `hooks/use_active_account_owner.ts`; тесты `tests/newcomer_restore_holes_2026_11_04.test.ts`, обновление `rank_gate_cohort_sticky`, `welcome_gate_2026_11_04`.

## Architecture

Владелец — `captureAccountGeneration()` (фаза active, stableId). Время создания — `peekCurrentAccountCreatedAtMs()` (уже есть, синхронно, без сети). Решение «новый/старый» фиксируется на аккаунт только при устойчивых причинах;
неизвестное (нет владельца, нет времени создания, нет метки онбординга) не фиксируется и всё открыто. Ключи: `story_events_v1:rank_cohort:<uid>` и `story_events_v1:welcome_b3:<uid>` — семейство уже стирается при выходе и удалении аккаунта.

## Security and privacy

Новых данных не собирается и не передаётся: время создания аккаунта читается локально из уже загруженного пользователя Auth; ключи — только на телефоне и стираются с аккаунтом. Политику менять не нужно.
