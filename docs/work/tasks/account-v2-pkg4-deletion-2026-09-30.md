## Outcome

Удаление аккаунта в Account V2 доказуемо полное и не зависает:
1. Сервер: чистое ядро плана удаления данных `accounts_v2/{uid}/**` (entities, ops, meta/rate) порциями ≤ 450 записей за коммит, идемпотентно, с возобновлением с любого места (курсор), + порт Firestore. Подключается как ещё один шаг существующего конвейера `functions/src/account_delete.ts` (через явный экспорт шага, без изменения публичных экспортов index.ts).
2. Ключ удаления (решение 13): проверка секрета, привязанного к цели `deletion_status` и точному operationId (хэш, сравнение за постоянное время, лимит частоты) даёт только «этап» и «дотолкнуть»; данных аккаунта не открывает; голый operationId, почта, чужой/новый uid — отказ.
3. Квитанция завершения — только этап, TTL 30 дней (решение 14, поле expireAt + fieldOverride ttl).
4. Клиент: чистая функция немедленного отсоединения — при подтверждении удаления V2-очередь синхронизации (outbox) и область хранения аккаунта (scope store) закрываются/стираются сразу, до ответа сервера; поздний ответ сервера не воскрешает данные; повторная регистрация той же почтой = новый uid, старые данные невидимы (решение 15, без уведомлений).
5. Матрица отказов тестами: обрыв до/после коммита, повтор, потеря ответа, падение посреди порции, неверный секрет/цель/операция, истёкшая квитанция, новый uid той же почты.
