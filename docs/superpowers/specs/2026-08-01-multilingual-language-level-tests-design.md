# Multilingual Language Level Tests

Дата: 2026-08-01
Статус: UX и продуктовые решения устно одобрены; письменная спецификация ожидает проверки владельца

## 1. Цель

Расширить публичный тест `https://knowlyapps.com/english-level-test/` до единой страницы пяти полноценных адаптивных тестов CEFR:

- английский (`en`);
- немецкий (`de`);
- французский (`fr`);
- итальянский (`it`);
- испанский (`es`).

Каждый язык получает самостоятельный валидируемый банк из 240 заданий: по 40 заданий для A1, A2, B1, B2, C1 и C2. Все тесты используют существующую прозрачную адаптивную лестницу из 12–20 вопросов и выдают честную предварительную оценку текстовых навыков, а не официальную языковую квалификацию.

Интерфейс всей страницы доступен на русском и английском. Это отдельное измерение от проверяемого языка: например, пользователь может проходить немецкий тест с английским интерфейсом.

## 2. Утверждённые продуктовые решения

### 2.1. Одна страница и один движок

Текущий URL остаётся рабочим и по умолчанию открывает тест английского. Проверяемый язык хранится в query-параметре:

- `?test=en`;
- `?test=de`;
- `?test=fr`;
- `?test=it`;
- `?test=es`.

Разрешены только эти пять значений. Отсутствующее или неизвестное значение безопасно заменяется на `en`. Выбор обновляет URL через History API без перезагрузки, поэтому ссылку можно скопировать и открыть с тем же тестом.

Отдельные SEO-адреса не входят в эту итерацию. В будущем их можно добавить как алиасы того же приложения без копирования движка или банков.

### 2.2. Язык интерфейса

Первый визит автоматически использует:

- русский, если основной язык браузера начинается с `ru`;
- английский во всех остальных случаях.

Кнопка в шапке переключает весь интерфейс между `ru` и `en`. Ручной выбор записывается в `localStorage` и при следующих визитах имеет приоритет над браузерной локалью. Query-параметр `ui=ru|en`, если он явно присутствует в общей ссылке, имеет наивысший приоритет и также синхронизирует сохранённый выбор. Неизвестное значение `ui` игнорируется.

При изменении локали обновляются `document.documentElement.lang`, заголовок страницы, метаописание и все пользовательские и accessibility-тексты текущего экрана.

### 2.3. Сертификат

Сертификат при открытии автоматически выбирает текущий язык интерфейса страницы. Он всегда называет фактически проверенный язык, например `Phraseman German Level Check`, а не жёстко заданный английский.

Существующий ручной переключатель русского и английского внутри сертификата сохраняется. Автоматический выбор задаёт правильное начальное состояние, но пользователь всё ещё может получить второй вариант сертификата вручную. Язык учитывается при повторном открытии, PNG, печати/PDF, CTA, подсказках сохранения и доступных именах элементов.

Имя файла содержит проверяемый язык, уровень и безопасное имя пользователя, например `phraseman-german-level-b2-alex-gold.png`.

## 3. UX и визуальная структура

### 3.1. Переключатель интерфейса

В правой части существующей шапки размещается компактная кнопка с SVG-иконкой глобуса и видимой подписью `RU` или `EN`. Видимая подпись исключает неоднозначность и показывает текущее состояние. Требования:

- зона нажатия не меньше 44×44 px;
- `button`, а не кликабельный `div`;
- локализованные `aria-label` и tooltip;
- видимый focus ring;
- достаточный контраст в обычном, hover, active и focus состояниях;
- переход цвета/прозрачности 150–300 мс без изменения геометрии.

### 3.2. Выбор проверяемого языка

На лендинге между вводным текстом и основной кнопкой старта располагается группа из пяти кнопок:

- English;
- Deutsch;
- Français;
- Italiano;
- Español.

Флаги и emoji не используются: язык не соответствует единственной стране, а текстовые названия понятнее и доступнее. Активное состояние обозначается не только цветом, но также рамкой/маркером и `aria-pressed="true"`.

На широком экране кнопки образуют один аккуратный ряд. На мобильном они переносятся на две строки без горизонтального скролла и сохраняют минимальную высоту 44 px. Переключение языка теста обновляет заголовок, описание, preview сертификата и CTA, но не меняет выбранный язык интерфейса.

### 3.3. Полная локализация страницы

RU/EN-словарь покрывает без смешения языков:

- шапку, лендинг, social proof, consent и footer;
- загрузку и сетевые ошибки;
- номер вопроса, таймер, инструкции, варианты действий и подтверждение выхода;
- результат, статистику, ввод имени, share и restart;
- сертификат, сохранение, печать и закрытие;
- CTA приложения и подписи App Store/Google Play;
- alert, prompt, clipboard/share-тексты;
- `aria-label`, `title`, `alt`, `lang` и динамические метаданные документа.

Текст задания отделяется от UI. В русской локали используются локализованные `scenarioRu` и `instructionRu`; в английской — `scenario` и `prompt`. Стимул и варианты ответа остаются на проверяемом языке.

## 4. Архитектура

### 4.1. Конфигурация языков

Один неизменяемый реестр описывает каждый проверяемый язык:

```js
{
  en: { bankUrl, names: { ru, en }, certificateNames: { ru, en } },
  de: { bankUrl, names: { ru, en }, certificateNames: { ru, en } },
  fr: { bankUrl, names: { ru, en }, certificateNames: { ru, en } },
  it: { bankUrl, names: { ru, en }, certificateNames: { ru, en } },
  es: { bankUrl, names: { ru, en }, certificateNames: { ru, en } },
}
```

Выбор языка не размазывается по условным операторам. Отдельный модуль локализации отвечает за разрешение locale, словарь и интерполяцию проверяемого языка. `app.js` использует эти интерфейсы и не содержит параллельных RU/EN-шаблонов целых экранов.

### 4.2. Банки заданий

Production-файлы:

- `data/questions.en.json`;
- `data/questions.de.json`;
- `data/questions.fr.json`;
- `data/questions.it.json`;
- `data/questions.es.json`.

Каждый файл имеет собственные `bankVersion`, `language`, уровни и ровно 240 уникальных заданий. Схема остаётся совместимой с существующим движком и включает как минимум:

- `id`, `level`, `difficulty`, `skill`, `format`;
- `scenario`, `prompt`, `scenarioRu`, `instructionRu`;
- `stimulus`, четыре уникальных `options`, `correctIndex`;
- `explanation`, `targetConstruct`, `cefrRationale`;
- `dialect`, `reviewStatus`, `ambiguityNotes`;
- `upperBandEvidence`, когда это требуется существующим контрактом верхних уровней.

ID имеют языковой префикс (`de-a1-001`). Правильный ответ однозначен в указанном контексте. Запрещены метаответы вроде `All of the above`, повторное циклическое размножение небольшой выборки и ложная маркировка `reviewed` без завершённой языковой проверки.

Банки создаются и проверяются по одному языку и одному уровню за раз, но публичный релиз происходит только после прохождения общих контрактов всех пяти языков. Генерация не использует project/user OpenAI API key; применяется только встроенная способность Codex и локальные валидаторы, что соблюдает API firewall проекта.

### 4.3. Загрузка и состояние

Страница лениво загружает только выбранный банк. Уже загруженный банк может храниться в ограниченном session-кэше максимум для пяти разрешённых языков. Смена языка до начала теста не загружает остальные четыре банка.

После старта выбранный проверяемый язык фиксируется на всю попытку. Его нельзя случайно поменять посреди теста. Для выбора другого языка пользователь выходит на лендинг или завершает текущую попытку.

Если банк не загрузился, показывается локализованная ошибка и retry для текущего языка. Приложение не подменяет его английским банком, потому что это создало бы ложный результат.

### 4.4. Engine

`engine.js` остаётся языконезависимым и получает массив заданий выбранного банка. Правила адаптации, перемешивания, остановки и предварительной оценки одинаковы для всех пяти языков. Языковые исключения в engine не допускаются; различия принадлежат данным и UI.

### 4.5. Аналитика и приватность

При добровольном consent существующие события дополняются:

- `testLanguage` — `en|de|fr|it|es`;
- `uiLocale` — `ru|en`;
- соответствующим `bankVersion`.

Backend принимает только allowlisted значения и сохраняет обратную совместимость со старыми английскими событиями без новых полей. Имя сертификата не отправляется. Смена интерфейса или теста до старта может учитываться только после согласия пользователя.

## 5. Результат и тексты

Итоговая шкала остаётся `Pre-A1`, `A1`, `A2`, `B1`, `B2`, `C1`, `C2`. Формулировки явно сообщают, что результат является предварительной текстовой оценкой и не проверяет аудирование, говорение или письмо.

Все динамические тексты используют название выбранного языка. Примеры:

- RU: `Предварительная текстовая оценка немецкого — B2`;
- EN: `Your preliminary German text assessment is B2`.

CTA Phraseman остаётся доступным после любого теста. Обещания обучения не должны утверждать поддержку немецкого, французского, итальянского или испанского внутри приложения, если продукт фактически этого не предлагает. Для неанглийских тестов CTA формулируется как предложение тренировать живой английский в Phraseman, а не продолжать выбранный язык.

## 6. Доступность и адаптивность

- Полная клавиатурная навигация и существующие горячие клавиши сохраняются.
- После смены локали фокус остаётся на переключателе, а screen reader получает понятное новое имя/состояние.
- `lang` задаётся отдельно для UI, стимула и вариантов ответа.
- Цвет не является единственным признаком выбранного теста.
- Анимации продолжают учитывать `prefers-reduced-motion`.
- Не допускаются горизонтальный скролл и обрезка текста на 375, 768, 1024 и 1440 px.
- Асинхронная загрузка не должна создавать скачок основной геометрии.

## 7. Ошибки и граничные случаи

- Неизвестный `test` → безопасный `en` с нормализованным состоянием.
- Неизвестный `ui` → сохранённый выбор или браузерная локаль.
- Недоступный `localStorage` → выбор работает в памяти до закрытия страницы.
- Смена UI-языка во время теста немедленно переводит chrome страницы, но не сбрасывает вопрос, таймер или ответы.
- Смена UI-языка при открытом сертификате синхронизирует последующее открытие; текущий сертификат сохраняет ручной контроль RU/EN.
- Ошибка одного банка не блокирует выбор и запуск другого.
- Повторный тест сохраняет выбранный проверяемый язык.
- Share-ссылка содержит выбранный тест и, когда пользователь явно переключал UI, выбранную локаль.

## 8. TDD и критерии приёмки

До production-изменений добавляются падающие тесты. Обязательные группы:

### 8.1. Locale и URL

1. `ru-*` браузер без сохранённого выбора получает RU; остальные браузеры — EN.
2. Ручной выбор сохраняется и имеет приоритет при следующем визите.
3. Валидный `ui` в URL имеет приоритет; неизвестный игнорируется.
4. `test` выбирает правильный банк; неизвестное значение даёт `en`.
5. Смена UI переводит текущий экран без сброса попытки.

### 8.2. Банки

Для каждого из пяти банков проверяются:

1. ровно 240 заданий и 40 на каждый уровень A1–C2;
2. уникальные ID с правильным языковым префиксом;
3. обязательные поля, четыре уникальных ответа и корректный индекс;
4. отсутствие запрещённых метаответов и нормализованных дублей;
5. баланс skills/formats и позиций правильного ответа;
6. наличие верхнеуровневых доказательных заданий C1/C2;
7. детерминированная сборка source-файлов в production JSON;
8. полное совпадение web- и server-копии, если backend использует банк.

### 8.3. Engine

Одинаковая симуляционная матрица прогоняется по всем пяти банкам:

- все ошибки/пропуски не повышают уровень и завершаются не позже 20 вопросов;
- последовательные правильные ответы поднимают сложность не больше чем на ступень;
- C1/C2 невозможно получить без прямых доказательных заданий соответствующей сложности;
- одна позиция ответа не даёт систематического преимущества;
- каждый маршрут завершается и не повторяет вопрос.

### 8.4. UI и сертификат

1. Лендинг, question, result, certificate и CTA проверяются в матрице 5 test languages × 2 UI locales.
2. На английском экране не остаётся русского UI-текста, а на русском — случайных английских служебных подписей, кроме брендов и содержимого проверяемого языка.
3. Сертификат по умолчанию совпадает с UI locale и называет правильный проверяемый язык.
4. PNG/print/share/CTA используют выбранный язык и не ведут на 404.
5. Переключатель языка и группа тестов доступны с клавиатуры и screen reader.
6. Мобильный viewport 375×812 и desktop 1440×900 проходят без горизонтального скролла и перекрытий.

### 8.5. Аналитика

1. Без consent новые события не отправляются.
2. С consent событие содержит allowlisted `testLanguage`, `uiLocale` и точный `bankVersion`.
3. Имя сертификата не попадает в payload.
4. Старые английские payload остаются валидными для backend.

## 9. План поставки

Работа разбивается на последовательные этапы с одним production writer:

1. locale/URL/config contracts и RU/EN UI;
2. динамический сертификат и аналитический контракт;
3. универсальный pipeline банков и усиленные валидаторы;
4. немецкий банк A1–C2;
5. французский банк A1–C2;
6. итальянский банк A1–C2;
7. испанский банк A1–C2;
8. общая симуляция, browser matrix, cache busting и release verification.

До финального релиза текущий английский тест должен оставаться работоспособным. Публикация выполняется только через Firebase Hosting target `knowlywww`; административная панель и мобильное приложение не изменяются без отдельной необходимости.

## 10. Не входит в эту итерацию

- аудирование, произношение, письменные ответы и TTS;
- официальная аккредитация или заявление о полной CEFR-квалификации;
- отдельные SEO-страницы для пяти языков;
- дополнительные UI-локали помимо русского и английского;
- изменение адаптивной математики без отдельного доказанного дефекта;
- обещание, что Phraseman обучает четырём новым языкам.

## 11. Definition of Done

Функция считается готовой только когда:

- все пять банков имеют 240 валидных уникальных заданий A1–C2;
- пользователь может выбрать любой тест, пройти его и получить соответствующий результат;
- каждый экран полностью работает на RU и EN;
- первый UI-язык определяется браузером, а ручной выбор сохраняется;
- сертификат автоматически совпадает с UI-языком и правильно называет тест;
- узкие unit/contract/simulation/E2E-проверки проходят свежим запуском;
- live-страница после целевого деплоя отдаёт новые versioned assets и проходит короткий production smoke test.
