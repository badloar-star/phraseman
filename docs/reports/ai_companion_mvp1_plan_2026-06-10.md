# MVP-1 killer-фичи: детальный план реализации (бумага)

> Дата: 2026-06-10. Основано на стратегии [ai_companion_strategy_2026-06-10.md](./ai_companion_strategy_2026-06-10.md) §8 и реальном коде.
> **Гейт:** этот план кодим ТОЛЬКО после зелёного света Спайка 0 ([spike0_voice_measurements](./spike0_voice_measurements_2026-06-10.md)) — если голос «мёртвый» на бюджетном Android или TTS роботный, часть архитектуры меняется (облачный TTS / стриминг раньше).
>
> Цель MVP-1: **самый тонкий скелет, доказывающий killer-гипотезу** — «русскоязычный учащийся захочет регулярно говорить вслух с Филом, который помнит его ошибки, и вернётся». НЕ строим: стриминг/barge-in, оракул-RAG, экран «Наш путь», hands-free (это fast-follow после подтверждения).

---

## 0. Что МЕРЯЕМ (метрика успеха MVP-1)

НЕ «время в приложении». Три прямых сигнала killer-гипотезы (через существующий `analytics.ts` / PostHog):
- **D7-retention** когорты, попробовавшей голос.
- **Слов сказано по-английски за сессию** (proxy выученного output; RCT Duolingo: именно это предсказывает прогресс).
- **Возврат на 2-ю сессию** (самый честный тест «хочет вернуться»).

## 2. Три пласта работ (волнами, как прошлые фазы)

### Wave 1 — Backend: режим `companion` + память (CF)

**Файл:** `functions/src/premium_dialog.ts` (расширить, НЕ ломать `scenario`).

1. **Новый режим `companion`** рядом со `scenario`:
   - Снять жёсткое `if (mode !== 'scenario') throw` → допустить `'scenario' | 'companion'`.
   - `buildCompanionSystemPrompt(cefr, memory)` — открытый дружеский разговор, БЕЗ роли/сценария.
2. **Промпт-инварианты** (из стратегии — обязательны):
   - «Вход = шумный ASR речи изучающего; угадывай намерение, НИКОГДА не придирайся к артефактам распознавания, не говори "не понял" из-за мелких ошибок».
   - «В потоке — только мягкие recast'ы, без явных исправлений и мета-комментариев» (уже есть в `GLOBAL_RULES`).
   - **Реинъекция CEFR**: добавить строку про уровень в КОНЕЦ промпта (не только в начало) — против alignment-drift к нативной сложности за ~9 ходов.
   - Ключевые фразы `[[...]]` — уже добавлено (подсветка).
   - **НЕ романтика / crisis-handling** (гард-рейл персоны): «ты платонический друг-коуч; на романтику мягко уводи; на сигналы селф-харма дай ресурсы, не продолжай игру».
3. **Память в промпт** (приходит из клиента в поле `memory`, собирается клиентом из SRS + профиля):
   ```ts
   interface DialogMemory {
     profile?: string;      // "Уровень A2. Цель: работа. Родной: русский."
     weakWords?: string[];  // top-K из getTrainerPremiumItems('weak')
     summary?: string;      // rolling-резюме прошлых разговоров (пока пустое в MVP-1)
   }
   ```
   Инъектить как system-строку: «Ты помнишь об ученике: {profile}. Слова, с которыми он мучается (вплети их естественно, заставь произнести): {weakWords}. Ранее: {summary}». Это и есть «он меня знает».
4. **Prompt caching** системного промпта (большой статичный блок) — обязательно (стратегия §5.1): экономит 59–81% input.
5. **Серверный fair-use cap** — уже есть `enforceDailyQuota`/`enforceRateLimit`; для premium `companion` поднять cap, но не «безлимит» (premium cap 100/день уже стоит).
6. **deploy:safe whitelist** — добавить новый/изменённый эндпоинт (грабли проекта [[phraseman-admin-alerts]]).

**Acceptance Wave 1:** `mode:'companion'` отвечает с учётом `memory`; tsc зелёный; задеплоено point-to-point `firebase deploy --only functions:premiumDialogSend`.

### Wave 2 — Клиент: голос+текст нить + сбор памяти

**Новый файл:** `app/ai_companion_session.tsx` (по образцу `spike_voice.tsx` + `ai_dialog_session.tsx`).

1. **Одна гибридная нить** (стратегия §6.3): hold-to-talk ИЛИ печатать; каждая устная реплика → текст; реплики Фила с подсветкой фраз (переиспользуем `ai_dialog_markup`) + тап-озвучка.
2. **3 состояния** (Слушаю/Думаю/Говорю) + живая волна (на старте — простой индикатор, без барж-ина).
3. **Сбор `memory` на клиенте** перед вызовом:
   - `profile` — из прогресса/настроек (CEFR, studyTarget, цель если есть).
   - `weakWords` — `await getTrainerPremiumItems('weak', 5, studyTarget)` → `.map(i => i.en)` (или поле фразы).
   - `summary` — в MVP-1 пустой (rolling summary — Wave 3 / fast-follow).
4. **Подсказки-ответы** (анти-«пустой микрофон»): 2–4 тапабельных + «скажи за меня» на каждом ходу.
5. **Вход** — «Поговори с Филом» (открытый), не «выбери сценарий». Сценарии — вторичная полка (не удалять `ai_dialog_scenarios.ts`).
6. **Лимит free** — `dialogs_limit_session.ts` (1 разговор/день) + пейвол `dialog_limit` (уже есть контекст).

**Acceptance Wave 2:** можно проговорить разговор голосом; Фил «знает» слабые слова (видно, что вплетает); tsc зелёный.

### Wave 3 — Контур обучения: recap → SRS + Day-0

1. **After-session recap** (отдельный дешёвый вызов, по образцу explain-стека): 2–3 ключевые ошибки + похвала на русском.
   - Записать ошибки обратно в SRS (`logMistake` / `markTrainerResult` — это «контур», ваш ров).
   - Экран-репорт по образцу `trainer_session_report.tsx`.
2. **Day-0 поток** (стратегия §6.5): заговорить <60 с, без анкеты/теста; Фил говорит первым; пейвол ПОСЛЕ первой ценности.
3. **Аналитика killer-метрик**: `words_spoken_per_session`, `returned_2nd_session`, D7-cohort.

**Acceptance Wave 3:** разговор → ошибки попали в повторение; Day-0 активирует речь; метрики пишутся.

## 3. Что ЯВНО НЕ в MVP-1 (fast-follow после подтверждения гипотезы)

- Стриминг (SSE) + TTS-по-первому-предложению + barge-in.
- Оракул-RAG (10k фраз + judge) — отдельный инкремент; в MVP Фил просто мягко объясняет в потоке.
- Экран «Наш путь», hands-free, whisper.rn «высокая точность», vector-store, knowledge-tracing v2, возрастная адаптация тона.
- Гео-A/B цены, 7-дневный триал A/B — после activation-сигнала.
- Облачный русский TTS для оракула — когда будет оракул.

## 4. Риски реализации (из стратегии + кода)

| Риск | Митигация в плане |
|---|---|
| Промпт «говори B1» дрейфует к нативной сложности | Реинъекция CEFR в конец промпта + пост-упрощение (Wave 1) |
| ASR врёт на акценте → Фил «исправляет» несуществующее | Промпт-инвариант «не придирайся к ASR» (Wave 1) |
| Identity-баг (stableId из body) | `resolveStableUidForAuth(db, request.auth.uid)` — уже правильно в premium_dialog |
| Новый CF не задеплоится | deploy:safe whitelist + point-to-point deploy |
| Квадратичный рост токенов | rolling summary вместо сырой истории (Wave 3) + prompt caching (Wave 1) |
| Параллельные сессии Claude | Работать в master, атомарные коммиты, не worktree (правило проекта) |

---

## 5. Порядок (после гейта Спайка 0)

1. Wave 1 (CF: режим companion + память + инварианты) → деплой → проверить ответы.
2. Wave 2 (клиент: голос+текст нить + сбор SRS-памяти) → живой тест на телефоне.
3. Wave 3 (recap→SRS + Day-0 + метрики) → замер D7/возврата.
4. Гейт MVP-1: если D7 и возврат-на-2ю растут → fast-follow (стриминг/оракул). Если нет → разбор почему.

### Итог простыми словами
- Это план «скелета» главной фичи — что и в каком порядке кодить, когда проверка голоса даст зелёный свет.
- Сначала серверная часть: научить Фила вести открытый разговор и помнить слабые слова человека (берём из уже готовой истории ошибок).
- Потом экран: говоришь голосом или пишешь, Фил отвечает и подсвечивает полезные фразы, всегда есть подсказки, чтобы не молчать в микрофон.
- Потом «контур»: после беседы Фил коротко разбирает 2-3 ошибки и кладёт их в повторение — это то, чего нет у бесплатного ChatGPT и что трудно скопировать.
- Что НЕ делаем пока: ускорение голоса по-сложному, всезнайку-оракула, лишние экраны — только после того, как докажем, что люди возвращаются говорить второй раз.
- Главная проверка — не «сколько сидят», а «вернулись ли поговорить снова и сколько сказали вслух».
