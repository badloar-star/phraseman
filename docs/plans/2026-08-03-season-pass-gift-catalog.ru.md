## 0. Общая инфраструктура подарка (нужна для ВСЕХ позиций ниже)

**Проблема, вскрытая аудитом**: единого инвентаря подарков в коде НЕТ. Три источника
(level_gift, friend_gifts, league_chest) хранят состояние тремя разными структурами:
- `app/level_gift_inventory.ts` — record-by-level в AsyncStorage, `expiresAtMs` вычисляется
  на лету как `receivedAtMs + GIFT_TTL_MS`.
- `app/friend_gift_inventory.ts` — плоский массив, та же формула TTL, **отдельная** реализация.
- League chest — вообще не «висит», клеймится и применяется одним действием без инвентаря.

`app/gift_expiry.ts` (уже написан параллельной сессией) — это ТОЛЬКО константа
`GIFT_TTL_MS = 72ч` + UI-хелперы (`giftCountdownLabel`, полночь для «первого показа»).
Хранилища подарков как типа он не задаёт.

**Решение для Season Pass**: НЕ плодить четвёртую отдельную структуру. Ввести единый тип
`SeasonPassGiftItem` и единую точку чтения/записи в новом файле `app/season_pass_gift_inventory.ts`,
по образцу `level_gift_inventory.ts` (та же формула TTL, тот же паттерн «фильтруем просроченные
при каждом чтении»), но с явным умыслом: как только эта работа появится, старые три источника
следует ПОСТЕПЕННО мигрировать на общий тип (отдельная задача, не в рамках Season Pass v1 —
помечено в 🧩-итоге, не блокирует запуск).

```ts
type SeasonPassGiftKind =
  | 'battery_full' | 'league_boost_x2' | 'league_group_boost' | 'golden_lesson'
  | 'collection_magnet_24h' | 'turbo_regen_24h' | 'tournament_ticket'
  | 'streak_time_machine' | 'choice_3';

interface SeasonPassGiftItem {
  id: string;               // `${seasonId}:${level}:${slotIndex}`
  kind: SeasonPassGiftKind;
  payload?: Record<string, unknown>;   // для choice_3 — варианты; для остальных пусто
  receivedAtMs: number;
  expiresAtMs: number;      // receivedAtMs + GIFT_TTL_MS, ЕДИНАЯ формула из gift_expiry.ts
  claimed: boolean;
}
```

**Анти-абьюз, общий для всех расходников**: серверная идемпотентность через
`reward_claims/{uid}_season_{seasonId}_{level}` (Firestore-транзакция) — тот же паттерн,
что `daily_tasks_all_shards_{dayKey}` в `functions/src/daily_tasks_shards.ts`. Повторный вызов
с тем же `(seasonId, level)` возвращает `alreadyClaimed: true`, не начисляет повторно.

## 1. Расходники (копятся в «Подарках», активируются вручную)

### 1.1 Батарея энергии — `battery_full`
**Что делает**: мгновенно `current = maxEnergy` (полный заряд), без похода в магазин.
**Статус**: 🟢 готовый кубик. Один в один код подарка `energy_full` из
`app/level_gift_system.ts:1288-1294` — `setEnergy(maxEnergy)` + запись `energy_state`.
**Количество на дорожке**: 5 штук (уровни 6, 13, 22, 34, 48 — растущий интервал).
**Анти-абьюз**: активация мгновенная и локальная (не требует сети), поэтому идемпотентность
только на этапе КЛЕЙМА подарка с дорожки (см. §0), не на этапе активации из инвентаря.
**Стак в инвентаре**: без лимита (таймер 72ч сам чистит, см. §0 общей инфраструктуры).
**Pro-эквивалент**: Pro и так безлимитная энергия → подарок автоматически превращается
в **3 жемчужины** при получении (Pro никогда не видит бесполезную батарею в инвентаре).

### 1.2 Буст лиги ×2 — `league_boost_x2`
**Что делает**: активирует персональный буст лиги на выбранной длительности.
**Статус**: 🟢 готовый кубик, но нужен ОДИН новый вариант в константе.
`app/league_personal_boosts.ts:22-27` уже содержит `x2_30m`/`x2_1h`/`x2_2h`/`x3_15m`.
Для Season Pass нужен `x2_until_end_of_day` (владелец выбрал «до конца дня» в опроснике,
в.32 → а) — этого варианта в массиве ещё нет, добавить пятую запись:
```ts
{ id: 'x2_eod_pass', multiplier: 2, durationMs: /* до ближайшей UTC-полночи, вычисляется динамически */, costShards: 0 }
```
Активация из подарка вызывает `activateLeagueBoost('x2_eod_pass')` напрямую — **минуя**
`spendShards` (это подарок, не покупка).
**Количество на дорожке**: 4 штуки (уровни 10, 24, 38, 52 — примерно раз в главу+).
**Анти-абьюз**: `activateLeagueBoost` уже проверяет, нет ли активного буста — повторная
активация до истечения текущего не складывается (не читал точный guard, но паттерн
персональных бустов в коде такой — один активный буст, не стек).

### 1.3 Тотем клуба — `league_group_boost`
**Что делает**: +10% очков лиги ВСЕЙ группе на день, с подписью «буст от {имя}».
**Статус**: 🟡 собрать из частей. `app/league_group_boosts.ts` уже даёт готовый групповой
буст ×2 на 3 часа за 50 жемчужин (`LEAGUE_GROUP_BOOST_MULTIPLIER=2`,
`LEAGUE_GROUP_BOOST_DURATION_MS=3ч`) — но это НЕ +10%, это ×2. У владельца в диалоге
запрошено именно «+10%» как отдельная, более мягкая механика (тотем — частый подарок,
не редкий джекпот).
**Решение**: переиспользовать серверную инфраструктуру (`league_groups.ts`, транзакция,
`groupBoost` поле в `league_groups/{groupId}`), но добавить второй тип буста
`groupBoostKind: 'x2_3h' | 'totem_10pct_24h'` в тот же документ, чтобы не плодить
параллельную коллекцию. Готовый прецедент бесплатной активации уже есть: поле
`progress.club_gift_free_boost_v1` (`league_groups.ts:808-813`) гасит ваучер в той же
транзакции, что активирует буст — Season Pass повторяет тот же паттерн с новым ключом
ваучера `progress.season_totem_voucher_v1`.
**Количество на дорожке**: 3 штуки (уровни 15, 33, 50 — редкий, статусный подарок).
**Анти-абьюз**: тот же guard, что у группового буста ×2 — если в группе уже активен
буст (любого типа) от другого игрока, второй активировать нельзя до истечения
(`already-active`, `league_groups.ts:801`). Один буст в группе одновременно.

### 1.4 Золотой урок — `golden_lesson`
**Что делает**: следующий пройденный урок даёт ×3 XP + гарантированный дроп коллекции.
**Статус**: 🟡 собрать из частей. XP-часть — паттерн `xp_boost` из `league_chest.ts`
(множитель + `remainingUses`, декремент при `registerXP`), но здесь `remainingUses: 1`
(разово, не 3). Дроп-часть — новый персональный множитель шанса (см. §1.5, тот же примитив).
**Реализация**:
```ts
progress.season_golden_lesson_v1 = JSON.stringify({ multiplier: 3, remainingUses: 1, guaranteedDrop: true, expiresAt })
```
Клиентский `consumeSeasonGoldenLessonMultiplier()` — калька с `consumeLeagueChestXpOverrideMultiplier`
(`app/services/league_chest_rewards.ts:441-462`), но дополнительно взводит флаг
`guaranteedDrop` для следующего вызова `collectiblesClaimDrop` (передаётся параметром
callable, сервер форсирует шанс 100% на этот один вызов — та же логика, что уже есть
для ПЕРВОЙ карточки за всё время, `state.total === 0` в `collectibles.ts:311`, только
триггер другой).
**Анти-абьюз**: `remainingUses: 1` + серверная проверка `expiresAt` (72ч на активацию,
эффект действует до первого урока ПОСЛЕ активации, не 72ч на сам эффект).
**Защита от абьюза коротких уроков**: не применяется к повторным/тренировочным урокам
короче N карточек (порог сверить с существующим гейтом `lesson_first`/`lesson_completed`
в `shards_system.ts`, там уже есть разделение «настоящий» урок vs повтор).
**Количество на дорожке**: 6 штук (уровни 4, 12, 20, 30, 41, 55).

### 1.5 Магнит коллекции — `collection_magnet_24h`
**Что делает**: 24 часа двойной шанс дропа карточек коллекции.
**Статус**: 🔴 с нуля, но точка внедрения известна и узкая. `flatDropChance` (0.15 дефолт)
глобальный, персонального множителя нет вообще. Нужно:
1. Новое поле в `progress`: `progress.season_collection_magnet_v1 = { multiplier: 2, expiresAt }`.
2. В `functions/src/collectibles.ts`, в `collectiblesClaimDrop` (строка 444-457, где уже
   читаются `isPremium`/`owned`/`state`) — добавить чтение этого поля ДО вызова
   `rollCollectibleDrop`, домножить `dropConfig.flatDropChance` на `multiplier`, если
   `expiresAt > now` (капнуть итоговый шанс на 1.0, если он мог бы превысить).
**Количество на дорожке**: 4 штуки (уровни 8, 26, 44, 58).
**Анти-абьюз**: чтение поля происходит СЕРВЕРНО внутри уже существующей Firestore-
транзакции (не новая точка входа с нуля, а расширение существующей) — клиент не может
подделать множитель.

### 1.6 Второе дыхание — `turbo_regen_24h`
**Что делает**: сутки энергия восстанавливается ×2 быстрее.
**Статус**: 🟢 готовый кубик. `applyTurboRegenOverride()` (`app/boons/boon_effects_energy.ts:33`)
уже делает ровно это — вызывается без параметров, сама вычисляет `base/2` и `expiresAt`
до конца текущих UTC-суток. Для подарка Season Pass дёргаем эту функцию напрямую при
активации из инвентаря, минуя дневной guard бунов (`boon_bootstrap.ts` дневная проверка
не блокирует прямой вызов).
**Важный нюанс из аудита**: длительность не фиксированные 24ч, а «до конца текущих
UTC-суток» — реалистично 0-24ч в зависимости от момента активации. Это ОК для подарка
(«второе дыхание сегодня»), но текст в UI должен говорить «до конца дня», не «24 часа»,
чтобы не создавать ложных ожиданий (соответствует правилу честности таймеров из ресерча).
**Совместимость**: уже есть логика «min из активных» с league-chest бустом энергии
(`energy_system.ts:78-94`) — если у юзера уже активен `energy_fast_recovery` из сундука
лиги, эффекты не конфликтуют, берётся более быстрый.
**Количество на дорожке**: 4 штуки (уровни 11, 27, 42, 56).

### 1.7 Билет на турнир — `tournament_ticket`
**Что делает**: вход в турнир без списания жемчужин-ставки.
**Статус**: 🟡 собрать из частей, но проще, чем казалось на входе. `entryGems: 0` —
уже штатно поддерживаемое значение в `normalizeTournamentEconomy`
(`functions/src/tournament_economy.ts:72-75`, явный комментарий владельца
«ноль = бесплатный вход, законная настройка»). Это конфиг СЛОТА турнира целиком,
не билет конкретного игрока.
**Решение для персонального билета** (не трогая экономику слота для всех): нужен
отдельный флаг на юзера, который сервер проверяет ПЕРЕД списанием `entryGems` при входе
в конкретный слот — `progress.season_tournament_ticket_v1 = { usesLeft: 1, expiresAt }`,
списание жемчужин при входе пропускается, если флаг активен и `usesLeft > 0`, инкремент
`usesLeft` не нужен (потребление = decrement до 0 в той же транзакции входа).
**Куда именно патчить**: точка реального списания `entryGems` — в `functions/src/tournaments.ts`
(сам `tournament_economy.ts` только чистая арифметика, не пишет в Firestore) — аудит
не нашёл точную строку, нужен дополнительный точечный grep перед реализацией.
**Количество на дорожке**: 3 штуки (уровни 17, 35, 53).
**Анти-абьюз**: `usesLeft` декрементируется в ТОЙ ЖЕ транзакции, что и вход в турнир
(атомарно) — гонка невозможна, повторный клик не даёт два бесплатных входа.

### 1.8 Машина времени — `streak_time_machine`
**Что делает**: чинит вчерашнюю дыру в серии задним числом.
**Статус**: 🟡 собрать из частей. `streak_repair.ts` (упомянут в общем аудите стриков
ранее в диалоге) уже содержит `wasRepairedToday()` — логика починки существует для
других источников (щит карточки, Chain Shield). Нужно добавить Season Pass как ЕЩЁ
один источник срабатывания того же каскада спасителей в `updateStreakOnActivity()`
(`app/hall_of_fame_utils.ts:232-388`), с приоритетом НИЖЕ, чем уже существующие бесплатные
щиты (машина времени — редкая премия, должна расходоваться только когда бесплатные
спасители исчерпаны).
**Ограничение по времени**: работает ТОЛЬКО для вчерашнего дня — если пропущено 2+ дня,
подарок не активируется (нельзя чинить многодневные дыры одним расходником, иначе это
конкурирует с платным `streak_revive.ts`, который явно линейно дороже для длинных дыр).
**Количество на дорожке**: **редко, 2 штуки за весь сезон** (уровни 39, 60 — премия,
не рутина, как договорено в опроснике в.37).
**Анти-абьюз**: серверная проверка `lastActiveDate` перед починкой — если разрыв больше
1 дня, callable возвращает ошибку `gap_too_large`, расходник НЕ тратится (иначе юзер
злится, что подарок исчез без эффекта).

### 1.9 Подарок другу (батарея/буст, НЕ жемчуг) — переиспользует `friend_gifts`
**Что делает**: отправляет другу батарею энергии или буст лиги (не жемчуг — решение
из диалога, чтобы не привлекать мультиаккаунт-фарм).
**Статус**: 🟡 собрать из частей, но с важным предупреждением от аудита. Клиентский
каталог `FRIEND_GIFT_CATALOG` (`app/friend_gifts.ts`) и серверный `GIFT_CATALOG`
(`functions/src/friend_gifts.ts:56-83`) уже РАСХОДЯТСЯ — клиент знает про `arena_extra_5`,
сервер не знает (нерабочий пункт в проде). **Прежде чем добавлять новый вид подарка,
нужно сначала синхронизировать существующее расхождение** (отдельная минимальная
правка вне Season Pass, но блокирующая — иначе третий несинхронизированный вариант
усугубит баг).
**Новый вид**: `season_battery_share` — добавить В ОБА каталога синхронно, обработка
на сервере в `buildRecipientGiftPatch` (`friend_gifts.ts:281-312`) — по аналогии с
`chain_shield_1` (инкремент счётчика), здесь: `setEnergy` получателя до максимума
(тот же эффект, что `battery_full`, но применяется получателю, не отправителю).
**Ограничение по частоте**: переиспользует существующие дневные лимиты
(`MAX_DAILY_GIFTS_TOTAL=3`, `MAX_DAILY_GIFTS_PER_FRIEND=1`) — Season Pass не меняет
общие лимиты дружеских подарков, просто добавляет ещё один вид ВНУТРИ уже
ограниченного бюджета.
**Количество на дорожке**: 2 штуки (уровни 19, 46) — сам подарок-предмет даёт ОДНУ
отправку батареи другу (не постоянную возможность).

## 2. Узлы «выбери 1 из 3» — `choice_3`

**Статус**: 🟢 готовый кубик паттерна. `choice_3_level` уже существует для подарков за
уровень (`app/level_gift_system.ts`, milestone-логика) — переиспользуем ТОТ ЖЕ UI-паттерн
выбора, только с другим набором вариантов на вход.
**Варианты на каждом узле**: батарея / буст лиги / жемчуг (фиксированный набор из трёх,
не рандомизируется — постоянство важно, юзер должен понимать, что выбирает).
**Количество на дорожке**: 5 штук (уровни 6, 18, 29, 40, 51).
**Анти-абьюз**: выбор фиксируется в той же claim-транзакции (§0) — нельзя выбрать
дважды, `reward_claims` документ хранит какой именно вариант был выбран.

## 3. XP-ускорители дорожки (наполнители середины)

### 3.1 XP-банк (×2 на следующие N XP)
**Статус**: 🟢 готовый кубик — уже существует как подарок за уровень (`xp_bank_150` —
явно упомянут в общем аудите наградных систем как гарантированная веха-5 награда).
Переиспользуем как наполнитель Season Pass без изменений кода.
**Количество на дорожке**: 4 штуки, разные номиналы (75/100/150/200 XP), уровни 3, 16, 32, 47.

### 3.2 Фокус-множитель

на дорожке как разнообразие наполнителей.
**Количество на дорожке**: 2 штуки (уровни 9, 37).

## 4. Валюта (жемчуг) — прямые номиналы без механики

Простейшая категория — просто `addShards(amount, 'season_pass_reward')` в claim-транзакции.
**Плотность на бесплатной дорожке**: суммарно 12 жемчужин за сезон (в.19 опросника → а),
раскидано по мелким узлам без вехи между крупными подарками.
**Плотность на платной дорожке**: суммарно ~210 жемчужин прямыми номиналами (плюс
эквиваленты дней Plus для Pro-юзеров, см. §5) — доводит self-refund до ~85% при полном
прохождении (в.2 опросника → б, PUBG-модель).

## 5. Время Plus (крючок конверсии) — фри-дорожка

**Статус**: 🟢 готовый кубик. Механика выдачи временного VIP уже существует в
`referral_spin_logic.ts` (`REFERRAL_SPIN_PRIZE_DAYS`) — Season Pass переиспользует ТУ ЖЕ
серверную функцию установки временного статуса, просто с другим триггером (claim уровня
вместо спина рулетки).
- **3 дня Plus** — уровень 12.
- **7 дней Plus** — уровень 33.
**Pro-эквивалент** (курс из рулетки, `REFERRAL_SPIN_PRIZE_PEARLS`): 3 дня → **25 жемчужин**,
7 дней → **70 жемчужин**. Подставляется автоматически на сервере при claim, если
`isPremiumAccessActive()` (`functions/src/premium_status.ts:236`) уже true — Pro никогда
не видит бесполезные дни подписки.

## 6. Статусные эксклюзивы (без таймера, платная дорожка)

Эти не «подарки в инвентаре» — применяются НАВСЕГДА при claim, не проходят через
72-часовой цикл §0 вообще (см. в.44 опросника — статус не сгорает).

> Решение владельца 2026-08-03: тема оформления как награда ОТМЕНЕНА (подтверждает
> в.25 опросника); вся «глубинная» номенклатура («Корона Глубины», «Хранитель Рифа»,
> главы-моря) отменена — названия нейтральные («Сезон 1», «стадия I..IV»).
> Переливающийся ник утверждён как финальная награда.

**Ауры (решения владельца 2026-08-03):** финальный вихрь утверждён эталоном (бывшая
«стадия II» повышена до финала), стадии I-III перегенерированы как нарастающая линейка
к нему — **вся линейка из четырёх утверждена владельцем («окей оставляем»)**. Готовые
ассеты лежат в `assets/images/season/` (aura_stage1..3.webp, aura_final.webp + 7 иконок
наград reward_*.webp; иконка отклонённой карточки не сохранялась). Ассеты — сгенерированные изображения-кольца (прозрачный центр и фон), анимация
только пульс (scale) и/или медленное кручение (rotate) — Animated.Image, native driver.

любую из открытых, стадии не заменяют друг друга, а копятся как предметы.
**Ник:** в списках ЧИСТЫЙ (цвет или перелив), плашек-титулов под ником НЕТ нигде.
