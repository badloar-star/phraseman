# E2E блока «Звук» — чек-лист для Сверки, 05.11

Governance-ID: TG-2876B76F831D

Кто пишет: Learning V2. Тестируется аудио-WIP в общем дереве (Metro), в HEAD его ещё нет: смена режима звука возвращает исход `applied` / `failed` / `timed_out`, озвучка и запись стартуют только при `applied`. Тесты и типы зелёные; на устройстве НЕ проверено. Ожидаемые логи ниже взяты из кода; точный текст строк воспроизведения фразы (`[PHRASE-AUDIO]`, `[SOUND-AUDIT]`) зависит от ветки — смотреть по префиксу.

Сбор логов: `.expo/metro-console.log`, фильтр `AUDIO-ARBITER|SPEAK-MIC|SOUND-AUDIT|PHRASE-AUDIO|SPEECH|VIDEO-PLAYER|SLOW-REPEAT`.

## Главные строки

| Строка | Смысл |
|---|---|
| `[SPEAK-MIC] audio-mode:outcome {"intent":"spoken","revision":N,"outcome":"applied"}` | смена режима прошла; intent: `ui` / `spoken` / `recording` |
| `[SOUND-AUDIT] audio_mode:timeout {"afterMs":~1500,...}` | нативный переход не ответил за 1,5 с (исход `timed_out`) |
| `[AUDIO-ARBITER] spoken not ready {"activityReady":..,"claimCurrent":..,"voiceEnabled":..,"recordingActive":..}` | озвучка НЕ стартовала; поле `false` называет причину |
| `[AUDIO-ARBITER] recording not ready {...}` | запись НЕ стартовала |
| `[VIDEO-PLAYER] режим звука не вернулся failed\|timed_out` | после закрытия видео режим не вернулся |

## Сценарии (на каждом: пройти и записать «ок / строка лога / что услышали»)

1. **Холодный старт.** Запустить приложение. Ожидание: один `audio-mode:outcome` с `intent":"ui"` и `"applied"`. Не должно быть `timed_out`/`failed`.
2. **EN: озвучка фразы (записанный mp3).** Классика en, урок 1, тап по динамику. Ожидание: фраза слышна; `audio-mode:outcome` `spoken`/`applied`; нет `spoken not ready`.
3. **ES/FR/DE/IT: системный голос.** Для каждого языка по одной фразе урока 1. Ожидание: слышен голос нужного языка (es-ES, fr-FR, de-DE, it-IT); записать, какой голос выбрал телефон; нет `spoken not ready`. Если голоса нет — записать, как приложение себя ведёт (тишина/ошибка).
4. **Повтор 0,7×.** Второй тап по динамику той же фразы в течение 3 с. Ожидание: строка `[SLOW-REPEAT] on`, фраза звучит медленнее. Проверить и системный голос (es), и mp3 (en); для mp3 скорость не проверялась — записать факт.
5. **Быстрая смена: фраза → фраза.** Тапнуть динамик у трёх разных фраз подряд. Ожидание: звучит последняя, прошлая обрывается; нет залипшего звука; допустим `spoken not ready` только с `claimCurrent:false` у вытесненной.
6. **Диалог (озвучка реплики).** Открыть диалог, воспроизвести реплику; в меню реплики «Медленнее». Ожидание: звук есть, `applied`, повтор медленнее.
7. **Запись микрофона.** Экран с записью (диалог голосом или тренировка произношения): начать запись. Ожидание: `audio-mode:outcome` с `"intent":"recording"` и `"applied"`; состояние «слушаю» наступает; нет `recording not ready`. Остановить запись → `intent":"ui"|"spoken"` снова `applied`.
8. **Возврат из видео.** Открыть встроенное видео, закрыть. Ожидание: режим вернулся (`[VIDEO-PLAYER] закрыт — возвращаю режим звука приложения`, затем `outcome ... applied`); после этого озвучка фразы работает (сценарий 2). Нет `режим звука не вернулся`.
9. **Тишина / перебивание.** (а) Включить беззвучный переключатель iOS: озвучка фразы — слышна или нет (записать). (б) Фоновая музыка (другое приложение): запуск озвучки — музыка глушится/приглушается и возвращается ли после. Эмулятор Android: пункт (а) неприменим, записать «н/п».
10. **Проверка 1,5 с.** Сразу после старта (до 5 с) тапнуть динамик, затем повторить на «нагруженном» ПК. Ожидание: озвучка стартует. Если в логе `audio_mode:timeout` + `spoken not ready {"activityReady":false...}` и фраза НЕ прозвучала — это дефект P1 «озвучка не стартует из-за 1,5 с»: приложить строки лога и сообщить Learning V2 (ретрай/увеличение таймаута делаю я).
