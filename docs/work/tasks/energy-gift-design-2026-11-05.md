# «Подарок энергии» (идея 9 «Друзей») — проектирование правила, сервера и клиента

Governance-ID: TG-ENERGY-GIFT-0511
Status: Проект (правила и контракты); код не начат. Флаг по умолчанию ВЫКЛ до проверки на устройстве.
Owner: «8 · МОМЕНТЫ» (правило, клиент) · «1 · ЯДРО» (сервер, правила базы, энергия) · «3 · МАКЕТЫ» (макет «Друзья» v2)

## Outcome

Владелец 05.11 (через координатора): «Подарок энергии» — РАЗРЕШИТЬ С ЛИМИТОМ. Опирается на решение 21.10 №43-Э («подарок копится сверх 5, восстановление идёт только до 5, получает одно устройство, на котором нажали „Забрать“»). Этот документ — предложение правила, серверного контракта и клиента; детали энергии подтверждает Ядро.

## 1. Правило экономики (предложение, консервативно)

| Параметр | Значение | Почему |
|---|---|---|
| Размер подарка | **+1 энергия** | 1 единица = 30 минут восстановления; не ломает «ровно 5 + бонус Пика» |
| Отправитель | **1 подарок в сутки** (в сутки по серверному дню, а не по часам телефона) | решение 21.10, не накручивается |
| Получатель | **не более 3 принятых подарков в сутки** | предел «всего +3/сутки» = 90 минут восстановления |
| Кому можно | только **принятым друзьям** (дружба двусторонняя, существует не менее 24 часов) | защита от накрутки новых пар |
| Себе | **нельзя** | |
| Получатель с Plus | **нельзя** (у Plus энергия не тратится): кнопка скрыта; если получатель стал Plus после отправки — подарок гаснет без ошибки | решение 21.10 |
| Хранение у получателя | «**копилка подарков**» на устройстве, максимум **3**; когда полна — новые подарки ждут на сервере (срок жизни 7 суток) | не накапливается бесконечно |
| Порядок траты | подарок тратится **первым**, затем обычная энергия | запас 5 и его восстановление не меняются; итог для человека тот же, что в формулировке владельца |
| Что НЕ меняется | `ENERGY_BASE_CAPACITY=5`, `ENERGY_BONUS_CAPACITY_LIMIT=0`, `SPIRE_ENERGY_BONUS_CAP=11`, сторожа энергии | копилка — отдельный счётчик, не запас; тесты-сторожа энергии не трогаются |

**Почему отдельная копилка, а не «запас выше 5».** Модель «запас > потолка» требует менять `energy_state_v2` (микро-единицы, ленивый пересчёт, сторожа «ровно 5/+бонус Пика»). Копилка меняет только место траты на старте занятия: `if gift > 0 → gift−1, иначе energy−1`. Для человека поведение то же: «сегодня прислали +3: если не хватает — выручит, если и так 5 — лежит сверху, потратил — дальше восстановление только до 5». Оговорка: решение по месту траты подтверждает Ядро (владелец энергии).

Влияние на монетизацию Plus (в `friends-ideas.html` помечено «бьёт по экономике Plus»): потолок «+3 в сутки на человека» и копилка 3 ограничивают эффект; метрику «конверсия в Plus до/после» смотреть неделю; выключатель — флаг.

## 2. Сервер (минимум чтений, идемпотентность, транзакция) — для «1 · ЯДРО»

Данные (создают и меняют только функции; клиент пишет в них нечего):
- `users/{получатель}/energy_gifts/{giftId}` — `{ fromUid, createdAtMs, status: 'pending'|'claimed'|'void', dayKey, expireAt }`. `giftId` детерминированный: `{отправитель}_{dayKey}` → повтор отправки в тот же день возвращает тот же подарок (идемпотентно).
- `energy_gift_quota/{uid}` — `{ dayKey, sent, received }` (один документ на человека, обновляется в транзакции; на смене дня сбрасывается).

Функции (callable, App Check не включаем):
1. **`energyGiftSend({ toUid, opId })`** — одна транзакция: (а) `auth`, `toUid ≠ uid`; (б) чтение `users/{uid}/friends/{toUid}` и `users/{toUid}/friends/{uid}` (дружба двусторонняя, `createdAt` ≥ 24 ч); (в) чтение `energy_gift_quota` отправителя и получателя: `sent < 1`, `received < 3`; (г) получатель не Plus (одно поле профиля/премиума); (д) запись подарка + инкремент счётчиков. ≈5 чтений, 3 записи на отправку. Ответ: `{ ok, giftId }` или `{ ok:false, reason: 'limit_sender'|'limit_receiver'|'not_friends'|'recipient_plus'|'self'|'too_new' }`.
2. **`energyGiftClaim({ giftId })`** — транзакция на документе подарка: `pending → claimed` (повтор возвращает `{ ok:true, already:true }`), проверка срока и Plus; ответ `{ ok, amount:1 }`. 1 чтение + 1 запись. Клиент зачисляет в копилку по ответу, **журнал применения** (см. §3) защищает от потери при падении между «забрал на сервере» и «зачислил на телефоне».
3. Уведомление получателю (пуш/колокольчик) через существующий конвейер: опрос ящика не нужен.
Правила базы: `energy_gifts` и `energy_gift_quota` — чтение только владельцем (`energy_gifts`), запись `if false`.
Удаление аккаунта: подарки получателя уходят с его деревом `users/{uid}`; подарки, отправленные удаляемым в чужие ящики, чистятся спекой collection-group `energy_gifts.fromUid` (+индекс COLLECTION_GROUP, сначала индексы, потом функция — как в аудите 05.11).
Политика конфиденциальности: новая запись связывает ID аккаунтов друзей и время → абзац в §6 политики (до выкладки функции).

## 3. Клиент (за флагом `energy_gift_enabled`, по умолчанию ВЫКЛ; вход через плитку «Занятие вдвоём», `FriendPairSheet`)

Отправитель:
- Кнопка «Подарить +1» в карточке друга. Тап → **мгновенно** «Отправлено ✓» и локальная отметка «сегодня уже дарил» (серверный день), хаптик управляющей кнопки; сеть догоняет фоном. Ошибка → откат кнопки и короткое понятное сообщение по `reason`. Защита от двойного тапа (`inFlight` по `toUid`).
Получатель:
- Входящие подарки показываются в «Друзьях» карточкой «Друг прислал +1 энергии · Забрать»: список из `users/{me}/energy_gifts` (`limit(3)`, `status=='pending'`), перечитывается при открытии вкладки не чаще раза в 30 мин (кэш), иначе по пушу — без опроса.
- «Забрать» → **мгновенно** +1 в копилку и «+1» на значке энергии, запись в журнал применения (`story_events_v1:energy_gift_apply:<владелец>` — стираемое семейство, ключ с `giftId`), затем `energyGiftClaim` в фоне; при отказе — откат копилки и сообщение; при успехе — журнал помечается завершённым. Повтор тапа игнорируется; поздний ответ не перетирает свежее локальное значение (last-write-guard).
- Копилка: ключ `story_events_v1:energy_gift_pool:<владелец>` (число 0..3); смена аккаунта сбрасывает память; тратится в точке «начало учебного занятия» перед обычной энергией.
- Энергия остаётся на телефоне: подарок получает то устройство, где нажали «Забрать» (решение 21.10).
Логи (префикс **`[ENERGY-GIFT]`**): отправка (кому-тег, исход, reason, мс), чтение ящика (откуда: кэш/сеть, сколько), забрать (giftId-тег, локально/сервер, откат), трата из копилки (до/после), КАЖДЫЙ ранний выход и `catch` с причиной.
Reduce Motion: pop значка и «+1» без анимации. Хаптик не на плитках.
