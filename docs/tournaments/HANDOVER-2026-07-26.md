## Как это работает

### Жизненный цикл турнира

```
за 10 мин: tournamentCreateRooms создаёт комнату
за 5 мин:  открывается лобби, можно войти
за 2 мин:  tournamentFillBots добирает ботов до 16
старт:     вход закрыт
```

Дальше цепочка состояний, которую ведёт крон `tournamentAdvanceRooms` (раз в минуту):

```
lobby → round1 → table1 → round2 → table2 → round3 → table3
      → round4 → final → results → rewards → closed
```

Тайминги (`tournament_core.ts`): таблица между раундами 12 сек, финал 5 сек,
результаты 5 сек, окно получения награды 24 часа.

### Раунды

4 раунда × 6 заданий = **24 вопроса**. Раскладка в `tournament_ai_blueprint.ts`
зеркалит `selectRoundTasks` в `tournament_core.ts`:

| Раунд | Режим | Сложность | Тип |
|---|---|---|---|
| 1 | single | [1] | assembly (собери фразу) |
| 2 | mix | [1,2] | все четыре |
| 3 | single | [2] | oddity (так не говорят) |
| 4 | mix | [2,3] | все четыре |

**ЛОВУШКА:** раунды 1 и 3 — `single`, сервер берёт ОДИН режим на весь раунд.
Если положить туда разные типы, `selectRoundTasks` не наберёт 6 заданий,
`buildRounds` вернёт null и комната отменится с возвратом жемчужин.

### Четыре типа вопросов

| Тип | Режим пула | Контракт | Пример |
|---|---|---|---|
| `situation` | `guess_phrase` | choice | «Официант принёс не то. Что скажешь?» + 4 англ. реплики |
| `gap` | `fill_gap` | choice | «I am looking ___ my keys» → for/at/after/to |
| `oddity` | `find_oddity` | choice | 4 фразы, одна — калька («I feel myself good») |
| `assembly` | `translate_build` | translate | банк слов + приманки |

**ЛОВУШКА assembly:** сервер (`verifyTournamentAnswer`) сверяет ПОРЯДОК токенов
точно. Если `tokens` не совпадают с `answer` по порядку — игрок не сможет
ответить верно НИКАК, а задание выглядит нормальным. Проверка стоит в
`tournament_ai_kind_items.ts` (`kind_tokens_answer_mismatch`).

### Экономика (решение владельца 2026-07-26)

- Вход: **3 жемчужины** (поле `shards` в документе пользователя)
- Платят ВСЕ 16 участников, включая ботов (у ботов — из казны игры)
- Полная комната: 16 × 3 = **48** в банке
- 20% (9) → недельный банк, 39 делятся 60/25/15 → **25 / 9 / 5**
- Недельный банк раздаётся кроном `tournamentWeeklyBankCron` в 00:10 UTC
  понедельника тройке лучших **по сумме очков за неделю**
- Настройки правятся из админки: `adminSetTournamentEconomy`

**Билеты УБРАНЫ полностью** — одна валюта. Файл `app/tournament_tickets.tsx`
ещё существует, но на него ничего не ведёт (можно удалить).

Формулы — `functions/src/tournament_economy.ts`, 19 тестов. Ключевое:
`splitByShares` гарантирует, что сумма выплат ВСЕГДА равна собранному
(остаток округления идёт победителю) — в проекте было 3 инцидента с пропажей
валюты, поэтому проверено на 200 значениях.

### Зрители

Кнопка «Смотреть турнир» на главной появляется, когда турнир идёт (вход уже
закрыт). Зритель видит ТУ ЖЕ таблицу, что игроки между раундами
(`app/tournament_table.tsx`, параметр `spectate=1`), но она постоянная и не
уводит в раунд.

**Почему только после закрытия входа:** турниру нужно 8 живых игроков, иначе
отмена. Зритель не должен отнимать участника.

Безопасность: правильные ответы лежат в `tournamentRooms/{id}/taskSecrets`,
закрытой для всех правилами. Документ комнаты содержит только имена, аватары,
очки, состояние.

## Известные проблемы и незакрытые хвосты

### 🔴 Блокеры запуска (данные, не код)

1. Расписание не создано → комнаты не создаются
2. Боты не засеяны (нужно ≥8) → комнаты не создаются
3. Пул заданий пуст → даже при созданной комнате раунды не наберутся

### 🟡 Незакрытое

- **Приложение не пересобрано.** Все правки экранов (кнопка «Смотреть», вход за
  жемчужины, «Скоро» вместо 00:00, убранные заглушки) в коде, но игроки их
  увидят только после сборки и выкладки. Правки клиента через хостинг НЕ
  доставляются.
- **Цвета турниров не следуют теме приложения.** Режим использует собственную
  палитру Deep Forest Green (`components/tournament/tournament_theme.ts`),
  перенесённую 1:1 из 47 утверждённых макетов. Владелец спросил, почему цвета
  «вырвиглазные» — решение о переводе на общую тему НЕ принято.
- `app/tournament_tickets.tsx` — мёртвый файл, можно удалить
- Форма настроек экономики в админке не сделана (функции есть:
  `adminSetTournamentEconomy` / `adminGetTournamentEconomy`)
- Тексты на `tournament_results.tsx` устарели: «50 жемчужин + титул», хотя приз
  теперь считается от банка
- Персональные уведомления (`user_notifications`) пишутся сервером, но ни один
  экран их не показывает — клиентский модуль есть, потребителя нет
- Поиск по тексту вопроса в админке не сделан (Firestore не умеет подстроку)

### ⚠️ Ловушки, стоившие времени

- **`node_modules` в `functions/` регулярно сносится** параллельными сессиями.
  Симптом: сотни ошибок `Cannot find module 'firebase-functions'`. Лечение:
  `cd functions && npm install --no-audit --no-fund`.
- **`lib/` блокируется** антивирусом при сборке (`error TS5033: UNKNOWN`).
  Лечение: `rm -rf lib && npm run build`.
- **Git часто занят** (`index.lock`) — коммитить в цикле с ожиданием.
- **`git worktree` запрещён хуком** — работать в общем дереве.
- Хук `FIREBASE-COST-GUARD` часто ложно срабатывает на серверных агрегатах —
  помечать `guard-ok` с обоснованием.

## Правила владельца, критичные для этого режима

- **Админка — только `admin/v2/legacy.html`.** Остальное заморожено.
- **Без обводок контейнеров.** Разделять тоном, тенью, скруглением.
- **Без подписей мелким шрифтом** под названием.
- **Без `adjustsFontSizeToFit`** — лечить переносом.
- **Optimistic UI обязателен**: мгновенный локальный апдейт, откат при ошибке,
  защита от двойного тапа.
- **Экран турниров ВСЕГДА рабочий** — никаких заглушек на весь экран.
- **Экономия Firestore**: агрегаты `count()` вместо выкачивания, батчи, лимиты.
