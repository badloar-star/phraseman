# Пейвол C — состояния и dev-входы для E2E (Maestro)

Governance-ID: TG-7D4A557FDC93

Для «Сверки». Всё ниже — только dev-сборка (`__DEV__` и не стор-сборка): в релизе параметры `_dev_state` игнорируются с записью в лог.

## Как открыть окно

Маршрут один: `/premium_modal`. Параметры: `context` (по умолчанию `generic`), `source` (по умолчанию `direct`), `_dev_state` (только dev).

```
phraseman:///premium_modal?context=<КОНТЕКСТ>&source=direct&_dev_state=<СОСТОЯНИЕ>
```

Либо в приложении: DEV-хаб → «Пейволы» → выбрать контекст → «Открыть Plus» (тот же диспетчер, `source=dev_hub`).

Окно НЕ откроется (по замыслу), если у аккаунта уже есть Plus (кроме `source=dialogue_v2_freeform_server`) или доступ ещё не определён (тогда ждёт). Для сценариев брать аккаунт без Plus.

## Контексты (сценарии), которые обязаны открываться

| Сценарий | context | Откуда в приложении |
|---|---|---|
| Ещё один язык (замок языка, новый пользователь) | `language_add` | тап по уроку запертого языка в списке / меню урока |
| Уроки 4+ классического курса | `course_after_lesson3` | тап по уроку 4+ без Plus |
| Все 3 бесплатных урока пройдены | `free_lessons_complete` | экран завершения урока |
| «Сегодня», Plus-ряд, настройки, истории | `generic` | настройки «Plus», карточка истории, сплэш |
| Энергия закончилась | `no_energy` | шторка остановки занятия |
| Лимит диалогов / закрытый уровень | `dialog_limit`, `dialog_locked_level` | раздел «Диалоги» |
| Карточки | `flashcard_limit`, `flashcard_create`, `pack_create`, `flashcard_training` | хаб «Карточки» |
| Серия / повышение уровня | `streak`, `level_up` | Главная, после уровня |
| Облако не подтвердило Plus | любой → `plus_server_refused` | подмена на «Восстановить / Оформить» |
| Замок раздела по рангу | пока отдельного контекста нет (см. «не покрыто») | — |

Полный список — 40 значений `PREMIUM_CONTEXT_VALUES` (`app/premium_context.ts`); тест `tests/paywall_c_context_matrix.test.ts` гоняет каждое по цепочке «разбор входа → тексты на 9 языках».

## Состояния окна (`_dev_state`)

`loading`, `live`, `reference`, `error_no_prices`, `billing_unavailable`, `purchasing`, `restoring`, `pending`, `unknown_outcome`, `status_unknown`, `store_promo`, `reminder_prompt`, `store_unreachable`.
Псевдонимы: `failed`→`error_no_prices`, `purchase_pending`→`pending`, `purchase_failed`→`unknown_outcome`, `promo`→`store_promo`, `checkout_error`→`store_unreachable`.

Что проверять в каждом (замки владельца):
- «Закрыть» и «Восстановить покупки» видны ВСЕГДА, во всех состояниях и контекстах (замок 25.10).
- Цены только из магазина (в `loading`/`error_no_prices` — без выдуманных цифр).
- Ряд плана: выбор годового/месячного, триал-строка у своего плана, акция (`store_promo`).
- Три строки выгод; для контекстного входа первая строка — выгода контекста.
- Светлая и тёмная тема; длинные цены (`₺ 12.345,67`) не обрезаются.

## Сценарии Maestro (набросок)

1. `language_add` → окно открылось, видны «Закрыть» и «Восстановить» → тап «Закрыть» → возврат на экран, откуда пришли (список уроков), урок не открыт.
2. `course_after_lesson3` + `lessonId=4` → пилюля с номером урока 4.
3. `generic&_dev_state=store_promo` → зачёркнутая цена + акция, кнопки на месте.
4. `generic&_dev_state=billing_unavailable` → сообщение «магазин недоступен», «Закрыть» работает.
5. `generic&_dev_state=purchasing` → кнопки заблокированы, «Закрыть» всё равно видна.
6. Тёмная ↔ светлая тема для `language_add` и `generic`.

## Не покрыто автотестами

- Замок раздела по рангу: отдельного контекста пейвола в коде нет — нужен ответ координатора, какой контекст/источник использовать.
- Покупка и восстановление — только вручную в тестовом режиме магазина (деньги на реальных аккаунтах не трогаем).
- Пиксельная сверка кадров C с утверждённым макетом — «Сверка».
- Реальный показ замка в списке уроков второго языка: правило выключено, пока `RANK_GATES_NEW_USERS_SINCE_MS` = максимум.
