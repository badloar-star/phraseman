# Task packet: «Очистить все ошибки» в разборе ошибок (ошибки не возвращаются)

Related epic/enabler: none

## Outcome

В списке «Все ошибки» есть пункт меню «Очистить все ошибки». После подтверждения все активные ошибки текущего курса сразу пропадают из экрана (оптимистично), а в журнал одной записью пишутся события 'hidden' (reason 'removed'). Старые ошибки не возвращаются ни после перезапуска, ни после переустановки, ни со второго телефона, ни после слияния облака. Новые ошибки, сделанные после очистки, появляются как обычно. Тост «Ошибки удалены» с кнопкой «Вернуть» (около 5 с) откатывает очистку событиями 'restored'.

Мера успеха: тесты (один батч-append, слияние облака не воскрешает, новая ошибка после очистки видна, «Вернуть» работает) зелёные; список после тапа пустеет в тот же кадр.

## Architecture

Журнал ошибок — набор неизменяемых событий; облако и телефон-состояние сливают объединением событий (mergeMistakeEventJournals), проекция (projectMistakes) сортирует по времени и считает последний статус. Событие 'hidden' с id из хеша (mistakeId, cycleId, type, occurredAtMs) идемпотентно. Очистка не удаляет события, а добавляет 'hidden': поэтому слияние облака не может воскресить ошибку (события только добавляются). Новая ошибка после очистки — событие 'captured' позже по времени, проекция возвращает её в active.
Данные ошибок на других курсах не трогаем: журнал ключуется по studyTarget.
Инвариант: одна запись журнала на очистку (mergeMistakeEvents с массивом), ни N записей.

## Security and privacy

Новых данных не собираем и не передаём: события 'hidden' уже существуют и синхронизируются тем же каналом, что и скрытие одной ошибки. Серверные правила не меняются. Политика конфиденциальности не затрагивается. Тосты и подтверждение не содержат личных данных.

## Technical debt

- Contain: отработка phone-state пишет по одному факту на событие (commitPhoneStatePracticeFact) — на сотни ошибок это сотни локальных коммитов подряд; экран при этом не ждёт (оптимистично). Выход: при росте жалоб на скорость — батч-коммит фактов; пометить в итоге для координатора.
- Accept temporarily: исправленные ошибки (вкладка «Исправлены») не очищаются — по постановке «все активные»; решение за владельцем через координатора.

Откат кода: revert коммитов. События 'hidden', уже записанные в журналы пользователей, остаются валидными (тот же тип, что и при «Удалить из ошибок»); вернуть ошибки можно событием 'restored' (функция restoreMistakes).
