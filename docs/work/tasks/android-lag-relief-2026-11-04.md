## Outcome

Диагноз по статике (`android_lag_diagnosis.md`, 04.11) нашёл причины лагов: тяжёлый граф V2 исполняется при открытии вкладки «Обучение»
(пока V2 заморожен), премаунт четырёх вкладок через 500 мс после кадра Главной, десятки перерисовок Главной из-за `setX` между `await`.
Владелец: замеров больше не делаем, облегчаем. Порядок: 2) ленивые V2-импорты, 4) премаунт только «Уроки», 3) сжатие обновлений состояния Главной,
5) memo-секции. Визуальный результат не меняется.

## Scope

- Пункт 2: `app/(tabs)/lessons.tsx` и файлы с `factory_native_course_v1`/`generated_release`
  (`learning_v2_course_released_session_client_v3`, `learning_v2_direct_session_player_v1`, `lesson1_release_parity_v1`, `learning_session_rune_reward_composite_v1`).
- Пункт 4: `app/(tabs)/_layout.tsx` (порядок премаунта вкладок).
- Пункт 3: `app/(tabs)/home.tsx` (`loadData`, `useRankAccess`). Пункт 5 — после 2–4.
- Не трогаем: герой/сцена Главной, `SceneStarTwinkle`/тихий повтор (Дизайн), пункты 6–7 до слова координатора.

## Architecture

Сначала считается статическое замыкание импортов (только чтение), чтобы лениться там, где это реально снимает работу со старта.
Модуль, нужный только при открытии V2, подключается внутри ветки открытия (`require`/`import()`); охранный тест запрещает статический импорт V2 из `lessons.tsx`/`_layout`/`home`.
Правки патчами от HEAD (в файлах есть чужие незакоммиченные хунки).
