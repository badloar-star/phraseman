# Optimistic UI — зона Моментов (26.10)

Обязательная проверка владельца: мгновенный отклик, откат с понятной строкой, защита от двойного тапа и гонок, без спиннера на
весь экран, без «прыжка» числа после ответа сервера. Разбор — чтение кода (приложение не запускалось).

## Починено (только JS, OTA)

- Итог диалога: двойной тап по ✕ / «Готово» уводил на два экрана назад — повтор в течение 1 с пропускается (`[DIALOG-SUMMARY] close skip`).
- Цепочка итога урока: цель счёта баланса замораживается на старте — поздний ответ кошелька посреди счёта больше не отбрасывает число назад.
- Пик: «Дальше / Ещё раз» при недостающих данных закрывает окно итога, и плашка причины видна (`[SPIRE] game: старт заблокирован`).

Repo: C:\appsprojects\phraseman, read-only. Date 2026-10-25.

## How the zone works (context)
- "One number" = `peekDisplayedRunes()` = wallet snapshot + Peak pending coins (app/runes_system.ts:269). `subscribeDisplayedRunes` (:356) delivers it. Wallet merge from a flush answer + settling pending run inside one batch `runDisplayedRunesBatch` (:317, 3 s fuse), so the number changes once.
- A late server balance can NOT push the number back: `mergeSpireFlushWallet` (app/spire/spire_flush_wallet.ts:82) skips the merge when `server.starsSeq <= localSeq` and only settles pending; `mergeLevelSpinServerStars` takes only a newer seq and keeps unacknowledged local ops (app/level_spin_star_grants.ts:1664-1670).
- Peak step coins go into pending at the moment of the result, before the disk write (`spireStepCoinsNow`, app/spire/spire_step_close.ts:63); rolled back on save failure / duplicate (`spireStepCoinsUndo`, :80) and on a server `rejected` verdict (`settleSpirePendingCoins`, spire_pending_coins.ts:144) together with screen rollback + notice (`useSpireRejectRollback`, spire_screen_rollback.ts:65-77, notice "stepNotCounted" in SpireHomeScreen.tsx, testID spire-reject-notice).

## Side notes (not rule gaps)
- Performance: `subscribeDisplayedRunes` calls `scheduleOrphanReconcile('start')` after every hydrate (runes_system.ts ~:366; the 60 s throttle skips only non-'start' triggers), so each mount of BalancePill/ChainCoinRow while pending > 0 triggers a disk-only reconcile. Cheap, could be throttled.
- Cost: no extra Firestore reads found in this zone. Week result reads one document once per week (cache states found/absent/dismissed); position moments use 0 reads.
- `spirePendingCoinsTotal` filters the 48 h TTL on read without emitting, so an expired line stays on screen until the next emit (harmless).
