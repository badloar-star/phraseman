# Агенты и гейты производства «Сокровищницы»

Протокол массового производства 30 сетов. Ключевое правило: **агенты пишут только в `batches/`**
(у каждого сета свои файлы — параллельные агенты и параллельные сессии не конфликтуют);
`catalog_seed.json` и `art/` мутируют только команды `merge` / `ingest-art` в сессии-оркестраторе.

## Ростер

| Роль | Модель | Вход | Выход | Запуск |
|---|---|---|---|---|
| **writer** | sonnet | промпт из `prompts <setId>` (часть 1) | `batches/<setId>.texts.json` — РОВНО 11 объектов (10+секретная) | параллельно, 1 на сет |
| **illustrator** | sonnet | промпт из `prompts <setId>` (часть 2), эталоны `art/set01_animals/*.svg` | `batches/art/<setId>/<id>.svg` × 11 | параллельно, 1 на сет |
| **reviewer** | sonnet | смерженный сет в каталоге + принятые арты | вердикт PASS/FIX со списком конкретных правок | после merge+ingest, 1 на 1–3 сета |
| **оркестратор** | основная сессия | — | merge → validate → lint → ingest-art → review-цикл → commit | последовательно |

## Гейты (все автоматические, кроме G6)

| Гейт | Что ловит | Команда | Проверен |
|---|---|---|---|
| G1 схема/уникальность | дубли id/фраз (по ВСЕМУ каталогу), битые редкости (5/3/2 или 5/3/1/1), счёт 300/150/90/45/15 | `validate` | ✅ selftest |
| G2 поля/лимиты | пропуски полей по статусу, превышения длины, скобки в IPA | `validate` | ✅ selftest |
| G3 стиль | канцелярит-стоплист, штампы в originRu, пример без фразы, literalRu с заглавной | `lint` (и внутри merge) | ✅ selftest |
| G4 SVG | viewBox≠200×160, `<text>/<script>/<image>/<filter>/href`, >8КБ, >80 строк, нет aria-label, неполный сет артов | `ingest-art` | ✅ selftest |
| G5 целостность мержа | чужой/дублирующий id, ПОДМЕНА en, батч ≠ 11 объектов; отказ = каталог не тронут | `merge` | ✅ selftest |
| G6 ревью смысла | факты в историях, естественность примеров, сцена арта = буквальный смысл фразы | reviewer-агент | пилот |
| G7 сборка | build только при нуле ошибок validate+lint | `build` | ✅ |

`node tools/collectibles/generate.mjs selftest` — прогоняет негативные тесты G1–G5 (15 кейсов), ничего не пишет.

## Цикл одного сета

```
prompts <setId> ──► [writer ∥ illustrator] ──► batches/
                                                  │
                       merge <setId>  (G1,G2,G3,G5)│  отказ → правка батча → повтор
                       ingest-art <setId>     (G4) │
                                                  ▼
                                        reviewer (G6) ──FIX──► точечные правки → validate
                                                  │PASS
                                                  ▼
                                     git commit (атомарно на сет) ──► build
```

## Массовый запуск (в т.ч. из параллельных сессий)

- Один сет = независимая пара батч-файлов → сеты можно вести из разных сессий Claude одновременно.
- В чужой сессии: спавнить writer/illustrator для своих сетов, после готовности батчей запускать
  `merge`/`ingest-art` ПО ОДНОМУ (команды атомарны: отказ не трогает каталог; сам файл каталога
  редактируют только эти команды — не редактировать руками параллельно).
- Коммитить после каждого принятого сета: `git add tools/collectibles && git commit`.
- Прогресс: `stats`; итоговая сборка: `build`.
