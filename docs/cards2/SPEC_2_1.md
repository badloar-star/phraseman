# Карточки 2.1 — спецификация переработки

Дата постановки: 12 августа 2026. Источник — прямое ТЗ пользователя.
Это следующая итерация после Cards 2.0 (`MASTER_PLAN.md`). Всё, что здесь противоречит Cards 2.0, — **отменяет** решения Cards 2.0.

---

## 0. Суть изменения одним абзацем

Раздел «Карточки» перестаёт быть «магазином наборов + витриной прогресса». Он становится: **мои сохранённые карточки как главный экран** + **наборы сообщества как основной социальный контент** (бесплатные, без валюты, с лайками и счётчиком добавлений). Вся отдельная механика звёзд/сундуков внутри раздела удаляется — звёзды это общая валюта всего приложения (Learning V2, Арена), отдельной «звёздной» надстройки в карточках быть не должно.

---

## 1. Наборы: только сообщество, всё бесплатно

### 1.1 Официальные наборы — вывести из оборота
- Все существующие официальные наборы (`official_peaky_blinders_en`, `official_prep_*`, `official_negotiator_en`, `official_dark_logic_en`, `official_wild_west_en`, `official_royal_tea_en` и т.д.) **убрать из каталога/магазина** — новые пользователи их не видят и не могут получить.
- **Критично:** у кого набор уже добавлен — он остаётся полностью рабочим (карточки, тренировка, слушание). То есть код бандлов и рендер НЕ удаляем, удаляем только показ в каталоге.
- Реализация: фильтр в источнике каталога (`app/flashcards/marketplace.ts`) — официальный пак попадает в выдачу **только если** его id есть в `loadAccessiblePackIds()` (уже купленные/выданные). Плюс тест «неовладелец не видит официальные паки в каталоге, владелец видит свой».

### 1.2 Цены — удалить полностью
- Из создателя наборов (`app/community_pack_create.tsx`) убрать поле/логику цены. Автор не может назначать цену.
- Убрать константу `COMMUNITY_PACK_PRICE_SHARDS` из пути создания/публикации и `priceShards` из схемы публикации (`app/community_packs/schema.ts`, `functionsClient.ts`, `communityFirestore.ts`, `communityPackDraftStorage.ts`).
- Обратная совместимость: в уже опубликованных документах поле `priceShards` может остаться — читать его нельзя, показывать нельзя, при чтении игнорировать.

### 1.3 Осколки/жемчужины — вне наборов
- Удалить путь покупки набора за осколки: `app/community_packs/purchaseCommunityPack.ts`, `app/flashcards/cardPackShardPurchase.ts`, `app/flashcards/CardPackShardPaywallModal.tsx` — из потока наборов убрать (сам модуль осколков `shards_system.ts` НЕ трогаем, он используется другими разделами).
- Вместо покупки — действие **«Добавить себе»**: одно нажатие, оптимистично, без списаний, без подтверждений.
- Убрать чип баланса осколков из шапки раздела «Карточки».

### 1.4 Награды
- Наборы **бесплатны и не приносят пользователю ничего** — ни осколков, ни звёзд, ни XP за сам факт добавления/публикации.

## 2. Социальное: счётчик добавлений и лайки активности

### 2.1 Счётчик добавлений
- На плитке и на экране набора показывать, **сколько людей добавило себе этот набор**.
- Хранение: счётчик на документе набора в Firestore (`addedCount`), инкремент при добавлении, дедупликация по пользователю (повторное добавление того же пользователя не увеличивает счётчик).
- Оптимистично: цифра растёт сразу при нажатии, сервер догоняет.

### 2.2 Лайк активности
- На набор можно поставить **лайк активности** — тот же тип лайка, что показывается в карточке пользователя (профиле).
- Лайк отображается: (а) на самом наборе, (б) в карточке пользователя-автора.
- Один пользователь — один лайк на набор, повторное нажатие снимает лайк.
- Хранение: `likesCount` на документе набора + запись «кто лайкнул» для идемпотентности; в профиле автора — суммарное число лайков активности.

### 2.3 Топ по лайкам
- Наборы с бóльшим числом лайков **выше в списке** и **визуально выделяются** (заметный, но не кричащий акцент — рамка/бейдж «в топе», без золотых «премиум»-коннотаций, чтобы не путать с платным).
- Сортировка каталога: по убыванию лайков, при равенстве — по числу добавлений, затем по свежести.

## 3. Звёзды и сундуки — удалить из раздела

Удаляется полностью из раздела «Карточки»:
- секция «Звёзды недели» с прогрессом и тремя сундуками 7★/14★/21★;
- «Сундуки колод» / best-звёзды колод / затухание (decay);
- milestone-сундуки 10★/25★/50★;
- начисление звёзд за сессии тренера/повторения/слушания/блица;
- все тексты и подписи про звёзды на экранах результата и в хабе;
- чип «×1.5 XP» и связанный с ним буст, если он завязан на звёздную механику раздела.

Основание: **звёзды — общая валюта всего приложения** (Learning V2, Арена). Отдельной звёздной механики внутри карточек быть не должно.

Технически: убрать из UI и из вызовов; файлы `stars_system.ts`, `stars_config.ts` и их тесты — удалить вместе с ключами `fc_stars_v1`, `fc_deck_best_stars_v1` (и убрать их из `SYNC_KEYS` и из `RESTORE_MERGE_STRATEGIES` в `cloud_sync.ts`). Экран результата сессии оставить, но без звёзд — только «верно/ошибок/точность» и XP (XP — общая механика, её не трогаем).

## 4. «Тренировка (моя практика)» — убрать из раздела

Секция/плитка «Тренировка» («моя практика») из раздела «Карточки» удаляется — этот вход уже есть на главном экране и остаётся только там. (Сами режимы тренировки при этом доступны из нового таббара, см. §5.)

## 5. Новая навигация раздела

### 5.1 Вход
Переход в раздел с главного экрана **сразу открывает сохранённые карточки** — без промежуточного хаба. Сверху — удобный поиск и фильтр по карточкам.

### 5.2 Нижний таббар (3 позиции)
| Позиция | Кнопка | Поведение при нажатии |
|---|---|---|
| Слева | **Тренировка** | Вверх выезжает анимированный список: **Тренировка**, **Слушать**, **Блиц** |
| По центру | **+** (акцентная круглая) | Над кнопкой раскрываются две анимированные кнопки: **Создать карточку**, **Создать набор** |
| Справа | **Наборы** | Открывает наборы сообщества (каталог) |

Требования к анимации: раскрытие/сворачивание пружиной со стаггером (кнопки появляются друг за другом), затемнение фона при раскрытии, поворот «+» в «×», закрытие по тапу вне и по системному «назад». Всё только на `transform`/`opacity`; при включённом «уменьшить движение» и на слабых устройствах — упрощённый вариант без потери функций.

### 5.3 Правая позиция — решение
Пользователь явно назвал левую («Тренировка») и центральную («+»). Третья позиция назначена как **«Наборы»**, потому что наборы сообщества становятся основным контентом раздела и им нужен постоянный вход. Если нужно иначе — поменять здесь и в реализации.

## 6. Тренировка: несколько наборов сразу

В выборе колоды разрешить отмечать **больше одного набора** и тренировать их объединённой колодой (карточки перемешиваются). Соответственно: чекбоксы вместо радио-выбора, счётчик выбранного («выбрано 3 · 84 карточки»), запрет старта при нуле выбранных.

## 7. Слушание

### 7.1 Эквалайзер
Вернуть/сделать **красивый анимированный эквалайзер** в плеере слушания: полосы «дышат» во время озвучки, замирают на паузе. Реализация — на `transform: scaleY` (не на height/width), без таймеров на JS-потоке где возможно; на слабых устройствах и при «уменьшить движение» — статичный/упрощённый вид.

*Замечание для истории:* пользователь спросил, почему эквалайзер «убрали». Проверка всей истории git показала, что экрана прослушивания и эквалайзера в этом репозитории **никогда не существовало** — файлы `flashcards_listening_session.tsx` / `listening_machine.ts` созданы в Cards 2.0 с нуля. Эквалайзер делается впервые.

### 7.2 Выбор режима — одна кнопка
Четыре чипа (**EN → RU**, **RU → EN**, **EN ×2**, **Только EN**) заменить **одной кнопкой** с текущим режимом; по нажатию — выпадающий список всех вариантов с анимацией и отметкой текущего.

## 8. Общее требование к виду

Всё перечисленное — анимированно и с премиальным дизайном: мягкие пружины, стаггер, аккуратные тени и границы, без «мультяшности». Производительность приоритетна: только `transform`/`opacity`, деградация на слабых устройствах и при `reduce motion`.

---

## 9. Что НЕ трогаем

- Общая система XP и общие звёзды приложения (вне раздела карточек).
- `shards_system.ts` — используется другими разделами.
- Языковой инвариант редактирования карточек (чужие локали не перезаписываются).
- Алгоритм повторения SM-2 в `review.tsx`.
- Уже добавленные пользователям наборы — должны продолжать работать.

## 10. Критерии готовности

1. `npx tsc --noEmit` — чисто.
2. `npx jest` — зелено, кроме трёх известных старых сьютов.
3. Смоук: вход в раздел → сразу сохранённые карточки с поиском; таббар раскрывается обеими группами кнопок; создание карточки и набора открываются; тренировка/слушание/блиц запускаются; мультивыбор наборов работает; эквалайзер виден и реагирует на паузу; выбор режима слушания через одну кнопку; каталог наборов без цен, с лайками и счётчиком добавлений; официальный пак не виден новому пользователю, но виден владельцу; ни одного упоминания звёзд/сундуков в разделе.
4. Галерея скриншотов всех экранов + визуальная проверка.
