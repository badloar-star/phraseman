  (экран приветствия), кэш видео на Главной пуст (`[HOME-COLD] video:raw_cache videos=0`). Вероятно, кэша не было вовсе.

  1. Немой `catch { return null; }` в чтении кэша (`youtube_catalog_cache.ts`): негодный снимок выбрасывался без следа,

     скелетонов вместо одного потолка D158 — «и через минуту скелетоны».

## Сделано

- `[VIDEO-FEED]`: `enter` (кэш hit / account_not_ready / missing / expired / invalid:<причина>, возраст, число видео,
  записей в хранилище), `net:start` / `net:done` (мс, видео, версия) / `net:error` (мс, причина), `net:skipped`
  (ранние выходы), `view` (skeleton / catalog / unavailable / no_channel / rss_fallback, мс от входа).
- `[VIDEO-FEED] cache:invalid` вместо немого catch; `[SCREEN-SNAPSHOT] remember:skipped` — снимок не записан
  (слишком большой / не сериализуется) вместо молчаливого выхода.
- Потолок D158 считается от первого скелетона захода; по нему сразу «Сейчас недоступно» (`[NO-ERROR-SCREEN]
  reason=catalog_ceiling_no_cache`). Тихие повторы при быстрой ошибке сети — как раньше.
- Тап по меню: `[TABBAR-PRESS] grant / end / grant:ignored` (раньше ранний выход при неизмеренной ячейке съедал тап
  молча), `[PROFILE-CARD] dismissed` — когда система убрала окно визитки. Визитка — системное окно `Modal`,
  невидимого слоя поверх меню в коде нет; на эмуляторе поток JS стоял по 2,5–4,3 с (`[JS-STALL]`).

## 404 ленты канала UCIr8fwZjbDtcUlQ-IKIbndg (обход, заход 6) — разбор 12.11

- Канал — **не dev-подмена и не тестовый аккаунт**: это боевой канал по умолчанию (`LINGMAN_DEFAULT_CHANNEL_ID`,
  Professor Lingman). `isOverride:true` — из серверных настроек (`remote_config` → `youtube_channel_*`, админка
  «Пульт» → «📺 YouTube-канал»), значение то же самое. Разобрано ещё 11.10 (§CORE-0166 в `INBOX_COORDINATOR_FROM_CORE.md`).
- 12.11 ~07:40: RSS `feeds/videos.xml?channel_id=UCIr8fwZjbDtcUlQ-IKIbndg` → 404, контрольный чужой канал
  Google Developers → тоже 404. **Сломана сама RSS-лента YouTube, не наш адрес — 404 получают все пользователи.**
- Клиент при 404 ведёт себя как надо, правка не нужна: один запрос за запуск, после 404 сеть для этого канала до
  конца запуска не трогается (`feedNotFoundChannelThisLaunch`); лента собирается из лучшего источника — свой список
  моложе 6 ч (0 чтений) → один запрос в серверный каталог → старый список → встроенный. Ошибка — только когда
  показать нечего. Кэш «5 ч» на обходе — ровно эта ветка.
- Вкладка «Видео» живёт на серверном каталоге (YouTube Data API, крон), RSS ей нужна только как запас — 404 её не роняет.

**На утро владельцу (ничего не выкладывалось):**
1. RSS YouTube отвечает 404 с 11.10. Каждый запуск у каждого человека — лишний запрос, заранее обречённый.
   Предложение — клиентская правка, не серверная: для ленты Главной брать серверный каталог основным источником
   и не ходить в RSS. Нужен ли RSS вообще — решение владельца.
2. Видимой пометки «не обновилось» при показе старого списка нет — только журнал. Правило «кэш + тихий признак
   обновления» здесь выполнено наполовину; если нужен признак — это правка вида, по макету.
3. Необязательно: «Пульт» → «📺 YouTube-канал» → «↩️ Вернуть PHRASEMAN» снимет `isOverride` (канал тот же) — при
   сбоях вернётся встроенный запасной список.
