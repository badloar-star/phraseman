# PM-243 — срок финального удаления legacy-данных (проект, 2026-10-01)

Статус: **проект для решения координатора/владельца**. Конкретные сроки в D-решениях не записаны и из них не выводятся, поэтому этот документ их НЕ принимает — он сводит принятое и предлагает цифры. Данные в боевой базе не трогались, скриптов чистки не запускалось.

## Предлагаемые ворота перед любой чисткой (все должны быть выполнены)
1. **Migration:** перенос Account V2 прошёл (`done`) на аккаунтах владельца, проверка OD24 на 3 аккаунтах пройдена (для G1).
2. **Совместимость:** `force_update` + `min_app_version` ≥ 2.0 действуют — иначе 1.6.24 читает лиги/подарки/спины и `friendsTogetherClaimLevel` (PM-235 §6; DEPLOY_NOW).
3. **Права:** правила Firestore 2.0 выложены; для G2 — `coinReconcileV1` выложен ДО чистки (в `level_spin_results` его единственный источник; DEPLOY_NOW:163).
4. **Откат:** снимок/экспорт проверен (`PM-237_backup_restore.md`: реальный backup/restore ещё не прогонялся на эмуляторе — ворота не пройдены); отдельная команда на каждую группу.
5. **Крон-хвост:** прошёл хотя бы один понедельничный `leagueFinalizeCron` или он снят (PM-222 §2–3) — для G2.
6. **Пробный прогон** (только чтение, число документов, оценка стоимости R+D) принят владельцем; сам скрипт — отдельная задача (его нет).

## Вопросы координатору (нужны варианты и выбор)
1. **G2: как понимать «сразу после релиза» (D90)?** (а) строго после ворот 1–6, самое раннее T+14 дней, потолок T+45 — **рекомендую**; (б) сразу в день релиза (риск: 1.6.24 ещё живы, потеря источника `level_spin_results` до `coinReconcileV1`); (в) без потолка, только по команде (риск «бессрочно», нарушает A2).
2. **G1: верхняя граница после OD20.** (а) 60 дней после 7B — **рекомендую**; (б) 90 дней; (в) без границы (нарушает A2).
3. **Старые журналы без `expireAt`** (до выкладки TTL): (а) одноразовый бэкфилл `expireAt = createdAt + 90 дн.` и дальше TTL — **рекомендую**; (б) разовое удаление старше 90 дней скриптом; (в) оставить как есть (бессрочно — нарушает A2).
4. **Скрипт чистки G2** (пробный прогон + запуск владельцем): завести отдельную задачу и исполнителя? **рекомендую да**; без него PM-243-A1 выполнить нельзя.

## Критерии
- **PM-243-A1** (purge после migration/совместимости/прав/отката) — **NOT_MET (решение координатора/владельца + скрипт)**: ворота описаны выше, но сроки не утверждены, скрипта чистки и проверенного backup/restore нет.
- **PM-243-A2** (не бессрочно хранить лишние личные данные) — **NOT_MET (решение владельца)**: у G3 сроки есть (TTL журналов в коде, не выложен), у G1 нет верхней границы, у G2 не определено «сразу»; после ответов на вопросы 1–3 критерий закрывается документом + выкладкой TTL.
