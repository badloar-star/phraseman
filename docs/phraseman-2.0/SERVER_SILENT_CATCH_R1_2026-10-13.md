# Немые catch и ранние выходы в серверных функциях — R1 (Ядро, 13.10)

Только чтение `functions/src` на HEAD. **Ничего не менялось:** функции прошли предполётную проверку, правки — после утренней выкладки
и по решению координатора.

## Как искали

1. Сканер по всем `functions/src/**/*.ts` (кроме тестов): блоки `catch` и `.catch(() => …)`, в которых нет ни логгера, ни `throw`.
   Нашёл **382 кандидата**.
2. Отдельно — `catch`, который **перебрасывает другой код ошибки**, не записав исходную причину. Сканер считал их «не немыми»,
   но причина там теряется.
3. Ручной разбор контекста в приоритетных файлах: Диалоги V2 (выкладка А), пуши возврата и окончания Plus (А, Б),
   обращения (Д), удаление аккаунта (Е), RevenueCat, веб-оплата, промокоды, монеты и Шпиль.

**Буквально пустых `catch {}` в серверном коде нет:** три совпадения — комментарии.

## Находки

### Б. Неверная причина (🔴)

| Файл:строка | Что глотается | Риск |
|---|---|---|
| `dialogue_v2_session_completion_core.ts:611-613` | сбой `readSession` (Firestore: сеть, квота, права) → `throw … 'session_not_found'` | человек и мы видим «сессия не найдена», хотя она есть, а сбой временный. Это класс бага «Сессия недоступна», на котором уже теряли круги. Лечение: свой код (`session_read_failed`) **или** хотя бы `logger.warn` с кодом исходной ошибки перед `throw` |

### А. Причина теряется при подмене кода (🟡, Диалоги — выкладка А)

| Файл:строка | Что глотается → во что превращается |
|---|---|
| `dialogue_v2_session_completion_core.ts:603` | сбой чтения выпуска (`resolveReleasedPacket`) → `release = null` → `release_unavailable` (`:607`) |
| `dialogue_v2_completion_server.ts:263-265` | сбой `resolveRelease` → `release_unavailable` |
| `dialogue_v2_completion_server.ts:291-293` | сбой OpenAI (`generateFeedback`: таймаут, 429, 5xx) → `provider_failed`, сам ответ модели теряется |
| `dialogue_v2_session_completion_core.ts:441` | ответ модели не JSON → `null` (итог разговора не собирается, текст ответа не виден) |
| `dialogue_v2_memory_writer.ts:987, 1020, 1125, 1223, 1230, 1243` | сбои личности / доступа Plus / выпуска → `dialogue_v2_memory_identity_unavailable` / `entitlement_unavailable` / `release_unavailable` |
| `dialogue_v2_memory_management.ts:371, 378, 392, 425` | то же для экрана «Память» |

Верхний уровень вызовов **пишет код** категории: `[DIALOGUE-V2-COMPLETE] failed` (`dialogue_v2_session_complete_callable.ts:241`),
`[DIALOGUE-V2-TURN] failed` (`dialogue_v2_turn_production_callable.ts:840`). Значит, видно «release_unavailable» или «provider_failed»,
но не видно, чем именно ответили Firestore или OpenAI.

### Е. Проверено и чисто

- **Удаление аккаунта** (`account_authority/*`, выкладка Е): все `catch` пишут через `accountAuthorityLogWarn` — сканер принял их за немые
  ошибочно. `account_delete.ts:1750` — комментарий.
- **Шпиль** `spire_progress_contract.ts:189`: битая запись недели даёт `{}`, но вызывающий код пишет `progress_field_unreadable`
  (`spire_progress.ts:209-211`), а монеты защищены от двойной выплаты ключом по номеру ступени.
- **Промокоды** `promo_codes.ts:740`: сбой чтения пользователя влияет только на подпись в списке админки, на право погасить код — нет.
- **Веб-оплата** `web_checkout.ts:2136`: не разобран id письма у почтового провайдера — письмо уже ушло и статус записан;
  ветка ошибки отправки логирует (`logger.warn` + тревога).
- **Обращения** (выкладка Д), RevenueCat, монеты (`stars_ledger`, `spire_coins`, `level_spin_star_grant`): немых мест сканер не нашёл.

## Что предлагаю после утренней выкладки (по решению)

1. **Б** (`completion_core.ts:611-613`): отделить «сбой чтения» от «не найдено». Это меняет код ответа — нужно проверить, как его
   показывает клиент (`dialogue_v2_completion_client.ts`). Минимум — `logger.warn` с исходной ошибкой.
2. **А, В, Г**: по одной строке `logger.warn('[DIALOGUE-V2-…] <код>', { cause: <code/message до 200 знаков> })` перед `throw` или `return`,
   без личных данных — ≈ 16 строк в 6 файлах, около часа. Нужна повторная выкладка функций А.
3. Остальные ≈ 330 кандидатов вне приоритета (админка — `admin_user_profile.ts` 18, `auth_recovery.ts` 6, `support_inbox.ts` 6;
   турниры, фабрика контента) — после R1, отдельным проходом.
