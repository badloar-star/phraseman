## Outcome

На пачку новых событий сервер читает 2 документа (владелец + карта владельца) вместо 2 + N. Повторы `event_target_mismatch` от клиентов прекращаются.

## Scope

`functions/src/mistake_practice_event_sync.ts`, тесты `mistake_practice_event_sync.test.ts` и `mistake_practice_foreign_events.test.ts`.

1. **Быстрый путь:** транзакция — `tx.get(owner)`, `tx.get(ownerMap)`, проверка владельца, затем `tx.create` каждого события БЕЗ чтения. id детерминированный (`mp_<sha256(owner, target, eventId)>`).
2. **Повтор:** если хоть одно событие уже есть, коммит падает `ALREADY_EXISTS` (код 6). Тогда эта пачка идёт прежним путём: чтение событий → сверка (`verifyMistakePracticeEventReplay`, конфликт = data-loss) → create недостающих. Повторы редкие: клиент 2.0 шлёт только неподтверждённое, полная выгрузка — раз в сутки.
3. **Счётчиков и наград по признаку «событие новое» в этой функции нет** — только запись и сверка конфликта. Триггеров на `progress_events/{id}` нет (grep).
4. **`event_target_mismatch`:** 124 из 400 записей [MP-SYNC] за сутки. Источник — события без строкового studyTarget: фильтр «чужих» их пропускал, и они валили всю пачку. Теперь такие события отбрасываются, как чужие. Клиент получает `appended = received` и перестаёт повторять — это понимают и старые клиенты, ответ той же формы, что №45.
5. **Логи:** `[MP-SYNC] append` — path (fast/replay), events, received, appVersion из документа владельца (уже читается, 0 доп. чтений).

## Architecture

Транзакция сохраняет атомарность и защиту от перехода владельца (merge pending / canonical owner). Запасной путь — прежний код без изменений.

## Security and privacy

Не меняется: владелец проверяется так же. Событие без языка не сохраняется — то же, что и сейчас, когда пачку отклоняют.

## Technical debt

Пачка с одним повтором стоит на 2 чтения больше, чем раньше: быстрая попытка плюс прежний путь. Это редкость.

## Verification

Тесты:
- новая пачка — 2 чтения, N созданий;
- повтор — запасной путь, без дубля, конфликт = data-loss;
- событие без studyTarget отброшено, ответ ok;
- переход владельца во время транзакции — failed-precondition.

**Оценка экономии:** −N чтений на пачку. При ~50 тыс. NOT_FOUND в сутки это ≈50 тыс. чтений в сутки, ≈20 % всех чтений проекта.
