# Наборы из сохранённых карточек: язык, компактный выбор и редактор

**Дата:** 2026-09-12
**Статус:** дизайн согласован владельцем; готов к планированию реализации
**Поверхность:** мобильный раздел карточек — «Сохранённые», «Мои наборы», «Наборы сообщества»

## 1. Цель

Пользователь должен быстро собрать пользовательский набор из уже сохранённых
карточек, назвать его, выбрать рубашку, сохранить, отредактировать, удалить или
опубликовать в сообществе. При этом каталог пользовательских наборов не должен
смешивать языки: по умолчанию показывается язык текущего обучения, но пользователь
может явно переключиться на English, Français, Deutsch или Español.

Главный UX-акцент — минимум движений и минимум визуального шума. Режим выбора
карточек является отдельным плотным режимом: карточки становятся низкими, чтобы на
экране помещалось больше элементов; обычный режим карточек не меняется.

## 2. Что входит в работу

### Входит

- Явный язык наборов с флагом-кнопкой в правом верхнем углу каталога.
- Фильтрация «Моих наборов» и «Наборов сообщества» по языку набора.
- Флаг текущего языка вместо текущего source-фильтра в шапке «Сохранённых».
- Меню `⋯` в шапке «Сохранённых».
- Пункт «Вид» внутри меню; текущая смена `Список / Стопка` переносится туда
  как текстовый пункт, а не как отдельная иконка в шапке.
- Пункт «Отметить».
- Компактный режим выбора с чекбоксами, счётчиком и нижней панелью действий.
- «Создать набор» недоступна до выбора 10 карточек.
- Пункт/действие «Удалить выбранные» с подтверждением.
- Открытие редактора с уже выбранными карточками.
- Название набора, рубашка карточек, приватность/публичность и редактирование.
- Удаление пользовательского набора с подтверждением.
- Человеческая подпись источника на каждой карточке: «Урок 12», «Видео …»,
  «Фраза дня», «Набор сообщества» и т. п.; технический `sourceId` в UI не
  показывается.
- Поддержка языков наборов `en | fr | de | es` на уровне данных наборов,
  независимо от более узкого текущего `StudyTarget` приложения.

### Не входит

- Перепроектирование режимов тренировки, озвучки или 3D-переворота в обычном
  просмотре карточек.
- Изменение глобального языка интерфейса приложения.
- Автоматическая публикация без явного включения пользователем публичного
  доступа.
- Удаление существующего swipe/undo-пайплайна удаления одной карточки.
- Расширение всех экранов курса до полноценного обучения на Deutsch/Español;
  язык набора является отдельным контекстом flashcards/community.

## 3. Согласованный пользовательский сценарий

### 3.1. Язык набора

1. При входе в каталог наборов выбран язык текущего обучения, если он есть в
   поддерживаемом набором списке. Иначе используется English.
2. Справа в шапке находится компактная кнопка с флагом и кодом языка.
3. Тап открывает небольшой language picker с четырьмя вариантами:
   `English`, `Français`, `Deutsch`, `Español`.
4. После выбора каталог сразу показывает только наборы выбранного языка.
5. Текущий язык сохраняется локально для этой поверхности и восстанавливается
   при следующем входе.
6. Если для языка нет наборов, показывается честное пустое состояние с кнопкой
   «Создать набор», а не наборы другого языка.
7. При смене языка активный режим выбора закрывается, временный набор выбранных
   id очищается. Если открыт редактор с несохранёнными изменениями, смена языка
   блокируется до явного решения «Сохранить» или «Выйти».

Язык набора (`packLanguage`) не подменяет текущий `studyTarget`: это отдельное
поле домена пользовательских/сообщественных наборов. Legacy-наборы без поля
получают `en` при чтении и миграции.

### 3.2. Шапка «Сохранённых»

В обычном состоянии справа остаются только:

- флаг текущего языка набора/карточек;
- кнопка `⋯` с доступным touch target не менее 44×44 pt.

Старый source-фильтр из шапки убирается. По нажатию `⋯` открывается anchored
menu поверх контента:

1. `Вид` — строка меню, показывающая текущий режим (`Список` или `Стопка`);
   тап переключает режим тем же действием, которое раньше выполняла отдельная
   кнопка.
2. `Отметить` — входит в режим выбора.
3. `Удалить выбранные` — доступно, когда есть выбранные карточки; в обычном
   состоянии может отображаться disabled с понятной подписью, но не вызывает
   действие.

Поиск сохраняется как возможность «Сохранённых», но открытие режима выбора не
должно приводить к скрытым выбранным результатам: selection count всегда считает
все выбранные id, включая временно скрытые поиском карточки. Выход из режима
выбора очищает временный selection.

### 3.3. Режим «Отметить»

После выбора `Отметить`:

- шапка меняется на `Выбрать карточки`, слева появляется `Отмена`, справа —
  счётчик `N / всего`;
- текущий режим просмотра принудительно становится списком;
- каждая карточка переходит в компактный фиксированный layout;
- высота компактной строки целиком заранее зарезервирована, чтобы список не
  прыгал при выборе;
- карточка показывает английскую/target-фразу, перевод и короткую подпись
  источника;
- обычный tap по карточке и tap по чекбоксу делают одно и то же: добавляют или
  убирают id из selection;
- flip, раскрытие деталей, озвучка и swipe-to-delete в этом режиме отключены;
- выбранная карточка получает золотую рамку, тёмно-золотую подложку и заполненный
  чекбокс; невыбранная остаётся спокойной графитовой;
- снизу закрепляется action bar над нижним tabbar.

Action bar:

- `Создать набор` — disabled при `N < 10`, enabled при `10 <= N <= 50`;
- `Удалить выбранные` — destructive action, доступна при `N > 0`;
- при `N < 10` под CTA коротко показывается `Выбери ещё N карточек`;
- при превышении лимита community-пака выбор ограничивается 50 и объясняется
  через inline hint, без неожиданного молчаливого отсечения.

Низкие строки должны быть заметно плотнее обычной карточки: цель — показать на
экране примерно в 2–3 раза больше карточек, сохранив минимум 44 pt для чекбокса
и других интерактивных элементов. Компактность достигается уменьшением пустого
пространства и скрытием деталей, а не уменьшением читаемого текста ниже
доступного кегля.

### 3.4. Удаление выбранных карточек

1. Пользователь нажимает `Удалить выбранные`.
2. Открывается подтверждение: `Удалить N карточек?` с уточнением, что карточки
   исчезнут из «Сохранённых», но исходные уроки/видео не изменятся.
3. Действия — `Отмена` и `Удалить`.
4. После подтверждения используется существующий deletion pipeline с optimistic
   UI и undo-снекбаром; batch-операция не должна удалять карточки по одной через
   серию видимых подтверждений.
5. Selection очищается, режим выбора закрывается, список остаётся на текущем
   безопасном offset.
6. Ошибка удаления оставляет карточки и сообщает понятный результат; нельзя
   показывать успешное удаление до локального коммита.

### 3.5. Создание набора

1. Пользователь выбирает минимум 10 карточек и нажимает enabled `Создать набор`.
2. Выбранные карточки передаются в editor staging по стабильным id, без передачи
   больших payload через URL.
3. Открывается единый редактор пользовательского набора, уже заполненный этими
   карточками.
4. В редакторе видны:
   - название набора;
   - язык набора с флагом;
   - выбранные карточки в компактном списке;
   - источник каждой карточки;
   - рубашка карточек;
   - переключатель «Опубликовать в сообществе».
5. Карточку можно убрать прямо из редактора свайпом/кнопкой удаления; возврат в
   «Сохранённые» не требуется. Если после удаления осталось меньше 10 карточек,
   сохранение/публикация блокируется и показывается точное количество.
6. Для приватного набора достаточно названия и карточек; описание остаётся
   компактным раскрываемым полем.
7. При включённой публикации редактор раскрывает необходимое описание и меняет
   CTA на `Сохранить и отправить в сообщество`. Публикация идёт через существующий
   review/publish контракт, а не прямой клиентский write в публичный каталог.
8. После сохранения пользователь возвращается в «Мои наборы» на тот же язык;
   новый набор появляется сразу из локального состояния, а cloud sync догружает
   статус публикации.

### 3.6. Редактирование и удаление наборов

Для набора, созданного текущим пользователем, доступны `Редактировать` и
`Удалить набор`.

- Редактор позволяет изменить название, описание, рубашку, публичность и состав
  карточек; язык опубликованного набора не меняется незаметно — для смены языка
  нужен явный выбор и повторная проверка карточек.
- Сохранение опубликованного набора переводит его через существующий
  `update_pending`/review путь; публичная версия не перезаписывается частично.
- `Удалить набор` требует подтверждения. Для локального набора удаляется локальная
  запись и ссылки владения; для опубликованного используется предусмотренный
  soft/unlist путь, чтобы не ломать уже выданные ссылки и журнал модерации.
- Наборы других авторов редактировать и удалять нельзя.

## 4. Источник карточки

На лицевой стороне карточки в обычном и компактном режиме остаётся небольшой
source badge. Он должен показывать только пользовательское название:

| Данные | UI |
|---|---|
| `source=lesson`, `sourceId=12` | `Источник: Урок 12` |
| `source=video`, video id/title | `Источник: Видео · Airport English` |
| `source=daily_phrase` | `Источник: Фраза дня` |
| `source=community` | `Источник: Набор сообщества` |
| `source=word/verb/dialog` | локализованная категория |
| неизвестный source | локализованный безопасный `Источник: Другое` |

`sourceId`, технические `DEV:*` и внутренние идентификаторы не рендерятся как
текст. Для source без названия используется стабильный fallback, чтобы подпись
не менялась между кадрами.

## 5. Языковая модель данных

Добавить в flashcards/community отдельный тип:

```ts
export type PackLanguage = 'en' | 'fr' | 'de' | 'es';
```

И метаданные:

```ts
type PackLanguageMeta = {
  code: PackLanguage;
  nativeName: string;
  shortName: string;
  flagAsset: ImageSource;
};
```

`FlashcardMarketPack` и payload community-пака получают обязательное в новых
записях поле `packLanguage`. Legacy-данные нормализуются к `en`.

Для карточек, где прежнее поле `en` означало именно английскую target-фразу,
нужен backward-compatible адаптер:

- новые записи используют нейтральные `targetText` и `translationText`;
- legacy-чтение мапит `en` в `targetText` и существующую локаль перевода в
  `translationText`;
- новая запись не должна записывать французскую/немецкую/испанскую target-фразу
  в поле, которое по контракту называется `en`;
- все операции selection/editor работают со стабильным `id` и нормализованной
  карточкой, а не с текущим текстом.

Выбор языка набора хранится отдельным локальным preference key. Существующие
`studyTarget`-ключи не удаляются и не переиспользуются для немецкого/испанского.
Нужно добавить target-language storage adapter только для flashcards/community,
с legacy fallback English и отдельной изоляцией данных по языку.

Любое изменение коллекций/полей обязано в том же изменении пройти проектный
контур: Firestore Rules, Jarvis fetchers/data-contract guard и необходимые
индексы. Нельзя добавлять публичный каталог только на клиенте.

## 6. Архитектура компонентов

### 6.1. Новые чистые модули

- `app/flashcards/pack_languages.ts` — тип, метаданные, legacy-нормализация,
  подписи и выбор default language.
- `app/flashcards/source_labels.ts` — чистое преобразование `(source, sourceId,
  metadata, lang)` в безопасную UI-подпись.
- `app/flashcards/saved_card_selection.ts` — add/remove/toggle, лимиты 10/50,
  validation для create CTA и стабильное преобразование selection в staging.
- `app/flashcards/selection_view_prefs.ts` — только если существующая схема
  хранения режима потребует отдельного запоминания; selection mode сам по себе
  не персистится.

### 6.2. Существующие поверхности

- `app/flashcards_collection.tsx` остаётся оркестратором: menu state, language
  state, selection state, staging, confirmation, navigation.
- `app/flashcards/CollectionHeader.tsx` получает language button и actions menu;
  старый source-filter UI удаляется только в рамках этой поверхности.
- `app/flashcards/CollectionListView.tsx` получает selection props и отдельный
  compact row renderer/variant.
- `app/flashcards/FlashcardListItem.tsx` сохраняет обычный интерактивный режим;
  selection variant не должен ломать обычный flip/details/delete.
- `app/flashcards_packs.tsx`, `FlashcardsCategoryHub` и `app/flashcards_my_packs.tsx`
  используют один language picker и фильтруют pack catalog по `packLanguage`.
- `app/community_pack_create.tsx` принимает staged card ids, показывает их в
  editor и сохраняет изменение через существующие local/cloud paths.
- `community_packs/schema.ts`, `marketplace.ts`, local author storage и Cloud
  Functions получают нормализацию и валидацию `packLanguage`.

Обычные карточки, открытые не из «Сохранённых»/editor selection, продолжают
использовать прежний путь без selection overlay.

## 7. Motion и визуальная система

Стиль — premium dark / graphite + olive + champagne gold, совместимый с текущими
токенами темы. Не использовать белый текст на ярком lime/green filled surface;
для CTA использовать `t.correctText`/тёмный foreground.

- Menu: opacity + translateY/scale, 180–220 ms, без изменения layout соседей.
- Вход selection mode: короткий crossfade/translate, без анимирования высоты
  каждой строки в процессе измерения.
- Compact rows: фиксированная геометрия; selection marker — scale/opacity
  micro-animation 160–220 ms.
- Enabled CTA: subtle gold glow и press scale 0.98; disabled CTA — только
  контрастное состояние и текстовая причина, без бесконечного pulse.
- Destructive confirmation: существующий themed alert shell, спокойный red/rose
  акцент, без агрессивной тряски.
- Для `reduceMotion` отключить transform animation, оставить мгновенную смену
  opacity/цвета.

## 8. Accessibility и edge cases

- Все icon-only controls имеют `accessibilityLabel` и роль button.
- Чекбокс имеет `accessibilityRole="checkbox"` и корректный `checked`.
- Disabled `Создать набор` сообщает причину через accessibility hint: «Нужно ещё
  N карточек».
- Кнопки не меньше 44×44 pt; сам compact row может быть визуально низким, но
  tap target чекбокса/строки остаётся доступным.
- Длинные названия набора и source labels обрезаются с многоточием, но полное
  значение доступно screen reader.
- Смена языка во время selection очищает selection предсказуемо и не смешивает
  карточки разных языков.
- Быстрые повторные taps по create/delete блокируются до завершения действия.
- Пустой результат поиска отличается от пустой коллекции.
- Нет карточек с неизвестным source — UI не падает, используется fallback.
- Offline: локальный приватный набор сохраняется по существующим client-local
  правилам; публикация показывает pending/error и не удаляет локальный результат.
- Максимум 50 карточек совпадает с community pack contract; меньше 10 нельзя
  сохранить как community set.

## 9. Тестовая стратегия

Работа выполняется TDD-циклом: каждый новый чистый модуль и новый режим сначала
получает падающий тест, затем минимальную реализацию.

### Unit tests

- `PackLanguage` нормализует legacy/missing/unknown values к `en`.
- default language следует текущему target только для поддержанных значений.
- фильтр набора не пропускает набор другого языка и не теряет unknown/legacy.
- source label mapper не показывает технический `sourceId`.
- selection toggle idempotent; duplicate id не удваивается.
- create CTA false для 0–9, true для 10–50, false для 51+.
- смена языка очищает selection.

### Component/interaction tests

- `⋯` открывает menu; `Вид` переключает существующий `list/deck` preference.
- `Отметить` переводит list в compact selection mode.
- tap по карточке и checkbox синхронно меняет checked state.
- compact mode не вызывает flip/details/speak.
- CTA disabled до 10 и enabled при 10.
- create navigation передаёт staged ids, а не URL payload.
- delete menu/action открывает одно подтверждение на batch.
- cancel confirmation оставляет карточки; confirm вызывает deletion pipeline.
- editor показывает выбранные карточки, source и cover; удаление из editor
  пересчитывает min-card validation.
- public toggle меняет CTA и вызывает review/publish path только при submit.
- own pack edit/delete доступны автору и скрыты у чужого набора.

### Contract/integration gates

- community pack schema и Cloud Function принимают `packLanguage` и отклоняют
  unsupported values.
- published catalog query/filter имеет parity с локальным catalog filter.
- Firestore Rules закрывают новые поля/коллекции согласно существующей модели.
- Jarvis fetcher и data-contract guard знают новую коллекцию/поле, если они
  добавляются.
- существующие tests для community pack create/edit/publish/delete, saved cards,
  view mode и source badges остаются зелёными.

## 10. Acceptance criteria

- [ ] В «Сохранённых» справа сверху видны флаг и `⋯`; старый source-filter из
      шапки убран.
- [ ] В `⋯` есть текстовый пункт «Вид» и пункт «Отметить».
- [ ] «Отметить» включает плотные низкие карточки; обычный режим не изменён.
- [ ] Каждая карточка в selection mode имеет видимый источник.
