## 1. Аудит: какой план у учителя сейчас

**Как учитель выбирает, чему учить (после сегодняшних правок):**
1. Тема, обещанная на прошлом уроке (`nextTopic` в памяти).
2. Повторяющиеся ошибки ученика (память, до 8).
3. **Фразы текущего урока курса** (снимок: до 10 фраз текущего урока + 6 фраз следующего) — учитель отрабатывает 2–3 из них, домашка — из них, тема на завтра — следующий урок.
4. Слабые слова из тренажёра (SRS, до 6).
+ Фиксированная структура урока: приветствие → проверка домашки → фокус → практика (одна поправка за реплику) → сцена (раз в урок) → итог с домашкой, темой и советом → сам прощается.

**Честная оценка:** это уже не «от фонаря» — учитель идёт синхронно с курсом и памятью. Но это **линейная лента фраз**, а не учебный план:
- нет **измеримой цели урока** («после урока ученик умеет X») и учёта её достижения (mastery);
- нет **расписания повторения именно для речи**: домашка проверяется один раз завтра — и всё; кривая забывания (1 → 3 → 7 → 21 день) не используется, хотя SRS-тренажёр в приложении есть;
- учитель не знает **грамматику урока** — только фразы (а в приложении есть `lesson_grammar_map.ts`: конструкции по 32 урокам, уровни, зависимости между уроками);
- **уровень определяется эвристикой** по номеру урока (≤8 → A1, ≤20 → A2, дальше B1) — нет диагностики речи;
- нет **горизонта**: каждый урок — «текущий урок курса», нет плана на неделю/цикл, нет «где я на пути к A2»;
- сцены предлагаются без критерия успеха, хотя у сценариев уже есть `objectives` (что ученик должен сделать в сцене);
- домашка живёт только в памяти учителя, в тренажёр не попадает.

**Активы, на которые можно опереться (уже в приложении):**
- 32 базовых урока: фразы + `lesson_grammar_map` (конструкция, CEFR-band, prerequisites) — готовый каркас грамматической прогрессии;
- Learning V2 (авторский курс, 26 сессий эпизода 1) — новый источник фраз/сессий на будущее;
- 124 сценария диалогов с `objectives`, ролями, уровнем (размечено 4×A1 / 17×A2 / 15×B1 / 6×B2 + диалоги уроков);
- SRS-тренажёр (`trainer_store`: слабые слова/фразы, due-даты), `mistake_log`, личный план, XP/серия;
- память учителя (`voice_tutor_memory`): факты, ошибки, домашка, тема, языковое предпочтение, счёт уроков.

## 2. Что делают лучшие и что говорит наука

| Источник | Что взять |
|---|---|
| **Speak** — курс из тематических юнитов («At the restaurant», «Plan a trip»), в каждом 5 типов активностей: Tutor Lesson → Speaking Drill (повтор паттерна) → Tutor Q&A (вопрос → ожидаемый ответ) → Vocab Builder → Roleplay; на старте больше дриллов, на средних уровнях — ролевые игры. | **Спираль внутри юнита**: показал → продриллил → спросил → применил в сцене. Один и тот же материал проходит 3–4 формы за юнит. |
| **Duolingo Video Call (Lily)** — «у каждого звонка есть цель» (рассказать историю / спросить мнение / чему-то научить / просто поболтать), первый вопрос генерируется под уровень и память, звонки согласованы с курсом. | **Тип урока задаётся заранее**, а не рождается в разговоре; тип чередуется. |
| **Praktika** — «Student Progress Agent» фоном следит за беглостью, точностью, словарём и повторяющимися ошибками; данные питают и поведение в уроке, и **долгосрочный план**, который постоянно перестраивается. | Раздельные роли: **планировщик** (редко, по данным) и **учитель** (в уроке). |
| **Loora** — один структурированный урок в день + свободная практика; «15 минут ежедневно лучше двух часов раз в неделю»; типы: Daily Conversation / Role-play / Read & Talk. | Ритуал «урок дня» + типы уроков; короткая ежедневная сессия — норма рынка. |
| **Наука: TBLT vs PPP** (систематический обзор 2015–2025; Lu 2025) — задачный подход даёт **больше беглости**, чем «презентация-практика-продукция»; PPP лучше для точечной грамматики/произношения. | Основа урока — **задача** (сцена с целью), грамматика — точечно внутри. |
| **Наука: retrieval + feedback, distributed practice** — извлечение из памяти работает только с корректирующим фидбэком; интервалы расширяются (в течение 24 ч → 3 дня → 1 неделя → 3 недели, Cepeda); распределённая практика повышает беглость (SSLA). | Учитель должен **сам вызывать на повторение** прошлый материал по расписанию, а не «проверить домашку один раз». |

Источники: [Speak review (Languatalk)](https://languatalk.com/blog/speak-app-review/), [Speak review (Lingostar)](https://lingostar.ai/speak-app-review/), [Duolingo — AI behind Video Call](https://blog.duolingo.com/ai-and-video-call/), [ZenML — Duolingo structured conversations](https://www.zenml.io/llmops-database/structured-llm-conversations-for-language-learning-video-calls), [Praktika — how it works](https://praktika.ai/blog/learning-english-with-an-ai-tutor-how-it-works), [Praktika help — learning process](https://intercom.help/praktika-ai/en/articles/10707916-learning-process), [Loora — lesson types](https://www.loora.com/support/features/types-of-lessons), [Loora — one lesson a day](https://www.loora.com/support/getting-started/will-i-only-have-access-to-one-conversation-a-day), [TBLT systematic review (IJLTER)](https://www.ijlter.org/index.php/ijlter/article/view/15904), [Localized TBLT vs PPP (Lu, 2025)](https://onlinelibrary.wiley.com/doi/10.1111/ijal.12608), [PPP method](https://teast.co/blog/ppp-method), [Distributed practice & L2 fluency (SSLA)](https://www.cambridge.org/core/journals/studies-in-second-language-acquisition/article/effects-of-distributed-practice-on-second-language-fluency-development/4F6787916C198376CAD222934D3B37E4), [Retrieval practice + feedback (L3 vocab)](https://www.researchgate.net/publication/362292887_Retrieval_practice_plus_feedback_benefits_a_third_language_vocabulary_learning), [Spaced retrieval A1 EFL (Frontiers 2025)](https://www.frontiersin.org/journals/education/articles/10.3389/feduc.2025.1715111/full), [Spaced repetition intervals (Maestro)](https://maestrolearning.com/blogs/how-to-use-spaced-repetition/).

## 3. Варианты плана обучения

### Вариант 1 — «Спираль по курсу с расписанием повторения» (расширить то, что есть; 2–3 дня)
Каждый урок = **юнит по текущему уроку курса**:
- материал: 3 фразы урока + **грамматическая конструкция урока** из `lesson_grammar_map` (учитель объясняет её на родном для A1/A2, отрабатывает в 2 подстановках);
- **retrieval-очередь речи**: у каждой отработанной фразы — `dueAt` по расширяющимся интервалам (1 → 3 → 7 → 21 день); в начале урока учитель просит **сказать** 2–3 «созревшие» фразы, результат (сказал/не смог) двигает интервал (инструмент `mark_phrase_result`); неудачные фразы уходят и в SRS-тренажёр;
- сцена = **задача (TBLT)** из сценариев с `objectives`: учитель объявляет цель («закажи кофе и спроси цену»), после сцены отмечает, выполнена ли (`mark_scene_result`);
- тип урока чередуется по дню (как у Duolingo/Loora): «новый материал» → «повторение + сцена» → «свободный разговор на слабых словах»;
- домашка = невыполненные/новые фразы, автоматически в тренажёр.
Плюсы: детерминированно, дёшево (память + контент в бандле), уже есть все данные. Минусы: линейно (курс задаёт порядок), нет цели уровня.

### Вариант 2 — «Карта речевых целей (can-do, CEFR)» (каркас; ~неделя, в основном контент)
Статический список **~60 речевых can-do целей** A1→B1 («могу представиться и рассказать о работе», «могу заказать в кафе и уточнить цену», «могу описать свой день», «могу договориться о встрече», …), у каждой — 2–4 опорные фразы, грамматика, привязка к сценам и урокам курса. У ученика — **карта mastery по целям (0–3)** в памяти учителя. Учитель берёт **следующую незакрытую цель своего уровня**, ведёт к ней 1–2 урока (материал → задача-сцена → проверка), фиксирует mastery (`mark_goal_progress`). Прогресс виден ученику: «14 из 60 целей до A2», следующая цель — на экране «Учитель» и в разборе. Уровень поднимается по закрытым целям (а не по номеру урока) — это и есть **диагностика** и **честный CEFR**.
Плюсы: измеримый прогресс, понятная ценность («доведу до A2»), продаваемость, детерминированный планировщик без LLM. Минусы: нужно написать и одобрить 60 целей (можно сгенерировать черновик и вычитать глазами, как контент Learning V2).

### Вариант 3 — «Адаптивный недельный план (агент-планировщик)» (поверх 1–2; 3–4 дня)
Раз в неделю (или после каждых 5 уроков) серверная функция строит **план на 7 уроков** по данным: ошибки и их частота, слабые слова, mastery целей, прогресс курса, доля речи ученика, серия — текстовой моделью, в JSON. Каждый урок получает **карточку плана** (цель, материал, что повторить, сцена, тип урока), которую учитель читает в промпте, а ученик — на экране «Учитель» (план недели с галочками). После урока разбор пишет факт → следующая перестройка учитывает. Это Praktika-подход «Progress Agent + Lesson Agent».
Плюсы: самый умный и «живой», хорошо продаётся («личный план недели»). Минусы: качество планировщика надо проверять (агент-новичок + владелец), 1 LLM-вызов/неделю на ученика (копейки), больше UI.

### Рекомендация
**1 → 2 → 3, не выбирая одно.** Сначала (сразу) — вариант 1: расписание повторения речи, грамматика урока, задачи-сцены с критерием, домашка в тренажёр — это фундамент методики. Затем — вариант 2 как **каркас целей и честный уровень**. Затем — вариант 3 как планировщик недели поверх целей.

**Анатомия 10-минутного урока (для всех вариантов):**
0:00 приветствие + одна личная фраза из памяти → 0:45 **повторение**: 2–3 «созревшие» фразы + вчерашняя домашка (retrieval с фидбэком) → 2:30 **новое**: 2–3 фразы + конструкция урока/цели, модель → повтор → мини-подстановка → 5:00 **задача-сцена** с целью (4–8 реплик) → 8:00 итог: 2 удачи + 1 поправка, домашка (в тренажёр), тема завтра, шаг в приложении → 9:15 прощание, `end_call`.

**Метрики успеха:** доля правильно сказанных фраз на повторении (retrieval success), фраз/уроков до mastery цели, удержание D7/D30 у уроков-звонков, доля речи ученика в уроке (цель ≥ 50 %), число закрытых целей в месяц.

**Модель данных (минимум):** в `voice_tutor_memory` добавить `plan: { goalId, goalMastery: {id: 0–3}, phraseQueue: [{text, dueAtMs, box}], grammarFocus, lessonType }`; контент: `content/tutor/can_do_goals_v1.json`; инструменты учителя: `mark_phrase_result(text, ok)`, `mark_goal_progress(goalId, level)`, `mark_scene_result(ok)`; сервер: недельный планировщик (вариант 3). Стоимость: 0 новых чтений в уроке (всё в памяти учителя, 1 док), +1 вызов текстовой модели в неделю (вариант 3).
