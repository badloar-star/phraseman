# R50: монеты за диалог теряются при уходе с итога — разбор и предложение (Ядро, 26.10)

Источник: Моменты, `docs/work/moments-optimistic-ui-2026-10-26.md`; код — `hooks/useDialogueV2CoinReward.ts:61-64`.

## Причина (из кода, логи для диагноза не нужны)

Начисляет только экран итога: хук `useDialogueV2CoinReward` живёт в `app/dialogue_v2_completion.tsx`, а его эффект ждёт,
пока копилка прочитается с диска: `if (!ready || practiceRunes.hydrating) return;`. Пути потери:

1. **Ушёл с итога до конца чтения копилки.** Экран размонтирован, чтение копилки отменено (`cancelled = true` в
   `usePracticeRunes`), эффект не запустится уже никогда. Монет нет, намерения нигде нет.
2. **Падение между отметкой и начислением.** Отметка «уже начислено» ставится ДО начисления (защита от двойного). Если
   процесс умрёт между ними, повтора не будет. Это безопасная сторона: потеря вместо двойного начисления.

Сеть тут ни при чём: зачёт на сервер уже идёт через долговечную очередь копилки
(`markPracticeRuneSettlementPending` → `flushStalePracticeRuneSettlements`).

## Почему 15.10 отложили

Решение координатора 15.10: «риск двойного начисления выше пользы». Риск в том, что второй начислитель (например, экран
и фоновый повтор) читает «не начислено» одновременно с первым. Тогда два экземпляра копилки с одним ключом пишут каждый своё.

## Предложение: один хозяин начисления

1. **Телефон решает сразу.** Как только итог готов (`ready`), пишется намерение
   `dialogue_v2_coin_intent_v1:<owner>:<sessionId>` = `{ amount, endedBy, mistakes, atMs }`. Экран сразу показывает «+N»
   из суммы (Optimistic UI), не дожидаясь копилки.
2. **Начисляет один хост.** `DialogueV2CoinAwardHost` монтируется один раз в корне приложения и берёт намерения по одному
   через тот же `usePracticeRunes`. Экономического кода не добавляется, у сервера тот же id операции. Экран итога сам
   больше не начисляет — двух начислителей не бывает.
3. **Порядок у хоста — как сейчас:** дождаться чтения копилки → отметка «начислено» → начисление → `settle()` в фоне.
   Намерение удаляется, только когда копилка приняла монеты (`credited > 0`). Если приложение закрыли раньше, намерение
   лежит на диске и хост доделает его при следующем запуске.
4. **Двойное закрыто четырьмя замками:**
   - один хозяин;
   - отметка «начислено», как сейчас;
   - намерение уникально по `sessionId`;
   - тот же id операции на сервере.

**Цена:**
- 1 хост в корне;
- `usePracticeRunes` включён, только пока есть намерение;
- ни одного нового чтения или записи в Firestore.

Правка затрагивает:
- `app/_layout.tsx` — частый общий файл, свои хунки отдельно;
- `hooks/useDialogueV2CoinReward.ts`;
- новый модуль намерений;
- тесты: уход до чтения копилки, повторный вход, падение после намерения, двойной вход (экран + хост).
