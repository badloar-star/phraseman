# Спецификация агентов генерации контента планов

**Дата:** 2026-06-08
**Цель:** агенты пишут контент дня под контракт `plan_content_schema.ts`, сверяют с официальными источниками, отбраковывают плохое.

**Вход:** задание на день (планId, dayIndex, тема-ситуация, gate уроков, целевой уровень CEFR, список конструкций которые можно использовать).
**Выход:** `PlanContentDay`, проходящий `validatePlanContentDay()` с нулём ошибок и `checkPlanContentGate()` без предупреждений.

---

## Стиль (зафиксирован владельцем)
- Фразы: живые разговорные (I'm, gonna, коротко), как реально говорят.
- Объяснения: дружелюбный тренер, на «ты», на языке юзера (ру; ук/es опционально).
- Объяснение = полное: title + rule (правило) + why (почему так) + commonMistake (частая ошибка), каждая часть ≤24 слов.
- Словарь дня: 5-8 ключевых слов, каждое = слово + часть речи + перевод + пример из фразы дня.
- Темы: реальные жизненные ситуации с сюжетной линией.

## Источники сверки (обязательны)
- **Cambridge / Oxford** словари — значения, сочетаемость, естественность.
- **British Council / Cambridge Grammar** — грамматические правила, корректность конструкций.
- **CEFR** дескрипторы — сложность фразы соответствует уровню дня (A1/A2/B1).
- **Частотность (COCA / частотные списки)** — слова реально частые, не редкие.

---

## Пайплайн агентов (максимально тщательно)

```
[1] Писатели (×3, разные углы)  →  [2] Грамматик-проверяльщик
                                    [3] Лексикон-проверяльщик
                                    [4] CEFR/частотность-проверяльщик
        (параллельно проверяют каждый черновик)
                                          ↓
                              [5] Судья (выбор лучшего + синтез)
                                          ↓
                              [6] Адверсарный контролёр (пытается сломать)
                                          ↓
                              Валидатор контракта (код) → 0 ошибок?
                                   да → готовый день / нет → назад к [5]
```

---

### Агент 1 — Писатель фраз (×3 параллельно, разные углы)
**Роль:** написать черновик дня по контракту.
**Углы (чтобы было разнообразие):**
- Писатель A: «минимум-выживание» — самые нужные фразы ситуации.
- Писатель B: «естественная речь» — как носитель сказал бы в этой ситуации.
- Писатель C: «грамматика-в-контексте» — фразы, мягко закрепляющие конструкции дня.

**Что делает:**
- 5-8 живых фраз по теме дня, только на разрешённых конструкциях (gate).
- Для каждой: english + meaning (ру) + конструкции + полное объяснение (друж. тренер).
- Словарь дня: 5-8 ключевых слов из этих фраз (слово + POS + перевод + пример).
- outcome дня (gain-framing), prerequisiteLessons.

**Запрещено:** конструкции выше gate; книжный/формальный английский; объяснения >24 слов; «просто/также/кстати».

---

### Агент 2 — Грамматик-проверяльщик
**Роль:** проверить грамматическую корректность каждой фразы.
**Источники:** British Council, Cambridge Grammar.
**Проверяет:**
- Фраза грамматически верна и естественна.
- Заявленные конструкции реально присутствуют (не приписаны).
- Конструкция соответствует уровню дня (не сложнее gate).
- Объяснение правила корректно (rule/why не врут).
**Вердикт:** pass / fix (с конкретной правкой) / reject (с причиной).

---

### Агент 3 — Лексикон-проверяльщик
**Роль:** проверить слова и сочетаемость.
**Источники:** Cambridge/Oxford словари.
**Проверяет:**
- Значения слов точны, перевод корректен (не «почему так перевели»).
- Сочетаемость естественна (collocations реальны).
- Словарь дня: каждое слово реально ключевое, перевод и пример верны, POS правильный.
- Нет ложных друзей / калек.
**Вердикт:** pass / fix / reject.

---

### Агент 4 — CEFR/частотность-проверяльщик
**Роль:** проверить уровень и употребимость.
**Источники:** CEFR дескрипторы, частотные списки.
**Проверяет:**
- Сложность фраз = уровню дня (A1 день не содержит B1-лексики).
- Слова достаточно частотные (учим полезное, не редкое).
- Длина/структура фраз посильна для уровня.
**Вердикт:** pass / fix / reject.

---

### Агент 5 — Судья
**Роль:** свести 3 черновика + вердикты проверяльщиков в один лучший день.
**Что делает:**
- Берёт лучшие фразы из 3 черновиков (по вердиктам).
- Применяет fix-правки проверяльщиков.
- Синтезирует финальный `PlanContentDay`.
- Гарантирует: 5-8 фраз, 5-8 слов, полные объяснения, единый сюжет дня.

---

### Агент 6 — Адверсарный контролёр
**Роль:** попытаться сломать финальный день (скептик).
**Проверяет с подозрением:**
- Есть ли хоть одна фраза, за которую юзер спросит «почему так»?
- Звучит ли что-то книжно/неестественно?
- Объяснение где-то врёт или слишком длинное?
- Слово в словаре не из фраз дня?
- Конструкция выше gate проскользнула?
**Если находит — возврат к Судье. Если чисто — пропускает в код-валидатор.**

---

## Финальный гейт (код, не агент)
- `validatePlanContentDay(day)` → должно быть `[]`.
- `checkPlanContentGate(day)` → `withinGate: true`.
- Если код-валидатор ругается — назад к Судье с конкретными issue-кодами.

---

## Масштабирование
1. Сначала **1 день-эталон** (voyazh день 1) через весь пайплайн. Владелец смотрит.
2. Если ок — **pipeline по дням** (каждый день независимо через те же 6 ролей).
3. Хранение результата: TS-файл контента на план (решено: формат на усмотрение исполнителя; вероятно `plan_content_<planId>.ts` экспортирующий `PlanContentDay[]`).
4. Подключение к рантайму через `plan_content_runtime_adapter` (мост уже готов).

---

## Стоимость/ограничения
- Агенты = Claude subagents в сессии (вариант A). Это разовая генерация контента, НЕ рантайм-инфраструктура.
- Рантайм НЕ зовёт LLM (контент статичен в бандле) — согласуется с правилом «без платных сервисов в рантайме».
- Источники: агенты используют свои знания + (при наличии) web-поиск для сверки; без платных API в продакшене.
