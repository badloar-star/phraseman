# Phase 06 — MAX: голосовой ИИ-разговор в реальном времени

**Status:** Planning
**Owner:** badloar@gmail.com
**Created:** 2026-08-10
**Целевая ветка:** после стабилизации `codex/full-performance-audio-audit-167`

## Идея в одном абзаце

Отдельная подписка **MAX** (тир выше Premium), внутри которой — полноценный живой голосовой разговор с ИИ-собеседником: пользователь говорит, ИИ отвечает голосом почти мгновенно, его можно **перебить в любой момент** (barge-in), он активно слушает и подстраивается под уровень. Это прямой ответ на Duolingo Max Video Call (Lily): у Duolingo разговор пошаговый — записал реплику → ждёшь несколько секунд → слушаешь ответ, перебить нельзя. Мы делаем настоящий полнодуплекс через OpenAI Realtime API по WebRTC — задержка ответа ~500–800 мс вместо 3–6 секунд, перебивание работает, и при этом себестоимость минуты у нас контролируемая и низкая.

## Почему мы выиграем у Duolingo

| | Duolingo Max (Video Call) | Phraseman MAX |
|---|---|---|
| Задержка ответа | секунды (STT→LLM→TTS цепочка) | ~0.5–0.8 с (нативный speech-to-speech) |
| Перебивание | нет, ходовая модель | да, barge-in через server VAD |
| Активное слушание | нет | да: подхватывает паузы, подбадривает, semantic VAD не режет медленную речь ученика |
| Привязка к контенту | слабая | сценарии из `ai_dialog_scenarios`, слабые слова из SRS-памяти (`ai_companion_memory`), CEFR-уровень юзера |
| Разбор после разговора | минимальный | транскрипт + исправления + фразы в SRS |
| Цена | $168/год (Max) | наша MAX дешевле или сопоставимо, себестоимость минуты ~$0.03–0.08 |

## Технология

**Модель:** `gpt-realtime-mini` как основная (аудио-вход $10/1M ток., выход $20/1M ток.; реальная себестоимость в проде $0.06–0.08/мин, с оптимизациями $0.03–0.05/мин). `gpt-realtime` (полный, ~3× дороже, ~$0.05–0.15/мин) — опционально как «премиум-голос» внутри MAX или для маркетинговых демо. Выбор модели — через remote config по образцу `openai_dialog_model_config.ts`, чтобы менять без релиза.

**Транспорт:** WebRTC напрямую с устройства к OpenAI. Клиент получает **ephemeral token** от нашей Cloud Function (эндпоинт `/v1/realtime/client_secrets` вызывается только сервером — API-ключ никогда не попадает на устройство), дальше устройство устанавливает peer connection само. Аудио не проксируется через наш бэкенд — нам не нужен свой медиасервер, себестоимость инфраструктуры ≈ 0.

**Клиент:** `react-native-webrtc` + config plugin для Expo (нужен dev build / EAS — уже используется). Микрофонный поток → RTCPeerConnection; события (VAD, транскрипт, состояние) → data channel. Эквалайзер переиспользуем: `voice_equalizer.tsx` уже умеет рисовать спектр из скаляра громкости.

**VAD и перебивание:** серверный `semantic_vad` OpenAI — понимает, что ученик закончил мысль, а не просто запнулся (критично для изучающих язык — они говорят медленно, с паузами). Barge-in: когда юзер начинает говорить во время ответа ИИ, клиент шлёт `response.cancel` + обрезает воспроизведение — эффект «живого собеседника».

## Архитектура (что строим)

### Сервер (functions/)

1. `realtime_session_mint.ts` — onCall-функция `maxVoiceSessionStart`:
   - App Check + auth (паттерн из `premium_dialog.ts`);
   - проверка entitlement **max** (RevenueCat → `premium_revenuecat_state`-паттерн, новый entitlement);
   - проверка квоты минут в Firestore-транзакции ДО выдачи токена (паттерн `enforceDailyQuota` / `premium_dialog_quotas`);
   - минтит ephemeral token с зашитой конфигурацией сессии: системный промпт (роль, сценарий, CEFR, слабые слова), `semantic_vad`, лимит длительности сессии, ограничение болтливости (`max_response_output_tokens`);
   - возвращает token + разрешённые минуты.
2. `realtime_session_report.ts` — списание фактических минут после сессии (клиент шлёт отчёт; сервер сверяет с потолком, зажатым в токене) + лог стоимости.
3. Kill switch — расширяем существующий `ai_kill_switch_copy` / глобальный бюджет (`AI_GLOBAL_BUDGET_ERROR_CODE`) на голосовые сессии: отдельный дневной бюджет $ на MAX-голос, при превышении — мягкая заглушка.

### Клиент (app/)

1. `max_voice_session.tsx` — экран звонка: аватар собеседника, эквалайзер (переиспользуем `voice_equalizer_model.ts`), кнопка «положить трубку», индикатор оставшихся минут, live-транскрипт (опционально скрываемый).
2. `max_voice_client.ts` — обвязка WebRTC: mint token → SDP → peer connection → data channel события; barge-in; аудио-режимы через существующий `audio_session_coordinator` (`SPEAKING_RECORDING_AUDIO_MODE`).
3. `max_voice_review.tsx` — экран после звонка: транскрипт, исправленные ошибки (одним дешёвым текстовым вызовом gpt-4o-mini по транскрипту — паттерн `mistake_explain`), кнопка «добавить фразы в повторение» (SRS).
4. Вход: карточка в `ai_dialog_home.tsx` («Позвонить собеседнику» с бейджем MAX) + гейт по возрасту/согласию (переиспользуем `ai_consent_factory` / `ai_dialog_consent_gate`).

### Монетизация

1. Новый RevenueCat entitlement `max` + продукты `max_monthly` / `max_yearly`. Premium остаётся как есть; MAX включает всё из Premium.
2. Пейволл MAX — отдельный экран в стиле существующих `paywall_*.tsx`, с живым демо (10-секундный предзаписанный пример разговора).
3. Апселл-точки: после исчерпания текстовых ИИ-диалогов; после N завершённых уроков со speaking-модулем; в разборе ошибок.
4. Free/Premium тизер: 1 пробный звонок 3 минуты (одноразово, series-gate по аккаунту) — конверсионный крючок.

## Экономика и квоты (черновик, уточняется в discuss-фазе)

Себестоимость минуты на `gpt-realtime-mini` в реальном проде: $0.06–0.08 без оптимизаций; наши обязательные оптимизации — prompt caching (кешированный аудио-вход ~99% дешевле), обрезка истории (context pruning каждые ~6–8 ходов со сжатием в summary), краткие ответы ИИ (болтливость — главный драйвер цены: ответ 35 с/мин ≈ 2× дороже, чем 15 с/мин), потолок сессии 10 мин. Целевая себестоимость: **$0.03–0.05/мин**.

| Тир | Квота | Себестоимость/мес (worst case) |
|---|---|---|
| Free | 1 пробный звонок 3 мин (одноразово) | ~$0.15–0.25 на юзера единожды |
| Premium | без голоса (или 5 мин/мес как тизер) | ~$0.25/мес |
| **MAX** | **10 мин/день, cap 200 мин/мес** | $6–10/мес при 100% выборке; реалистично 30–40% выборки → **$2–4/мес** |

При цене MAX $14.99–19.99/мес маржа комфортная даже при жадном использовании. Все цифры (квоты, модель, потолки) — в remote config, меняются без релиза. Обязателен дашборд фактической стоимости на юзера (лог из `realtime_session_report`) в существующей админке.

## Риски

1. **Expo + react-native-webrtc** — нужен dev build (уже есть EAS), но плагин надо проверить на текущем SDK — закрывается спайком (План 0).
2. **Стоимость длинных сессий** — контекст растёт, без pruning счёт ×2–5; митигация: жёсткий потолок 10 мин/сессия + pruning + caching.
3. **Echo/дуплекс на Android** — уже есть наработки в `ai_dialog_session.tsx` (комментарий про «микрофон и динамик никогда не одновременно»); в WebRTC встроен AEC, но проверить на дешёвых Android.
4. **Злоупотребления** (шеринг аккаунта, скрипты) — квоты в транзакции ДО выдачи токена, потолок в самом токене, series-gate на пробный звонок.
5. **Минорные пользователи** — возрастной гейт и consent уже есть (`ai_consent_factory`), голосовой режим наследует те же правила + safety identifier в mint-запросе.

## Success Criteria

1. Задержка «юзер замолчал → ИИ начал говорить» ≤ 1.2 с p50 на реальном устройстве.
2. Перебивание работает: ИИ замолкает ≤ 300 мс после начала речи юзера.
3. Средняя фактическая себестоимость ≤ $0.05/мин по дашборду за первые 2 недели.
4. Квоты не пробиваемы с клиента (сервер — источник истины, как в premium_dialog).
5. Конверсия trial-звонок → MAX ≥ 5% в первый месяц (метрика пейволла).
6. Никаких регрессий текстовых ИИ-диалогов и existing premium-флоу.

## Out of Scope (parking lot)

- Видео-аватар собеседника (только голос + анимированный аватар из существующих ассетов).
- Телефонные звонки (SIP).
- Групповые разговоры.
- Собственный STT/TTS-пайплайн (только нативный speech-to-speech Realtime).
