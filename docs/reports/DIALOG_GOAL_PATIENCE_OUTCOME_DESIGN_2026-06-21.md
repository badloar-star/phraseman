# Диалоги как игра: цель · терпение собеседника · модал-вердикт

Дизайн-документ. Автор-сессия: 2026-06-21. Статус: **утверждён пользователем по направлению, ждёт реализации** (спорные файлы редактируются параллельными сессиями — см. §7).

Цель фичи: превратить «бесконечный ИИ-чат» в мини-игру с условием победы. У каждого диалога — явная цель, у каждого собеседника — характер и порог терпения; по завершении показывается модал-вердикт с реакцией персонажа.

---

## 1. Решения пользователя (зафиксированы)

| Вопрос | Решение |
|---|---|
| Глубина | Всё сразу: цели + терпение + модал-вердикт |
| Индикатор по ходу | Смайлик 😊→😐→😠 в шапке (без цифр, не пугает новичка) |
| AI-контракт | JSON в ТОМ ЖЕ вызове `premiumDialogSend` (reply + скрытый сайдкар), с фолбэком при битом JSON |
| Награда | Больше XP за успех (используем существующий XP; провал/заглох — меньше, но не ноль) |
| Жёсткость терпения | Зависит от персонажа, «как в реальной жизни». Ошибки ЯЗЫКА терпение НЕ роняют — роняют грубость, оффтоп, бесконечные повторы, затягивание у нетерпеливых |

## 2. Модель данных (`app/ai_dialog_scenarios.ts`)

Расширить `DialogScenario`:

```ts
/** Проверяемая под-цель диалога. id — стабильный ключ для галочек. */
export interface DialogObjective {
  id: string;          // 'order_drink' | 'ask_size' | 'ask_price'
  labelRu: string;     // «Заказать напиток» (показывается в чек-листе)
  // + остальные 7 языков по образцу DIALOG_SCENARIO_COPY_UK (uk/es/pt-BR/vi/id/tr/pl)
}

/** Темперамент персонажа — как быстро теряет терпение. */
export interface DialogTemperament {
  /** 'high' терпит почти всё (бариста) · 'medium' · 'low' нетерпелив (очередь/чиновник). */
  patience: 'high' | 'medium' | 'low';
  /** Легко ли расположить: 'warm' · 'neutral' · 'cold'. */
  warmth: 'warm' | 'neutral' | 'cold';
}
```

Добавить в каждый сценарий:
- `objectives: DialogObjective[]` — 2-4 шт. Для coffee: order_drink / ask_size / ask_price (1:1 с текущим `goalEn`).
- `temperament: DialogTemperament` — выводится из персоны. Mia(coffee)=high/warm; Sam(grocery)=high/warm; Mr.Patel(pharmacy)=medium/warm; officer(airport)=low/neutral и т.п.

Оба поля опциональны в типе на время миграции; экран и сервер деградируют корректно, если их нет (старое поведение).

## 3. AI-контракт (`functions/src/premium_dialog.ts`)

Один вызов, модель возвращает reply + строгий JSON-сайдкар. Формат — JSON-объект целиком (response_format json_object у OpenAI снижает риск порчи), парсим на сервере, наружу клиенту отдаём разобранные поля.

Серверный ответ (`PremiumDialogResponse`) расширить:

```ts
interface DialogTurnState {
  /** Настроение собеседника 0..100. Клиент мапит в смайл, не показывает число. */
  mood: number;
  /** id выполненных к этому моменту под-целей (накопительно). */
  objectivesMet: string[];
  /** 'ongoing' | 'success' | 'lost_patience' | 'stalled'. */
  outcome: 'ongoing' | 'success' | 'lost_patience' | 'stalled';
  /** Реакция персонажа от 1-го лица для финального модала (только при outcome!='ongoing'). */
  characterReaction?: string;
  /** 1-2 короткие фразы разбора «что сказать в следующий раз» (мягко, без занудства). */
  coachTips?: string[];
}
```

Промпт (добавка к SCENARIO_BLOCK), ключевые правила:
- Веди скрытый mood-счётчик, стартовое значение по temperament (high≈85, medium≈70, low≈55).
- ПОВЫШАЙ mood за вежливость и движение к под-целям. ПОНИЖАЙ за грубость, оффтоп, бесконечные повторы; у `patience:'low'` — ещё и за затягивание/воду.
- **ЯЗЫКОВЫЕ ОШИБКИ mood НЕ понижают** (это учебное приложение — soft correction остаётся). Понижает только намеренно плохое поведение в роли.
- Отмечай выполненные под-цели в `objectivesMet`.
- Ставь `outcome:'success'` когда ВСЕ под-цели выполнены → тепло закрой сцену.
- `outcome:'lost_patience'` когда mood≤0 → выйди из сцены в характере (officer машет следующему).
- `outcome:'stalled'` когда ~8+ ходов без нового прогресса целей.
- При любом терминальном outcome заполни `characterReaction` (1-2 предложения, в характере) и `coachTips`.

**Фолбэк (обязателен):** если JSON не распарсился — отдать reply как раньше, `outcome:'ongoing'`, mood=neutral, objectivesMet=[]. Диалог продолжается как обычный чат, фича просто «молчит» этот ход. Никогда не падать из-за битого JSON.

Биллинг/квоты/лимиты — без изменений (тот же платный вызов).

## 4. Клиент (`app/ai_dialog_session.tsx`)

Состояние:
- `mood` (число) → производный `moodFace` (😊 mood≥66 · 😐 33–65 · 😠 <33). Только смайл в шапке, рядом с «онлайн».
- `objectivesMet: Set<string>` — для чек-листа и прогресса «2/3» (опционально в шапке мелким).
- `outcome` → если `!== 'ongoing'`, блокируем ввод и показываем **модал-вердикт** (через OverlayArbiter — правило из памяти про авто-модалки главной; здесь экран не главная, но Modal со statusBarTranslucent лучше гейтить, чтобы не ловить фриз — проверить, нужен ли арбитр на этом экране).

Модал-вердикт (заменяет нынешний сухой `ended`-блок):
- Заголовок по исходу: «Получилось!» / «Собеседник потерял терпение» / «Разговор заглох» (8 языков).
- Аватар персонажа + имя (personaName уже извлекается) + финальный смайл.
- `characterReaction` курсивом (реакция от 1-го лица).
- Чек-лист `objectives` с галочкой/крестиком (выполнено/упущено).
- `coachTips` — 1-2 фразы разбора.
- XP-награда по исходу (success > stalled > lost_patience, но всё >0).
- Кнопки: «Ещё раз» (перепройти) · «К диалогам».

Смайл по ходу обновляется на каждом ответе ИИ из `mood`. Анимация смены лица — лёгкий fade (без жести).

Макет трёх исходов согласован визуально (карточки success/lost_patience/stalled).

## 5. XP по исходу (`app/...` — существующая XP-система)

- success: полный XP (напр. базовый +бонус).
- stalled: ~60% базового.
- lost_patience: ~40% базового (попытка ценна).
Точные числа подобрать по текущей XP-экономике диалогов (где начисляется XP за `ai_dialog_completed`). НЕ вводить новую валюту.

## 7. ВАЖНО: координация сессий (блокер реализации)

На момент написания (2026-06-21) рабочее дерево грязное:
- `app/ai_dialog_scenarios.ts` — редактируется ДРУГОЙ сессией (mtime свежее моих правок).
- `functions/src/premium_dialog.ts` — ДРУГАЯ сессия переписала COMPANION_BLOCK/GLOBAL_RULES на нейтральный язык ({LEARNER_LANG_NAME}, renderLanguageTemplate).

Эта фича глубоко правит ОБА файла. Чтобы не затереть чужую несохранённую работу — реализацию начинать ТОЛЬКО когда эти файлы освободятся (закоммичены/чисты) либо после явной координации. Сам дизайн-документ — отдельный новый файл, конфликта не создаёт.

Порядок реализации, когда разблокируется:
1. Данные: objectives + temperament в scenarios (+ типы). Миграция мягкая (опц. поля).
2. Сервер: JSON-сайдкар в промпт + парсер с фолбэком + расширить response. Контракт-тесты.
3. Клиент: смайл в шапке, чек-лист, модал-вердикт, XP по исходу. Чистые модули + тесты.
4. Деплой functions + билд приложения.
