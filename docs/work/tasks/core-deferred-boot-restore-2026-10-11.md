## Outcome
Факты: [BOOT-RESTORE-APPLY] 25–44 с на старте (ожидание замков), делит поток с первым кадром Главной. Для
вернувшегося на этом телефоне человека (локальные данные уже сведены с его облаком) облако может прийти на
несколько секунд позже без потерь: восстановление стартует после кадра Главной и простоя, не позже 8 с, сразу —
при уходе в фон. Для всех остальных (первый вход, другой аккаунт, онбординг, недоказанная личность) — как сейчас.

## Scope
In: `app/boot_restore_defer.ts` (решение + отложенный запуск + рубильник), `app/boot_restore_dirty_keys.ts`
(ключи, записанные за время ожидания), `app/_layout.tsx` (bootstrap: решение, метка владельца),
`app/cloud_sync.ts` (защита «последняя запись» в ветке «облако главнее», метка в инвентаре аккаунта),
`app/local_account_data.ts` (метка — не «значимые данные»). Out: сервер, формат облака, слияния.

## Architecture
Две ловушки — оба места запуска (bootstrap и runHeavyInit) берут ОДИН промис `cloudHydratePromise`, назначенный
сразу. Откладываем только если: метка `boot_restore_owner_v1` == uid, `onboarding_done==='1'`, личность чистая
(`freshIdentity.status==='ready'`, `recoveryGate.result==='proceed'`), слежение за записями хранилища включено,
рубильник `bools.boot_restore_defer_enabled !== false` в кэше remote_config (действует со следующего холодного
старта). Перед стартом — проверка поколения аккаунта: сменилось → отмена без тоста и без синка. Защита «последняя
запись»: ключи, записанные локально за время ожидания, в ветке «облако главнее» не перезаписываются облаком
(кроме ключей со своими правилами слияния — они и так сохраняют локальное). Метка пишется после успешного
восстановления и стирается вместе с данными аккаунта.

## Security and privacy
Новых данных наружу нет; метка — uid этого же аккаунта локально, стирается при выходе/смене/удалении.
