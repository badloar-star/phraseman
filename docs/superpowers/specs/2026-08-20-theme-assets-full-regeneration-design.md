# Полный аудит и регенерация тематических ассетов Phraseman

**Дата:** 2026-08-20  
**Статус:** утверждено владельцем  
**Область:** только растровые ассеты, которые реально переключаются вместе с темой интерфейса

## 1. Контекст

В `assets/images` находится 1 764 файла. Первичный статический проход нашёл 944 уникальных изображения, подключённых через `require()`, и 539 путей, лексически связанных с девятью действующими темами. Эти числа являются только отправной точкой: часть путей общая для нескольких тем, часть содержит слово темы по другой причине, а некоторые реестры имеют неполную паритетность.

Цель работы — не размножить весь графический контент приложения, а полностью проаудировать и перегенерировать только те подключённые UI-ассеты, источник которых меняется при смене темы интерфейса.

## 2. Утверждённые решения владельца

1. Остаются девять живых тем:
   - `indigo`;
   - `sagePorcelain`;
   - `olive`;
   - `midnight`;
   - `ember`;
   - `aurora`;
   - `volt`;
   - `dark`;
   - `gold`.
2. Темы `minimalDark`, `candyBlue`, `business`, `businessLight` удаляются полностью из приложения: из типов, палитр, реестров, специальных веток, статических `require()`, тестов и тематических папок.
3. Старое сохранённое значение любой из четырёх удалённых тем мигрирует в `indigo`. Миграция остаётся явной и тестируемой даже после удаления режимов из `ThemeMode`.
4. Регенерируются только реально подключённые и достижимые тематические растровые ассеты.
5. Неподключённые изображения не получают новые варианты и не попадают в бандл.
6. Полностью удаляются и исключаются из генерации:
   - `level_gifts` и `level_gift_reward_icons`;
   - тематические сундуки `league_bonus/*-chest`;
   - `weekly_boon_icons`;
   - тематическая картинка «Фразы дня» из `trainer_theme_icons/*/phrases.webp`.
7. Удаление перечисленных картинок не является разрешением удалить действующие награды, лиги, дары недели или «Фразу дня». Там, где поверхность продолжает существовать, она временно получает кодовый нейтральный fallback без нового raster-ассета.
8. Визуальное направление — утверждённый вариант C: единая мягкая 3D-грамматика и собственные физические материалы каждой темы, а не простая перекраска.
9. Производственная стратегия — утверждённый вариант B: сначала эталон слота, затем девять тематических вариантов с зафиксированными композицией, ракурсом, масштабом и смыслом.

## 3. Источник истины аудита

Аудит строится от кода к файлам, а не от содержимого `assets/images`.

В область регенерации входит ассет, только если одновременно выполнены условия:

1. Он подключён статическим `require()` в рабочем коде `app/`, `components/`, `constants/`, `hooks/`, `lib/` или `modules/`.
2. Его реестр или ветка реально выбирает разные источники в зависимости от живого `ThemeMode`.
3. Потребляющая поверхность достижима в приложении.
4. Ассет не входит в утверждённое семейство на удаление.

Каждый тематический реестр преобразуется в логический слот. Для каждого слота формируется матрица:

```text
family / slot / consumer / source registry
  indigo          -> file
  sagePorcelain   -> file
  olive           -> file
  midnight        -> file
  ember           -> file
  aurora          -> file
  volt            -> file
  dark            -> file
  gold            -> file
```

Алиас на чужой файл считается пропуском темы, если только аудит явно не докажет, что этот слот намеренно общий. Новый тематический файл разрешён только после появления статического `require()` для соответствующего слота.

## 4. Артефакты аудита

Аудитор создаёт проверяемые отчёты вне bundled asset tree:

- JSON-манифест всех подключённых тематических слотов;
- Markdown-сводку по семействам;
- список отсутствующих вариантов;
- список алиасов между живыми темами;
- список подключённых файлов, которые отсутствуют на диске;
- список тематических файлов без потребителя;
- список путей и веток четырёх удаляемых тем;
- список файлов четырёх удаляемых семейств;
- размеры, формат, наличие alpha и вес каждого финального файла.

Отчёты и генерационные исходники хранятся в игнорируемой рабочей директории `.codex-tmp/theme-assets-v2/`. В `assets/images/**` попадают только финальные сжатые файлы, которые статически подключены приложением.

## 5. Визуальная грамматика C

### 5.1 Общие инварианты

Для одного логического слота во всех девяти темах неизменны:

- смысл объекта;
- силуэт и доля кадра;
- угол камеры и перспектива;
- направление света;
- безопасные поля;
- точка визуального центра;
- уровень детализации;
- прозрачность или форма контролируемой подложки;
- читаемость на фактическом размере в приложении.

Общий язык:

- premium soft-3D без мультяшного пластика;
- простые округлые формы;
- умеренная предметная материальность;
- мягкий студийный свет;
- аккуратная контактная и внешняя тень;
- ограниченное число вторичных деталей;
- никакого текста, букв, цифр, логотипов, водяных знаков или псевдописьма внутри изображения;
- цвет не является единственным различием между темами.

### 5.2 Материальный характер тем

| Тема | Основные материалы | Акценты | Запрещённый дрейф |
|---|---|---|---|
| `indigo` | индиго-керамика, лавандовая эмаль, тёплая бумага | приглушённая латунь | не уходить в детский фиолетовый пластик |
| `sagePorcelain` | молочный фарфор, матовый шалфей, светлый камень | сдержанная ботаника | не делать белое на белом без контура и тени |
| `olive` | дымчатая оливковая эмаль, известняк, состаренная бронза | сухая зелень | не превращать в хаки/милитари |
| `midnight` | тёмно-синее стекло, обсидиан, холодная эмаль | серебро, лунный камень | не терять силуэт в чёрном фоне |
| `ember` | терракота, медь, пергамент, тёплая керамика | сухая ботаника | не делать всё оранжевым и перегретым |
| `aurora` | перламутровое стекло, полупрозрачная эмаль | teal-violet перелив, холодное серебро | не использовать шумный rainbow-gradient |
| `volt` | графитовая керамика, полупрозрачный lime-polymer | электрический лайм | никакого белого текста/символов на лайме; не превращать в кислотный шум |
| `dark` | лесная эмаль, угольный камень, тёмно-зелёное стекло | тёплая латунь | не сливать объект с фоном |
| `gold` | чёрный рояльный лак, шампанский металл, ivory-эмаль | тонкая античная бронза | не делать жёлтый пластик или дешёвый блеск |

## 6. Производственный конвейер B

### 6.1 Нормализация слота

Перед генерацией для каждого слота фиксируются:

- назначение и потребитель;
- текущая рамка и фактический размер показа;
- целевой pixel size;
- режим фона и alpha;
- safe area;
- семантический объект;
- обязательные и запрещённые детали;
- эталонный prompt без темы;
- theme material override для девяти тем.

### 6.2 Эталон и варианты

1. Генерируется один эталон слота в выбранной базовой теме.
2. Эталон проходит визуальную проверку в фактической рамке приложения.
3. После фиксации эталона создаются девять тематических вариантов отдельными запросами, а не одним атласом.
4. Каждый вариант сохраняет инварианты слота и меняет только утверждённый material override.
5. Плохой вариант перегенерируется точечной корректировкой одного свойства; эталон и остальные темы не меняются.

### 6.3 Безопасность генерации

- Используется встроенная генерация Codex, которая не читает и не расходует проектный или пользовательский `OPENAI_API_KEY`.
- CLI/API fallback для image generation запрещён Phraseman OpenAI API Firewall.
- Большой набор разбивается на небольшие семейства.
- После каждого семейства результаты экспортируются в файлы и проверяются; base64-ответы не накапливаются в одной сессии.
- Исходники, варианты и contact sheets не кладутся в `assets/images/**`.

### 6.4 Постобработка

- Финальный формат — WebP, если конкретный runtime-контракт не требует другого.
- Alpha сохраняется там, где объект должен быть вырезанным.
- Размеры приводятся к контракту слота без растяжения.
- Используется визуально достаточное сжатие примерно в диапазоне quality 58–80; точное значение выбирается по семейству.
- Перед подключением проверяются края, halo, фон, цветовой профиль и вес.

## 7. Изменения архитектуры тем

Удаление `minimalDark`, `candyBlue`, `business`, `businessLight` включает:

- сокращение `ThemeMode`;
- удаление палитр и импортов;
- удаление `THEME_MAP` и специальных layout/flat-mode веток;
- удаление записей во всех `Record<ThemeMode, ...>`;
- удаление реестров и `require()` их ассетов;
- замену legacy fallback на один явный `indigo` fallback;
- сохранение строковой миграции старых AsyncStorage-значений;
- удаление тематических папок и файлов только после доказанного отсутствия потребителей;
- обновление узких контрактных тестов.

Слово `business` в учебном контенте, категориях карточек и обычной предметной области не относится к удаляемой теме и не изменяется.

## 8. Удаляемые семейства и временные fallbacks

После удаления raster-источника потребитель обязан компилироваться и сохранять поведение.

- Подарки уровня: контейнер, название награды и логика выдачи остаются; изображение заменяется кодовой нейтральной пиктограммой или геометрической заглушкой.
- Сундук лиги: экономика, получение результата и модалки остаются; raster chest удаляется, поверхность использует кодовый нейтральный знак награды.
- Дары недели: boon-логика и тексты остаются; raster icon map удаляется, используется единый кодовый символ без тематического bitmap.
- «Фраза дня»: карточка, вопрос, XP и сохранение остаются; декоративная тематическая картинка удаляется без замены новым raster-файлом.

Ни одна проверка не должна быть ослаблена ради удаления изображений. Если тест требует старый raster-путь, тест обновляется на новый утверждённый контракт сохранения функциональности без bitmap.

## 9. Порядок внедрения

1. Создать детерминированный аудитор и baseline-отчёт.
2. Добавить красные контрактные тесты для девяти тем, удаления четырёх legacy-тем и запрещённых семейств.
3. Удалить legacy-темы из runtime-кода и миграционно сохранить переход в `indigo`.
4. Удалить четыре запрещённых семейства raster-ассетов и внедрить code-native fallbacks.
5. Повторно построить матрицу; она становится окончательным списком регенерации.
6. Обрабатывать семейства по одному: эталон → девять вариантов → постобработка → wiring → визуальный QA → узкие тесты.
7. После каждого семейства запускать orphan/missing/parity guards.
8. В финале выполнить полный статический аудит тематических ассетов и узкую runtime-проверку основных поверхностей во всех девяти темах.

## 10. Ошибки и восстановление

- Генерация не перезаписывает рабочий файл до прохождения QA; финал сначала получает staging path.
- Для каждого слота хранится checkpoint: prompt, входной эталон, theme override, размер, hash и статус проверки.
- Повторный запуск идемпотентен: готовый подтверждённый hash пропускается.
- Ошибка одного варианта не блокирует сохранение уже подтверждённых вариантов, но семейство не считается готовым до полного паритета.
- Существующая грязная рабочая директория считается пользовательской; затрагиваются только файлы из явного manifest и нельзя откатывать чужие изменения.
- Файлы Арены не откатываются и не перезаписываются из старых копий.

## 11. Проверки

### Статические

- `ThemeMode` содержит ровно девять живых режимов.
- Ни один рабочий тематический реестр не содержит четырёх удалённых режимов.
- Ни один статический `require()` не указывает на удалённые тематические папки или запрещённые семейства.
- Каждый слот имеет ровно девять отдельных живых источников — по одному статически подключённому файлу на тему. Алиасы между живыми темами запрещены.
- Каждый подключённый путь существует на диске.
- Каждый новый bundled image имеет статический потребитель.
- В удаляемых папках не осталось файлов.
- Формат, размеры и alpha соответствуют slot contract.

### Визуальные

- смысл слота одинаков во всех темах;
- silhouette/scale/angle не дрейфуют;
- тема узнаваема по материалу и акцентам;
- объект читается в реальном размере;
- отсутствуют текст, псевдотекст, watermark и обрезанные детали;
- светлые объекты не исчезают на светлой теме;
- тёмные объекты не исчезают на тёмной теме;
- лаймовые поверхности соблюдают dark-foreground contrast rule.

### Runtime

- приложение загружается с каждой из девяти тем;
- старые сохранённые четыре значения мигрируют в `indigo`;
- домашний экран, уроки, карточки, профиль/социальные поверхности, серия, сезон и турнир не получают missing-module ошибок;
- подарки, лига, дары недели и «Фраза дня» сохраняют работу без удалённых bitmap-файлов.

## 12. Критерии готовности

Работа завершена только когда:

1. Аудитор выдаёт полный зелёный отчёт без missing, orphan и legacy references в утверждённой тематической области.
2. Все реально подключённые тематические слоты имеют утверждённый паритет по девяти темам.
3. Все финальные варианты следуют style-lock C и прошли визуальную проверку.
4. Четыре legacy-темы отсутствуют в runtime-контрактах и bundled assets, но их сохранённые значения безопасно мигрируют.
5. Четыре запрещённых семейства изображений удалены и не генерируются.
6. Действующие функции не удалены и не сломаны из-за чистки картинок.
7. В `assets/images/**` нет новых неподключённых или несжатых файлов.
8. Узкие тесты и обязательные asset guards зелёные.
