# Крестик пейвола из Настроек: задержка закрытия 532–668 мс → цель ≤ 250 мс (15.10)

Governance-ID: TG-8B09ED9AAB9A

## Outcome
Закрытие пейвола крестиком (контекст `settings`) от отпускания пальца до первого кадра Настроек укладывается в ≤ 250 мс. Измерено Сверкой (evidence/tabs_tap_r7d): 532–668 мс. Сначала журнал `[PAYWALL-CLOSE-TIMING]` с таймлайном по этапам, потом правка по фактам.

## Scope
Журнал: новый `app/paywall_close_trace.ts`; точки в `app/paywall_purchase.ts` (`handleClose`/`doClose`), `app/navigation_back.ts` (`dismissPaywallModal`), `app/premium_modal.tsx` (размонтирование), `app/(tabs)/settings.tsx` (фокус, кадры, число перерисовок). Правка по результатам журнала — отдельным шагом. Файлы пейвола — общая зона с сессией «Авторизация» (предупреждена).

## Architecture
Модуль-счётчик: `paywallCloseMark(stage)` держит t0 с первого `handleClose` и пишет `+N мс (Δ…)` на каждом этапе: handleClose → начало/конец аналитики и планирования уведомления → вызов dismiss → «пульс» JS-потока (0/50/150/300 мс) → размонтирование пейвола → фокус Настроек → два кадра. `paywallCloseRender` считает перерисовки Настроек, пока закрытие идёт. Сами логи одна строка на этап, активны только между закрытием и вторым кадром (3 с предохранитель).

## Security and privacy
Данные не затрагиваются: в журнал идут только названия этапов и миллисекунды.

## Technical debt
Старые `[WINBACK-FREEZE]` и `[PAYWALL-CLOSE-FREEZE]` оставлены до разбора; после правки лишнее убрать, а логи в ранних выходах и catch оставить.

## Verification
Закрытие крестиком на эмуляторе (Сверка/координатор), строка `[PAYWALL-CLOSE-TIMING]` с итогом; контрактный тест на точки журнала.
