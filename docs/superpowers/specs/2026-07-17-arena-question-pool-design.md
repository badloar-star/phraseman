# Arena: управляемый пул вопросов

Дата: 2026-07-17  
Статус: согласовано для планирования  
Область первого выпуска: английский язык для русскоязычного пользователя (`en` / `ru`).

## Цель

Дать редактору быстрый и безопасный способ пополнять вопросы Арены партиями по 10 через существующий Content Factory. Матчи всегда выбирают готовые опубликованные вопросы быстро, не ожидая генерации, и не повторяют недавно показанные вопросы участникам без необходимости.

## Пользовательский сценарий админа

1. Админ открывает Admin V2: `Контент → Арена → Пул вопросов`.
2. Выбирает пул сложности (`A1`, `A2`, `B1` или `B2`) и тему.
3. Нажимает «Создать 10 вопросов». Content Factory создаёт черновую партию: у каждого вопроса ровно четыре уникальных варианта, один правильный ответ, объяснение/правило и метаданные качества.
4. Админ просматривает карточки. До публикации можно перегенерировать всю партию или заменить один вопрос, не меняя остальные.
5. Админ одобряет партию и нажимает «Добавить в пул». Только после этого вопросы становятся доступны матчам.
6. В пуле админ фильтрует вопросы по сложности, теме, статусу и дате; видит запас, историю и карточку вопроса. «Убрать из пула» прекращает выдачу вопроса, но не стирает его и его аудит.

## Навигация и UX

`Пул вопросов` не становится восьмым пунктом верхнего левого меню. Он размещается внутри раздела `Контент` как экран Арены: это сохраняет лимит в семь крупных разделов Admin V2 и не разносит связанную работу по разным местам.

На экране одна главная задача: управление опубликованным запасом вопросов Арены. Первый экран показывает состояние пулов и кнопку «Создать 10 вопросов». Генерация, просмотр и публикация остаются последовательными шагами с понятными статусами `черновик`, `на проверке`, `в пуле`, `снят с выдачи`. Все действия имеют текст, tooltip, loading/error state и аудит.

## Разделение данных

Существующий Content Factory остаётся источником неизменяемых артефактов, проверок качества и журнала смысловых ключей. Новый runtime-пул хранит только одобренные, готовые к выдаче записи и их состояние доступности. Это не «кэш» и не синхронная генерация на поиске матча.

Запись runtime-пула содержит как минимум: идентификатор вопроса, языковую пару, уровень CEFR, тему/skill tag, сложность, четыре варианта, правильный индекс и текст ответа, состояние доступности, происхождение (stage/artifact/release), даты публикации/снятия и случайный ключ выбора. Снятие с выдачи обратимо и сохраняет доказательства происхождения.

## Привязка рангов

| Ранги | Пул |
| --- | --- |
| Bronze I–III | A1 |
| Silver I–III, Gold I–III, Platinum I–III | A2 |
| Diamond I–III, Master I–III | B1 |
| Grandmaster I–III, Legend I–III | B2 |

Матч с игроками разных рангов использует уровень самого высокого ранга в лобби — это существующее правило и сохраняется.

## Подбор матча

1. После нахождения игроков сервер выбирает 10 уже опубликованных активных вопросов только из нужной языковой пары и пула уровня.
2. Сначала исключаются вопросы, недавно показанные любому участнику матча; история хранится серверно и ограничена размером/сроком жизни.
3. Затем выбирается разнообразный набор по теме, типу и сложности. При недостатке доступных свежих вопросов подбор ослабляет ограничения по заранее заданному порядку и фиксирует диагностическое событие, но не ждёт генерацию.
4. Все 10 идентификаторов записываются в сессию атомарно до её открытия игрокам.

## Границы первого выпуска

- Только `en` / `ru`; схема всегда хранит языковую пару, но другие пары не выдаются, пока для них не добавлен контент и явное включение.
- Только ручное создание и ручная публикация через Admin V2.
- Никакой генерации во время поиска матча и никакой автоматической публикации.
- Не меняется текущая система рангов, начислений, результатов, очереди или бот-матчей.
- Жёсткое удаление опубликованного контента не является действием интерфейса; вместо него применяется обратимое снятие с выдачи.

## Критерии приёмки

- Админ может создать, проверить, заменить один вопрос или всю черновую партию из 10 и опубликовать только одобренную партию.
- Вопрос с нечетырьмя уникальными вариантами, неверным correct index, неподходящей языковой парой, уровнем или смысловым дублем не попадает в пул.
- Активный вопрос из пула выдаётся только для `en` / `ru` и соответствующего A1/A2/B1/B2.
- Матч получает 10 готовых вопросов без ожидания генератора; недавно показанные участникам вопросы избегаются при достаточном запасе.
- Снятый вопрос не выдаётся новым матчам, остаётся в аудите и может быть возвращён в пул.
- В Admin V2 есть понятные loading/empty/error состояния, действие публикации объясняет последствия и оставляет audit log.

## Проверка

Нужны узкие unit/emulator tests для: схемы пула, публикации/снятия/возврата, дедупликации, контроля языковой пары и уровня, алгоритма исключения недавних вопросов, атомарного создания матч-сессии и доступа к новым admin callable. Для UI нужны контрактные проверки route/actions/labels Admin V2. Существующие контракты matchmaking, Firestore rules, Content Factory и Arena runtime должны остаться зелёными.
