## 1. Алерт ≠ потолок (PM-224-A1)

| Механизм | Что это | Останавливает трату? | Задержка | Что происходит при срабатывании |
|---|---|---|---|---|
| Бюджет Google Cloud Billing (Budgets & alerts) | **алерт** | Нет. Только письмо / сообщение в Pub/Sub при пороге | данные о расходах приходят с задержкой (часы, до суток) — трата успевает уйти дальше порога | ничего не выключается; владелец получает письмо |
| Авто-отключение биллинга по Pub/Sub (функция `disableBilling`) | **потолок проекта целиком** | Да, но грубо | та же задержка данных + время функции | ложится ВСЁ: Firestore, вход, хостинг, покупки, удаление аккаунта. **Не рекомендуется** — убивает выдачу оплаченного |
| Blaze (Firebase) | — | своего потолка нет | — | — |
| Лимиты OpenAI (Settings → Limits: месячный бюджет / пороги уведомлений по организации и проекту) | алерт; есть ли **жёсткий** потолок на этом аккаунте — **проверить владельцу** | неизвестно для этого аккаунта | неизвестно | при жёстком потолке OpenAI отвечает ошибкой квоты → наши функции уходят в ветку «провайдер недоступен» |
| Квота YouTube Data API (10 000 ед./сутки по умолчанию) | **жёсткий потолок вендора** | Да | мгновенно | `youtubeCatalogSyncCron` получает 403 quotaExceeded до полуночи по Тихоокеанскому времени; каталог не обновляется, приложение показывает прежний снимок |
| `maxInstances` у функций (например, диалоги 20) | потолок параллелизма | Ограничивает скорость траты, не сумму | мгновенно | лишние запросы получают отказ «нет свободного инстанса»; клиент повторяет (`ai_callable_resilience`) |
| **Наши кап-счётчики в коде** (§2) | **потолок операции** | Да, до вызова OpenAI | мгновенно (транзакция Firestore) | отказ `resource-exhausted` / отложенный статус; деньги не тратятся |
| **Рубильник ИИ** `remote_config/app.bools.ai_global_disable` (§3) | **ручной стоп** | Да, до вызова OpenAI | сервер: следующий вызов (читается на каждом вызове, кэша нет); клиент: до 6 ч (TTL remote config, 40ad82f77), но сервер отказывает сразу | `failed-precondition ai_globally_disabled`; кэшированные ответы продолжают отдаваться бесплатно |

Вывод: алерты Google/OpenAI сообщают о трате постфактум; реально останавливают трату только
счётчики в коде, рубильник и квоты вендоров. Поэтому основная защита — в коде, алерты — сигнал.

## 3. Рубильник ИИ — покрытие (изменено в этой пачке)

`ai_global_disable` проверялся в: legacy-диалоги (send/stream/translate), Dialogue V2
start/turn/complete, explain phrase/choice, mistake_hub_advice.

**Добавлено 2026-10-01 (код, без деплоя):**
- `mistake_explain.ts` — проверка перед платным вызовом (только на промахе кэша; кэш отдаётся и при
  выключенном ИИ; pending-замок снимается штатно, дневной кап не списывается). Тест:
  `mistake_explain.test.ts` «global AI kill switch blocks a fresh paid breakdown but still serves the warm cache».
- `card_tts_worker.ts` — при выключенном ИИ набор уходит в `deferred_budget` с причиной
  `ai_globally_disabled`, OpenAI не вызывается, суточный бюджет знаков не трогается; повторное
  использование уже готовых клипов работает. Возврат в очередь — `adminCardTtsRequeuePack`.
  Тесты: `card_tts_worker.test.ts` (2 новых).

**Не покрыто (вне этой пачки — файлы в активной работе другой сессии, в рабочем дереве лежат её
неотслеженные тесты Dialogue V2):** `premiumDialogReview` (текстовый разбор), `dialogueV2Freeform*`
(свободный разговор). Их держат дневные капы §2, но ручного стопа у них нет.

**Мёртвый переключатель (находка):** в админке «Пульт» есть галка «ИИ-диалог (Theo) включён»
(`admin/v2/legacy.html`, пишет поле `dialog` документа `admin_runtime_config/openai_jobs` через `openAiJobsConfig`), но ни одна
серверная функция это поле не читает (`assertJobEnabled(…, 'dialog')` нигде не вызывается). Владелец,
сняв галку, думает, что остановил диалоги, а они работают. Рабочий стоп — `ai_global_disable`.
Решение — вопрос координатору (подключить к диалогам или убрать галку).

## 5. Статус критериев

- **A1 (алерты отличаются от потолков)** — выполнено документом: §1 разделяет алерты и потолки
  по каждому механизму, §2–3 перечисляют реальные потолки и стопы в коде.
- **A2 (проверены доступность потолков по сервисам, задержка, поведение при остановке)** — для
  наших потолков и рубильника проверено кодом и тестами (§2–3); для Google Cloud Billing и OpenAI —
  **не проверено в консолях** (шаги 1–2 §4, владелец). Критерий не принят до ответа владельца.
