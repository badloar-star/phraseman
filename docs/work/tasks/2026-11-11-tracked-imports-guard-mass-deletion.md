# Task packet: сторож импортов не зависает на массовом удалении

Governance-ID: TG-6DF257BF4D9E
Status: In progress
Owner: сессия удаления курса занятий (владелец разрешил правку сторожа 11.11, вариант «Ускорить сторож»)
Related epic/enabler: удаление курса занятий из приложения и сервера

## Outcome

Коммит, который удаляет десятки тысяч файлов, проходит сторож `scripts/guard_tracked_imports.mjs --staged` за секунды, а не
за часы. Выигрывают все сессии: длинный pre-commit больше не держит индекс и не проигрывает гонку с чужими коммитами.
Мера успеха: сторож на наборе «удаление курса» (58 тыс. удалений) завершается быстрее минуты и по-прежнему находит
импорт, указывающий на удалённый или неотслеживаемый файл.

## Scope

In scope: `scripts/guard_tracked_imports.mjs` — только ветка `--staged`, способ выбора файлов-импортёров при большом числе
удалений.

Out of scope: остальные сторожа pre-commit, сам хук, режимы без `--staged`, правила того, что считается неразрешённым
импортом.

## Architecture

Сейчас для каждого удалённого файла запускается отдельный `git grep` по его имени, чтобы найти возможных импортёров:
стоимость растёт линейно от числа удалений (58 тыс. удалений — часы). Новая граница: если удалений больше порога,
сторож не ищет импортёров поштучно, а проверяет ВСЕ файлы приложения в индексе — это надмножество прежней выборки
(любой импортёр удалённого файла входит во «все файлы»), поэтому проверка не слабее. При числе удалений до порога
поведение прежнее. Инвариант: каждый относительный импорт проверяемого файла обязан разрешаться в файл индекса.

## Security and privacy

Не затрагивает аутентификацию, авторизацию, секреты и персональные данные: это локальный сторож pre-commit, он читает
только индекс git и ничего не отправляет наружу.

## Technical debt
