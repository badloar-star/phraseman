# Тесты Арены

```bash
bash tools/arena_tests/run.sh
```

Компилирует тесты Арены во временную папку `.arena-test-build/` и прогоняет их
крошечным прогонщиком. В конце печатает строку вида:

```
SUITES=39 ASSERTIONS=790 FAILED_SUITES=0
```

`ARENA_SKIP_BUILD=1` пропускает компиляцию — удобно, когда правился только код
самого прогонщика.

## Почему не jest

Jest в проекте не установлен, а тесты Арены написаны в его словаре. Здесь
реализовано ровно то, чем они пользуются: `describe`, `it`/`test`, `it.each`,
`expect` с обычным набором проверок, `expect.any` и `objectContaining`,
асинхронные тесты. Ничего сверх этого.

## Почему оснастка лежит в репозитории

Раньше она жила в `/tmp`. Среда однажды перезапустилась — и проверить работу
стало нечем, пока всю оснастку не написали заново. Оснастка, которой нельзя
доверять пережить ночь, не оснастка.

## Файлы

| Файл | Зачем |
| --- | --- |
| `run.sh` | сборка и прогон |
| `jestlite.js` | сам прогонщик и проверки |
| `mockshim.js` | заглушки Firebase и нативных пакетов: логика Арены от них не зависит, но `require` их задевает |
| `rootshim.js` | тесты-инспекторы читают исходники из репозитория, а не из папки сборки |
| `tsconfig.json` | что компилировать |

## Что сюда не входит

`functions/src/arena_v2_rules.emulator.test.ts` — ему нужен эмулятор Firestore,
он запускается отдельно.
