## Outcome

восстановления (смена аккаунта, состояние телефона, восстановление входа) не
имеет права держать его снаружи непроходимым модальным экраном.

Владелец 2026-09-22, дословно: «ее не должно быть, надо чтобы так работало чтобы

повторялся многократно и до сих пор не исполнен до конца.

Наблюдаемый результат: экран «Нужна безопасная проверка» больше не существует;
при нерешённом споре о владельце приложение открывается на **чистой локальной
сессии**, старые данные остаются на диске нетронутыми и невидимыми.

Мера успеха: не существует состояния хранилища, при котором приложение
открывается в непроходимый модал. Закреплено сторожем.

## Architecture

Текущая граница: `runAuthRecoveryBootGate()` — fail-closed. Любой вердикт кроме
`proceed` ведёт к модалу без выхода. `publish({ visible: true, status:
'quarantined' })` поднимает `AccountSwitchRecoveryScreen`, у которого
`onRequestClose` пуст, а единственная кнопка гоняет ту же проверку по кругу
(`validOwnerStable` сравнивает строки на точное равенство — при реальном
расхождении результат не изменится НИКОГДА).

Целевая граница: **fail-open для входа, fail-closed для данных.** Неудача
проверки владельца больше не запирает приложение — она переводит его в режим
чистой локальной сессии. Старые данные не стираются и не показываются, пока
владелец не подтвердится штатным входом.

Инвариант, который обязан сохраниться: при `owner_*_mismatch` / `marker_invalid`
локальные данные прежнего владельца **не отдаются** текущей сессии и **не
удаляются**. Меняется только то, что человек при этом внутри приложения, а не
перед стеной.

Управление: `invalidateAccountGeneration()` и `beginPremiumAccountTransition()`
остаются — именно они изолируют данные. Уходит только UI-стена и терминальность
ветки.

## Security and privacy

- Authn/authz: не ослабляется. Доступ к облачным данным по-прежнему решает
  Firebase Auth + правила Firestore; поколение аккаунта инвалидируется, поэтому
  чужой прогресс не подхватится.
- Персональные данные: локальные данные прежнего владельца остаются на
  устройстве нетронутыми и невидимыми для новой сессии — это строго безопаснее
  варианта «показать их всем».
- Риск, принятый осознанно: на общем устройстве новый вошедший увидит пустую
  сессию вместо стены. Это не утечка.
- Privacy Policy: изменений в сборе/хранении/передаче данных нет — новые поля не
  появляются, сторонние сервисы не подключаются. Политику править не нужно.
- Дети: не затрагивается.
