# Пик: пустой подиум (колонок нет) — экономия 0, ступень не качается (Ревизор по c5ccfd458, 🟡)

Governance-ID: TG-8CC2A8FB842B
Governance-ID: TG-C04117880920

## Outcome
Компактный подиум экономил константу 40 dp, даже когда колонок нет (пустая комната, офлайн без данных): компакт ничего не сжимает, а бюджет прибавлял 40 к верху окна и сдвигал границы. rawFit занижался, и при истинном значении 64–88 dp ступень качалась между «строка этажа» и режимом прокрутки. Теперь экономия подиума — 0, когда колонок нет.

## Scope
`components/spire/spire_tower_window.ts` (`spireStepSave`, параметр `podiumColumns` в границах/уровне/приведении верха), `use_spire_tower_budget.ts` (параметр `podiumColumns`, ref в layout-эффекте для пометки замера), `SpireHomeScreen.tsx` (колонки = скелет или комната не пуста; вызов хука перенесён ниже `members`), тест `spire_tower_window_height`.

## Architecture
Колонки подиума есть, когда `podiumLoading` (скелет: live, комната ещё не приходила) или `members` непусты. Границы лестницы и прибавка к измеренному верху считают экономию подиума через `spireStepSave(id, podiumColumns)`: без колонок 0 — границы для [подиум, строка]: 180 / 180 / 88. Пометка «сколько сняли с верха» берётся из колонок в момент замера (ref в layout-эффекте).

## Security and privacy
Данные не затрагиваются.

## Technical debt
Экономия подиума остаётся константой 40 при наличии колонок (самая высокая колонка при однострочном нике); при двухстрочных именах лишь меньшая колонка выше — погрешность ≤ гистерезиса 16.

## Verification
Юнит-тесты: границы с колонками/без, прибавка к верху, нет качаний при rawFit 44…134 со всех стартов, исходники хука и экрана; сторожа Пика.

## Rollback
Откат коммита.
