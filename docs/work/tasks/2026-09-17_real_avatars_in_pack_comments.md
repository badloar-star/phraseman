# Task packet: настоящие аватарки в комментариях (вместо emoji-заглушки)

Governance-ID: TG-F276A0AD8818
Status: In progress
Owner: Claude session (badloar@gmail.com)
Related epic/enabler: docs/work/tasks/2026-09-17_pack_comments_visual_redesign.md

## Outcome

Владелец увидел, что у каждого комментария под набором показывается
случайный emoji вместо настоящей аватарки автора (`avatarFor()` — хэш от
authorId → один из 8 emoji), и потребовал полноценный вид. Задача — заменить
заглушку на реальный `AvatarView` с данными из `public_profiles/{authorId}`.
Независимая консультация (советник) указала на самый дешёвый путь: уже
существующий кэш `packAuthorNames.ts` читает `public_profiles/{sid}` целиком
ради `.name` и выбрасывает `avatar/frame/aura` из того же документа — расширить
кэш вместо новых запросов, это даёт ноль дополнительных чтений Firestore.

## Scope

In scope:
- `app/community_packs/packAuthorNames.ts`: расширить кэш с `{name, at}` до
  `{name, avatar, frame, aura, at}`; бампнуть ключ кэша (`_v1` → `_v2`, иначе
  старые записи без avatar залипнут на TTL); снизить TTL профиля до 24 часов
  (аватарка/рамка/аура — покупаемая косметика, меняется чаще ника); новая
  функция `resolveCommunityAuthorProfile` возвращает весь профиль, старая
  `resolveCommunityAuthorNickname` остаётся для обратной совместимости (может
  переиспользовать новую внутри). Починить немой `catch` в
  `fetchPublicProfileName` (правило проекта — причина отказа не глушится).
- `app/community_packs/PackCommentsSheet.tsx`: заменить `avatarFor()`/emoji на
  `<AvatarView avatar={...} auraId={...} size={34} animateAura={false} />` с
  нейтральным фолбэком, пока профиль не подтянут/если аватарки нет; НЕ
  передавать `level`/`totalXP` (протухшая проекция может исказить уровень —
  известный баг «Издевательство», см. AvatarView.tsx). Свой оптимистичный
  комментарий получает свой аватар из локального источника сразу (не из
  public_profiles) — не ждать сети для собственной картинки. Вынести строку
  списка в отдельный `memo`-компонент, чтобы AvatarView не перерисовывался
  на каждый чужой ре-рендер шторки (подсветка/скролл).
- `functions/src/user_notifications.ts` (`notifyOnPackCommentCreated`):
  дописать `fromAvatar` в уведомление колокольчика — 1 доп. чтение
  `users/{uid}.progress.user_avatar` (тот же «горячий» источник, что уже
  использует `friend_activity_likes.ts`, не `public_profiles`, которая
  обновляется по расписанию клиентом).

Out of scope:
- Полная полировка визуала шторки за пределами аватарок (типографика,
  прочие детали) — отдельная более широкая задача при необходимости.
- Аватар автора набора в каталоге/плитках — тот же кэш это тоже почини́т
  «бесплатно» (он через ту же функцию), но отдельно не тестируется в этой
  задаче.

## Architecture

Не меняется структурно — расширяется существующий клиентский кэш профилей
автора, добавляется одно поле в уже существующий Cloud Function триггер.
Источник правды для чужого аватара — `public_profiles/{stableUid}` (уже
публично читаемая коллекция, `allow read: if request.auth != null`).

## Security and privacy

Не затрагивается — `avatar`/`frame`/`aura` уже публичные поля того же
документа, который уже читается ради имени; новых данных не собирается и не
раскрывается. `identityHidden`-профили (public_profiles не пишется для них)
корректно дают пустой профиль → нейтральный фолбэк, не ошибку.

## Technical debt

Нет нового долга.
