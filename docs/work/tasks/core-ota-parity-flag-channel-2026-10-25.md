# Ядро · OTA из HEAD: пропуск PARITY-GATE только явным флагом, публикация через --channel (25.10)

Governance-ID: TG-60EB9EF810F4

## Outcome
Решение координатора 25.10: PARITY-GATE для обновления по воздуху НЕ блокирует. Это реестр сверки уже выпущенных экранов 2.0.2:
те же расхождения уже у людей, OTA-1 и OTA-2 вышли так же. Пропуск должен быть осознанным, а не молчаливым: флаг
`--allow-parity-gate` с записью в журнал. Без флага красный PARITY-GATE — стоп. Условие координатора: новые экраны этого OTA
(экзамен v2, Мастерская фраз) проходят склейку «макет | эмулятор» до включения своего флага. Команда публикации —
`--channel production`, как в OTA-1 и OTA-2.

## Scope
scripts/ota_from_head.sh: разбор аргументов (ревизия + `--allow-parity-gate`), шаг precheck, печать команды публикации,
комментарий о том, что канал и ветка у нас одно и то же.

## Architecture
Проверено чтением: `eas channel:view production` → branchMapping `{"branchId": …, "branchMappingLogic": "true"}`, единственная
ветка production. Значит `--channel production` публикует ровно туда же, куда OTA-2 (`--branch production`, журнал
eas_update_ota2.log: «Branch production»). Канал надёжнее: если координатор когда-то перенаправит канал на другую ветку,
публикация пойдёт туда, куда смотрят сборки.

## Security and privacy
Без изменений: ключи не печатаются, скрипт ничего не публикует.

## Technical debt
Пропуск PARITY-GATE для OTA — временное решение до строгого прогона после R1. Флаг делает его видимым в журнале каждой
подготовки.

## Verification
`bash -n`; повторного полного прогона не нужно (меняется только ветка precheck и печать), проверка ветки — подстановкой
журнала прошлой репетиции.

## Rollback
