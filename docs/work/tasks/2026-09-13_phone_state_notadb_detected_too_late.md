## Outcome

Владелец видит на экране тренировок: «Не удалось открыть данные тренировок на
этом устройстве. Попробуй снова или перезапусти приложение». Кнопка «Попробовать
снова» не помогает НИКОГДА — состояние воспроизводится на каждом запуске.

Успех: база phone-state с неверным ключом распознаётся как нечитаемая В МОМЕНТ
ОТКРЫТИЯ, автоматически пересоздаётся, мост поднимается, тренировки карточек
открываются без ручных действий владельца.

## Факты из логов (не гипотеза)

`.expo/metro-console.log`, запуск 19:31:40–19:32:04:

```
[PHONE-STATE-DB] open:step 4/5 integrity rows=0
[PHONE-STATE-DB] open:step 5/5 страница прочитана, user_version={"user_version":0}
[PHONE-STATE-DB] open:ok                        ← база признана ИСПРАВНОЙ
[FC-TRAIN-ENTRY] bootstrap:FAILED за 1087мс — Error: Calling the 'finalizeAsync' function has failed
→ Caused by: Error code 26: file is not a database   ← NOTADB, но уже ПОЗЖЕ
[FC-TRAIN-ENTRY] bridge:unavailable — runtime моста не инициализирован
[FC-TRAIN-ENTRY] preview:out unavailable — чеки не прочитались
[FC-TRAIN-ENTRY] blitz entry:catch {"error":"Error: pending_grant_unavailable"}
```

Строк `open:catch`, `recover:verdict`, «пересоздаём» в логе **ноль**. То есть
механизм восстановления (добавленный 2026-09-13) не вызывался ни разу: до него
управление не доходит.

**Корень.** `openEncrypted` считает базу пригодной по двум проверкам, каждая из
которых на нерасшифровываемом файле даёт ложный успех:

1. `PRAGMA cipher_integrity_check` возвращает ноль строк. Ноль строк трактуется
   как «ошибок нет», но на битом файле прагма не выполняется вовсе и тоже даёт
   пустой результат. Отличить «цела» от «не смогла проверить» невозможно.
2. `PRAGMA user_version` задумывался как принуждение расшифровать первую
   страницу, но на битой базе он возвращает `0` вместо исключения — страница
   так и не читается.

Настоящая расшифровка происходит только при обращении к таблицам — в
`importLegacy`, уже ВНЕ `openPhoneStateDatabase`. Там NOTADB и вылетает, минуя
ветку восстановления, и приложение встаёт на этом месте каждый запуск.

## Scope

In scope: `modules/phone-state/database.ts` — замена ложных проверок на чтение,
которое физически расшифровывает страницу данных; тесты
`tests/phone_state_database_security.test.ts`.

Out of scope: `app/phone_state_bootstrap.ts` и `app/_layout.tsx` (их контракт
верен — они вправе ожидать от открытия пригодную базу); текст экрана-заглушки
(он честен и остаётся для случаев, когда восстановление невозможно).

## Architecture

- Проверка пригодности становится ЧТЕНИЕМ ДАННЫХ, а не чтением метаданных:
  `SELECT count(*) FROM sqlite_master`. Эта таблица — реальная страница базы,
  её нельзя прочитать без корректного ключа, поэтому на битом файле запрос
  бросает NOTADB внутри `try`, где его ловит существующее восстановление.
- `cipher_integrity_check` СОХРАНЯЕТСЯ как дополнительный сигнал (он ловит
  повреждение при верном ключе), но перестаёт быть единственным доказательством.
- Ветка восстановления и `isUnreadableDatabaseFailure` не меняются: они уже
  написаны верно, просто до них не доходило управление.

## Security and privacy

Новых данных, полей и сервисов нет. Пересоздание базы удаляет локальный файл,
который расшифровать невозможно в принципе (ключ утрачен) — потери данных сверх
уже случившейся нет; содержимое возвращают importLegacy и облачная синхронизация.
Privacy policy не затрагивается.
