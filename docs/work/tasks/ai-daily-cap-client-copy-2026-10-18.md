# Task packet: клиент — дневной потолок ИИ показывается спокойным «на сегодня всё»

Related epic/enabler: координатор 18.10 — «маппинг daily_spend_cap / *_rate_limited → спокойное «ИИ отдохнёт до завтра» везде, где платные вызовы». Сервер: 37e8d86cf, 4dc391249, c055fd6d9.

## Outcome

Сервер отказал по дневному потолку: общий потолок расходов `daily_spend_cap` или дневное окно uid/IP с суффиксом `_rate_limited`. Тогда человек видит спокойное «на сегодня всё, продолжим завтра», без технических слов, без кнопки Plus и без бесконечного «Повторить».

Где показывается:
- Диалоги V1 и V2;
- свободный разговор;
- перевод;
- объяснения и советы;
- озвучка.

Короткий сбой `rate_window_busy` / `spend_cap_busy` (код `unavailable`) остаётся обычным «попробуйте ещё раз».

## Scope

В работе:
- app/ai_daily_cap_signal.ts — один распознаватель `isAiDailyCapError` и список дневных окон сервера;
- подключение в существующие классификаторы:
  - Диалоги V1 (`classifyPremiumDialogError` → `premium_limit`, это уже экран «На сегодня разговоров достаточно»);
  - Диалоги V2 (`classifyDialogueV2TurnFailure` → `plus_daily_cap`, ввод закрыт, повтора нет);
  - свободный разговор (ошибка несёт причину daily_cap, плашка без «Повторить», старт без тихих повторов);
  - объяснения, советы, озвучка — ОТЛОЖЕНЫ по слову координатора 18.10 (все силы на вход), следующим заходом.

Вне работы:
- новые экраны и вёрстка: используются существующие пути «на сегодня всё»;
- часовые окна (dlg_turn, ff_turn и др.) — остаются «подожди немного»: они правда открываются через час.

## Architecture

Один распознаватель вместо копий по файлам. Классификатор каждого экрана проверяет его ДО общего `resource-exhausted`. Иначе отказ уехал бы в «слишком много сообщений подряд».
