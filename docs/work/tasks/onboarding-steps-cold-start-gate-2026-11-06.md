## Outcome

На свежей установке (кэша нет) список шагов из админки приходит из сети через ~3 с, когда маршрут уже выбран, — и человек видит все 12 шагов или пропускает нужные. Теперь welcome показывается сразу, «Начать» ждёт список (до ~4 с, индикатор на кнопке, без спиннера на весь экран), маршрут фиксируется один раз. Нет списка за 4 с → безопасный минимум welcome, language, name (+согласия на name), а не «всё включено».

## Scope

`app/onboarding_steps_gate.ts` (новый, чистое решение + ожидание), `components/CleanOnboarding.tsx` (кнопка «Начать» + фиксация маршрута, `go` принимает порядок), тест `tests/onboarding_steps_cold_start_2026_11_06.test.ts`. Кэш пришедшего списка уже делает `remote_config_client` (applyRemoteConfigCacheFromStorage) — не меняется.

## Architecture

`awaitOnboardingStepsList`: готов (`hasRemoteConfigSnapshotApplied`) → список сразу; иначе подписка на `remote_config_changed` + таймаут 4000 мс → безопасный минимум. Результат фиксируется (`routeLockedRef`): дальнейшие обновления списка маршрут не двигают. Журнал `[ONB-FLAGS] route:` — источник, ожидание мс, порядок.

## Security and privacy

Согласия живут на обязательном шаге name — он всегда в списке. Данные не собираются.

## Technical debt

Safe-minimum не включает privacy/niceToMeet/promise и т.п. — их возвращает только ответ Пульта. Проверка на эмуляторе — Сверка/Эмулятор.

## Verification

Тест: свежая установка + список админки → только шаги админки; таймаут → минимум; готовый кэш → без ожидания.

## Rollback

Вернуть прямой вызов go('privacy') на кнопке «Начать», удалить модуль.
