Всё за `FRIENDS_TOGETHER_UI_ENABLED=false`. Монет за победу нет (ECONOMY.md); добавить можно только D-решением.

## Как играется (макет)
1. Вызов — из шторки друга или визитки: «Дуэль с Ириной», факты «5 фраз · общие уроки 1–2 · 24 ч на ответ».
   «Начать дуэль» · «Без энергии · три вызова в день» · «Позже». Нет общих занятий — «Позвать на занятие» (идея 2).
2. Ход — 5 фраз «Собери фразу» (банк слов), сверху «Дуэль с Ириной · 2 из 5» и таймер. После каждой: «Верно · 7 секунд» / разбор.
3. Ход отправлен — «Ждём Ирину»: свои отметки видны, чужие — песочные часы. Нет сети — «Ход готов · сохранён на телефоне».
4. У друга — маркер «щит» с оставшимся временем; шторка «Алекс вызывает на дуэль»: «Принять» / «Отказаться».
   Счёт вызвавшего открывается только после своего хода.
5. Итог у обоих — счёт, время, таблица фраз; «Реванш» в одно касание, «Разобрать ошибки» → повторение.
6. Отказ и сутки без ответа — тихой строкой в «Сообщениях», «вызвать снова».

## Правила (клиент считает так же, решает сервер)
- Побеждает точность (верных из 5); при равенстве — меньшее суммарное время; равны и они — ничья.
- Время хода — сумма времени на 5 фраз, целые миллисекунды; телефон шлёт, сервер обрезает в пределах 0…15 мин.
- Срок ответа — 24 ч от создания; после — дуэль закрыта, ход вызвавшего сохранён.
- Три вызова в день на отправителя; повторный вызов того же друга, пока висит открытая дуэль, — нельзя.
- Без энергии.

## Firebase (условие координатора 22.10, поправки 1 · ЯДРО 22.10)
- Одна дуэль — один документ `friend_duels/{pairKey}_{seq}`: pairKey — оба stableUid по возрастанию. «Одна открытая дуэль на пару»
  держит детерминированный id (или документ-замок пары в транзакции) — без запроса where по коллекции, дешевле и без гонок.
- 1 запись — создание с id пяти фраз и ходом вызвавшего; 1 запись — ход друга (сервер считает итог в той же транзакции).
- Итог читается один раз при открытии (пуш, маркер, «Сообщения»). Слушателей в реальном времени нет.
- Тексты фраз — из курса на телефоне, по сети только id.
- Срок — лениво, без плановой функции: в документе expiresAtMs; любой вызов (Move, Decline, открытие) видит «просрочено» и
  закрывает дуэль в той же транзакции; телефон при показе сам сравнивает с expiresAtMs. Стоит 0 запусков вместо ~720 в месяц.

## Условие на будущее (1 · ЯДРО 22.10)

## Контракт сервера (для 1 · ЯДРО)
1. `friendsDuelChallenge` {stableId, senderDisplayName?, friendUid, phraseIds[5], move: {results: boolean[5], elapsedMs}, requestId}
   → {ok, duelId, expiresAtMs}. stableId и senderDisplayName телефон шлёт так же, как friendsLessonInvite
   (prepareTogetherSender): сервер сверяет stableId с вызывающим, имя — запасное. Проверки: дружба; ≤3 вызовов в день;
   нет открытой дуэли с этим другом; phraseIds — 5 разных строк ≤ 96 символов. Уведомление другу:
   nav {kind:'friend_event', action:'duel_challenge', duelId, expiresAtMs, lessonsLabel}. Пуш без счёта вызвавшего.
2. `friendsDuelMove` {stableId, duelId, move: {results: boolean[5], elapsedMs}, requestId}
   → {ok, outcome: 'win'|'loss'|'draw', mine: {correct, elapsedMs}, theirs: {correct, elapsedMs, results}}.
   Только адресат, только до срока, один раз (повтор того же requestId — тот же ответ). Вызвавшему — уведомление «Итог дуэли».
3. `friendsDuelDecline` {duelId} → {ok}. Вызвавшему — тихая строка «X не принял(а) дуэль».
4. Ошибки — подстрокой: `limit`, `open_duel`, `not_friends`, `expired`, `already_moved`, `not_invited`, `disabled`.
5. Срок — лениво (см. Firebase): строку «не ответил за сутки» вызвавший видит, когда его телефон или любой вызов по дуэли
   замечает просрочку; плановой функции нет.

## Ответы по коду (8 · МОМЕНТЫ, чтением, 22.10; Learning V2 проверит потом — решение координатора)
- **Языки не совпадают по содержанию.** Каркас курса общий (course_topology_v1: 32 урока × 56 занятий), но тексты
  занятий пишутся отдельно на каждый язык: es_authored_sessions_v1.ts — «испанский контур строит свой мост независимо»,
  сейчас там только занятие 1 (владелец 28.08 удалил 2–34). Одинаковых фраз по номеру нет.
  **Решение:** дуэль только между друзьями с одним изучаемым языком (studyTarget). Иначе «Дуэль» неактивна с надписью
  «Дуэль — когда учите один язык», вместо неё «Позвать на занятие» (идея 2).
- **Ход:** готовый режим PhraseBuilderModeV1 (modules/learning-v2/modes/phrase_builder_mode_v1.tsx). Им управляет игрок
  через LearningV2ModeCommonPropsV1 (prompt, options, orderedResponseIds, phase, onPick…) — для дуэли нужен маленький
  свой игрок на 5 фраз, новый контент не нужен.
- **Пройденные фразы:** тексты занятий лежат в приложении (ленивые статические require по номеру занятия); какие занятия
  пройдены — прогресс курса на телефоне. id фразы дуэли = язык·урок·занятие·номер задания; у обоих один язык, поэтому id
  совпадает.

## Сделано на телефоне (8 · МОМЕНТЫ, 22.10, за выключателем)
- **id фразы** — id задания курса из сборки: `en:lesson-02:session-03:i01` (бывают хвосты вида `:i15:s02`,
  `:practice:payment`; сейчас не длиннее 40 символов). Сервер проверяет только «5 разных строк ≤ 96» — разбирать не нужно.
- **Фразы:** только «Собери фразу» из пройденных занятий (app/friends_together/duel_phrases.ts, duel_phrase_source.ts);
  у друга фразы собираются по id из курса на его телефоне — сеть не нужна.
- **Ход без сети:** ход сначала ложится на телефон, потом уходит; повтор — тем же requestId (досылка при входе во «Друзей»).
  Поэтому оба вызова обязаны узнавать повтор по requestId и отвечать тем же, без второго хода и второго пуша.
- **Экран:** /friends_duel?mode=challenge|answer&friend&name&rank&plus&ids&duel&me (app/friends_duel.tsx); после пятой фразы
  сразу «Ход отправлен» со своими отметками, сеть поправляет на «Ход готов» (нет сети) или итог (ход друга).

## Уведомления дуэли (принято 1 · ЯДРО 22.10)
Строки «Сообщений» — тип 'friend_nudge' (другие типы не показываются), nav.kind 'friend_event', actorStableUid — другой игрок,
eventId уникальный. Старые duel_invite / duel_state — Арена (D83), скрыты.
- **duel_challenge** (другу): {duelId, expiresAtMs, phraseIds[5]} → маркер-щит в строке вызвавшего с остатком «23 ч»,
  шторка «Принять / Отказаться».
- **duel_result** (вызвавшему): {duelId, outcome — с его стороны, mine {correct, elapsedMs, results[5]},
  theirs {correct, elapsedMs, results[5]}, phraseIds[5]} → маркер-кубок; тап по нему или по строке «Сообщений» —
  экран итога из самой строки (0 чтений).
- **duel_declined** (вызвавшему): {duelId} — тихая строка, текст сервера.
- friendsDuelDecline {duelId} → {ok}; ошибки expired / not_invited / already_moved. «Принять» — без запроса: ход уходит
  в friendsDuelMove. Строка вызова гаснет, когда ход сыгран; вышел посреди хода — щит остаётся.
- Итог или отказ снимает «дуэль уже идёт» в журнале вызовов на телефоне. «Реванш» — новый вызов от нажавшего.
