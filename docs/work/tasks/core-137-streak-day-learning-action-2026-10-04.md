## Outcome
День серии = первое ЗАВЕРШЁННОЕ учебное действие дня (урок, тренировка карточек, «Мои ошибки») по локальной дате. Простое открытие приложения больше не засчитывает день. Единый локальный сигнал «день засчитан» (мгновенно, без сети) для серии/экрана; логи [STREAK-DAY].

## Scope
- app/streak_day_signal.ts (новый): список засчитывающих действий, правило мягкого перехода, состояние «засчитан ли сегодня» (синхронный peek + подписка), событие `streak_day_counted`.
- app/hall_of_fame_utils.ts: `touchStreakForToday` различает «засчитать» и «сверить»; новая `sweepStreakWithoutCounting` (сгоревшая серия → 0 без засчитывания дня); ветка LOST не дублирует потерю, если серия уже обнулена сверкой.
- app/events.ts: тип события `streak_day_counted`.
- tests/streak_day_rule_137.test.ts.

## Architecture
- Холодный старт / возврат в приложение (`cold_start`, `foreground`) и не-учебные действия (диалог, видео, Шпиль) — «сверка»: серия сгорела (пропущено ≥2 дней, журнал не лечит) → `streak_count = 0`, `last_active_date` не трогаем. Пропуск ровно одного дня ждёт действия (там решает Plus-заморозка, без изменений).
- `activity:lesson|cards|mistakes` — прежний `updateStreakOnActivity` (вся логика заморозки/журнала без изменений).
- Мягкий переход: ключ `streak_rule_v137_since` = день первого запуска с новым правилом; в этот день открытие засчитывается по старому правилу. Серии не сбрасываются.
- Журнал времени (MIN_ACTIVE_MS) — по решению остаётся внутренним «лечением» пропущенного вчера.

## Security and privacy
Новых данных не собирается: один локальный ключ AsyncStorage с датой. Политику менять не нужно.

## Technical debt
Отображение серии на Главной при сгоревшей серии до первой сверки берёт прежний `streak_count` (сверка идёт на холодном старте до первого кадра данных — см. Verification).

## Verification

## Rollback
