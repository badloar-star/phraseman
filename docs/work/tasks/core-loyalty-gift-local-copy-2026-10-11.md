## Outcome
1. Получатель 72-часового подарка лояльности видит доступ с первого кадра: срок, подтверждённый облаком, хранится
   локально (`loyalty_gift_verified_copy_v1`, вместе с id аккаунта). На старте срок в будущем → доступ сразу,
   облако сверяет фоном один раз; облако сказало «нет» → копия стирается, один пересчёт доступа.
2. Восстановление из облака уже читает `users/{uid}` — подарок засевается из этого же документа (кэш чтения подарка +
   локальная копия), второго чтения нет.
3. После этого облачная проверка подарка в `getVerifiedPremiumAccessStatus` получает потолок 3 с: держатель подарка
   с копией его не замечает; поздний ответ «подарок есть» сохраняет копию и один раз пересчитывает доступ.

## Scope

## Architecture
Копия хранит `{v, uid, untilMs, verifiedAtMs}`; читается только при совпадении uid с текущим аккаунтом и сроке
в будущем, не дальше 30 дней вперёд (защита от мусора). Ключ в списке данных аккаунта — стирается при выходе и смене.
Фоновая сверка — один раз на поколение аккаунта, поздний ответ после смены аккаунта игнорируется (поколение).
Ошибка сети копию не трогает: отзывает подарок только успешный ответ облака без активного срока.

## Security and privacy
Новых данных нет: срок подарка уже лежит в `users/{uid}.progress`. Подделка локальной копии на изменённом устройстве
даёт не больше, чем подделка премиум-ключей сейчас: серверные функции проверяют подарок сами (`isGiftAccessActive`).
