# Раздел «Рефералы» в админке не обновляется

Governance-ID: TG-3ED4E8961782
Дата: 2026-09-21

Запрос владельца: «В РАЗДЕЛЕ РЕФЕРАЛЫ НИЧЕГО НЕ ОБНОВЛЯЕТСЯ» (в админке).

## Диагноз (по коду и живой боевой)

Две причины, независимые друг от друга.

**1. Повторный вход в раздел молча выходит.**
`loadReferralsData` (`legacy.html:46650`) начинается с:

```js
if (!force && !append && window._referralsDashboardLoaded) return;
```

А открытие раздела зовёт её БЕЗ force (`legacy.html:24119`):

```js
void window.loadReferralsData(false, false);
```

Первый заход грузит данные и ставит `_referralsDashboardLoaded = true`.
Каждый следующий — мгновенный `return`: ни запроса, ни лога, ни сообщения.
Владелец видит вчерашние цифры и считает раздел сломанным.

**2. Обновить вручную нечем.**
Замер на боевой: в разделе четыре кнопки — «Приглашения», «Аналитика»,
«⬇ CSV», «⬇ Показать ещё 300». Кнопки «Обновить» нет.
`ref-load-more` только дозагружает следующую страницу (append), свежесть
уже загруженных строк она не восстанавливает.

Класс бага знакомый: механизм обновления есть (`force = true` работает,
его зовут из ремонта и отзыва привязки), но у владельца нет способа его
вызвать, а автоматический путь заблокирован флагом.

## Outcome

1. Вход в раздел обновляет данные, а не показывает вчерашний снимок.
2. В разделе есть явная кнопка «Обновить».
3. Видно, когда данные получены, — чтобы «свежесть» не приходилось угадывать.

## Scope

### Правится
- `admin/v2/legacy.html`:
  - открытие раздела зовёт загрузку с актуализацией (TTL, а не «один раз
    за сессию»);
  - кнопка «Обновить» рядом с «⬇ CSV»;
  - отметка времени последней загрузки.

### НЕ трогается
- `adminGetReferralDashboard` — серверная функция исправна, 78 тестов зелёные.
- Постраничная догрузка (`append`): работает как задумано.

## Architecture

Флаг «загружено один раз» заменяется отметкой времени + TTL: вход в раздел
перезагружает данные, если снимок старше порога, иначе показывает кэш.

TTL нужен, потому что дашборд читает Firestore пачкой по 100 строк:
перезагружать на каждый клик по вкладке — лишние чтения без пользы.
Порог 2 минуты: владелец переключается между разделами часто, но и ждать
свежих цифр дольше пары минут не должен.

Кнопка «Обновить» зовёт `loadReferralsData(true, false)` — принудительно,
мимо TTL. Это тот же путь, которым уже пользуются ремонт и отзыв привязки.

## Security and privacy

Только чтение уже доступных админу данных, тем же admin-only callable.
Новых данных, прав и получателей нет. Privacy policy правок не требует.

## Technical debt

Похожий флаг «загружено один раз» используется и в других разделах админки
(`_*Loaded`). Если владелец пожалуется на несвежесть ещё где-то — причина,
скорее всего, та же; общий хелпер стоит вынести при повторе.

## Verification

- Живой прогон: повторный вход в раздел вызывает запрос (а не молчит).
- Кнопка «Обновить» присутствует и вызывает загрузку с force.
- Отметка времени меняется после обновления.
- Лишних запросов при быстром переключении вкладок нет (TTL держит).

## Rollback

`git revert`. Правка локальна в клиенте админки; серверная часть и данные
не затронуты.
