## Outcome

`functions/src/coin_reconcile_v1.ts` `runCoinReconcileV1` читает `users/{stableUid}/level_spin_results` только у текущего stableUid; сверка одноразовая (поле записи → replay). При слиянии аккаунтов (`auth_merge.ts`) строки `level_spin_*` проигравшего не копируются и остаются под скрытым (`identityHidden`) id (подтверждено 8O). Значит человек не получает компенсацию монетами за Spin-призы второго аккаунта.

1. Сперва логи `[COIN-RECONCILE] sources=… loser_ids=… lanes=… ` без uid (первые 8 символов допустимы, как в текущем коде).
2. Для ЕЩЁ НЕ сверенных аккаунтов: сверка учитывает `level_spin_results` всех аккаунтов, слитых в этот stableUid. Источник связи — найти надёжный: поле в документе проигравшего (`mergedInto`/`identityMergedInto`/аналог, что ставит `auth_merge.ts` при скрытии) или запись outbox/`auth_links`; запрос через `where` по индексированному полю с лимитом, НЕ выкачивание коллекций. Если обратной связи (winner → losers) нет и нужен индекс — предложить минимальный путь (например, маркер `mergedFromStableIds` у победителя, который уже пишет/может писать слияние) и описать стоимость.
3. Без двойного начисления: дедуп по id операции/результата (как существующие `deliveredSpinStarLanes`/receipts), идемпотентность повтора; строки проигравшего не трогать (только чтение).
4. Для УЖЕ сверенных: только read-only скрипт подсчёта затронутых (агрегаты `count()`/минимальные чтения; без записи; прод — только с явной командой владельца/координатора), число — в INBOX.
5. Совместимость с клиентом 1.6.24: форма ответа `coinReconcileV1` не меняется (тест на точное равенство полей).
6. Учесть лимиты транзакции (чтения/размер) — при большом числе проигравших ограничить и залогировать.

## Scope

functions/src/coin_reconcile_v1.ts (+тест), при необходимости functions/src/auth_merge.ts (только добавление маркера связи — согласовать с 8M/8O тестами; без изменения правила победителя), новый read-only скрипт в scripts/. Out of scope: деплой (координатор), прод-запись, клиент.

## Architecture

Сверка = все Spin-результаты владельца, включая слитые в него аккаунты; источник связи — уже существующие данные слияния или минимальный новый маркер.

## Security and privacy

Только данные самого владельца (его слитые аккаунты); проверка, что проигравший действительно слит в этот stableUid (не произвольный чужой id). Логи без полного uid. App Check не включать.
