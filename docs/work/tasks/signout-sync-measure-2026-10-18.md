## Outcome

Одна строка [SIGNOUT-SYNC] на каждый шаг сохранения перед выходом: сколько мс, сколько записей и каких, ушла ли
сеть, сколько повторов. По этим фактам — второй шаг: ускорение (параллельно / только изменённое / батч) и надпись
«Сохраняем прогресс…» на кнопке вместо спиннера на весь экран. Гарантия «сначала сохранить, потом стереть» остаётся.

## Scope

- app/cloud_sync.ts forceSyncToCloud: опция `logPrefix` (по умолчанию [FORCE-SYNC], выход передаёт [SIGNOUT-SYNC]);
  засечки: личность (ensureAnonUser), ожидание отложенного восстановления, ожидание идущего синка, авторитетная
  личность (сеть), чтение локальных ключей (сколько), фильтр (сколько выброшено и почему), сколько из оставшихся
  совпадает с последним снимком (то есть «изменённых»), выгрузка карточек (мс, исход), запись документа (полей,
  ~байт, мс), запись снимка; итог с общим временем; каждый отказ — с шагом.
- Осколки: отдельный шаг уже меряется засечкой [ACC-SIGNOUT] shard_sync_done в auth_provider — app/shards_system.ts не трогаю.
- app/auth_provider.ts: передать logPrefix '[SIGNOUT-SYNC]' в forceSyncToCloud при выходе.
- Поведение не меняется (ни порядок, ни состав записей).

## Architecture

Засечки — локальная функция в forceSyncToCloud, одна строка JSON на шаг; без значений ключей и идентификаторов.
Повторов в forceSyncToCloud нет (одна попытка, потолок FORCE_SYNC_FIRESTORE_WRITE_MS) — это пишется явно (retries: 0).
