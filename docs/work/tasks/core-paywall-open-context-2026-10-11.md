## Outcome
1. Шаг 1 (логи, правило «сперва логи»): цепочка `[PAYWALL-OPEN]` от вызова `openPremiumPaywall` до решения диспетчера
   `/premium_modal` (wait / dismiss / show) со ВСЕМИ значениями, которые решили ветку: context, source, режим, живой доступ,
   доступ из кэша профиля, прошёл ли потолок ожидания, откуда взят итоговый доступ. Немой выход «dismiss по Plus» (окно
   закрылось само у человека с доступом) теперь пишет причину.
2. Найденное при чтении кода (до логов, факты из исходника):
   - `resolvePremiumModalEntry` молча возвращает `dismiss`, если доступ Plus есть: у владельца/тестера с Plus окно
     «не открывается» без единой строки в журнале;
   - `PaywallPlusScreen` получает `entry.context`, но шапка (`PaywallPlusHeader`) его не использует — контекст уходит
     только в аналитику. Тексты под каждый контекст уже есть в 9 языках (`app/paywall_copy.ts`: `PAYWALL_COPY`,
     `PAYWALL_PLANNED_COPY`, `CONTEXT_BENEFITS`) — их показывали старые пейволы A–G, удалённые 30.09.
3. Шаг 2 (после логов и макета Дизайна): чистая функция контракта «контекст → заголовок / подзаголовок / первая выгода»
   на существующих текстах + сторож «каждая точка входа передаёт context из белого списка». Подключение к шапке —
   только по макету (гейт «приложение = макет»).

## Scope

## Architecture
Логи — `console.log/warn` с префиксом `[PAYWALL-OPEN]` (как соседний `[PAYWALL]` в диспетчере: debug-logger тянет лишние
модули в транзитный экран). Решение диспетчера логируется один раз на смену решения (ref), не на каждый рендер.
Контракт контекста — чистая функция поверх уже написанных текстов, без новых строк, пока Дизайн не утвердит макет.
