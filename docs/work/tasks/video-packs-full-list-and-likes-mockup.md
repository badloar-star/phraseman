## Outcome

Владелец выбрал вариант Б («Список») и уточнил четыре вещи. Нужен второй макет,
показывающий:

1. **Вход не через таббар**, а из экрана «Карточки» — витрина вверху над
   сохранёнными, куда наборы из видео попадают наравне с наборами сообщества,

3. **Тренировка без добавления себе** — набор открывается и запускается прямо

5. У набора из видео (в отличие от набора сообщества) есть **кнопка видео /
   превью** прямо в строке — ролик включается оттуда.

Успех = владелец выбирает вариант полного списка и подтверждает поведение лайка.

## Architecture

**Исправление прошлого хода:** в первом макете я нарисовал таббар раздела
«Карточки» с вкладками. Владелец поправил: такого таббара нет. Прочитано заново:

- `app/flashcards_collection.tsx` — корень раздела, всегда открывается на
  «Сохранённых» (строка ~530, `FLASHCARDS_HUB_CATEGORY_ORDER = ['saved']`);
- `app/flashcards/FlashcardsCategoryBar.tsx` — горизонтальная полоса категорий
  (иконка 33px + подпись 10px), категории из `app/flashcards/constants.ts`;
- `app/flashcards/SavedTopCommunityPacks.tsx` — **витрина «лучшие наборы
  сообщества» НАД списком сохранённых**. До 10 плиток, горизонтальный скролл,
  `COLS = 3` задаёт размер плитки. Тап открывает набор в режиме просмотра.
  Ноль дополнительных чтений Firestore: берёт уже загруженный `marketPackCatalog`.

Готовая механика, которую НЕЛЬЗЯ дублировать (иначе появится второй счётчик):

- `app/community_packs/packSocial.ts` — `toggleLikeOptimistic`,
  `mergeServerCounts` (с защитой от гонок — комментарий про баг «лайк не
  ставится»), `comparePacksBySocial` (лайки ↓ → добавления ↓ → свежесть),
  `topLikedPackIds`, `PACK_TOP_MIN_LIKES = 3`;
- `app/community_packs/communityCatalogFilter.ts` — сортировки
  `'popular' | 'new'`, поиск по названию;
- `?preview=1` в `flashcards_collection.tsx` (строки 223–230, 867) — **набор
  уже умеет открываться ДО добавления себе**. Это ровно то, что владелец просит
  для «тренировать без добавления»; изобретать новое не нужно.

Намеченная граница (для будущей реализации, здесь только зафиксирована):
наборы из видео — те же документы каталога наборов плюс поля «канал» и
«videoId», поэтому они естественно участвуют в той же сортировке по лайкам и
могут попадать в витрину «лучшее» наравне с наборами сообщества.

**Конфликт, вынесенный владельцу и РЕШЁННЫЙ им:** правило
`CommunityPackSocialBar.tsx` — лайк только после добавления себе. Владелец
выбрал «оставить как в сообществе». Значит в макете: до добавления сердце
серое и неактивное, после «+ Себе» — активное. Тренировка без добавления
при этом разрешена: это два независимых действия.

Архитектурное изменение в этом ходу: нет — создаётся статический HTML вне
дерева приложения.

## Security and privacy

Не применяется:
- статический HTML без скриптов, сети и полей ввода;
- имена каналов, авторов и названия наборов вымышленные; uid не показывается —
  что согласуется с правилом «рядом с uid всегда имя», поскольку uid нет вовсе;
- обложки не грузятся с YouTube — CSS-градиенты, обращений к стороннему домену нет;
- новых данных не собирается → политику приватности трогать не нужно.

На будущее при реализации: превью пойдёт с `i.ytimg.com` (IP пользователя
уходит к Google) — тогда свериться с политикой. Лайк пишет `userId` в
подколлекцию `pack_likes` — механизм уже существует и уже покрыт правилами.

## Technical debt

- **Pay now**: макет строится на РЕАЛЬНОЙ структуре экрана (витрина над
  сохранёнными, полоса категорий), а не на выдуманном таббаре — ошибка прошлого
  хода исправлена сразу, а не записана в долг.
- **Pay now**: в макете нет обводок контейнеров, нет мелких подписей-расшифровок
  под названиями, нет ужатия шрифта — проверено grep'ом, а не на глаз.
- **Contain**: макет переиспользует уже существующие правила сортировки
  (лайки → добавления → свежесть) и порог топа (3 лайка). Граница: при
  реализации запрещено заводить вторую функцию сортировки — только
  `comparePacksBySocial`. Exit condition: реализация ссылается на этот модуль.
- **Accept temporarily**: HTML живёт вне репозитория (scratchpad + `.codex-tmp/`,
  обе в .gitignore). Владелец: эта сессия. Пересмотр: после выбора варианта.
  Потолок влияния: нулевой — на бандл, типы и тесты не влияет.
