# Сцена 2.0 — утверждённый вид (слово владельца 29.10)

> Вердикт владельца дословно (координатор, 29.10 ~07:40): **«Тёмная тема везде должна стать глубокое небо!!! а светлая — тон темы ярче и глубже!
> Это всех экранов касается».**
>
> Утверждено: **тёмное оформление — освещение «Глубокое небо»**, **светлое оформление — стратегия цвета «А — тон темы ярче и глубже»**,
> на всех экранах со «Сценой» (Главная, Диалоги, Пик, Сезон). Стили сцен (суми-э, маркер, аврора, витраж, коллаж), варианты вечера и
> карточек владелец **не выбирал** — остаются как сейчас.

Это эталон для переноса в код сессией Темы «пиксель в пиксель». Источник истины — чистая функция
[scene-approved.js](scene-approved.js): `SceneApproved.approved(tokens, appearance, screen, W, H, { premium })`. Макет
[scene-palettes.html](scene-palettes.html) (раздел «Утверждено владельцем 29.10») рисует ровно её числа: headless-проверка
`window.__dt.checkApproved()` (журнал `[DT-APPROVED]`) даёт 0 расхождений по пикселям в тёмном и 0 по числам в светлом для каждой темы.
Эталонные кадры — `assets/approved/scene/` (ниже).

## 1. Вход и выход функции

- **Вход:** токены темы уровня «Максимум» (`liquidGlassTokens(id, { level: 'max', appearance })`) — используются только `accent` и
  `opaqueCard` (светлое: ещё `text` и `cta` для надписей и кнопок на кадре, см. §5); `appearance` — `dark` | `light`; `screen` —
  `home` | `dialogs` | `peak` | `season`; `W`, `H` — размер области сцены в px (на кадре 1080 × 2400 при 2,625 px/dp: Главная и
  Диалоги 1082, Пик 1950, Сезон 1029); `opts.premium` — true для шести премиум-тем.
- **Выход:** все цвета (rgb и hex), слои по порядку, позиции и радиусы в долях W/H, альфы, звёзды (сид + готовый список), солнце, дымка,
  виньетка, параметры стража контраста. Область сцены, скругление 32 dp, герой, надписи, стекло — **как сейчас**, меняется только фон.
- **Цвет:** OKLCH по Björn Ottosson (те же матрицы, что `oklchToHex` приложения); выход из sRGB-охвата — уменьшаем насыщенность шагом .004
  при тех же оттенке и светлоте. Контраст — WCAG (`whiteOn(c) = 1.05 / (Y + .05)`). Шум — xorshift32 с сидом (одни и те же звёзды на любой
  платформе).

## 2. Палитра «А» из токенов (общая для обоих оформлений) — `paletteA(t, appearance)`

| Шаг | Формула |
| --- | --- |
| Оттенок и насыщенность | `[L, C, H] = oklch(accent)`; `S = round(H)` |
| Насыщенность сцены | `Ct = clamp(C × 1.6, .07, .17)`; `Cb = Ct × .7` |
| Верх | `top = ok(Lt, Ct, H)`, `Lt = .50` (светлое .52); пока `whiteOn(top) < 4.6` и `Lt > .20` — `Lt −= .01` |
| Низ | `bot = ok(Lb, Cb, H − 8°)`, `Lb = .30` (светлое .28); **в тёмном** пока `contrast(bot, opaqueCard) < 1.34` и `Lb < .50` — `Lb += .01` |
| Света | `Cl = max(.06, Ct × .9)`; `lightC = ok(.80, Cl, H)`; `light2C = ok(.62, Cl, H + 18°)`; альфы `a1 = .85`, `a2 = .55` |

## 3. Тёмное оформление — «Глубокое небо» — `darkSky(t, screen, W, H)`

Все цвета — от `S = round(H)` и **сырой** насыщенности акцента `C` (не Ct). Слои по порядку (каждый поверх предыдущего, обычное
альфа-смешивание):

| # | Слой | Формула |
| --- | --- | --- |
| 1 | Вертикальный градиент (0 → H) | 0: зенит `ok(.40, min(.17, C+.03), S)` · .42: середина `ok(.47, min(.15, C+.01), S+4°)` · .66 и .74: горизонт `ok(.60, min(.13, C+.02), S+12°)` · .80: земля `ok(.27, min(.10, C), S−8°)` · 1: низ `ok(.22, min(.08, C), S−10°)` |
| 2 | Солнце | эллиптический радиальный свет: центр (.18 W, .02 H), радиусы .62 W × .46 H, цвет `lightC`, альфа .72 в центре → 0 на краю (линейно) |
| 3 | Дымка горизонта | горизонтальная полоса .62 H … .76 H, цвет `ok(.80, .08, S)`, альфа 0 → .34 (середина) → 0 |
| 4 | Звёзды | 70 штук, белые; `r = rng(3)`; на каждую по порядку: `x = r()·W`, `y = r()·H·.4`, радиус `.8 + r()·1.8` px, альфа `.18 + r()·.5`; первые пять: (0.0002, 0.0188, r 2.07, a 0.402), (0.4269, 0.0449, r 2.25, a 0.325), (0.2461, 0.3990, r 2.31, a 0.505), (0.6621, 0.2888, r 0.84, a 0.313), (0.8519, 0.2336, r 0.87, a 0.585) |
| 5 | Виньетка | радиальный чёрный от центра, эллипс .78 W × .78 H: 0 на 45 % радиуса → .22 на краю |
| 6 | Страж | по нарисованным пикселям: средняя линейная яркость строки (x 40 … W−40 шагом 6); худшая строка в зоне текста (y .5 H … .96 H) должна давать белому ≥ 4.6, верхние строки 4…80 px — ≥ 3.5; иначе низ темнеет чёрным: градиент 0 на .42 H → `a` на .62 H и далее постоянно до низа; верх — `a` на 0 → 0 на 110 px; `a = min(.7, 1 − (target/Y)^(1/2.2) + .04)`, `target = 1.05/ratio − .05` |

Образец отрисовки на 2D-канве — `SceneApproved.drawSky(ctx, spec, W, H)` (тот же код, что в макете). В приложении: слои 1–3 и 5 —
градиенты (Skia/expo-linear-gradient + радиальные), 4 — 70 кружков по готовому списку `spec.stars.list` (доли W/H), 6 — на практике
страж срабатывает только снизу (у всех тем `aBottom ≈ .20`, `aTop = 0`) — значение в `manifest.json` у каждого кадра (`check.guard`).

## 5а. Герой сцены Главной — крупно, справа, по центру (владелец 29.10 ~10:40)

Слово владельца: «иконки книжка и другие почему-то в самом верху маленькие, вкраю, а должны быть большие и не под самый верх, а посредине
справа». Спецификация (`SceneApproved.HERO_HOME`, `heroHome(W, H, dp)`):

| Что | Значение |
| --- | --- |
| Размер картинки героя (home_scene_continue, streak_risk, …) | **144 dp** (сейчас 84 dp); на кадре 1080 px — 378 px |
| Горизонталь | справа, отступ **20 dp** от края: x = W − 378 − 52 = 650 px |
| Вертикаль | по центру области сцены: y = (sceneH − 378) / 2 (сцена 1082 → 352 px) |
| Непрозрачность | .96, как сейчас |
| Текст под героя не лезет | блок текста (подпись, заголовок, строка под ним) шириной ≤ **53 %** ширины экрана (W − 2·20 dp − 144 dp − 24 dp зазора); заголовок — до двух строк, как в Диалогах |
| Днём | «Урок 1» + заголовок в две строки — блок начинается выше (на кадре с 560 px), «0 из 50» и «Продолжить» на месте |
| Вечером | «Серия 5 дней» + заголовок в две строки + «Одно занятие — и серия спасена» в две строки — блок с 556 px, «Продолжить» на месте |

На Диалогах герой уже крупный и справа — не меняется. Эталон вида — `scene-final.html` (чистый макет «только утверждённое»).

## 5б. Вечер — «тёплый янтарь» по умолчанию

Вечерний отсвет на «Глубоком небе» (`warmEdge`): режим по умолчанию `band` — тёплая полоса 40…80°, точка в ней — от оттенка темы
(40 + (H mod 60) / 60 × 40), OKLCH L .78 C .14; эллипс в (92 % W, 102 % H) радиусами 55 % × 42 %, альфа .5 → 0 на 85 % радиуса, слой после
дымки, перед звёздами. Другие трактовки (`warmer`, `theme`) в функции остались для сравнения, в макете владельцу не показываются.

## 6. Эталонные кадры `assets/approved/scene/`

Каждый кадр — область сцены (0 … sceneH) **реального кадра Сверки**, у которого по пикселям перекрашен только фон по утверждённой формуле
(герой, надписи, стекло — как сняты). Имя: `{screen}_{theme}_{ap}.png`, 1080 × sceneH. Опись — `manifest.json` (источник, sceneH,
размер, результат сверки с функцией, пометки). Получено: 124 кадров (тёмное 62, светлое 62);
не снято Сверкой: 108 (Пик и Сезон у 25 тем; тема «Саванна» (olive) не снята целиком) — для них эталон только по формуле.
Расхождений макета с функцией: 0. Кадров, где перекраска не совпала с моделью сцены (пометка `unfit`): 2 — dialogs_sage_light.png, dialogs_eucalyptus_light.png.

**Как сверять (гейт):** снимок экрана приложения (та же тема, оформление, состояние, 1080 × 2400) → область сцены по той же высоте →
сравнение с эталоном. Фон (вне героя, надписей и стекла) должен совпадать в пределах ±3/255 на канал; у героя и краёв надписей возможны
артефакты перекраски (±8) — их вес в метрике снизить или исключить по маске. Точные цвета для любой точки сцены даёт
`SceneApproved.painter` (светлое) и `drawSky` (тёмное) — при споре прав код функции, не png.

## 7. Как проверить перенос

1. `node docs/design/v2-app/scene-palettes.make.cjs` — пересобрать макет (scene-approved.js подключён сборщиком).
2. Открыть `scene-palettes.html` по http, выбрать тему и оформление, раздел «Утверждено владельцем 29.10»; в консоли
   `window.__dt.checkApproved()` → `maxDiff 0` по каждому экрану.
3. В приложении: сцена на тех же токенах → снимок → сравнение с `assets/approved/scene/*.png` (§6).
