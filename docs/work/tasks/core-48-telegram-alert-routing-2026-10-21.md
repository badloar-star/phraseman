## Outcome

Владельцу в Telegram приходит только важное, коротко, одним сообщением:
- **Сразу.** Покупка Plus, старт пробного, критичная ошибка приложения, сбой приёма оплаты, безопасность ИИ, возврат денег, всплеск ошибок входа, обращения и жалобы (поддержка, сайт, жалоба на пользователя, на контент, на объяснение, на набор).
- **Повторы критичной ошибки** одного вида за час не шлются новыми сообщениями. Первое сообщение правится на «×N за час».
- **Раз в неделю,** в понедельник в 10:00 по Киеву, приходит одна сводка: всё остальное, обычные ошибки, версии 1.x и события старше часа. Ежедневный дайджест в 20:00 убран.
- **Не слать.** Тестовые покупки (SANDBOX / TEST) и ники из списка «тестовые аккаунты» в настройках оповещений.

## Scope

- Новый `functions/src/admin_alert_routing.ts`: чистое решение «сразу / сводка / не слать» и ключ группы ошибки.
- Новый `functions/src/admin_alert_compact.ts`: сообщение в 2–3 строки + ссылка в админку, всегда одно.
- `functions/src/admin_alert_dispatcher.ts`: маршрут после проверки настроек, короткий формат (версия 5), группировка критичных ошибок с правкой сообщения, журнал `[ADMIN-ALERT-ROUTE]`.
- `functions/src/admin_alert_digests.ts`, `functions/src/admin_alert_daily_counts.ts`, `functions/src/admin_alert_templates.ts`: окно сводки — неделя (понедельник 10:00, Europe/Kyiv). Тип события `ownerDailyDigest` и имя функции крона не меняются: переименование означало бы удаление и создание функции.
- Тесты к каждому файлу.
- Старые прямые отправители (email_delivery_watchdog, auth_recovery, telegram_support, Джарвис) — следующим шагом, не здесь.

## Architecture

Все события и дальше пишутся в `admin_alert_events`, очередь и правила не меняются. Решение принимается в `dispatchAdminAlertEvent` сразу после проверки настроек:
- «Не слать» и «в сводку» помечают событие как `suppressed` с причиной (`drop:…`, `weekly:…`), без Telegram.
- Сводка за неделю считает события по `occurredAtMs` из той же коллекции, поэтому дополнительных записей нет.
- Группа критичной ошибки — документ `admin_alert_groups/{вид}:{час}` со счётчиком и `telegramMessageId`. Повтор увеличивает счётчик и правит первое сообщение (`editMessageText`).

## Security and privacy

- Новых данных не собирается.
- Короткий формат печатает только поля, которые уже разрешены санитайзером: ник из серверного поиска, платформу, версию, тип ошибки. Стек и тексты пользователей режутся до коротких строк.
- Для ошибок uid и ник по-прежнему не печатаются.
- Политика конфиденциальности не затрагивается.

## Technical debt

- Имя `adminAlertDailyDigestsCron` и тип `ownerDailyDigest` теперь означают недельную сводку, это отмечено комментарием.
- Список тестовых ников задаётся полем `admin_config/alerts.testNicknames`. Интерфейса в админке пока нет.
