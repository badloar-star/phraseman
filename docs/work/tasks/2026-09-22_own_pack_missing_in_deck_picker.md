## Outcome

Набор, созданный человеком в редакторе карточек («Сохранить»), появляется в шторке
выбора наборов при старте тренировки — во всех режимах (Тренировка, Говорить, Блиц)
и на экране `flashcards_training_setup`.

Кто выигрывает: автор собственного набора. Жалоба (21.09.2026, Premium, 32 дня в
приложении, стрик 15): «В «Карточках» я создала себе набор, но не вижу его в выборе
наборов, когда выхожу в «Начать тренировку» и выбираю способ тренировки».

Мера успеха: после сохранения набора в редакторе он присутствует в списке наборов
с верным названием и счётчиком карточек; Блиц без явного выбора набора берёт его
карточки в пул; опубликованный набор показан ОДНОЙ строкой, а не двумя.

## Architecture

Текущая граница. Наборы человека живут в ТРЁХ независимых хранилищах:
- `flashcards_owned_packs` — купленные в маркете (`loadAccessiblePackIds`);
- `community_owned_pack_ids_v1` — добавленные/купленные чужие (`loadCommunityOwnedPackIds`);
- `community_local_author_packs_v1` — СВОИ, созданные в редакторе (`loadLocalAuthorPacks`).

`deck_options.ts:347` собирает `packIds` только из первых двух. Третий источник
загружается рядом (строка 313), но используется лишь как справочник названий и
обложек — в обход списка. Загрузчик карточек своих наборов при этом существует и
работает (`deck_sources.ts:202` умеет `local_pack_*`): механизм не сломан, его
просто не позвали.

Намеченная граница. `packIds` включает все три источника. Порядок сохраняется:
купленные → добавленные → свои (свои последними, чтобы не переставить привычный
список у тех, у кого своих наборов нет).

Инварианты, которые правка обязана удержать:
1. **Одна строка на набор.** Локальная копия НЕ удаляется после публикации, она
   получает поле `cloudPackId` (`publishLocalPack.ts:189`). Дедупликация — по
   множеству `cloudPackId` локальных записей, как в `flashcards_my_packs.tsx:203`
   (`localCloudIds`). Сравнение по точному связывающему id, НЕ по названию:
   `mergeLocalAuthorPacks` сравнивает `автор|язык|название` и даёт ложные
   срабатывания при совпадении названий и ложные пропуски при переименовании.
   Побеждает локальная копия — в ней свежие правки автора, ещё не прошедшие модерацию.
2. **Изоляция языков.** `loadLocalAuthorPacks` читает ОБЕ цели (en + fr) и склеивает
   их, проставляя `pack.studyTarget`. Без фильтра по текущей цели во французском
   режиме всплывут английские наборы — этот класс бага уже чинили 05.09
   (см. комментарий `deck_options.ts:240`). Сторож
   `gustav_flashcards_target_isolation.test.ts` требует протаскивания `studyTarget`.
3. **Скорость первого кадра.** Ничего не добавляется на критический путь: локальные
   наборы уже грузятся в том же `Promise.all` (строка 313). Снимки
   (`_warmDeckOptions`, `fc_deck_options_snapshot_v1`) продолжают работать как есть;
   контракт `deck_options_instant_open_contract.test.ts` не нарушается.

Решение: архитектура не меняется, устраняется пропущенный источник. Единый помощник
на 4 места — отдельная задача (см. Technical debt).

## Security and privacy

Не применяется. Правка читает только локальное хранилище устройства
(AsyncStorage), уже доступное этому же экрану. Новых полей, новых сторонних
сервисов, новых разрешений, экспорта или удаления данных нет. Сетевых вызовов не
добавляется — наоборот, свои наборы читаются локально, без Firestore. Персональные
данные не покидают устройство; детских данных не касается. Privacy policy правки
не требует.

## Technical debt

- **Pay now.** `deck_options.ts` дублирует строковый префикс `local_pack_`
  (`deck_sources.ts:188`) вместо импорта готового `isLocalAuthorPackId` — переходим
  на общий помощник в затронутых местах.
- **Pay now.** `loadAllFcDeckRefs` и `countAvailableFcCards` чинятся вместе со
  списком: один корень, три проявления. Чинить по одному — гарантированный возврат.
- **Contain.** Четыре места (`deck_options`, `useCollectionData`, `flashcards_packs`,
  `flashcards_my_packs`) собирают «все наборы» каждое своим кодом; четвёртое отстало
  и дало эту жалобу. Граница: сторож
  `tests/fc_deck_options_local_packs_contract.test.ts` ловит возврат дефекта в
  `deck_options.ts`. Exit condition: вынести единый `loadAllAccessiblePackIds`
  (аккаунт + цель + дедуп по `cloudPackId`) и перевести на него все четыре места.
  Владелец: следующая сессия по карточкам. Потолок влияния до выхода: остальные три
  места уже работают верно, риск ограничен новым пятым местом.
- **Accept temporarily.** `countAvailableFcCards` — мёртвый код: продакшен-вызывающих
  нет (подтверждено полным grep), её комментарий про таббар устарел, реальный гейт
  Блица берёт число из `summarizeDeckSelection`
  (`flashcards_training_setup.tsx:313`). Чиним дефект внутри неё, но не удаляем и не
  подключаем. Владелец: следующая сессия по карточкам. Дата пересмотра: 2026-10-22.
  Потолок влияния: нулевой, значение никуда не подаётся.
- **Accept temporarily.** `useCollectionData.ts:556` подмешивает локальные наборы
  БЕЗ дедупликации по `cloudPackId` — если человек добавит себе собственный
  опубликованный набор, в коллекции он может задвоиться. Вне текущего объёма.
  Владелец: следующая сессия по карточкам. Дата пересмотра: 2026-10-22.
  Потолок влияния: дубль строки в коллекции, данные не теряются.

Ручной прогон на устройстве (владелец):
1. «Карточки» → создать набор из 3–4 карточек → «Сохранить».
2. «Начать тренировку» → выбрать способ → набор ВИДЕН в списке, название верное,
   счётчик совпадает с числом карточек.
3. Отметить его, начать сессию — идут карточки именно этого набора.
4. Блиц без явного выбора набора — стартует, карточки своего набора в пуле.
5. Опубликовать набор → снова открыть список → набор показан ОДНОЙ строкой.
6. Переключить язык изучения на французский → английский набор в списке НЕ появился.

Наблюдаемость: трассировка `[FC-DECKS]` уже есть и остаётся навсегда. Добавляется
строка о локальных наборах (сколько найдено, сколько скрыто как облачные близнецы)
— без неё следующий такой пропуск снова будет невидим. Evidence: вывод
`.expo/metro-console.log` по grep `[FC-DECKS]` прикладывается к задаче.

## Rollback

Правка аддитивная и обратимая: откат — вернуть сборку `packIds` к
`[...ownedIds, ...communityIds]` и снять новый сторож. Пользовательские данные не
мигрируются и не переписываются: свои наборы лежат в
`community_local_author_packs_v1` как лежали, задача лишь читает их на один экран
больше. Выданные права не затрагиваются — платные наборы, покупки и подарки идут
прежними путями (`loadAccessiblePackIds`, `loadCommunityOwnedPackIds`).

Единственный побочный артефакт — durable-снимок `fc_deck_options_snapshot_v1`: после
отката он какое-то время может держать свой набор в списке. Самоисцеляется при
следующей сборке списка (окно 3 секунды, `DECK_OPTIONS_REBUILD_MIN_GAP_MS`), ручной
чистки не требует.
