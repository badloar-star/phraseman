# Общие уведомления: модал при входе

## Цель

Каждое новое активное общее уведомление, созданное командой через `app_messages` для Inbox, один раз показывается пользователю при входе в приложение в анимированном стиле существующего `UpdateModal`. После подтверждения уведомление считается прочитанным, но остаётся в центре уведомлений до обычного dismiss пользователя.

## Границы

- В область входят общие `app_messages` с `deliverySurface: 'inbox'` и типами `message`/`poll`.
- Сообщения для плашек настроек и персональные сообщения не меняют текущую семантику.
- Старые сообщения без нового признака не должны внезапно открывать модал после релиза.
- Показ ограничен текущей аудиторией, версией приложения, активностью и сроком жизни сообщения.

## Архитектура и поток данных

1. Cloud Function при создании общего Inbox-сообщения записывает `showOnNextLoginModal: true`. Для draft этот признак сохраняется, чтобы первая последующая публикация тоже считалась отправкой. Для settings-сообщений признак false.
2. Клиент нормализует этот признак и читает отдельное состояние `appMessageModalAcknowledgedAtMs` в `users/{uid}/app_message_states/{messageId}`.
3. При старте root layout получает обычный снапшот `app_messages`, отбирает первое ещё не подтверждённое модальное уведомление с учётом аудитории и показывает новую обёртку над `UpdateModal`.
4. Подтверждение модала локально записывается в account-scoped outbox, сразу делает модал закрытым после перезапуска и best-effort синхронизируется с Firestore. Одновременно записывается `readAtMs`, чтобы колокольчик показывал прочитанное состояние.
5. Действие dismiss Inbox остаётся отдельным: оно продолжает писать только visibility-состояние и удалять строку из ленты. Подтверждение модала не вызывает `dismissAppMessage`.
6. Если опубликовано несколько новых сообщений, root показывает их по одному в порядке существующей сортировки приоритет/дата.

## UI

- Переиспользуется `UpdateModal` с его полноэкранным затемнением, фоном, entrance-анимацией и одной primary-кнопкой.
- Для уведомления primary-кнопка называется локализованно «Понятно» и подтверждает прочтение.
- В модале отображаются локализованные title/body самого сообщения.
- Back/наружной тап не должны обходить подтверждение; строка в колокольчике после подтверждения остаётся доступной.
- Повторный показ после подтверждения, перезапуска и смены устройства с тем же аккаунтом запрещён после синхронизации состояния.

## Надёжность и совместимость

- Существующие `personalModalAcknowledgedAtMs` и персональный поток сохраняются без изменения поведения.
- Offline-подтверждение не теряется и не привязывается к следующему аккаунту.
- Старые документы без `showOnNextLoginModal` получают false.
- Ошибка записи Firestore не блокирует вход: локальный outbox остаётся источником pending-операции.

## Проверки

- Нормализатор Cloud Function устанавливает признак только для Inbox.
- Селектор выбирает только активные, допустимые по аудитории/версии и неподтверждённые сообщения.
- Подтверждение модала не удаляет сообщение из snapshot и не меняет dismiss-state.
- Account-scoped outbox переживает offline/restart и не смешивает аккаунты.
- Contract-тест проверяет использование `UpdateModal`, отдельный overlay и отсутствие вызова dismiss.
