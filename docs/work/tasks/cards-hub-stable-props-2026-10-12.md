# Хаб Карточек: стабильные пропсы CardsHubV2 (аудит скорости R1, пункт C2)

## Outcome
`CardsHubV2` обёрнут в `memo`, но экран `FlashcardsHubScreen` отдавал ему свежие `tiles`, `labels`, `fresh` и колбэки `onBack/onTrain` на каждый рендер корня, поэтому `memo` не срабатывал. После правки пропсы стабильны: плитки и подписи пересчитываются только при смене данных или языка, обработчики не меняют ссылку. Хаб не перерисовывается на коммит корня без изменения данных (квота/фокус/сеть/окно). Вид и поведение не меняются.

## Scope
Только `app/flashcards/FlashcardsHubScreen.tsx` (сборка пропсов хаба) и сторож `tests/cards_hub_stable_props_contract.test.ts`. `CardsHubV2.tsx`, логика квоты, раннего тапа, окна режимов и пейвола не трогаются.

## Architecture
`tiles` и `fresh` — `useMemo` по данным (`copy`, счётчики, форматтер чисел, язык, `router`, dev-флаг «hub_loading»). `labels` — `useMemo` по трём строкам. `onBack` — `useCallback([router])`. `onTrain` — стабильная обёртка поверх «последней» `onTrainPress` через ref (`onTrainPressRef`): сама `onTrainPress` читает свежую квоту/флаги, ссылка на пропс при этом не меняется. Тап-обработчики внутри плиток остаются замыканиями над `router` (он стабилен).

## Security and privacy
Только вычисление пропсов. Данные, права, сеть и покупка не затрагиваются; политика не меняется.

## Technical debt
Нет теста реального числа рендеров (нужен renderer для RN); вместо него сторож по исходнику плюс замер `[PERF-R1]` через Сверку. `windowHeight` (C4) остаётся в корне, низкий приоритет.

## Verification
Точечный тест-сторож (`npm run test:one`, при ≥3 ГБ и слоте светофора, `--maxWorkers=1`), срез типов по двум файлам, существующие контракты хаба (`perf_r1_probe_contract`, `design_cards_defects_contract`).

## Rollback
git revert коммита; вид и логика хаба не менялись, возвращается прежняя (неэффективная) сборка пропсов.
