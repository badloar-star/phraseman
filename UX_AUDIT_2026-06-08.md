# UX/UI Аудит приложения Phraseman

**Дата:** 2026-06-08
**Тип:** Финальный продуктовый аудит UX/UI пробелов
**Платформа:** React Native / Expo Router (iOS + Android)

---

## Краткое резюме

Проверено **~30 экранов** в кластерах: флешкарты и пейволл, тренажёры (фразы/слова/смарт), персональный план, арена, уроки, настройки, веб-вью, видео Lingman, главная и табы. Всего **53 находки**, из них верифицировано adversarial-проверкой: **17 high-confidence** и **2 critical**, остальные — dev-уровня (low) под ручную проверку.

**Главные классы проблем:**

1. **Доступность (a11y) — системная, массовая.** Корневые обёртки `TapScale`/`PressableScale` не пробрасывают accessibility-пропсы, из-за чего десятки icon-кнопок (40+ экранов) невозможно озвучить. Кастомный `CustomSwitch` без роли `switch`. Это блокирует VoiceOver/TalkBack в основных флоу.
2. **Обработка ошибок загрузки — риск «вечного загрузчика».** Три тренажёра и лидерборд арены грузят данные без try/catch: при сбое сети экран навсегда застревает на пустом загрузчике или маскирует ошибку под пустое состояние.
3. **Локализация — заявлено 8 языков, реально работают 3.** Системный фолбэк на русский + целые экраны (персональный план, premium_modal_v2) захардкожены кириллицей.
4. **Состояния загрузки — невидимый прогресс.** Пустые `<Text/>`, многоточие «...», мёртвый код спиннеров в пейволле.
5. **Мёртвые роуты и дубли экранов.** 5 сирот-экранов и враппер-дублей, недостижимых из продакшн-флоу.
6. **Незавершённые фичи в проде.** SRS-счётчик dev-only (всегда 0), «скоро появится»-заглушки, утечка внутреннего жаргона.

## Находки по категориям

### Пустые состояния (empty_state)

- **`app/flashcards/FlashcardsCategoryHub.tsx` — вкладка «Витрина» без пустого состояния** (medium, verified high). `showcaseTabPacks` (стр. 451-454) фильтрует купленные наборы, рендер (стр. 956-967) вызывает только `renderPackTiles` без проверки `length === 0`. Если все наборы куплены/каталог не загрузился — пустой экран. У «Сообщества» (стр. 1025-1039) пустое состояние есть — асимметрия. → Добавить EmptyState («Все наборы уже у вас» / «Витрина временно пуста»).
- **`components/ui/EmptyState.tsx` — переиспользуемый компонент мёртвый** (medium). Grep по проекту: 0 импортов. Экраны рисуют пустые состояния инлайн, каждый по-своему (`lingman_videos.tsx:319`, `arena_leaderboard.tsx:491`, `flashcards_collection.tsx:1450`). → Развести единый `EmptyState` по экранам со списками ИЛИ удалить.
- **`app/flashcards/FlashcardsCategoryHub.tsx` — вкладка «Мои» без пустого состояния** (low). Нет приглашающего текста/CTA на «Витрину», когда нет купленных наборов.
- **`app/beta_testers.tsx` — список через `.map` без empty-ветки** (low). Данные статические, риск низкий.

### Обработка ошибок (error_handling)

- **`app/trainer_words_session.tsx` — нет обработки ошибок загрузки колоды** (HIGH, verified). `useEffect` (стр. 249-285): `consumeTrainerSessionEntry`, `getDueItems`, `Promise.all` без try/catch. При reject — `loading` навсегда true, пустой загрузчик (стр. 332-340). ErrorBoundary не ловит async-rejection в useEffect. → try/catch + UI ошибки с retry.
- **`app/trainer_smart_session.tsx` — `loadSession` без обработки ошибок** (HIGH, verified). `setLoading(false)` только последней строкой (541) после всех await; при reject — застревание на «...». → try/catch + `finally`.
- **`app/arena_leaderboard.tsx` — сбой маскируется под пустое состояние** (HIGH, verified). `reloadBoard` (стр. 192-202) без catch, только `.finally`. При reject `rows=[]` → показ «Пока пусто. Сыграй дуэли…» вместо ошибки. Нет `loadError`/retry. → Отдельная ветка ошибки с «Повторить».
- **`app/web_screen.tsx` — `Linking.openURL` без обработки** (medium, verified). `onPress={() => Linking.openURL(url)}` (стр. 54-56) без await/catch/`canOpenURL`. url — из route-параметров. При невалидном URL — молчаливый сбой. → async-handler с `canOpenURL` + сообщение об ошибке.
- **`components/ErrorBoundary.tsx` — подключён только в корне** (low). Падение тяжёлого экрана рушит весь UI. → Локальные boundary вокруг `arena_game`/`flashcards_swipe`/`exam`/`diagnostic_test`.
- **`app/lingman_videos.tsx` — `load()` через try/finally без catch** (low). Митигировано offline-notice, но throw всплывёт. → Добавить catch + `logAppWarning`.

- **`app/trainer_words_session.tsx`** (medium, verified) — пустой `<Text/>` (стр. 332-340).
- **`app/trainer_smart_session.tsx`** (medium, verified) — `<Text>...</Text>` (стр. 644-652), буквальное многоточие.
- **`app/flashcards/CardPackShardPaywallModal.tsx` — мёртвый код спиннера** (medium, verified high). Во всех трёх CTA при `purchasing` только `opacity: 0.85` + `disabled`. Спиннер отключён мёртвыми ветками `{false && purchasing ? <View/> : ...}` (стр. 936-938, 998-1002). `voucherCtaBusy`/`waitBusy` — пустые строки во всех локалях. → Включить `ActivityIndicator` при `purchasing`, менять подпись на «Покупка…».

→ Рекомендация для всех: `ActivityIndicator` или скелетон с подписью («Готовим карточки…») на время `accessReady || loading`.

### Доступность (accessibility)

**Корневая причина большинства a11y-находок — обёртки не пробрасывают пропсы.** Чинить сверху вниз:

1. **`components/TapScale.tsx`** (CRITICAL) — Props (стр. 6-16) без a11y-полей, `Pressable` (стр. 71-79) без `{...rest}`. В `lesson1.tsx:2833` передаваемые `accessibilityRole`/`Label` молча отбрасываются. Используется в 40+ экранах. → `extends ComponentProps<Pressable>` + `{...rest}`.
2. **`components/PressableScale.tsx`** (HIGH) — то же для крупных кнопок/карточек.
3. **`components/CustomSwitch.tsx`** (CRITICAL) — нет `role="switch"`/`state.checked` (settings, notifications, edu).
