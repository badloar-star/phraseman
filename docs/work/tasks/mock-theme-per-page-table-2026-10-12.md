## Outcome
Раздел «Тема кадра по страницам» в `docs/phraseman-2.0/DEV_SWITCHES_R1_CORE.md`: для ВСЕХ 81 страницы `docs/design/v2-app/*.html` — какая тема, оттенок ползунка и оформление (светлое/тёмное) нарисованы на образце и готовый хвост ссылки `theme=…&level=…[&appearance=light]` для съёмки приложения (подмена из коммита 9f6d6220c). Сверка получает однозначное правило: с какой темой снимать кадр под каждый образец.

## Scope
Только документ (раздел в DEV_SWITCHES_R1_CORE.md). Данные получены рендером страниц в браузере (вычисленные `--g1/--acc/--on/--cta`, активный чип, ползунки, фоны телефонов `.ph`), а не чтением кода; код приложения и макеты не меняются.

## Architecture
Классы страниц: (A) страницы с чипами тем — «Аврора» на полной насыщенности (`grad_aurora`, level 1), часть имеет второй, светлый телефон `ph lite`; (B) страницы «Насыщенность» (themes-gradient*, ползунок 60 → level 0,6); (C) страницы без чипов — базовый вид kit.css (графит на нуле, нейтральная кнопка `#F2F1F6`); (D) собственная палитра онбординга; (E) не экраны (индексы, анимация). Для светлых телефонов найден ближайший по цвету level.

## Security and privacy
Только документация; данные пользователей не затрагиваются.

## Technical debt
Светлые телефоны `ph lite` нарисованы акцентом `color-mix(#38E0AA 78%, #000)` (`#2CAF85`), которого генератор светлых тем «Пастель» не выдаёт (ближайший уровень 0,6 → `#579B84`, Δ≈48 по RGB): цветной акцент на светлых кадрах будет отличаться от образца — решение Макетов/владельца.

## Verification
Рендер каждой страницы в браузере и сверка вычисленных значений с токенами `liquidGlassTokens` (dark @1 `#7EF0C8`/`#04261D`; themes-gradient @0,6 `#ACF0DA`; themes-gradient-light @0,6 `#579B84` — совпали с образцом).
