# Task packet: предел ожидания для выкладки Firebase

Governance-ID: TG-016C714955B5

Дата: 2026-11-11. Исполнитель: сессия-координатор.

## Outcome

Выкладка через `scripts/deploy_from_clean_head.sh` больше не может висеть бесконечно: если
`firebase deploy` (или его сухой прогон) не завершился за отведённое время, команда
прерывается с понятным сообщением, скрипт выходит, слот светофора освобождается.

Повод (факты 11.11): выкладка двух функций Пика зависла в 21:31:14 на запросе
`GET cloudresourcemanager.googleapis.com/v1/projects/phraseman-ea0b3` без ответа и держала
единственный слот светофора до 22:05 — 34 минуты; восемь живых сессий стояли в очереди.
Владелец на предложение «выкладкам нужен предел ожидания — скажите, если поручить»
ответил: «да».

## Scope

- Новый файл `scripts/run_with_deadline.sh` — запускает команду с пределом времени.
- `scripts/deploy_from_clean_head.sh` — два вызова firebase (сухой прогон и выкладка)
  идут через этот помощник; на истечении времени печатается причина и что проверить.
- Новый тест `tests/deploy_deadline_contract.test.mjs`.
- НЕ трогаются: `.claude/semaphore/slot.sh`, хук светофора, сторожа pre-commit, сам набор
  проверок скрипта выкладки (сверка «бой vs HEAD», сборка, паритет, проверка права вызова),
  запрет `--force`, правило «выкладка только с `--execute` по слову владельца».
- Вне задачи: отдельная дорожка светофора для выкладок; сторож
  `check_callable_invoker.mjs` и регион `europe-west1`; сырые `firebase deploy` в обход
  скрипта (их предел не коснётся — сессиям об этом сообщается).

## Architecture

- `run_with_deadline.sh <секунды> <подпись> -- <команда…>`: обёртка над `timeout
  --foreground -k 15` из Git Bash. `--foreground` нужен, потому что настоящая выкладка
  может спросить подтверждение в консоли. Код возврата команды пробрасывается как есть;
  при истечении времени — код 124 и строка в stderr с подписью и числом секунд.
- Пределы: выкладка — `PHRASEMAN_DEPLOY_DEADLINE_SEC`, по умолчанию 900 с (ровно TTL слота
  светофора: дольше слот всё равно считался бы протухшим); сухой прогон —
  `PHRASEMAN_DEPLOY_DRYRUN_DEADLINE_SEC`, по умолчанию 300 с. Значения проверяются: только
  целое от 30 до 3600, иначе отказ до запуска.
- После истечения времени на настоящей выкладке скрипт НЕ завершается молча: печатает, что
  выкладка могла частично уйти, и всё равно запускает существующую проверку права вызова —
  именно прерванное первое создание функции оставляет её без права вызова (замечание 22.10
  в самом скрипте).
- Скрипт выкладки запускается через `slot.sh run`, поэтому выход скрипта = отдача слота.

## Security and privacy

Секретов и данных пользователей не касается. Команда для запуска берётся только из
аргументов самого скрипта выкладки, новых входов извне не появляется. Проверки доступа и
запрет `--force` не ослаблены.

## Technical debt

- Предел общий, а не «нет вывода N минут»: честная длинная выкладка многих функций дольше
  15 минут будет прервана — для неё предел поднимается переменной окружения осознанно.
- На Windows `timeout` завершает процесс firebase; если облако уже приняло операцию, она
  доедет на стороне Google — поэтому после прерывания обязательна проверка состояния.

## Verification

- `node --test tests/deploy_deadline_contract.test.mjs`: быстрая команда проходит со своим
  кодом возврата; медленная прерывается с кодом 124 и сообщением; неверный предел
  отклоняется; оба вызова firebase в скрипте выкладки идут через помощник.
- `bash -n` обоих скриптов.
- Настоящая выкладка в рамках задачи не запускается.

## Rollback

`git revert <хеш>` — скрипт выкладки возвращается к прямому вызову firebase; на прод и
данные не влияет.
