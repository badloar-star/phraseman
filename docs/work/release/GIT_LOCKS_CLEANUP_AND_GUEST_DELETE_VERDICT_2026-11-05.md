# Старые замки git и вердикт по удалению гостей (05.11, «Ядро»)

## 1. Старые временные индексы и замки в `.git`
**Проверка живости.** Имена вида `aa_part_<хэш>_<PID>.index(.lock)` и `core_tmp_index_<PID>(.lock)` несут номер процесса-владельца. Для каждого файла сверил номер со списком живых процессов Windows и Git Bash (`ps -W`, `ps`): живых владельцев **0 из 63**. Возраст: самый молодой — 33 447 минут (≈23 суток), остатки со времён октябрьских параллельных коммитов.

**Удалено:**
- 63 файла `aa_part_*` и `core_tmp_index_*` (замки нулевого размера и копии индекса по ~6 МБ), всего ≈56 МБ. Полный список имён — `C:/Temp/claude/adm/git_stale_deleted_list.txt` (вне репозитория).
- 8 замков `next-index-*.lock` (4 шт.) и `safe_commit_index_*.lock` (4 шт.) с мёртвыми PID и возрастом от 261 минуты до 72 суток.

**Оставлено:** `safe_commit_index_160358`, `.lock`, `.cerr` — PID жив, возраст 0 минут (идёт чужой коммит). Основной `index.lock` и замок общего коммита не трогал.

**Эффект.** Длинная очередь коммитов определяется общим замком `git_commit.lock` и окнами (`--wait-window`), а не этими файлами; удаление освобождает 56 МБ и снимает риск, что скрипт примет чужой старый замок за живой. Если очередь останется длинной, причина в окнах коммитов (правило владельца 13.10), а не в замках.

## 2. №170: удаляются ли гости с сервера сразу
**Вердикт: ДА, но в два шага.**
1. **Пользователь входа (Auth) гостя удаляется сразу** в момент постановки удаления: решение `decideAccountDeleteGuestImmediate` (`functions/src/account_delete.ts:2472`) возвращает `immediate: true`, причина `anonymous_no_links` (`:2524`), дальше `releaseAuthForDeletion(authUid, decision.immediate, …)` (`:2619`) и лог стадии `auth_user_deleted` (`:2660`).
2. **Данные гостя стираются воркером** `accountDeleteWorker` сразу после постановки задачи (минуты), без 14-дневной отсрочки: у задачи стоит `guestImmediate` (`:2758`).

**Условия «сразу»** (все должны выполниться, иначе обычные 14 дней): способ входа `anonymous` (`:2491`), нет привязанных провайдеров в токене (`:2497`) и в Auth (`:2507`), нет связанного профиля (`:2517`) и привязки входа (`:2519`), нет ситуации «профиль стабильного аккаунта пропал» (`:2523`). При любой ошибке чтения решение осторожное: 14 дней, причина пишется в журнал `[D189-GUEST]` (`:2484`).
**Отдельно:** кнопка «Удалить навсегда сейчас» (`deleteNow`, `:2593`) даёт мгновенное удаление не-гостю.

Проверка на деле: в боевом журнале искать `[D189-GUEST]` с `immediate:true reason:anonymous_no_links`.
