## Защита от двойной выплаты

Ключ операции собран только из оплачиваемого факта, без времени, суммы и id пачки:

| Факт | opId |
|---|---|
| ступень n | `spire_step:{lang}_{weekKey}_s{n}` |
| этаж f (1..15) | `spire_floor:{lang}_{weekKey}_f{f}` |
| вершина | `spire_summit:{lang}_{weekKey}` |
| место/повышение | `spire_week:{lang}_{weekId}` |

- **Повтор пачки / обрыв связи.** Уже учтённые отчёты — `duplicate`, счётчик не растёт,
  операций нет. Если бы они и появились, журнал ответил бы `already_applied`.
- **Ретрай транзакции (конфликт).** `beginStarLedgerTransactionAttempt` сбрасывает
  защиту от двойного prepare; всё пересчитывается из свежего чтения, `nowMs` один на вызов.
- **Разбиение на пачки.** Ступень 7 имеет один ключ в любой пачке (проверено тестом).
- **Обнулённая запись недели** (битый JSON → `{}`). Ступени 1..N придут заново, но их
  расписки уже есть → `already_applied`, баланс не меняется. Поэтому ключ по номеру
  ступени, а не по диапазону пачки.
- **Ретрай недельного крона.** Выплата сначала читает расписку `spire_week:…`: есть →
  итог помечается `paid` суммой ИЗ РАСПИСКИ, журнал не вызывается (переживает и смену
  сумм в админке между прогонами). `earnedAtMs` = понедельник 00:00 UTC (фиксирован),
  поэтому повтор операции совпадает с распиской байт в байт. `rewardStatus` — только
  отметка для экрана, защитой не считается (как и предупреждал PM-276).

## Стоимость Firebase

- Ступени: +1 чтение и +1 запись (расписка) на каждую НОВУЮ ступень/этаж; пачка сама по
  себе не дорожает — баланс едет в том же `set` users/{uid}. Вершина за неделю ≈ 151
  расписка. Расписки живут 400 дней (TTL журнала).
- Неделя: на каждого с наградой одна транзакция (3 чтения + 3 записи). Мест и повышений
  в комнате ≤ ~8.

## Логи (правило «сперва логи»)

- `[SPIRE-REPORT]`: `coins_truncated`, `coins_ledger_failed` (диапазон ступеней и сумма —
  для ручной доплаты), `coins_op_rejected`, `coins_op_already_applied`; `batch_done`
  несёт `fromSteps`, `coinsPlanned`, `coinsGranted`.
- `[SPIRE-PAYOUT]`: итог каждой выплаты (`paid`/`already_paid`/`skipped_*`/`rejected`).
- `[SPIRE-FINALIZE]`: `payout_failed`, `room_payout_incomplete`, в `done` —
  `payoutsPaid`, `payoutsFailed`, `coinsPaid`.
- `[SPIRE-REPORT]` на устройстве: `streak: день … засчитан ступенью …` / отказ.

## «Сегодня» — контракт типа задачи

Хука `useTodayTasks` в коде нет (есть только `today_tasks_placeholder.ts`), поэтому сам
блок не изобретался (это PM-259). Добавлен только тип:

{ id: 'spire_steps', kind: 'spire_steps', title: 'Пройди N ступеней Шпиля',
  progress: <ступени, пройденные сегодня по локальному дню>, target: N,
  done: progress >= target, rewardCoins: <сумма задачи из PM-259>, route: <экран Шпиля, PM-279> }

Источник `progress` для PM-259: отчёты с `outcome: 'passed'` и `completedAtMs` в

день серии): завести счётчик «ступеней за день» рядом с отметкой серии.

## Открытые вопросы

- **О-280-1. «Над облаками» (16+).** TOWER.md §4.3: «16+: как 11–15, только за место».
  Прочтено как «этажи 16+ не платят бонус этажа, ступени платят по 10». Если ступени
  выше вершины не должны платить вовсе — одна проверка в `spireStepCoinOps`.
- **О-280-2. Класс операций.** Ступени — `earn` (как урок: двигают `earnedTotal`,
  `weekEarned`, лигу, пока она жива). Место/повышение — `grant`: приз прошлой недели
  выплачивается в понедельник и иначе попал бы в очки новой недели. Если монеты-ранги
  (D34, 20 рангов) должны считать и призы — сменить на `earn` одной строкой в журнале.
- **О-280-3. День серии без опыта.** Урок засчитывает день через `registerXP` (опыт >0).
  Шпиль опыта не даёт, поэтому зовётся сам механизм серии `updateStreakOnActivity`.
  Замечено попутно: `app/_layout.tsx` (~стр. 2300) уже зовёт `updateStreakOnActivity()`
  при каждом запуске приложения — то есть день серии засчитывается простым открытием.
  Это существующее поведение, не менялось; если так быть не должно — отдельная задача.
- **О-280-4. Аккаунт в переезде в понедельник.** Выплата пропускается
  (`skipped_identity_transition`), прогон ретраится 3 раза; если переезд дольше —
  итог остаётся `pending_wallet`, комната не отмечена. Нужен дожим (например, при входе
  в Шпиль) — решить вместе с О-276-3.
- **О-280-5. Испорченный баланс.** При `star_ledger_inconsistent` ступени
  синхронизируются, монеты этой пачки не пишутся (лог `coins_ledger_failed`). Выбрано,
  чтобы человек не застрял в рейтинге; альтернатива — ронять пачку до починки журнала.
- **О-280-6. Время крона.** На комнату теперь flush + до ~8 транзакций. При сотнях
  комнат 540 с может не хватить — тогда вынести выплаты в отдельный крон по
  `rewardStatus == 'pending_wallet'` (нужен индекс группы коллекций).
