## Outcome

Владелец присылает скриншоты экранов, которые ему неудобны (Настройки, шапка «Обучения», «Словарь», разбор ошибки, «Видео», далее — «Темы» с ползунком). Для каждого экрана делается 3 РАЗНЫХ варианта раскладки и форм в стиле PhraseMan 2.0 (графит / Inter / hairline / белая CTA, без жёлтого). Владелец выбирает буквами (A/B/C), выбранный вариант передаётся сессии «Дизайн» для внесения в основной макет переноса. Успех: по каждому экрану есть выбранный владельцем вариант, зафиксированный в макете «Дизайна».

## Scope

In scope:
- `docs/design/v2-app/redesign-round-1.html` — единственный файл с макетами (HTML, автономная копия токенов kit.css).
- Этот task packet.
- Сообщения сессиям «Дизайн» и координатору о выбранных вариантах.

Out of scope:
- Любой код приложения (`app/**`, `components/**`, `constants/**`) — перенос ведёт сессия «Дизайн»; ползунок темы кодирует тот, кому владелец это поручит напрямую.
- `kit.css`, `profile.html` и прочие файлы «Дизайна» — не трогать.
- Эмулятор — не используется.

## Architecture

No architecture change: только документация/макеты. Токены скопированы внутрь HTML, чтобы артефакт открывался автономно; при изменении `kit.css` макет не обновится сам (принято, макет одноразовый — раунд).

## Security and privacy

Не применимо: макеты без данных пользователей, демо-имена; сторонних сервисов нет (шрифт Inter с Google Fonts — только для просмотра макета в браузере, не в приложении).
