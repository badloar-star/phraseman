# Аудит производительности: «Уроки» открываются с подвисанием

**Дата:** 2026-06-22
**Тип:** аудит без правок (по запросу).
**Симптом:** при заходе в раздел «Уроки» и при нажатии кнопок там переходы открываются не мгновенно, а с лёгким подвисанием.

---

## Главный вывод (одной фразой)

Анимации переходов **выключены** глобально (`animation: 'none'`, `app/_layout.tsx:2231`).
Значит подвисание — это **чистое время синхронного монтажа тяжёлого экрана в том же кадре, что и тап** (плюс на самом списке уроков — дорогой рендер без виртуализации). Лечить надо монтаж/рендер, а не анимацию.

Два разных подвисания:
- **A. Вход в раздел «Уроки»** — рендер списка `app/(tabs)/lessons.tsx` (1273 стр): ~41 тайл строится сразу, цвета/градиенты/тени считаются в `.map` на каждый рендер. Нет `FlatList`/виртуализации.
- **B. Нажатие кнопки урока** → `router.push('/lesson_menu')` (1503 стр), экзамен → `level_exam` (1706 стр), диагностика → `diagnostic_test` (1900 стр). Push монтирует экран синхронно в кадре тапа.

## Контекст навигации (проверено лично)

- `app/_layout.tsx:2231` — `animation: ENABLE_SCREEN_TRANSITIONS ? 'slide_from_right' : 'none'`, по умолчанию **none**. Переход мгновенный → весь видимый лаг = монтаж.
- `app/_layout.tsx:2233` — `freezeOnBlur: false` → неактивные экраны в стеке продолжают перерисовываться.
- Префетч **уже есть и фоновый** (не блокирует push): `prefetchLessonMenuCache` (`app/lesson_menu.tsx:179`), `primeLessonScreenFromStorage`/`primeAllLessonsFromStorageOnAppLaunch` (`app/lesson_screen_bootstrap.ts:147/123`). Но он греет **данные** (AsyncStorage), а не **монтаж дерева компонентов** — самая дорогая часть остаётся в кадре тапа.
- Entrance-анимация тайлов отключена (`itemAnims` = массив `null`, `lessons.tsx:545`) — не источник лага.

## Что НЕ является причиной (проверено, чтобы не чинить лишнее)

- Анимации переходов — выключены (`animation:'none'`).
- `hapticTap` — асинхронный, с cooldown 80мс, не блокирует (`hooks/use-haptics.ts`).
- Entrance-анимация тайлов — отключена (`itemAnims` = `null`).
- Префетч данных — уже фоновый и правильно не ждётся перед push.
- Провайдеры (Theme/Lang/StudyTarget) — мемоизированы, при навигации не пересчитываются. `EnergyProvider` — кандидат на профилировку (таймер восстановления), но не доказанная причина (P3).
