# Admin v2: достоверная аналитика

Дата: 2026-07-12
Статус: утверждено владельцем для безопасной реализации в отдельной ветке

## Цель

Заменить сырой и недостоверный аналитический снимок новой Admin v2 на серверно рассчитанный экран, где денежные доступы, события RevenueCat, сигналы paywall-воронки и качество источников разделены и честно подписаны.

Старая `admin/index.html` не изменяется. Развёртывание Functions или Hosting в эту работу не входит.

## Рассмотренные подходы

1. **Только переименовать карточки.** Быстро, но неправильные классификаторы, sandbox и браузерный кэш останутся. Отклонено.
2. **Исправить расчёты в браузере.** Сохраняет полное чтение Firestore, кэш и риск расхождения серверной логики. Отклонено.
3. **Серверный типизированный снимок и пассивный UI.** Один источник определений, проверяемые агрегаторы, явные состояния полноты. Выбрано.

## Архитектура

### Чистое ядро

Новый `functions/src/admin_analytics_core.ts` содержит чистые функции без Firestore:

- классификация активного доступа;
- взаимоисключающая агрегация доступов;
- агрегация RevenueCat за период;
- агрегация покупок шардов;
- агрегация consented paywall-сигналов;
- типы снимка и качества источников.

Категории доступа имеют фиксированный приоритет и не пересекаются:

1. `store_trial`;
2. `store_lifetime`;
3. `store_subscription`;
4. `gift`;
5. `admin_grant`;
6. `vip`;
7. `manual_or_unknown`.

`activeAccessTotal` равен сумме категорий. Store-доступ требует RevenueCat-происхождения и действующего срока с существующим 72-часовым grace period. Присутствие одного `premium_plan` недостаточно.

### Серверный callable

`functions/src/admin_analytics.ts` сохраняет проверки `admin=true`, роли и `money.read`, а также периоды 7/28/90 дней.

Он:

- постранично читает пользователей до документированного предела;
- исключает скрытые неканонические документы;
- читает RevenueCat premium и shard events;
- читает paywall funnel и app activity;
- возвращает для каждого источника состояние, число строк, признак усечения, свежесть и безопасный код ошибки;
- помечает зависимые метрики неполными при ошибке или усечении;
- не возвращает UID, email, сырые документы или секретные поля.

RevenueCat учитывает только `PRODUCTION`. Sandbox и неизвестное окружение исключаются и показываются как quality counters. Старт триала — только `INITIAL_PURCHASE + TRIAL`. Повторные события дедуплицируются по идентификатору события/документа.

Paywall funnel остаётся событийной выборкой пользователей с analytics consent: повторные показы и клики считаются как события. Конверсия подписывается как отношение сигналов, а не уникальных пользователей или денег.

### Интерфейс Admin v2

Новый `admin/v2/scripts/admin-analytics-view.js` рендерит семантический HTML. `admin-core.js` только управляет состоянием загрузки и передаёт снимок view-модулю.

Экран содержит:

- активные доступы с раздельными store/VIP/admin/gift категориями;
- production-события магазина за период;
- consented paywall-сигналы;
- компактный app activity breakdown;
- качество, свежесть и полноту каждого источника.

Есть один главный CTA «Обновить», select 7/28/90 дней и состояния `idle`, `loading`, `ready`, `partial`, `empty`, `error`. При обновлении последний успешный снимок остаётся видимым. Ошибка не очищает полезные данные.

UI следует Admin UI Bible: светлая спокойная панель, без emoji и декоративных градиентов, тёмный текст на лаймовом CTA, видимый focus, 44px targets, label для select, tooltip для кнопки и отсутствие горизонтального скролла страницы.

## Ошибки и неполные данные

- Ошибка одного источника переводит снимок в `partial`, но не уничтожает остальные показатели.
- Ошибка всех обязательных источников даёт `error`.
- Пустые успешно прочитанные источники дают `empty`, а не ошибку.
- Усечённый источник явно показывает лимит и не называется точным.
- Неизвестное RevenueCat environment не считается production.
- Неразрешимое происхождение исторического подарка не угадывается и попадает в `vip` либо `manual_or_unknown` с quality counter.

## Проверки

TDD-фикстуры покрывают:

- активные, истёкшие и grace-period store-планы;
- trial, subscription и lifetime;
- admin grant, VIP, gift, revoke и пересечения;
- sandbox, unknown environment, refund, renewal и дедупликацию;
- production/sandbox shards;
- dev-фильтр и нулевой знаменатель воронки;
- empty/error/partial/truncated source states;
- UI-контракт без сырого JSON, с корректными подписями и доступностью.

Финальная read-only сверка использует production-период как контроль, но production-числа не вшиваются в тесты.
