## Scope
In scope: только ЧТЕНИЕ текущего состояния чекпоинта публикации (`arena_target_publication_jobs`/аналог) через service-account.json, чтобы понять реальное состояние пайплайна перед любой записью. Если чекпоинт НЕ в состоянии `ready` — работа останавливается здесь, пишется честный отчёт, дальше без владельца не продолжаю (это уже не "включить кнопку", а полноценная контентная публикация с этапом stage, которая требует данных о бандле, которых у меня нет).
Out of scope: сама активация (запись в конфиг), если чекпоинт не готов. Сборка/стейджинг нового бандла с нуля.

## Architecture
Без изменений кода. Только диагностический read-only скрипт с Admin SDK (service-account.json), выполняется локально, не деплоится, не коммитится с секретами.

## Security and privacy
service-account.json — секретный файл с полным доступом к прод-базе Firebase. Скрипт временный, живёт в scratchpad-директории сессии (не в репозитории), удаляется после использования. Не логирую и не вывожу содержимое ключа. Публикация контента арены — не персональные данные пользователей, публичный игровой контент.
