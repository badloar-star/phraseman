# «Следующий урок»: сценарий «холодный кэш + платящий + таймаут → урок открылся» (15.10)

Governance-ID: TG-88B9E65C8D56

## Outcome
Координатор: при таймауте урок открывается «без пейвола, решает замок урока» — значит, замок (lesson_menu / lesson1) не должен сам закрыть платящего по тому же холодному `false`. В тест добавлен сценарий: холодный кэш + платящий + таймаут → урок открылся, а не пейвол; проверка замка на входе в урок — в системной проверке Ревизора.

## Scope

## Architecture
Сценарии на `resolveNextLessonAccess` с поддельным кэшем: после `prepare` кэш пуст, ответ проверки не приходит; фоновый поздний ответ не меняет принятое решение; контекст Plus читается в момент решения.
