# Аудит чата лиг + как оживить его без нагрузки на Firebase — 2026-06-28

> Цель: добавить функции, мотивирующие людей **общаться** в групповом чате лиги, и
> «оживить» чат Компасом (шутки/факты/итоги, видимые всем) — **без роста стоимости
> Firestore** (минимум realtime-чтений и записей).
>
> Только аудит + research. Код НЕ менялся.

---

## 0. Главный вывод за 30 секунд

- **Инфраструктура «системных сообщений» уже built-in, но мотора нет.** В коде есть тип
  `LeagueChatSystemType` (`rank_up | new_leader | member_joined | chest_unlocked |
  week_ending | generic`), поле `kind: 'user' | 'system'`, зарезервированный автор
  `LEAGUE_CHAT_SYSTEM_UID`, и UI уже умеет рисовать системное сообщение по центру с
  иконкой. **Но НИКТО эти сообщения не создаёт** — генератора нет (grep по типам в
  `functions/` = 0). Это «заготовка без двигателя» под Компаса.
- **Дешёвый способ оживления уже архитектурно лежит на блюдечке.** Есть `onSchedule`-крон
  для лиг (`functions/src/league_finalize_cron.ts`, `every monday 00:05`), который и так
  пагинирует по всем `league_groups`. Пост Компаса встраивается ровно в эту точку:
  **1 запись на группу в день** ложится в ту же коллекцию сообщений и читается тем же
  слушателем → **0 дополнительных reads на юзера**.
- **Правило экономики, на котором держится весь отчёт:** одно realtime-сообщение, которое
  видят все онлайн в чате = **N firestore reads** (N = число активных слушателей).
  Поэтому «дёшево» = контент, который пишется ОДИН раз на группу и читается из кеша/локально.
  «Дорого» = поток мелких realtime-доков на каждого юзера.

## ЧАСТЬ 1. АУДИТ текущей реализации

### 1.1 Архитектура чтения
- **Realtime listener** (`onSnapshot`), не одноразовый `getDocs`.
  `subscribeLeagueChatMessages()` — `app/firestore_league_chat.ts:277-304`.
- Запрос: `where(groupId) + where(weekId) + where(status=='visible') + orderBy(createdAt desc) + limit(80)` (`MAX_VISIBLE_MESSAGES=80`, строка 22).
- **Cache-first есть:** AsyncStorage (`loadCachedLeagueChatMessages` :156-170,
  `cacheLeagueChatMessages` :172-177). Ключ `league_chat_messages_cache_v1:{weekId}:{groupId}`.
- Подписка стартует только при `connectionUi.shouldSubscribe` (есть комната, авторизован,
  нет ошибки) — `LeagueChatPanel.tsx:285`; корректно закрывается в cleanup `:306-309`.

### 1.2 Стоимость Firestore (что именно платное)
**На одного зрителя (realtime):** 1 read на старте (до 80 доков по факту) + **+1 read за
каждое новое/изменённое сообщение**. При 10 онлайн и 20 сообщениях/час ≈ 210 reads.

**На одно отправленное сообщение** (`leagueChatSendMessage`, `functions/src/league_chat.ts:238-304`):

| Операция | Тип |
|---|---|
| `rateRef.get()` | 1 read |
| `assertActiveChatUser()` → **5 параллельных get** (league_groups, users, leaderboard, banned_users, league_chat_bans) `:152-158` | 5 reads |
| `league_chat_messages.add()` | 1 write |
| `rateRef.set(merge)` | 1 write |
| `grantRoomReadAccess()` set | 1 write |
| (если review/blocked) `moderation_queue.add()` | +1 write |
| **Итого на 1 сообщение** | **~7 reads + 3-4 writes + 1 CF-вызов** |

**На авторизацию комнаты** (`leagueChatAuthorizeRoom` :222-236): ~7-8 reads + 1 write + 1 CF
(но кешируется в AsyncStorage на 7 дней → повторно бесплатно).

**Самое дорогое место:** `assertActiveChatUser()` — **5 одновременных get на КАЖДУЮ отправку**
и **каждый** report/delete. Это узкое место №1 по стоимости записи.

### 1.3 Что уже готово под «оживление»
- ✅ Тип системных сообщений + UI-рендер (`league_chat_system.ts`, `LeagueChatPanel.tsx:79-88`).
- ❌ **Генератора системных сообщений НЕТ** (никто не пишет `kind:'system'`).
- ❌ Реакций/эмодзи нет. ❌ Лайков нет. ❌ Упоминаний нет (handle-ы даже блокируются модерацией).
- ❌ Опросов/квизов с кнопками нет. ❌ Pinned-сообщений нет.
- ✅ Аватар/аура автора в сообщении есть (`authorAvatar`, `authorAura`).

### 1.4 Безопасность и нагрев — здесь ХОРОШО
- `firestore.rules` для `league_chat_*` = default-deny → **клиент не может писать/читать напрямую**,
  всё через Cloud Functions. (Важно: реакции тоже придётся делать через CF или жёсткое правило на `increment`.)
- Подписки, `setInterval`, `setTimeout`, `AppState` — **все с корректным cleanup**, утечек нет.
- Троттлинг отправки двойной: клиент (`SEND_THROTTLE_MS=12s`) + сервер (`league_chat_rate_limits`).

## ЧАСТЬ 2. RESEARCH — 12 механик оживления (с оценкой стоимости)

Оценка стоимости: **Дёшево** = 1 запись/день на группу или чтение из кеша/локально (0-1 read/юзер).
**Средне** = реакция на действие, но агрегируется. **Дорого** = поток realtime-доков на каждого.

| # | Механика | Почему мотивирует писать | Стоимость |
|---|---|---|---|
| 1 | **Вопрос дня от Компаса** (1 пост/день) | Низкий порог, «социально разрешённый повод» написать; первые ответы запускают волну | Дёшево |
| 2 | **Опрос/квиз с кнопками** (голос = `increment` в 1 счётчик) | Самый низкий порог участия, мгновенный дофамин-отклик | Дёшево-средне |
| 3 | **Слово/идиома дня** (контент из бандла, в Firestore только индекс) | Польза + взаимность + хвост-вопрос | Очень дёшево |
| 4 | **Реакции-эмодзи** (`map` внутри дока сообщения, не отдельные доки) | «Ответить не печатая», петля подкрепления (как kudos в Strava) | Средне |
| 5 | **Брифинг лиги от Компаса** (итоги недели при ресете) | Соц.доказательство + гордость за группу | Дёшево |
| 6 | **Дневная батч-сводка достижений** («сегодня финишировали: …») | Видимость прогресса других + FOMO | Дёшево (замена дорогого антипаттерна) |
| 7 | **Групповой квест** «соберём X фраз за неделю» (общая полоска) | Кооперация, «не подвести своих» (как Friend Quests в Duolingo) | Дёшево-средне |
| 8 | **Pinned-икебрейкер для новичков** «представься одной строкой» | Снимает паралич чистого листа → выше удержание | Очень дёшево |
| 9 | **Серия активности группы** (group streak, «🔥 день 6») | Коллективная ответственность, никто не хочет оборвать | Дёшево |
| 10 | **Мини-челлендж выходного** (задание пт → разбор пн) | Дедлайн + лёгкий вход + обещанная обратная связь | Дёшево |
| 11 | **Голос группы** (кнопками выбрать тему слов) | Соавторство, «группу слышат» | Дёшево |
| 12 | **«Кстати…» соц-сводка при входе** (личное, не в общий чат) | Персональное подкрепление = сильный возвратный крючок | Средне (читает только сам юзер) |

## ЧАСТЬ 3. КОМПАС В ЧАТЕ — что делает и как ДЁШЕВО

**Принцип:** Компас = **серверный шедулер**, пишет **1 пост в день на группу** (+ редкие
событийные: ресет лиги, вехи квеста). Пост = `kind:'system'` в ту же коллекцию → читается тем
же слушателем, **без extra reads**. Контент — из бандла приложения, в Firestore летит лишь
крошечный указатель (индекс/seed дня). Канон тона: **от первого лица, по-человечески, без
слоганов/пафоса/вранья, короткий хвост-вопрос в конце, на языке группы (заготовленные
локали, не перевод в рантайме).**

9 форматов постов (образцы по-русски):

1. **Слово дня** — «Сегодня принёс вам слово *overwhelmed* — когда всего навалилось и голова
   кругом. *I felt overwhelmed at work today.* Узнаёте состояние? Расскажите, когда последний
   раз так было — по-английски, как сможете.»
2. **Грамма-квиз (кнопки)** — «Маленькая проверка. «Я живу здесь с понедельника» — как? Жмите
   вариант, вечером покажу, кто как ответил. A) I live here since Monday B) I've lived here since Monday»
3. **Факт про английский** — «Забавное: у слова *set* больше 400 значений — больше любого
   другого. Так что если запутались — вы не одни. Какое слово вас бесит больше всего?»
4. **Итоги недели** — «Неделя закрылась. Вы вместе разобрали 1 240 фраз — правда много. Выше
   всех поднялась Анна. Новая неделя началась, я снова с вами.»
5. **Сводка успехов (батч)** — «Заглянул в ваши успехи за сегодня: дневную цель закрыли Олег,
   Марина и ещё шестеро. Если вы пока нет — день не кончился, я подожду.»
6. **Икебрейкер (pinned)** — «Привет. Я Компас, буду рядом по дороге к английскому. Чтобы
   влиться — напишите одну строчку: откуда вы и зачем взялись за язык. Мне правда интересно.»
7. **Челлендж выходного** — «Выходные. Лёгкое задание: опишите их тремя фразами на английском,
   как получится. В понедельник зайду и аккуратно подскажу, где можно сказать естественнее.»
8. **Серия активности** — «Шестой день подряд в чате кто-то да пишет. Мне нравится эта
   компания. Давайте не обрывать — хватит одной фразы в день.»
9. **Голос группы (опрос)** — «Решайте сами: про что слова на следующей неделе? [Путешествия] [Работа] [Сериалы]»

## ЧАСТЬ 5. АНТИПАТТЕРНЫ (НЕ делать)

- ❌ **Typing-индикаторы «…печатает»** в реалтайме — write+read у всех онлайн ради косметики.
- ❌ **Лайки как отдельные доки** `likes/{msg}/{uid}` — плодит мелкие доки. Только `increment` в map внутри дока.
- ❌ **Realtime-бродкаст каждого достижения** в момент события — reads = события × онлайн. Заменить дневной сводкой.
- ❌ **Presence/online каждого члена** в реалтайме — heartbeat-writes × все слушатели.
- ❌ **Спам Компаса** — ≤1 плановый пост/день, иначе чат мьютят. Качество хвоста-вопроса > частоты.
- ❌ **Перевод контента Компаса в рантайме** — дорого и ломает тон. Локализованные шаблоны в бандле.
- ❌ **Лидерборды, пересчитываемые чтением всех участников на каждом входе** — считать агрегат по расписанию.

## Итог простыми словами

- В чат уже встроено место для «сообщений от системы», но их сейчас **никто не пишет** — это
  пустая заготовка ровно под Компаса.
- Дешевле всего оживить чат так: **Компас раз в день пишет одно сообщение на всю группу**
  (вопрос дня, слово дня, факт, итоги, поздравление) — его читают вместе с обычными
  сообщениями, поэтому это почти ничего не стоит.
- Людям нужен **лёгкий повод откликнуться, не печатая много**: опросы с кнопками и эмодзи-реакции
  на чужие сообщения — самые выгодные «движки» общения.
- Достижения других показывать **общей сводкой раз в день**, а не оповещением о каждом — и
  людей подстёгивает, и денег почти не тратит.
- Чего избегать: значков «печатает…», отдельных «лайков», мгновенных оповещений о каждом
  успехе и частых сообщений Компаса — это дорого или превращает чат в шум.
- Хорошая новость по технике: нужный «таймер на сервере» для лиг **уже есть** — новую функцию
  Компаса можно подвесить к нему, дописывать почти ничего не надо.
