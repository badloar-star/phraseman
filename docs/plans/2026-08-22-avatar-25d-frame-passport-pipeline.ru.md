# Аватар 2.5D: «Паспорт кадра» и конвейер согласованных whole-render ассетов

**Решение владельца 2026-08-22:** кастомизатор в приложении, вид — пиксаровский
референс (парень в терракотовом худи), путь — 2.5D из AI-изображений, пресеты
вместо слайдеров. Слоёная композиция (hair-overlay поверх портрета) отвергнута
ранее — только **цельные рендеры** (`wholeRenderSrc(base, look)`), см.
`2026-08-21-avatar-studio-whole-render-mock.md`.

## Почему раньше получалась «дичь» (диагноз по четырём скриншотам)

1. **Каждый ассет генерился независимым text-to-image** → поза, масштаб,
   положение головы и свет плыли от картинки к картинке (пучок «уехал» вверх и
   влево, за спиной проступал фон другого рендера).
2. **Маттинг эвристикой** («стереть почти нейтральные светлые/тёмные пиксели»,
   `matte_visual_mock_hair.mjs`) выбивал дырки внутри самих волос.
3. **Не было машинной приёмки** — кривой ассет попадал в каталог, и его первым
   видел владелец, а не сторож.

Все три причины устраняются контрактом ниже. Философия та же, что у GLB-аудитора
3D-трека: **детерминированный сторож вместо глаз**.

## 1. Паспорт кадра (единственный источник правды)

Файл `config/avatar-25d/frame_passport.v1.json` — числа фиксированы и проверяемы:

```json
{
  "canvas": { "width": 1024, "height": 1280 },
  "background": "#F7EFE4",
  "anchor": {
    "pupilLineY": 0.38,
    "faceCenterX": 0.50,
    "headHeightFrac": 0.42
  },
  "safeMargins": { "top": 0.04, "sides": 0.05, "bottom": 0.0 },
  "pose": "бюст 3/4 корпуса анфас, плечи в кадре, руки опущены, взгляд в камеру,
           мягкая полуулыбка, студийный мягкий свет слева-сверху",
  "lockZones": {
    "faceOval":  "эллипс вокруг лица — меняется ТОЛЬКО при смене базы/тона кожи",
    "torso":     "зона одежды — меняется ТОЛЬКО при смене одежды",
    "hairZone":  "зона волос/головного убора"
  }
}
```

Смысл: у КАЖДОГО рендера каталога зрачки, центр лица и высота головы стоят в
одних и тех же долях холста. Аксессуар физически не может «вылезти» — сторож
не пропустит силуэт за safeMargins.

## 2. Генерация: только edit-режим от канонического базового рендера

- На каждую базу (`base_m`, `base_f`) один раз руками/итерациями добывается
  **канонический базовый рендер**, идеально стоящий в паспорте кадра. Его SHA-256
  пломбируется в манифест — это «нулевой пациент», аналог референсов из 3D-плана.
- Все варианты (причёска, одежда, головной убор, эмоция) генерятся **только как
  image-edit этого базового рендера**: «замени ТОЛЬКО причёску на X; поза,
  кадрирование, лицо, свет — без изменений». Никакого свободного text-to-image.
  Это и есть «готовый шаблон позы», который просил владелец: поза не описывается
  словами каждый раз, а наследуется от пиксельного оригинала.
- Цвета волос/одежды НЕ генерятся отдельными запросами: одна канонизированная
  генерация формы + **детерминированный перекрас по маске** (sharp, hue-shift).
  Маска = diff между вариантом и базой, порог по ΔE; никакой эвристики
  «нейтральных пикселей».

## 3. Машинная приёмка каждого ассета (сторож каталога)

`scripts/avatar-25d/audit_render.mjs` — каждый кандидат проходит до попадания
в каталог:

1. **Размер/формат** — ровно 1024×1280, sRGB.
2. **Фон** — углы и рамка 2% равны `#F7EFE4` (ΔE < 3): чужой фон не пролезет.
3. **Совмещение** — edge-map кросс-корреляция lock-зоны лица с базовым рендером
   ≥ порога (для смены причёски лицо обязано совпасть попиксельно с точностью до
   шума). Смещение/масштаб «пучка вверх-влево» умирает здесь.
4. **Границы** — силуэт (diff с фоном) не пересекает safeMargins: ничего не
   обрезано краем и не вылезло.
5. **Зона изменения** — diff с базой лежит ВНУТРИ заявленной lock-зоны
   (сменил одежду → волосы и лицо не тронуты).
6. Результат пишется в `assets/avatar-25d/manifest.json`: id, слоты, SHA-256,
   метрики приёмки. Jest-контракт держит манифест честным (как в 3D-треке).

FAIL любого пункта = ассет не существует для приложения. Перегенерация дёшева.

## 4. Матрица P0 (пресеты, без комбинаторного взрыва)

| Слот | Вариантов | Комментарий |
|---|---:|---|
| База (маск./фем.) | 2 | два канонических рендера |
| Причёска | 6 | генерация формы ×1, цвета перекрасом |
| Цвет волос | 4 | маской, не генерацией |
| Одежда | 6 | по одной генерации |
| Головной убор | 2 | капюшон / без |
| Тон кожи | 3 | edit базы (меняется faceOval) |

Генераций: ~2×(6+6+2+3) ≈ **34** (остальное — перекрас). Хранение: whole-render
собирается на лету из «формы» и перекраса при сборке каталога, в приложение
уходит готовая матрица WebP 512×640 (~35 КБ шт.). Полная матрица кэшируется как
статические ассеты — офлайн, ноль Firestore-чтений в рантайме.

## 5. Экран приложения

Раскладка уже одобрена (`2026-08-21-avatar-dna-approved-studio.md`): пять вкладок
Основа/Лицо/Волосы/Образ/Сцена, cream/cocoa/terracotta, «Сохранить персонажа».
Меняется только источник превью: `wholeRenderSrc(base, look)` из манифеста.
Выбор — мгновенный (ассеты локальные, prewarm перед вводом), сохранение = ids
пресетов + готовый портрет-снапшот для остальных экранов приложения.

## Статус смежных треков

- Процедурный 3D (CC0 Art P0, задачи 1–6 готовы) — замораживается как фундамент,
  не удаляется; ART-гейт против референса этим путём не проходится (озвучено).
- `prototypes/avatar-studio` — остаётся песочницей для приёмочного сторожа до
  переноса в RN.
