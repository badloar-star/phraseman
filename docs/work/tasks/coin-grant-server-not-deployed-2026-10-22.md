## Клиент: почему после клеймов телефон не звал начисление (22.10)

Governance-ID: TG-34784342AB23

Разбор кода `app/level_spin_star_grants.ts` + `app/phone_state_economy_bridge.ts`:
- «Получить» → `claimReportRewardBundle` → `claimReportReward` (сервер) → `creditRunes` → `enqueueLevelSpinStarGrant(..., { syncNow: true })`. Операция пишется в очередь на телефоне, баланс виден сразу. Отправка — `syncPendingLevelSpinStarGrants` в фоне (`void`).
- Повторные отправки — только по двум поводам: новая постановка в очередь (`syncNow`) и стартовое чтение кошелька (`readUnifiedLevelSpinStars`, ~1582). Таймера нет.
- После 400: `catch` → запись в локальный журнал (warning), операция остаётся в очереди, баланс не откатывается. Монеты на телефоне не теряются.
- До сети цикл выходит МОЛЧА:
  - `hasValidFingerprint` = false → `continue`: операция пропускается навсегда, без лога;
  - `commitPhoneStateNonMonetaryEconomyGrant` = false → `break`: стоит ВСЯ очередь, без лога. Внутри — 7 условий `return false`; первое — `runtime` ещё не настроен (состояние телефона поднимается фоном после первого кадра Главной).
- В релизе `DebugLogger.info/warn` ничего не печатает, жалоба из приложения журнал не прикладывает. С телефона живого человека клиентские логи до нас не доходят.

Шаг 1 (по правилу «сперва логи»): метки `[COIN-WALLET]` на каждом выходе цикла отправки и на каждом отказе моста для `star_credit`. Поведение не меняется. Проверка — на своём устройстве или эмуляторе (logcat и консоль сборщика). Коммит 7b804a37e.
