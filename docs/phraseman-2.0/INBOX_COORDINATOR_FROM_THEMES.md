## 11.10 00:40 — причина раздувания Metro до 5–6,5 ГБ найдена, правка подготовлена (НЕ применена) — `2394441b1`

- **Причина:** Metro сам берёт число процессов-преобразователей по формуле `ceil(ядра·(0.5+0.5·exp(−ядра·0.07))−1)`; на **24 логических ядрах = 14 процессов jest-worker**. Замер живого сеанса: `expo start --dev-client --port 8081` + **ровно 14 воркеров**. Каждый при преобразовании растёт до 300–450 МБ и не пересоздаётся: 14 × ~400 МБ + основной 1–1,5 ГБ ≈ 5,5–7 ГБ. (Рост каждого воркера до 400 МБ — типичная оценка, замер сразу после старта показал 49 МБ; подтвердить через 15 минут после перезапуска.)
- **Вторично:** вне блок-листа ~40 тыс. файлов (`android` 8,8 тыс., `functions-admin/-content/-english-test` по 6–7 тыс. со своими `node_modules`, `output`, `dist`, ~80 папок `.tmp_*_backup`, `.arena-*`) — нагружают обход/события и дают дубли `package.json`, но на память почти не влияют (карта файлов — мегабайты). `require.context` роутера читает только `app/` (~1,2 тыс. файлов) — не причина; `watchFolders` не заданы; Watchman 18 МБ.
- **Правка:** `docs/work/tasks/bundler-memory-fix-2026-10-10.patch` (накладывается чисто: `git apply --ignore-whitespace --check` проверен): `config.maxWorkers = 4` только для локальной разработки (EAS/CI/стор-релиз не ограничены; своё число — `PHRASEMAN_METRO_MAX_WORKERS=N`) + 26 корневых папок и 5 префиксов (`.arena-`, `.tmp`, `.codex-tmp`, `_scoped_build_`, `_worktree_backups_`) в блок-лист.
