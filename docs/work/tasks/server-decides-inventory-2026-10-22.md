## Architecture — что значит «хранит» на сервере

Сервер оставляет только проверки целостности хранения, которые защищают «чтобы не потерялось», а не решают за человека:
- владелец записи = вызывающий (auth → stableUid) — иначе один телефон пишет в чужой кошелёк;
- идемпотентность по opId: повтор того же opId с тем же содержимым = тот же ответ; тот же opId с другим содержимым = конфликт (иначе одна запись перезапишет другую);
- форма записи (схема, размеры) — чтобы не сломать чтение на втором телефоне.
Всё остальное (суммы, лимиты, «можно ли») решает телефон. Сервер вместо отказа ставит пометку и шлёт сигнал в Джарвис, если запись выглядит аномально.

## «Друзья» по закону — предлагаемая пересборка

- «Урок вместе»: телефон друга после занятия пишет на сервер отметку «прошёл по приглашению» (хранение по inviteId, идемпотентно). Телефон пригласившего при следующем входе забирает отметки и сам начисляет +2 через кошелёк (opId `lesson_together:<pair|day|uid>`; второй раз тот же opId не начислится). Телефон друга начисляет +2 себе так же. Раз-в-день на пару решает телефон детерминированным opId (одинаковый у A→B и B→A). Помощник Learning V2 на сервере не нужен.
- Дуэль: ход и отметки хранятся по duelId / requestId; итог считают оба телефона по одним правилам; сервер не возвращает отказы, решающие, что увидит человек (кроме «нет такой дуэли / не ты адресат» — целостность).
- Лимиты «3 в день» — на телефоне; сервер их не проверяет.
- Риск: тот же, что А1 (изменённый телефон начислит себе +2 сколько угодно раз с разными днями/парами).
