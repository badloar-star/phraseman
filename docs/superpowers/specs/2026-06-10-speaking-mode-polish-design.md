# Дизайн: Speaking Mode до идеала (Фаза 2 перестройки планов)

> Дата: 2026-06-10. Статус: утверждён владельцем (брейншторм).
> Связано: `docs/plan_rebuild_workplan.md` (Ф2), память `phraseman_content_generation_order.md`.

## Контекст и решение

Перестройка системы планов phraseman. Изначально Ф2 формулировалась как «добавить несколько новых
разговорных режимов». Разведка Ф0 показала, что речевой фундамент **уже построен** (прошлые сессии
speaking-mode):

- on-device STT работает: `expo-speech-recognition@^3.1.3` + плагин в `app.config.js` (Google
  on-device пакет, mic/speech permissions), бесплатно, без серверов.
- Готовый режим end-to-end: `components/SpeakingPanel.tsx` (mic, ленивый `ExpoSpeechRecognitionModule`
  с graceful `unavailable`, эквалайзер, пер-словная подсветка, кнопки, статус+%).
- Реальный детерминированный скоринг: `app/personal_plan_pronunciation_scoring_core.ts`
  (Levenshtein слов + LCS + completeness, веса 0.62/0.28/0.10, без рандома/сети), покрыт тестами.
- Панель встроена в ~8 экранов; есть dev-лаборатория `_admin_speaking_lab.tsx` со всеми 8 статусами.

**Решение владельца:** новые режимы НЕ делаем. Берём существующий режим и доводим до идеала и единого
стандарта по 4 направлениям. Порог годности остаётся **90%** (`PRONUNCIATION_PASS_THRESHOLD`).

## Границы (что трогаем / что нет)

Внешний контракт пропсов `SpeakingPanel` (`targetText`, `lang`, `theme`, `onPass`, `onClose`,
`previewStatus`, `previewScore`) **не меняем** — иначе пришлось бы трогать все хосты. Все улучшения
внутри панели и её хелперов.

**Трогаем:**
- `components/SpeakingPanel.tsx` — подписка на громкость, рендер кружка вместо строки, доведение
  состояний ошибок.
- `app/personal_plan_voice_waveform.tsx` — новый опциональный проп `level` (реальная громкость),
  текущая пульсация остаётся фолбэком.
- `components/SpeakingScoreRing.tsx` — **новый** локальный аниматор-обёртка над `CircularProgress`
  (заполнение 0→score). Общий `CircularProgress` НЕ трогаем.
- `app/speaking_volume.ts` — **новый** чистый хелпер нормализации/сглаживания громкости (под тест).
- `app/_admin_speaking_lab.tsx` — прокинуть `previewScore` (сейчас не прокинут) + превью уровня
  громкости, чтобы кружок/эквалайзер были видны в QA без сборки.
- Хосты (`lesson1`, `trainer_phrases_session`, `(tabs)/quizzes`, `lesson_menu`,
  `achievements_screen`, …) — только если аудит найдёт расхождение в вызове; тогда выравниваем по
  эталону `lesson1.tsx`.

**НЕ трогаем:** скорер `..._scoring_core.ts`; серверный дубль `functions/src/pronunciation_scoring_core.ts`
(CF, тоже 90); порог 90%; контракт пропсов; `planId`; 32 базовых урока; worktree
`.claude/worktrees/referral-vip/`; копии в `phraseman-ai-dialogue`/бэкапах.

**Принцип:** панель остаётся самодостаточной (сама владеет правами/распознаванием/скорингом/жизненным
циклом); хост даёт фразу и узнаёт об успехе. Уже так — сохраняем.

## Направление 1 — эквалайзер на реальный голос

`expo-speech-recognition` умеет volume metering нативно на iOS+Android (README: событие
`volumechange`, значение −2…10, «Real-time volume levels ✅✅»). Сейчас панель его не включает.

Поток:
1. В `speech.start({...})` добавить `volumeChangeEventOptions: { enabled: true, intervalMillis: 100 }`.
2. Подписаться `speech.addListener('volumechange', e => …)`, `e.value` ∈ −2…10.
3. Через `app/speaking_volume.ts`:
   - `normalizeVolume(raw)`: −2…10 → 0…1, всё ≤0 → 0 (тишина).
   - сглаживание: `smoothed = prev*0.6 + next*0.4` (бары не дёргаются).
   - чистые функции → юнит-тест.
4. Уровень → новый опциональный проп `level?: number` (0…1) в `VoiceWaveform`.

`VoiceWaveform`:
- `level` передан → высота баров = функция от `level` (разброс по `BAR_PEAKS` для вида эквалайзера).
- `level` не передан → текущая авто-пульсация (фолбэк для превью без микрофона).

Граничные случаи: нет события → `level=0` → бары в покое (не падаем); тихий голос → низкие бары
(честно «плохо слышно»). Перфоманс: 10 Гц × 7 баров — дёшево.

Поведение при остановке: при записи виден эквалайзер; на `scoring` он плавно гаснет в покой; на его
месте появляется кружок-оценка.

## Направление 2 — кружок-оценка (ScoreRing)

Используем готовый `components/CircularProgress.tsx` (кольцо + процент в центре). Анимацию заполнения
0→score (~600мс) делаем через **новый локальный** `components/SpeakingScoreRing.tsx` (Animated-обёртка,
на каждом кадре рендерит `CircularProgress` с текущим pct). Общий компонент не трогаем.

Поведение по статусам:
- `idle/requesting/listening` → эквалайзер.
- `scoring` → эквалайзер гаснет (спиннер на кнопке как сейчас).
- `passed/failed` → `SpeakingScoreRing`:
  - `pct = score`; `color = passed ? theme.correct : theme.wrong`; `bg = theme.border`;
    `textColor = theme.textPrimary`; размер ~96–104px (крупно для 50+).
  - под кружком подпись-цель: «нужно 90%» (понятно, почему 88% не зачтено).
  - текстовую строку `97% / 90%` убираем (роль у кружка + подписи).

Тексты статусов остаются как подпись под кружком (без числа в строке). Доступность:
`accessibilityLabel = «Результат N процентов из 90 нужных, засчитано/не засчитано»`.

## Направление 3 — единый стандарт по хостам

Эталон вызова — `lesson1.tsx`: премиум-гейт `usePremium()` → не премиум → `premium_modal`
`context:'speaking'`; `theme` из `useTheme()` по единой схеме; `lang` из `useLang()`; поведение после
`passed`.

Аудит всех хостов. Если хост вызывает иначе (нет гейта / своя тема / игнор `onPass`) — выравниваем по
эталону **в рамках Ф2**. Если все одинаково — направление закрывается аудитом без правок.

Риск: хосты — чужие файлы из разных сессий. При конфликте (чужие незакоммиченные правки) — сообщить
владельцу «редактируется в другой сессии», пропустить, выписать заметкой.

## Направление 4 — состояния ошибок/недоступности

Сейчас `denied`/`unavailable` — серый текст + disabled кнопка. Доводим:
- **`denied`** (отказ в микрофоне): текст + кнопка «Открыть настройки» (`Linking.openSettings()`).
- **`unavailable`** (нет on-device движка): спокойное «Это устройство не умеет распознавать речь.
  Остальные упражнения доступны» + кнопка «Понятно» (закрыть). Не тупик.
- **Пустой результат** (`nomatch`/тишина → сейчас сразу `failed`): мягче — «Не расслышал. Скажи чуть
  громче» со стрелкой на «Ещё раз», а не «провал 0%».

Тексты ru/uk/es (через `L()`), спокойный тон под 50+, без эмодзи.

## Тестирование и проверка

- jest: `speaking_volume.ts` (−2→0, 10→1, ≤0→0, сглаживание монотонно, кламп). Скорер — регресс
  (не трогаем).
- Визуал без сборки: `_admin_speaking_lab.tsx` — прокинуть `previewScore` + превью громкости →
  глазами проверить 8 статусов + кружок + эквалайзер.
- Реальная запись голоса: нативный dev-build + микрофон → проверяет владелец на устройстве. Claude
  обеспечивает зелёные jest/tsc + визуал статусов в лаборатории. Эмулятор-изоляция (свой AVD/порт)
  по памяти при прогоне.

## Порядок работ (атомарные коммиты в текущую ветку)

1. `speaking_volume.ts` + тест.
2. Эквалайзер на громкость: `VoiceWaveform` проп `level` + подписка в `SpeakingPanel`.
3. `SpeakingScoreRing.tsx` + замена строки на кружок в панели.
4. Состояния `denied`/`unavailable`/пустой результат + «Открыть настройки».
5. Лаборатория: `previewScore` + превью громкости.
6. Аудит 8 хостов → выравнивание по эталону (или заметка о конфликте).
7. Финал: jest + tsc + эмодзи-скан, обновить workplan/память.

## Результат аудита хостов (направление 3, шаг 6 — выполнено 2026-06-10)

Реальных JSX-монтирований `<SpeakingPanel>` в `app/` всего три:
- `app/lesson1.tsx` — напрямую (инлайн тема + свой premium-гейт `openSpeaking`).
- `components/SpeakingButton.tsx` — общий drop-in: premium-гейт (`usePremium` → `premium_modal`
  `context:'speaking'`) + `buildPanelTheme(t)` + монтирование панели + `onPass`. Используется
  `app/(tabs)/quizzes.tsx` и `app/trainer_phrases_session.tsx`.
- `app/_admin_speaking_lab.tsx` — QA-превью (добавляет `previewStatus/previewScore`, это ожидаемо).

**Вывод: единый стандарт уже соблюдён.** Все три точки вызывают панель консистентно (тот же
premium-гейт, тот же маппинг темы, тот же `onClose/onPass`). Расхождений, требующих правок, нет —
направление закрыто аудитом без изменений хостов.

**Отложенный косметический пункт (НЕ в объёме Ф2):** `lesson1.tsx` дублирует инлайн-тему и гейт
вместо переиспользования `SpeakingButton`/`buildPanelTheme`. Это не дефект (рабочий код), а вкусовщина;
дизайн запрещает рефактор ради красоты. Плюс на момент Ф2 `lesson1.tsx` редактировался в другой
сессии — не трогаем. Если решим убрать дублирование позже: заменить инлайн-объект темы (lesson1
~1465-1480) на `buildPanelTheme(t)` либо перевести на `SpeakingButton`, поведение не менять.
