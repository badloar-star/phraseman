# Аудит мгновенности отклика (tap latency) — 2026-09-02

Жалоба владельца: «нажатие на любую кнопку, открытие любого раздела — есть лёгкая,
почти незаметная задержка; хочу как в Instagram». Ниже — где именно в этом приложении
теряется время, что уже сделано в этой сессии (измеритель), и план по этапам.

## 0. Главное за минуту

1. **Сначала цифры, потом починка.** В приложение добавлена трассировка `[TAP-LAT]`
   (`app/tap_latency_trace.ts` + `components/TapLatencyNavProbe.tsx`, подключена в
   `app/_layout.tsx`). Она печатает для КАЖДОГО открытия экрана: касание→JS,
   касание→обработчик, обработчик→коммит, коммит→кадр, всего. В dev включена всегда,
   в release — только с `EXPO_PUBLIC_TAP_LATENCY_TRACE=1`. Прогнать 20-30 тапов на
   устройстве и смотреть, какой из четырёх отрезков толстый — это и есть диагноз.
2. **Самая вероятная причина «лёгкой задержки» — полный холодный маунт каждого
   push-экрана без предзагрузки, при переходах `animation: 'none'`.** Экраны-монолиты
   (5141 строк Главная, 5116 Статистика, 4510 Уроки, 3934 Друзья) монтируются с нуля
   на каждый push (после ухода `freezeOnBlur` + pop = unmount). Instagram не рендерит
   экран в момент тапа — он держит его готовым. У нас есть инструмент для того же:
   `router.prefetch()` (expo-router 6 → React Navigation `PRELOAD`; native-stack 7.18
   рендерит preloaded-маршрут и НЕ замораживает его — проверено в `node_modules`).
   Использований `router.prefetch` в проекте: **0**.
3. **Три обработчика ждут диск/сеть ДО навигации** (класс «await перед push»):
   `app/(tabs)/lessons.tsx` `openLearningRoute` (3-4 `await`, включая
   `invalidatePremiumCache()` + сетевую проверку премиума), `app/arena_today.tsx` `start`
   (`await confirmArenaTodayEnergy` до первого видимого отклика), `app/streak_stats.tsx`
   `handleReviveStreak` (`await refreshReviveOffer()` перед модалкой, данные уже в state).
4. **Отклик кнопки идёт через JS-поток.** Все четыре общих примитива
   (PressableScale/TapScale/DuoPressable/PressableHybrid) = RN `Pressable` +
   `Animated` с native driver: анимация нажатия стартует только когда JS-поток
   обработал касание. Если JS занят (ре-рендер, парсинг JSON, Firestore-снапшот) —
   нажатие «тупит». `Gesture.Tap`/UI-thread feedback: **0** использований.
   `TouchableOpacity` напрямую: **1388** мест.
5. **Сравнивать с Instagram можно только release-сборку.** Dev-клиент (Metro, `__DEV__`,
   без байткода Hermes) добавляет десятки миллисекунд на каждый тап сам по себе.
   Замер `[TAP-LAT]` обязателен на release/preview-сборке с флагом.

## 1. Как измерять (сделано в этой сессии)

Файлы: `app/tap_latency_trace.ts`, `components/TapLatencyNavProbe.tsx`; подключение:
`app/_layout.tsx` (`onStartShouldSetResponderCapture` на корне + `<TapLatencyNavProbe />`),
метка действия: `app/(tabs)/_layout.tsx` (`handleTabChange`). Метку в `go()` Главной
(`noteTapAction('home:' + path)`) добавить, когда `app/(tabs)/home.tsx` освободится —
на 2026-09-02 файл правится другой сессией (раскладка «Спин»/«Подарок»); без метки
строка навигации всё равно печатается — по касанию из корня.

Строка лога (grep `[TAP-LAT]` в `.expo/metro-console.log`, в release — logcat / Console.app):

```
[TAP-LAT] → streak_stats (из home) · палец 64мс · JS-лаг на отпускании 2мс
  · отпускание→обработчик 1мс · обработчик→коммит 138мс · коммит→кадр 17мс
  · ОТ ОТПУСКАНИЯ ДО КАДРА 156мс ⚠️ МЕДЛЕННО
```

Как читать:

| отрезок | что означает | норма (release) | если толстый — виноват |
|---|---|---|---|
| палец | нажал→отпустил, по JS-часам | 40-120 мс | это не задержка приложения, только контекст |
| JS-лаг на отпускании | (JS-интервал нажал→отпустил) − (нативный интервал) | 0-5 мс | JS-поток был занят, когда палец отпустили (§3.5, §3.6) |
| отпускание→обработчик | от отпускания до `onPress` | 0-5 мс | JS занят между событием и обработчиком; `await` в обработчике (§3.2) |
| обработчик→коммит | рендер + коммит экрана назначения | < 50 тёплый / < 120 холодный | тяжёлый маунт экрана (§3.1, §3.3) |
| коммит→кадр | до следующего кадра после коммита | 8-17 мс | > 33: нативная вёрстка (сотни вью, градиенты) или JS занят эффектами сразу после коммита |
| ОТ ОТПУСКАНИЯ ДО КАДРА | то, что чувствует человек | < 100 мс | — |

JS-лаг считается по разницам интервалов, поэтому не зависит от единиц и точки
отсчёта нативных часов (iOS отдаёт секунды, Android — миллисекунды).

Строки без навигации печатаются только когда отпускание→обработчик > 16 мс — это
«кнопка тупит» без перехода (тумблеры, шторки, модалки). Последние 60 замеров —
`getRecentTapLatency()` (можно вывести в DEV-хаб).

Стоимость измерителя: две JS-функции на касание (touchStart в capture-фазе без
захвата responder + touchEnd корня) и один слушатель `state` навигации. В release
без флага — ноль.

**Ловушка dev-клиента (первый замер 2026-09-02 12:23).** Metro докачивает модули
лениво: в первые ~40 с после холодного старта в логе идут строки `Bundled … (N modules)`,
и JS-поток стоит в ожидании сети. Замеры в этом окне (264 мс маунт «Темы», 1096 мс
возврат на табы) не показательны. Правило замера: приложение живёт ≥ 1 минуты,
рядом в логе нет `Bundled`, каждый экран открывается дважды (второе открытие —
чистый маунт без докачки).

## 2. Анатомия одного тапа в этом приложении (по коду)

```
палец ↓  → Fabric → JS: Pressable.onPressIn → Animated(native driver) старт   [§3.4]
палец ↑  → JS: onPress → hapticTap() (fire-and-forget) → logFeatureOpened() (нативный вызов)
         → trackFeatureOpened() (async: AsyncStorage read + JSON + write)     [§3.5]
         → router.push()
         → React: рендер AppContent (2250 строк, 69 useEffect; usePathname)   [§3.6]
         → React: маунт экрана назначения С НУЛЯ (нет preload)                [§3.1]
         → коммит → native-stack показывает экран БЕЗ анимации ('none')      [§3.1]
```

Факты, на которые опирается диагноз:
- `app/config.ts:186-203` — все переходы в store-сборке `animation: 'none'` (решение
  владельца 2026-08-25, закреплено `tests/interaction_responsiveness_contract.test.ts`).
- `router.ctx.js` — маршруты в режиме `sync`: Metro требует ВСЕ модули маршрутов при
  старте (шаблон `const map = { "./x": require("./x") }` в
  `metro/src/lib/contextModuleTemplates.js`). Значит, на тапе модули НЕ вычисляются —
  стоимость тапа = чистый React-маунт + нативная вёрстка. (Обратная сторона: тяжёлый
  холодный старт; `inlineRequires` в Expo по умолчанию выключен —
  `metro-config/src/defaults/index.js:106`.)
- `freezeOnBlur: true` глобально + `animation: 'none'`: после pop экран размонтируется,
  повторный push = полный маунт заново. Второе открытие НЕ дешевле первого.
- Табы: `react-freeze` на скрытых панелях; тап по табу = размораживание = полный
  ре-рендер панели (Главная 5141 строк, 49 `useState`, 45 `useEffect`).

### 3.4. Отклик кнопки зависит от JS-потока (системно)

- Все общие примитивы (`components/PressableScale.tsx`, `TapScale.tsx`, `DuoPressable.tsx`,
  `PressableHybrid.tsx`) — RN `Pressable` + `Animated` (native driver). Фидбек стартует
  ПОСЛЕ того, как JS обработал `onPressIn`. `Gesture.Tap` + Reanimated worklet
  (фидбек на UI-потоке, не зависящий от занятости JS): 0 использований.
- `TouchableOpacity` напрямую: 1388 мест; `<Pressable`: 487. Переписывать всё — нет;
  достаточно перевести 4 общих примитива на UI-thread (`Gesture.Tap()`/`Gesture.Native()`
  с `onBegin/onFinalize` worklet → `scale/opacity` shared values), и постепенно
  заменять сырые `TouchableOpacity` на них в горячих местах (Главная, таббар, уроки).
- RN `Pressable`: `onPress` срабатывает на отпускании — это норма (так у всех); но
  `DEFAULT_MIN_PRESS_DURATION = 130` мс держит состояние «нажато» минимум 130 мс —
  это правильно, не трогать.
- `hapticTap()` зовётся в `onPress` (на отпускании). Apple даёт хаптик на касании.
  Мелочь, но ощущается: перенести в `onPressIn` в общих примитивах (уже так в
  PressableScale по контракту «сначала визуал, потом хаптик»).

- `useGuardedNav`: не задерживает первый тап (600 мс — только на повторы).
- Новая архитектура включена (`app.json` `newArchEnabled: true`), Reanimated 4.1,
  react-native-screens 4.16, Hermes — фундамент современный.
- Секционные шторки (`section_sheet_navigation.ts`) и пейволы — уже `animation: 'none'`
  через native-stack, без `await` перед переходом.

## Находки и предложения

- Самый быстрый ощутимый выигрыш при минимальном риске: этап 1 (три `await`) + этап 2
  (prefetch 5 экранов) — оба локальны, за флагом, откатываются одной строкой.
- Разбиение монолитов (Главная/Статистика/Уроки/Друзья) — самая большая работа, но
  она лечит сразу три симптома: маунт, разморозку таба и ре-рендеры от каждого
  счётчика на Главной.
- Политика `animation: 'none'` закреплена контрактом; менять только решением владельца
  и только после этапа 0 с цифрами.
- `console.warn('[BOOT] RootLayout render')` в `app/_layout.tsx` — в production лишний.
