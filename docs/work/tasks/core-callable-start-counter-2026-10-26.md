# Ядро · счётчик вызовов функций на старте [CALLABLE-START] (аудит холодного старта, п. 4)

Governance-ID: TG-01D227DDD968
Status: In progress
Owner: 1 · ЯДРО (координатор 26.10)

## Outcome
`[FS-READS]` видит только чтения Firestore. Сколько облачных функций зовёт старт, не знал никто (`docs/work/cold-start-audit-2026-10-26.md`, раздел 3).
Новая dev-перепись `[CALLABLE-START]` пишет сводки в 10, 30 и 60 с:
- каждая функция: сколько раз вызвана, сколько ок / ошибок, среднее и максимум мс;
- общее число вызовов.

По ней — цена на 1000 запусков и что отложить. Поведение приложения не меняется: только логи.

## Scope
In scope:
- `app/dev_callable_counter.ts` — чистая логика;
- `app/dev_callable_counter_boot.ts` — установка, только `__DEV__`;
- одна строка в `index.js` рядом с `[FS-READS]`;
- тест.

Out of scope: релиз (в стор-бандл не попадает, как `[FS-READS]`), правка вызовов.

## Architecture
Модуль функций не экспортирует свой класс. Поэтому в деве берётся прототип у экземпляра `getFunctions()` и оборачивается
`httpsCallable` / `httpsCallableFromUrl`: время, итог и код ошибки, ответ и ошибка возвращаются как были. Разные регионы
делят один прототип.

## Security and privacy
В журнал идут только имя функции, код итога и миллисекунды. Данные запроса и ответа не печатаются.

## Technical debt
Счётчик живёт только в деве, как `[FS-READS]`. Релизный замер — отдельной задачей, если понадобится.

## Verification
Тест: обёртка считает вызов, итог (ok / код ошибки) и мс, отдаёт ответ без изменений, пробрасывает ошибку; сводка по окну
времени; установка идемпотентна; точка входа закрыта `__DEV__` и подключена в `index.js`.

## Rollback
Удалить строку из `index.js`.
