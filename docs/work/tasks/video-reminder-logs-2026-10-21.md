# Task packet: подробные логи [VIDEO-REMINDER] для «Не удалось поставить напоминание» (вкладка «Видео»)

Governance-ID: TG-C045646DA230
Status: In progress

Related epic/enabler: багрепорт тестера 21.10 17:26 (iPhone, «Видео» → «Новое», окно «Не удалось поставить напоминание.»), поручение координатора

## Outcome

Правило «сперва логи, потом починка»: вся цепочка напоминания о премьере пишет в журнал префикс `[VIDEO-REMINDER]` — вход (id ролика, время старта, платформа), статус разрешения до/после запроса, итог общего тумблера уведомлений, аргументы и trigger планировщика (дата в будущем ли, формат), результат, каждый `catch` с полной ошибкой. Владелец или «Сверка» воспроизводят тап и по одному поиску находят причину. Успех измеряется тем, что по журналу однозначно видно, какая из трёх веток (`master_disabled`, `schedule_failed`, исключение) показала окно.

## Scope

In scope: `app/notifications.ts` (`scheduleYoutubePremiereLocalNotification` — убрать немой `catch`, логи), `app/youtube_premiere_notifications.ts` (`requestYoutubePremiereReminderFromTap`, `readStoredReminders`, зависимости по умолчанию), `app/lingman_videos.tsx` (`remind`: вход, итог, catch). Поведение и сигнатуры НЕ меняются, только трассировка.

Out of scope: починка причины (будет отдельным шагом по фактам из журнала), замена текста окна ошибки, изменение расписания/триггера, серверная часть.

## Architecture

No architecture change: те же функции и те же возвращаемые значения; добавляются только `console.warn` с префиксом на ранних выходах, ветвлениях и в `catch`. Данные для журнала не содержат персональных сведений: id ролика, канал, время старта, платформа, статус разрешения. Заголовок ролика в журнал не пишется (только длина).

## Security and privacy

Новых данных не собираем и не передаём: журнал остаётся на устройстве (консоль / `DebugLogger`). Название ролика не логируется (только длина), токены и uid не логируются. Privacy Policy не затрагивается.

## Technical debt

Pay now: немой `catch { return null; }` в `scheduleYoutubePremiereLocalNotification` и немой `catch { return [] }` в `readStoredReminders` получают лог причины (оставляем навсегда, как требует правило владельца). Contain: временная избыточная трассировка входа/выхода убирается после починки причины; ранние выходы и `catch` остаются.
