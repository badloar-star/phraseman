## 2. Рамки и как читать

Рамки владельца соблюдены во всех предложениях: без обводок-контейнеров (тонкие 1 px допустимы), без мелких подписей-расшифровок, без `adjustsFontSizeToFit`, цвета только из токенов темы, анимации только transform/opacity на UI-потоке, ничего тяжёлого (каждая приятность не добавляет View, картинки или JS-работу в кадрах), прогресс пользователей не трогаем. Усилие: S ≤ 1–2 часа, M до дня.

**Как просмотрено (честно).** Четыре помощника читали код по группам (A: Главная, профиль, настройки, оплата, онбординг, друзья, видео; B: уроки, Learning V2, диалоги, экзамены, ошибки; C: карточки, наборы, сообщество; D: Пик, окна, шторки, тосты, общие компоненты), раздел «Темы» дописали Темы. ## 5. Что НЕ делать (сведено по четырём группам)

- **Массовая замена** `TouchableOpacity` (80 файлов / 265) и сырого `Pressable` (265 файлов / 680) на `V2Pressable` одним заходом — большой выигрыш, но риск раскладки на каждом экране; только по экранам, отдельной задачей.
- **Stagger / layout-анимации на строках списков** (`FadeInDown` на каждую строку, `LayoutAnimation`, `layout={…}`) и на клетках `ActivityHeatmap365` — +Animated.View на строку, просадки на слабых Android; максимум один `FadeIn` на контейнер или первые 6–10 элементов.
- **Счёт чисел и таймер-кольцо через `setState`/`setInterval`** — только `AnimatedCountUpText`/shared value; кольцо оставить шагом 250 мс, пока нет перевода на `useAnimatedProps`.
- **Шиммер на мелких скелетонах** (Главная `pending`, «Загрузка…» шторки) — вечный цикл ради долей секунды; допустим один общий пульс на группу.
- **Pull-to-refresh на Главной и «Друзьях»** — данные догружаются стратегиями SWR; жест без TTL-кулдауна ≥ 60 с бьёт по чтениям Firestore. В каталоге сообщества — только с троттлингом.
- **Кнопки «Повторить» / экраны-ошибки** на пустых/офлайн состояниях видео и друзей — противоречит правилу владельца («экранов-ошибок нигде»); жест «потяни» достаточно.
- **Кнопки-действия в пассивных тостах** «серия сгорит» / «оплата не прошла» — решение координатора 04.10.
- **Хаптик на плитки, варианты ответов, чипы, строки `settings_language`** — запрещён правилом владельца; хаптик на ответ в Пике — только после слова владельца (звук Пика отдан Моментам 18.10).
- **Перелёт чипа слова (shared element) в сборке фразы** и анимированные переходы между шагами диагностики — измерения на JS и лишние View.
- **Полировать мёртвый код**: модалка «Титулы» в `home.tsx`, `HomeV2ContinueCard`, `HomeV2VideoRail`, `DayRings`, `shop.tsx`, `LearningV2Horizons`, `HorizonSessionResult`, `LearningV2TaskTopBar`, `FeedbackPlashka`, `CollectionLimitHeader`, `StatusFilterChips`, `FlashcardsShelves`, `FlashcardsCategoryBar/Tiles`, `UgcPackEditorCardPreview` — на них нет импортов (кандидаты на удаление отдельной задачей).
- **Свести `KitSheetModal` и `HybridSheetShell` в один компонент** сейчас — два разных механизма закрытия; выравнивать точечно.
- **Трогать** `CardPackShardPaywallModal`, начисления, лимиты, квоты — платёжные/экономические экраны вне задачи.
- **Возвращать подписи-расшифровки** («Требует отдельного подтверждения», «Показывается друзьям», subtitle в `lesson_help`/меню) — нарушают запрет; это вопрос их удаления (🟡), не приятностей.

#### Общие приятности через общий компонент
1. **`components/v2/V2Pressable.tsx` — нажатие при «Уменьшить движение»** (строка 51: `if (reduceMotion) { scale.setValue(1); return; }`). Сейчас у пользователей с reduce-motion нет вообще никакого визуального отклика на нажатие: ни масштаба, ни прозрачности. `PressableHybrid.tsx` в тех же условиях делает fade до 0.82 (`PRESS.reducedDownMs`). Правка: в ветке reduceMotion анимировать только `opacity` (до `KIT_PRESS_OPACITY_DOWN.toValue`) и не трогать scale. Выигрывают: все потребители V2Pressable — 59 файлов / 150 использований (весь Пик, V2Button — 31 вызов в 16 файлах, V2Card, V2Row, V2IconButton, V2AnswerOption, V2PillSwitch, V2SheetFrame…). Риск: минимальный (нативный драйвер, те же значения), для остальных пользователей поведение не меняется. Усилие S.
2. **`V2Pressable` — «плиточное» нажатие vs хаптик.** Дефолт `withHaptic = true` (строка 43) даёт вибро на любой тап и любую плитку, включая прокручиваемые списки (`SpireAllMembers`, строки V2Row) — при начале скролла по V2Pressable-строке срабатывает `onPressIn`. Правка в общем месте: для `V2Row`/`V2Card` (список-строки) по умолчанию `withHaptic={false}`, а у кнопок оставить как есть; плитки — точечно. Охват общей правки: V2Card (3 использования в 2 файлах) + V2Row (7 в 1 файле); остальное (150) решается точечно. Риск: поменяется ощущение тапа по карточкам, согласовать с владельцем. S.
3. **`components/v2/V2Kit.tsx` — `V2Button`** (строки 252-293): `loading` рисует системный `ActivityIndicator` и **нигде не используется (0 вызовов из 31)**; вместо него экраны делают `disabled={busy}` и кнопка становится серой. Правка: (а) заменить `ActivityIndicator` на `KitSpinner` (22 px, цвет `fg`); (б) в Пике (`SpireStepResultMoment`, `SpireWeekMomentHost`, `NoEnergySheet`) передать `loading={busy}`; (в) не вибрировать, пока `loading`. Выигрывают: 31 кнопка в 16 файлах (по мере перехода на `loading`). Риск: ширина кнопки меняется на время загрузки — зафиксировать `minWidth` на момент загрузки. S.

Правка: скопировать формулу. Выигрывают: 5 шторок (NotificationCenterButton, LessonReviewSheet, PhraseWorkshopTheorySheet, SpireNoEnergySheet, SpireLastChanceSheet).
