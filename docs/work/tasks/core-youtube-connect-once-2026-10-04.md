## Outcome
Шаг A (без нового секрета):
- Логи `[VIDEO-TRANSCRIPT]` на подключении: что ждём (внутренний id каталога, YouTube-id канала, название), что
  вернул Google (id и названия каналов выбранного аккаунта), откуда статус (вкладка / localStorage).
- Корень «Выбран другой канал»: админка сравнивала YouTube-id (`UC…`) с внутренним номером каталога
  (`channel-3`) — совпасть не могли никогда. Сверка теперь по `channel.youtubeChannelId`.
- Статус «подключён» и токен переживают закрытие вкладки (localStorage вместо sessionStorage) до истечения
  токена (~1 ч); показ «подключён ✓ (кем, когда)».
Факт подключения (YouTube-id, название, кто и когда) — документ `admin_youtube_connections/state` в Firestore без токенов: «подключён ✓ (кем, когда)» не пропадает после закрытия вкладки. Истёкший токен обновляется тихо: GIS prompt:"" + login_hint. Шаг B (серверный code-flow) отменён владельцем.

## Scope
Шаг A: только блок «Подключение каналов YouTube» в `admin/v2/legacy.html` (VP_YT_*), коммит своих кусков через
временный индекс — чужие правки «Шпиля» в этом файле не трогаются. Шаг B: восстановление
`functions/src/youtube_captions_oauth.ts`/`_core.ts` из fe0e733a0 с правкой сверки по channelId.

## Architecture
Шаг A — клиентский GIS как сейчас; ключ токена — внутренний id каталога (им же помечены ролики), сверка с
Google — по YouTube-id. Шаг B — как в fe0e733a0: state в Firestore, callback меняет code на refresh-токен,
коллекция `admin_youtube_channels` закрыта правилами (`if false` + исключение из админского catch-all).

## Security and privacy
Шаг A: access-токен (1 ч, scope youtube.force-ssl) лежит в localStorage браузера админа — только у
вошедшего админа, живёт до часа; в логи токены не пишутся. Шаг B убирает токен из браузера совсем.
Секрет OAuth-клиента не вводим — его ставит владелец.

## Technical debt
Шаг A не даёт «навсегда»: access-токен Google живёт ~1 ч, дальше повторный вход (без выбора канала, если
Google помнит аккаунт). Настоящее «один раз» — только шаг B.
