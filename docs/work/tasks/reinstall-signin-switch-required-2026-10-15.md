## Outcome

Ответ координатору: «переустановил → не могу войти в свой аккаунт» — НЕ блокировка, но лишний шаг у каждого переустановившего.
Правило (`app/auth_provider.ts`, ветка `anonymous_link_conflict`): Google-аккаунт уже существует
(`auth/credential-already-in-use`) → `isLocalAnonymousIdentityProvenCleanForCredentialHandoff` (`app/local_account_data.ts`) →
гость «не чист» и не «после смены» (`postCompletionHandoff=false`) → `account_switch_required`.
Журналы 15.10: у свежего гостя 23–26 «грязных» ключей, почти все — значения по умолчанию и служебные (аватар 1, рамка plain,
серия 1, дни активности, дата установки, энергия, unlocked_lessons=[1], лимит бесплатных уроков 3, время в приложении,
кэш привязки, отметка миграции, очередь outbox). Утренние входы r7b/r7g прошли только потому, что гость был «после смены».
Что видит человек: в онбординге — окно «Этот аккаунт уже есть в Phraseman» → «Войти в этот аккаунт» → вход продолжается сам;
из Настроек — шторка «Телефон уже связан с другим аккаунтом» → смена аккаунта.

Сопутствующее: строка А5 в «Результаты» плана беты (`beta-test-2026-10-15.md`).

## Scope

In scope: разбор правила, ответ координатору и Сверке, строка А5. Следующий шаг (после ДА): лог полного списка грязных ключей

## Architecture

Граница clean_proof защищает от смешения прогресса гостя A с аккаунтом B. Починка будет сужать понятие «прогресс» до настоящих
данных (уроки, сессии, карточки, монеты, покупки); значения по умолчанию и служебные следы не считаются. Ревью Opus обязательно.
