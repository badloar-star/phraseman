# Task packet: партнёрские ролики блогеров в модале «нет энергии» → полное восстановление за просмотр

Governance-ID: TG-0A7C705BC0FC
Status: Planned (ожидает утверждения владельцем)
Owner: сессия Claude / владелец
Related epic/enabler: нет

## Outcome

Появляется бартерный канал с блогерами: блогер рекламирует Phraseman у себя на
канале, взамен фрагмент его ролика крутится у нас в модале «энергия
закончилась». Бесплатный пользователь с нулём энергии видит третью кнопку —
«Посмотреть видео», смотрит ролик до отсечки, получает **полный бак энергии** с
анимацией заполнения.

Измеримый успех:
- в админке можно завести ролик, включить его, и он доезжает до телефонов;
- на телефоне кнопка появляется только когда ролик реально есть и включён;
- после досмотра энергия становится полной, анимация играет, повтор недоступен
  до следующих суток;
- в админке видно три числа на ролик (показы / досмотры / пропуски), чтобы
  отчитаться перед блогером.

Что НЕ является успехом: «файлы изменились». Пока кнопка не появилась на
реальном телефоне и энергия не заполнилась — задача не сделана.

## Решения владельца (зафиксированы 2026-09-21, менять только по его слову)

| Вопрос | Решение |
|---|---|
| Источник видео | **Только mp4.** YouTube отвергнут дословно: «не делаем ютуб» |
| Хранение | Оба: загрузка в наш Storage через админку **и** внешний URL |
| Плеер | Ставим `expo-video` сразу (в проекте плеера для mp4 НЕТ) |
| Награда | Полный бак, **1 раз в сутки** |
| Где играет | Отдельный полноэкранный экран, не внутри модала |
| Недосмотр | Ничего не даём, попытка не сгорает, можно начать заново |
| Кому показываем | Только бесплатным |
| Нет ролика / выключен | Кнопки просто нет |
| Доставка конфига | Один документ, кэш 6 часов |
| Сколько роликов | Несколько, и круг, и квоты, и веса — «всё это надо реализовать» |
| Статистика | Счётчики в админке (показы / досмотры / пропуски) |
| Карточка сделки | Да, минимум полей |
| Верификация досмотра | Телефон решает сам |
| Предохранитель расходов | Потолок показов в сутки на весь раздел |
| Текст письма блогерам | НЕ пишем в этой задаче |

## Scope

**В объёме:**

Новые файлы (клиент):
- `app/partner_video_contract.ts` — чистые типы и правила: форма ролика,
  выбор следующего по очереди (круг + веса + квоты), проверка «положен ли
  сегодня показ». Без React, покрывается тестом.
- `app/partner_video_config.ts` — чтение документа конфига, кэш 6 часов в
  AsyncStorage, `peek` для первого кадра (как в лигах).
- `app/partner_video_watch_state.ts` — durable-состояние на телефоне: когда
  последний раз получена награда, счётчик очереди, счётчик показов за сутки.
- `app/partner_video_reward.ts` — начисление полного бака + защита от
  двойного начисления (латч + operationId, как в `energy_shard_refill`).
- `app/partner_video_watch.tsx` — полноэкранный экран просмотра: `expo-video`,
  кружок обратного отсчёта в правом верхнем углу, превращается в «Пропустить»
  на заданной секунде.
- `components/energy/PartnerVideoCtaButton.tsx` — третья кнопка в модале.
- `components/energy/EnergyRefillCelebration.tsx` — анимация заполнения шкалы.

Правится:
- `components/NoEnergyModal.tsx` — добавить кнопку между «Получить Плюс» и
  «Восстановить за жемчужины». Всё остальное поведение не трогать.
- `storage.rules` — новый блок `/partner-videos/**`: публичное чтение, запись
  запрещена всем клиентам (заливает админка через Admin SDK, в обход правил).
- `firestore.rules` — новая коллекция, только чтение авторизованным.
- `package.json` — `expo-video`.

Новое (сервер / админка):
- `functions/src/admin_partner_videos.ts` — CRUD роликов и сделок, загрузка
  файла, инкремент счётчиков батчем.
- `admin/v2/legacy.html` — новая вкладка «Партнёрские ролики». **Только этот
  файл** — правило проекта.

**Вне объёма:**
- текст письма блогерам (владелец: «нет, только механика»);
- показ где-либо, кроме модала энергии;
- YouTube как источник;
- подробная аналитика по дням;
- серверная верификация досмотра.

## Architecture

**Текущая граница.** Энергия целиком клиентская: `energy_state_v2` в
AsyncStorage, `EnergyContext` раздаёт её экранам, `energy_shard_refill`
единственный существующий канал «купить полный бак». Модал `NoEnergyModal` —
единственная точка входа в пейвол энергии, 19 вызовов. Плеера для mp4 нет,
`YoutubeInlinePlayer` — WebView и к mp4 неприменим.

**Целевая граница.** Партнёрское видео становится **вторым каналом
восстановления**, зеркальным жемчужинам: тот же итог (полный бак), та же
защита от двойного начисления, та же клиентская авторитетность. Именно поэтому
награда переиспользует `createFullEnergyState`, а не изобретает свою запись.

Поток данных:

```
админка → Firestore doc config/partner_videos (один документ)
        → partner_video_config (кэш 6 ч, peek в первом кадре)
        → partner_video_contract.pickNext (круг/веса/квоты, чистая функция)
        → NoEnergyModal: кнопка есть или нет
        → partner_video_watch.tsx (expo-video, отсчёт)
        → partner_video_reward (полный бак + латч)
        → EnergyRefillCelebration (анимация на своём экране)
```

**Инварианты:**
1. Ролика нет / выключен / лимит суток исчерпан / награда уже взята сегодня →
   кнопки НЕТ. Мёртвых кнопок не бывает.
2. Награда начисляется ровно один раз за просмотр — латч плюс operationId.
3. Празднование НЕ durable (правило `feedback_no_durable_celebration_queues`):
   в хранилище едет энергия, а не «долг на показ». Анимация живёт на своём
   экране и пропущенная не стоит ничего.
4. Конфиг читается не чаще раза в 6 часов, фоновых таймеров нет.
5. Счётчик показов за сутки живёт на телефоне — ноль записей в Firestore за
   показ.

**Почему один документ, а не коллекция.** Роликов единицы, читают все.
Коллекция дала бы N чтений на человека; один документ — одно чтение раз в 6
часов. Та же модель, что у лиг.

## Security and privacy

- **Авторизация записи.** Ролики и сделки пишет только админ (custom claim
  `admin: true`), как остальные админ-функции. App Check не трогаем — он
  запломбирован навсегда.
- **Storage.** `/partner-videos/**`: `allow get: if true`, `list: false`,
  `write: false`. Файл заливает админка через Admin SDK в обход правил — та же
  модель, что у `course-packs` и `collectible-images`.
- **Внешние URL.** Ссылка от блогера — недоверенный ввод. Валидируем на
  сервере при сохранении: только `https:`, только расширение видео, длина
  ограничена. Плеер не исполняет JS (в отличие от WebView), поэтому
  поверхность атаки меньше, чем у нынешнего YouTube-плеера.
- **Персональные данные.** Контакт блогера — это данные **партнёра**, не
  пользователя, и они не покидают админку. На телефон едет только URL ролика.
  Пользовательских данных ролику не передаём: ни uid, ни имени, ни статистики.
  Внешний хост увидит только IP и User-Agent — как при любой загрузке картинки.
- **Privacy Policy.** Проверяется отдельно. Предварительно: собственный
  Storage политики не требует (мы уже так раздаём аудио и картинки). **Внешний
  URL — требует**: при проигрывании запрос уходит на чужой сервер, это
  раскрытие IP третьему лицу. Пункт про «сторонние хостинги видео» надо
  дописать ДО релиза, если вариант внешнего URL останется включённым.
  Помечено как 🔴 в итоге.
- **Детская безопасность.** Ролик увидит любой пользователь, включая детей.
  Модерация ручная: ролик появляется у людей только после явного включения
  владельцем в админке. Это и есть контроль, автоматического подхвата нет.

## Verification

Автоматические:
- `npx jest tests/partner_video_contract.test.ts --runInBand --watchman=false` —
  чистые правила: очередь по кругу, веса, квоты, «положен ли показ сегодня»,
  пустой список, выключенный ролик, исчерпанный суточный потолок.
- `npx jest tests/partner_video_reward.test.ts --runInBand --watchman=false` —
  награда ровно один раз; двойной тап не начисляет дважды; отказ откатывает.
- `npx jest tests/no_energy_modal_partner_cta_contract.test.ts` — сторож: нет
  ролика → кнопки НЕТ; платнику кнопки НЕТ.
- `npx tsc --noEmit` точечно по затронутым файлам.

Ручной прогон на эмуляторе (обязателен, зелёный tsc ≠ экран открывается):
1. Админка: завести ролик, включить, выставить секунду пропуска.
2. Телефон: сжечь энергию до нуля → открыть модал → кнопка видна.
3. Нажать → полноэкранный экран → кружок считает → на заданной секунде
   становится «Пропустить».
4. Досмотреть → анимация заполнения → энергия полная.
5. Снова сжечь энергию → кнопки НЕТ (лимит суток).
6. Выключить ролик в админке → после протухания кэша кнопки НЕТ.
7. Свернуть приложение на середине → вернуться → награды НЕТ, попытка не
   сгорела.
8. Оборвать сеть на середине → понятное сообщение, не чёрный экран.

Логи: единый префикс `[PARTNER-VIDEO]` на всю цепочку — вход, выбор ролика и
какое значение это решило, откуда пришёл конфиг (кэш или сеть), каждый ранний
`return`, каждый `catch` с причиной, финальный результат. Немого `catch {}` нет
нигде.

Артефакт: скриншоты шагов 2–4 и выдержка логов по префиксу.

## Rollback

Три уровня, от мягкого к жёсткому:

1. **Выключить ролики в админке** — кнопка исчезает у всех в течение 6 часов.
   Кода не трогаем, ничего не теряется. Это штатный выключатель.
2. **Потолок показов в 0** — мгновенно перекрывает расход трафика, не трогая
   сами ролики.
3. **Откат коммита** — кнопка исчезает сразу. Уже начисленная энергия
   остаётся у людей: она легла в обычное состояние энергии, отдельной записи
   про «видео» нет, поэтому откат не отбирает ничего выданного.

`expo-video` при откате остаётся в зависимостях до отдельной чистки — это
безопасно, неиспользуемый модуль ничего не делает.

Необратимых миграций нет.
