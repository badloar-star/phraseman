## Outcome

Владелец одобрил макет `docs/v2/mockups/35-new-ui-approved.html` и сказал
«подтверждаю, добавляй». Реализовать одобренное в приложении и проверить на
живом андроид-эмуляторе.

Наблюдаемый результат для пользователя:
1. «Восстановить покупки» — на экране Plus, виден всегда, даже без подписки.
2. Выход из аккаунта спрашивает подтверждение; без привязанной почты — первой
   кнопкой предлагает привязать её, а не выйти.
3. Тост ошибки несёт кнопку «Повторить» прямо в себе.
4. Отмена удаления показывает, сколько секунд осталось.
5. Плашка «нет интернета» при офлайне, без бесполезной кнопки обновления.
6. Поиск по урокам — кнопкой-лупой в существующем ряду чипов.
7. Pull-to-refresh там, где он стоит 0 чтений Firestore.
8. После занятия Learning V2 видно, на чём именно человек споткнулся.

Мера успеха: каждый пункт проверен на эмуляторе скриншотом или логом, а не
«по коду должно работать».

## Architecture

**Текущая граница.** Тост уже существует (`ActionToast.tsx`), слушает событие
`action_toast` через `app/events.ts`, имеет 5 тонов и хром по темам
(`themedToastChrome.ts`). Подписка читается авторитетно из RevenueCat
(`Purchases.getCustomerInfo`), экран `manage_subscription.tsx` уже импортирует
`Purchases`, `invalidatePremiumCache`, `emitAppEvent` и работает через
генерацию аккаунта (`isCurrentAccountGeneration`).

**Намеренная граница — расширяем существующее, не плодим второе:**
- кнопка в тосте — новое ОПЦИОНАЛЬНОЕ поле payload у `ActionToast`,
  второй очереди тостов не заводим;
- офлайн-плашка берёт состояние сети у того же источника, что
  `components/OfflineBanner.tsx` — второго детектора сети нет;
- подтверждение выхода — на `ThemedConfirmModal`/`CenteredDialogShell`,
  новой модалки не создаём;
- восстановление покупок идёт через уже настроенный RevenueCat и обязано
  уважать генерацию аккаунта: поздний ответ чужой генерации игнорируется
  (класс бага «подмена stable_id», память 25.08).

**Поток данных и стоимость.** Восстановление покупок — RevenueCat, 0 чтений
Firestore. Поиск — локальная фильтрация уже загруженного списка, 0 чтений.
Pull-to-refresh ставим ТОЛЬКО на экранах с локальными данными: пересчёт кэша,
0 чтений. Разбор ошибок читает журнал, который уже пишется локально.
Новых коллекций и полей в Firestore задача не создаёт.

**Инварианты:** без обводок вокруг блоков · без подписей-расшифровок мелким
шрифтом · без `adjustsFontSizeToFit` · анимации только transform/opacity ·
скелетон = геометрия финального кадра · Optimistic UI с откатом и защитой от
двойного тапа · логи на каждом раннем выходе и в каждом catch.

## Security and privacy

- **Восстановление покупок** не собирает новых данных: покупки и так привязаны
  к аккаунту магазина, RevenueCat уже подключён и уже используется на этом
  экране. Privacy Policy не меняется.
- **Ответ ученика в журнале ошибок** — новое сохраняемое поле, но это его
  собственный учебный ответ, хранится ЛОКАЛЬНО на устройстве, в Firestore не
  уходит. Политику это не затрагивает; если позже решим синхронизировать в
  облако — политику надо будет пересмотреть ДО релиза.
- Детских данных, новых разрешений и сторонних сервисов задача не добавляет.
- Секретов в коде нет; ключи RevenueCat уже живут в конфигурации.

## Technical debt

- **Скелеты в `components/ui/new/`** — *Pay now*. Либо доводим до рабочих и
  подключаем, либо удаляем. Оставлять неподключённый код нельзя: он гниёт.
- **Ответ ученика не хранится в журнале** — *Pay now* в рамках разбора ошибок:
  без него строка «ты написал» физически невозможна.
- **Светофор занят на момент старта** — *Contain*. Тяжёлое (tsc, jest, Metro,
  эмулятор) запускается только со слотом; если слота нет — делаю лёгкую часть
  и честно пишу в итоге, что проверка не прогонялась.
- **Темы за жемчуг** — *Contain*, отдельная сессия task_9f2164eb.

## Rollback

Задача идёт по частям, каждая часть — отдельный атомарный коммит в общую
рабочую ветку. Откат любой части — `git revert` её коммита; части независимы.

Данные не мигрируются: новое поле ответа в журнале добавляется как
необязательное, старые записи без него читаются как раньше. Выданные права
(Plus, покупки) задача не трогает — восстановление только ЧИТАЕТ состояние у
RevenueCat и не меняет его.

⚠️ Файлы Арены и Learning V2, занятые другими сессиями, не трогаются — значит
откат этой задачи не может задеть их работу.
