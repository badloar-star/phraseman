## Outcome

Владелец попросил третий аудит — с построением карты связей, потому что
предыдущие два шли «по подозрениям», а не по полной карте источников звука.
Карта немедленно выявила класс, который прошлые проходы не видели: экраны,
играющие аудио **в обход арбитра владения**.

Наблюдаемый результат: ни один источник звука в приложении не играет мимо
общего владения. Звук с такого экрана глушится при записи микрофона, уважает
тумблер голоса в настройках и сам останавливается, когда звук забирает другой
экран.

Мера успеха: карта не имеет разрывов; сторож перечисляет источники и падает,
когда появляется новый неподключённый.

## Architecture

Карта владения звуком (по фактам кода):

```
Пользовательские источники          Владение                 Потребители состояния
─────────────────────────           ────────                 ─────────────────────
use-audio.speak ─────────┐
phrase_audio_player ─────┤
SpeakingPanel (реплей) ──┼──► claimSpokenAudio ──┐
onboarding aha_audio ────┤                       │
learning-v2 session ─────┤                       ├──► audio_activity ──┬──► нативный режим сессии
managed_spoken_player ───┘                       │    (счётчики аренд)  ├──► sound_director → эффекты
                                                 │                      └──► выдача новых претензий
микрофон: SpeakingPanel ─┐                       │
speaking_hold_recorder ──┼──► claimRecordingAudio┘
ai_dialog, SpeechBeat ───┘

РАЗРЫВ (до этой правки):
mistake_detail ──────────► useAudioPlayer  ✗ мимо владения
mistake_practice_session ► useAudioPlayer  ✗ мимо владения (а рядом микрофон!)
```

Текущая граница: владение процессное, единственный вход — арбитр. Экран,
берущий `useAudioPlayer` напрямую, оказывается ВНЕ этой границы: его не глушит
запись микрофона, не останавливает тумблер голоса, и он не уступает звук
следующему экрану.

Интенция: каждый пользовательский источник звука входит в границу владения.
Для плееров на хуке это уже решённая задача — `useManagedSpokenAudioPlayer`,
который применяется на двух других экранах. Новый код не нужен, нужно
подключение.

Инвариант: играть звук мимо арбитра может только слой коротких UI-эффектов,
у которого своя, намеренно микшируемая дисциплина.

## Security and privacy

Правка усиливает приватность: звук больше не может зазвучать в динамик во время
записи микрофона на экране «Мои ошибки» и попасть в записываемый фрагмент.
Новых данных не собирается, прав не добавляется. Обновление privacy policy не
требуется.

## Technical debt

- **Pay now.** Два экрана ошибок подключить к владению через существующий хук.
- **Contain.** Сторож перечисляет источники звука и падает при появлении нового
  вне границы владения. Условие выхода: новый экран с озвучкой обязан либо
  использовать управляемый хук, либо быть внесён в список исключений осознанно.
- **Accept temporarily.** Оснастка замеров на физическом устройстве играет мимо
  владения. Владелец: сессия. Пересмотр: не требуется, пока это не
  пользовательский путь. Потолок влияния: нулевой в проде.
