## Outcome

Модуль `modules/story_events/` копит реальные факты о человеке как «истории»: итог недели в Шпиле (вверх/вниз/удержался + этаж),
рубеж серии, повышение ранга монеты, открытая ачивка — ровно четыре вида образца `docs/design/v2-app/stories-avatar.html` (s1–s3).
Дизайн получает `useStoryEvents() → { enabled, unseenCount, stories, playback, markSeen }` (playback — непросмотренные по времени, от старого к новому)
и рисует кольцо у аватарки, когда `unseenCount > 0`. Пока флаг `stories_v1` выключен, модуль ничего не пишет и не показывает.

## Architecture

Хранение только локально: AsyncStorage `story_events_v1:<stableId>`, на аккаунт. Событие живёт 7 дней, не больше 20 событий
(старые вытесняются). Повтор отсекается детерминированным ключом из типа и полезной нагрузки (неделя+язык, число дней+день, ранг,
id ачивки). Записи одного аккаунта идут последовательно (цепочка промисов), чтобы два события подряд не затёрли друг друга.
Флаг: `remote_config_cache_v1.bools.stories_v1` (по умолчанию выкл) + dev-переключатель `EXPO_PUBLIC_STORIES_DEV=1` только в __DEV__.
Подключения — `void recordStoryEvent(...)`: ничего не ждут, ошибок наружу не бросают, поведение исходных мест не меняется.
Празднование не durable (фундамент 01.09): храним факт с датой и отметкой «просмотрено», срок 7 дней — «долг на показ» не вечен.

## Security and privacy

Новых данных на сервер не уходит; ни одного чтения/записи Firestore. Локально — только типы фактов и числа (неделя, этаж, ранг, id ачивки).
Политику конфиденциальности не затрагивает: данные не покидают устройство.
