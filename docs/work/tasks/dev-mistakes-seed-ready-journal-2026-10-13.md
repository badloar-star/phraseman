# dev-подмена mistakes=demo засевает журнал ≥5 готовых ошибок (mistakes-panel-021)

Governance-ID: TG-78A878E9D6AA
Status: в работе
Owner: сессия «4 · ТЕМЫ 2.0» (поручение координатора: практика «Моих ошибок» требует ≥5 готовых ошибок, демо-снимок хаба даёт 2, сессия читает журнал)

## Outcome
`dev_state?mistakes=demo` кроме снимка хаба кладёт в настоящий журнал ошибок текущего одноразового гостя шесть готовых к практике ошибок (источник lesson_phrase), поэтому «Начать» → шторка → практика доходит до экрана практики с кнопкой `#mistake-practice-menu`, а не до «Готовых к разбору ошибок сейчас нет». В релизе подмена мертва.

## Scope
`app/dev_mistakes_demo.ts` (новая функция засева, вызов из `setDevMistakesDemo(true)` после проверки одноразового гостя), тест подмены, строка ссылки в `scripts/dev_links_r1_steps_errfix.py`. Runtime практики, экран практики и `dev_state_fixtures.ts` не меняются.

## Architecture
Засев идёт через публичный путь записи журнала `captureCurrentAccountObjectiveAttempt` (тот же код, что пишет ошибки урока): шесть попыток verdict `wrong`, objective, `lesson_phrase`, устойчивые attemptId (повторный запуск идемпотентен — запись уже есть, appended=false). Свежая запись по проекции сразу готова (dueAt = момент записи). Только `__DEV__ && !IS_STORE_RELEASE`, только одноразовый гость; лог `[DEV-STATE] mistakes seeded N ready (источник …)`.

## Security and privacy
Только dev-сборка и одноразовый гость; в релизе код не выполняется, пользовательские данные и облако не затрагиваются (журнал локальный, облачную синхронизацию событий гость не имеет).

## Technical debt
Демо-снимок хаба остаётся прежним (две готовые), а журнал даёт шесть — расхождение только в dev и только между хабом и практикой; приведение к одному источнику — отдельным шагом.

## Verification
Новый тест на подмену (засев в хранилище-заглушке, число готовых ≥5, идемпотентность, отказ в не-dev); тесты практики ошибок точечно; пересъёмка mistakes-panel-021 Сверкой.
