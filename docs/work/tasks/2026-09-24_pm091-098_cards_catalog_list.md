## Outcome

Владелец (дословно): «когда мы отмечаем наборы для тренировки... сделать удобное
чтобы мы отмечали удобно, не квадраты блоки здоровые, а типа удобно списочек...
если это карточки из видео, превьюшка видео с кнопочкой play».

Наблюдаемый результат: (1) выбор наборов для тренировки (DeckPickerSheet →
DeckSelectionTile) превращается из квадратных плиток 2-в-ряд в компактный список
строк — превью/иконка слева, название и счётчик карточек посередине, чекбокс
справа; длинные названия не ломают строку. (2) «Мои наборы» (flashcards_my_packs)
получают локальный поиск по названию и согласованную сортировку (по дате
изменения), сохранённую локально. (3) У раздела «Карточки» и его существующих
подразделов остаются/проверяются краткие описания (D20, прямое требование S64 —
НЕ путать с общим запретом CLAUDE.md на подписи-расшифровки: это осознанное
исключение владельца). (4) PM-091/PM-097 — проверка без переделки: базовый жест
просмотра/переворота карточки и нейтральные поля лицевой/оборотной стороны не
задеты соседними правками этой сессии (PM-058 жемчуг, PM-062 ауры и т.п.).

## Architecture

Текущая граница: DeckSelectionTile — чистый презентационный компонент, принимает
DeckSheetOption[] (из DeckPickerSheet.tsx) без сетевых вызовов и без записи
состояния. Изменение — только layout (flex row вместо квадратной плитки 48.5%
ширины), контракт props не меняется, родитель (DeckPickerSheet) не редактируется.

flashcards_my_packs.tsx уже читает данные локально (peekMyPacksGroups/loadMine);
поиск и сортировка добавляются как чистые client-side фильтры/компараторы над уже
загрученным `groups` — новых Firestore-чтений нет. Сортировка сохраняется в
AsyncStorage (новый маленький ключ, без миграции существующих данных).

## Security and privacy

Не применимо: изменения чисто клиентские, презентационные и локальные
(AsyncStorage-настройка сортировки). Новых полей профиля, сторонних сервисов,
разрешений или PII не добавляется.
