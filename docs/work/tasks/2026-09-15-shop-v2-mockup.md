## Outcome

Владелец видит предложенный магазин глазами пользователя и может принимать
решения по развилкам аудита, глядя на экран, а не на таблицу.

Требование владельца дословно: «изучи точно код приложения чтобы не предлагать
бред который не будет работать». Поэтому в макете у КАЖДОГО товара проставлен
честный статус реализуемости, сверенный с кодом:
ГОТОВО (механизм есть, нужна витрина) / ЛЕГКО (есть каркас) / НОВОЕ (писать
с нуля). Макет, показывающий нереализуемое, считается проваленным.

## Scope

In scope: новый файл `docs/v2/mockups/30-shop-v2.html`.

Наследует дизайн-систему `docs/v2/mockups/28-shop.html` (палитра, медальоны 52,
разделение тоном, док категорий) — магазин обязан выглядеть продолжением
кошелька рун, а не чужим экраном.

Out of scope: правка `app/shop.tsx`, `app/shop_catalog.ts`, цен в коде,
подключение магазина к навигации, закрытие дыры фарма. Макет ничего не
включает и не продаёт.

## Architecture

Архитектурных изменений нет — это статический HTML-документ вне бандла
приложения (папка `docs/`), Metro его не видит, на размер сборки и старт
не влияет.

Зафиксированные в макете факты кода (проверены чтением, не по памяти):
- `upgradeProfileCardLevel()` (`app/profile_card_system.ts:507`) — рабочая
  покупка «+10 энергии»; ей не хватает только витрины;
- `buyQuotaDayPass()` (`app/quota_day_pass.ts:46`) — рабочий дневной пропуск;
- `getCurrentRecoveryIntervalMs()` (`app/energy_system.ts:66`) берёт `Math.min`
  из override-ов → третий источник (покупка) добавляется одной строкой;
- `customization_purchase_intent.ts:31` уже знает `currency: 'pearls'|'runes'`,
  но за руны разрешён только `target === 'avatar'` (строка 92) — ауры за руны
  требуют снятия одного условия;
- траты рун идут только через `prepareCustomizationRunePurchase`
  (`app/level_spin_star_grants.ts:1201`) с `reason` из двух значений — под
  магазин нужен generic-путь;
- хранилища «купленных сценариев диалога» НЕТ → диалоги за руны = НОВОЕ.

## Security and privacy

Персональные данные не затрагиваются: в макете вымышленные балансы, ни uid,
ни имён. Новых сторонних сервисов, разрешений и полей профиля нет →
privacy policy правки НЕ требует.

Макет фиксирует границу «что нельзя продавать за руны» (красный список), то
есть работает на снижение риска каннибализации подписки, а не создаёт его.

## Technical debt

- **Pay now:** в макет НЕ попали товары, противоречащие коду и решениям
  владельца — «+1 матч Арены» и «+1 сессия ошибок» за валюту. Проверка
  показала: `QUOTA_POLICY` (`app/revenue_daily_quota.ts:79,87`) задаёт им
  `passKind: null` осознанно (решение владельца 2026-09-14: «вторая
  покупаемая валюта на том же действии путала бы экономику»). Эти позиции
  вынесены в открытые вопросы, а не нарисованы как готовые.
- **Contain:** статусы ГОТОВО/ЛЕГКО/НОВОЕ живут в макете рядом с товаром —
  если при реализации статус окажется другим, расхождение видно сразу.
  Exit condition: при переносе каталога в код статусы удаляются.
- **Accept temporarily:** макет дублирует цены из
  `SHOP_CATALOG_PROPOSAL_2026-09-15.ru.md`. Владелец, ревью — при утверждении
  цен; тогда источником станет код, а оба документа станут историей.
