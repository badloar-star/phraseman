# DEV_LINKS_R1 — как добраться до состояния (Дизайн, 12.10)

Строки реестра `release=r1`, `status=pending|diff`. Для каждой — готовая ссылка (`dev_state`, `premium_modal?…&_dev_state=…`, `next=…`) или ручной путь, плюс что сделать перед кадром. Источники: реестр, `R1_SHOT_LIST*.md`, `app/dev_state_fixtures.ts`, `app/dev_paywall_state.ts`. Ссылки подобраны по названию состояния — если кадр не тот, смотри колонку «shot list» (точный путь тапами).

## Правила перед КАЖДЫМ кадром

1. `adb shell am force-stop app.phraseman` → запуск → дождаться «DEV-STATE OK» (экран `dev-state-done`).
2. Ссылка начинается с `phraseman://dev_state?` и всегда содержит `onboarding=done&intros=seen` (**новое**: `intros=seen` помечает все окна знакомства с разделами показанными — не нужно жать «Позже» на каждом экране; `intros=reset` вернёт их).
3. Окна и тосты прошлого кадра: перед новым состоянием пейвола очередь блокирующих окон очищается сама (6bdba4d26). Для остальных — force-stop.
4. Свойства аккаунта: `plus=on|off` (Plus), `free=on` (без dev-Plus), `energy=0..5`, `cards=demo` (64 сохранённые, 4 набора), `catalog=demo|empty`, `quota=N|exhausted|reset`, `dquota=N|reset`. Снимать перепробованные фикстуры значением `off`/`reset`.
5. VIP-плашка и план подписки (`vip=`, `plan=`) читаются при старте: после ссылки force-stop → запуск.
6. Тема кадра: тёмная «Аврора» (Спокойно), если в строке не сказано иное.
7. Колонка «тапы» — шаги после открытия ссылки (грамматика — `scripts/parity_steps.mjs`: `tap:#testID`, `tap:Текст`, `long:`, `swipe-left:`, `type:`, `back`, `wait:`); их выполняет робот `scripts/parity_batch_shoot.mjs` через `uiautomator dump`. Колонка «уникальна»: **да** — ссылка+шаги открывают ровно этот кадр (робот берёт только такие); **нет** — ссылка общая с соседями или путь не выведен, снимать руками по shot list. `cards=empty` очищает сохранённые/свои карточки и наборы (пустые кадры); `cards=demo` и `cards=empty` сбрасывают масштаб сетки и режим «стопка».

8. ⚠️ **Фикстуры `cards=demo|demo_lessons|empty|custom50|demo_published|notranslation` пишут в синхронизируемые ключи карточек и наборов** (облачная синхронизация и Account V2) — поэтому работают ТОЛЬКО на анонимном госте (`pm clear` → онбординг) и отказываются на аккаунте с Google/Apple (лог `[DEV-STATE] cards=… refused: real account`). Тестовые аккаунты №2/№3 для Карточек не использовать.
