# Вес приложения: картинки в сборке — план на после выпуска (18.10)

Запрос владельца: приложение около 30 МБ. Задача от Координатора: только анализ, ничего не переносить.
Автор: сессия «Моменты». Метод: чтение кода и файлов, без сборки.

## 1. Что реально попадает в сборку

- `assets/images` — 11,8 МБ на диске (323 файла). Цифра «14 МБ» — это `du` с учётом блоков файловой системы.
- В нативную сборку Metro кладёт только картинки, на которые есть `require(...)` в достижимом коде. `assetPatternsToBeBundled` в `app.json` и `MINIMAL_OTA_ASSET_PATTERNS` в `app.config.js` относятся к обновлениям по воздуху, на размер магазинной сборки не влияют.
- По `require` найдено 423 ссылки (одинарные и двойные кавычки, по нескольку на строку — сгенерированный реестр `components/theme/themed_art_assets.generated.ts`).

| | МБ | Файлов |
|---|---:|---:|
| Картинки с `require` (идут в сборку) | **8,89** | 274 |
| Без `require` (в сборку не идут) | 2,94 | 49 |

Без `require`, то есть в сборку не идут:
- значки приложения: `ios-icon.png` 652 КБ, `android-icon-foreground.png` 398 КБ, `icon.png` 290 КБ, `splash-icon.png` 120 КБ — из них нативная сборка генерирует свои иконки (п. 4);
- `v2art/review/**` (~1,0 МБ) — макеты для сверки;
- `level-spin-rewards/*` (0,28 МБ), `learning_v2_map/*` (0,10 МБ), часть `home_last_lesson/*` — мёртвые файлы.

Чистка репозитория от мёртвых файлов размер сборки не меняет.

## 3. Кандидаты в облако с кэшем на диске

Образец — карточки коллекции: `collectible_image_url_map` + `.easignore` (сэкономило 71 МБ). Каждой вынесенной картинке нужен запасной вид без сети.

| Группа | Из сборки, МБ | Почему можно | Запасной вид без сети |
|---|---:|---|---|
| Сцены первого входа `intro_*` | **2,97** | Не первый экран; показываются по одному разу при первом заходе в раздел; можно качать только текущую тему (dark или light) и только при первом заходе. | Уже есть: если сцены нет, `FeatureIntroModal` показывает стадию «семья / значок» (`showScene=false` → `family` / `icon`). Окно и тексты работают как сейчас. |
| Значки рангов Пика | 0 | Весят 1,0 МБ только из-за разрешения; после пережатия (п. 4) это ~45 КБ — в облако выносить незачем. | — |
| Монеты рангов | 0 | Нужны мгновенно и всем рангам: в списках друзей и Пика видны чужие монеты; без сети пустой кружок вместо монеты хуже. | — (оставить в сборке, пережать) |
| Плитки Главной | 0 | Первый экран: без сети и на холодном старте должны быть сразу. | — (оставить, пережать) |

## 4. Пережать без видимой потери

Оценка: байты webp растут примерно как площадь^0,75. Точные цифры даст прогон `cwebp -q 80 -resize …`.

| Группа | Сейчас | Предлагаемо | Было, МБ | Станет ≈, МБ | Экономия ≈, МБ |
|---|---|---|---:|---:|---:|
| Значки рангов Пика | 1024² | 128² (25 dp × 4 = 100 px с запасом), q80 | 1,00 | 0,05 | **0,95** |
| Плитки Главной | 1024² | 512² (до 160 dp × 3), q80 | 1,26 | 0,44 | **0,82** |
| Монеты рангов | 768² | 512² q80; для церемонии (до 240 dp) — отдельная 768-версия текущего ранга из облака с запасным видом 512 | 1,93 | 1,05 | **0,88** |
| Сцены первого входа (если НЕ выносить в облако) | 1536×1024 | 1320×880 (440 dp × 3), q80 | 2,97 | 2,23 | 0,74 |
| `ios-icon.png` (нативная иконка iOS 1024², ложится в каталог ресурсов как есть) | PNG 652 КБ | pngquant / oxipng без смены вида | 0,64 | ~0,20 | **0,44** |
| `android-icon-foreground.png`, `icon.png`, `splash-icon.png` | PNG | pngquant; Android сам режет mipmap — эффект на сборку меньше размера файла | 0,79 | — | 0,1–0,3 |

## 6. Важно для цели «≈ 30 МБ»

- Картинки — не главный вес. В `assets/audio` 626 МБ, в сборку идёт стартовый набор озвучки V2; его урезание до 5 сессий ведёт Ядро — это решение владельца «звук V2 не в бандле».
- Остальное в `assets`: `sounds` 3,0 МБ, `daily_phrase_packs` 2,1 МБ, шрифты 1,8 МБ.
- Код JS и нативные библиотеки — отдельная статья, её меряет Ядро по `.aab` / `.ipa`.
- Мёртвые файлы (п. 1, ~1,4 МБ) на сборку не влияют, но их стоит удалить из репозитория, чтобы следующий подсчёт не путал.

## 7. Риски и порядок (после выпуска)

1. **Сначала пережатие** (п. 4): без сети и без нового кода, вид не меняется. Проверка — кадры Сверки на 3 экранах; значки 25 dp особенно на 3x.
2. **Потом сцены в облако:**
   - карта `intro_*` → URL по образцу `collectible_image_url_map`;
   - скачивание при первом заходе в раздел с таймаутом;
   - кэш на диске;
   - строки `.easignore`;
   - журнал `[INTRO-ART] origin=cloud|cache|fallback` — уже есть `[INTRO-ART]` с `origin`.
3. 💸 **Firebase / хранилище:** 14 сцен × 2 темы ≈ 3 МБ разово на пользователя, только при первом заходе в раздел, дальше — кэш. Отдавать с CDN хранилища с долгим `Cache-Control`; Firestore не нужен.
