# Task packet: Настройки — имя прошлого аккаунта не остаётся у гостя после выхода (утечка, прогон 18.10)

Governance-ID: TG-E4DEEF785FBF
Status: В работе
Owner: 5 · АВТОРИЗАЦИЯ

## Outcome

После выхода из аккаунта (и любой смены владельца) карточка профиля в Настройках не показывает имя прежнего аккаунта:
у гостя — «Профиль», у нового аккаунта — его имя. Защита «пустое имя из снимка не затирает загруженное» действует
только внутри одного владельца.

## Scope

- app/(tabs)/settings.tsx: состояние userName помнит владельца (stableId) и сбрасывается при смене владельца.

## Architecture

Факт (эмулятор 18.10 11:24–11:29, logcat): выход из №3 → владелец 143aa86c; `[SETTINGS-NAME] storage storedPresent=false`,
`snapshot snapshotPresent=false currentPresent=true decision=kept_previous` → гость видит «Максим2» (имя №3) в карточке
профиля, хотя «Аккаунт» показывает «Не задано». Вкладка Настроек смонтирована и пережила смену владельца; эффект снимка
сохранял `current`, если снимок пуст. Правка: userNameOwnerRef — чей это ник; пустое хранилище/снимок при другом
владельце → сброс ('' → «Профиль»), решение пишется в [SETTINGS-NAME] (cleared_foreign).

## Security and privacy

Закрывает показ имени одного аккаунта другому пользователю устройства. Журнал — без имён.

## Technical debt

Прочие поля карточки (ранг/монеты) берутся из своих снимков с отслеживанием поколения — не трогаю.

## Verification

Точечные тесты settings (контракт) через светофор; эмулятор: вход → выход → Настройки = «Профиль».
