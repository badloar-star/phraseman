# Task packet: сервер Шпиля не отклоняет пройденное по времени

Governance-ID: TG-EDBC79BB5F1C

## Outcome
Владелец (2026-09-24): «сервер идёт нахуй с самого начала, никакого сервера, сервер только для синхронизации». Прямое указание — сервер `spireReportSteps` НЕ должен отклонять уже пройденную на телефоне ступень по признакам скорости (`too_fast`) или частоты (`rate_limited`): локальный прогресс на устройстве всегда авторитетен, сервер только синхронизирует его в общий рейтинг.

## Scope
In scope: `functions/src/spire_progress_contract.ts` — убрать ветки `too_fast`/`rate_limited` из `evaluateSpireReportBatch` (или как называется функция реально в файле), не удаляя типы `SpireReportRejectReason` целиком (оставить как диагностику/на будущее, если понадобится показать админу).
Out of scope: остальные причины отказа (`overlap`, `stale_week`, `clock_ahead`, `pack_mismatch`, `malformed`) — они про целостность данных (битый/повторный/будущий отчёт), не про «слишком быстро прошёл», их не трогаем.

## Architecture
Сервер остаётся источником агрегата для рейтинга комнаты, но перестаёт быть судьёй «правда/неправда» по времени прохождения. Комментарий в коде фиксирует прямую цитату владельца как причину.

## Security and privacy
Риск накрутки рейтинга вырос (теоретически можно слать быстрые пачки). Владелец решение принял осознанно, ответил явно на прямой вопрос об этом риске («Убираю этот отказ вовсе»). Остаток защиты: overlap (ступени не могут идти быстрее, чем длится ступень + допуск), pack_mismatch (отпечаток пакета должен совпадать — нельзя послать выдуманные задания).
