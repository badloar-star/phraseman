## Outcome

Дизайн подключает три окна Пика без «хозяина». Ядро даёт решение «когда показывать» по договору `SpirePositionMoments`:
- **rise** — после своей ступени человек пересёк линию зоны повышения (зона стала `up`);
- **overtake** — между двумя загрузками комнаты место ухудшилось, хотя сам человек не откатился. Не чаще раза за сессию;
- **lastChance** — воскресенье после 18:00 местного, неделя ещё идёт, человек ниже линии повышения (зона не `up`). Раз в неделю.

## Architecture

Источник данных — только то, что экран Пика уже держит: отсортированные строки комнаты `useSpireGame().rows`, rankBy, weekId, время загрузки комнаты (`room.fetchedAtMs`), энергия из `useEnergy`. Зоны считаются той же функцией `spireZonesFor`, что экран «Все участники»: окно не может противоречить списку.

1. **rise** — переход зоны не-`up` → `up` между двумя строками одной недели при собственном росте (ступени или монеты).
   - Это событие, а не состояние: пометка «показано» живёт в памяти.
2. **overtake** — позиция `{weekId, fetchedAtMs, place, steps, coins}` хранится на устройстве (1 ключ на uid+язык).
   - Новая загрузка комнаты (другой fetchedAtMs той же недели) с худшим местом при неубывших своих ступенях и монетах → окно.
   - Соперник — строка прямо надо мной.
   - Флаг «раз в сессию» — в памяти процесса.
3. **lastChance** — пометка «показано на неделе W» хранится на устройстве.
   - Конец недели = понедельник 00:00 UTC.
   - Если местное воскресенье 18:00 уже после конца недели (пояса западнее UTC−6), окна нет — с логом.
   - gapCoins (только режим монет) = монеты последнего в зоне `up` − мои; зоны `up` нет → поля нет.
4. Празднование не durable (фундамент владельца): непоказанное не копится, решение пересчитывается по текущим данным. Хранятся только пометки «уже показано» и последняя виденная позиция.
