## Outcome

Владелец: «модал удаления аккаунта почему-то на весь экран, должен быть маленький
аккуратный». Наблюдаемый результат — окно подтверждения удаления занимает высоту
собственного содержимого (заголовок «Вы уверены?», подпись, поле ввода слова,
два действия), центрировано, не растягивается на весь экран. Мера успеха: на
телефоне окно ощутимо ниже экрана; при этом на маленьком экране/с клавиатурой
контент остаётся достижимым (скролл внутри, кнопки видны).

## Architecture

Текущая граница: модалка передавала `fillAvailableHeight` в `HybridAlertShell`,
что ставит `flex:1` на обёртку и панель → панель всегда во весь доступный экран.
Проп был оправдан, когда внутри жил длинный список удаляемых данных; сейчас этот
блок отключён (`{false && …}`), контента осталось ~200 px, и растяжка стала
чистым дефектом.

Намеренная граница: модалка — обычный hybrid-алерт. Шелл сам даёт
`maxHeight: '100%'` и скролл; панель высотой по содержимому. Внутренний
`ScrollView` модалки остаётся (клавиатура/мелкие экраны), но без `flex:1` —
он сжимается по контенту и растёт только до потолка.

Клавиатура: `KeyboardAvoidingView` требует растянутой родительской цепочки
(`flex:1` до самого верха) — ровно того, что делало окно полноэкранным.
Убрали его из гибрид-ветки целиком; подъём над клавиатурой теперь делает
`HybridAlertShell` через `paddingBottom = keyboardInset` (тот же механизм,
что и для остальных гибрид-модалок с собственным `ScrollView`). Чтобы не
включать этот отступ по умолчанию для ВСЕХ вызывающих (три из них держат свой
`KeyboardAvoidingView` и получили бы двойной подъём), добавлен явный проп
`avoidKeyboard`, включённый только в `DeleteAccountConfirmModal`.

Инвариант: поле ввода и обе кнопки достижимы при любой высоте экрана и с
поднятой клавиатурой.

## Security and privacy

Правка чисто визуальная: высота контейнера. Не затрагивает аутентификацию,
данные пользователя, удаление, отправку чего-либо наружу. Текст об удалении и
предупреждения не меняются, поэтому Privacy Policy править не нужно.

## Verification

Владелец 2026-09-22 запретил запуск jest и тяжёлых проверок на этом ПК, поэтому
верификация — статическая (чтение кода) плюс ручная проверка на телефоне.

Статически сверено в этой сессии:
- в модалке не осталось `fillAvailableHeight` (ни в коде, ни в комментариях) и
  `flex: 1` во вьюпортах панели/её ScrollView — растяжка на весь экран
  невозможна;
- `hybridDialog` несёт `maxHeight: '100%'`, `hybridScrollViewport` —
  `flexShrink: 1`: контент не обрезается на коротком экране;
- `scrollContent={false}` + `avoidKeyboard` у шелла — вложенного второго
  ScrollView нет, а клавиатурный отступ (`paddingBottom = keyboardInset`)
  включён явно для этой модалки;
- у трёх других вызывающих `HybridAlertShell` со `scrollContent={false}` и
  собственным `KeyboardAvoidingView` (`CertificateNameModal`, `ReportPackModal`,
  `ReportUserModal`) `avoidKeyboard` НЕ передан — их клавиатурное поведение не
  изменилось (условие `avoidKeyboard || scrollContent` совпадает со старым
  `scrollContent` при отсутствии нового пропа);
- обработчики удаления (`handleConfirmDelete`, `beginAccountDeletion`, звук,
  трассировка, порядок закрытия) не изменены ни в одной строке;
- баланс скобок (`(`/`)`, `{`/`}`) во всех трёх изменённых файлах проверен
  построчным подсчётом — 0 расхождений;
- сторожи, ссылающиеся на модалку, перечитаны: актуализирован только
  `account_delete_modal_layout_contract` (он охранял устаревшую растяжку),
  `responsive_screen_reachability` остаётся зелёным — дефолтное поведение
  шелла (`fillAvailableHeight`) не тронуто.
