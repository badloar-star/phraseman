# Ядро · храповик `as any` считает по индексу коммита, а не по рабочему дереву (25.10)

Governance-ID: TG-F72EE0D1CFE8

## Outcome
Блокер коммитов (сообщили Темы через координатора): pre-commit `scripts/guard_as_any_ratchet.mjs` считает `as any` по
РАБОЧЕМУ ДЕРЕВУ (171 против 169 в baseline), поэтому чужие незакоммиченные правки (рост — в components/paywall/
PaywallPlusScreen.tsx, правка другой сессии) блокируют коммиты всех сессий. Нужно считать то, что уходит в коммит.

## Scope
scripts/guard_as_any_ratchet.mjs: источник содержимого — git-индекс (`git ls-files` + `git cat-file --batch` по `:path`). Индекс
берётся из окружения: safe_commit запускает pre-commit с `GIT_INDEX_FILE` своего временного индекса (HEAD + пути коммита),
обычный `git commit` — с обычным индексом. Флаг `--worktree` — прежний режим для ручной проверки. `--update` — по индексу.
PaywallPlusScreen.tsx не моя (в этой сессии не правился) — не трогаю, сообщаю координатору.

## Architecture
Один вызов `git ls-files -z -- app components modules` и один процесс `git cat-file --batch` на все файлы (без процесса на файл).
Фильтры (тесты, authoring-исходники Learning V2) и подсчёт (stripNoise + /\bas\s+any\b/) не меняются. В выводе — режим счёта.

## Security and privacy
Не затрагивается.

## Technical debt
Рост в рабочем дереве у других сессий теперь не виден до их коммита — это правильно: каждый отвечает за свой коммит. Ручной
обзор всего дерева — `--worktree`.

## Verification
На текущем состоянии: по индексу ≤ baseline (169), по `--worktree` — 171 (как у координатора). Проверка с временным индексом
(HEAD + чужой файл) показывает рост — сторож по-прежнему ловит свой коммит.

## Rollback
Откат коммита — возврат к счёту по рабочему дереву.
