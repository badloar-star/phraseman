# Аудит: что добавить в «Пульт управления» (Control Panel)

Дата: 2026-06-14 · Аудит read-only (приложение `app/` + админка `admin/index.html` + сервер `functions/`).
Цель: список инструментов для «Пульта», отсортированный по ценности и стоимости внедрения.

## Главный критерий отбора
В «Пульт» имеет смысл выносить **живые рычаги** — то, что меняет приложение у пользователей **без релиза**. Стоимость внедрения делит всё на 3 класса:

- **🟢 Класс A — только запись в Firestore** (мгновенно, без передеплоя). Самые дешёвые победы.
- **🟡 Класс B — нужен передеплой Cloud Functions** (мигрировать хардкод-константу в Firestore-док). Разовая работа на фичу.
- **🔴 Класс C — нужен релиз/пересборка клиента** (env-флаг или хардкод в приложении). Дорого, но часть критична для «выключателей».

## Что в Пульте уже есть
Тумблер lifetime, хаб-ссылки: Remote Config, Paywall A/B, App-сообщения, Alerts, Push. (Сделано 2026-06-14.)

## Главные находки (контекст)
1. **Серверного Remote Config почти нет.** Единственный живой Firestore-тюнинг на сервере — `admin_runtime_config` (модель и квоты ИИ-диалога), и у него **нет UI в админке**. Всё остальное на сервере — хардкод (передеплой) или env.
2. **App Check — только env** (`callable_options.ts:8`), переключается передеплоем, НЕ кнопкой. Платные OpenAI-функции зовутся без аттестации.
3. **Нет «режима обслуживания» / глобального баннера / форс-апдейта** — ни на клиенте, ни на сервере. Это заметная дыра для управления инцидентами.
4. **Дрейф админки vs клиент:** в `RC_BOOL_FIELDS` нет `collectibles_enabled` (есть в клиенте); в `RC_NUMBER_FIELDS` нет `arena_sr_win/loss/bot_win`, `arena_season_rollback_steps`, `onboarding_green_pct` — хотя клиент их читает. Их нельзя крутить из админки СЕЙЧАС, хотя механизм готов.
5. **Дубли математики клиент↔сервер** (арена SR/ранг): менять надо в ДВУХ местах; кандидат на централизацию.

## СПИСОК ИНСТРУМЕНТОВ (по приоритету)

### 🥇 Приоритет 1 — дешёво и сразу (🟢 Класс A: только запись/уже готово на бэке)

1. **Грант/отзыв Premium и VIP прямо в Пульте.**
   Сейчас: спрятано в модалке вкладки Users. Запись в `users/{uid}.progress.vip_*` уже работает; CF `vipRevokeMine` есть. Вынести поиск юзера + кнопки «выдать на 1/3/12 мес / навсегда» и «снять» в Пульт.
   Польза: частая операция (диаспора, поддержка), сейчас неудобно. Стоимость: только UI.

2. **Управление ИИ-диалогом: модель + дневные лимиты (free/premium).**
   Бэкенд УЖЕ живой: CF `openAiDialogModelConfig` + `openAiDialogQuotaConfig` пишут `admin_runtime_config` (`openai_dialog_model_config.ts`). **UI в админке нет вообще.** Добавить: выбор модели из `ALLOWED_DIALOG_MODELS` + два числа (free=3/premium=100, потолок 10000).
   Польза: прямой контроль расходов OpenAI без релиза. Стоимость: только UI к готовым CF. **Лучшее соотношение польза/цена.**

3. **Достроить Remote Config до полного набора (закрыть дрейф).**
   Добавить в админские массивы недостающие ключи, которые клиент уже читает:
   - bool: `collectibles_enabled` (kill-switch «Сокровищницы»).
   - числа: `arena_sr_win` (25), `arena_sr_loss` (20), `arena_sr_bot_win` (12), `arena_season_rollback_steps` (3), `onboarding_green_pct` (A/B цвета онбординга), `arena_shard_refill_slots` (5), `energy_recovery_interval_ms`, `free_trainer_sessions_per_day`.
   Польза: эти рычаги уже живые в клиенте, но недоступны из админки. Стоимость: правка 2 массивов в `admin/index.html`. (Бонус: вынести экономику/лимиты в Пульт как «быстрый блок».)

4. **Аварийные kill-switch фич (уже есть в клиенте) — крупными тумблерами в Пульте.**
   `speaking_enabled`, `collectibles_enabled`, `referral_enabled`, `league_xp_promotion_enabled` + сам `lifetime_button_enabled`. Все читаются клиентом через onSnapshot. Сейчас разбросаны в Remote Config мелким списком — собрать в Пульт как «рубильники фич».
   Польза: экстренно гасить сломавшуюся фичу за секунды. Стоимость: только UI (значения уже есть).

5. **Модерация UGC (паки сообщества) — ссылка/действия в Пульт.**
   CF `communityModerateSubmission` / `communityAdminModeratePack` уже админ-вызываемые. Добавить хаб-ссылку (как для Remote Config). Стоимость: ссылка.

### 🥈 Приоритет 2 — высокая ценность, нужен передеплой CF (🟡 Класс B)

6. **🚨 Режим обслуживания / глобальный баннер / мягкий форс-апдейт.**
   Сейчас НЕТ нигде. Это самый важный отсутствующий инструмент управления инцидентами.
   Реализация: новый bool `maintenance_mode` + текст в `remote_config/app`; клиент читает и показывает блок-экран/баннер; (опц.) `min_supported_build` → мягкое «обнови приложение». Тумблер — в Пульт.
   Польза: один рубильник на случай инцидента/поломки платежей/срочного объявления. Стоимость: клиентский экран + чтение флага (релиз клиента, но делается один раз и навсегда).

7. **Управление моделями/лимитами для weekly_review, stats_insights, explain_phrase.**
   Сейчас хардкод (`weekly_review.ts:45`, `stats_insights.ts:60`, `explain/explain_budget.ts`). Диалог уже тюнится — распространить тот же паттерн `admin_runtime_config` на эти 3 функции (модель + дневные капы).
   Польза: полный контроль расходов OpenAI. Стоимость: передеплой CF (паттерн уже есть, копируется).

8. **Server-side kill-switch для платных ИИ-функций.**
   Сейчас сервер не читает ни одного «enabled»-флага для AI. Добавить чтение `remote_config/app` (или `admin_runtime_config`) в explain/dialog/weekly/stats → тумблеры в Пульт. (Частичный обход уже сегодня: поставить дневной кап диалога = 0.)
   Польза: мгновенно отkey платную фичу при всплеске расходов/абьюзе. Стоимость: разовый передеплой + чтение флага.

9. **Тюнинг арены/экономики, перенесённый в Firestore (с устранением дублей).**
   Арена SR/ранг-математика и сезон сейчас хардкод И продублированы клиент↔сервер (`arena_season.ts:25-29`, `arena_rank_progression.ts`; зеркала в `app/arena_season_math.ts`). Высокая ценность + высокий риск рассинхрона → кандидат №1 на централизацию в Firestore-док, читаемый обеими сторонами.
   Также хардкод-экономика для тюнинга: бусты лиги (`league_group_boosts.ts`), сундук лиги (`league_chest.ts`), реролл задач (`daily_tasks.ts`), кулдауны подарков (`friend_gifts.ts`), шанс дропа премиум-паков (8%). Стоимость: передеплой + (для дублей) единый источник правды.

### 🥉 Приоритет 3 — полезно, но требует релиза клиента (🔴 Класс C)

10. **Промоутнуть env-флаги в Firestore-флаги (чтобы крутить без пересборки QA):**
    `ai_dialog_enabled` + `free_dialogs_per_day` (`ai_dialog_flags.ts`), `explain_enabled` (`explain_phrase_flags.ts`), `screen_transitions`, `ranked_wager_enabled`/`bot_fallback_enabled` (`config.ts`). Сейчас меняются только пересборкой.
    Польза: A/B и аварийное выключение без релиза. Стоимость: перенести чтение из env в remote_flags (релиз клиента).

11. **Тайминги вовлечения/уведомлений как Firestore-числа:**
    часы недельного рекапа/D1-напоминания, тихие часы, кулдауны (`notifications.ts`), окно «старой цены» пейвола, `trial_reoffer_cooldown` (90 дней, `premium_trial_eligibility.ts`), `EXIT_TRIAL_CONTEXTS` (где показывать exit-триал).
    Польза: оптимизация ретеншна/конверсии без релиза. Стоимость: релиз клиента (перенос хардкода в remote_flags).

12. **Тайминги бот-матчей арены** (`BOT_FALLBACK_MIN/MAX_MS` 8–40с, окно accept 15с — синхронизировать с CF). Польза: тюнинг «ощущения» матчмейкинга. Стоимость: релиз клиента (+ согласование с сервером).

## Рекомендованный порядок работ
1. Сначала весь **Приоритет 1** (только UI/готовый бэк): гранты premium/VIP, UI диалог-модели+квот, достроить Remote Config, рубильники фич, ссылка на UGC-модерацию. Это закрывает дрейф и даёт реальный контроль почти бесплатно.
2. Затем **№6 (режим обслуживания)** — самый ценный отсутствующий инструмент.
3. Далее по необходимости — Приоритет 2 (расходы OpenAI, kill-switch AI, централизация арены), потом Приоритет 3.

## Чего НЕ выносить в Пульт
Аналитика/read-only (Overview, Analytics, OpenAI budget, App Health, Archive, Audit, Ops-log) и контент-вкладки (паки, фразы дня) — оставить как есть; Пульт = только живые рычаги.

> Связанные памятки: App Check off (`phraseman_app_check_disabled_prod`), дубли арена-ранга (`phraseman_arena_rank_duplicate_math`), сервер-аудит (`phraseman_server_audit`), кнопка lifetime (`phraseman_lifetime_button_paywalls`).
