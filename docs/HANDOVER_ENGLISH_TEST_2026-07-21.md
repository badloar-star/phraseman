## Ключевые факты об устройстве страницы (проверено в этой сессии)

- Исходники: `knowly-www/english-level-test/` — `index.html` (1215 байт), `app.js`, `engine.js`, `certificate.js`, `styles.css`, `data/`.
- `index.html` — это пустая оболочка: `<main id="app">` + три script-тега (`engine.js`, `certificate.js`, `app.js`). **Вся разметка рендерится из `app.js`.** Строки «Пройти тест» в index.html нет и не должно быть.
- Живой `https://knowlyapps.com/english-level-test/` отдаёт БАЙТ-В-БАЙТ тот же index.html, что локальный (проверено curl). То есть HTML на сервере актуальный.
- **Service worker НЕ используется** (проверено grep).
- **У script/link-тегов в index.html НЕТ cache-busting query** (`./app.js`, `./styles.css` — без `?v=`). Это главная гипотеза бага №1: телефон держит в кэше СТАРЫЙ `app.js` со старым лендингом. На десктопе владелец, видимо, обновлял сильнее / кэш был свежее.

## Гипотезы и направление исправления

### Баг 1 (легаси на телефоне)
- **Гипотеза A (главная):** устаревший кэш JS/CSS на телефоне. Фикс: добавить версионный query ко ВСЕМ локальным ресурсам в `index.html` (например `./app.js?v=20260721-2`, `./styles.css?v=...`, `./engine.js?v=...`, `./certificate.js?v=...`) и сделать это привычкой на каждый деплой (лучше — маленький скрипт/шаг, который поднимает версию). Проверить также cache-заголовки в `firebase.json` для target `knowlywww` — для `english-level-test/*.js` разумно `Cache-Control: no-cache` или короткий max-age (HTML — no-cache обязательно).
- **Гипотеза B:** в `app.js` есть ветка по User-Agent/ширине экрана, которая на мобильных рендерит другой (старый) шаблон. Прочитать `app.js` целиком и искать `matchMedia`, `innerWidth`, `userAgent`, `mobile`.
- Проверить A первой — она дешевле и объясняет «на десктопе новое, на телефоне старое».
- После фикса на живом сайте убедиться: `curl -s https://knowlyapps.com/english-level-test/ | grep 'app.js?v='`.

### Баг 2 (подсветка прошлого ответа)
- Искать в `app.js`/`engine.js` состояние выбранного ответа (selectedIndex / selectedChoice / lastAnswer и т.п.), которое не сбрасывается при рендере следующего вопроса. Фикс: сбрасывать выбор на каждый новый вопрос; класс `correct/selected` навешивать только на ответ ТЕКУЩЕГО вопроса.
- Не сломать подсветку правильного/неправильного после выбора (если она есть по дизайну) — сброс только при ПЕРЕХОДЕ к следующему вопросу.

### Баг 3 (скачать сертификат → 404 на iPhone)
- Читать `certificate.js`: найти, что происходит по нажатию «Скачать». Типичная причина на iOS Safari: `window.open(blobUrl)` или `window.open(dataUrl)` — iOS трактует это как навигацию и показывает «страница не найдена»; так же ломается `<a href="data:...">` навигацией.
- Рабочий паттерн для iOS: сгенерировать изображение (canvas → `toBlob`), создать objectURL, и в ТОМ ЖЕ обработчике жеста программно кликнуть реальный `<a href={objectURL} download="certificate.png">`. Не `window.open`, не `location.href`, не навигация.
- Запасной UX для iOS (рекомендуется добавить): показать сгенерированный сертификат картинкой прямо на экране с подсказкой «зажми изображение, чтобы сохранить» — на iPhone это самый надёжный путь.
- Проверить, что по пути, куда ведёт кнопка сейчас, реально нет страницы (404.html в корне knowly-www — это общий фолбэк, его показ подтверждает, что шла НАВИГАЦИЯ, а не скачивание).
