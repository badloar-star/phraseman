## 1. Замер: что поставлено и как снять

Хук `usePerfR1Probe(screen)` (`app/perf_r1_probe.ts`) стоит в корне **Главной** (`home`), **списка Уроков** (`lessons`), **хаба Карточек** (`cards_hub`). В релизе и стор-сборке это пустая функция без единого React-хука (владелец 22.09: тело горячего экрана — чистое); в dev пишет в Metro три возможные строки на заход:

```
[PERF-R1] {"screen":"home","stage":"first_frame","ms":…,"commits":…}   — от первого рендера корня до первого кадра после коммита
[PERF-R1] {"screen":"home","stage":"commits_3s","commits":…,"ms":…}   — сколько раз корень перерисовался за первые 3 с
[PERF-R1] {"screen":"home","stage":"left_early","commits":…,"ms":…}    — экран закрыли раньше 3 с
```

Считаются **коммиты** (`useEffect` без зависимостей), а не вызовы `render`: в dev-StrictMode render зовётся дважды, коммит — один раз. Для Главной уже есть собственные метки `[HOME-RENDER]` (`homeFirstRenderStartedAt` / `homeFirstPassiveStartedAt`, сторож `home_render_timing_log_contract`) — они остаются и читаются вместе.

**Просьба Сверке (очередь):** холодный старт, гость, Главная → Уроки → Карточки; по 3 захода на экран; в Metro-журнале выбрать `[PERF-R1]` и `[HOME-RENDER]`; приложить строки в `INBOX`. Ориентиры для решения: `first_frame` ≲ 300 мс, `commits_3s` ≲ 6 для Главной / Уроков и ≲ 4 для хаба. Что выше — берём из таблицы M/L ниже в порядке цены/эффекта.

### Окно +2…+4 с и решение по `inlineRequires` (Дизайн, координатор 13.10)

Разбор `summary_cold1-3.txt`: окна +1,0…+4,5 с во всех трёх прогонах заняты `loadModuleImplementation` на 100 % (собственное время 2546 / 2364 / 2331 мс) — это исполнение тел модулей бандла при старте, а **не** первый коммит Главной: React-коммит (`completeRoot`, `react-stack-bottom-frame`) начинается только с +4,5…+5,5 с. Причина по конфигу сборщика (`metro.config.js:56`): `inlineRequires` включается только переменной `PHRASEMAN_INLINE_REQUIRES=1` (по умолчанию выключен), поэтому все статические `import` исполняются сразу.

**Решение координатора 13.10: до сборки R1 флаг НЕ включаем** — за три дня до сборки это риск порядка инициализации модулей (побочные эффекты на уровне модуля), в релизе JS лежит байткодом (dev-цифра завышена), а сравнительный прогон требует перезапуска общего сборщика и сорвёт ночную съёмку.

- [ ] **После R1: замер с `PHRASEMAN_INLINE_REQUIRES=1`, затем решение.** Сравнить на одном устройстве: `loadModuleImplementation` (сумма мс за холодный старт) и время первого кадра Главной с флагом и без; смотреть, не сломался ли порядок инициализации (журналы `[LESSONS-BOOT]`, `[COLD-START-IO]`). Базовая цифра для сравнения — 2,3–2,5 с в dev, релизная цифра снимается в день сборки (`adb shell am start -W` ×5 на release-сборке).
