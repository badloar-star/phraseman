### 1.4 Блокировка старых клиентов
- **Есть (клиентская):** `force_update_enabled` + `min_app_version` (`app/remote_flags.ts:55-59,145-147,296,336,612-614`), сравнение `isVersionBelow` (`:676`), решение `shouldForceUpdate` (`:709`), экран `components/ForceUpdateGate.tsx:153-161`, подключён в `app/_layout.tsx:3148`. Дефолт выкл; пустой/мусорный `min_app_version` = не блокировать.
- Ограничения: (1) работает только в билдах, где гейт уже есть — добавлен коммитом `580782611` от 2026-06-21; доля активных установок старше — **unknown**; (2) подхват до 6 ч кэша `remote_config` (`remote_config_client.ts:35`); (3) это самоблокировка клиента — сервер ничего не проверяет.
- **Серверный min-version gate: `missing`.** Ни один callable не сверяет версию клиента; правила Firestore не мешают старому клиенту писать старые поля.

### 1.5 Точки необратимости
1. **`everEnabled`** — ставится при первом включении любого серверного флага, сервер не снимает (`accounts_v2_flags.ts:85-95`). Следствие: удаление аккаунта навсегда стирает `accounts_v2/{uid}/**`. Вручную не снимать (runbook 6A). Это не потеря данных, а необратимость настройки.
2. **Выкладка функций с 7A/7C/7E** — после неё откат функций только вперёд (см. 1.3).
3. **Первая запись V2 в форме хранения** — смена формы позже требует миграции (`accounts_v2_apply_core.ts:123-128`).
4. **Удаление аккаунта, этап `v2_purged`** — для конкретного человека необратимо (`accounts_v2_deletion/deletion_flow.ts:391-392,443-453`); это нормально.
5. **Чистка старых данных (OD20, 30 дней, по команде владельца)** — **не реализована**: `legacyCleanupPaths` для реальных отчётов возвращает `[]` (`functions/src/accounts_v2_migration/report.ts:258-259`). Настоящей точки purge сейчас нет.

## 7. T1 — план блокировки старых версий при релизе 2.0 (Пакет 8F, 2026-10-01)

Что выставляет **владелец** (ядро и исполнители прод не трогают) и в каком порядке.

| Шаг | Где | Значение | Что даёт |
|---|---|---|---|
| 0. Сейчас | — | `force_update_enabled=false`, `min_app_version=''`, `config/accounts_v2.minClientVersion` нет | поведение не меняется |
| 1. Выкладка функций 2.0 (OD18) | деплой | функции с 8F (поле `clientVersion`, проверка минимума) — **раньше клиента** | новый клиент шлёт `clientVersion`; старые функции его бы отвергли (`request_unknown_field`) |
| 2. Релиз сборки 2.0 в сторах | сторы | номер сборки N (Android `versionCode` = iOS `buildNumber`; сейчас 130 → 2.0 больше) | — |
| 3. После того как сборка 2.0 доступна в обоих сторах | `remote_config/app` | `min_app_version` = версия 2.0 (строка `x.y.z`), `force_update_enabled=true`; затем `refreshRemoteConfigNow` или ждать до 6 ч кэша | старые сборки (с гейтом обновления, от `580782611`) показывают экран обновления |
| 4. Одновременно с шагом 3 | `config/accounts_v2` | `minClientVersion` = N (номер сборки 2.0, целое) | сервер V2 отвечает `client_too_old` всем, кто ниже N или без поля (≈ сборки до 8F); такая сборка останавливает V2 (как «сервер выключен»), старая синхронизация у неё работает дальше |
| 5. Проверка на 3 аккаунтах владельца (OD24) | — | — | — |
| 6. Только после 3–5 | `remote_config/app` | `accounts_v2_legacy_sync_disabled=true` (Пакет 7B) | старая синхронизация V2-доменов выключается у новых клиентов |

Почему так: шаг 6 без шагов 3–4 оставляет старые телефоны писать карточки в старое облако, которое V2 после переноса больше не читает (E2E J). Сборки ДО гейта обновления (`580782611`, 2026-06-21) экран обновления не покажут — их доля неизвестна (unknown), для них остаётся только серверный отказ V2 (шаг 4) и то, что старое облако живо (OD20, 30 дней).

Откат: `minClientVersion` удалить или 0 (действует в течение ≤ 5 мин — кэш флагов на инстансе); `force_update_enabled=false`.

**T5 — версия формы хранения V2 (правило выкладки, Пакет 8F).** Записи `accounts_v2/**` читаются строгим кодеком (`accounts_v2_store.ts` → `stored_state_corrupt` на незнакомой форме). Код «читать N и N+1» нельзя добавить заранее — форма N+1 ещё не известна; а поле версии формы в записи само было бы сменой формы. Поэтому правило: любая смена формы хранения — **две выкладки**: (1) функции, которые ЧИТАЮТ старую и новую форму, но ПИШУТ старую; дождаться, пока все инстансы обновятся (и закрыть окно отката на версию до шага 1); (2) функции, которые пишут новую форму. Откат после шага 2 — только на версию шага 1 (не старее). Так уже вышло с 7C (`titles`): первая выкладка V2 обязана включать 7C, откат функций V2 — только вперёд.
