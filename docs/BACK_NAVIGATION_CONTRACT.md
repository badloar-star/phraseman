# Back navigation contract

Владелец, 2026-08-13: кнопка Back не имеет права открывать экран ранее
посещённого чужого раздела.

## Инварианты

1. Back с дочернего экрана возвращает только на непосредственный предыдущий
   экран той же непрерывной ветки.
2. Back с корня раздела ведёт на Главную.
3. Если предыдущая запись принадлежит другому разделу, она отбрасывается и
   используется явный fallback экрана.
4. Общие экраны (`paywall`, магазин жемчуга, подарки, достижения, настройки
   обучения, AI/MAX-сессии и другие порталы) наследуют раздел точки входа.
5. Неизвестный новый маршрут работает fail-closed: чужую историю не наследует.
6. Экранная кнопка и Android hardware Back используют один и тот же guard.
7. Production-код не вызывает `router.back()` напрямую.

## Реестр

Источник истины — `app/navigation_back.ts`:

- `SECTION_ROOTS` — жёсткие границы разделов;
- `fixedChildSection()` — однозначные дочерние семейства;
- `CONTEXTUAL_PORTAL_PATHS` — многоисточниковые экраны;
- `TRANSIENT_REDIRECT_PATHS` — технические redirect-маршруты;
- `SCREEN_OWNED_ANDROID_BACK_PATHS` — экраны с собственным подтверждением или
  внутренним Back-состоянием.

Каждый production-экран из корневого `<Stack>` обязан быть классифицирован.
Это проверяет `tests/navigation_back_underlay_contract.test.ts`; новый экран без
политики ломает тест. Поведенческие сценарии веток и параметризованных экранов
проверяет `tests/navigation_back.test.ts`.

## Аудит обходных путей

Разрешены только детерминированные `dismissTo` на заранее вычисленную цель:

- возврат из открытого набора карточек к точному экрану происхождения;
- возврат из урока в параметризованный список уроков;
- закрытие турнирного потока на Главную.

Все общие и экранные Back-вызовы проходят через `safeRouterBack()` или
`dismissPaywallModal()`.
