## 0. Что такое «зависание» в React Native (модель)

В RN весь UI-код (логика, рендер, обработка тапов) крутится на **одном JS-потоке**, а анимации/жесты Reanimated — на **UI-потоке**. Отсюда три физически разных вида «заморозки»:

1. **JS-поток заблокирован** — бесконечный цикл, тяжёлая синхронная работа, шторм `setState`. Всё мёртвое: ни тапов, ни скролла. Самый страшный вид.
2. **UI-поток заблокирован** — бесконечный worklet/`useAnimatedReaction`-петля или флуд `runOnJS` из пер-кадрового worklet. Анимации/касания умирают.
3. **«Мягкая» заморозка** — поток жив, но юзер заперт: модалка без кнопки закрытия, заставка не уходит, кнопки выхода заблокированы флагом загрузки, который не сбросился. С точки зрения юзера — то же зависание.

Аудит прошёлся по всем трём. **Хорошая новость наперёд:** грубых JS-/UI-петель в проде нет. Реальная проблема одна — «мягкая» (вход в онбординге). Остальное — условные риски и джанк.

## 2. Подтверждённые находки (детали)

### 🔴 H-ENTER — вход в онбординге запирает все кнопки на промисе без таймаута

**Где:** `components/onboarding.tsx:2753` (`handleSignIn`) + `app/auth_provider.ts` (`signInWithProvider`).

```tsx
// onboarding.tsx
const handleSignIn = async (provider) => {
  setLoadingProvider(provider);
  try {
    const result = await signInWithProvider(provider);  // ← может висеть вечно
    setLoadingProvider(null);
    ...
  } catch { setLoadingProvider(null); }
};
const handleLater = async () => {
  if (authBusy || loadingProvider) return;   // ← скип тоже мёртв, пока loadingProvider стоит
  ...
};
const interactionLocked = loadingProvider !== null || authBusy;  // блокирует ВСЕ кнопки
```

`setLoadingProvider(null)` достигается **только если промис разрешился/отклонился**. А внутри `signInWithProvider` — серия Firestore-await **без таймаута** (проверено грепом по `auth_provider.ts`):

- `auth.signInWithCredential(credential)` (`:692`) — голый await
- `linkRef.get()` (`:720`) — голое чтение Firestore
- `db.runTransaction(...)` (`:760`)
- `syncToCloud({ forceNow: true })` (`:961`), `restoreFromCloud()` (`:996/1056/1079`)

`withTimeout` в файле **есть** (`:396`) и обёрнут только нативный Google-пикер (`:431`, 30с) и одно `.get()` (`:356`). Но обмен credential + вся секция линка/мерджа/восстановления **после** возврата пикера — без таймаута.

**Триггер:** юзер тапнул Google/Apple, выбрал аккаунт, и ровно в этот момент пропала сеть (или Firestore завис). `loadingProvider` залипает → `interactionLocked` навсегда true → и кнопки входа, и «Позже» неактивны.
**Выход:** в приложении нет. Только перезапуск.
**Безопасная мера (не внесена):** обернуть `signInWithProvider` (или хотя бы его пост-credential Firestore-секцию) общим таймаутом; в `handleSignIn` добавить страховку-watchdog, чтобы «Позже» не могла залипнуть неактивной.

### ⚠️ H-VIPCHURN / H-ARBITER / H-TOASTQ — условные

- **H-VIPCHURN** (`components/PremiumContext.tsx:188-295`, deps `[isPremium, …]`): не бесконечная петля (спасает `vipSnapshotStateRef`-гард на line 257), но на каждом реальном переходе premium/VIP `onSnapshot` отписывается и переподписывается; вместе с инлайновым `value={{...}}` (line 412) бьёт ре-рендером по всем `usePremium()`. Лечение: вынести `isPremium`/`isVip` в ref внутри эффекта-листенера, убрать из deps; обернуть Provider value в `useMemo`.
- **H-ARBITER + H-TOASTQ** (`components/OverlayArbiter.tsx`, `components/AchievementContext.tsx`): один оверлей-слот, непреемптивно. Если модалка-владелец не сбросит свой `ownState`, нижние тосты/алерты голодают; `showingRef` тоста-достижения залипает true → достижения копятся, не показываются, до перезапуска. Срабатывает только при стечении (сначала залипнуть должно другое окно). Лечение: watchdog force-release слота через N секунд в `OverlayArbiterProvider` + TTL-фоллбэк авто-дисмисса в `AchievementContext`.

### ⚠️ H-PAYSCROLL — пейвол перерисовывается на каждом кадре скролла

`components/paywall/paywallShared.tsx:165` (`useStickyCta`, на `paywall_b`/`paywall_c`): `onScroll → setScrollY(...)` — обычный JS-`setState` на каждое событие скролла (`scrollEventThrottle={32}` ≈ 30×/с) перерисовывает всё дерево пейвола. Не намертво (скролл конечен, `setScrollY` хранит число → React бэйлит на одинаковом y), но джанк/дропы кадров на слабом Android. Лечение: гнать `scrollY` как Reanimated shared value + `useAnimatedReaction` → `runOnJS(setVisible)` только на смене булева (идиома уже используется в `StatScoreRing`).
