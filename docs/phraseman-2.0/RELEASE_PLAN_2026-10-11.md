# План выпуска PhraseMan 2.0 — сроки и ускорение сверки (координатор, 11.10.2026)

Приказ владельца 11.10: «исправить немедленно, план как ускорить и сделать правильно, дать работу нужным сессиям, точные сроки».

## Узкое место
Ворота «приложение = макет»: 860 строк реестра (`registries/visual_parity.json`): match 6 · pending 724 · diff 110 · removed_by_owner 18 · blocked 1 · no_mockup 1. Из них 298 строк с анимацией.
Почему медленно: снимки делались руками по одному. Один эмулятор работал то как камера, то как место проверки. Сборщик и эмулятор падали. Экраны перекрашивались в стиль «Тень» уже ПОСЛЕ съёмки, и снимки приходилось переснимать.

## Как ускоряем (5 решений)
1. **Робот-съёмка.** Сессия «Эмулятор» пишет сценарии Maestro (`.maestro/parity/<макет>.yaml`), по одному на файл макета. Сценарий проходит состояния и после каждого вызывает `node scripts/parity_shot.mjs shot|anim <id>`. Человек не тыкает: склейка «макет | приложение» появляется сама.
2. **Конвейер без простоя.** Эмулятор только снимает. Сверка смотрит готовые склейки (эмулятор ей не нужен) и ставит match или diff с точным списком отличий. Работают параллельно.
3. **Сначала «Тень», потом съёмка.** Дизайн отдаёт группу экранов в новом стиле, и только тогда робот её снимает. Пересъёмок нет.
4. **Замечания чинят 3 сессии сразу:** Дизайн (основные экраны), Темы (themes/coins/цвета), Авторизация (profile — 26 diff, вход/аккаунт). Сразу после правки строка уходит на пересъёмку.
5. **Отличия «как задумано» закрываются правкой макета (сессия 3), а не «принято»:** Б3/Б6 энергии, Free=50 и т. п.

Инфраструктура: сборщик с лимитом 6 ГБ под сторожем `metro_watch.sh`, приложение берёт бандл через localhost (`set_debug_host.sh`). `pm clear` запрещён без повторной настройки. Один tsc на ПК, jest --maxWorkers=1.
