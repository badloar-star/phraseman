## Architecture

Решение (совет ревьюеров: «хранить state строкой JSON»): вся пользовательская структура хранится ТОЛЬКО как канонические JSON-строки (`stateJson`, `idJson` и т.п.), а не как вложенные объекты Firestore. `JSON.stringify` экранирует одиночные суррогаты и управляющие символы, поэтому Firestore видит только валидные строки; исчезают проблемы вложенных массивов, глубины 20, запрещённых имён полей, длины имён, количества индексных записей (плюс адаптеру — исключение индексов для строкового поля). Размер хранимого состояния считается по формуле Firestore (байты UTF-8 строки + 1) с запасом ≤ 900 КБ. Сервер перестаёт быть строже клиента к id и ключам: отклонения из-за хранения удаляются (id хэшируются, значения экранируются); остаются лимиты конверта клиента. Это закрывает P1-1 без изменения принятого клиента.

## Security and privacy

Ключи документов — хэши; пользовательские строки только внутри JSON-строк; JSON.parse результат копируется в объекты с собственными ключами (defineProperty), прототип не подменяется. Данных не логируем.
