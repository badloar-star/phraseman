# Home Hint Studio — дизайн

Дата: 2026-09-14  
Статус: дизайн утверждён владельцем, ожидает письменного просмотра перед планом реализации.

## Цель

Добавить на домашний экран короткую дружелюбную подсказку с тем же мягким пульсом,
который уже используется у карточки результатов. При каждом новом входе на главную
показывается следующая опубликованная подсказка; после конца очереди начинается круг
заново. Подсказка должна быть короткой, лёгкой и иногда шутливой, но не обещать
неподтверждённые возможности или выгоды.

Владелец готовит 300 смысловых идей. Для каждой идеи редактор содержит три русских
варианта. В приложение попадают только выбранные владельцем идеи/варианты. Переводы
на остальные поддерживаемые языки добавляются позднее только для одобренных записей.

## Контекст существующего приложения

- Текущий текст подсказки и локали находятся в `components/LangContext.tsx`.
- Домашняя карточка результатов и текущий пульс находятся в `app/(tabs)/home.tsx`.
- Единственная рабочая админка — `admin/v2/legacy.html`.
- Существующий Remote Config применяется без релиза, но его не следует превращать в
  большой массив контента: 300 записей неудобны для поиска, аудита и частичной публикации.

## Рекомендуемая архитектура

Используется отдельный контентный снимок, а не большой текстовый Remote Config:

1. Админка читает каталог черновиков и отображает фильтры.
2. Владелец выбирает один из трёх вариантов каждой идеи и отмечает записи для публикации.
3. Админская callable-функция валидирует вход, права и размер набора, записывает новую
   версию опубликованного снимка и журналирует действие.
4. Приложение при запуске/возврате на главную читает опубликованный снимок, сохраняет
   безопасный локальный кэш и выбирает следующий элемент очереди.
5. При недоступной сети остаётся последняя валидная версия; приложение не падает и не
   заменяет её пустым или частично повреждённым ответом.

Публикация считается мгновенной с точки зрения владельца: после успешного ответа
админской функции новый снимок доступен клиентам при следующем запуске/возврате на
главную согласно существующей политике кэша. В UI показываются номер версии, время
публикации и результат валидации.

## Модель записи

Черновой документ:

```ts
type HomeHintDraft = {
  id: string;
  category: HomeHintCategory;
  variantsRu: [string, string, string];
  audience: 'all' | 'free' | 'plus';
  factStatus: 'verified' | 'needs_owner_confirmation' | 'copy_only';
  factSource?: string;
  ownerNote?: string;
  selectedVariantIndex?: 0 | 1 | 2;
  status: 'draft' | 'approved' | 'published' | 'paused';
  updatedAtMs: number;
};
```

Категории покрывают домашний экран и существующие механики: результаты/статистика,
уроки, диалоги, карточки, энергия/жемчужины, видео, Plus, лига, рефералы, арена,
настройки/идеи, серия и ежедневные занятия. Категория не даёт права утверждать факт:
каждый фактический текст обязан иметь источник в коде или документации.

Опубликованный снимок содержит только записи со статусом `published`, выбранным
вариантом и валидной аудиторией. Русский текст является источником до отдельного
этапа локализации. Для клиента без перевода публикуется безопасный fallback текущей
локали, а не русская строка поверх интерфейса другой локали.

## Каталог админки (вариант A)

Добавить отдельный раздел в `admin/v2/legacy.html` в стиле существующей тёмной панели:

- верхняя строка: число всего / одобрено / опубликовано / выбрано к отправке;
- поиск по тексту и фильтры по категории, аудитории, factStatus и статусу;
- компактная карточка идеи с тремя вариантами, радиовыбором одного варианта и чекбоксом
  «в публикацию»;
- рядом с фактической подсказкой видны источник и метка проверки;
- предпросмотр ограниченной ширины показывает, как строка будет выглядеть под карточкой
  результатов;
- кнопка `Отправить выбранные` отключена при нулевом выборе, а перед записью показывает
  количество записей и список предупреждений;
- после публикации показываются версия, время, число записей и ссылка на журнал аудита.

UI-правила: интерактивная зона не меньше 44px, заметный focus-state, управление с
клавиатуры, контраст текста не ниже 4.5:1, `prefers-reduced-motion` для предпросмотра
пульса и отсутствие визуального шума в каталоге.

## Ротация в приложении

- Очередь строится отдельно для `all`, `free` и `plus`; запись `all` доступна обоим
  сегментам, специализированная — только своему сегменту.
- На входе/возврате на главную выбирается следующий id, а не случайный текст: это даёт
  предсказуемый круг и позволяет не повторять подсказку до конца очереди.
- Текущий индекс/версия хранятся локально. Если опубликованная версия изменилась,
  индекс безопасно нормализуется по длине новой очереди.
- Повторный вход в тот же экран без нового foreground-события не должен бесконечно
  менять подсказку.
- Пульс использует уже существующий motion-паттерн и должен отключаться при системном
  `reduceMotion`.
- Тап по подсказке не превращает текст в неподтверждённую навигацию: кликабельным
  остаётся существующий блок результатов, а подсказка сохраняет роль поясняющего текста.

## Фактическая дисциплина контента

Перед генерацией 300 идей составляется таблица механик. Для каждой идеи фиксируются:

- точное утверждение;
- файл/документ-источник;
- аудитория;
- допустимый CTA, если он существует;
- что нельзя обещать.

Фразы про цену Plus, ускорение восстановления энергии, награды, лиги, рун, арену,
рефералов и доступность функций публикуются только после проверки соответствующих
контрактов. Юмор может менять подачу, но не числовой факт, условие доступа или результат
действия. Идеи со статусом `needs_owner_confirmation` остаются в редакторе и не могут
попасть в опубликованный снимок.

## Безопасность и контракты

- Публикация только через существующий админский callable-паттерн с custom claim
  `admin: true` и аудитом; App Check не включать без отдельного распоряжения владельца.
- Публичный клиент читает только опубликованный снимок; черновики, заметки и источники
  не выдаются обычному пользователю.
- Новая коллекция/поля требуют Firestore Rules и обновления Jarvis data-contract audit
  в том же изменении.
- Версия снимка и idempotency key делают повторную публикацию безопасной: повтор запроса
  не создаёт дубликаты и не смешивает частично записанные наборы.
- Пользовательский текст из админки не вставляется через `innerHTML` без экранирования;
  предпросмотр использует text nodes/экранированный вывод.

## Тестируемые критерии при реализации

1. Каталог показывает 300 смысловых идей и ровно три варианта на каждую.
2. Можно выбрать только один вариант идеи и отметить несколько идей для публикации.
3. Публикуются только выбранные валидные записи; неподтверждённые факты блокируются.
4. Повторная публикация того же набора идемпотентна.
5. Free, Plus и общий сегмент получают правильные очереди.
6. Переход по очереди детерминирован, переживает перезапуск и корректно сбрасывается
   при смене версии снимка.
7. Нет русской строки в неподдержанной локали: до перевода работает локализованный
   fallback.
8. При offline/пустом/повреждённом снимке сохраняется прежняя подсказка или текущий
   локализованный текст.
9. Существующая навигация карточки результатов, её пульс и accessibility-контракт не
   ломаются.
10. Узкие контракты админки, функций, Firestore Rules, Jarvis и локальных тестов зелёные.

## Не входит в этот этап

- автоматический перевод всех 300 идей;
- публикация неподтверждённых обещаний о тарифах или скорости восстановления;
- push-уведомления, персональные рекомендации и аналитика кликов;
- изменение существующей экономики, Plus-правил, лиг, арены или реферальных наград.
