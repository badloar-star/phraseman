# Professor Lingman Agent Office Pipeline

## 0. Purpose

This document is the operating manual for the Professor Lingman YouTube script office.

The office exists to create educational English videos that:

- get clicked because the title and thumbnail are strong;
- confirm the click promise in the first seconds;
- teach one clear English skill simply and memorably;
- feel intelligent, funny, useful, and human;
- are written as natural teleprompter text, not as an article;
- include Phraseman advertising only where it increases value and conversion;
- improve over time through title, thumbnail, retention, and conversion data.

The standard is not "a decent lesson." The standard is a video that a cold viewer clicks, understands, enjoys, finishes, remembers, and then wants to practice in Phraseman.

## 1. Core Brand

### Professor Lingman

Professor Lingman is:

- very smart, but never academic for the sake of sounding smart;
- simple, direct, charismatic, and sharp;
- funny in a human way, not in an AI way;
- strict with bad explanations, but kind to the viewer;
- obsessed with making English finally make sense;
- able to use smart vocabulary, but always explains it in plain human language.

Core position:

> English is not impossible. It was just often explained like a cursed dishwasher manual.

Tone formula:

> Smart professor + stand-up rhythm + older brother who finally explains the thing properly.

### Channel Promise

Every video must give the viewer one of these feelings:

- "Now I finally understand."
- "That was easier than school made it."
- "I can actually use this."
- "I want to try this in real phrases."
- "This professor is funny, but he knows exactly what he is doing."

## 2. Non-Negotiable Rules

1. One video teaches one main skill.
2. Packaging comes before final script: weak title/thumbnail means the topic is not ready.
3. Title and thumbnail must be confirmed in the first 5-20 seconds.
4. The beginning gives a quick reward, but does not reveal the entire video.
5. Every 20-40 seconds must contain a new reason to keep watching: example, joke, twist, question, test, visual, or mini-payoff.
6. Every general claim needs a concrete example.
7. Every full script must run a research and fact-check pass before final writing.
8. Official or primary sources must back factual claims whenever they are available.
9. Interesting facts must be woven into the lesson as conversation, not dumped as trivia.
10. Humor must clarify or energize the lesson, not replace the lesson.
11. The script must be readable from a teleprompter in a natural voice.
12. Long-form scripts must flow like one charismatic conversation, not chopped notes with a full stop after every small thought.
13. Phraseman must be advertised as the next logical step after understanding, not as a random interruption.
14. No final script ships without pedagogy, retention, promise, research/fact-check, flow, and teleprompter QA.
15. No description ships with timecodes.
16. No title wins only because it is loud. It must attract the right viewer and preserve trust.

### 3.1 Series Format Selection Gate

When the user asks for a repeatable show format, course, season, or long-running lesson series, the office must not create the final series bible immediately.

Required sequence:

```text
1. Ask a substantial but easy-to-answer format brief.
2. Capture the user's answers on audience level, viewer pains, 30-episode outcome, course/show balance, host persona, humor, respect level, clickbait level, lesson density, Phraseman ad load, product fit, and conversion tone.
3. Research CEFR or relevant learning progression, YouTube retention/packaging logic, and local Phraseman product facts.
4. Offer multiple named format options.
5. Each option must include:
   - format name;
   - public promise;
   - show engine;
   - episode structure;
   - title/thumbnail style;
   - Phraseman conversion fit;
   - season potential;
   - risks;
   - 3 sample clickable Russian titles.
6. Recommend the top 2.
7. Wait for the user to choose before producing the final format bible, season map, or first episode script.
```

Phraseman Course Sync:

```text
If the user wants maximum Phraseman conversion and the app already has a defined lesson order, add an app-aligned format option.
The YouTube series may follow the same 32-lesson order as Phraseman while each episode still uses a clickable title, a strong hook, and a native practice bridge.
Every app-aligned episode should include:
- app lesson number;
- YouTube title;
- one main video promise;
- 3-5 connected mechanisms;
- exact Phraseman mission;
- conversion line that says the viewer can continue the same course path in the app.
```

Full app-aligned episode package:

```text
Every lesson in the 32-lesson Phraseman Course Sync series must ship as a complete YouTube package:
- final aggressive clickable Russian title;
- 10 backup title variants;
- thumbnail idea with visual, 2-4 words of on-thumbnail text, face/emotion, contrast, and mistake/correction object;
- one-page brief;
- full teleprompter script, normally 10 minutes unless the user asks for or approves a longer dense version;
- native Phraseman ad script up to 90 seconds;
- exact Phraseman mission for that app lesson;
- full YouTube description without timecodes;
- pinned comment;
- short CTA variants;
- 3 Shorts/Reels cut ideas;
- research/fact-check notes;
- QA report for click promise, lesson clarity, flow, conversion, and overpromise risk.
```

Dense conversational lesson standard:

```text
Each public script must be thicker than a worksheet:
- long explanations that unpack why the example works;
- direct examples in clusters, not isolated two-line fragments;
- Russian trap -> English mechanism -> natural example -> why it sounds right;
- one idea flowing into the next through speech, not through textbook headings;
- source names kept in fact-check by default, not spoken in the script unless they are audience-interesting;
- no obvious AI humor, random exaggerated metaphors, or meme jokes that feel inserted;
- humor should be dry, sharp, calm, and carried by the host's intelligence;
- every ad bridge must feel like the practical continuation of the lesson, not an inserted commercial.
```

Universal clarity and dead-weight control:

```text
Run this pass before delivery:
1. Can an intelligent 10-year-old understand the point without grammar background?
2. Does every example explain why the English version works?
3. Is any joke dependent on obscure culture, niche facts, or random weirdness?
4. Is any fact interesting only to the writer, not useful to the learner?
5. Does each paragraph teach, hook, clarify, transition, convert, or create recognition?
6. If the answer is no, rewrite the paragraph instead of decorating it.
7. Do not compress a useful explanation only to hit a runtime. Longer is allowed when it holds attention.
```

Full rewrite trigger:

```text
If the user says changes were not significant, the writer must not use the old script as a template.
Start from a new outline, rebuild the hook, examples, sequence, ad bridge, and ending.
The new draft should be recognizably different in structure and explanation path.
```

Anti-list narrative control:

```text
Density is not a list of examples.
Default rule: no more than 2 examples in a row.
More than 2 examples are allowed only inside a clearly marked drill, diagnostic, recap, or deliberately rhythmic punch, and only briefly.

When the draft contains stacked examples, replace the stack with:
- a small real-life scene;
- an interesting fact that directly explains the mechanism;
- a learner objection;
- a slow unpacking of one example;
- a transition to the next idea;
- a Phraseman practice bridge.

Every example must earn its place by answering at least one question:
- why would a Russian-speaking learner say this;
- what exactly does English need here;
- what should the viewer notice next time;
- how does this connect to real speech.

Reject "worksheet energy":
- phrase after phrase;
- translation after translation;
- table rhythm;
- long lists of correct and incorrect forms;
- examples used as filler.
```

Direct address rule:

```text
Public teleprompter scripts must address the person watching directly.
Preferred language:
- вы;
- у вас;
- ваш мозг;
- вы замечаете;
- вы открываете;
- если вы учите английский.

Avoid detached third-person labels in public script:
- зритель;
- ученик;
- новичок;
- аудитория.

These words are allowed in briefs, QA, packaging strategy, and internal notes.
If the script discusses a general learner pattern, turn it back to direct address quickly.
```

Exception:

```text
Only skip the gate if the user explicitly says:
"выбери формат сам и сразу собирай библию"
```

If the user does not answer, use this default:

```text
Mode: one full script
Audience: A2-B1
Length: 8 minutes
Phraseman ad mode: full native integration
Ad goal: agent chooses best goal
Tone: sharp and funny, but educational
```

## 6. Pipeline Gates

### Gate 0: Routing Gate

The project can move forward only if it has:

- a selected route;
- active protocols named;
- irrelevant protocols skipped;
- the main risk named;
- repair triggers stated.

Fail action: send back to Algorithm Control Director.

### Gate 0.5: Topic Pitch Gate

If the requested topic is broad, the project cannot move to a full script until it has:

- 10 proposed topic angles;
- top 3 ranked choices;
- a recommended first script;
- a stated reason for the recommendation;
- user approval or explicit auto-pick permission.

Fail action: send back to Idea Architect and Viral Packaging Department.

### Gate 1: Topic Gate

The topic can move forward only if it has:

- a real audience pain;
- one clear learning outcome;
- a clickable angle;
- enough examples;
- a reason to exist on Professor Lingman's channel.

Fail action: send back to Trend Intelligence or Idea Architect.

### Gate 2: Packaging Gate

The packaging can move forward only if:

- the title is understandable in under 2 seconds;
- the thumbnail has 2-4 words maximum;
- title and thumbnail are not duplicates;
- the click promise is honest;
- the first 15 seconds can confirm the title/thumbnail.

Fail action: send back to Viral Packaging.

### Gate 3: Lesson Gate

The lesson can move forward only if:

- one main concept is taught;
- factual claims have a source-backed research note when the topic needs research;
- official or primary sources were used when available;
- interesting facts or usage observations are present and relevant;
- examples are concrete;
- there is at least one mini-test;
- the explanation does not create a false rule;
- the viewer has a practical skill at the end.

Fail action: send back to Curriculum Architect or Research & Interesting Facts Agent.

### Gate 4: Retention Gate

The script can move forward only if:

- there is a strong hook;
- no 40-second stretch is flat;
- the script flows from beat to beat like a conversation, not a dry list;
- research details create curiosity without interrupting the lesson;
- open loops are used honestly;
- the final payoff closes the promise;
- the ad does not break the viewing rhythm.

Fail action: send back to Retention Editor.

### Gate 5: Human Voice Gate

The script can move forward only if:

- it sounds natural when read out loud;
- it does not feel like an AI essay;
- it does not sound like chopped notes with a full stop after every small thought;
- it has connective tissue between ideas;
- it does not rely on mechanical contrast templates such as "не потому что..., а потому что...";
- examples are introduced through spoken thought, not through repeated colon labels like "Правильно:" or "Сравните:";
- jokes are short and relevant;
- Professor Lingman sounds distinct;
- the text works on a teleprompter.

Fail action: send back to Voice, Humor, or Teleprompter agents.

### Gate 6: Monetization Gate

The Phraseman ad can move forward only if:

- the insertion point is logically connected to the lesson;
- it sells one main product promise;
- it is not too long for the video length;
- it does not overpromise;
- it has a clean return to the lesson.

Fail action: send back to Phraseman Ad Integration Agent.

### Gate 7: Hook Gate

The hook can move forward only if:

- the first sentence creates attention;
- the first 5 seconds confirm the title or thumbnail;
- the first 20 seconds give one useful insight;
- the viewer knows what payoff is coming;
- there is no slow greeting or generic setup.

Fail action: send back to Hook Surgeon.

### Gate 8: Natural English Gate

The English examples can move forward only if:

- they sound like something a real person might say;
- they match the viewer level;
- they are not unnatural textbook phrases;
- corrections include context;
- native-sounding alternatives are marked as optional, not mandatory.

Fail action: send back to Native Naturalness Agent and Pedagogy QA.

### Gate 9: Discoverability Gate

The final package can move forward only if:

- title has either search value, browse value, or both;
- description contains natural keywords;
- first description lines match the title promise;
- no keyword stuffing exists;
- the topic can be understood by YouTube and by humans.

Fail action: send back to SEO Discoverability Agent and Description Writer Agent.

### Gate 10: Boredom Gate

The script can move forward only if:

- no section exists only because it is "informative";
- every section has tension, example, visual, joke, test, or payoff;
- long explanations are broken into beats;
- repetitive examples are cut or varied;
- the middle of the video has at least one strong turn.

Fail action: send back to Boring Detector and Retention Editor.

### 6.1 Loopback Rules

When an agent fails a section, the pipeline loops back to the earliest responsible point.

```text
Weak topic -> Trend Intelligence / Idea Architect
Weak title -> Viral Packaging / Title Testing
Weak thumbnail -> Thumbnail Director
Weak hook -> Hook Surgeon / Click Promise Agent
Confusing lesson -> Curriculum / Cognitive Load
Too few examples -> Example Density
Wrong English -> Pedagogy QA / Native Naturalness
Flat middle -> Retention / Boring Detector
Bad jokes -> Human Humor
AI tone -> Anti-AI / Lingman Voice
Bad ad -> Phraseman Ad Integration / Conversion Guard
Bad description -> Description Writer / SEO Discoverability
```

The Final Director must report loopbacks in the final package:

```text
Loopbacks performed:
- Hook rewritten after Hook Gate failed.
- Ad moved from 1:10 to 4:30 after Conversion Guard found early interruption risk.
- Title changed because first version overpromised the payoff.
```

### 6.2 Risk Levels

Every issue should be tagged:

```text
P0: cannot publish. Wrong, misleading, damaging, or unusable.
P1: must fix before final. Major retention, clarity, or conversion problem.
P2: should fix. Noticeable quality issue.
P3: optional polish.
```

P0 and P1 issues block approval.

### 7.0E Agent Anti-Bloat Rule

Agents must not rewrite the whole project when their layer is weak.

Use smallest repair:

```text

Hook problem -> Hook Surgeon.
Teaching problem -> Curriculum / Pedagogy / Cognitive Load.
Example problem -> Example Density / Native Naturalness.
Voice problem -> Lingman Voice / Anti-AI.
Humor problem -> Human Humor.
Ad problem -> Phraseman Ad Integration / Conversion Guard.
Spoken delivery problem -> Teleprompter / Table-Read.
```

If an agent wants a full rebuild, it must name the broken root cause.

- user request;
- known channel strategy;
- available data;
- Phraseman priority;
- topic type;
- output deadline.

Outputs:

```text
Routing snapshot:
- detected request type
- selected route
- active protocols
- skipped protocols
- evidence level
- main risk
- repair triggers
```

Rules:

- Activate only protocols that can change the output.

### 7.21 Teleprompter Polish Agent

Mission: make the final script easy to read into camera.

```text
[Пауза when needed]
Text in natural spoken paragraphs.

[На экран: I have lost my keys.]
More text.
```

- One idea per paragraph.
- Mark pauses and emphasis.
- Remove tongue-twisters.
- Read every sentence aloud mentally.

- If it sounds like chopped notes with dots after every phrase, merge it into a flowing spoken paragraph.

### 7.21.1 Conversational Flow Control & Repair Agent

- too many "Ошибка номер..." markers;
- repeated generic transitions such as "Вот почему", "И вот важно", "Теперь давайте";

```text

- dry example blocks found
- repaired beats
- remaining risk
```

Rules:

- Preserve grammar accuracy and source-backed facts.

- Replace colon scaffolding with natural setups like "в живой речи это звучит так", "английский просит другой кусок", "и фраза собирается уже так".
- A separate example line is allowed when it helps the presenter, but the line before it must be conversational, not a label.

### 8.7 Statistical Decision Protocol

When choosing titles, thumbnails, and ads, use this hierarchy:

```text
1. Real channel data
2. Real competitor/platform data
3. Real audience comments
4. Heuristic prediction
5. Taste
```

If data volume is low, mark decisions as provisional.

Rules:

- Do not call a winner before enough impressions exist.
- If CTR is high but retention collapses in the first 30 seconds, the packaging attracted the wrong viewer.
- If retention is high but CTR is low, the packaging is under-selling the video.
- If CTR and retention are strong but Phraseman clicks are weak, the ad angle or placement is wrong.
- If comments ask the same follow-up question, create the next video from that question.

Recommended minimums:

```text
Early signal: 1,000+ impressions
Useful comparison: 5,000+ impressions per variant
Stronger comparison: 10,000+ impressions per variant
Do not over-trust tests with tiny samples
```

Decision labels:

```text
Data-backed: enough relevant data exists.
Directional: some data exists, but not enough for certainty.
Heuristic: no reliable data; expert prediction only.
```

### 8.13 Hook Matrix

The Hook Surgeon chooses one primary hook type.

```text
1. Error Hook
Use when the viewer likely makes a mistake.
Pattern: "If you say [X], this is why it sounds wrong."

2. Myth Hook
Use when school taught an oversimplified rule.
Pattern: "They told you [X]. Native speech does [Y]."

3. Translation Trap Hook
Use for Russian-speaker mistakes.
Pattern: "You are translating [word] too literally."

4. Status Hook
Use when the video helps the viewer sound smarter or more natural.
Pattern: "This is the difference between correct English and natural English."

5. Relief Hook
Use when a topic feels intimidating.
Pattern: "[Topic] is not hard. The explanation was bad."

6. Curiosity Hook
Use when a phrase looks strange.
Pattern: "Why do natives say [phrase] if it literally means nonsense?"

7. Test Hook
Use when the viewer can be challenged immediately.
Pattern: "Choose one: [A] or [B]. If you hesitated, this video is for you."
```

Hook rules:

- Use one dominant hook, not five at once.
- The first example should arrive fast.
- A hook should create tension and direction, not just volume.
- If the hook needs more than 25 seconds to make sense, it is too slow.

### 8.15 Humor Style Bible

Lingman humor is sharp, specific, and connected to learning.

Allowed humor:

```text
Bad school explanations:
"This rule was explained like a hostage note from a grammar textbook."

Translation traps:
"Russian is trying to drive the English sentence from the back seat."

Grammar personification:
"Present Perfect walks in with a lawyer and asks: where is the result now?"

Self-aware professor energy:
"I know. This looks illegal. Unfortunately, English approved it."

Tiny exaggeration:
"If you translate this literally, the sentence starts wearing a fake mustache."
```

Forbidden humor:

```text
Random absurd jokes unrelated to the lesson.
Memes that will age badly.
Jokes that insult the viewer's intelligence.
Long comedic stories that delay the teaching.
AI-style quirky comparisons with no human rhythm.
Any joke that makes the example harder to remember.
```

Humor density:

```text
Shorts: 1 strong joke maximum.
5-7 minutes: 4-7 jokes or sharp lines.
8-12 minutes: 6-10 jokes or sharp lines.
Series lessons: recurring joke allowed, but not every episode.
```

Rule:

> A joke earns its place only if the viewer understands the English better after it.

## 11. Weak Spots Audit

This section exists to attack the pipeline itself. A strong office can still fail if it becomes too heavy, too clever, too slow, too ad-driven, or too confident without data.

### 11.1 P0 Risks: Must Fix Before Real Production

#### P0.1 Agent Overload

Risk:

The pipeline has many agents. If every small task runs through every agent, production becomes slow, expensive, repetitive, and mentally exhausting.

Failure mode:

```text
A simple 60-second Short gets treated like a 12-minute flagship lesson.
The office spends more time managing agents than improving the video.
```

Fix:

- Use mode-specific routes.
- Add a "Minimum Viable Route" for simple outputs.
- Final Director must explicitly say which agents were skipped and why.

Minimum viable routes:

```text
Short:
Intake -> Hook -> Scriptwriter -> Lingman Voice -> Teleprompter -> Final

Title only:
Intake -> Viral Packaging -> Title Testing -> False Promise -> Final

Ad insert only:
Intake -> Phraseman Ad Agent -> Conversion Guard -> Teleprompter -> Final
```

#### P0.2 No Clear Final Authority

Risk:

Agents can disagree: Title Testing wants more drama, Pedagogy wants nuance, Humor wants a stronger joke, Conversion wants a longer ad.

Failure mode:

```text
The script becomes a compromise blob.
No one protects the main viewer experience.
```

Fix:

Final Director has final authority, but must follow this priority order:

```text
1. Truth and pedagogy
2. Viewer trust
3. Click promise
4. Retention
5. Lingman voice
6. Phraseman conversion
7. SEO
8. Extra cleverness
```

Rule:

> If conversion damages trust, trust wins.

#### P0.3 Weak Ad Disclosure

Risk:

If Phraseman is owned by the creator or financially connected to the channel, the integration must not pretend to be neutral.

Failure mode:

```text
The ad feels manipulative or legally sloppy.
```

Fix:

- Say "our app Phraseman" or another truthful phrase when appropriate.
- Do not disguise a full ad as a spontaneous recommendation.
- Keep the recommendation honest and tied to the lesson.

Allowed:

```text
That's exactly why we built Phraseman around phrase practice, not just isolated word lists.
```

Forbidden:

```text
I recently found this random app...
```

#### P0.4 Unsupported Facts

Risk:

The Research Agent may add interesting facts that sound good but are not verified.

Failure mode:

```text
A fun linguistic claim is wrong, oversimplified, or impossible to source.
```

Fix:

- Any historical, etymological, statistical, or "natives say" claim must be sourced or marked as an inference.
- If no source is available, use it as a soft observation, not a fact.
- Pedagogy QA can delete any fact that creates risk.

Rule:

> Interesting is not enough. It must be true enough to survive comments.

### 11.2 P1 Risks: Must Fix For High-Quality Output

#### P1.1 Too Much Humor

Risk:

Because Lingman is charismatic, the office may overcorrect into constant joking.

Failure mode:

```text
The viewer remembers the jokes but not the English.
```

Fix:

- Humor density rules must be enforced.
- Every joke must attach to a learning point.
- If two jokes appear back-to-back without a teaching beat, cut one.

#### P1.2 Too Much Intelligence

Risk:

The character may become impressive but less useful.

Failure mode:

```text
The script sounds brilliant, but the viewer cannot repeat the rule.
```

Fix:

- Cognitive Load Agent must protect simplicity.
- Every smart term must be followed by a plain explanation.
- Final test must prove the viewer can use the idea.

#### P1.3 Data Theater

Risk:

The analytics layer may sound scientific while relying on tiny samples or weak signals.

Failure mode:

```text
The office declares a title winner from 300 impressions.
```

Fix:

- Every analytics decision must be labeled: data-backed, directional, or heuristic.
- Tiny samples can guide hypotheses, not final truth.
- Retention and conversion must be considered with CTR.

#### P1.4 SEO vs Browse Conflict

Risk:

Search-friendly titles can become boring. Browse-friendly titles can become unclear.

Failure mode:

```text
Title is searchable but dead, or clickable but YouTube cannot classify it.
```

Fix:

SEO Discoverability Agent must label each title:

```text
Search-led
Browse-led
Hybrid
```

Rule:

> For educational grammar videos, use at least one clear topic signal in either title, description, or spoken intro.

#### P1.5 Phraseman Feature Dump

Risk:

The ad may list too many features because the app has many strengths.

Failure mode:

```text
The viewer hears "lessons, flashcards, arena, analytics, premium, rewards" and remembers nothing.
```

Fix:

- One ad = one primary feature.
- Supporting features are allowed only after the primary pain is sold.
- CTA must match the primary feature.

#### P1.6 Missing Instrumentation

Risk:

The office wants to optimize Phraseman conversion but may not have clean tracking.

Failure mode:

```text
Nobody knows which video, title, or ad angle drove installs or trials.
```

Fix:

Every video should define:

```text
UTM/source code:
video id:
title variant:
thumbnail variant:
ad angle:
ad timestamp:
CTA text:
landing destination:
```

Post-Publish Analytics Agent cannot evaluate conversion without this packet.

#### P1.7 Thumbnail Not Tested On Mobile

Risk:

Thumbnail ideas may look good in a document and fail at phone size.

Failure mode:

```text
Text is unreadable, face is too small, visual conflict is unclear.
```

Fix:

Thumbnail Director must run a mobile-legibility check:

```text
Can read text at small size?
One emotion visible?
One conflict visible?
No more than 2-4 words?
Title + thumbnail create one promise?
```

#### P1.8 No Negative Viewer Persona

Risk:

The pipeline defines who the video is for, but not who it should repel.

Failure mode:

```text
The title attracts advanced grammar nerds to a beginner lesson, or beginners to a B2 nuance video.
```

Fix:

Audience Persona Agent must include:

```text
This video is not for:
- viewer type
- reason
- packaging adjustment to avoid wrong clicks
```

### 11.3 P2 Risks: Should Fix During Polish

#### P2.1 Repeated Lingman Catchphrases

Risk:

Recurring phrases create brand, but too many make the character feel scripted.

Fix:

- Limit repeated signature phrases to 1-3 per video.
- Avoid using the same joke frame in consecutive videos.

#### P2.2 Examples Without Context

Risk:

Examples can be grammatically correct but context-poor.

Fix:

Every important example should answer:

```text
Who says it?
Where?
To whom?
Formal or casual?
What does it replace?
```

#### P2.3 Weak Endings

Risk:

The script may teach well but end with a generic CTA.

Fix:

Ending must include:

```text
final rule
final emotional payoff
optional Phraseman reminder
comment question
next-video bridge if relevant
```

#### P2.4 Description Underweight

Risk:

The description score is only 3 points in the scorecard, but descriptions matter for search, trust, and conversion.

Fix:

- Score remains low because the video experience matters more, but Description Writer must still pass Discoverability Gate.
- If the video is search-led, description quality becomes a P1 issue.

#### P2.5 Shorts As Afterthought

Risk:

Shorts Extractor may merely cut moments instead of creating native short scripts.

Fix:

Each Short must have:

```text
independent hook
one idea
on-screen text
payoff
optional CTA
```

### 11.4 Missing Agents Or Subsystems To Add Later

These are not mandatory now, but they may become useful.

```text
Legal/Compliance Agent:
Checks ad disclosure, claims, platform rules, and subscription/trial wording.

Localization Agent:
Adapts scripts if the channel later creates Ukrainian, Spanish, or other language versions.

Community Manager Agent:
Writes pinned comments, replies, polls, and next-topic prompts after publication.

Landing Page Conversion Agent:

Production Feasibility Agent:

Comment Response Agent:

```

### 11.5 Weak Spot Fix Checklist

Before final approval, ask:

```text
Is this route too heavy for the task?
Who has final authority if agents disagree?
Is the title honest?
Is the first 20 seconds proof of the click?
Is the lesson actually usable?
Is any fact unsupported?
Is the humor helping memory?
```

## 12. Strengths Audit

This section identifies what is already strong in the pipeline and must be protected. Strong systems often fail when their best ideas get diluted during execution.

### 12.1 Strong Core: Packaging Before Script

Strength:

The pipeline does not treat title and thumbnail as decoration after the script. It makes packaging a strategic gate before production.

Why it matters:

- YouTube rewards the promise before it rewards the lesson.
- A strong script with weak packaging may never get seen.
- Packaging forces the topic to become clear.

Protect this by:

- never writing a full script before at least 3 title/thumbnail directions exist;
- rejecting topics that cannot produce a clean click promise;
- checking the first 20 seconds against title and thumbnail after every major rewrite.

Upgrade path:

```text
Build a title/thumbnail pattern library:
- pain titles
- myth titles
- relief titles
- status titles
- curiosity titles
- search-led titles
- browse-led titles
```

### 12.2 Strong Core: Click Promise Discipline

Strength:

The pipeline explicitly connects title, thumbnail, first seconds, body, and final payoff.

Why it matters:

- This protects trust.
- It reduces early drop-off.
- It prevents empty clickbait.

Protect this by:

- requiring a Click Promise Contract for every full video;
- making False Promise Auditor a blocking role;
- forcing the ending to close the same loop opened by the title.

Upgrade path:

```text
Add a "promise ledger" to every script:
- promised in title
- promised in thumbnail
- confirmed in first 5 seconds
- rewarded in first 30 seconds
- fully paid off at the end
```

### 12.3 Strong Core: One Skill Per Video

Strength:

The pipeline refuses broad, vague lessons and pushes toward one usable outcome.

Why it matters:

- Viewers remember one clean model better than five partial explanations.
- Strong titles are easier when the outcome is narrow.
- Phraseman integration becomes more natural when the practice goal is specific.

Protect this by:

- forcing every script to state one learning outcome;
- deleting side quests that do not serve that outcome;
- using series format when a topic is too large.

Upgrade path:

```text
Add "skill cards" for every video:
- skill name
- level
- prerequisite
- examples
- common mistake
- Phraseman practice mode
```

### 12.4 Strong Core: Professor Lingman As A Real Voice

Strength:

The channel has a character with a point of view, not a generic educational narrator.

Why it matters:

- Voice creates retention.
- Voice creates brand memory.
- Voice lets the same grammar topic feel new.

Protect this by:

- keeping the Lingman Lexicon alive;
- limiting generic educational phrases;
- balancing intelligence, simplicity, and sharp humor;
- attacking bad explanations, not the viewer.

Upgrade path:

```text
Create a Lingman Voice Reference Pack:
- 10 canonical openings
- 10 canonical transitions
- 10 canonical correction lines
- 10 canonical ad returns
- 10 canonical endings
- banned phrase list
```

### 12.5 Strong Core: Humor With Function

Strength:

Humor is not treated as decoration. It must clarify, release tension, or make the concept memorable.

Why it matters:

- Educational humor increases emotional retention.
- It makes hard topics less threatening.
- It separates Lingman from textbook channels.

Protect this by:

- enforcing humor density;
- cutting jokes that do not help memory;
- testing jokes in table-read;
- storing jokes that work in the office memory.

Upgrade path:

```text
Tag every joke by function:
- relief
- analogy
- correction
- transition
- callback
- ad return
```

### 12.6 Strong Core: Phraseman Integration As Practice Continuation

Strength:

The pipeline positions Phraseman as the next step after understanding, not as a random sponsor block.

Why it matters:

- It increases conversion without destroying trust.
- It gives the app a real role in the viewer journey.
- It connects free value with product action.

Protect this by:

- choosing one ad angle per video;
- matching the ad to the lesson pain;
- keeping disclosure honest;
- tracking ad angle and timestamp.

Upgrade path:

```text
Build a Phraseman conversion map:
- topic type
- viewer pain
- best product feature
- best CTA
- best timestamp
- conversion result
```

### 12.7 Strong Core: Two-Pass Creation And Attack

Strength:

The pipeline separates creation from critique.

Why it matters:

- Drafting needs momentum.
- Auditing needs skepticism.
- Mixing both too early can make the script timid.

Protect this by:

- letting Scriptwriter and Voice Agent create freely in pass 1;
- letting auditors attack in pass 2;
- preventing auditors from making the script sterile.

Upgrade path:

```text
Use red-team reports:
- top 3 risks
- top 3 fixes
- what not to change
- final publish confidence
```

### 12.8 Strong Core: Memory Loop

Strength:

The office is designed to learn from each published video.

Why it matters:

- Repeated publishing without memory creates random improvement.
- Data turns taste into patterns.
- Viewer comments become topic fuel.

Protect this by:

- creating memory files before the first real publishing cycle;
- storing failures, not only winners;
- connecting analytics to future decisions.

Upgrade path:

```text
Every post-publish report should create:
- one title lesson
- one hook lesson
- one retention lesson
- one Phraseman lesson
- one next topic
```

### 12.9 Strong Core: Teleprompter-First Writing

Strength:

The script is designed to be spoken to camera, not read like an article.

Why it matters:

- Delivery affects trust.
- Natural speech hides the machinery.
- Teleprompter readability protects the presenter.

Protect this by:

- table-reading every final script;
- using short lines and performance notes;
- deleting clever lines that are hard to say.

Upgrade path:

```text
Create delivery tags:
[Пауза]
[Улыбка]
[Серьезнее]
[Быстрее]
[На экран]
[Тест]
[Возврат к теме]
```

### 12.10 Strong Core: Built-In Anti-AI Texture

Strength:

The pipeline explicitly fights sterile AI writing.

Why it matters:

- Educational YouTube is full of smooth, lifeless scripts.
- Human texture makes Lingman feel present.
- Specificity builds trust.

Protect this by:

- banning generic transitions;
- using real viewer language from comments;
- keeping asymmetry and rhythm;
- making examples concrete.

Upgrade path:

```text
Anti-AI audit should flag:
- generic setup
- repeated paragraph structure
- fake excitement
- vague benefit language
- symmetrical lists
- empty transitions
```

## 14. Middle Zones Audit And Upgrades

This section audits the parts of the pipeline that are not broken and not yet excellent. These "middle zones" usually create the biggest practical improvement because they already exist, but need sharper rules.

### 14.1 Middle Zone: The Middle Of The Video

Current state:

The pipeline is strong on hook, packaging, and final payoff, but the middle can still become a long explanation block.

Why it is only medium:

- The first minute has clear rules.
- The ending has clear payoff rules.
- The 35%-70% section needs more explicit engineering.

Upgrade:

Add a Mid-Video Tension Map:

```text
Middle section must include:
- one escalation
- one mini-test
- one surprising example
- one callback to the hook
- one visual reset
- one reason to wait for the final payoff
```

Mid-video failure signs:

```text
Three examples in a row with the same rhythm.
No question for more than 60 seconds.
No visual change.
No tension after the first concept is explained.
Phraseman ad appears before enough trust is earned.
```

Fix:

```text
At 40%-60% of the script, add a "second trap":
"Now you understand the basic rule. But here is where people still mess it up."
```

### 14.2 Middle Zone: Research And Interesting Facts

Current state:

The Research Agent exists and can add depth.

Why it is only medium:

The pipeline says facts should be useful, but it does not yet rank fact types by value.

Upgrade:

Use a Fact Value Ladder:

```text
Level 5: Fact changes how the viewer understands the rule.
Level 4: Fact creates a memorable analogy.
Level 3: Fact explains native usage.
Level 2: Fact is interesting but optional.
Level 1: Fact is trivia and should be cut.
```

Rule:

Only Level 3-5 facts should survive in the main script. Level 2 facts can become Shorts, pinned comments, or bonus notes.

### 14.3 Middle Zone: Visual Production

Current state:

Visual Producer Agent gives visual notes.

Why it is only medium:

Visual notes can remain too abstract: "show examples" or "add graphic" is not enough.

Upgrade:

Every visual note must specify:

```text
visual type:
- on-screen text
- split screen
- app screenshot
- gesture
- zoom
- correction overlay
- simple diagram
- prop

exact content:
what appears on screen:
when it appears:
why it helps:
must-have or optional:
```

Rule:

If a visual does not teach, clarify, reset attention, or support humor, delete it.

### 14.4 Middle Zone: Description

Current state:

Description Writer exists and has a no-timecodes rule.

Why it is only medium:

The description score is small, and the description can become formulaic if not controlled.

Upgrade:

Add Description Quality Levels:

```text
Level 1: Basic summary.
Level 2: Summary plus keywords.
Level 3: Hooked intro plus useful bullets.
Level 4: Matches title promise, supports SEO, includes natural Phraseman CTA.
Level 5: Feels like a companion to the video and creates comments.
```

Rule:

All published descriptions must reach Level 4. Search-led videos must reach Level 5.

### 14.5 Middle Zone: Shorts Extraction

Current state:

Shorts Extractor can create clips from long videos.

Why it is only medium:

A clip is not automatically a good Short. Shorts need their own hook and payoff.

Upgrade:

Shorts must be classified:

```text
Type A: mistake correction
Type B: mini-test
Type C: funny analogy
Type D: phrase upgrade
Type E: myth bust
Type F: Phraseman practice prompt
```

Each Short must include:

```text
0-2s hook
2-12s explanation
12-25s example/test
25-35s payoff
optional CTA
```

Rule:

If the Short requires context from the long video, rewrite it until it stands alone.

### 14.6 Middle Zone: Series Planning

Current state:

Series Continuity Agent exists.

Why it is only medium:

The pipeline can plan episode order, but does not yet define how difficulty and viewer identity evolve across the series.

Upgrade:

Every series needs a Series Growth Arc:

```text
Episode 1: relief, "this is not impossible"
Episode 2: control, "I can use the model"
Episode 3: nuance, "I can handle exceptions"
Episode 4: naturalness, "I sound less textbook"
Episode 5: confidence, "I can test myself"
```

Rule:

Series episodes should not feel like random lessons under one playlist name. They should change the viewer's ability and identity step by step.

### 14.7 Middle Zone: Phraseman Bridge

Current state:

Phraseman ads are placed by emotional state and lesson pain.

Why it is only medium:

The bridge from lesson to app can still feel like an ad if it lacks a precise practice task.

Upgrade:

Every Phraseman integration should include a Practice Bridge:

```text
You just learned:
- skill

Now practice:
- exact phrase type
- exact mistake type
- exact app feature

Why now:
- because understanding without repetition fades
```

Example:

```text
You just learned why "interested in" works.
Now go train preposition patterns in Phraseman, because this is not a rule you admire once. It is a reflex you build.
```

Rule:

Do not send the viewer to the app generally. Send them to practice the exact thing they just learned.

### 14.8 Middle Zone: Analytics Interpretation

Current state:

The pipeline collects CTR, retention, and Phraseman clicks.

Why it is only medium:

It needs clearer diagnosis for mixed signals.

Upgrade:

Use Mixed Signal Diagnosis:

```text
High CTR + low first 30s retention:
Packaging overpromised or wrong viewer clicked.

Low CTR + high retention:
Video is good but packaging is weak.

High retention + low comments:
Useful but not emotionally provocative.

High comments + low retention:
Topic is emotional, but structure may be messy.

High Phraseman clicks + low retention:
Ad may be effective, but video experience is suffering.

Low Phraseman clicks + high retention:
Viewer trusts the content, but ad angle/CTA is weak.
```

Rule:

Never interpret one metric alone.

### 14.9 Middle Zone: Examples

Current state:

Example Density Agent and Native Naturalness Agent protect example quality.

Why it is only medium:

The pipeline checks number and naturalness, but not always progression.

Upgrade:

Use Example Progression:

```text
1. beginner clear example
2. common wrong version
3. corrected version
4. natural spoken version
5. edge case or trap
6. mini-test
```

Rule:

Examples should not be a pile. They should teach by moving from simple to useful to tricky.

### 14.10 Middle Zone: Viewer Participation

Current state:

The pipeline includes mini-tests and comment hooks.

Why it is only medium:

Participation can be too late or too rare.

Upgrade:

Add Participation Beats:

```text
First 60 seconds:
one simple question or choice.

Middle:
one mini-test.

End:
one final test or comment prompt.
```

Rule:

The viewer should not only watch Lingman think. The viewer should be invited to think with him.

### 14.11 Middle Zone: Production Constraints

Current state:

Production Feasibility is listed as a future subsystem.

Why it is only medium:

Without constraints, scripts may request visuals that are hard to produce.

Upgrade:

Add a Production Constraint field to every brief:

```text
Production level:
- simple talking head
- talking head + text overlays
- app screenshots
- heavy motion graphics
- studio/props

Available assets:
- Lingman face shots
- Phraseman screenshots
- whiteboard
- stock clips
- custom graphics

Editing time:
- low
- medium
- high
```

Rule:

A great script that cannot be produced consistently is not yet a great production asset.

### 14.12 Middle Zone: Quality Score Calibration

Current state:

The scorecard totals 100 and covers key areas.

Why it is only medium:

Different video modes need different weights.

Upgrade:

Create scorecard variants:

```text
Full lesson:
education, retention, examples, teleprompter matter most.

Hype conversation:
hook, voice, emotional tension, title matter most.

Short:
hook, speed, one idea, payoff matter most.

Search-led tutorial:
clarity, SEO, examples, promise match matter most.

Phraseman-heavy video:
trust, ad bridge, conversion, disclosure matter most.
```

Rule:

Do not score a Short with the same weight logic as a 10-minute lesson.

### 14.13 Middle Zone Upgrade Checklist

Before final delivery, ask:

```text
Does the middle of the video have a second trap or escalation?
Are facts ranked by value, not just interestingness?
Are visual notes concrete enough to edit?
Is the description at least Level 4?
Do Shorts stand alone?
Does the series have viewer growth, not just topic order?
Does the Phraseman ad send viewers to a specific practice task?
Are analytics interpreted as combinations, not isolated metrics?
Do examples progress from simple to natural to tricky?
Does the viewer participate before the ending?
Are production constraints realistic?
Is the scorecard adjusted for video mode?
```

If several answers are "no", the pipeline is functional but not elite yet.

## 20. Feature Strengthening Audit

A feature is not a decoration.

A feature earns its place only if it makes the episode more clickable, clearer, funnier, more watchable, more memorable, more shareable, or more conversion-friendly.

If a feature does not improve at least one of those outcomes, it is not a feature. It is office noise.

### 20.1 Feature Strength Test

Before adding or keeping any feature, the office must score it through this test:

```text
1. Click role
Does this feature make the idea, title, or thumbnail more clickable?

2. Promise role
Does this feature help confirm the title/thumbnail promise early?

3. Teaching role
Does this feature make the English concept easier to understand or use?

4. Retention role
Does this feature create a reason to keep watching?

5. Personality role
Does this feature make Professor Lingman more distinct and human?

6. Conversion role
Does this feature create a natural bridge to Phraseman or another action?

7. Repeatability role
Can this feature become a repeatable channel asset, not a one-time trick?

8. Production role
Can this feature be produced consistently without slowing the whole office?
```

Verdict rule:

```text
0-2 yes answers: remove or archive.
3-4 yes answers: keep experimental.
5-6 yes answers: upgrade and add to standard workflow.
7-8 yes answers: make it a signature channel mechanic.
```

### 20.2 Feature Upgrade Formula

Every feature should be upgraded with the same formula:

```text
Feature name
Viewer trigger
Promise it supports
Exact beat in the script
Visual proof on screen
Teaching payload
Lingman personality moment
Phraseman bridge if relevant
Metric to watch
Kill condition
```

Example:

```text
Feature name:
Russian Brain Trap Detector

Viewer trigger:
"I always translate this from Russian and it sounds wrong."

Promise it supports:
Stop making one specific mistake today.

Exact beat in the script:
After the hook and before the first explanation.

Visual proof on screen:
Bad translation on the left, natural English on the right.

Teaching payload:
Show the thought pattern, not only the correct phrase.

Lingman personality moment:
Professor Lingman cross-examines the Russian sentence like a suspicious witness.

Phraseman bridge:
"This is exactly why phrases beat word-by-word translation. Practice the natural version in Phraseman."

Metric to watch:
Retention in first 45 seconds, comments with viewer examples, Phraseman clicks.

Kill condition:
If it becomes repetitive or shames the learner instead of freeing them.
```

## 21. Idealization Layer

The ideal pipeline is not the biggest pipeline.

The ideal pipeline is the one that produces the strongest possible script with the least confusion, the clearest ownership, and the most repeatable quality.

The office must optimize for this:

```text
viewer trust
viewer curiosity
viewer understanding
viewer emotion
viewer practice
viewer action
```

If a decision improves only the office but not the viewer experience, it is not an improvement.

### 21.1 Definition Of Ideal

An ideal Lingman script is not just "good writing."

It is a complete persuasion and learning machine:

```text
1. It earns the click without lying.
2. It proves the click promise early.
3. It makes one English problem feel urgent and solvable.
4. It explains the problem with a simple mental model.
5. It gives enough examples for the viewer to feel progress.
6. It uses Professor Lingman as a memorable teaching instrument.
7. It uses humor to sharpen attention, not to decorate silence.
8. It creates active learning through questions, tests, contrasts, or practice.
9. It gives Phraseman a natural reason to exist inside the episode.
10. It ends with a concrete phrase, insight, or action the viewer can use today.
```

Non-ideal:

```text
"This is a nice script."
```

Ideal:

```text
"This script makes a specific viewer click, stay, understand, laugh, practice, and take the next action."
```

### 21.2 Master Decision Hierarchy

When agents disagree, decisions follow this order:

```text
1. Truth and viewer trust
2. Clear teaching
3. Promise alignment
4. Retention and watchability
5. Lingman character
6. Phraseman conversion
7. SEO and discoverability
8. Production feasibility
9. Cleverness
```

Rule:

```text
Cleverness loses to clarity.
Conversion loses to trust.
Retention loses to truth.
SEO loses to watchability.
Voice loses to the lesson if the joke blocks understanding.
```

The Final Director must use this hierarchy in every major conflict.

### 21.3 Ideal Script DNA

Every ideal script contains these ten pieces:

```text
1. Human pain:
What does the viewer feel stuck on?

2. Click promise:
What does the title/thumbnail promise to solve?

3. Promise receipt:
How does the first minute prove the promise is real?

4. Enemy:
What misconception, bad habit, textbook myth, or translation trap are we fighting?

5. Mental model:
What simple explanation makes the topic click?

6. Example ladder:
How do examples move from easy to natural to expressive?

7. Active moment:
Where does the viewer guess, choose, repeat, or diagnose?

8. Lingman signature:
Where does the character become unmistakable?

9. Practice bridge:
Where does Phraseman become the obvious next step?

10. Payoff:
What can the viewer say, understand, or do after watching?
```

If any piece is missing, the script can still be usable, but it is not ideal.

### 21.5 Ideal Script Architecture

The script must be built on three levels.

#### Macro Level: The Viewer Journey

```text
Click:
The viewer sees a problem they recognize.

Confirmation:
The opening proves the video is about that exact problem.

Curiosity:
The script reveals there is a hidden reason behind the problem.

Understanding:
The mental model makes the topic simpler.

Use:
Examples turn the model into speech.

Personality:
Lingman makes the lesson memorable.

Practice:
The viewer gets a concrete task.

Payoff:
The viewer leaves with one usable upgrade.
```

#### Middle Level: The Beat Flow

Recommended full script beat flow:

```text
0:00-0:05
Pattern interrupt or direct mistake.

0:05-0:20
Promise receipt.

0:20-0:45
Viewer pain and why the mistake is logical.

0:45-1:30
First reveal or misconception x-ray.

1:30-3:00
Simple mental model.

3:00-4:30
Examples and native ladder.

4:30-5:30
Micro-test or viewer diagnosis.

5:30-6:30
Phraseman practice bridge or ad segment if enabled.

6:30-8:00
Deeper examples, exceptions, or social tone.

8:00-9:00
Final compression and one-sentence payoff.

9:00-end
CTA, comment prompt, and next episode bridge.
```

The timing can change, but the logic cannot.

#### Micro Level: Teleprompter Sentences

Every teleprompter sentence should pass at least one of these tests:

```text
It advances the lesson.
It sharpens curiosity.
It gives an example.
It reveals personality.
It creates a transition.
It moves the viewer toward practice.
```

If a sentence does none of those, cut it.

### 21.8 The Ideal Hook Standard

The hook is ideal only if it does all five:

```text
1. Shows the exact problem.
2. Makes the viewer feel recognized.
3. Gives early proof that the video will solve it.
4. Opens a curiosity gap without lying.
5. Uses language the target viewer would actually understand.
```

Hook failure examples:

```text
"Today we will talk about prepositions."
Problem: no pain, no curiosity.

"This one mistake destroys your English forever."
Problem: false drama.

"Native speakers never use this."
Problem: usually too absolute.

"Let's dive into..."
Problem: empty opening.
```

Ideal hook patterns:

```text
Mistake-first:
"If you say 'I am agree,' I know exactly what your brain is doing."

Contrast-first:
"Both sentences are grammatically possible. Only one sounds like a living person said it."

Pain-first:
"You know the rule, you know the words, and still the sentence comes out weird."

Test-first:
"Choose one: 'interested in' or 'interested on.' Your answer tells me how your brain stores English."

Myth-first:
"The problem is not your memory. The problem is that someone taught you English like a spreadsheet."
```

### 21.9 The Ideal Teaching Standard

An explanation is ideal when the viewer can use it without remembering the whole explanation.

Every teaching block must include:

```text
1. The problem
2. The wrong mental model
3. The better mental model
4. One clean example
5. Three natural examples
6. One mistake warning
7. One active practice moment
```

Forbidden teaching style:

```text
definition dump;
rule pile;
exception avalanche;
translation-only explanation;
example without context;
advanced terminology without a payoff;
"just memorize it" without a practice path.
```

Ideal teaching move:

```text
Name the pattern.
Show the pattern.
Break the old habit.
Give the viewer a phrase they can actually say.
```

### 21.10 The Ideal Humor Standard

Humor is ideal only when it does at least one of these:

```text
makes the misconception memorable;
lowers the viewer's shame;
creates a character moment;
sets up a contrast;
gives rhythm before a dense explanation;
makes the viewer want to quote the line.
```

Humor must not:

```text
mock the learner;
replace the explanation;
delay the answer;
sound like a random meme;
depend on insider knowledge;
repeat the same Lingman trick too often.
```

The best Lingman humor formula:

```text
serious professor energy
+ tiny language problem
+ unexpected human phrasing
+ immediate educational payoff
```

### 21.11 The Ideal Phraseman Integration Standard

Phraseman is ideal when it appears as the continuation of the lesson.

Bad integration:

```text
"By the way, download the app."
```

Better:

```text
"You understood the pattern. Now you need repetitions with real phrases."
```

Ideal:

```text
"Today we fixed the habit of translating word by word. Your mission in Phraseman is to practice the natural phrase versions until your brain stops building the Russian sentence first."
```

Every full Phraseman integration must include:

```text
1. Why the lesson alone is not enough.
2. What exact practice the viewer should do.
3. Which Phraseman strength supports that practice.
4. One honest conversion line.
5. One light CTA.
```

Never include:

```text
fake neutrality if the channel owns or is connected to Phraseman;
unverified app claims;
too many feature lists;
promises of instant fluency;
pressure that makes the lesson feel like bait.
```

### 21.12 The Ideal Description Standard

The description is not a landfill for keywords.

It should help the viewer decide, understand, and act.

Ideal description structure:

```text

Specific promise of the video.

2. Short context:

3. What the viewer will learn:
3-5 natural bullets.

4. Phraseman bridge if enabled:
one honest sentence with the practice reason.

5. Comment prompt:
specific question related to the video.

6. Search-friendly paragraph:
natural keywords, no stuffing.
```

No timestamps unless the user requests them.

Description must not reveal every payoff in a way that makes watching unnecessary.

### 21.15 The Ideal Teleprompter Standard

The text is written for a human speaking to camera.

Teleprompter rules:

```text
natural spoken paragraphs;
short sentences only for punchlines, hard concepts, and emphasis;
clear breathing points without breaking every thought into fragments;
no paragraph bricks, but also no artificial staccato;
no one-word line chains;
no constant dots after every small phrase;
no academic throat-clearing;
no "in this video we will explore" unless intentionally ironic;
examples on separate lines when useful;
hard words explained through context;
transitions that sound spoken, not written;
one idea per sentence when the concept is hard.
```

Dense-flow standard:

```text
For 8-12 minute scripts, default to a continuous charismatic monologue.
Use paragraphs that carry the thought forward.
Use pauses sparingly and intentionally.
The text should feel like a smart person speaking easily, not like notes chopped for a nervous presenter.
```

Read-aloud rejection signs:

```text
the sentence is hard to say in one breath;
the point arrives too late;
the joke needs punctuation to work;
the example is visually clear but verbally confusing;
the line sounds like a blog post;
the ad sounds like a separate sponsor read.
```

### 21.16 The Ideal Anti-AI Standard

The script must feel authored, not generated.

Human texture checklist:

```text

specific examples;
asymmetrical rhythm;
light imperfection in phrasing;
clear point of view;
unexpected but useful comparisons;
no generic motivational filler;
no repetitive transition phrases;
no list-shaped monologue unless the format needs it;
no fake warmth without a concrete teaching purpose.
```

AI smell list:

```text

"This is a game-changer"
"Unlock your potential"
```

## 23. Final Polish Protocol

Polish is not making the script prettier.

Polish is making every part of the package harder to ignore and easier to use.

The office must polish for:

```text

watchability;

character;

production ease.
```

Do not polish before the structure works.

### 23.1 Polish Order

Always polish in this order:

```text
1. Promise polish
Make sure the package promises one clear thing.

2. Structure polish
Make sure the viewer journey moves correctly.

3. Teaching polish
Make sure the explanation is simple and usable.

4. Example polish
Make sure examples sound natural and varied.

5. Rhythm polish
Make sure the script can be watched without sagging.

6. Character polish
Make sure Professor Lingman sounds distinct.

7. Humor polish
Make jokes sharper, fewer, and more useful.

8. Phraseman polish
Make the app feel like the next practical step.

9. Teleprompter polish
Make the text easy to say into camera.

10. Package polish
Make the final output clean, ordered, and production-ready.
```

If earlier polish fails, do not continue downward.

Fix the higher layer first.

### 23.2 Polish Levels

Use three polish levels.

#### Light Polish

Use for fast drafts.

```text
cut filler;
improve hook;
make examples clearer;
smooth transitions;
remove generic AI phrases.
```

#### Standard Polish

Use for normal production.

```text
repair title/script match;
strengthen first minute;
improve examples;
sharpen Lingman moments;
read-aloud pass;
Phraseman naturalness pass if enabled;
description pass.
```

#### Surgical Polish

Use for flagship videos.

```text
line-by-line spoken edit;
beat-by-beat retention edit;
title/thumbnail pressure test;
ad placement ranker;
humor density control;
red team re-check;
final package compression.
```

### 23.3 The Compression Pass

A polished script is usually shorter than the draft.

Cut:

```text
intro throat-clearing;
repeated explanation;
examples that teach the same point;
soft claims;
fake excitement;
obvious transitions;
long setup before the useful part;
product feature lists;
extra CTAs;
generic motivational endings.
```

Keep:

```text
the clearest mistake;
the strongest contrast;
the simplest mental model;
the most natural examples;
the sharpest Lingman line;
the most honest Phraseman bridge;
the most useful final payoff.
```

Compression rule:

```text
If cutting a line does not reduce clarity, emotion, trust, or usefulness, cut it.
```

### 23.4 The Spoken Rhythm Pass

The script must feel spoken, not written.

Check every paragraph:

```text
Can the presenter say this in one breath?
Does the sentence land before it becomes heavy?
Is there a clear place to pause?
Does the next sentence naturally follow?
Would this sound normal if said to one person?
```

Fixes:

```text
split long sentences;
move examples to separate lines;
replace abstract explanation with direct address;
turn dense paragraphs into beats;
add short reset lines after difficult ideas;
make the first word of each sentence less repetitive;
remove written transitions.
```

Useful reset lines:

```text
"Here is the trick."
"Look at the logic."
"Now watch the sentence change."
"That is the whole disease."
"And this is where English becomes rude for no reason."
"So what do we say instead?"
```

### 23.5 The First Minute Polish

The first minute gets special treatment.

It must contain:

```text
recognizable problem;
early proof;
one useful example;
one curiosity gap;
one clear reason to stay;
no slow intro;
no biography of the topic;
no generic welcome.
```

First-minute polish test:

```text
If the viewer leaves at 0:45, did they still get proof that the video was worth clicking?
```

If no, rewrite the opening.

### 23.6 The Explanation Polish

A polished explanation has a clean spine:

```text
wrong habit;
why it feels logical;
why English rejects it;
better model;
natural phrase;
practice cue.
```

Weak:

```text
Present Perfect is used for actions that started in the past and continue to the present.
```

Stronger:

```text
Past Simple puts the event in a finished box.
Present Perfect keeps a wire connected to now.
```

Polish moves:

```text
replace grammar definition with mental image;
explain why the mistake happens;
show the wrong sentence before the rule;
show the natural sentence immediately after;
add one real-life context;
name the pattern in five seconds or less.
```

### 23.7 The Example Polish

Examples must not be random.

Each example should answer:

```text
Where would someone say this?
What emotion does it carry?
What does it teach?
Is it natural enough to steal?
```

Upgrade examples by adding:

```text
message context;
work context;
friend context;
polite version;
casual version;
emotional version;
wrong version contrast;
Russian-logic warning if relevant.
```

Bad example set:

```text
I have eaten.
I have gone.
I have seen.
```

Better example set:

```text
I've already eaten, but thanks.
I've never seen this word used like that.
I've been trying to say this naturally for years.
```

The best examples feel immediately reusable.

### 23.8 The Lingman Polish

Professor Lingman should sound like a person with a mind, not a collection of jokes.

Polish his lines for:

```text
precision;
deadpan confidence;
warm authority;
small theatrical turns;
controlled sarcasm;
clear teaching payoff.
```

Weak Lingman line:

```text
This is a very common mistake.
```

Stronger Lingman line:

```text
This mistake is common because your brain is trying to be logical. Sadly, English filed a complaint.
```

Polish rule:

```text
Every Lingman joke must leave the viewer smarter than before the joke.
```

### 23.9 The Humor Polish

Humor polish means removing half-good jokes.

Keep a joke only if it:

```text
reveals the mistake;
makes the rule memorable;
creates rhythm;
fits Lingman;
does not delay the answer;
does not require too much explanation.
```

Cut jokes that:

```text
could be used in any video;
sound like internet filler;
mock the learner;
break the teaching flow;
arrive where the viewer needs clarity;
repeat an earlier comic move.
```

Humor density rule:

```text
High density in hook and transitions.
Medium density in examples.
Low density during core explanation.
Sharp return at the payoff.
```

### 23.10 The Phraseman Polish

Phraseman polish removes sales friction.

Bad ad feel:

```text
The lesson stops.
The app appears.
The viewer feels sold to.
```

Polished ad feel:

```text
The viewer understands the lesson.
The viewer sees the practice gap.
The app appears as the practical next step.
```

Polish every Phraseman mention through these questions:

```text
Does this mention continue the lesson?
Is the action specific?
Is the claim honest?
Is the feature list short?
Does the viewer know why to click now?
Would the video still feel useful without the app?
```

Strong bridge:

```text
"Understanding the phrase once is nice. Using it twenty times in the right context is where it becomes yours."
```

CTA polish:

```text
one action;
one reason;
one low-pressure invitation;
no pile of benefits.
```

### 23.11 The Title Polish

A polished title is specific enough to click and honest enough to trust.

Polish moves:

```text
replace broad topic with concrete pain;
replace abstract promise with visible outcome;
remove fake absolutes;
put the recognizable phrase near the front;
make the title shorter if the thumbnail carries part of the idea;
avoid cleverness that slows understanding.
```

Weak:

```text
Learn Present Perfect Easily
```

Stronger:

```text
Stop Translating Present Perfect Like This
```

Even stronger when supported by script:

```text
Past Simple vs Present Perfect: The Russian Trap
```

### 23.12 The Thumbnail Polish

Thumbnail polish is about instant recognition.

Check:

```text
one visual conflict;
one readable phrase;
one emotional signal;
no tiny grammar lecture;
no clutter;
clear connection to title;
clear first-minute payoff.
```

Polish moves:

```text
delete extra words;
increase contrast between wrong and right;
show the mistake visibly;
use fewer objects;
make the face or expression purposeful;
test at phone size;
remove clever details that disappear small.
```

Thumbnail text should feel like a slap of meaning, not a sentence.

### 23.13 The Description Polish

The description should sound written for this exact video.

Polish by checking:

```text
Does the first line promise the actual lesson?
Does it include the viewer pain?
Does it tell what the viewer will learn without spoiling every beat?
Does it include natural search phrases?
Does it include Phraseman only if relevant?
Does it invite a specific comment?
Could this description belong to any other video?
```

If yes to the last question, rewrite.

Remove:

```text
generic channel hype;
keyword stuffing;
empty motivational lines;
too many exclamation marks;
timelines unless requested;
duplicate CTAs.
```

### 23.14 The Final Package Polish

The final package must be easy to use.

Polish the output by:

```text
putting the best title first;
labeling alternatives clearly;
keeping thumbnail ideas scannable;
separating teleprompter text from notes;
keeping ad copy separate from light mentions;
making visual notes practical;
making QA short and decisive;
listing risks without drama;
ending with the next test.
```

The package should not make the user hunt for the important decision.

### 23.15 The Before/After Rewrite Format

When polishing an existing line, use:

```text
Original:

Problem:

Polished:

Why better:
```

Example:

```text
Original:
Today we are going to talk about common mistakes with prepositions.

Problem:
Too broad, slow, and familiar.

Polished:
If you say "interested on," your brain is not broken. It is just translating with fake confidence.

Why better:
It shows the mistake, removes shame, creates character, and starts the lesson immediately.
```

### 23.16 The Polish Stop Rule

Stop polishing when:

```text
the promise is clear;
the opening works;
the lesson is understandable;
examples are natural;
the script sounds speakable;
Lingman is present but not overwhelming;
Phraseman feels honest if enabled;
the package is easy to film;
the remaining changes are taste, not quality.
```

Do not polish until the script loses life.

Over-polished scripts become smooth and forgettable.

### 23.17 The Final Polish Checklist

Before final approval:

```text
[ ] The first line is not generic.
[ ] The first minute gives proof.
[ ] The main promise is repeated in different words, not forgotten.
[ ] The rule is explained with a mental model.
[ ] Examples feel usable in real speech.
[ ] At least one sentence is quotable.
[ ] Humor has a teaching function.
[ ] Phraseman has a practice reason if enabled.
[ ] The ad has one main CTA.
[ ] The description belongs only to this video.
[ ] The title and thumbnail match the first minute.
[ ] The script can be read naturally out loud.
[ ] The final package is clean.
```

### 23.18 Final Polish Verdict

A polished Lingman package feels like this:

```text
fast to understand;
easy to film;
sharp in promise;
clear in teaching;
alive in voice;
useful in examples;
honest in conversion;
clean in delivery.
```

The viewer should not feel the work.

They should feel:

```text
"I clicked for a problem, got the answer, laughed once or twice, and now I know what to practice."
```

## 26. High-Confusion Grammar Strengthening Protocol

High-confusion grammar topics are dangerous because they attract viewers but can easily become unclear.

Examples:

```text
in / on / at;
articles;
Present Perfect vs Past Simple;
conditionals;
phrasal verbs;
modal verbs;
gerund vs infinitive;
prepositions after adjectives;
word order.
```

The office must treat these topics differently from simple mistake corrections.

### 26.1 Scope Fence

Every high-confusion lesson needs a scope fence.

Scope fence answers:

```text
What exact part of the topic are we teaching?
What are we not teaching today?
What should the viewer be able to do after the video?
What would make this video too broad?
```

Weak:

```text
Today we explain all prepositions.
```

Strong:

```text
Today we explain the core IN / ON / AT model for common place and time phrases. We will not cover every idiom.
```

Rule:

```text
If the scope cannot be stated in one sentence, the topic is too broad.
```

### 26.2 Core Model First

The explanation must start with one core model.

The core model should be:

```text
visual;
short;
repeatable;
useful for many examples;
honest about its limits.
```

Example:

```text
IN = container.
ON = surface/system/day.
AT = exact point.
```

Do not start with exceptions.

Exceptions before the model create panic.

### 26.3 Example Clusters

High-confusion lessons need grouped examples.

Use clusters:

```text
place;
time;
movement;
work/school;
messaging;
social tone;
fixed chunks;
Russian translation traps;
common wrong versions.
```

Each cluster should include:

```text
wrong version if useful;
natural version;
one-sentence reason;
one phrase worth practicing.
```

### 26.4 Exception Parking Lot

Do not hide exceptions.

Also do not let exceptions eat the lesson.

Use an exception parking lot:

```text
Important exception:

Why it matters:

What to do:
practice as a chunk / save for another episode / mention briefly.
```

Example:

```text
Important exception:
at night

Why it matters:
It does not behave like a normal time period.

What to do:
practice it as a fixed chunk.
```

### 26.5 Chunk Practice Rule

When the topic has many exceptions, the practice path must shift from rules to chunks.

Formula:

```text
Understand the model.
Practice the phrases.
Let repetition handle the fixed expressions.
```

This is where Phraseman often fits naturally.

Phraseman bridge:

```text
The model gives the map.
Phrase practice gives the reflex.
```

### 26.6 Anti-Overclaim Rule

Never say:

```text
This rule always works.
This explains every case.
Now you will never confuse them again.
Master all prepositions in one video.
```

Say:

```text
This model handles many common cases.
Some phrases are fixed by usage.
We practice those as chunks.
This video gives you a map, not the whole country.
```

### 26.7 High-Confusion QA Additions

For high-confusion topics, QA must check:

```text
[ ] Scope is narrow enough.
[ ] Core model is stated early.
[ ] Examples are grouped.
[ ] Exceptions are named but controlled.
[ ] The lesson does not promise total mastery.
[ ] Phraseman practice focuses on chunks, not abstract rules.
[ ] The title does not overpromise.
[ ] The ending gives one usable model and one practice list.
```

### 26.8 High-Confusion Verdict

The best high-confusion lesson does not make the viewer think:

```text
I now know every rule.
```

It makes the viewer think:

```text
I finally have a model, and I know what to practice.
```

## 27. Tense Contrast Strengthening Protocol

Tense contrast topics are difficult because the learner often knows both forms but does not know when to choose each one.

Examples:

```text
Past Simple vs Present Perfect;
Past Simple vs Past Continuous;
Present Perfect vs Present Perfect Continuous;
will vs going to;
used to vs would;
Present Simple vs Present Continuous;
Future Simple vs Present Continuous for plans.
```

The office must not explain tense contrasts as isolated definitions.

It must teach a decision.

### 27.1 Time Anchor

Every tense contrast lesson must identify the time anchor.

Time anchors include:

```text
finished time words;
unfinished time words;
specific dates;
recent results;
life experience;
duration;
background action;
planned arrangement;
speaker intention;
evidence visible now.
```

The time anchor answers:

```text
What part of the context changes the tense?
```

Example:

```text
yesterday
```

usually pushes:

```text
Past Simple.
```

### 27.2 Contrast Pair

Every tense contrast lesson needs contrast pairs.

Format:

```text
Sentence A:

Sentence B:

What changed:

Why it matters:
```

Example:

```text
Sentence A:
I lost my keys yesterday.

Sentence B:
I've lost my keys.

What changed:
Finished time story vs present result.

Why it matters:
One is about when it happened; the other is about why it matters now.
```

### 27.3 Decision Test

Every tense contrast lesson must give a decision test.

Good decision tests are:

```text
short;
usable while speaking;
based on meaning, not terminology;
connected to examples;
repeated at least twice.
```

Example:

```text
Is the time finished and specific?
Or is the result/experience connected to now?
```

If the viewer cannot use the test without grammar vocabulary, simplify it.

### 27.4 Wrong Camera, Right Camera

Show the wrong way to look at the situation.

Then show the better way.

Example:

```text
Wrong camera:
It happened before now, so use Past Simple.

Right camera:
Is it a finished story, or does it still matter now?
```

This makes the misconception visible.

### 27.5 Practice Pairs

For tense contrast topics, examples should come in pairs.

Practice pair examples:

```text
I saw him yesterday.
I've seen him before.

I finished it last night.
I've finished it.

She went home two hours ago.
She's gone home.
```

Phraseman integration should use these pairs as practice missions.

### 27.6 Cognitive Load Limit

Do not teach every use in one episode.

Limit the lesson to:

```text
one main contrast;
one decision test;
three to five contrast pairs;
one edge-case warning;
one practice mission.
```

If the topic needs more, create a series.

### 27.7 Tense Contrast QA Additions

QA must check:

```text
[ ] The main contrast is clear.
[ ] The time anchor is named.
[ ] The contrast pair appears in the first minute.
[ ] The decision test is short enough to use while speaking.
[ ] Examples appear in pairs.
[ ] Edge cases are parked.
[ ] Phraseman practice uses contrast pairs.
[ ] The title does not promise total mastery.
```

### 27.8 Tense Contrast Verdict

The best tense contrast lesson does not make the viewer recite a definition.

It makes the viewer think:

```text
I know what question to ask before choosing the tense.
```

## 28. Quick Correction Strengthening Protocol

Quick correction topics are small mistakes with high recognition and high short-form potential.

Examples:

```text
I very like it;
I am agree;
interested on;
depend from;
explain me;
say me;
more better;
I feel myself.
```

The office must not inflate these topics into heavy grammar lectures.

It must create fast clarity, phrase upgrades, and reusable clips.

### 28.1 Core Error

Every quick correction lesson must name the exact wrong pattern.

Format:

```text
Wrong pattern:

Why learners say it:

Natural replacement:
```

Example:

```text
Wrong pattern:
I very like it.

Why learners say it:
Russian "очень" feels like one universal intensifier.

Natural replacement:
I really like it.
```

### 28.2 Word Function Check

Quick corrections often depend on a tiny word-function difference.

The script must identify it.

Examples:

```text
very + adjective;
really + verb;
agree = verb;
interested + in;
explain + object + to person;
better already contains more.
```

Rule:

```text
Name the grammar only as much as the correction needs.
```

### 28.3 Correction Reflex

The viewer needs a reflex, not a lecture.

Correction reflex format:

```text
When you want to say X, say Y.
```

Examples:

```text
When you want "очень + verb", use really + verb.
When you want "я согласен", say I agree.
When you want "объясни мне", say explain it to me.
```

The reflex must be repeated at least twice.

### 28.4 Before/After Upgrade

Quick correction scripts must include before/after lines.

Format:

```text
Before:

After:

Better:

More natural:
```

Example:

```text
Before:
I very like it.

After:
I really like it.

Better:
I love it.

More natural:
I'm really into it.
```

### 28.5 Shorts Hook

Every quick correction lesson must generate at least five shorts hooks.

Shorts hook rules:

```text
start with the mistake;
give the correction fast;
show one tiny rule;
avoid slow setup;
end with a phrase the viewer can steal.
```

Example:

```text
Do not say "I very like it." Say "I really like it."
```

### 28.6 Phrase Upgrade Ladder

After correcting the mistake, give better phrases.

The ladder:

```text
correct;
natural;
casual;
strong;
expressive;
polite if relevant;
work/message version if relevant.
```

This prevents simple topics from feeling too thin.

### 28.7 Phraseman Fit

Quick correction topics should usually connect to Phraseman through phrase replacement practice.

Bridge:

```text
The mistake is small, but the reflex needs repetitions.
```

Phraseman mission format:

```text
Practice these replacement chunks:

wrong habit -> natural phrase;
basic correction -> stronger phrase;
formal/casual variants.
```

Avoid feature dumps.

### 28.8 Quick Correction QA Additions

QA must check:

```text
[ ] The mistake appears in the first 5 seconds.
[ ] The correction appears in the first 20 seconds.
[ ] The tiny rule is clear.
[ ] The topic is not over-expanded.
[ ] There are phrase upgrades.
[ ] There are at least five shorts moments.
[ ] The Phraseman bridge is phrase-replacement practice.
[ ] The ending gives one reflex phrase.
```

### 28.9 Quick Correction Verdict

The best quick correction lesson makes the viewer think:

```text
I know exactly what to stop saying and what to say instead.
```

It should feel fast, useful, and easy to share.

## 29. Social Temperature Strengthening Protocol

Social communication topics are not only about correct phrases.

They are about how a sentence feels in a relationship.

Examples:

```text
polite disagreement;
requests;
apologies;
refusals;
workplace feedback;
small talk;
asking for help;
softening criticism;
customer service;
online replies.
```

The office must not output generic phrase lists for these topics.

It must teach tone control.

### 29.1 Social Temperature

Every social communication lesson must name the temperature of phrases.

Temperature scale:

```text
cold;
direct;
neutral;
warm;
diplomatic;
too much.
```

Example:

```text
I disagree.
Temperature: direct/cold depending on context.

I'm not sure I agree.
Temperature: neutral/soft.

I see your point, but...
Temperature: warm/diplomatic.
```

The viewer should understand not only what the phrase means, but how it lands.

### 29.2 Relationship Context

Every phrase must be tied to a relationship.

Relationship contexts:

```text
friend;
colleague;
boss;
client;
stranger;
teacher;
online comment;
group meeting;
close relationship;
formal situation.
```

Rule:

```text
No social phrase should appear without a situation unless it is clearly universal.
```

Weak:

```text
Use "I see your point."
```

Strong:

```text
Use "I see your point, but..." with a colleague when you want to acknowledge their idea before raising a concern.
```

### 29.3 Risky Direct Version

Show the phrase learners may say when translating directly.

Format:

```text
Risky direct version:

Why it feels risky:

Safer version:
```

Example:

```text
Risky direct version:
You're wrong.

Why it feels risky:
It attacks the person more than the idea.

Safer version:
I'm not sure that's quite right.
```

This makes the communication problem visible.

### 29.4 Softened Version

Softened versions should preserve meaning, not erase it.

Good softening:

```text
I see your point, but I think the timeline may be difficult.
```

Bad softening:

```text
Maybe, perhaps, possibly, if it is not too terrible, I might have a tiny thought.
```

Rule:

```text
Polite does not mean weak. It means controlled.
```

### 29.5 Tone Ladder

Every social communication lesson should include a tone ladder.

Format:

```text
too direct;
direct;
neutral;
warm;
diplomatic;
strong but controlled.
```

Example:

```text
Too direct:
You're wrong.

Direct:
I disagree.

Neutral:
I'm not sure I agree.

Warm:
I see your point, but...

Diplomatic:
I can see why you'd say that. My concern is...

Strong but controlled:
I don't think that's quite right.
```

### 29.6 Situation Test

Social topics need scenario-based micro-tests.

Format:

```text
Situation:

Relationship:

Goal:

Phrase options:

Best answer:

Why:
```

Example:

```text
Situation:
Your boss suggests a risky timeline.

Relationship:
boss.

Goal:
disagree without sounding dismissive.

Best answer:
I see your point. My concern is the timeline.
```

### 29.7 Phraseman Fit

Phraseman should be positioned as situational phrase practice.

Mission format:

```text
Practice phrase sets by relationship:

friend;
work;
boss/client;
online;
strong but controlled.
```

Bridge:

```text
The phrase is not enough. You need to practice choosing it in the right situation.
```

Avoid:

```text
generic "download the app" language;
long feature lists;
pretending one phrase works everywhere.
```

### 29.8 Social Temperature QA Additions

QA must check:

```text
[ ] The lesson names the social risk.
[ ] Phrases are tied to relationship context.
[ ] There is a temperature scale or tone ladder.
[ ] The script avoids generic phrase-list output.
[ ] The viewer gets situation-based tests.
[ ] The Phraseman mission practices phrases by situation.
[ ] The title does not promise one magic phrase for every context.
[ ] The final payoff gives one safe default phrase.
```

### 29.9 Social Temperature Verdict

The best social communication lesson makes the viewer think:

```text
I know not only what to say, but when and how to say it.
```

It should teach English as social control, not just vocabulary.

## 30. Bug Audit And Hardening

Bug searches are part of the pipeline.

The office should not only add new features.

It should find where the system contradicts itself, where templates fall behind, and where checks create false confidence.

### 30.1 Bug Classes To Search

Search for these bug classes:

```text
template drift:
new protocol fields exist in one place but not in another.

QA drift:
new risks are added but the QA report does not check them.

mode bloat:
all fields are forced into every brief even when irrelevant.

test-loop drift:
test requirements say one thing, but test files use another format.

scorecard drift:
score checks count lines outside the scorecard.

master-prompt drift:
the full pipeline has a rule that the master prompt does not know.

overclaim drift:
titles, descriptions, or scripts promise more than the lesson can teach.

Phraseman drift:
app mentions become generic, too frequent, or disconnected from practice.
```

Bug audit file:

```text
LINGMAN_BUG_AUDIT_001.md
```

Findings fixed:

```text

3. There was no canonical QA Report Format for new protocol checks.
4. Test run naming examples stopped at Test Run 003 while the system already had Test Runs 004 and 005.
5. Test Run Verdict Format omitted "Files updated" even though Required Test Run Output demanded it.
6. Scorecard checking could accidentally match score-like labels outside the scorecard block.
```

Fixes applied:

```text
1. Added specialized notes to the Production Command Template.
2. Added a Field Rule: fill specialized fields only when relevant; use N/A otherwise.
3. Added QA Report Format to the full pipeline and master prompt.
4. Updated test run file naming examples through Test Run 006.
5. Added Files updated to the Test Run Verdict Format.
6. Added Scorecard Integrity Rule.
```

Findings fixed:

### 30.6 Bug Audit Procedure

When the user asks for "поиск багов", run this procedure:

```text
1. Compare full pipeline vs master prompt.
2. Compare master prompt vs test run outputs.
3. Compare test run recommendations vs applied updates.
4. Check whether new fields appear in brief, command template, QA, and relevant protocol.
5. Check whether final output format includes the new behavior.
6. Check scorecard integrity.
7. Check for generic AI phrases.
8. Patch real bugs immediately.
9. Create or update a bug audit note.
10. Report fixes and remaining risks.
```

### 30.7 Bug Severity

Use:

```text
P0:
bug can make the final script false, misleading, or trust-breaking.

P1:
bug can make the pipeline ignore an important protocol or QA check.

P2:
bug creates drift, bloat, inconsistency, or slower production.

P3:
bug is cosmetic or naming-related.
```

### 30.8 Bug Audit Rule

Every bug fix must answer:

```text
What broke?
Why it matters?
Where fixed?
How to prevent it next time?
```

If the answer is vague, the fix is not complete.

## 31. Workplace Message Strengthening Protocol

Workplace-message topics are not vocabulary lessons.

They are task-completion lessons.

Examples:

```text
follow-ups;
scheduling;
status updates;
asking for clarification;
handing off tasks;
reviewing docs;
delaying meetings;
client messages;
internal team messages.
```

Rule:

```text
Every phrase must answer what action the message should make happen.
```

### 31.1 Workplace Context

Name the channel and situation before teaching phrases.

Use:

```text
Slack / Teams;
email;
meeting;
client note;
internal update;
manager-to-team;
teammate-to-teammate.
```

Without context, the phrase becomes trivia.

### 31.2 Message Intent

Every phrase needs a job.

Common intents:

```text
reply later;
investigate;
review;
schedule;
delay;
mention carefully;
follow up;
hand off;
confirm;
ask for clarification;
close the loop.
```

The viewer should know when to use the phrase, not just what it means.

### 31.3 Register Level

Label the register:

```text
casual work chat;
neutral professional;
formal;
too casual for clients;
too stiff for teammates.
```

If a phrasal verb sounds too casual, give a formal alternative.

### 31.4 Task Outcome

Tie each phrase cluster to the desired outcome.

Examples:

```text
get an answer;
reduce pressure;
ask for time;
move a task forward;
avoid blame;
sound helpful;
sound decisive;
make the next step clear.
```

The lesson wins when the viewer can send a better message immediately.

### 31.5 Phrase Cluster

Group phrases by action, not alphabetically.

Good clusters:

```text
Follow up:
check in, circle back, follow up on.

Review:
look over, go through, double-check.

Delay:
push back, move back, hold off on.

Raise carefully:
bring up, flag, point out.
```

Bad cluster:

```text
Ten random phrasal verbs for work.
```

### 31.6 Message Template

Every workplace-message lesson should include reusable message templates.

Template format:

```text
Phrase + object + reason + next step.
```

Example:

```text
I'll look over the draft this afternoon and send comments before 4.
```

Templates should sound ready to send, not like grammar exercises.

### 31.7 Phraseman Fit

Phraseman integration should practice full message chunks.

Use missions like:

```text
Rewrite this stiff message into natural work English.
Choose the right phrasal verb for the intent.
Make this Slack reply warmer without making it weak.
Turn a Russian-style direct request into a clear English work message.
```

Do not make the app practice isolated verbs when the lesson is about workplace communication.

### 31.8 Workplace Message QA Additions

For workplace-message episodes, QA must check:

```text
[ ] Workplace context is named.
[ ] Every phrase has a message intent.
[ ] Register level is clear.
[ ] At least one formal alternative is given where needed.
[ ] Phrase clusters are grouped by task outcome.
[ ] Phraseman mission practices full message chunks, not isolated verbs.
[ ] The title does not promise all phrasal verbs.
[ ] Final payoff gives one reusable message template.
```

### 31.9 Workplace Message Verdict

A workplace-message script passes only if the viewer can use at least one phrase today in a real message.

If the viewer only learned definitions, the lesson failed.

## 32. Algorithm Control Layer

The office needs a control layer so it does not behave like a giant checklist.

The control layer answers:

```text
What are we making?
Which route should run?
Which protocols are truly relevant?
What is the highest-risk failure?
What should be repaired first if the output is weak?
```

### 32.1 Request Classification

Classify every user request before production.

Use:

```text
idea generation;
full script;
series design;
shorts pack;
existing script improvement;
pipeline audit;
bug fix;
post-publish analysis;
style calibration.
```

If the request is ambiguous, choose the mode that produces the most useful next artifact.

### 32.2 Protocol Activation Matrix

Activate protocols by topic type.

```text
High-confusion grammar:
SCOPE FENCE, EXCEPTION PARKING LOT.

Tense contrast:
TIME ANCHOR, CONTRAST PAIR, DECISION TEST.

Quick correction:
CORE ERROR, WORD FUNCTION CHECK, CORRECTION REFLEX, SHORTS HOOK.

Social communication:
SOCIAL TEMPERATURE, RELATIONSHIP CONTEXT, TONE LADDER.

Workplace message:
WORKPLACE CONTEXT, MESSAGE INTENT, REGISTER LEVEL, TASK OUTCOME, PHRASE CLUSTER, MESSAGE TEMPLATE.

Phraseman-heavy episode:
practice gap, native ad position, conversion guard, CTA variant.
```

Do not activate a protocol just because it exists.

### 32.3 Evidence Ladder

Every major recommendation should label its evidence level.

```text
Level 1:
hard channel data.

Level 2:
platform-visible pattern or repeated comments.

Level 3:
reasoned audience assumption.

Level 4:
creative hypothesis.
```

Level 4 can be used, but it must not pretend to be data.

### 32.4 Conflict Resolver

When agents disagree, use this order:

```text
truth over click;
clarity over cleverness;
viewer trust over conversion;
one strong lesson over broad coverage;
spoken rhythm over written elegance;
natural phrase over literal grammar explanation;
repeatable format over one-off gimmick.
```

The Final Director must name the winning principle when a conflict matters.

### 32.5 Viewer Experience Trace

For full scripts, the office should simulate the viewer's state.

Use:

```text
0:00-0:15
Do I know why I clicked?

0:15-1:00
Did the video prove the title promise?

1:00-3:00
Do I understand the mental model?

3:00-6:00
Am I getting examples and small payoffs?

ad moment
Does the Phraseman mention feel like the next step?

final minute
Can I do something now?
```

If any beat has no viewer payoff, repair that beat.

### 32.6 No Dead Field Rule

Every field in the brief must do work.

If a field does not change:

```text
title;
hook;
example choice;
script structure;
Phraseman placement;
QA;
or final recommendation;
```

then remove it or mark it N/A.

### 32.7 Repair Priority

Repair in this order:

```text
1. False or overbroad promise.
2. Wrong route.
3. Unclear lesson model.
4. Weak first-minute receipt.
5. Boring middle.
6. Generic Lingman voice.
7. Forced Phraseman integration.
8. Weak description or shorts extraction.
```

Do not polish language while the route or promise is broken.

### 32.8 Algorithm Output Requirement

Every full production package should include:

```text
Routing snapshot:
route, active protocols, skipped protocols, main risk.

QA report:
routing fit, promise match, first-minute receipt, learning clarity, examples, research depth, official sources, fact-check status, interesting information, voice, humor, Phraseman, teleprompter, conversation flow, type-specific check.

Repair note:
what was improved before final delivery.
```

### 32.9 Algorithm Upgrade Verdict

The algorithm is stronger when it makes fewer random decisions.

Good algorithm behavior:

```text
fast route selection;
small number of relevant active protocols;
clear conflict resolution;
specific loopbacks;
visible repair history;
no generic output.
```

Bad algorithm behavior:

```text
every agent runs on every request;
every field appears in every brief;
all recommendations sound equally confident;
quality checks are listed but do not change the output;
Phraseman is inserted because it is required, not because the lesson creates a practice gap.
```

## 33. Agent Accountability Layer

The office has many agents, so the quality problem is no longer "more agents."

The quality problem is agent accountability.

### 33.1 Agent Role Types

Every agent belongs to one primary role type.

```text
Router:
chooses path and active protocols.

Researcher:
brings outside evidence or audience language.

Architect:
turns raw material into structure.

Creator:
writes, packages, designs, or rewrites.

Auditor:
finds risks and blocks weak work.

Polisher:
improves clarity, rhythm, voice, or readiness.

Memory agent:
learns from results and updates patterns.
```

An agent can assist another layer, but it should not quietly take ownership from the correct owner.

### 33.2 Agent Decision Rights

Each agent must know what it can decide.

Examples:

```text
Title Testing & Analytics Lab:
can recommend title winner, but cannot approve a misleading promise.

Human Humor Agent:
can add or cut jokes, but cannot sacrifice teaching clarity.

Phraseman Ad Integration Agent:
can choose the best ad point, but Conversion Guard can block it.

Pedagogy QA Agent:
can block a charismatic explanation if the rule is false or overbroad.

Final Director:
can override agents, but must name the reason and risk.
```

### 33.3 Agent Block Rights

Block rights are reserved for trust-breaking risks.

Block if:

```text
route is wrong;
title promise is false;
grammar or usage is wrong;
examples are unnatural;
ad is forced or misleading;
script cannot be read naturally;
QA is missing a required check;
agent output is vague and non-actionable.
```

Do not block for taste alone.

Taste disagreements become variants, not blockers.

### 33.4 Agent Evidence Labels

Agents must label how confident their advice is.

```text
Data-backed:
based on channel data, A/B tests, analytics, or reliable source.

Observed pattern:
based on repeated platform comments, competitor patterns, or audience phrasing.

Heuristic:
based on known YouTube/scriptwriting principles.

Taste:
based on style judgment.

Creative hypothesis:
worth testing, not proven.
```

No agent may present taste as data.

### 33.5 Agent Repair Standard

A weak agent report says what is wrong.

A strong agent report fixes or routes the problem.

Required repair format:

```text
Problem:
specific beat, line, field, title, ad moment, or example.

Why it matters:
viewer, learning, trust, retention, or conversion impact.

Repair:
exact replacement or responsible owner.

Expected improvement:
what should be better after repair.
```

### 33.6 Agent Anti-Overlap Rule

When two agents touch the same material, use ownership.

```text
Packaging owns click.
False Promise owns honesty.
Hook Surgeon owns first 30 seconds.
Curriculum owns learning structure.
Pedagogy owns correctness.
Example Density owns quantity and usefulness of examples.
Native Naturalness owns whether English sounds real.
Lingman Voice owns character.
Human Humor owns punchlines.
Cognitive Load owns ease.
Retention owns watchability.
Phraseman Integration owns ad concept.
Conversion Guard owns ad trust and rhythm.
Teleprompter owns speakability.
Final Director owns delivery decision.
```

If overlap creates conflict, Final Director resolves by principle, not by averaging opinions.

### 33.7 Agent Skip Rule

Skipping an agent is allowed when:

```text
the route does not need it;
the output is too small;
the protocol is irrelevant;
the agent would only repeat another agent's check.
```

Skipping is not allowed when:

```text
the agent protects truth;
the agent protects promise match;
the agent protects ad trust;
the agent protects spoken readability;
the user specifically requested that function.
```

### 33.8 Agent Performance Memory

After real publishing data exists, track agent performance.

Use:

```text
Packaging prediction accuracy.
Hook retention accuracy.
Humor comment response.
Phraseman conversion prediction.
Pedagogy clarity comments.
Description/search contribution.
Shorts extraction performance.
```

Agents that repeatedly predict poorly must update their heuristics.

### 33.9 Agent Upgrade Verdict

An improved agent office should feel like this:

```text
fewer vague comments;
clearer ownership;
faster loopbacks;
stronger blockers;
less duplicated work;
more precise repairs;
better final scripts.
```

If adding agents creates more confusion than quality, remove or merge agents.

## 34. Golden Rule

The office does not produce "content."

It produces a complete viewing experience:

```text
Click -> confirmation -> curiosity -> understanding -> laughter -> practice -> payoff -> action.
```

If any part of that chain is weak, the pipeline loops back and fixes it.
