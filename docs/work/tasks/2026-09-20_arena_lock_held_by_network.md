## Корень

`reserveArenaCall` (`app/arena_client.ts:510`) оборачивает в
`withAccountTransitionLock` вызов `prepareArenaCall`, а тот внутри делает ДВА
СЕТЕВЫХ вызова:

```
await ensureStableAuthLink().catch(() => false);      // привязка аккаунта на сервере
await initFirebaseAppCheckIfAvailable().catch(() => {});
```

Замок (`account_generation.ts:174`) — честная очередь: `await previous` ждёт
предыдущего владельца БЕЗ таймаута. Пока один вызов Арены ждёт сеть, ВСЕ
остальные владельцы замка стоят. На моргнувшей сети это минуты.

В проекте 231 вызов этого замка — страдает не только Арена.

## Scope

In scope: `app/arena_client.ts` — сетевой bootstrap выносится ИЗ-ПОД замка.

Out of scope: сам механизм замка (его чинить — отдельная большая задача),
остальные 230 вызовов.

## Architecture

**Что защищает замок.** Смену поколения аккаунта: пока идёт переход, нельзя
отправить запрос от имени старого владельца. Для этого достаточно ПРОВЕРКИ
владельца до и после подготовки — она локальная и мгновенная.

**Что НЕ должно быть под замком.** Сетевой bootstrap
(`ensureStableAuthLink`, App Check) — он не меняет поколение аккаунта и может
длиться сколько угодно.

**Решение.** Bootstrap выполняется ДО захвата замка. Под замком остаётся
только создание callable и проверка владельца — обе операции локальные.

**Инвариант.** Под замком аккаунта не выполняется ни один сетевой вызов.

## Security and privacy

Защита сохранена: владелец проверяется под замком до и после подготовки,
как и прежде. Bootstrap вынесен, но он и не зависит от поколения.
