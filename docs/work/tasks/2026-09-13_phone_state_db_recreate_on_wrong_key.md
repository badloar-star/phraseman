## Outcome

Владелец сообщил: «наборы грузятся вечно», затем экран «Не удалось проверить
лимит тренировок». Логи доказали, что починка из `6823b8de2` **не сработала
вообще**: ни одной строки `[PHONE-STATE-DB]`, а `bootstrap:FAILED — file is not
a database` повторяется на каждом запуске.

Причина моей ошибки: перехват стоял на `openPhoneStateDatabase`, но SQLCipher
**не проверяет ключ при открытии** — `openDatabaseAsync`, `PRAGMA key` и даже
`PRAGMA cipher_version` проходят успешно на нерасшифровываемом файле. Ошибка
`SQLITE_NOTADB (code 26)` вылетает позже, при первом реальном чтении страницы
базы — в `readUserVersion` внутри `migratePhoneStateSchema`
(`app/phone_state_runtime.ts:316`), то есть НА СТРОКУ НИЖЕ моего `catch`.

Наблюдаемый результат: при нечитаемой базе в логах появляется
`[PHONE-STATE-DB] … пересоздаём`, затем `… пересоздана успешно`, bootstrap
завершается успехом, мост phone-state поднимается, квота читается, наборы
грузятся без вечного спиннера.

## Architecture

Границы не меняются. Правка усиливает УЖЕ принятый контракт
`openPhoneStateDatabase`: «вернуть работоспособную базу либо бросить».
Сейчас контракт нарушался — функция возвращала базу, которая падает при первом
чтении, перекладывая обработку на вызывающего.

Инвариант безопасности сохраняется: пересоздание по-прежнему срабатывает ТОЛЬКО
на подписи `SQLITE_NOTADB`. `phone_state_sqlcipher_unavailable` и
`phone_state_cipher_integrity_failed` летят наверх как раньше — аварийное
удаление данных из-за отсутствия SQLCipher недопустимо.

Почему `PRAGMA user_version`, а не что-то иное: это самое дешёвое обращение к
данным (чтение заголовка), его же первым делает `migratePhoneStateSchema` —
значит воспроизводит ровно тот отказ, что наблюдался в логах, не добавляя
нового поведения.

## Security and privacy

Персональные данные, авторизация, секреты не затрагиваются. Ключ шифрования
по-прежнему живёт только в Keychain и в коде не логируется (в лог попадает
только имя файла базы).

Риск потери данных: пересоздание удаляет локальный файл. Это неизбежно —
расшифровать его нечем; иначе приложение неработоспособно навсегда. Данные
восстанавливаются из локального legacy-хранилища (`importLegacy`) и облака.
Правка НЕ расширяет условия удаления, а лишь делает достижимой уже одобренную
владельцем ветку.
