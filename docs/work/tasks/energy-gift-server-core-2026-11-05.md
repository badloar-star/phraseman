# Task packet: серверный «подарок энергии» (за флагом OFF)

## Outcome
Сервер для подарка +1 энергии между друзьями по правилу владельца «разрешить с лимитом»: отправитель 1 в сутки, получатель до 3 в сутки, только друзьям ≥ 24 ч, не себе, не получателю с Plus. Функции `energyGiftSend` и `energyGiftClaim` не работают, пока в remote config не включён `bools.energy_gift_enabled` (по умолчанию его нет = выключено).

## Scope
- `functions/src/energy_gift_core.ts` — чистые правила и счётчики (без Firestore), тест `functions/src/energy_gift_core.test.ts`.
- `functions/src/energy_gift.ts` — callable `energyGiftSend` / `energyGiftClaim`, тест формы ответов.
- Позже отдельным коммитом: правила базы (`firestore.rules`), индекс COLLECTION_GROUP `energy_gifts.fromUid`, спека удаления аккаунта, экспорт в `index.ts`. Эти общие файлы сейчас грязные у других сессий, правки только своими хунками.
- Клиент (копилка, кнопки) — «Моменты»; журнал энергии (вариант B, списание копилки внутри операции) — отдельный патч «Ядра» после.

## Architecture
Формы по согласованию с «Моментами»: send → `{ ok, giftId, remainingToday }`, claim → `{ ok, bank, applied }`. Коды `HttpsError`: `not_friends_24h`, `quota_sender`, `quota_receiver`, `plus_receiver`, `self`. Данные: `users/{to}/energy_gifts/{giftId}` со статусом `pending|claimed|void` и счётчики `energy_gift_quota/{uid}` (`dayKey`, `sent`, `received`). Возраст дружбы берётся из серверного `createTime` документов рёбер дружбы (поля документа клиент пишет сам, им верить нельзя). Всё в одной транзакции, повтор — тот же ответ (идемпотентно по giftId). Сутки по UTC серверного времени.

## Security and privacy
Требуется вход; личность из auth. Друзья проверяются по двум рёбрам. Новая запись связывает идентификаторы друзей и время — абзац в политику конфиденциальности до выкладки; удаление аккаунта обязано чистить подарки (collection-group по `fromUid`). Идентификаторы в логах обрезаются до 6 символов.

## Technical debt
Лимиты зашиты константами в ядре; при необходимости вынести в remote config `numbers`. Ограничение «≥ 24 ч» защищает от накрутки только частично (альтернативные аккаунты).

## Verification
Юнит-тесты ядра (порядок отказов, сутки, срок жизни, Plus, повтор). Сухой прогон выкладки — только после того, как все четыре общих файла закоммичены. Включение флага — только после проверки на устройстве двумя аккаунтами.

## Rollback
Выключить флаг (ключ отсутствует = выключено). Функции безвредны без клиента; откат кода — `git revert` коммита и адресная выкладка.
