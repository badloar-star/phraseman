## Architecture

- Правило владельца 01.09 «празднование не durable»: модель строит историю из двух состояний очков (до и после) —
  `buildSkillLevelUpStory` / `pickSkillLevelUpStory`. Уровень на деле не вырос — истории нет. Ничего не сохраняется.
  Источник «до» уже есть: `takeSkillSessionBase()` хранилища навыков (только в памяти).
- Одна история за раз: если за занятие выросло несколько навыков — тот, что поднялся на больше уровней, затем выше новый.
- Экран «глупый»: получает историю и колбэки `onClose`, `onTrain?`, `topRight?`; ничего не читает и не пишет.
- Движение — числами макета (`elevate-mechanics.css`, `elevate-extra.css`): деление 800 мс cubic-bezier(.2,.8,.2,1)
  через 60 мс; через 500 мс — звезда 1400 мс, отсчёт числа 500 мс (кубическое затухание) с подскоком 650 мс, вспышка
  18 искр 1100 мс cubic-bezier(.1,.8,.3,1) с лесенкой 18 мс, пульс 1,4 с ease-out дважды (×2,1), подсветка подписи 240 мс;
  второй кадр — прозрачность 400 мс, полоска через 300 мс за 1100 мс.
- Звезда истории своя (`SkillLevelUpStar`): в общем `SkillsStar` переход 1300 мс, в истории макета — 1400.

Решения по спорному (сообщены координатору):
- Строка «За две недели ты узнал 46 новых слов» — данных за две недели нет; оставлена только фактическая часть
  «Луч «Словарь» стал длиннее».
- «Нужно N очков» — показывается остаток до следующего уровня (в макете — полная цена уровня при уже заполненной полоске).
- Второй кадр «Быстрее всего растёт» — текст из `SKILL_SOURCE` без повтора «Растёт».
- Кнопка «Тренировать» — только при `onTrain` и не для «Социального» (его не тренируют, решение владельца 11.11).
- На последнем, 30-м уровне второго кадра нет (до 31-го уровня не бывает).
- Плашка монет в шапке — через `topRight`; градиент кнопки макета заменён цветом кнопки палитры.
