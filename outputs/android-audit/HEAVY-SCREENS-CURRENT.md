## Minimal deterministic RED work-count contracts (proposals, not tests)

1. **Gallery layout work:** instrument `fitAtScale`; a build over `N` cards performs exactly `N` initial fit calls, and constructs one grid. This exposes full-array preprocessing even when only a small visible window is rendered. Separately assert rendered `Tile` count equals the computed visible slice length and remains within the row-window range including its two-row overscan.
2. **Dialogue list work:** with `N` supplied messages, the screen currently maps `N` message subtrees; the report transcript considers at most 12. Keep these counts separate in any work-count test. If the intended UI work budget is lower than `N`, define that bound before changing the current ScrollView contract; the source alone supplies only a server cap of 64 turns, not a measured or device-verified acceptable render budget.
3. **Lifecycle work:** assert cleanup of the gallery batch timer on unmount. For dialogue keyboard-show timers, first define whether a callback scheduled before blur/unmount must be cancelled; current source does not retain its handle.

These are operation-count contracts only. This audit does not establish that either screen causes observed lag.
