# Протокол параллельных сессий: один редактор ветки без потери работы (PM-244)

Сложился 03–04.10.2026 на реальных инцидентах (INBOX §120, §136, §139). Действует для ВСЕХ сессий в одном рабочем дереве; правило владельца «не плодить дополнительные рабочие копии дерева и ветки» (CLAUDE.md) остаётся в силе — изоляция достигается не копиями дерева, а порядком коммита.

## 1. Кто что делает
- Одна рабочая ветка, одно дерево. Писать (менять файлы) могут все сессии, но каждая коммитит ТОЛЬКО свои пути.
- Ревьюеры и разведчики — только чтение (агент типа Explore/Plan не редактирует). Вердикт ревью пишется в отчёт, статус задачи меняет исполнитель/координатор.
- Файл с чужими незакоммиченными правками (статус файла в git не пуст, а правки не твои) — не править; обойти или сообщить «файл редактируется в другой сессии».
- Тяжёлые команды (тесты, проверка типов, сборка) — только под слотом общего светофора; эмулятор — по очереди через семафор и словом координатора.

## 2. Коммит только своих файлов — через временный индекс
Общий индекс делят все сессии; обычный коммит заберёт чужие подготовленные файлы или откатит чужие коммиты (инциденты: «временный индекс откатил чужой коммит», «набор 38 файлов устарел и откатывает 3b2ebf79d»).
```
export GIT_INDEX_FILE=<файл во временной папке сессии>
BR=$(git symbolic-ref HEAD); BASE=$(git rev-parse HEAD)
git read-tree HEAD
git add -- <только свои пути>
TREE=$(git write-tree)
C=$(git commit-tree $TREE -p $BASE -m "<сообщение с Governance-ID и Co-Authored-By>")
git update-ref $BR $C $BASE      # третий аргумент: старое значение — защита от гонки
unset GIT_INDEX_FILE
[ "$(git rev-parse HEAD^)" = "$BASE" ] && echo PARENT_OK
```
Проверка после коммита: последний коммит в журнале и его родитель равен BASE; иначе чужие коммиты потеряны — вернуть их немедленно.

## 3. Выровнять общий индекс после КАЖДОГО коммита
Иначе в общем индексе остаётся старое дерево, и чужой простой коммит откатит твою работу: `git restore --staged -- <свои пути>` (рабочие файлы не трогает). Цель: список подготовленных файлов содержит только чужое.

## 4. Общие файлы-реестры (tasks.json, worklog.jsonl, INBOX, 03_DECISIONS)
- Правка блока задачи — через `docs/phraseman-2.0/tools/mark.py` или его `write_task_block` (меняет только блок задачи).
- Если файл грязный от чужих правок: в рабочем файле меняешь свой блок/строку, а в коммит кладёшь «HEAD + только мои блоки» (собрать текст из версии файла в HEAD и подменить блок), чтобы чужие незакоммиченные правки не уехали в твой коммит.
- Реестр после правки: `python tools/validate.py` — по своим id ошибок быть не должно.

## 4а. Зависшая блокировка индекса
Файл блокировки индекса размером 0 и старше ~2 минут при отсутствии живых процессов git — брошен; удалить и повторить. Живой git рядом — ждать.

## 4б. Временные файлы — только с уникальным именем
Временный индекс (`GIT_INDEX_FILE`) и файл сообщения коммита (`git commit -F`) называть с id сессии и временем, например `idx_<сессия>_<ГГГГММДД-ЧЧММСС>` и `msg_<сессия>_<ГГГГММДД-ЧЧММСС>.txt`, и класть в свой каталог для временных файлов, а не в общий `/tmp`. Общие имена вроде `/tmp/msg.txt`, `/tmp/idx` запрещены: две сессии пишут в один файл, и чужая правка уезжает под чужим заголовком. Так вышло с коммитом 52cea217d (04.10): заголовок «PM-034 repeat review», содержимое — правка INBOX другой сессии. После коммита проверить `git show --stat HEAD`: в списке файлов только свои.

## 5. Если конфликт неизбежен
Сначала искать обходной путь (другой файл, отложить кусок). Если обхода нет — сообщить координатору «этот файл редактируется в другой сессии» и не лезть. Запрещено: прятать правки в скрытое хранилище git, создавать дополнительные рабочие копии дерева, перезаписывать рабочую копию версией из git.
