### 0.D. ЗАПРЕТ ОБВОДОК — приоритет над макетами

В макетах (`card-v2.html` и др.) есть `border:1px solid rgba(255,255,255,.12)` и
`border:1px solid var(--line)` на контейнерах. **Это HTML-условность подачи, в приложение НЕ переносить.**

Жёсткое правило владельца: **никаких `borderWidth`/`borderColor` вокруг блоков.** Разделяем
тоном, тенью, фоном, скруглением. Убирая `borderColor` — убирать и `borderWidth` (иначе остаётся
невидимый отступ-артефакт). По разделу уже прошли 3 волны снятия обводок (коммиты `9f46ea4cc`,
`bd156b2b4`, `f629898b6`) — возврат рамок будет прямой регрессией.

Читать макеты так: **композиция, иерархия, цвет, моушн — эталон; рамки — игнорировать.**
Там, где в макете рамка несёт смысл разделения, в RN использовать сдвиг фона на 1 ступень
тона или мягкую тень.

Из того же свода: **никаких подписей-расшифровок мелким шрифтом под названием** (название
самодостаточно) и **никакого `adjustsFontSizeToFit`** для ужатия текста — лечить переносом
и вёрсткой.

### 1.1. Карточка профиля (CARD_AUDIT_V2.md, 2026-07-19)

**Анатомия:** карточка — система из **7 поверхностей и 14 режимов**:
- S1 своя (Hero, режимы R1–R7: просмотр / апгрейд доступен / не хватает / max V / скелетон / офлайн / ошибка)
- S2 чужая (Social, R8–R10: лайк доступен / лайк отдан / «vs вы»)
- S3 мини-карточка в списках (`top_helpers`, `club_screen`, `(tabs)/friends`)
- S4 апгрейд-флоу (R11–R14: превью → подтверждение → церемония → тупик «не хватает»)
- S5 панель бонусов, S6 тосты/события, S7 онбординг лестницы

**Выбранный стиль: «AURORA-METAL»** — гибрид трёх концептов: основа AURORA (глубина, живой свет, готовые тап-зоны) + дисциплина NOIR (иерархия, воздух) + фишка EMBLEM («металл растёт с уровнем»: матовый → сталь → тил → синий → багряный → платина). Концепты NOIR/AURORA/EMBLEM оценены в аудите §3.2; EMBLEM-шрифт (Cormorant Garamond) в финал НЕ идёт — только Inter.

**Обязательные UX-исправления (аудит §3.1):**
1. «LV 8» — только на аватаре; в статистике опыт/цепочка/лига без дубля уровня.
2. Один primary CTA по состоянию: `<V и хватает` → «Улучшить до II · 450 💠»; `<V и не хватает` → «До II не хватает 120 💠» (честный тупик прямо на кнопке, не ошибка по тапу); `V` → «Поделиться карточкой». Кнопка апгрейда на уровне V не рендерится вовсе.
3. Живой чип щита с III уровня в шапке — виден каждый день (как у Duolingo): «Щит активен» / «перезарядка · N дн» / «использована вчера».
4. «Модификаторы XP» — раскрывающийся ряд чипов с итогом, не строка-простыня.
5. Блоки «Выучено / Арена / Путь / Легенда» — тапабельные роутеры в свои разделы (карточка = хаб, не витрина).
6. Лайки: своя карточка при 0 → «Пока нет лайков — поделись карточкой»; чужой счётчик показывать только при ≥ 3. Кнопка лайка заранее показывает состояние «лайк отдан сегодня / вернись завтра» (базовый лимит 1/день).
7. Тап-зоны ≥ 44px (было 31px у кнопок × и ↑).
8. Уровень V — чище, а не длиннее: «витрина статуса» без простыни блоков.

## 3. СТРОГИЕ ПРАВИЛА АНИМАЦИЙ

Извлечено дословно из CSS/JS макетов. Каждое правило пронумеровано (A-n) и проверяемо по файлу макета. Все значения — эталон для RN-реализации (Reanimated/Animated): кривые Безье переносятся в `Easing.bezier(...)`, пружины — в `withSpring` (параметры см. A-4).

### 3.1. Глобальные токены моушна

| ID | Токен | Значение | Где определён |
|---|---|---|---|
| A-1 | `--spring` | `cubic-bezier(.34,1.56,.64,1)` | `:root` во всех трёх финальных макетах |
| A-2 | `--ease-out` | `cubic-bezier(.22,.61,.36,1)` | `:root` там же |
| A-3 | `--ease-in` | `cubic-bezier(.55,.06,.68,.19)` | `:root` во flashcards-макетах (в card-v2 используется встроенный `ease-in` для отдельных переходов) |
| A-4 | Пружинный эквивалент для RN | **не задан аудитом, предложить значение по умолчанию.** Дефолт-предложение: `withSpring(value, { damping: 14, stiffness: 170, mass: 0.7 })` — даёт overshoot ~4%, эквивалентный b1=1.56 в cubic-bezier(.34,1.56,.64,1). Подобрать визуально по демо в секции 09 `card-v2.html` | — |

**Бюджетные правила (аудит CARD_AUDIT_V2 §4.2, FLASHCARDS_AUDIT §3.4):**

| ID | Правило |
|---|---|
| A-5 | Анимировать **только `transform` и `opacity`**. Никаких layout-анимаций, blur-анимаций, box-shadow в кадрах |
| A-6 | **≤ 2 вечных цикла** на один экран/карточку. В списках (MINI, строки) — **ноль** вечных FX |
| A-7 | `backdrop-filter: blur()` **запрещён** (самый дорогой эффект на Android, в RN нет дешёвого аналога). Замена — предрасчитанные полупрозрачные градиенты |
| A-8 | Пауза всех вечных циклов при уходе экрана из фокуса: `visibilitychange` → `body.pause .fx { animation-play-state: paused }` (в RN — существующий AppState-guard, применить и к карточкам) |
| A-9 | `perf_freeze_contract`: ноль бесконечных `withRepeat(-1)` без флага. FX-поверхности — `will-change`/`contain`; бюджет ≤ 60мс JS на кадр |
| A-10 | Конфетти/частицы — **один раз**, не loop; DOM-узлы частиц удаляются после проигрывания (в макетах: `setTimeout(remove, 950)`) |
