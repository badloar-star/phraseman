## Если владелец не может войти — СНАЧАЛА ПРОВЕРЬ ПРАВА, НЕ КОД

Симптом «не пускает в админку» **почти всегда означает пропавший claim, а не
сломанный HTML**. Правка `legacy.html` в этой ситуации бесполезна: она ломает
работающую защиту и не решает проблему.

Шаг 1 — прочитать права (ничего не меняет):

```bash
node -e "const a=require('firebase-admin');process.env.GOOGLE_APPLICATION_CREDENTIALS='C:/appsprojects/phraseman/service-account.json';a.initializeApp({credential:a.credential.applicationDefault()});a.auth().getUserByEmail('badloar@gmail.com').then(u=>{console.log('claims:',JSON.stringify(u.customClaims||{}),'disabled:',u.disabled);process.exit(0)})"
```

Шаг 2 — если вернулось `{}` или `admin` не `true`, вернуть доступ:

```bash
GOOGLE_APPLICATION_CREDENTIALS=C:/appsprojects/phraseman/service-account.json node scripts/set_admin_claim.mjs badloar@gmail.com owner --grant
```

Шаг 3 — владелец обновляет страницу админки. Перезаходить НЕ нужно: токен
перечитывается сам, плюс на экране есть кнопка «Проверить доступ снова».

Только если права на месте, а войти всё равно нельзя — можно смотреть код.

## Что в коде входа трогать запрещено

Файл: `admin/v2/legacy.html`, обработчик `onAuthStateChanged`.

| Что | Зачем оно там |
|---|---|
| `tr.claims.admin !== true` | сама проверка прав; уберёшь — админка открыта любому Google-аккаунту |
| `getIdTokenResult(true)` | принудительный перевыпуск токена; без него свежий claim не виден час |
| `browserLocalPersistence` | сохранение сессии — это и есть автовход |
| `getRedirectResult(auth)` | дочитывает вход с телефона; без него экран логина крутится по кругу |
| `showAdminRetryClaimButton` | кнопка «Проверить доступ снова» без перезахода |

### 🚫 Главный запрет: НИКАКОГО `signOut` в блоке отказа

Именно это сожгло автовход владельца 16.08.2026.

Firebase хранит сессию в **IndexedDB** (не в localStorage, несмотря на имя
`browserLocalPersistence`). Пока claim был стёрт, каждый заход владельца:

```
восстановил сессию из IndexedDB → не нашёл claim → signOut снёс сессию
```

Каждый раз. Система выжигала собственный автовход. Когда claim вернули,
восстанавливать было уже нечего — владелец стоял на выжженном месте.

Тот же `signOut` бил ещё дважды: при обрыве сети (токен приходит без claim —
владельца выкидывало насовсем при живом claim) и сразу после
`signInWithRedirect`, когда claim не успел подъехать в свежий токен.

**Сессию не трогаем никогда.** Нет прав — показываем причину и кнопку
повторной проверки, но сохранённый вход оставляем жить.

## Ещё запреты

- **`setCustomUserClaims` без `...user.customClaims`.** Вызов перезаписывает
  права целиком. Один такой вызов — и владелец заперт снаружи. Именно так,
  судя по всему, claim и пропал: в продовом коде claims не пишет никто, только
  `scripts/set_admin_claim.*` и консоль Firebase.
- **Админка живёт только в `admin/v2/legacy.html`.** Hosting публикует папку
  `admin/v2`. Правка входа в любом другом файле на боевую не попадёт.
- **После правки — деплой.** Без `firebase deploy --only hosting` владелец
  продолжит видеть старую версию.
