# Admin v2: управление экранами онбординга

Дата: 2026-07-12
Статус: одобрено пользователем

## Цель

Дать администратору в Admin v2 понятный список экранов текущего онбординга и возможность временно выключать любой необязательный экран. Выключенный экран не показывается: движение вперёд, назад и восстановление незавершённого онбординга проходят через ближайший включённый шаг. Повторное включение возвращает экран на прежнее место без новой публикации приложения.

Финальный экран `name`, содержащий проверку возраста и принятие обязательных юридических условий, всегда включён и не может быть отключён.

## Канонический порядок

Приложение сохраняет один канонический каталог шагов со стабильными идентификаторами и русскими названиями:

1. `welcome` — Приветствие
2. `source` — Откуда вы узнали о приложении
3. `language` — Выбор языка (сейчас скрыт локальным продуктовым условием)
4. `level` — Уровень языка
5. `goal` — Цель обучения
6. `minutes` — Время занятий
7. `aha` — Практическая демонстрация
8. `notifications` — Уведомления
9. `plusBenefits` — Преимущества Plus
10. `startMode` — Выбор режима старта
11. `planComparison` — Сравнение планов
12. `onboardingPaywall` — Предложение подписки
13. `name` — Имя, возраст и обязательные согласия

Локальные продуктовые условия и удалённая настройка применяются совместно: шаг показывается только тогда, когда он разрешён обоими источниками. Admin v2 честно отображает локально недоступный шаг как недоступный в текущей версии, а не обещает включение, которое приложение не выполнит.

## Формат конфигурации

В `remote_config/app.texts` хранится один версионированный ключ `onboarding_enabled_steps_v1`. Его значение — JSON-массив идентификаторов включённых необязательных шагов в каноническом порядке.

Правила безопасности:

- отсутствие ключа, ошибка чтения, невалидный JSON или неизвестная версия означают текущий полный онбординг;
- неизвестные идентификаторы игнорируются;
- порядок из Remote Config не меняет канонический порядок приложения;
- `name` принудительно добавляется приложением независимо от содержимого конфигурации;
- админка никогда не предлагает снять галочку с `name`;
- первая доставка механизма потребует релиза приложения; последующие переключения работают через Remote Config без релиза.

## Поведение приложения

Из канонического порядка, локальных условий и удалённой конфигурации строится `enabledOrder`. Вся навигация использует общий резолвер вместо прямых переходов между именованными шагами.

- «Далее» открывает ближайший следующий включённый шаг.
- «Назад» открывает ближайший предыдущий включённый шаг.
- Если сохранённый шаг выключен, восстановление идёт к ближайшему следующему включённому шагу.
- Если текущий шаг выключили во время незавершённого онбординга, пользователь переводится только вперёд; назад его автоматически не отбрасывает.
- Если выключены все необязательные шаги, первым открывается обязательный `name`.
- Уже завершившие онбординг пользователи не проходят повторно включённые шаги.
- Прогресс рассчитывается по фактически включённым шагам.

Автоматический пропуск не имитирует пользовательский выбор и не отправляет аналитику выбора. Для пропущенных `source`, `level`, `goal` и `minutes` используются уже существующие безопасные значения по умолчанию. Побочные действия (запрос уведомлений, покупка, сохранение ответа) выполняются только после реального действия пользователя, а не при пропуске.

Переходы около `startMode`, `planComparison` и `onboardingPaywall` должны учитывать фактический пункт назначения. Сначала резолвер определяет ближайший включённый шаг, затем выполняются только предусловия этого шага:

- если пункт назначения — `onboardingPaywall`, выполняется необходимая подготовка paywall и только тогда фиксируется его показ;
- если `onboardingPaywall` пропущен, не создаётся pending-plan, не запускается подготовка покупки и не отправляется событие просмотра paywall;
- если `planComparison` пропущен, но `onboardingPaywall` включён, подготовка paywall всё равно выполняется перед его показом;
- если оба шага выключены, переход идёт к `name` без побочных действий этих экранов.

Во время активной операции покупки изменение конфигурации не прерывает транзакцию. Новый маршрут применяется после завершения или отмены операции.

## Admin v2

В разделе «Приложение» добавляется карточка «Экраны онбординга» в стиле `ADMIN_UI_BIBLE.md`:

- строки идут в реальном порядке прохождения;
- у каждой строки есть русское название, короткое объяснение и подписанная галочка «Показывать»;
- вся строка имеет достаточную область нажатия, видимый клавиатурный фокус и текстовое состояние;
- обязательный финальный шаг включён, заблокирован и помечен «Обязательный» с tooltip;
- локально недоступные шаги помечены отдельно;
- интерфейс не показывает сырой JSON как основной способ работы.

Изменения используют существующий защищённый процесс Remote Config:

1. загрузить актуальную конфигурацию и ревизию;
2. изменить галочки;
3. указать причину;
4. увидеть предпросмотр точных включений и отключений;
5. опубликовать серверной командой с проверкой ревизии, журналом и возможностью восстановления.

Публикация сохраняет все посторонние ветки и ключи `remote_config/app`.

## Ошибки и совместимость

- При ошибке загрузки управление блокируется и показывает понятную ошибку; состояние не угадывается.
- Конфликт ревизии требует обновить данные и повторить предпросмотр.
- Старые версии приложения, не знающие этот контракт, продолжают показывать прежний онбординг.
- Новые версии сохраняют существующую семантику Remote Config: при офлайне применяется последняя валидная кешированная настройка. Полный безопасный маршрут используется только тогда, когда валидного кеша нет или сохранённое значение повреждено.

## Проверка

Тесты сначала фиксируют ожидаемое поведение и должны падать до реализации.

- чистый резолвер порядка: первый, последний, один, несколько и соседние выключенные шаги;
- движение вперёд и назад не попадает на выключенные шаги;
- сохранённый выключенный шаг восстанавливается на ближайшем следующем;
- отключение текущего шага ведёт только вперёд;
- все необязательные шаги выключены — остаётся `name`;
- `name` невозможно исключить даже повреждённой конфигурацией;
- отсутствующая или невалидная конфигурация сохраняет полный маршрут;
- пропуск не создаёт ложных ответов или аналитических событий выбора;
- все комбинации включения `startMode`, `planComparison` и `onboardingPaywall` приводят к правильному пункту назначения и запускают только необходимые для него побочные действия;
- валидная кешированная настройка действует офлайн, а отсутствующий или повреждённый кеш даёт полный маршрут;
- Admin v2 показывает полный каталог и блокирует обязательный шаг;
- предпросмотр сохраняет посторонние ключи и публикацию через ревизию, причину и аудит;
- узкие проверки Admin v2: синтаксис JS, actions/routes, язык и tooltips.

## Критерии приёмки

- Администратор видит текущие состояния всех шагов понятными галочками.
- После предпросмотра и публикации выключенные шаги пропускаются у новых и незавершивших онбординг пользователей.
- «Далее», «Назад» и восстановление никогда не открывают выключенный шаг.
- Повторное включение возвращает шаг в исходное место без нового релиза приложения.
- Завершившие онбординг пользователи не возвращаются в него.
- Юридические согласия и возрастная проверка не обходятся.
- Ошибочная или отсутствующая конфигурация не сокращает онбординг.
- Каждая публикация имеет причину, ревизию, аудит и путь восстановления.

## Вне задачи

- изменение порядка экранов из админки;
- редактирование текста или дизайна экранов;
- повторный запуск онбординга для завершивших его пользователей;
- отключение юридически обязательного финального шага;
- удаление существующих экранов или их функциональности.
