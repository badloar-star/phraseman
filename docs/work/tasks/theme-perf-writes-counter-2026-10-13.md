# Счётчик записей в журнале [THEMES-PERF] (проверка скорости ползунка и смены темы)

Governance-ID: TG-6C0FBE0D4C2D
Status: в работе
Owner: сессия «4 · ТЕМЫ 2.0» (поручение координатора: проверить перерисовки, записи в хранилище и мгновенность смены темы; лог renders/tokensMs/writes)

## Outcome
Строка `[THEMES-PERF] change` в dev-журнале показывает ещё и число записей в хранилище за шаг (`writes`), рядом с уже имеющимися `consumersRendered` (перерисовки) и `buildMs` (цена сборки токенов). По коду подтверждено: значение контекста мемоизировано, токены в LRU-кэше, ползунок шлёт превью по шагам без записи, запись одна на отпускание.

## Scope
`components/ThemeContext.tsx` — один модульный счётчик, инкремент в `write` персистера и поле в dev-логе. Поведение приложения не меняется; в боевой сборке счётчик не читается.

## Architecture
Модульная переменная `themePerfWrites` рядом с `themePerfConsumerCalls`; в `createThemePersister({ write })` увеличивается на 1 перед записью; в setTimeout-логе выводится разность на момент смены и через 250 мс. Остальное — IS_DEV.

## Security and privacy
Только dev-счётчик, данные пользователя не затрагиваются.

## Technical debt
Нет новых; счётчик считает записи только этого персистера (тема, оформление, насыщенность), прочие записи ThemeContext (размер шрифта, первый запуск) не входят.

## Verification
Точечная проверка синтаксиса файла; на устройстве — движение ползунка даёт строки change с writes=0 на шагах и writes=1 на отпускании.
