# Gate MIGRATION_AND_ROLLBACK_APPROVED_BEFORE_DESTRUCTIVE_CHANGE — пакет (2026-10-01)

Решение координатора §37 (Q85/Q83): gate подтверждается пакетом, если по КАЖДОЙ миграции есть
ссылка на решение владельца, проверка с выводом, шаг отката, судьба данных при откате и правило
«прод — только владелец». Пакет проверяет независимый агент-ревьюер, затем подписывает координатор.
Без шага отката gate не подтверждается.

Задачи, на которые распространяется: PM-046, PM-055, PM-078, PM-079, PM-084, PM-085, PM-089, PM-090.
Все прогоны — 2026-10-01 на HEAD ветки feature/referral-roulette, под светофором, без устройства и без прода.

**Общее правило для всех миграций: прод — только владелец.** Ни одна миграция ниже не запускается
серверным скриптом по базе; всё выполняется на телефоне человека при обновлении приложения или за
рубильником Remote Config, который включает владелец. Ядро и исполнители прод не трогают.

## M1. Подарки и спины → монеты (PM-046, Q12)

- **Решения владельца:** Q12 (компенсация незабранных подарков монетами), D49 («Дневной путь» удалён,
  компенсация цела), D53 (строка-итог на сервер), D70/D103/D104 (жемчуг не начисляется). Спецификация:
  `docs/phraseman-2.0/docs/GIFTS_TO_COINS_MIGRATION.md` §5.
- **Механика:** `app/gifts_to_coins_migration_v1.ts` — WAL на аккаунт `gifts_to_coins_v1:<owner>`
  (`planned → plus_applied → credited → retired → done | blocked`); опись фиксируется в WAL один раз;
  монеты через кошелёк с детерминированным `requestId` `g2c1_<hash32>_<i>` (`g2cdj_` — «Дневной путь»),
  дубль схлопывается кошельком и сервером; списание предметов — ТОЛЬКО после зачисления и одним
  `multiSet` вместе с меткой WAL.
- **Проверки (вывод):**
  - `tests/gifts_to_coins_migration.test.ts` — Tests: 28 passed, 28 total
  - `tests/gifts_to_coins_real_wallet.test.ts` — Tests: 3 passed, 3 total
  - `tests/gifts_to_coins_legacy_daily_path.test.ts` — Tests: 6 passed, 6 total
  - `functions/src/gifts_to_coins_report.test.ts` — Tests: 3 passed, 3 total
  - `tests/home_spin_entry_contract.test.ts` — 2/2; `tests/level_spin_star_callable_retired.test.ts` — 4/4
  - пробы `level_gift_client_retirement`, `level_gift_server_retirement`, `pm048_gift_section_retirement`,
    `server_remote_event_allowlist` — PASS
- **Откат:**
  1. Рубильник Remote Config `gifts_to_coins_enabled=false` (владелец) — новые миграции останавливаются
     (`skip reason=flag_off`, `app/gifts_to_coins_migration_v1.ts:558`), уже прошедшие не трогаются.
  2. Откат кода — новой сборкой/OTA (владелец).
- **Судьба данных при откате:** зачисленные монеты НЕ забираются (деньги человека; обратное списание —
  только отдельным решением владельца). Списанные предметы откат не возвращает; WAL с описью хранится
  на устройстве (≥ 90 дней по спецификации) — по нему видно, что было и сколько выдано. Даунгрейд до
  1.x через стор невозможен (D30); вручную поставленная старая сборка увидит пустые кредиты и
  повторно не начеканит.

## M2. Множители опыта и бусты (PM-055)

- **Решения владельца:** переход экономики на монеты (D49/D68/D70), XP-бусты сняты. Аудит полноты:
  `docs/phraseman-2.0/evidence/PM-055_xp_multiplier_completeness_2026-10-01.md`.
- **Механика:** нового хранения нет; старые локальные ключи (`gift_xp_bank_v1`, `gift_xp_multiplier`,
  `club_gift_free_boost_v1`) стираются вместе с аккаунтом (`RETIRED_2_0_ECONOMY_ACCOUNT_LOCAL_KEYS`
  в `app/cloud_sync.ts`); старые XP-подарки переводятся в монеты в M1.
- **Проверки (вывод):** пробы `pm055_xp_multiplier_runtime_retirement`, `pm055_xp_surface_retirement`,
  `xp_boost_tokens_compat_only` (3178 файлов, совместимость 6/6) — PASS.
- **Откат:** откат кода сборкой/OTA (владелец).
- **Судьба данных при откате:** стёртые ключи бустов не восстанавливаются; старая сборка увидит
  «бустов нет» — это безопасно (буст только добавлял XP, а XP в 2.0 не используется для доступа).
- ⚠️ Отдельно: «Супер-воскресенье» (×2 монет) — живой буст монет без решения в 03_DECISIONS (Q87).
  К gate миграции не относится (ничего не удаляется), но в PM-055 указано как открытый вопрос.

## M3. Повышение ранга монеты (PM-078, PM-079)

- **Решения владельца:** D34/D42/D60/D62 (ранг монеты, цена N × 1000, человек сам жмёт «Повысить»).
- **Механика:** `app/coin_rank_upgrade_v1.ts` — списание и новый ранг одним `multiSet`; идемпотентность:
  `expectedFromRank`, детерминированный `operationId` `coin_rank:to_N`, замки аккаунта/хранилища и
  токен поколения (смена аккаунта посреди повышения не спишет у нового владельца). Сеть не нужна.
  Потраченный баланс отделён от права доступа (PM-079): ранг — отдельное поле, доступ от баланса не зависит.
- **Проверки (вывод):** `tests/coin_rank_upgrade.test.ts` — Tests: 7 passed, 7 total;
  `coin_rank_upgrade_guard_behavior` 4/4 (node:test); проба `coin_rank_ceremony_once` — PASS.
- **Откат:** откат кода сборкой/OTA (владелец); миграции существующих данных нет — ранг стартует с
  текущего значения.
- **Судьба данных при откате:** уже поднятые ранги и списанные за них монеты остаются (трата
  состоялась по действию человека); старая сборка без экрана ранга просто не показывает его.

## M4. Энергия: запас, списание на первом вопросе, ноль (PM-084, PM-085, PM-089, PM-090)

- **Решения владельца:** D98 (старый запас > 5 обрезается до 5, без долива), D72 (энергия списывается
  при показе первого вопроса), D87 (автовозврат при сбое), D95, D06/D07 (Plus не тратит).
- **Механика:** `app/energy_state_v2.ts` — однократная обрезка `> 5 → 5` при чтении состояния,
  результат записывается обратно → идемпотентно; лог `[ENERGY-CAP] D98 migration: stored=… → 5`.
  Ноль энергии: окно один раз на попадание, без рекламы (PM-090).
- **Проверки (вывод):** `tests/energy_cap_d98_migration.test.ts` — Tests: 5 passed, 5 total;
  `tests/energy_first_question_gate.test.ts` — Tests: 11 passed, 11 total;
  `tests/pm090_zero_energy_no_forced_ads_contract.test.ts` — Tests: 5 passed, 5 total.
- **Откат:** откат кода сборкой/OTA (владелец).
- **Судьба данных при откате:** обрезанный запас (> 5) не восстанавливается — исходное число не
  хранится (D98: владелец принял обрезку без долива). Старая сборка прочитает 5 как обычный запас.
  Энергия, списанная на первом вопросе, при откате не возвращается задним числом; автовозврат при
  сбое (D87) работает в новой сборке.
