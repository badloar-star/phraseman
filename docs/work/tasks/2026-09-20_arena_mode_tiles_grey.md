## Outcome

нажимаются. Подпись «Данные пока недоступны» с них исчезает.

Владелец: «на кнопках РАНГ РАЗМИНКА ДУЭЛЬ прямо на них, и они недоступны…
они серые они не нажимаются».

## Диагноз (логи устройства, 15:06–15:20)

```
[ARENA-HUB] ... availabilityEnabled=true quickEnabled=true rankedEnabled=true
            homeLoaded=true serverFailure=false ... reportGuard=checking
```

Хаб ЗДОРОВ: Арена включена, данные загружены, ошибок нет. Но `reportGuard`
во ВСЕХ строках лога остаётся `checking` — он никогда не становится `clear`.

`baseBlock = arenaHubActionBlock({ known: home !== null && !reportChecking, ... })`
→ при `checking` даёт `known: false` → причина блока `unknown`
→ `enabled = false` для всех режимов
→ плашки серые, подпись `blockHint('unknown')` = `valueUnknown` =
  «Данные пока недоступны».

Эффект гварда сбрасывает состояние в `checking` при каждом изменении `active`
(`useRuntimeActive`). Пока `active` мигает, проверка стартует заново и не
успевает завершиться — кнопки мертвы бесконечно.

## Scope

In scope: `components/arena/ArenaHubSurface.tsx` — гвард отчётов перестаёт
блокировать выбор режима.

Out of scope: сам механизм outbox, сервер, экран поиска.

## Architecture

**Что такое гвард отчётов.** `arenaOutboxBlockedByUpdate` проверяет, нет ли в
локальной очереди отчётов о матчах, которые сервер отверг как «старый клиент».
Если есть — новый матч начинать бессмысленно: его отчёт тоже отвергнут.

**Почему он не должен держать кнопки.** Это проверка ЛОКАЛЬНОГО хранилища,
она не обязана предшествовать выбору режима. Её результат важен, только когда
он ПОЛОЖИТЕЛЕН (`blocked`). Состояние «ещё проверяю» — не причина запрещать
игру: оно ничего не утверждает.

**Целевое поведение.**
- `checking` → кнопки активны (проверка не закончена, запрещать нечего);
- `blocked` → кнопки заблокированы с честной причиной (как и было);
- `clear` → кнопки активны.

То есть `known` перестаёт зависеть от гварда: `known: home !== null`.
Блокировка по `reportBlocked` остаётся отдельным входом `arenaHubActionBlock`
и работает как прежде.

**Дополнительно.** Эффект больше не сбрасывает состояние в `checking` при
каждом мигании `active` — сброс только при смене языкового контура. Мигание
видимости не должно перезапускать локальную проверку.

**Инвариант.** Незавершённая локальная проверка никогда не блокирует
пользовательское действие. Блокирует только подтверждённый отказ.
