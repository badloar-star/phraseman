# Task packet: вход гостя с прогрессом в существующий аккаунт не стирает прогресс молча (сценарий №2)

Governance-ID: TG-F8D6505A8DDE
Status: В работе
Owner: 5 · АВТОРИЗАЦИЯ

## Outcome

Гость, у которого есть настоящий прогресс (уроки, карточки, свои наборы, ошибки), при входе в УЖЕ существующий аккаунт
Google/Apple получает окно «Сменить аккаунт» (account_switch_required) — как и задумано правилами, — а не молчаливое
стирание. Метка «свежий гость после смены аккаунта» (post-completion handoff, 24 ч) больше не перекрывает факт прогресса.

## Scope

- app/auth_provider.ts: ветка конфликта привязки — условие окна смены аккаунта.
- tests/auth_provider_behavior.test.ts: новый тест «метка есть + прогресс → окно, без входа».

## Architecture

Факты (эмулятор 18.10 10:04, журнал logcat): `clean_proof decision not_clean progress=26` (lesson1_progress, 64 карточки,
4 своих набора, ошибки) → `handoff-proof localClean=false postCompletionHandoff=true` → передача без окна →
`swap local_data_checked preserveLocalProgress=false` → wipe_done → облако аккаунта. Метка post-completion писалась ради
«подарка новичку» (до классификатора 15.10); с классификатором (default/service/progress) значения по умолчанию уже
считаются чистыми, поэтому метка нужна только как след в журнале, а не как пропуск мимо прогресса.

## Security and privacy

Новых данных не собираем. Журнал — только флаги и счётчики, без значений и uid (identityTag).

## Technical debt

Данные этого гостя на эмуляторе уже стёрты локально (облачная копия users/{гость} осталась на сервере).
Слияние гостя с существующим аккаунтом без окна — отдельное продуктовое решение, не здесь.

## Verification

Точечный тест через светофор; повтор сценария №2 на эмуляторе: гость с прогрессом → Google существующего → окно смены.
