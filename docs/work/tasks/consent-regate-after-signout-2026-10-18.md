## Outcome

После выхода или смены аккаунта при следующем запуске показывается ТОЛЬКО экран согласия онбординга (шаг 'name':
галочка аналитики, вопрос возраста, строка Условий под «Продолжить»). Остальной онбординг не повторяется.
Условия принимает только сам человек нажатием «Продолжить»; аналитика выключена до его выбора (галочка по умолчанию
снята). Тексты — существующие строки онбординга, новых нет.

## Scope

- app/device_onboarding_marks.ts: ключ устройства `consent_regate_pending_v1` и чистое решение
  `resolveConsentRegate(onboardingDone, legalAccepted, pending)`.
- app/cloud_sync.ts: `resetConsentsBeforeSignoutWipe` ставит метку `consent_regate_pending_v1='1'` (только режим 'signout').
- app/_layout.tsx: при запуске читает Условия и метку; при решении «показать» монтирует онбординг с `consentOnly`;
  свой обработчик завершения (без приветствия, пушей, бонуса и тутора энергии нового ученика). Журнал [CONSENT-REGATE].
- components/CleanOnboarding.tsx: проп `consentOnly` — старт сразу на 'name', без восстановления шага, без записи
  шага, без метрики старта воронки, без стрелки «назад»; «Продолжить» пишет Условия, возраст, выбор аналитики,
  снимает метку и закрывает экран.
- tests: решение показа (все ветки) + «A вышел → метка стоит, Условия сняты → экран согласия показан» + проводка.

## Architecture

Метка — ключ устройства вне описи аккаунта (как device_onboarding_done_v1). Решение — чистая функция, чтобы его
сторожил тест. Показ — тот же оверлей онбординга, что и обычно, без нового экрана. Решение показа только по метке:
старые пользователи без записанного ключа Условий (вход «уже есть аккаунт») НЕ получают экран неожиданно.

## Security and privacy

Сбор не расширяется. Аналитика нового человека выключена до явного выбора. В журнал — только значения ключей
('1'/null) и решение. Политику менять не нужно (координатор).
