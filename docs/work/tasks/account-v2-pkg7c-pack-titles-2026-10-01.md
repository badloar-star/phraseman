Если в контракте нет места — опциональное поле с лимитами длины и паритетом клиент/сервер, совместимое со старыми клиентами. Догрузка названий из документов наборов — только как запасной путь, батчем (`in`-запросы по 30), один раз, с кэшем, и только для id без названия.

## Итог исполнителя (2026-10-01)

**Анализ.** Названия живут ТОЛЬКО локально (`community_owned_pack_titles_v1` + скоупы по цели), пишутся в
`addCommunityOwnedPackId`. Старое облако их никогда не синхронизировало (нет в `SYNC_KEYS`, нет в истории
`cloud_sync.ts`) — старый restore тоже восстанавливал только id; правило инвентаря `p.flashcards_misc` (info) —
предосторожность, данных в `progress` нет → перенос OD21 названий не несёт (источника нет). Контракт library V2
был строгим (`{itemIds}`/`{removeItemIds}`, состояние ровно `{items, removed}`).

**Решение (ноль дополнительных чтений Firestore).** Названия — в той же сущности `<target>:community_packs`:
- операция `{ itemTitles: [[id, ru, uk, es], …] }` — ОТДЕЛЬНАЯ (урок 7A P2b: старый сервер ответит `payload_invalid`
  только на неё, id наборов не теряются); 1…100 записей, строка ≤ 200 (как обрезает `community_packs.ts`), хотя бы
  одна непустая, без повторов; смешанная операция — `payload_invalid`;
- состояние: необязательное `titles` (только живые id, по id); без названий ключа нет — форма байт-в-байт прежняя;
  удаление id снимает название; все названия ≤ 64 КиБ (сверх — `entity_state_too_large` только для операции
  названий); сборка мусора tombstone учитывает байты названий;
- база для названий не проверяется (не разрушающая правка, побеждает последняя пришедшая), «из будущего» — conflict;
- клиент: снимок библиотеки несёт локальные названия, производитель шлёт только изменившиеся (зеркало `titles`),
  повторно добавленный id получает название заново; гидрация читает `titles`, засевает зеркало (повторной отправки
  нет), пишет название только для своих наборов и только без локального названия; битое хранилище названий не
  перезаписывается; для библиотеки с локальным зеркалом id не применяются, названия — да.
- Запасной путь (догрузка из документов наборов) НЕ понадобился.
