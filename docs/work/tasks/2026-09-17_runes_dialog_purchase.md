## Outcome

Человек видит в списке диалогов цену под названием сценария и покупает доступ
за руны на уже существующей афише (`ai_dialog_briefing.tsx`) — нового экрана
нет (решение владельца, второй круг макета).

Наблюдаемый результат:
- первый диалог бесплатен, три стартовых сценария остаются бесплатными;
- обычный сценарий стоит 5 000 рун, интересный/сложный — 10 000;
- цена написана строкой под названием, **без слова «навсегда»**;
- тап по кнопке покупки списывает руны и открывает диалог **в том же кадре** —
  ни крутилки «идёт списание», ни «отказ сервера», ни «нет сети» не существует
  (прямая цитата владельца: «сервер не принимает участия, он только
  синхронизация! Главный телефон только»);
- купленное переживает окончание Plus; открытое по Plus — исчезает вместе с
  подпиской.

## Scope

In scope:

- новый чистый модуль владения диалогами (по образцу

- `components/AiDialogBriefingScreen.tsx` — кнопка покупки на существующей афише;
- `functions/src/` — синхронизация покупки + новый `StarOpReason`

## Architecture

Текущая граница: доступ решают ДВА замка в `app/ai_dialog_level_lock.ts` —
`isScenarioUnlockedForAccount` (премиум + белый список из трёх) и
`isScenarioLevelUnlocked` (уровень курса).

Целевая граница: ОДИН замок — владение. Роли валют расходятся и перестают
конкурировать:
- **руны** — ДОСТУП (какие диалоги существуют для человека);
- **Plus** — ОБЪЁМ (сколько реплик в день);
- **жемчужины** — удобство и косметика (без изменений).

Инвариант из кода, который обязан сохраниться: тап по плитке и расчёт её
статуса спрашивают ОДНУ функцию, иначе плитка покажет одно, а тап сделает
другое.

Владение диалогами и купленные реплики — ОДИН документ игрока, не коллекция
из документа на сценарий (Firebase-экономия: одно чтение при входе).

Цена — свойство сценария, а не счётчика покупок: видна заранее и не штрафует
за вовлечённость.

## Security and privacy

- **Персональные данные.** Новых не собирается: владение — это список id
  сценариев, локально + в существующем документе игрока. Privacy policy правки
  НЕ требует (состав данных не меняется). Отдельно: privacy policy потребуется
  для экрана 5 (разбор промаха шлёт текст во внешний сервис) — это другой пакет.
- **Авторизация.** Телефон авторитетен по прямому решению владельца
  (риск R6 в исходном пакете: модифицированный клиент откроет каталог себе
  сам). Владелец предупреждён, решение принято осознанно. Естественная
  страховка сохраняется: дневной лимит 10 реплик остаётся всегда, поэтому
  вскрытый каталог не даёт бесконечного расхода OpenAI.
- **Списание.** Через существующий журнал `stars_ledger.ts`, одной
  идемпотентной операцией по стабильному `operationId`. «Списали, потом
  выдадим» запрещено.
- **App Check** не включается — запломбирован.

## Technical debt

- **Pay now:** `isScenarioLevelUnlocked` и `FREE_DIALOG_SCENARIO_IDS` после
  перехода на владение меняют смысл — обновить комментарии в том же коммите,
  иначе следующая сессия будет чинить «расхождение» по ложному следу.
- **Contain:** сервер не проверяет владение (решение владельца). Граница —
  дневной лимит реплик. Exit condition: если появится реальное злоупотребление,
  вернуть серверную проверку отдельной задачей.

## Rollback

Откат — `git revert` коммита. Данные не мигрируют: владение пишется в
собственные ключи, прогресс диалогов (`dialogs_progress`) не трогается.
Списанные руны остаются в журнале как обычная трата — журнал не переписывается
задним числом (Constitution). Осиротевшие ключи владения безвредны.
