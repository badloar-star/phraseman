# Task packet: D162 — место, повышение и понижение в комнате Пика по монетам недели (рубильник rankBy)

Governance-ID: TG-C7C90BEDFE70
Status: In progress
Owner: Ядро (сессия 1)
Related epic/enabler: E25 Пик; D162 (OWNER_FINAL 10.10); план d99b5fbd0; решение координатора 13.10 «ВАРИАНТ А, страхуемый рубильником»

## Outcome

При `config/spire_v1.rankBy = 'coins'` (ставит владелец своим словом 17.10, действует с недели 2026-W43) место в комнате, места 1–3,
повышение и понижение решает сумма монет, заработанных за неделю во всех режимах (`users.stars.weekEarned`, серверный журнал),
с потолком `weekCoinsCap`; подиум, «Все участники» и итог недели показывают «N монет». Без поля или `'steps'` — всё как сейчас.
Если клиент не готов к 15.10 18:00 — рубильник остаётся `'steps'`, R1 едет по ступеням.

## Scope

In scope: контракт конфига Пика (сервер + клиент: `rankBy`, `weekCoinsCap`), снимок `members.<uid>.weekCoins` при входе в комнату
и отчёте ступеней (из уже прочитанного users), финализация (`spire_finalize_core.ts`, `spire_finalize_cron.ts`: getAll users живых,
сорт монеты → ступени → reachedAtMs, лог [SPIRE-FINALIZE]), клиент (`modules/spire/room_rows.ts`, `SpirePodium`, `SpireAllMembers`,
`SpireWeekResultCard`, боты — монеты для показа), строки 9 языков, тесты обоих режимов, ранбук §3а.
Out of scope: начисления монет (D162: не меняются), Learning/уроки, админка (рубильник — конфиг, админ-UI позже).

## Architecture

Один рубильник `config/spire_v1.rankBy` читают и финализация, и клиент (клиент — из уже кэшируемого конфига, 0 чтений).
Счётчик недели — `stars.weekEarned` журнала (ISO-неделя UTC = `spireWeekId`), `starsWeekEarned` читает и прошлую неделю.
Неделя < W43 — всегда ступени (правило не меняется посреди недели).

## Security and privacy

Потолок `weekCoinsCap` против накрутки суммы практики модифицированным клиентом (PM-291). Новых персональных данных нет:
в комнате — число монет недели участника (видят соседи по комнате, как раньше ступени).

## Technical debt

Contain: сумма практики задаётся клиентом (PM-291) — потолок недели ограничивает выигрыш накрутки; полное решение — PM-291.

Тесты сервера: ранжирование по монетам/ступеням, потолок, ничьи, нули, граница W42/W43, отсутствие поля = steps, getAll.
