# Task packet: аудит раздела «Мои ошибки» и макеты нового раздела

Status: Planned

## Outcome

Владелец получает (1) честный аудит текущего раздела «Мои ошибки» по семи осям
(вход с Главной, вау-эффект, реальная польза, удобство, объяснение «почему так»,
помощник, награды/прогресс) с фактами из кода, и (2) кликабельные HTML-макеты
нового раздела уровня «Статистика»: хаб раздела, экран задания с живым
объяснением, карточка ошибки, финал с наградами, полка исправленного, пустое
состояние. Успех: владелец может выбрать направление и отдать макеты в
реализацию без повторного исследования кода.

## Scope

In scope:
- `docs/design/mistakes/index.html` + `docs/design/mistakes/shared/*` (копия
  общих токенов/рамы телефона из `docs/design/dialogs/shared`, чтобы не трогать
  файлы параллельной сессии «Диалоги»).
- Этот пакет.

Out of scope: любые правки приложения (`app/**`, `components/**`,
`modules/**`), функций, правил Firestore. Реализация по макетам — отдельная
задача после решения владельца.

## Architecture

No architecture change: только документация и макеты. Макеты описывают целевую
архитектуру раздела (хаб → задание → карточка ошибки → финал → полка), опираясь
на существующие контракты `modules/mistake-practice/*` (фасеты, проекция
«исправлено» = 3 дня × 2 режима × самостоятельный ответ, requeue при ошибке,
`stop_for_today` после 3 промахов) и на существующий ИИ-разбор
`use_mistake_explain.ts` (в разделе ошибок сейчас НЕ подключён).

## Security and privacy

Не применяется: новых данных, разрешений, сторонних сервисов нет. Макеты не
содержат PII (имена и цифры выдуманы и помечены как пример). Если реализация
подключит ИИ-разбор в раздел ошибок — текущая политика уже покрывает ИИ-разбор
уроков (ai_explain_consent), проверить формулировку при реализации.

## Technical debt

- Найдено: `checkAchievements({type:'mistake_practice_progress'})` вызывается,
  но ни одно достижение `mistake_*` в каталоге v2 не заведено — событие уходит
  в пустоту. Disposition: Contain — зафиксировано в аудите и в 🔴-итоге,
  exit condition: заведение достижений при реализации макетов.
- Дубль `shared/*` между `dialogs` и `mistakes`. Disposition: Accept
  temporarily — владелец сессии макетов, пересмотр при следующем разделе;
  ceiling: 3 файла, 30 КБ; exit: вынести в `docs/design/shared` когда обе
  сессии закончат.
