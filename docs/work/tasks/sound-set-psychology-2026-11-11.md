## Outcome

Владелец получает в том же макете (`prototypes/sound-lab/index.html`) ещё один набор звуков, собранный по
итогам исследования: что в звуке вызывает приятные ощущения и не надоедает, как звучат конкуренты, и в каких
местах приложения звук нужен, а в каких вреден. Макет показывает только те места, где звук оправдан;
остальные убраны. К каждому звуку приложен точный запрос для генерации. Мерило: владелец выбирает из
нового набора и не встречает в макете мест, где звук лишний.

## Scope

In scope: исследование (психоакустика, конкуренты), решение «где звук нужен», новое семейство в
`prototypes/sound-lab/synth.py` и `events.py`, запросы для генерации, пересборка макета и заметок.

Out of scope: код приложения и его звуковые файлы (новый набор в приложение не кладётся, пока владелец не
выберет); удаление «Молнии»; коммиты.

## Architecture

No architecture change: это инструмент выбора вне приложения. Добавляется семейство звуков и признак
«место нужно / не нужно» у событий; сборка макета прежняя.

## Security and privacy

Не затрагивается: локальные файлы, без данных пользователей. В запросах к поиску в сети нет имён и данных
проекта.

## Technical debt

- Accept temporarily: подключение к сервису генерации звука (ElevenLabs) в этой сессии не работает, поэтому
  набор собирается программой, а запросы для генерации прикладываются текстом. Владелец продукта; пересмотр —
  когда подключение починят; потолок вреда — качество тембра в макете.
- Contain: решение «где звук нужен» опирается на исследование, а не на замер на людях; места убираются из
  макета списком в одном файле и возвращаются одной правкой.

## Verification

Макет собирается без ошибок, скрипт страницы проходит проверку синтаксиса, в браузере открываются все
оставшиеся события; чистота новых файлов замеряется тем же замером `[SOUND-QUALITY]`. На слух — владелец.

## Rollback

Убрать новое семейство и список убранных мест из `events.py`, пересобрать макет. Приложение не меняется.
