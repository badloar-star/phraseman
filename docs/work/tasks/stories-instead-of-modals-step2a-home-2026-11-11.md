## Outcome

Игрок, вернувшийся после перерыва, и игрок, у которого хватило монет на следующий ранг, больше не получают окно поверх
Главной: факт приходит кадром в «Истории», загорается кольцо у монеты. Владелец 11.11: «никаких модальных окон совсем,
всё отображается только в историях», на шаг 2 — «Да, шаг 2».

Истории в приложении включаются удалённым флагом `stories_v1` (по умолчанию выключен). Поэтому замена действует только
при включённом флаге; при выключенном оба окна работают как раньше — игрок ничего не теряет.

Мера успеха: при `stories_v1` = on в журнале `[STORY-INSTEAD] записано kind=back|rank_enough`, окно слот очереди не
просит; при off — прежние строки `[WELCOME-BACK] слот получен` / `[RANK-ENOUGH] слот получен`.

## Architecture

Сейчас: хук решает «показать» → просит слот очереди → Главная рисует окно → «показано» пишется при получении слота.
Станет (при включённых историях): хук решает «показать» → пишет событие истории и сразу отмечает «показано» → слот не
просит, окна нет. Событие — один тип `instead` с полем `kind`; ключ повтора `instead:<kind>:<key>` (день для
возвращения, номер ранга для монеты) — один факт даёт одну историю.

Инварианты:
- правило проекта «празднование не durable»: история — показ факта; монеты и ранг не зависят от её просмотра;
- отметка «показано» ставится только после успешной записи события (или при прежнем показе окна) — факт не теряется,
  если запись не удалась: в следующий заход хук решит заново;
- при выключенном флаге поведение прежнее строка в строку.

## Security and privacy

Новых данных нет: в событие пишутся числа, которые окно и так показывало (дни перерыва, число карточек и фраз, ранг,
баланс, цена). Событие хранится локально в журнале историй, как остальные; имён и идентификаторов в нём нет.
Политика конфиденциальности не затронута.
