# PM-273 — preflight движка ступени Шпиля (2026-09-24)

Только чтение репозитория, без сборок и без правок кода экрана (кросс-граница с
сессией интерфейса, D31/D40 — эта сессия логику/хуки, не JSX).

## Что переиспользуется как есть

| Нужно | Модуль | Годится без правок? |

| Мгновенная проверка ответа (choice/translate/dictate/пары) | `modules/arena/answer_check.ts` (`arenaAnswerIsCorrect`, `arenaPairIsCorrect`) | Да — те же отпечатки, что в пакете недели (арена и Шпиль используют один формат `answerFingerprints`) |

## Дыры

1. **Голосовые задания не проходят через `arenaAnswerIsCorrect`.**
   Функция обрабатывает только `'choice' | 'listen'`, `'translate' | 'dictate'` и
   массив подвопросов — ветки `kind === 'voice'` нет вообще. T21/T22 («голос
   обязателен на верхних этажах», «не снимает сердце, 2 доп. попытки») требуют
   отдельного пути: запись → распознавание речи → сравнение с ожидаемым текстом,
   не через отпечаток fingerprint. Нужен новый модуль `spire_voice_check.ts`,
   а не расширение answer_check (у него есть тест паритета с сервером — трогать
   рискованно, см. комментарий в файле про «расхождение = показали верно,
   начислили 0»).
2. **Цена энергии за ступень не может быть внедрена раньше E08.** Сейчас
   `EnergyActivityKey` — фиксированный список с ценами 10/20/25 (старый масштаб
   cap 100–260). T3 требует 1 энергию по контракту 5/1/10, который сам ещё не
   реализован (E08 — весь `planned`, только PM-086 в review). **Добавлена явная
   зависимость PM-274 → PM-084** в реестре, чтобы никто не списал цену ступени
   по старой шкале.
3. **Пауза/фон/«назад» = провал (T18)** — нет готового модуля жизненного цикла
   именно для этого правила. Ближайший аналог — матч Арены
   (`modules/arena/match_machine.ts`, `matchmaking_state.ts`), но там пауза не
   роняет попытку (можно вернуться), логика другая. Для Шпиля нужен свой
   маленький конечный автомат: `active → (blur/backgrounded) → paused → (foreground) → active`,
   а «назад» с подтверждением сразу переводит в `failed`, не в `paused`.

## Вывод

Движок можно писать поверх `answer_check.ts` для 4 обычных типов заданий и
`captureObjectiveAttempt` для ошибок — без изменения этих файлов. Отдельно
нужны: маленький голосовой модуль (не трогает answer_check) и маленький
конечный автомат паузы/провала. Цену энергии PM-273 НЕ жёстко кодирует —
берёт константу из `config/spire_v1` (админка, PM-283), чтобы переключение на
новую шкалу 2.0 не требовало правки движка повторно.
