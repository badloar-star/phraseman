## Architecture

Границы не меняются. `objectives` — существующее опциональное поле
`DialogScenario`; `scenarioObjectives(scenario)` уже отдаёт явный список, если
он есть, и нарезает `goalEn` только когда списка нет. Заполняя поле, мы просто
переводим сценарии с ветки «нарезка» на ветку «авторский список».

Инварианты, которые обязаны сохраниться:
1. `id` цели уходит на сервер (`objectivesMet`) и сравнивается по строке —
   значит id должен быть стабильным, латиницей, уникальным внутри сценария.
2. `gameEnabled = objectives.length > 0` — список не может быть пустым, иначе
   молча гаснут игра, лампочка и поправка реплики.
3. `success` требует ВСЕ цели (`canonicalizeDialogTurnState` понижает success до
   stalled при неполном списке). Значит цели обязаны быть реально достижимыми
   в разговоре на 2–3 реплики каждая, иначе победы не будет никогда.
4. Потолок обменов `RECOMMENDED_EXCHANGES = 14` (поднят в этой же сессии) —
   7 целей × ~2 реплики укладываются; больше 7 ставить нельзя.

Правила содержания целей (выведены из существующих хороших примеров):
- цель = речевое действие («попросить счёт»), а не состояние («понять меню»);
- порядок = ход живого разговора, первая цель выполняется первой репликой;
- для конфликтных сцен (`challenge`) цели описывают, как человек ведёт себя
  под давлением: назвать проблему, не согласиться, предложить решение;
- медицинские/юридические темы: НЕ ставим цели, требующие совета (лекарство,
  дозировка, диагноз) — их режет серверный `sanitizeRegulatedAdviceReply`.

## Security and privacy

Правка чисто контентная: строки в клиентском бандле. Новых полей, сервисов,
разрешений и персональных данных нет; в Firestore ничего не пишется. Privacy
policy обновления не требует.

Единственная содержательная граница безопасности — медицинская: в `pharmacy`
и `doctor_visit` цели не должны подталкивать персонажа к выдаче лечения или
дозировки. Соблюдается явно (см. Architecture).

- Автонарезка `scenarioObjectives` после этой задачи почти не используется.
  Disposition: **Contain** — оставляем как страховку для новых сценариев,

- Метки целей только на ru (+es у части). Disposition: **Accept temporarily**.

  Impact ceiling: не-русские интерфейсы видят русскую метку в чек-листе — как
  и до этой правки, регрессии нет.

## Rollback

`git revert` коммита возвращает прежние списки; сценарии без целей снова
получают автонарезку из `goalEn` — то есть поведение до задачи. Данных не
мигрируем. Риск для уже идущих диалогов: сохранённый `objectivesMet` содержит
id старых целей; после отката они снова совпадут, после применения — просто не
найдутся и цель будет считаться невыполненной (диалог не сломается, максимум
придётся закрыть цель заново). Прогресс «Пройдено» хранится по id СЦЕНАРИЯ и
не затрагивается.
