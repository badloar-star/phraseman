## ФАЗА 1 — Разговорные режимы: ядро UI + STT — ✅ УЖЕ БЫЛА РЕАЛИЗОВАНА (прошлые сессии speaking-mode)
**Статус:** фундамент построен до начала этой работы (см. вердикт Ф0). `SpeakingPanel` + on-device STT

**Цель (исходная):** один рабочий разговорный режим end-to-end, переиспользуемый.
**Задачи:**
- Компонент **VoiceEqualizer**: реагирует на громкость голоса юзера в реальном времени (визуальный отклик), on-device.
- Компонент **ScoreRing**: кружок заполняется на % правильности, проценты в центре (стиль Rosetta).
- STT-обёртка: записать → распознать on-device → вернуть текст → сравнить с эталоном → % совпадения (нормализация регистра/пунктуации, толерантность к мелким ошибкам).
- **Скоринг СТРОИМ САМИ (критично).** Нативный STT отдаёт ТЕКСТ (транскрипт), а не «процент правильности произношения». «% совпадения» = наша функция поверх транскрипта (нормализация + расстояние строк/по словам, опц. фонетика типа Soundex/double-metaphone). НЕ выдавать случайный/жёстко-зашитый процент — это ровно ловушка текущего `plan_pronunciation_repeat`. Скоринг должен быть детерминированным и покрыт юнит-тестами (тот же транскрипт → тот же %).
- Кнопки: «Прослушать» (TTS/аудио эталона), «Ещё раз» (перезапись), «Дальше» (видна ТОЛЬКО при score ≥ 90% — порог `PRONUNCIATION_PASS_THRESHOLD`, решение владельца 2026-06-10).
- Первый режим: **«Скажи фразу»** (показан текст ru→ скажи по-английски / или показан эталон → повтори).
**Критерии готовности:**
- [ ] Юзер говорит → эквалайзер живой → распознаётся on-device → кружок показывает % → <90% прячет «Дальше», ≥90% показывает.
- [ ] «Прослушать» и «Ещё раз» работают.
- [ ] Никаких сетевых вызовов к платным сервисам (проверено).
- [ ] tsc/jest зелёные.

## Известные риски STT (зафиксировано до Ф0 — не переоткрывать)
1. **`@react-native-voice/voice` плохо живёт на современном Expo.** Пакет давно почти не мейнтейнится и регулярно конфликтует со свежими Expo SDK (нужен dev build / config plugin, ломается на managed workflow). НЕ ставить его вслепую первым. В Ф0 сначала проверить `expo-speech-recognition` (community, заявляет on-device на iOS/Android) и нативные API; `react-native-voice` — запасной вариант, не дефолт.
2. **Нативный STT даёт ТЕКСТ, а не «процент произношения».** iOS Speech / Android SpeechRecognizer возвращают транскрипт. «Кружок на 90%» = НАШ скоринг поверх текста — УЖЕ реализован в `app/personal_plan_pronunciation_scoring_core.ts` (детерминированный, с тестами). Риск фейкового процента закрыт в Ф0.
3. **on-device ≠ всегда офлайн на Android.** Часть устройств уходит в облачное распознавание. Требование владельца — без платных сервисов и без отправки голоса наружу; в Ф0 подтвердить именно on-device-режим (флаг `requiresOnDeviceRecognition`/эквивалент), иначе это нарушение инварианта `phraseman_no_paid_speech`.
