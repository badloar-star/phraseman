## Outcome

Пять правок по решению координатора, в порядке 1 → 4 → 2 → 3 → 5.

1. Выплата Пика за место и повышение сразу видна в балансе шапки.
   - Крон дописывает в итог недели снимок кошелька после выплаты: `starsBalanceAfter`, `starsEarnedTotalAfter`, `starsSeq`.
   - Клиент при загрузке итога вливает снимок через `mergeLevelSpinServerStars`. Защита по starsSeq не даёт старому снимку затереть свежий.
   - «+N монет» показывается только при `rewardStatus = paid`.
2. Заморозка серии Plus при неизвестном статусе Plus не сбрасывает серию; при исчерпанном лимите сбрасывает с объяснением. Сначала логи `[STREAK-FREEZE]`.
3. Патч снимка серии в cloud_sync сверяется со свежим значением и не уменьшает число.
4. Отказ энергии `cancelled` в экзамене, экзамене уровня и диагностике даёт тот же тост, что в брифинге диалогов.
5. Сверка баланса на экране ранга не обнуляет число до ответа.

Мера успеха: тесты на каждую правку; у человека цифра монет и серии не прыгает вниз и не врёт.

## Architecture

1. Новых путей начисления нет.
   - Сервер лишь дописывает в уже существующую запись итога (та же транзакция, merge) снимок кошелька из журнала монет.
   - Клиент применяет его единственным законным каналом серверных снимков, `mergeLevelSpinServerStars`. Он применяет только более новый starsSeq и не трогает несогласованные локальные операции.
2. Заморозка: решение «сбросить» принимается только при известном статусе Plus. Неизвестный статус откладывает решение до следующей проверки.
3. Снимок серии: перед записью снимка число сравнивается с текущим локальным, меньшее не пишется.

## Security and privacy

Новых данных о человеке нет. Баланс монет и номер операции уже лежат в users/{uid}.stars. Итог недели читает только владелец (firestore.rules: `userDocOwnerMatchesAuth`, запись клиенту запрещена). Сервер остаётся источником правды о балансе, клиент ничего не пишет на сервер. Privacy policy не затронута.

## Technical debt

- Contain: итог, прочитанный в короткое окно между записью итога и выплатой (один прогон крона), остаётся в кэше без снимка. Баланс догонит следующий урок, строки «+N» не будет. Это логируется.
- Defer: гонка publishProjection (п.6), по решению координатора.

## Verification

- Серверный тест выплаты:
  - снимок кошелька пишется в итог при новой выплате;
  - при повторе снимок берётся из расписки.
- Клиентский тест загрузки итога:
  - снимок вливается;
  - без снимка вливания нет;
  - строка «+N» только при paid.
- Тест заморозки: «статус неизвестен → серия цела».
- Тест снимка серии: меньшее число не пишется.
- Тест тоста отказа энергии.
- Тест use_coin_balance: нет null при reconcile.
- Typecheck затронутых файлов.

## Rollback

- Сервер: поля в итоге лишние и безвредны. Откат — убрать запись полей.
- Клиент: убрать вызов слияния. Без полей он и так ничего не делает.
- Остальные правки откатываются по одному коммиту на пункт.
