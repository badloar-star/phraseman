# Тренировка слов по одному в «Скажи вслух» (Speaking word drill)

**Дата:** 2026-07-04
**Статус:** дизайн одобрен, готов к плану внедрения
**Область:** `components/SpeakingPanel.tsx` + новые чистые модули `app/speaking_word_drill*.ts`

---

## 1. Проблема и идея

Сегодня после голосовой попытки панель «Скажи вслух» (`SpeakingPanel`) уже раскрашивает
фразу по словам — зелёный (чисто), жёлтый (нечётко), красный (не прозвучало) — и даёт
кнопки «Моя запись» / «Эталон» на **всю фразу целиком**. Но:

- слова — статичный текст, по ним нельзя нажать;
- эталон озвучивается только фразой, отдельное слово послушать нельзя;
- повтор всегда переигрывает **всю фразу**, нет цикла «дожать одно слово до идеала».

**Идея пользователя:** после голосового ввода фразы дать возможность сразу **послушать,
повторить и потренировать отдельные слова**, чтобы добиться 100% правильного звучания
каждого проблемного слова.

## 2. Что уже есть (переиспользуем)

- **Пословный статус уже считается** после каждой оценённой попытки —
  `buildSpokenWordReport` → `SpokenWordEntry[]`, index-aligned с
  `speakingTargetTokens(targetText)`:
  ```ts
  type SpokenWordStatus = 'clean' | 'fuzzy' | 'missed';
  type SpokenWordEntry = {
    target: string;
    status: SpokenWordStatus;
    heard?: string;            // что услышал движок в этом слоте
    soundHints?: SoundHint[];  // напр. /TH/ вместо /S/
  };
  ```
  Держится в стейте панели (`wordReport`). Это ровно те данные, что нужны тренажёру.
- **Фонетический разбор** — `speaking_phoneme_diff.ts` (Double Metaphone + ARPAbet g2p,
  `comparePhonemes`, `SoundHint`).
- **Скоринг** — `personal_plan_pronunciation_scoring_core.ts` (`wordSimilarity` и пр.).
- **Опции распознавания** — `speaking_recognition_options.ts` (`buildSpeakingStartOptions`,
  биасинг через `contextualStrings`).
- **Запись/распознавание** — потоковый системный движок (iOS + Android fallback),
  запись+whisper на Android (`speaking_hold_recorder.ts`, `speaking_neural_judge.ts`).
- **Озвучка** — `expo-speech` уже импортирован в панели (`playReference` = `Speech.speak`).

## 3. Чего сегодня НЕТ (добавляем)

- **Оценки одного слова** (скоринг только пофразовый) → новый чистый модуль.
- **Озвучки одного слова** → тонкая функция на `Speech.speak(word)`.
- **Пословного цикла повтора/тренировки** → новый под-поток в панели + чистый редьюсер.

## 4. Границы (scope)

**В объёме:**
- Внутри `SpeakingPanel`, после оценённой попытки, **жёлтые и красные** слова становятся
  нажимаемыми. Тап открывает инлайн-карточку слова (выезжает под картой фразы; фраза
  остаётся видна). Открыта всегда только одна карточка.
- Карточка: слово + транскрипция, строка «услышал … · звук /x/ вместо /y/» (когда есть),
  кнопки **«Послушать»** (эталон слова, TTS) и **«Повторить»** (запись одного слова + оценка).
- Слово оценивается отдельно; при «чисто» перекрашивается в карте в зелёный.
- Когда все слова карты зелёные — короткая плашка «Фраза идеальна» + success-хаптик.

**Вне объёма (НЕ делаем):**
- Зелёные слова не тренируем (остаются зелёным текстом, не кнопки).
- **Не трогаем** онбординг (`components/onboarding_aha/SpeechBeat.tsx`) и ИИ-диалог
  (`app/ai_dialog_session.tsx`) — у них своя речевая логика, там цель — общение, а не
  полировка слова.
- Не добавляем отдельный экран — всё в существующей модалке.
- **Не меняем** пофразовый балл, порог прохождения фразы (`PLAN_PRONUNCIATION_PASS_THRESHOLD`),
  honesty-контроль фразы. Плашка «Фраза идеальна» — чисто позитивное подкрепление, попытку
  не перезачитывает и балл не меняет.

**Охват:** одно изменение в `SpeakingPanel` → фича появляется автоматически везде, где
панель монтируется (уроки `lesson1`, персональный план `personal_plan_exercise`, тренажёр
фраз `trainer_phrases_session`, через `SpeakingButton`).

## 5. Оценка одного слова (Путь 1 + страховка)

Гибрид: распознать слово и сверить — основной путь; «послушай себя ↔ эталон» — мягкая
страховка при «не расслышал».

1. Пользователь жмёт «Повторить» → короткая сессия распознавания на одно слово (тот же
   движок, что и для фразы; биасинг на целевое слово через `contextualStrings`).
2. Полученный текст → `judgeSingleWord({ target, heardTranscript, segments? })` →
   вердикт `clean | fuzzy` (+ `heard`/`soundHints`). Ядро переиспользует
   `speaking_phoneme_diff`/scoring-core — **нового фонетического кода не пишем**.
3. Реакция:
   - **clean** → слово в карте зеленеет, success-хаптик, карточка авто-сворачивается (~1с).
   - **fuzzy** → слово остаётся жёлтым/красным, показываем `heard` + звук-подсказку, кнопки
     активны, можно ещё раз.
   - **no_speech (не расслышал)** → **НЕ провал**: мягкий текст «не расслышал, скажи чуть
     громче», всегда доступны «Послушать» и «Моя запись», дать ещё попытку.

**Порог «чисто для слова»** — отдельная константа, чуть мягче фразового (короткое слово даёт
движку меньше контекста; слишком строгий порог сделал бы 100% недостижимым). Точное число
подберём на этапе плана/тестов. Принцип: «чисто = фонетически совпало и нет явного не того
звука».

**По платформам:** iPhone (потоковый движок) и Android-с-whisper (запись+whisper) —
надёжно. Старый Android без whisper — распознавание слабее, чаще «не расслышал»; страховка
«послушай себя ↔ эталон» закрывает пробел.

## 6. Устройство кода

Логику держим ОТДЕЛЬНО от UI (панель уже ~1430 строк). Ядро — на готовых модулях.

**Новые чистые модули (без React, юнит-тестируемые):**

- `app/speaking_word_drill.ts`
  - `judgeSingleWord({ target, heardTranscript, segments? }): { status: 'clean' | 'fuzzy'; heard?: string; soundHints?: SoundHint[] }`.
  - Порог «чисто для слова» — одной именованной константой.
  - Собирает вокруг `speaking_phoneme_diff`/`personal_plan_pronunciation_scoring_core`;
    своего фонетического кода не содержит.

- `app/speaking_word_drill_state.ts`
  - Чистый иммутабельный редьюсер: какое слово открыто, какие слова «дочинены» до зелёного,
    флаг all-clean. Каждое изменение — новый объект (правило иммутабельности проекта).
  - Панель дёргает редьюсер и рисует по его состоянию.

**Меняем существующее:**

- `components/SpeakingPanel.tsx` — только UI-слой:
  - в цикле карты слов (~строки 1096–1130) жёлтые/красные слова оборачиваем в `Pressable`
    (пунктирное подчёркивание + `hitSlop`, `accessibilityRole="button"`);
  - инлайн-карточка слова с «Послушать»/«Повторить» и состояниями (см. §7);
  - под-поток записи ОДНОГО слова (короткая сессия) + вызов `judgeSingleWord`;
  - перекраска слова = обновление локальной копии `wordReport` через редьюсер;
  - взаимная блокировка: микрофон карточки и микрофон всей фразы не работают одновременно.
  - «сказать слово» — маленькая функция на базе `expo-speech` (по аналогии с `playReference`).

**Переиспользуем как есть (не трогаем):** `speaking_recognition_options`,
`speaking_hold_recorder`, `speaking_neural_judge`, `speaking_phoneme_diff`,
`personal_plan_pronunciation_scoring_core`, весь пофразовый скоринг и honesty-контроль.

## 7. UI: карточка слова и состояния

**Карта фразы (после оценки):**
- Жёлтые/красные — нажимаемые (пунктир + `hitSlop`); зелёные — обычный зелёный текст.
- Тап → под картой плавно раскрывается ОДНА карточка; тап по другому слову переключает.

**Карточка слова:**
- слово крупно + транскрипция (если доступна);
- строка «услышал «…» · звук /f/ вместо /p/» — из готовых `heard`/`soundHints`, только когда есть;
- кнопки **«Послушать»** (эталон слова, TTS) и **«Повторить»** (микрофон на одно слово);
- крестик «свернуть».

**Состояния карточки:**
`idle` → `listening` (пишу…) → `scoring` (проверяю…) →
- `clean` — галочка, слово зеленеет, авто-сворачивание ~1с;
- `fuzzy` — осталось нечётко, подсказка по звуку, кнопки активны;
- `no_speech` — «не расслышал», «Послушать»/«Моя запись» + ещё раз.

**Финал:** все слова зелёные → ненавязчивая плашка «Фраза идеальна» + success-хаптик
(без изменения балла/зачёта).

**Тексты:** 8 языков (ru, uk, es, pt-BR, vi, id, tr, pl) через существующий хелпер `L(...)`.
**Тема:** из переданной `SpeakingPanelTheme` (`correct`/`warn`/`wrong`) — ничего нового.
**Доступность:** слова-кнопки с понятной подписью («тренировать слово coffee»); статусы
карточки озвучиваемы.

## 8. Тестирование

Соответствие правилам проекта (80%+, unit/integration).

- **Unit (чистые модули):**
  - `speaking_word_drill.ts` — `judgeSingleWord`: чистое совпадение → clean; близкая
    подмена → fuzzy + heard/soundHints; пустой транскрипт → как «не оценили» (обрабатывает
    вызывающий как no_speech); граничные случаи вокруг порога.
  - `speaking_word_drill_state.ts` — редьюсер: открыть/переключить слово, пометить чистым,
    all-clean-флаг, иммутабельность (исходный объект не мутируется).
- **Integration (панель):** тап по жёлтому слову открывает карточку; «чисто» перекрашивает
  слово и не трогает пофразовый балл; «не расслышал» не ставит провал; все зелёные → плашка.
- **Не ослаблять** `tests/perf_freeze_contract.test.ts` и существующие speaking-тесты.

## 9. Риски

- **Распознавание одного короткого слова** менее надёжно, чем фразы → страховка «послушай
  себя ↔ эталон» + «не расслышал ≠ провал». Порог «чисто для слова» подбираем на тестах.
- **Рост `SpeakingPanel.tsx`** → ядро вынесено в чистые модули; в панели только тонкий UI.
- **Двойная запись** (карточка + фраза) → взаимная блокировка микрофонов.
- **Нативная пересборка** может понадобиться только если тронем нативные модули — по
  дизайну НЕ трогаем (переиспользуем существующие), значит достаточно JS-бандла.

## 10. Совместимость с Performance Bible

Никаких новых постоянных слушателей/циклов; карточка живёт внутри уже существующей модалки,
монтируется по требованию. Живые сэмплы (эквалайзер) в карточке не переиспользуются вне
активной записи. Перекраска слова — локальное иммутабельное обновление, без тяжёлых ре-рендеров
всей модалки (по образцу существующего императивного эквалайзера, где это критично).
