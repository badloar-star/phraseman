# R1 · Optimistic UI: Главная и Уроки (аудит 12.10, вечер)

Заказ координатора. Образцы — `R1_SETTINGS_OPTIMISTIC_UI.md` и `R1_SPIRE_COMMUNITY_OPTIMISTIC_UI.md`. Пять проверок на действие:
**1** мгновенный локальный апдейт · **2** откат с сообщением · **3** защита от двойного тапа и гонок · **4** нет полноэкранного спиннера · **5** нет скачка цифры после ответа сервера.
Цена правки: S (до часа, один файл), M (полдня), L (с сервером). Читал код экранов целиком по цепочке «тап → состояние → диск/сеть», в эмулятор не заходил (им владеет Сверка).

Закреплено тестами: `tests/optimistic_home_lessons_audit.test.ts` (исходники экранов слишком тяжёлы для поведенческих тестов, сторожим места, где замок или журнал уже терялись).

## Побочная находка (моя же)

`tests/energy_start_confirmation_contract.test.ts` краснел: при «сперва логи» в `flashcards_swipe.startSession` ранний выход по замку стал блоком `{ fsLog(…); return; }`, а сторож искал `) return`. Смысл замка не изменился (читается до любого `await`), контракт обновлён — принимает оба вида записи.

Ничего. Монеты «Сегодня» уходят по существующему белому списку кошелька; новых полей, коллекций и вызовов нет.
