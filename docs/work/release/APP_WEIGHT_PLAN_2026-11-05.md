## 2. Ленивая загрузка (главный рычаг)

**Идея.** В бандле остаётся только то, без чего нельзя начать (манифест-оглавление, урок 1 выбранного языка, интро), остальное скачивается при выборе языка/урока и кладётся в `documentDirectory`, проверяется по `sha256`.

### 2.1 Классика — уже готова к этому

`modules/classic-courses/manifest.json` содержит для каждого `lessons-NN.json` **`bytes` и `sha256`**, плюс `rev` и `sourceZipSha256` языка. То есть контракт «файл ↔ хеш» уже есть; нужен только загрузчик: `CLASSIC_LESSON_LOADERS[lang][n]()` (сейчас `require`) заменяется на «прочитай из локального кэша, иначе скачай, проверь sha256, иначе упади на вшитую копию».

- Прогресс классики опирается на **номер урока и порядковый индекс фразы** (позиционные ключи). Перенос файла из бандла в загрузку их не меняет, пока **номер ↔ содержимое** стабилен. Гарантия: загрузчик берёт файл строго по ключу `lang/lessons-NN.json` и проверяет `sha256` из **вшитого** (не скачиваемого) `manifest.json`. Если выйдет новая `rev`, вшитый манифест обновляется вместе со сборкой, и позиции не «переезжают» тихо в середине жизни установки.
- Вшить в бандл: язык, который выбран при онбординге, уроки 1–2 (≈ 90 КБ). Остальные 4 языка — только по выбору.
- Риски: офлайн-первый запуск (решается вшитым уроком 1–2); потеря связи в середине урока (кэш последнего открытого урока + явная ошибка с повтором); место на диске (≈ 4,5 МБ на язык).

### 2.2 V2 — сложнее и важнее (167 + 23 МБ)

- Сегодня 1792 сессии × (`learner.json` + `learner.uk.json`) + `intro`, `answers`, `auxiliary`. Минимум два шага без смены формата:
  1. **Грузить только `learner` своей локали** (ru **или** uk): вдвое меньше без правки контента.
  2. Тянуть **по урокам** (`l01`…`l32` — папки), а не весь курс: пока пользователь на уроке 1–3, остальное не нужно.
- Манифест `factory_native_manifest_v1.generated.ts` (10,8 МБ исходника, ≈ 16 МБ байткода) сам разбить на: лёгкое оглавление (id сессий, счётчики) в бандле и тяжёлые поля по урокам — в шардах.
- **Хеши.** В V2 манифесте я хеши файлов не видел (в классике они есть). Нужно: сгенерировать `sha256` каждого шарда при `generated_release` (одна строка в генераторе) и положить в вшитое оглавление; иначе проверка целостности невозможна.
- **Позиционные ключи прогресса V2** — это идентификаторы сессий (`l01/s01…`) из оглавления; они остаются в бандле, а контент идёт по ним. Ключи не меняются, пока оглавление остаётся вшитым. Проверить перед работой: что `session id` не выводится из порядка массива, который будет изменён разбиением.
- Откуда качать: уже есть Cloudflare Worker и Storage для озвучки V2 (588 МБ вне приложения) — тот же канал, с токеном аккаунта (см. раздел политики про «download course audio»). Новых сторонних сервисов нет, **политика конфиденциальности не меняется** (запросы к нашему же хранилищу; формулировку про Cloudflare проверить при релизе).
- Риски: самый крупный из всего плана (меняется основной путь урока), нужны офлайн-сценарии, предзагрузка следующего урока в фоне по Wi-Fi, повтор при обрыве, откат (флаг «читать из бандла»). Вшитый fallback на урок 1 — обязательно.

### 2.3 Как это согласуется с OTA и ревью

Скачиваемый контент — данные, не исполняемый код, и сторы это допускают; важно не скачивать исполняемый JS. Флаг-откат и вшитая копия урока 1–3 нужны ещё и для офлайн-ревью.
