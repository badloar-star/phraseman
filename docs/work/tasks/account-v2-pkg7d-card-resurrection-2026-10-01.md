## Outcome

TEMP из 6G (add-only применение гидрации) и остаток ревью 7A (P3-3): карточка или набор, удалённые на телефоне, могут «вернуться»:
- (а) удалены на телефоне ДО включения V2 → перенос OD21 берёт их из старого облака (если старое облако ещё не успело получить удаление) → гидрация добавляет обратно;
- (б) выключатель 7A вкл, выход/вход тем же аккаунтом → старый restore из устаревшего облака возвращает удалённые после включения карточки, затем V2 добавляет своё;
- (в) удалены на другом устройстве (tombstone в V2), а на этом телефоне ещё лежат → гидрация add-only их не убирает.

1. Анализ: где удаляются сохранённые/свои карточки и наборы библиотеки (hooks/use-flashcards.ts, app/flashcards/custom_cards_store.ts, communityOwnedStorage.ts), что уже есть из «журнала удалений», как V2 хранит tombstone (сущность карточки, removed в библиотеке), что видит pull.
2. Решение (минимально и безопасно):
   - гидрация применяет tombstone из V2: карточка/набор, удалённые в V2 ПОЗЖЕ, чем локальная правка этой карточки, убираются локально (сравнение по времени/ревизии; локальная более свежая правка выигрывает — никаких удалений «на всякий случай»);
   - локальный журнал удалений (id + время, ограниченный размер, аккаунтный ключ — стирается вместе с данными аккаунта, входит в инвентарь `accountLocalDataKeysForToday`) — producer отправляет tombstone по нему, а restore/гидрация не возвращают id из журнала;
   - для (б): после старого restore при наличии журнала/tombstone V2 повторно убрать воскрешённое.
3. Логи `[ACCOUNT-V2]` на каждом решении «убрать/оставить» с причиной (без uid/PII).
