# Task packet: окно выбора Google показывается при каждом входе (прогон 18.10, сценарии №1/№9)

Governance-ID: TG-84DC38FCB1EE
Status: В работе
Owner: 5 · АВТОРИЗАЦИЯ

## Outcome

Каждое нажатие «Войти через Google» открывает окно выбора аккаунта. После отказа (account_switch_required), отмены или
закрытия приложения посреди входа следующий вход не подставляет молча прежний аккаунт.

## Scope

- app/auth_provider.ts: runGoogleNativeSignIn — перед НОВЫМ нативным вызовом signIn снять прежнюю нативную сессию Google
  (GoogleSignin.signOut, срок 3 с), с журналом; висящий вызов по-прежнему переиспользуется.
- tests: контракт исходника.

## Architecture

Факт (эмулятор 18.10 10:49 и 10:55, logcat): `[AUTH-LINK-GOOGLE] start` → `native ok` через 1,7 с без окна выбора,
providerSubject = аккаунт прошлой (отказанной / прерванной) попытки. GoogleSignin.signOut вызывается только в
performCurrentProviderSignOut (обычный выход), поэтому нативная сессия Google переживала отказ и убийство процесса.
Следствие — тупик: выбрал не тот аккаунт → отказ → повтор снова молча тот же. Сброс нативной сессии Google не трогает
Firebase-личность (гость остаётся гостем) и не влияет на продолжение входа после смены аккаунта (там сохранённый
пропуск, без нового signIn).

## Security and privacy

Только сброс локального выбора аккаунта Google на телефоне; данных не собираем. Журнал — код ошибки без токенов.

## Technical debt

+≈100–300 мс перед окном выбора (локальный вызов). Отказ signOut не блокирует вход (пишется причина).

## Verification

Точечные тесты через светофор; эмулятор: после отказа/прерванной попытки повторное нажатие показывает окно выбора.
