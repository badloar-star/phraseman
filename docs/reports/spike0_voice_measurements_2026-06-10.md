## D. Слепой A/B качества голоса (5 человек) — решение по TTS

Дать послушать ОДНУ и ту же фразу Фила, озвученную 3 движками, **не говоря какой есть какой**. Пусть оценят «насколько приятно/живо» 1–5 и выберут лучший.

| Слушатель | Kokoro (on-device) | Облачный neural (Google/OpenAI) | Сток expo-speech | Выбрал лучший |

| 1 | /5 | /5 | /5 | |
| 2 | /5 | /5 | /5 | |
| 3 | /5 | /5 | /5 | |
| 4 | /5 | /5 | /5 | |

> Для облачного образца — сгенерировать заранее (Google Cloud TTS Standard ~$4/1М симв или OpenAI gpt-4o-mini-tts) и сохранить mp3. Сток — то, что играет прототип без Kokoro.

## E. ГЕЙТ — решение по итогам (заполнить вывод)

- [ ] **Голос на бюджетном Android:** живой / приемлемо / мёртвый → _____
- [ ] **Лучший TTS по слепому тесту:** Kokoro / облако / сток → _____
- [ ] **WER на акценте (среднее):** _____ %

**Развилки:**
- Если бюджетный Android **мёртвый** → либо облачный TTS обязателен (он легче on-device-Kokoro), либо голос-фича только для флагманов (сузить аудиторию в позиционировании).
- Если **Kokoro проигрывает облаку** и звучит роботно → ставить облачный neural TTS для английской речи (правило проекта «no paid cloud» = про STT, не TTS — подтвердить владельцу).
- Если **WER > 35%** → whisper.rn-тумблер в инкремент, держать сессии короткими.
- Если всё «живое» и Kokoro звучит хорошо → **зелёный свет MVP-1** (скелет: голос+текст нить, память из SRS, recap→SRS).

### Итог простыми словами
- Это таблицы, которые ты заполняешь, пока тестируешь на телефонах — они дают честный ответ, стоит ли вообще делать голос.
- Главный телефон в тесте — недорогой Android: если на нём голос тормозит или греется, это меняет план.
- Отдельно вслепую сравниваешь три голоса на живых людях — какой приятнее; от этого зависит, оставляем бесплатный голос на телефоне или берём облачный.
- В конце — простое решение: зелёный свет делать дальше, или сначала чинить голос/сужать аудиторию.
