## Outcome

В 3c45d2b0c decideFriendsCacheAgainstCachedSocialEvent запоминал «самое свежее событие дружбы, по которому уже
сбросили кэш» одной переменной на весь телефон. После смены аккаунта A → B отметка A (поздний createdAt) могла
скрыть более раннее, но свежее для B событие: решение 'already_handled', кэш друзей B не сбрасывался до 30 мин.
Теперь отметка хранится по владельцу кэша (stableId из scopeKey кэша друзей/заявок).

## Scope

- app/firestore_friend_requests.ts: Map stableId → время последнего обработанного события; владелец берётся из
  scopeKey текущего кэша; в вердикт и журнал добавлен признак, что отметка своя.
- tests/firestore_friend_requests.test.ts: сценарий «A обработал позднее событие → смена на B → событие B (раньше
  отметки A, но новее загрузки кэша B) → invalidate».

## Architecture

Отметка живёт только в памяти процесса; uid в журнал не пишется. Кэш друзей сам по владельцу (scopeKey), поэтому
отметка берёт владельца оттуда же — без нового чтения текущего uid.

## Security and privacy

Решение одного аккаунта больше не влияет на другой. Новых данных нет.

## Technical debt

Карта растёт на одну запись на владельца за жизнь процесса — пренебрежимо.
