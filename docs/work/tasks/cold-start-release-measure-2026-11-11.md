## Outcome
Сравнимые числа холодного старта release-сборки текущего дерева на слабом профиле (2 ядра / 2 ГБ): старт процесса →
`[COLD-START] js_entry` → `[HOME-PAINT] first_frame` → `[COLD-START] native_splash_hidden`, `am start -W`, обращения к
хранилищу за 15 с. Рядом — та же серия для сборки 04.10 (`app_fin7`, база PM-010) на том же эмуляторе в тот же день,
чтобы отделить нагрузку ПК от изменений кода.

## Scope
In scope: `scripts/cold_start_measure.mjs` (замер, закоммичен cee5bb96e), отчёт в `docs/work/`, вспомогательные скрипты
и журналы во временной папке сессии, отдельный AVD `Phraseman_ColdStart` (порт 5580).
Out of scope: любые правки поведения старта и Главной; чужие эмуляторы (`emulator-5554` и AVD Pixel_8*); iOS.

## Architecture
Один release x86_64 APK текущего дерева (`assembleRelease`, `EXPO_PUBLIC_STORE_RELEASE=1`, через светофор), установка
на чистый AVD, прохождение онбординга гостем, затем серии по 6 холодных запусков. Разбор журналов — общий с
`scripts/pm220_perf_gates.mjs`.

## Security and privacy
В журналах только время и счётчики. Прохождение онбординга создаёт одного гостевого пользователя в боевом проекте
на каждую установку (как и замер 04.10); личных данных нет. Ключи и `.env` никуда не копируются.

## Technical debt
Новой не создаёт. Скрипт замера заменяет потерянный `baseline010.sh`.

## Verification
Самопроверка разбора на синтетическом журнале; отказ на отладочной сборке; в отчёте — паспорт каждого прогона
(сборка, AVD, ядра, память) и число запусков с полными метками.

## Результат замера 11.11 (13:07–13:15, AVD Phraseman_ColdStart, 2 ядра / 2 ГБ, Android 15)

Условия плохие и это часть результата: на ПК 120+ процессов node/claude, свободно 1–4 ГБ, CPU хоста ~91 %, эмулятор
дважды уходил в offline. Числа годятся только для сравнения двух сборок между собой в один час, не с базой октября.

| Сборка | Старт процесса → первый кадр Главной, мс | Медиана | Обращений к хранилищу за 15 с |
|---|---|---|---|
| store-release 04.10 (`app_fin7`, 1.5.60) | 3996, 3506, 3821 (первый после установки 9282 — отброшен) | 3821 | 279–309 |
| release 11.11 (дерево 77fc67412 + незакоммиченные правки сессий) | 3211, 3509, 5743, 2414, 5039 (первый после обновления 4176 — отброшен) | 3509 | 501–526 |

Новая сборка по отрезкам (5 запусков): процесс → `js_entry` 1037–4080 (медиана 1639); `js_entry` → первый кадр
1377–2496 (медиана 1663); первый кадр → снятие заставки 146–280.

Выводы:
1. Разницы во времени старта между сборками при таком шуме не видно (3,5 с против 3,8 с при разбросе 2,4–5,7 с).
   Та же сборка 04.10 в октябре давала 1496 мс — сегодняшний стенд медленнее примерно в 2,5 раза. Цель «1 с» не проверена.
2. Обращений к хранилищу на старте стало ~505 при потолке бюджета 240 (`config/perf-budgets.json`) — устойчиво во всех
   запусках. Главный источник: ключ `premium_real_snapshot_v1:<uid>:pending` читается 46–52 раза и
   `premium_real_snapshot_v1:<uid>` 23–26 раз за 15 с (`app/premium_real_storage.ts`), ещё `loyalty_gift_verified_copy_v1`
   до 22 раз. Оговорка: на эмуляторе нет биллинга (RevenueCat 17 ошибок `BILLING_UNAVAILABLE`) — часть повторов может
   быть следствием этого; проверять на устройстве с Play.
3. Заставка снимается через 0,15–0,28 с после первого кадра; метка `native_splash_hidden` в release работает.

Не сделано: сценарии «офлайн», «холодная ссылка», «смена аккаунта», отклик первого тапа, iOS; серия ≥ 6 чистых запусков
на спокойной машине. Журналы — во временной папке сессии (не в репозитории).
