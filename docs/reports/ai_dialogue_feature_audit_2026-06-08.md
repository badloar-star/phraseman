# ИИ-диалоги в Phraseman: стратегический документ

> Дата: 2026-06-08. Источник: многоагентный аудит (5 аудиторов кодовой базы + 4 ресёрчера рынка/экономики + синтез), ~890K токенов.
> Вводные владельца: цель = practice+закрепление+тьютор+ролёвки; бюджет = только премиум окупает облачный LLM; формат = текст сначала, голос фаза 2.

## 1. Вердикт: стоит ли делать

**Да, делать — но с трезвой оговоркой по аудитории.** Это не «ещё одна болталка с GPT», а возможность занять практически пустую нишу: *50+ + русскоязычный + учит английский + beginner/early-intermediate*. Все топ-конкуренты (Speak, Loora, Duolingo Max, ELSA) её недообслуживают — у них англоязычный интерфейс объяснений, штраф за не-американский акцент, youth-центричная геймификация и, главное, **отсутствие памяти между сессиями** (жалуются на это и Speak, и Loora, и Duolingo). У Phraseman уже есть то, чего у них нет: 10 000+ фраз, SRS-история ошибок каждого юзера (`trainer_store.ts`, `active_recall.ts`), русская локализация объяснений (`diagnosis_training` уже даёт TriText-объяснения на ru), on-device speech без платных сервисов.

**Чем выигрываем:**
- Экономика феноменальная. Текстовый диалог на GPT-4o-mini стоит **$0.003–0.004 за диалог**, активный юзер — **$0.08–0.12/мес**. При подписке $4.99/мес (нетто ~$3.49–4.24 после стора) валовая ИИ-маржа **97–99%**. Облако окупается с запасом в ~1000 диалогов на юзера до точки безубыточности. Бюджетного риска при текстовом MVP по сути нет — только abuse-риск (боты), который гасится лимитами.
- Педагогически фича реально учит, если встроить SRS-фразы юзера как forced output (spaced retrieval в разговоре) — это сильнейший дифференциатор, которого нет ни у кого.
- Архитектура готова на 90%: паттерн trainer-сессии, premium-гейтинг, прокси-ключа через Cloud Function (`pronunciation_scoring.ts`) — всё переиспользуемо.

**Чем рискуем:**
- **Аудитория 50+ боится чата с открытым вводом.** Главный продуктовый риск. Пустое поле «напишите что-нибудь по-английски» для новичка 60 лет = паралич. Это решается UX (см. §2, §6, §8), но если проигнорировать — фича не взлетит независимо от качества LLM.
- **On-device для free как «живой ИИ» — мёртв.** Ресёрч однозначен: ExecuTorch/llama.rn хотят 6–8 ГБ RAM, целевые телефоны 3–4 ГБ крашатся. Free-tier нельзя строить на on-device LLM.
- Speech-фаза 2 на старых телефонах тормозит (5–15 tok/sec), но это фаза 2 и не блокер MVP.

**Вывод: делать, текстом, premium-фичей с free-teaser, с UX, спроектированным под страх чата у 50+.** Не делать — значит отдать единственную незанятую нишу рынка конкурентам, которые до неё пока не дотянулись.

## 2. Что это будет

Один экран-движок — **«Разговор с ИИ»** — с четырьмя режимами, которые юзер не воспринимает как четыре отдельные фичи. Это **один диалоговый интерфейс**, где режим задаёт *сценарий и системный промпт*, а UX одинаков. Принцип: **никогда не показывать 50+ юзеру пустое поле ввода в роли первого шага.**

**Четыре режима как «карточки старта»:**

1. **Ситуации / ролёвки** (`scenario`) — «Закажите кофе», «Регистрация в отеле», «У врача». ИИ играет роль (бариста, портье). Цель ситуации видна заранее на русском. Это самый безопасный вход для 50+ — есть структура и понятная цель (педагогика: situational task снижает тревожность).
2. **Закрепление выученного** (`recall_drill`) — ИИ строит разговор вокруг фраз/слов юзера, которые сейчас «к повторению» по SRS (`getDueItems`, `getTrainerPremiumItems('smart_mix')`). Юзер вынужден *произнести* выученное (forced output), а не узнать его в карточке. Это уникальный режим — ровно то, чего нет у конкурентов.
3. **Practice / свободный разговор** (`free_talk`) — открытая беседа на тему по уровню юзера. Для более уверенных. Для новичков прячется или подаётся с подсказками-кнопками готовых ответов.
4. **Тьютор / объяснялка** (`tutor`) — «Спросите про грамматику»: «почему a/an?», «в чём разница since/for?». ИИ отвечает **на русском** с примерами. Фактически это conversational-версия `diagnosis_training`.

**Что видит юзер в сессии (один UX для всех режимов):**
- Чат-лента с крупным шрифтом (наследуем `fontSize` из `ThemeContext`).
- Реплика ИИ — с **кнопкой 🔊 озвучить** (готовый `useAudio()`/expo-speech) и **кнопкой «перевод»** (тап → русский перевод реплики; на A1–A2 показывается, на B2+ прячется).
- Ввод: поле + **3–4 кнопки-подсказки готовых ответов** (suggested replies) — критично для 50+, снимает паралич пустого поля. Юзер может тапнуть готовый ответ или напечатать свой.
- **Мягкая коррекция в потоке (recast):** если юзер ошибся, ИИ ненавязчиво переформулирует правильно и продолжает, не прерывая разговор.
- **Никаких таймеров, стрик-стыда, давления.** Право на ошибку и повтор без штрафа.
- В конце — **«Разбор после диалога»**: 2–3 ключевые ошибки с explicit-объяснением **на русском** + «вы употребили 5 выученных слов, говорили N реплик». Это и retention-крючок, и педагогика.

## 3. Точки внедрения

**Главный вход — отдельный модальный экран `/ai_dialog_home`** (новый файл `app/ai_dialog_home.tsx`), вызываемый карточкой с Home Tab (`app/(tabs)/home.tsx`, ~строка 2838, рядом с trainer/PersonalPlanCard). Это самый видимый CTA. Карточка показывается под условием `if (studyTarget)` — энергию для входа не требуем (вход бесплатный, лимит считаем по диалогам, не энергии).

**Сессионный движок — `app/ai_dialog_session.tsx`**, построенный по паттерну `trainer_phrases_session.tsx`: state-машина `messages[]`, экран-репорт в конце (аналог `trainer_session_report.tsx`). Режим (`scenario|recall_drill|free_talk|tutor`) и параметры (lessonId, studyTarget) передаются через params expo-router.

**Вторичные точки (фаза 2+, после валидации главного входа):**
- **После урока** — кнопка «Обсудить с ИИ» на `lesson_complete.tsx` → `/ai_dialog_session?mode=scenario&lessonId=...`. Юзер уже в контексте материала. Фразы доступны через `lesson_data_all.ts`.
- **Личный план** — новый тип задачи `type:'ai_dialog'` в `personal_plan_catalog.ts` + визуал в `personal_plan_task_visuals.ts` + роут в `personal_plan_navigation.ts`. ИИ-диалог как одна из 5–7 дневных задач.
- **Тренажёр** — 4-й `SectionInfo` (`queue:'ai_dialog'`, icon `chatbubbles-outline`) в `trainer.tsx`. Логично, но это уже расширение, не MVP.

**Что НЕ трогать в MVP, чтобы не сломать существующее:**
- **Не встраивать в `review.tsx` inline** (предложение `pickReviewMode() → 'ai_dialogue'` при `Math.random()<0.15`). SRS-поток — критичный, любой сбой ИИ обрушит повторения. Оставить на потом.
- **Не вешать ИИ-диалог на расход энергии** так же, как trainer. Лимит ИИ — отдельный счётчик «диалогов/день» (см. §5), не `spendOne()`. Это чище экономически и не конкурирует за энергию с уроками.
- XP/achievements/daily_tasks — подключать **в конце сессии** (`registerXP`, `checkAchievements`, `updateMultipleTaskProgress`), чтобы фича жила в экосистеме, но не на каждом сообщении (иначе XP-инфляция).

## 4. Архитектура

### Текстовый MVP

```
ai_dialog_session.tsx (клиент, RN)
   │  httpsCallable('premiumDialogSend')  — Firebase Auth ID token
   ▼
Cloud Function premiumDialogSend (onCall, us-central1)
   │  request.auth.uid → источник правды (НЕ stableId из body!)
   │  1. auth-guard  2. валидация (len ≤ 2000)  3. rate-limit/quota ДО fetch
   │  4. собрать messages[] (system-промпт по режиму + обрезанная история)
   ▼
LLM API (OpenAI /chat/completions, GPT-4o-mini)
   ▲  Authorization: Bearer ${LLM_API_KEY}  ← из Firebase Secret Manager
   │  5. сохранить диалог + квоту + billing-лог в Firestore (транзакция)
   ▼
ответ: { assistantMessage, tokensUsed, remainingQuota } — без ключа
```

**Это новая функция — готовой интеграции LLM-диалогов в коде НЕТ.** Строим `functions/src/premium_dialog.ts` по образцу `pronunciation_scoring.ts` (единственный существующий LLM-вызов, уже с правильным проксированием ключа). Конфиг: `onCall`, `timeoutSeconds: 30`, `memory: '512MiB'`, `maxInstances: 20`.

**Критичные правила безопасности (из аудита бэкенда — это checklist):**
- **`request.auth.uid` как единственный источник identity.** НЕ принимать `stableId` из body — это та самая уязвимость, что висит в 15+ функциях (`league_chat`, `vip_survey`, и др.). `pronunciation_scoring` сделан правильно — копируем его, не их.
- **Ключ в Firebase Secret Manager** (`defineSecret('LLM_API_KEY')`), не в `.env.local`, не `EXPO_PUBLIC_*`. Никогда не возвращать ключ в response/error.
- **Rate-limit ДО fetch**, в Firestore-транзакции: `premium_dialog_quotas/{uid}` с `dailyCount/dailyTokens/resetAtMs`. Это против abuse, не ради экономии на норм-юзерах.
- Биллинг-лог каждого вызова в `premium_dialog_billing`.
- Включить `ENFORCE_APP_CHECK=true` для прода (сейчас false).
- Добавить в `deploy:safe` whitelist **только после стабилизации** (урок из памяти: `onArenaSessionAborted` не попал в whitelist и не задеплоился).

**Какую модель брать (с числами):**
- **Основная: GPT-4o-mini** ($0.15/$0.60 за 1M) — лучший баланс качества следования роли/коррекции и цены, автоматический prompt caching. ~$0.004/диалог, ~$0.12/мес на активного юзера.
- **Эконом-флор: Gemini 2.5 Flash-Lite** ($0.10/$0.40) — ~$0.0027/диалог, ~$0.08/мес. Для масс-free-teaser.
- **Премиум-качество для режима «тьютор» (сложные грамматические разборы): GPT-4.1-mini** ($0.40/$1.60) — ~$0.011/диалог, всё ещё окупается. Роутить только tutor-режим сюда.
- **Не брать в прод DeepSeek** (депрекейшн deepseek-chat 24.07.2026 + гео-риски). Claude Haiku 4.5 — качество отличное, но 8–10x дороже, только если A/B покажет заметную разницу.

**Оптимизация input (input = 95% стоимости — история+роль шлются каждый запрос):**
- **Prompt caching системного промпта** — экономия ~40–50% input.
- **Sliding window истории:** слать последние 6–8 реплик, старое суммаризировать в 1–2 предложения — режет накопленный input на 40–60%.
- **`max_tokens: 150–200`** на ответ — короткие реплики уместны педагогически и режут output.
- Внедрять caching + обрезку **с самого начала** — превращает $0.12/юзер в ~$0.03–0.05 при росте базы.

**Переиспользование паттерна trainer-сессии:** state-машина и финальный репорт копируются из `trainer_phrases_session.tsx`; контент-источник — не `getDueItems('ai_dialog')` (новая очередь не нужна), а `getTrainerPremiumItems('smart_mix')` для recall-режима. Контексты (`useTheme/useLang/useStudyTarget/usePremium`) подключаются автоматически через провайдеры `_layout.tsx`.

### Фаза 2 (голос)
On-device, без платного STT (жёсткое правило проекта). Всё готово:
- TTS реплик ИИ — `useAudio()` / expo-speech (en/ru/uk/es, регулировка темпа `normalizeSpeechRate` — критично для 50+).
- Распознавание речи юзера — `ExpoSpeechRecognitionModule` (on-device, no-server), паттерн из `personal_plan_exercise.tsx`.
- Скоринг ответа — `personal_plan_pronunciation_scoring_core.ts` (word-coverage, 90% порог).
- `VoiceWaveform` для live-listening индикатора.
- **Gaps фазы 2:** multi-turn state-машина голоса, graceful-прерывание TTS при новом распознавании, chat-scroll история. OpenAI Whisper-fallback — только для scored-feedback при confidence <0.75, не как primary recognition.

## 5. Free vs Premium лимиты

**Числа (синтез педагогики + экономики + рыночного коридора TalkPal 10 мин/день):**

| | Free | Premium |
|---|---|---|
| Диалоги/день | **1 полный диалог/день** (3–5 мин, ~6–8 обменов) | безлимит (мягкий cap 100/день против abuse) |
| День 0 (онбординг) | **1 диалог БЕЗ лимита сразу** (показать wow) | — |
| Teaser-обрыв | на 6–7 реплике «на интересном месте» → paywall | нет |
| Разбор ошибок после диалога | 1 раз/день | каждый диалог |
| Recall выученных SRS-слов | базово | все SRS-слова |
| Режим «тьютор» | teaser/on-device decision-tree | полный LLM |

**Как гейтить (точный паттерн из аудита premium-гейтов — копия `trainer_session.ts`):**
- Новый файл `app/dialogs_limit_session.ts`: `DAILY_FREE_DIALOG_KEY='dialogs_free_session_v1'`, функции `hasUsedFreeDialogToday()`, `markFreeDialogUsed()`, `getFreeDialogsLeftToday()`.
- В `remote_flags.ts`: добавить `free_dialogs_per_day` (дефолт 1), ENV `EXPO_PUBLIC_FREE_DIALOGS`, getter `getFreeDialogsPerDay()` (по образцу `getFreeTrainerSessionsPerDay`).
- В сессии при старте: `if (!hasPremiumAccess) { const left = await getFreeDialogsLeftToday(); if (left<=0) { showPremiumModal('dialog_limit'); return; } }`. После завершения — `markFreeDialogUsed()`.
- В `premium_modal.tsx` добавить context-тип `'dialog_limit'` (рядом с `'trainer_limit'`, `'no_energy'`).
- **Серверный лимит обязателен** независимо от клиентского (`premium_dialog_quotas/{uid}`) — клиентский гейт обходится, серверный нет.

**A/B-тест:** djb2-хеш по userId (детерминированный, уже есть для trainer). Группы `dialog_ab_a/b/c_pct` → 1/2/3 диалога free. Тестировать: какой free-лимит максимизирует конверсию не убивая trial. Цена: **держать $4.99/мес как сейчас** (низкая цена конвертит 47.8% vs 28.4% у дорогих), годовой $39.99 продвигать (~5x множитель, education годовой ~5.4x месячного).

**Экономика сходится с гигантским запасом:** free-юзер с 1 диалогом/день = ~30/мес = $0.12 максимум, но free делает меньше. Premium-юзер $0.08–0.12/мес ИИ-затрат против нетто ~$3.49–4.24 выручки = маржа 97%. Ограничитель — не цена токенов, а abuse (бот льёт тысячи запросов) → серверные лимиты.

## 6. Педагогика

Фича учит (а не игрушка) только если соблюдены 4 принципа из мета-анализов 2025:

1. **Адаптивная сложность (i+1).** Системный промпт ОБЯЗАН содержать CEFR-уровень юзера (берём из прогресса в приложении) и инструкцию «говори чуть выше текущего уровня, незнакомое слово вводи с контекстом-подсказкой». Единый промпт для всех уровней — главная ошибка, которую избегаем. Адаптивный бот даёт больший рост автономии и self-efficacy, чем статичный скрипт.

2. **Recall выученного через forced output.** Бот получает в контекст список SRS-слов «к повторению» (`getTrainerPremiumItems('smart_mix')`) и строит сценарий так, чтобы юзеру пришлось их **произнести**, а не узнать. Это превращает диалог в spaced-retrieval-тренажёр — сильнейший дифференциатор. После диалога — `markTrainerResult()` обновляет SRS, `logMistake()` пишет ошибки.

3. **Гибридная коррекция.** Внутри диалога — **recast** (мягкая переформулировка, не прерывая flow, d≈0.70, не убивает мотивацию). После диалога — **explicit-разбор** 2–3 ключевых ошибок на русском (d≈0.81, максимальный обучающий эффект). Не править каждую мелочь — выбирать значимые. Recast особенно силён для foreign-language контекста (русские учат английский вне среды).

4. **Градуированный русский (L1).** A1–A2: объяснения ошибок и значений на русском, реплики бота дублируются переводом по тапу, снижает тревожность. B1: объяснения на русском, диалог только на английском. B2+: минимум русского, объяснения по запросу. Не делать единого правила «всегда только английский» (отпугнёт новичков) или «всегда с переводом» (затормозит продвинутых). Это ровно барьер, который не решают ELSA/Speak/Loora.

**Мотивация не-бросать:** позиционировать как «безопасное место без осуждения» в онбординге; каждый диалог = ситуация с целью; пост-диалог показывает прогресс («7 новых слов, 3 минуты»); дать боту лёгкую персону/имя для bond. Adults benefit from explicit correction — но поданной не унизительно.

## 7. Конкуренты

**Копируем:**
- **Speak:** связку «watch → hear at multiple speeds → shadow с оценкой → free talk» как onboarding; регулировку скорости речи (нужна для 50+).
- **Duolingo Max:** сценарные роуплеи, привязанные к уровню курса; человеческий контроль контента (вычитка промптов на точность).
- **ELSA:** мгновенный гранулярный фидбэк (какой звук/интонация); 10-мин free как «разминка»-крючок.
- **TalkPal:** разнообразие режимов (дебаты, описание фото, персонажи) против приедания; честный 10-мин/день free-teaser.
- **Praktika:** прозрачная единая цена без апселл-лабиринта; low-pressure среда для застенчивых.

**Избегаем:**
- **Лимит 2–3 реплики** (Duolingo) — обрывает разговор на полуслове, фрустрирует. Наша ниша — «настоящий длинный разговор».
- **Отсутствие памяти между сессиями** (Speak + Loora + Duolingo) — это рыночная дыра. Мы храним историю и SRS → наш козырь.
- **Репетативность** (Speak на высоких уровнях) — лечим разнообразием сценариев + recall персональных слов.
- **Штраф за не-американский акцент** (ELSA) — толерантность к русскому акценту.
- **Англоязычный-только интерфейс** (ELSA, Loora) — объяснения на русском.
- **Обязательные отвлекающие аватары без аудио-онли** (Praktika) — для 50+ визуальная нагрузка когнитивно лишняя; аватар (если будет) — опция, не навязка.
- **Позиционирование «обёртка над GPT»** (риск TalkPal) — явная добавленная ценность: структура, память, коррекция, русская локализация, SRS-интеграция.
- **Цена $20+** (Duolingo Max $168/год) — не лезть туда без сильного бренда.

## 8. Риски и анти-паттерны

| Риск | Митигация |
|---|---|
| **Стоимость убегает (abuse)** | Серверная квота в Firestore-транзакции ДО fetch; rate-limit per-uid; биллинг-лог + Cloud Monitoring alert при daily cost > threshold. Норм-юзеры физически не могут разорить (1000+ диалогов до $4.99). |
| **50+ боятся пустого поля чата** | Кнопки-подсказки готовых ответов; старт всегда со сценария с целью (не пустого talk); «безопасное место без осуждения» в онбординге; крупный шрифт; озвучка + перевод по тапу. **Это главный продуктовый риск — UX решает.** |
| **On-device тормозит старые телефоны** | Free «живой ИИ» = облако (teaser-лимит), НЕ on-device LLM. On-device decision-tree как fallback для tutor-режима. On-device LLM/Gemini Nano — только opportunistic turbo для флагманов с runtime-детектом RAM≥8ГБ и fallback. |
| **Безопасность ключа** | Firebase Secret Manager; никогда не в клиент/response/логи; прокси через CF. |
| **Impersonation (stableId-уязвимость)** | `request.auth.uid` — единственная identity. Не повторять баг 15+ функций. |
| **Галлюцинации грамматики на русском** | Для tutor-режима — проверенные шаблоны/RAG из существующих `diagnosis_training`, не свободный SLM. Человеческая вычитка системных промптов. |
| **XP-инфляция / ломка экономики** | XP/achievements только в конце сессии, не на каждом сообщении. Лимит — отдельный счётчик, не энергия. |
| **Деплой сломает прод** | `deploy:safe` whitelist только после стабилизации; локальный emulator-тест; не трогать telegram/admin функции. |
| **Day-0 отмены** | 80–90% отмен в день установки → показать wow-диалог в День 0 без лимита; триал 7–14 дней (не 3 — конвертит на 70% лучше). |

## 9. План внедрения по фазам

**Фаза 0 — проверка спроса (3–5 дней, минимум кода).**
Карточка «Разговор с ИИ» на Home Tab → один сценарный режим, hardcoded системный промпт, GPT-4o-mini через простейшую CF (auth + квота, без caching/sliding-window пока). Лимит 1 диалог/день free, paywall-teaser. Цель: измерить *спрос* (CTR карточки, % завершивших первый диалог, конверсия teaser→premium). Если CTR карточки и completion низкие — UX для 50+ не работает, чинить до масштабирования.

**Фаза 1 — текстовый premium MVP (2–3 недели).**
- CF `premium_dialog.ts` полная: Secret Manager, prompt caching, sliding-window история, billing-логи, App Check.
- `ai_dialog_session.tsx` — полный движок по паттерну trainer-сессии + финальный репорт + «разбор ошибок».
- 4 режима с CEFR-адаптивными промптами; recall-режим с интеграцией `getTrainerPremiumItems`.
- Гейтинг: `dialogs_limit_session.ts`, `remote_flags` `free_dialogs_per_day`, `premium_modal` context `'dialog_limit'`.
- Кнопки-подсказки, озвучка реплик (TTS уже готов), перевод по тапу, градуированный L1.
- Интеграция XP/achievements/daily_tasks/SRS в конце сессии.
- A/B free-лимита. Вторичные точки (lesson_complete, personal_plan) — в конце фазы.
*Усилие: основная работа. Этап 1 (~40% сложности) — CF+UI; этап 2 (~30%) — интеграция в паттерны.*

**Фаза 2 — голос (2–3 недели, после валидации текста).**
On-device TTS+STR (всё готово в `useAudio`/`ExpoSpeechRecognitionModule`), multi-turn voice state-машина, VoiceWaveform, graceful TTS-прерывание, регулятор скорости речи. Whisper-fallback только для scored-feedback. Premium-only.

## 10. Метрики успеха

Через `analytics.ts` / PostHog / Firebase (`logFeatureStart`/`trackFeatureSuccess`, паттерн из `lesson1.tsx`):

**Спрос / активация (День 0 решает всё):**
- CTR карточки «Разговор с ИИ» на Home.
- % завершивших **первый** диалог (онбординг, без лимита). Если <50% — UX для 50+ сломан.
- Доля 50+ среди использующих (cross-tab с возрастным сегментом, если есть).

**Вовлечённость:**
- Диалогов на юзера/неделю; средняя длина (обменов реплик); % дошедших до teaser-обрыва.
- Доля по режимам (scenario vs recall vs free_talk vs tutor) — какой работает.
- Retention D1/D7/D35 у тех, кто попробовал диалог, vs кто нет.

**Конверсия:**
- Teaser-обрыв → открытие paywall → покупка (воронка `dialog_limit` контекста).
- Trial-to-paid D7/D35 для когорты, увидевшей ИИ-диалог (бенчмарк education ~6.5%).
- Влияние фичи на общую premium-конверсию (A/B: когорта с фичей vs без).

**Педагогический эффект (что реально учит):**
- Recall-режим: % SRS-слов, которые юзер *произнёс*; их последующий `correctStreak` в trainer (диалог должен ускорять graduation фраз).
- Открытие «разбора ошибок» после диалога; повторное снижение тех же ошибок в `mistake_log`/`phrase_analytics`.

**Экономика / здоровье:**
- Cost/active-user (alert если > $0.30); cost/диалог; cache-hit rate; средний input-токен/диалог (контроль sliding-window).
- Rate-limit/quota срабатывания (детект abuse).
