## Outcome

recordSupportDiagnostic больше не читает/пишет AsyncStorage на каждое событие trackActivity: событие кладётся в память (O(1)),
сброс на диск — пачкой под замком: через 30 с после первого несброшенного события, при уходе приложения в фон и перед захватом журнала
для обращения. Потеря последних ≤30 с журнала при падении приложения допустима (решение координатора). Лог сброса: записей, байт, мс, причина.

## Scope

In scope: app/support_diagnostics.ts (буфер + flushSupportDiagnostics), новый app/support_diagnostics_flush.ts (таймер 30 с и AppState —
вне «кольца», где таймеры запрещены сторожем privacy), подключение планировщика из app/app_activity.ts, тесты.
Out of scope: состав событий, сервер, форма поддержки.

## Architecture

Буфер — массив { key, token, event } с владельцем, захваченным в момент записи (событие ушедшего аккаунта не попадёт в новый). Сброс группирует
по ключу, под withMutationLock читает-сливает-обрезает-пишет один раз на ключ; события сменившегося поколения отбрасываются с логом.
Планировщик регистрируется слушателем «появилось событие» (чистая регистрация в памяти при импорте), AppState подписывается лениво при первом событии.

## Security and privacy

Без изменений: состав и фильтрация полей те же; журнал не уходит с устройства сам.
