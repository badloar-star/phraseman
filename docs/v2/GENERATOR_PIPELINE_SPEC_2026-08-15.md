**Статус:** active spec. Зафиксирован 2026-08-15 по решению владельца.
**Кто исполняет:** Claude или Codex, строго по этому документу, без импровизации.
**Где живёт:** вкладка «Генератор» в админке (`admin/v2/legacy.html` — исходник,
публикуется на `https://phraseman-ea0b3.web.app/legacy.html#v2-generator`).

> Этот документ не отменяет и не смягчает
> [GENERATOR_DELIVERY_CONTRACT.md](./GENERATOR_DELIVERY_CONTRACT.md) и

## 0. Решение владельца, из которого всё следует

Генератор — **не** вызов внешней модели за текстом урока. Генератор — это
подробный пайплайн, который:

1. принимает **авторский материал владельца** (он единственный автор контента);
2. разворачивает его в полный урок: 56 сессий, 7 глав по 8;
3. прогоняет через проверки (язык × 8 локалей, методика, assessment, аудио);
4. показывает preview и **ждёт ручного утверждения**;
5. только после утверждения делает TTS и immutable release.

**Провайдеры.** Текст/структуру/проверки ведёт Claude или Codex по этому
пайплайну — отдельная LLM-интеграция за текстом не нужна. OpenAI API нужен
**только для TTS**: четыре голоса `ash`, `onyx`, `nova`, `coral` зафиксированы
контрактом и `modules/learning-v2/contracts/voice_playback_policy_v1.ts`.

**Что это НЕ упрощает.** Отпадает только интеграция с провайдером текста
(вызовы, ретраи, парсинг, бюджеты). Валидаторы, preview/approve, release,
rollback, TTS-конвейер и админка остаются в полном объёме — именно они и есть
Definition of Done.

## 2. Стадии

Каждая стадия: **вход → работа → выход → gate**. Следующая не начинается, пока
gate предыдущей не закрыт. Частично закрытая стадия называется частичной.

---

### S0 · Приём авторского материала

**Вход:** владелец в админке выбирает урок (1–32) и вводит/импортирует свой
материал: тему, целевые фразы, смысловые заметки, при необходимости — свои
формулировки интро.

**Работа:** нормализация без творчества. Пайплайн не додумывает фразы и не
заменяет авторские формулировки «более удачными».

**Выход:** `ownerAuthoredEpisodeInput` — immutable, с `ownerInputOrigin`,
fingerprint и меткой `contentClass`.

**Gate S0:**
- [ ] урок выбран явно, ordinal 1–32
- [ ] материал непустой, каждая фраза имеет перевод-смысл
- [ ] `contentClass` = `production_candidate` либо `neutral_test_fixture`
- [ ] fingerprint посчитан и записан

**Отказ:** пустой ввод, отсутствие перевода, попытка подать чужой fingerprint.

---

### S1 · Развёртка топологии

**Вход:** выход S0.

**Работа:** построить каркас 56 сессий: главы 1–7 по 8 сессий, роли
(`guided_learning` / `chapter_checkpoint` / `transfer_practice` / `final_exam`),
бюджет взаимодействий на каждую сессию по профилю.

**Выход:** `courseLessonTopology` для выбранного урока.

**Gate S1:**
- [ ] ровно 56 сессий, ровно 7 глав по 8
- [ ] сессии 8/16/24/32/40/48 помечены проверками главы
- [ ] сессия 56 помечена экзаменом
- [ ] профиль каждой сессии внутри своего диапазона, ни одна не превышает 22

**Отказ:** любое отклонение от 32×56 или попытка вернуть старую модель 12×12.

---

### S2 · Распределение материала по сессиям

**Вход:** S0 + S1.

**Работа:** разложить авторский материал по сессиям так, чтобы соблюсти
introduce-before-use: понятие → тренировка → перенос → независимая проверка →
отложенное повторение.

**Выход:** план сессий с coverage matrix `objective component × session`.

**Gate S2:**
- [ ] ни одна фраза не используется раньше, чем введена
- [ ] coverage matrix заполнена: introduction / practice / retrieval /
      assessment / transfer видимы
- [ ] пробелы и fake diversity выписаны отдельными findings
- [ ] экзаменационные сессии не переиспользуют тренировочные ответы

**Отказ:** дыра в покрытии, скрытая под высоким средним баллом.

---

### S3 · Сборка сессии

**Вход:** S2, по одной сессии.

**Работа:** собрать четырёх детей — intro, learner, evaluator capsule,
auxiliary. Интро — ровно 3 страницы, у каждой один вопрос внизу, проверяющий
только эту страницу.

**Выход:** канонические дети сессии с fingerprint.

**Gate S3:**
- [ ] 3 intro-страницы, вопросы = canonical slots 1–3
- [ ] практика начинается со slot 4
- [ ] порядок `interactionId` совпадает в learner / evaluator / auxiliary
- [ ] `inputKind` evaluator выводится из family и совпадает с `inputMode`
- [ ] у каждого взаимодействия есть Report, Save-to-cards и голосовой ответ
- [ ] для голосового ответа доступен tap-to-record, а не только удержание
- [ ] подготовлено объяснение второй ошибки
- [ ] каждый distractor имеет релевантный `trapType`, конкретную ошибочную
      модель и собственное объяснение выбранной ловушки
- [ ] нет случайного filler, очевидно чужих слов, недоказанных механических
      мутаций или скопированного feedback
- [ ] ни один близкий distractor не становится вторым допустимым ответом в
      естественном контексте, диалекте или регистре

**Отказ:** отдельный блок вопросов после интро; hold-to-talk без tap-альтернативы;
случайный/механический distractor; универсальное объяснение ошибки.

---

### S4 · Локализация интерфейсных текстов

**Вход:** S3.

**Работа:** восемь локалей: `ru`, `uk`, `es`, `pt-BR`, `vi`, `id`, `tr`, `pl`.

**Gate S4:**
- [ ] все восемь локалей заполнены, пустых нет
- [ ] по каждому языку отдельная проверка: грамматика, естественность, перевод,
      культурная уместность
- [ ] результат машинной проверки — только `eligible_for_human_review`
- [ ] BLOCKER/ERROR перечислены явно и не скрыты средним баллом

**Отказ:** «переведём позже», подстановка английского в чужую локаль.

---

### S5 · Quality gate по reference v3

**Вход:** S3 + S4.

**Работа:** прогнать пакет по
[QUALITY_REFERENCE_GENERATED_CURRICULUM_V3](./QUALITY_REFERENCE_GENERATED_CURRICULUM_V3.md).

**Gate S5:**
- [ ] минимум 15 измерений с оценкой и confidence
- [ ] счётчики BLOCKER / ERROR / WARNING
- [ ] evidence coverage и список объектов на перепроверку
- [ ] ни один BLOCKER не остаётся открытым
- [ ] независимый ревьюер ≠ автор материала

**Отказ:** высокий средний балл при открытом BLOCKER.

---

### S6 · Preview и утверждение владельцем

**Вход:** S5 зелёный.

**Работа:** показать в админке ровно то, что увидит ученик. Никаких
«технических» экранов вместо настоящего вида.

**Gate S6:**
- [ ] preview показывает карту, модалку, интро и практику как в приложении
- [ ] видны findings и scorecard, а не только «готово»
- [ ] двухшаговое подтверждение владельца
- [ ] `manifest ≠ готовое аудио`, `заполнено ≠ одобрено` — подписи честные

**Отказ:** любая формулировка, создающая ложное ощущение готовности.

---

### S7 · TTS: четыре голоса

**Вход:** S6 утверждён владельцем.

**Работа:** OpenAI TTS. На каждую утверждённую реплику — 4 варианта:
`ash`, `onyx`, `nova`, `coral`.

**Gate S7:**
- [ ] 4 варианта на каждый утверждённый аудиотаргет
- [ ] у каждого выбираемого слова/chip есть собственный аудиотаргет
- [ ] hash / byteSize / contentType / generation прочитаны обратно
- [ ] `objectPath` заканчивается на `/<contentHash>.mp3`
- [ ] в активной сессии нет remote TTS fallback и запроса на каждое воспроизведение

**Отказ:** manifest без байтов; смена текста без перегенерации всех вариантов.

**Стоимость:** единственная платная стадия. Считать заранее и показывать
владельцу оценку до запуска.

---

### S8 · Immutable release

**Вход:** S7.

**Работа:** версионированный text+audio root, immutable Storage pins,
generation-pinned readback, CAS active head, rollback.

**Gate S8:**
- [ ] пакет immutable и hash-bound
- [ ] exact readback совпал по всем объектам
- [ ] active head переключается через CAS
- [ ] rollback отрепетирован, а не только реализован
- [ ] `releaseAuthority` теста остаётся `false`

**Отказ:** активация без readback; тестовый provenance в production.

---

### S9 · Проверка на устройстве

**Вход:** S8.

**Работа:** физический проход на реальном устройстве.

**Gate S9:**
- [ ] cold load, LKG offline reopen, background restart
- [ ] быстрые повторные тапы по chip
- [ ] арбитраж звука с hold-to-talk
- [ ] VoiceOver / TalkBack, крупный шрифт, reduced motion
- [ ] answer-free сводка ушла в фон только после полного завершения

**Отказ:** зелёные unit-тесты вместо устройства.

## 3. Что запрещено пайплайну

- Писать за владельца реальный контент уроков E1–E32.
- Запускать массовую генерацию реального курса.
- Повышать `neutral_test_fixture` до production сменой поля.
- Обещать сертификат или фактический C2 из-за разметки диапазона.
- Считать звёзды, завершение или покупку доказательством знания.
- Деплоить, активировать, тратить деньги провайдера без разрешения владельца.
- Трогать Арену.

## 4. Как докладывать результат

Разрешено: «закрыт пакет X», «готова часть Y», «остаётся Z».
Запрещено: «генератор готов», «release-ready» — до полного Definition of Done
из контракта §9.

Каждый отчёт содержит: какие стадии закрыты, какие gate прошли, точные counts
тестов, что осталось открытым.
