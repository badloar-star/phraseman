# Admin v2: почта поддержки и понятные русские названия

Статус: согласовано пользователем 2026-07-13.

## Цель

Исправить рабочую очередь почты поддержки и убрать из основного интерфейса Admin v2 непонятные внутренние ключи. Администратор должен видеть только понятные русские названия, компактный список писем пользователей и полезные сообщения об ошибках. Исходные технические значения сохраняются для диагностики, но не становятся главным текстом.

## Выбранный подход

Использовать единый замороженный реестр названий Admin v2 и progressive disclosure:

- русское название всегда показывается первым уровнем;
- исходный технический ключ доступен вторым уровнем с явной подписью;
- неизвестный ключ получает честное русское fallback-название, а не автоматический псевдоперевод;
- письма изначально свернуты, одновременно открыто не больше одного;
- по умолчанию видны только письма пользователей, а служебные остаются доступными в отдельном фильтре;
- массовые действия работают только с явно человеческими письмами.

Отклонённые альтернативы:

- переводить только таблицу со скриншота: оставляет ту же проблему в других разделах;
- скрыть технические ключи полностью: ухудшает диагностику и поиск;
- автоматически заменять `_`, `:` и kebab-case пробелами: создаёт правдоподобные, но потенциально неверные названия;
- удалять служебные письма при получении: может скрыть важное письмо и нарушает правило сохранения функциональности.

## Единый реестр названий

Classic-script загружается до router и всех страниц Admin v2. Он описывает смысловые значения по паре `kind + key` и возвращает:

- `label`: понятное русское название;
- `technicalKey`: исходное неизменённое значение;
- `known`: найдено ли точное соответствие.

Реестр покрывает только реально отображаемые группы: действия, события, экраны, источники, статусы, состояния операций, категории, аудитории, виды заданий, причины ошибок и разрешения. Существующий `AdminAnalyticsLanguage` остаётся совместимой оболочкой, чтобы не ломать аналитические страницы во время переноса.

Примеры:

- `shards_shop:open` → «Открыли магазин осколков»;
- `onboarding_source_select` → «Выбрали источник знакомства с приложением»;
- `paywall:abandoned_push` → «Отправлено напоминание после закрытия экрана оплаты».

Неизвестные значения не становятся сырым главным текстом. Интерфейс показывает «Неизвестное действие», «Другой экран», «Неизвестный статус» или «Неизвестный источник», а ниже — `Технический ключ: <code>…</code>`.

Непрозрачные идентификаторы не переводятся. UID, `reportId`, `operationId`, `campaignId` и подобные значения получают русскую подпись поля, но остаются техническим кодом. Нельзя менять `data-action`, route IDs, Firestore-поля, object keys, callable names и серверные контракты.

## Почта поддержки

### Фильтрация

По умолчанию выбран фильтр «Пользователи». Доступны фильтры:

- «Пользователи»;
- «Служебные»;
- «Не определено»;
- «Все».

Фильтр категории работает вместе с текущими статусами «Новые», «Отвечено», «Архив». Сервер использует существующую классификацию Google, `noreply`, рассылок и автоответов. Для старых документов без категории эффективная категория вычисляется хотя бы по адресу отправителя. Ничего автоматически не удаляется.

Обе группы фильтров имеют видимое выбранное состояние. Кнопки категории и статуса используют `aria-pressed` и понятное имя группы либо эквивалентную семантику radio/select. У каждого фильтра есть tooltip, видимый `focus-visible`, управление клавиатурой и зона нажатия не меньше 44 px.

Массовая генерация, число готовых черновиков и подготовка пакета включают только письма категории `human`. Индивидуальные генерация, редактирование, подготовка отправки и архивирование служебного или не определённого письма остаются доступны после осознанного перехода в соответствующий фильтр.

### Компактные карточки

Все письма закрыты при первой загрузке. Заголовок строки содержит тему, отправителя, время, русскую категорию и статус. Кнопка «Открыть» раскрывает тело, поле ответа и действия; открытие другого письма закрывает предыдущее. Повторное нажатие сворачивает текущее письмо.

Контрол раскрытия имеет `aria-expanded`, `aria-controls`, tooltip, видимый `focus-visible` и зону нажатия не меньше 44 px. Несохранённый ручной ответ хранится в `state.support.replyEdits`, поэтому не теряется при закрытии, смене фильтра и повторном открытии карточки в рамках текущей сессии.

### Ошибка генерации

Голое `internal` не является допустимым пользовательским сообщением. Генерация получает безопасный диагностический ID и этапные серверные логи:

1. чтение конфигурации;
2. вызов провайдера;
3. сохранение черновика и audit record.

Один диагностический ID создаётся в начале каждой попытки генерации. Он возвращается клиенту в безопасном `HttpsError.details`, присутствует тем же значением во всех structured logs этапов и показывается в сообщении Admin v2. Уже сформированные `HttpsError` сохраняют свой исходный код, но также получают этот ID; неожиданные ошибки преобразуются в стабильную ошибку генерации с тем же ID. Логи не содержат текст письма, адрес, ответ, provider body или секреты.

Исправление не ограничивается улучшением сообщения. По диагностическому ID необходимо определить фактический сбой на этапе конфигурации, вызова провайдера либо сохранения черновика/audit record и исправить его в источнике. Пакетная генерация возвращает число успешных и неуспешных писем и не выдаёт молчаливый успех при нуле созданных черновиков.

Codex не вызывает OpenAI API для smoke-проверки: это запрещено проектным firewall. Проверка выполняется mock-тестами, а после безопасного выпуска — одним пользовательским кликом с сопоставлением диагностического ID и серверного лога.

## Совместимость и сохранение текущей работы

Опубликованная Admin v2 и локальные dirty-файлы расходятся. До редактирования и Hosting deploy необходимо:

1. получить точный список опубликованных Admin v2-ассетов;
2. сохранить их в ignored backup/report-каталог;
3. сравнить live, Git HEAD и рабочую копию;
4. перенести live-only и текущие пользовательские изменения без перезаписи;
5. только после объединения менять почту и реестр названий.

Ни существующая отправка, ни архив, подпись, подтверждение пакета, аудит и диагностика не удаляются. Развёртывание выполняется узко: только изменённые callables и затем только Firebase Hosting target `admin`.

## Доступность и адаптивность

- Основной русский текст имеет приоритет над `<code>`.
- Tooltip не заменяет видимую подпись.
- Цвет не является единственным признаком состояния.
- Кнопки доступны с клавиатуры, порядок Tab совпадает с визуальным порядком.
- Таблицы и закрытые строки проверяются на 375, 768, 1024 и 1440 px без горизонтального скролла всей страницы.
- Раскрытие использует короткий переход opacity/transform и уважает `prefers-reduced-motion`.

## Проверка

Нужны focused-тесты и аудиты:

- точные русские названия согласованных событий;
- перенос всех существующих label-map без потери значений;
- безопасный fallback с `known: false` и неизменённым `technicalKey`;
- экранирование специальных символов;
- русское название появляется раньше технического ключа;
- сырой смысловой ключ не используется как заголовок, badge или основная ячейка;
- реестр загружается раньше страниц и router;
- legacy-письма получают эффективную категорию;
- пакетные операции исключают automated/unknown;
- начальное состояние карточек закрыто, одновременно открыта максимум одна;
- ручной ответ сохраняется при переключении;
- один тест сопоставляет диагностический ID из клиентской ошибки с ID во всех mock structured logs;
- существующий `HttpsError` сохраняет код и получает безопасный диагностический ID;
- ошибка генерации содержит понятное сообщение и диагностический ID;
- focused-тесты отдельно покрывают сбой конфигурации, провайдера и сохранения;
- `node --check`, focused Jest, Admin v2 language/route/action/tooltip audits;
- визуальная и клавиатурная проверка 375/768/1024/1440 px;
- после публикации — повторная сверка live-ассетов.

## Критерии приёмки

- Во всей Admin v2 смысловые ключи имеют понятные русские основные названия.
- Исходный ключ доступен только вторично и остаётся неизменённым.
- При входе в почту видны новые письма пользователей, все строки закрыты.
- Google, рассылки и автоответы находятся в отдельном фильтре и не попадают в массовые операции.
- Открытие нового письма закрывает предыдущее, ручной текст не теряется.
- Выбранные фильтры видны визуально, объявляются через `aria-pressed` или эквивалентную семантику и работают с клавиатуры.
- Фактическая причина `internal` определена и исправлена на исходном этапе.
- Один разрешённый пользовательский клик после выпуска успешно создаёт и сохраняет черновик; если этому мешает внешний сервис, завершение допускается только с документированным внешним блокером, диагностическим ID и доказательством исправности остальных этапов.
- Существующие функции почты и несвязанные изменения Admin v2 сохранены.
