# План улучшений генератора планов

**Дата:** 2026-06-08
**Принцип владельца:** сначала дописать генератор, потом наполнять дни. Движок должен сам строить дни правильно.

Покрывает всё из аудита ([plan-generator-audit.md](plan-generator-audit.md)) + 2 новых требования:
адаптивность к 32 урокам с рекомендацией уроков, и словарь ключевых слов на каждый день.

---

## 0. Карта 32 уроков = шкала сложности (фундамент адаптивности)

Грамматическая прогрессия приложения (из `constants/lessons.ts`):

| # | Тема | Условный уровень |
|---|---|---|
| 1–2 | To Be (местоимения, отрицание, вопросы) | A1 |
| 3–6 | Present Simple (утв/отр/вопр, спец. вопросы) | A1–A2 |
| 7–10 | To Have, предлоги времени, There is/are, модальные | A2 |
| 11–13 | Past Simple (прав/неправ), Future Simple | A2 |
| 14–16 | Степени сравнения, притяжательные, фразовые глаголы | A2–B1 |
| 17–20 | Present Continuous, повелительное, предлоги места, артикли | A2–B1 |
| 21–24 | Неопр. местоимения, **герундий**, **Passive**, **Present Perfect** | B1 |
| 25–28 | Past Continuous, **условные**, **косвенная речь**, возвратные | B1 |
| 29–31 | Used to, Relative Clauses, **Complex Object** | B1–B2 |
| 32 | Финальное повторение | — |

**Ключевая идея:** каждый день плана объявляет, какие уроки он «требует». Фразы дня строятся **только** на конструкциях из требуемых (и более ранних) уроков. Урок 22 (герундий) не может появиться в дне 1.

## ЭТАП 1 — Модель грамматической готовности (фундамент)

**Цель:** дать генератору структурированное знание «какая конструкция в каком уроке».

### 1.1 `app/lesson_grammar_map.ts` (новый)
- Таблица: `lessonId → { constructions: string[], level: 'A1'|'A2'|'B1'|'B2', requiresLessons: number[] }`.
- 32 записи, по карте выше. `constructions` = граммар-теги (`to-be`, `present-simple`, `gerund`, `passive`…).
- Чистый модуль, без зависимостей — легко тестируется.

### 1.2 `lessonGateForDay(planId, dayIndex)` 
- Возвращает максимальный «разрешённый урок» для дня плана: день 1 → уроки ≤ N₁, день 7 → ≤ N₂ и т.д.
- Кривая: ранние дни = базовые уроки (1–8), к концу плана открываются продвинутые.
- Источник истины для фильтра контента и рекомендации уроков.

**Тесты:** день 1 не пускает герундий; день 30 пускает Present Perfect; монотонность (gate не убывает).

## ЭТАП 3 — Адаптивность фраз к урокам + рекомендация (НОВОЕ, главное)

**Цель:** фразы дня построены на конструкциях доступных уроков; в меню плана — рекомендация «пройди урок X».

### 3.1 Фильтр фраз по грамматическому gate
- Каждая фраза дня имеет `requiredConstructions` (граммар-теги).
- Генератор берёт только фразы, чьи конструкции ⊆ `lessonGateForDay`.
- День 1 плана = фразы на To Be / Present Simple, без перфектов и герундиев.

### 3.2 Рекомендация уроков в меню плана
- `recommendedLessonsForDay(planId, dayIndex)` → список уроков, которые стоит пройти ДО дня.
- В UI меню плана (`personal_plan.tsx`) — баннер: «Рекомендуем пройти урок 7 и 9 перед началом — так фразы дня будут понятнее».
- Привязка к **реальному прогрессу юзера**: если урок уже пройден (есть в `lessonPassCount`), не рекомендуем повторно.

### 3.3 Поле в модели дня
- `PlanDay.curriculum` уже есть (`allowedGrammarTags`/`blockedGrammarTags`, lessonPrerequisites) — но не используется для фильтрации контента. **Подключить его** к генерации фраз, а не держать декоративным.

**Тесты:** фразы дня 1 проходят gate; рекомендация исключает пройденные уроки; blockedGrammarTags реально блокируют.

## ЭТАП 4 — Словарь ключевых слов на каждый день (НОВОЕ)

**Цель:** в каждом дне — блок новых ключевых слов из фраз этого дня, чтобы юзер их выучил.

### 4.1 Извлечение ключевых слов
- `dayKeyVocabulary(day)` → из фраз дня берём новые слова (которых не было в предыдущих днях плана).
- Каждое слово: `{ word, translation, partOfSpeech, exampleFromDay }`.
- POS берём из уже починенной POS-системы ([[pos_taxonomy]]) — связь с пунктом #4 аудита.

### 4.2 Новый таск-блок «Словарь дня»
- `PlanTaskKind: 'plan_vocabulary'` — короткий блок: показать слово + перевод + пример из фразы дня.
- Ставится в начало дня (до упражнений) — сначала слова, потом фразы.
- Слова уходят в `bumpStatsDaily('words_learned')` — связь со статистикой (уже работает).

**Тесты:** словарь дня = только новые слова; нет повтора между днями; каждое слово имеет POS + пример.

## ЭТАП 5 — Recall из реальных пройденных фраз (дыра #5)

**Цель:** recall повторяет то, что юзер реально учил, а не позиционный «день N-1».

- Сейчас `recallLessonId = {plan}_d{N-1}_content_unit` (вслепую).
- Заменить на выборку из **attempt events** (уже пишутся, [[personal_plan_attempt_events]]) — реально пройденные фразы юзера, с приоритетом слабых.
- Связь с пунктом #5 аудита (attempt events читаются в UI).

**Тесты:** recall тянет пройденные фразы; слабые фразы в приоритете; fallback на день N-1 если истории нет.

## ЭТАП 6 — Оживить персонализацию (дыра #3, отдельный большой блок)

**Цель:** `personal_plan_generator.ts` (weakSpots/loadHint) сейчас мёртв (0 потребителей). Подключить к генерации.

### 6.1 loadHint → объём дня
- `derivePlanPersonalization().loadHint` ('light'/'steady'/'push') влияет на число видимых задач (поверх тиров минут).
- Уставший юзер ('light') → короче; ударник ('push') → больше.

### 6.2 weakSpots → подмешивание задач
- Топ слабых частей речи/тегов юзера → добавлять адресные задачи в день.
- «Тебе тяжело даются предлоги» → лишний missing_word на предлоги.
- Связь с «персональным тренером по частям речи» (пункты #4/#5).

### 6.3 Точка подключения
- `buildPlanGeneratorInput()` вызывать при открытии плана; результат прокидывать в `visibleTasksForMinutes`/`makeGeneratedDay`.
- Кэшировать (не пересчитывать на каждый рендер).

**Тесты:** loadHint меняет число задач; weakSpot добавляет адресную задачу; пустая история = базовый план (не падает).

## Порядок выполнения (зависимости)

```
Этап 1 (грамматическая модель)  ─┬─> Этап 3 (адаптивность + рекомендации)
                                 └─> Этап 2 (прогрессия режимов)
Этап 4 (словарь дня) ── независим, опирается на POS (готов)
Этап 5 (recall) ── опирается на attempt events (готовы)
Этап 6 (персонализация) ── опирается на Этап 1+3
Этап 7 (контент) ── последним, решение A/B за владельцем
```

**Рекомендуемая последовательность:**
1. **Этап 1** — фундамент (грамматическая карта уроков). Без него нет адаптивности.
2. **Этап 3** — адаптивность фраз + рекомендация уроков (твоё главное требование).
3. **Этап 2** — прогрессия режимов (дёшево, 1 файл).
4. **Этап 4** — словарь дня.
5. **Этап 5** — recall из реальных фраз.
6. **Этап 6** — персонализация.
7. **Этап 7** — контент (A или B).

Каждый этап — отдельные чистые модули + jest-тесты перед подключением к UI. Прод-экран трогаем в последнюю очередь каждого этапа.
