## Architecture

Ключевой факт, установленный аудитом и проверенный лично
(`functions/src/community_packs.ts:914`):

    const packRef = db.collection(COMMUNITY_PACKS).doc(submissionId);

Опубликованный набор создаётся ПОД ID ЗАЯВКИ. При наличии `submissionKey` этот id
всегда имеет вид `create_<sha256>` (строки 891-893). Следовательно идентификатор
заявки и идентификатор опубликованного набора — ОДНО И ТО ЖЕ значение по
конструкции, и различить их по форме строки невозможно в принципе.

Отсюда: прежнее поведение (`cloudPackId = result.submissionId`) было ВЕРНЫМ —
поле заполнялось правильным значением с опережением, до одобрения. Моя эвристика
принимала законный id за мусор.

Инвариант, который возвращаем: `cloudPackId` хранит id, под которым набор живёт
(или будет жить) в `community_packs`; он же равен id заявки.
