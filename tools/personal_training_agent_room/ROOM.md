# Jesse Pinkman Room Protocol

Room name: Jesse Pinkman

Mission: create personal trainings that repair one logged user mistake at a
time. The product must feel like a small concrete fix, not a grammar lecture.

## Roles

- Room Lead: chooses one diagnosis id and keeps the session inside that scope.
- Evidence Auditor: checks lessons, words, distractors, and logged mistakes.
- Error Taxonomist: confirms the training is exactly one error category.
- Copy Teacher: writes beginner-safe RU/UK/ES copy without unexplained jargon.
- Exercise Builder: creates focused single-choice tasks with plausible options.
- Feedback Mapper: writes feedback for every wrong option, tied to that option.
- Integration Maintainer: wires imports, routes, admin paths, and tests.
- QA Gatekeeper: runs hygiene and content checks before the room reports done.

## Non-Negotiable Product Standard

- One personal training teaches one concrete mistake type.
- UI explanations use the learner interface language.
- English examples are allowed, but grammar explanations must not switch to
  English jargon for RU/UK learners.
- Every wrong answer option needs its own specific feedback.
- The tone is calm, useful, and shame-free.
- No broad grammar lecture. One error, one reason, one pattern, several repeats.

## Replace-Mode

`JESSE_REPLACE_MODE` is always on.

Before creating a training for `<id>`, the Integration Maintainer must:

1. Search `app` for `diagnosis_training_<id>*`.
2. Search the repo for `<id>` and `diagnosis_training_<id>`.
3. Identify the current connected training, if any.
4. Replace the current file in place.
5. Remove stale same-id variants.
6. Reconnect imports and routes to the new current file.
7. Confirm admin/manual training lists point to the current route.

Allowed final app file:

```text
app/diagnosis_training_<id>.ts
```

Forbidden stale app files:

```text
app/diagnosis_training_<id>_new.ts
app/diagnosis_training_<id>_v2.ts
app/diagnosis_training_<id>_draft.ts
app/diagnosis_training_<id>_backup.ts
app/diagnosis_training_<id>_old.ts
app/diagnosis_training_<id>_tmp.ts
app/diagnosis_training_<id>_candidate.ts
```

Do not preserve old content inside `DIAGNOSIS_TRAININGS` as inline fallback.
Diagnosis trainings live in standalone files and the registry only connects
those files.

## Registry Rules

For each published training id:

- Add exactly one import in `app/diagnosis_trainings.ts`.
- Add exactly one `if (id === '<id>') return <TRAINING>;` route.
- Add exactly one `<id>` entry inside `getAllDiagnosisTrainings()`.
- Keep `DIAGNOSIS_TRAININGS` empty unless a future migration explicitly changes
  this room protocol.
- Do not duplicate the same id through both standalone import and inline object.

## Jesse-Reworked Marker

File existence is not proof that Jesse already rebuilt a training.

A training is protected as already rebuilt only when:

1. `app/diagnosis_training_<id>.ts` contains
   `JESSE_REWORKED_PERSONAL_TRAINING`.
2. `app/personal_training_taxonomy.ts` lists the id as Jesse-reworked.
3. The admin manifest generated by `training:personal:sync-admin` lists the id
   in `jesseReworkedIds`.

If any of these is missing, the training is legacy. The next integrator pass for
that id must replace the old file in place, remove stale imports/routes for that
id, add the marker, and then sync/check.

## Parallel Session Rule

Multiple sessions may work in parallel only when each session owns a different
diagnosis id. Two sessions must not edit the same `app/diagnosis_training_<id>.ts`
or the same registry block at the same time without manually merging.

## Done Definition

A training is done only when:

- Replacement sweep is complete.
- The current training has no stale sibling files.
- The current training has `JESSE_REWORKED_PERSONAL_TRAINING` in its app file.
- The registry has exactly one route for the id.
- `getAllDiagnosisTrainings()` returns unique ids.
- Admin/manual lists do not point to removed files.
- `npm run training:personal:sync-admin` has refreshed admin output.
- `npm run training:personal:check` passes.

## Mandatory Post-Publish Commands

After every created or replaced training, the Implementation Integrator runs:

```powershell
npm run training:personal:sync-admin
npm run training:personal:check
```

If either command fails, fix only failures related to the changed personal
training files, registry, taxonomy, admin manifest, or Jesse protocol.
