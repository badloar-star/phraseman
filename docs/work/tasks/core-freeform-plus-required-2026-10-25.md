## Outcome
Владелец видит «Сервис недоступен» в свободном диалоге. По логам старт отказывает `dialogue_v2_freeform_plus_required`: у записи
владельца на сервере нет Plus, а клиент считает Plus включённым. Поручение координатора (JS, в обновление по воздуху):
- Б — в `[PREMIUM-RESOLVE] reload:done` печатать, какой источник дал «да» (realPremium / vip / verifiedCloud / intro / devOverride),
  без идентификаторов;
- В — на отказ plus_required при старте не повторять старт и не писать «сервис недоступен», а открыть экран Plus, как плитка делает
  для бесплатных; журнал `[DIALOGUE-V2-FREEFORM]` с причиной;
- описать расхождение «клиент да / сервер нет» (intro на 3 дня и др.) и предложение, без выкладки.

  dialogue_v2_freeform_plus_required);
- app/dialogue_v2_freeform.tsx — старт с этой причиной: без тихих повторов, замена экрана на /premium_modal, журнал;

Сервер не меняется. Файлы согласованы с «5 · ВХОД»: она правит серверный обработчик хода, эти три файла не трогает.

## Architecture
Причина берётся из кода и сообщения ошибки вызова (Firebase передаёт message с сервера). Экран при plus_required один раз
переходит на тот же маршрут, что и плитка каталога (`/premium_modal`), с тем же видом параметров; генерация и таймер повтора
гасятся, чтобы ответ, пришедший позже, ничего не перезапустил.

## Security and privacy
Новых данных нет. В журнал пишутся только имена источников и булевы значения, без uid, почты и токенов. Сервер по-прежнему
единственный судья Plus: клиент просто честно показывает его ответ.
