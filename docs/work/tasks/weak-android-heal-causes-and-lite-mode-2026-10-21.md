# Task packet: слабые Android — лечим причины (журнал ошибок, озвучка V2) и «Лёгкий режим»

## Outcome

На слабом Android (Galaxy A04, ~3–4 ГБ, Helio P35) «Работа над ошибками» не замедляется с ростом журнала, вход в занятие V2 не замирает на разовой загрузке таблиц озвучки, а на устройствах с ОЗУ < 3 ГБ (и по ручному переключателю «Лёгкий режим» в Настройках) выключаются мягкие тени и принудительная предзагрузка вкладок.
Мера успеха: (1) стоимость одного ответа в «Работе над ошибками» не растёт линейно с числом событий (тест на счётчик операций хранилища и хеширований); (2) лог [PERF-LITE] объясняет, включён ли режим и почему; (3) все существующие тесты журнала зелёные; старые журналы (одна запись v1, корень v2 со страницами/кусками) читаются и дописываются без потерь.

## Scope

In scope:
- B2: `app/mistake_practice_store.ts`, `app/mistake_practice_cloud_merge.ts` (линейное разбиение на куски, побайтово тот же результат), кэш разобранного графа журнала по значению корня, дописывание только нового куска, удаление ставших недостижимыми ключей без `getAllKeys` по всему хранилищу (полная чистка — раз за процесс). Формат на диске НЕ меняется (корень v2 → страницы → куски), миграция не нужна.
- B3: загрузчик `app/learning_v2_factory_production_audio_v1.ts` и `app/learning_v2_lesson_audio_pack_v1.ts`: подогрев таблиц озвучки вне входа в занятие (после первого кадра карты курса), с логом. Файлы `*.generated.ts` и контент Codex НЕ трогаются.
- A: общий модуль «Лёгкий режим» (`app/lite_mode.ts`) поверх существующего `app/flashcards/low_power.ts`; выключение теней (`constants/liquidGlassShadowStyle.ts`) и принудительной предзагрузки вкладок через 8 с (`app/(tabs)/_layout.tsx`); переключатель в `app/(tabs)/settings.tsx` (9 языков, без подписи-расшифровки); лог [PERF-LITE].

Out of scope: правка файлов `*.generated.ts`, скриптов их генерации и контента курса; новый формат журнала; inlineRequires; выгрузка замеров на сервер; изменение вида при выключенном лёгком режиме.

## Architecture

Журнал: сейчас каждое чтение — корень → страницы → куски с SHA-256 на JS, каждое дописывание — перечитывание, пересборка и перезапись ВСЕГО журнала, затем getAllKeys. Станет: чтение сверяет сырой корень с кэшем (корень содержит headPageId; страницы и куски адресуются хешем содержимого, неизменяемы), при совпадении граф не перечитывается и не хешируется; запись сравнивает куски по закодированному тексту, пишет только новые куски/страницы и корень; бывшие достижимыми, но ставшие недостижимыми ключи удаляются точечно. Кэш — по хранилищу и ключу корня, сбрасывается при любой ошибке записи, при отсутствии/смене корня, при смене ревизии моста phone-state и по TTL для объединённого с phone-state журнала.
Инварианты: порядок записи chunks → pages → root прежний; assertCurrentOwner на тех же местах; журнал неизменяем (freeze); id куска = SHA-256 его канонического JSON, как раньше.
Лёгкий режим: один источник правды — `low_power.ts` (ключ `fc_low_power_override_v1`, порог < 3 ГБ); `lite_mode.ts` даёт подписку, лог и React-хук; тени читают плоский флаг из `constants/lite_mode_flag.ts` (без тяжёлых импортов).

## Security and privacy

Журнал ошибок — данные пользователя и участвует в облачной синхронизации: формат и проверка хешей при полном чтении сохраняются, кэш не переживает процесс и не пересекает аккаунты (ключ содержит accountScope). Новых данных не собирается: переключатель — локальная настройка; [PERF-LITE] пишет модель и ОЗУ только в локальную консоль (не уходит с устройства) → политика конфиденциальности не меняется. Секретов, прав доступа и серверных вызовов нет.

## Verification

- Новые тесты: линейное разбиение == прежнему (случайные журналы, в тесте хранится копия прежнего алгоритма); побайтовая эквивалентность хранимого графа (корень/страницы/куски) прежнему алгоритму; счётчики setItem/getItem/getAllKeys/хеширований на серии дописываний; чтение старых журналов (v1 одна запись, v2 несколько страниц/кусков); повреждения по-прежнему дают те же причины; сброс кэша при смене корня/ошибке.

- Вид: переключатель в Настройках — кадр эмулятора под замком, только после слова координатора (эмулятор выключен владельцем).
